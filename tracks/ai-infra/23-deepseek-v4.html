1. 动机：百万 token 上下文 + 万亿参数，同时要稳、要省

DeepSeek-V3 用 MLA 压 KV、MoE + FP8 压训练成本；V3.2 用 DSA 把注意力计算从 O(L²) 降到 O(Lk)。但 DSA 只减少了每步读多少 KV，KV 仍要按完整长度存；到 1M 上下文，存储与计算都还太贵。另一方面，更宽的残差流（Hyper-Connections）能提升模型质量，却在大规模训练中不稳定。

一句话理解 V4 保留了 V3 的 Transformer 主干与 MTP，加了三件事：CSA / HCA——先把 KV 序列按 4 或 128 倍压缩，再（对 CSA）做稀疏选择；mHC——残差流扩成 4 路，但把路间混合矩阵约束为双随机矩阵，让信号既不放大也不衰减；Muon——大部分参数用正交化更新。系统侧配套了融合 EP 内核、确定性内核、FP4 量化感知训练与磁盘 KV 缓存。

3.3 Muon 优化器

V4 对大部分参数改用 Muon：对动量矩阵做 Newton–Schulz 迭代近似正交化，再按更新的 RMS 重新缩放（目标 RMS 0.18），从而可以直接沿用 AdamW 的学习率等超参；动量 0.95、权重衰减 0.1。嵌入、输出头、所有 RMSNorm 权重以及 mHC 的静态偏置与门控因子仍用 AdamW。Newton–Schulz 共 10 步、两组系数：前 8 步 (3.4445, −4.7750, 2.0315) 快速收敛，后 2 步 (2, −1.5, 0.5) 精确收敛到正交。V4 §2、§4.2.2

$$X_{k+1} = a X_k + b\,(X_kX_k^\top)X_k + c\,(X_kX_k^\top)^2X_k,\qquad X_0 = \frac{M}{\lVert M\rVert}$$

分布式实现上，Muon 需要完整的参数矩阵才能正交化，与 ZeRO 式的扁平分片冲突。V4 的 “Muon ZeRO” 用背包式分桶把稠密参数整块分给各 DP 秩，填充开销通常低于 10%。（Kimi K3 则只通过点对点取回自己负责的分片，见 Kimi Linear 页。）

4. 伪代码

mhc_layer.py（一层 mHC，n = 4）
def sinkhorn(logits, iters=20):
    M = exp(logits)                                   # 非负
    for _ in range(iters):
        M = M / M.sum(-1, keepdim=True)               # 行归一
        M = M / M.sum(-2, keepdim=True)               # 列归一 → 近似双随机
    return M

def mhc_block(x, F, p):                               # x: [T, n=4, C]
    h = rmsnorm(x.flatten(-2))                        # 动态系数来自当前输入
    H_pre  = sigmoid(h @ p.W_pre  + p.b_pre)          # [T, 1, 4]，非负
    H_post = 2 * sigmoid(h @ p.W_post + p.b_post)     # [T, 1, 4]，(0, 2)
    H_res  = sinkhorn((h @ p.W_res + p.b_res).view(-1, 4, 4))
    y = F(einsum("tin,tnc->tic", H_pre, x))           # 读：4 路 → 1 路，跑注意力 / MoE
    return einsum("tmn,tnc->tmc", H_res, x) + H_post.transpose(-1, -2) * y   # 混合 + 写回

6. 简答题

Q41mHC 解决了 Hyper-Connections 的什么问题？双随机约束为什么能保证稳定，系统代价是多少？

HC 把残差流扩成 n 路并用可学习矩阵在路间混合，能提升质量，但路间混合矩阵 Hres 没有约束：多层连乘后信号可被放大或衰减，27B 实验中最大增益峰值约 3000、训练约 12k 步出现损失激增。mHC 把 Hres 投影成双随机矩阵（Sinkhorn-Knopp 20 次），并让 Hpre、Hpost 非负。

  • 为什么稳：双随机矩阵谱范数 ≤ 1（不放大），乘积仍是双随机（任意深度都成立），且保持各路的总和（不吞掉信号）；可理解为置换矩阵的凸组合。实测最大复合增益约 1.6。
  • 代价：n = 4 时训练时间 +6.7%。靠融合内核（读 (3n+1)C → (n+1)C、写 3nC → nC）、分段重计算（只存段输入）、DualPipe 重叠跨阶段通信压到这个水平。
  • 收益：27B 上 BBH 43.8 → 51.0、DROP 47.0 → 53.9（对普通残差）；DeepSeek-V4 全面采用 n = 4。

依据：mHC 论文 §3–5、Tab. 4；V4 论文 §2.2、§3.4.2、§4.2.1。

Q42DeepSeek-V4 的百万 token 上下文效率来自哪些设计？分别压缩了什么？

分三层看：存多少——CSA 把 KV 序列压 4×、HCA 压 128×，KV 再用 BF16（RoPE 64 维）+ FP8（其余）混合精度存；读多少 / 算多少——CSA 只对索引器选出的 top-k（512 / 1024）条压缩 KV 做注意力，HCA 对很短的压缩序列做稠密注意力，索引器本身用 FP4；局部细节——每层一个 128 token 的未压缩滑动窗口补回最近的信息。

  • 效果（1M 上下文，相对 V3.2）：单 token FLOPs Pro 27% / Flash 10%，KV Pro 10% / Flash 7%；KV 约为 BF16 GQA8 基线的 2%。
  • 演进：MLA 压每 token 的 KV 宽度（V2 / V3）→ DSA 压每步读取的条数（V3.2）→ CSA / HCA 压 KV 序列长度本身（V4）。
  • 系统配套：长上下文的两阶段上下文并行、压缩 KV 落盘做前缀复用、先稠密后稀疏的分阶段训练。

依据：V4 论文摘要、§2.3、§3.5、§4.2；DSA 页的谱系表。
