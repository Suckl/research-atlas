1. 动机：注意力本身不知道顺序

自注意力对 token 集合是置换等变的——打乱输入顺序，输出跟着打乱，但每个 token 的输出不变。语言需要顺序，于是要“注入位置”。2021 年前的两条路：

  • 绝对位置（原始 Transformer 的正弦、BERT/GPT 的可学习向量）：加在输入 embedding 上。简单，但模型要自己从两个绝对位置推断相对距离，且可学习版本对超出训练长度的位置没有定义。
  • 相对位置（Shaw 2018、T5 的偏置、ALiBi）：在注意力分数里加一个依赖 m−n 的项。表达了“距离”，但要改注意力内核、与 FlashAttention 这类融合内核不友好，有的还不能用于线性注意力。
一句话理解 把 q 和 k 的每两维看成一个复数，按绝对位置旋转 mθ 角；两个旋转后的向量做点积，结果只和角度差 (m−n)θ 有关——于是用“绝对位置的操作”得到了“相对位置的效果”，而且什么参数都不加、注意力内核不用改。

2. 机制

$$f_q(x_m, m) = R^d_{\Theta,m} W_q x_m,\quad f_k(x_n, n) = R^d_{\Theta,n} W_k x_n,\quad q_m^\top k_n = x_m^\top W_q^\top R^d_{\Theta,n-m} W_k x_n$$
$$R^d_{\Theta,m} = \mathrm{diag}\big(R(m\theta_0), R(m\theta_1),\dots,R(m\theta_{d/2-1})\big),\qquad \theta_i = \text{base}^{-2i/d}$$

3. 组件拆解

3.1 四条性质

  1. 相对性：分数只依赖 n−m（上式），这是推导出来的而非近似。
  2. 远程衰减：论文证明分数的上界随 |n−m| 增大而衰减（各频率的旋转相互“失相”），符合“近处更相关”的先验。
  3. 无参数、内核友好：只对 q、k 做逐元素变换，注意力内核本身不变，FlashAttention / 分页 KV 都直接适用。KV cache 里存的是旋转后的 k（位置固定了），所以解码时只需旋转新的 q。
  4. 可用于线性注意力：旋转保持范数，可以在核函数 φ(q)、φ(k) 之后施加，不破坏线性注意力的结合律（论文 §3.5）。

3.2 长度外推与各种“缩放”

训练长度 4K 的模型直接跑 32K：低频对转到了训练时从未见过的角度，困惑度爆炸。改法都是重新设计 θᵢ：

方法做法直觉
位置插值（PI）m → m/s把长序列压回训练区间；损失近距离分辨率
NTK-awarebase → base·s^(d/(d−2))高频少压、低频多压
YaRN按频率分段：高频不动、低频插值、中间过渡 + 温度缩放当前长上下文模型的常用方案
更大的 base直接用 5×10⁵ – 10⁷ 训练Llama 3、Qwen 等的做法
部分 RoPE只旋转一部分维度（如 25%），其余不加位置给模型留“无位置”的通道；GPT-NeoX、Qwen3-Next 的全注意力层

3.3 没有位置编码行不行：NoPE

Kazemnejad 等（2023）与后续工作发现：因果掩码本身就泄露位置——第 t 个 token 只能看到前 t 个，注意力的归一化分母随 t 变化，模型可以从中恢复绝对位置（至少在前几层），并且理论上能表示相对位置。小模型上 NoPE 的长度泛化甚至好于 RoPE。但大规模实践中 NoPE 的困惑度与检索能力仍普遍弱于 RoPE，于是出现折中：部分层 NoPE、部分层 RoPE（如 Llama 4 的交错），或部分维度 RoPE。

4. 伪代码

rope.py
def rope_freqs(d, base=10000.0):
    i = torch.arange(0, d, 2) / d                     # [d/2]
    return base ** (-i)                               # θ_i = base^(-2i/d)

def apply_rope(x, pos, theta):                        # x: [..., seq, d]; pos: [seq]
    angles = pos[:, None] * theta[None, :]            # [seq, d/2]
    cos, sin = angles.cos().repeat_interleave(2, -1), angles.sin().repeat_interleave(2, -1)
    x1, x2 = x[..., 0::2], x[..., 1::2]
    rot = torch.stack((-x2, x1), -1).flatten(-2)      # rotate_half
    return x * cos + rot * sin                        # 逐元素，无参数

q = apply_rope(W_q @ x, pos, theta); k = apply_rope(W_k @ x, pos, theta)   # v 不旋转
scores = q @ k.transpose(-1, -2)                      # 只依赖相对位置

5. 简答题

Q24RoPE 怎样用绝对位置的旋转得到相对位置的效果？递归式的线性注意力层还需要位置编码吗？

RoPE 是用绝对位置的旋转实现相对位置的注意力：无参数、内核友好、随距离衰减。对于线性注意力 / Gated DeltaNet 这类递归层，显式位置编码不是必须的——递归本身按顺序扫描、状态随位置累积，天然区分先后；Qwen3-Next / Qwen3.5 的实现里线性层不用 RoPE（前面的短因果卷积提供局部位置信息），只有每 4 层一次的全注意力层用 RoPE。

  • 为什么全注意力需要：softmax 注意力对 token 集合置换等变，没有位置信息就分不清“A 在 B 前”还是“B 在 A 前”（尽管因果掩码会泄露一些，见 NoPE）。
  • 为什么递归层不需要：S_t = f(S_{t−1}, k_t, v_t) 的更新顺序就是位置；门控衰减 α_t 让“更久以前”的信息自然更弱——这本身就是一种随距离衰减的相对位置先验，和 RoPE 的衰减性质殊途同归。Gated DeltaNet 论文没有提到任何位置编码；FLA / HF 的实现中 GDN 层不含 RoPE。
  • 混合架构里的全注意力层仍用 RoPE：Qwen3-Next 的 gated attention 层用 RoPE（HF 配置中为部分旋转，partial_rotary_factor = 0.25，即只旋转 25% 的头维），DeepSeek-V4 对每个 query / KV 条目的最后 64 维做 RoPE。所以答案是：线性层可以去掉，全注意力层通常保留；整个模型层面“位置编码”并非必须，但完全不用的模型目前在长上下文检索上仍有差距。
  • Qwen3.5 的多模态部分：它用三分量的多模态 RoPE（时间、高、宽）处理视觉 token，这是在全注意力层上。
