1. 动机：用 2048 张被限速的 H800 训一个 671B 的 MoE

H800 是 H100 的出口版：算力相同，但 NVLink 带宽被砍（报告用 160 GB/s 对比 IB 的 50 GB/s）。671B 参数、每 token 激活 37B 的 MoE 在这样的集群上训练，瓶颈不是算力而是专家并行的 all-to-all 通信与显存。V3 报告的系统部分围绕三件事：让通信藏进计算（DualPipe + 节点受限路由）、让 FP8 稳定可用（细粒度缩放 + 高精度累加）、让 KV 小到能大 batch 推理（MLA）。最终 2.788M H800 小时训完（按 $2/小时约 557 万美元）。

一句话理解 MoE 的通信是 all-to-all；DeepSeek 把每个 token 限制在 ≤4 个节点内路由，用 IB 发一次到目标节点再用 NVLink 分发，并把这些通信与另一个 micro-batch 的计算流水重叠；FP8 则靠“小块各有缩放因子 + 每 128 个元素就把部分和提升到 FP32”把误差压到 0.25% 以内。

3. 组件拆解

3.1 EP 的通信原语：all-to-all

与 TP 的 all-reduce（所有卡得到同一个和）不同，EP 的 dispatch 是“卡 i 的第 j 块发给卡 j”——一次转置。通信量 ∝ 被路由的 token 数 × 隐维 × 每 token 的专家数，与专家总数无关。节点受限路由把“每 token 最多 M=4 个节点”作为硬约束，IB 上每 token 最多发 4 份而非 8 份。下面用 4 卡演示 all-to-all 与 all-reduce 的差别：

3.3 MLA：每 token 只缓存 576 个数

多头潜在注意力把 K、V 的生成改成“先把隐状态压到 d_c = 512 维的潜向量 c，再由 c 上投影出各头的 K、V”，推理时只缓存 c；RoPE 不能和低秩投影交换顺序，于是另开一个 64 维的“解耦 RoPE key”单独缓存。每层每 token 缓存 512 + 64 = 576 个数，而同等规模的 MHA（128 头 × 128 维 × 2）是 32768 个——约 57×。query 也做低秩压缩（d_c' = 1536）以省训练激活。推理时上投影矩阵可以吸收进 W_Q / W_O（“MQA 模式”），这使得后来的 DSA 能把 top-k 选择做在共享的潜向量上。

5. 简答题

Q20E4M3 与 E5M2 的差别是什么？为什么前向路径选 E4M3，而 DeepSeek-V3 连梯度也用 E4M3？

因为缩放因子的粒度从“整张量”细化到 1×128 / 128×128 的块后，每块内部的动态范围很小，E4M3 的 18 个 binade 足够覆盖，于是可以用精度更高的 E4M3 替代原本推荐给梯度的 E5M2。报告原话：“为了更高精度，所有张量采用 E4M3 格式”，可行性来自细粒度量化策略。通用的 E4M3 vs E5M2 讨论见 FP8 页 Q20。

依据：报告 §3.3.2。

Q21FP8 训练到底节省了什么、没有节省什么？前提是什么？

省的是三个核心 GEMM 的 Tensor Core 时间、反向缓存的激活显存和 dispatch 的通信字节；主权重 / 梯度 FP32、Adam 矩 BF16、敏感算子 BF16 都没省。代价是分块缩放与每 128 元素的 FP32 提升累加。通用解释见 FP8 页 Q21。

Q22专家并行的通信原语是什么？DeepSeek-V3 用哪些办法压低 all-to-all 的代价？

EP 的通信原语是 all-to-all（dispatch 把 token 发到专家所在卡、combine 发回），这是 TP（all-reduce）、DP（all-reduce / reduce-scatter + all-gather）之外的第三种模式；DeepSeek-V3 在其上叠了三项“新做法”：节点受限路由、两跳（IB → NVLink）转发与专用通信 SM、DualPipe 重叠。

  • 为什么是 all-to-all：每张卡的每个 token 要去不同的卡，每张卡又要从所有卡收 token——正好是一次矩阵转置式的交换；通信量 ∝ token 数 × 隐维 × top-k，与专家数无关。
  • 节点受限路由：先选 4 个节点再在其中选 8 个专家，使每 token 的跨节点流量有上界（最多 4 份而不是 8 份）。
  • 两跳转发：IB（50 GB/s）只负责“到目标节点的同号 GPU”，节点内再用 NVLink（160 GB/s）分发；DeepEP 库实现了这套内核，并用 20 个 SM 专跑通信。
  • 重叠：DualPipe 把一个 micro-batch 的 all-to-all 与另一个的注意力 / MLP 计算交错，使通信几乎完全被掩盖。
  • 推理侧：decode 用 EP320（每卡一个专家 + 冗余热门专家），注意力走 DP 而非 TP，避免 all-reduce；通信仍是 all-to-all。

依据：报告 §2.1.2（路由）、§3.2.1–3.2.2（DualPipe、跨节点 all-to-all）、§3.4（推理部署）。

Q23线性注意力混合路线（Qwen3.5）与稀疏注意力路线（DeepSeek / GLM）各自的取舍是什么？

DeepSeek 的路线是“保留精确（softmax）注意力，但把它的内存和计算压下去”：MLA 压 KV（57×）、DSA 压注意力计算（O(L²) → O(Lk)）、V4 再压缩 KV 序列；配合 MoE + EP + FP8 把训练成本压到同规模的几分之一。优势是长上下文下的精细检索能力不打折（GLM-5 报告称 DSA“构造上无损”并因此弃用线性注意力）；代价是仍需 KV cache 与专用稀疏内核。线性注意力混合路线的取舍见 Gated DeltaNet 页 Q23，DSA 细节见 DSA 页 Q23。
