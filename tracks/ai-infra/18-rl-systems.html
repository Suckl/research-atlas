1. 动机：RL 后训练是“推理 + 训练”的混合负载

PPO / GRPO 类算法的一步迭代包含三类完全不同的计算：生成（actor 自回归解码，带宽受限、需要推理引擎）、准备（critic 估值、参考模型 logprob、奖励模型或规则 / 沙箱打分，都是一次前向）、训练（actor 与 critic 的反向与优化器更新，需要 FSDP / Megatron 式的训练并行）。每个节点本身就是一个分布式程序，节点之间要在不同的并行布局之间搬运数据和权重。

一句话理解 HybridFlow（verl）解决“怎么编排”：用单控制器写数据流、多控制器跑每个模型，并让 actor 的同一份权重在训练布局与生成布局之间零冗余切换。AReaL 解决“怎么不空等”：生成与训练彻底解耦为两条流水线，代价是样本会落后于最新策略若干个版本，用陈旧度上限与解耦 PPO 目标来控制。

3. 组件拆解

3.1 混合编程模型：为什么不全用单控制器或全用多控制器

单控制器（如早期 Ray 程序）

一个中心进程调度所有算子，写起来像串行代码、容易改算法；但 LLM 的每个算子要发给成百上千张卡，中心调度开销巨大。

多控制器（SPMD，如 Megatron / DeepSpeed）

每张卡运行同一份程序，没有中心瓶颈；但 RL 的多个模型、多种布局、彼此之间的数据依赖全要硬编码进每个进程，改算法就要改分布式代码。

HybridFlow 取两者之长：节点之间（模型与模型）用单控制器表达数据流；节点内部（一个模型的分布式计算）用多控制器执行。控制器只负责发起调用和按协议重分发数据，不介入每个算子。

3.2 放置：共置、独立还是拆分

放置方式代表特点论文发现何时更优
全部共置（colocate）DeepSpeed-Chat所有模型分时共用全部卡小集群（16–64 卡）
各自独立（standalone）OpenRLHF每个模型独占一组卡13B 模型、128 卡
两两拆分（split）NeMo-Aligneractor + ref 一组，critic + reward 一组34B 模型、更大规模

PPO 的 4 个模型共有 15 种放置（Bell 数），verl 的自动映射算法枚举放置与每组的卡数，用模拟器估算每种并行策略的耗时，取最优。HybridFlow §6、§8.3

3.3 AReaL：完全异步与解耦 PPO

异步之后，生成样本的“行为策略” πbehav 可能比当前参数落后多个版本，甚至一条轨迹前后来自不同版本。直接套用 PPO 的裁剪比值会把信赖域中心放在一个过时的策略上。AReaL 把两个角色拆开：

$$J(\theta)=\mathbb E\Big[\sum_t \frac{\pi_{\text{prox}}(a_t|s_t)}{\pi_{\text{behav}}(a_t|s_t)}\,\min\big(u_t(\theta)\hat A_t,\ \mathrm{clip}(u_t(\theta),1-\epsilon,1+\epsilon)\hat A_t\big)\Big],\qquad u_t(\theta)=\frac{\pi_\theta(a_t|s_t)}{\pi_{\text{prox}}(a_t|s_t)}$$

πprox 是信赖域中心（实现上取每次更新前的参数），πbehav 只出现在重要性权重里修正采样分布的偏差。这与 训推不一致页里 TIS 的思路相通：凡是“样本不是从当前训练器分布里采的”，都需要一个显式的重要性修正。

3.4 之后的系统

verl、AReaL、OpenRLHF、slime 等框架已成为开源 RL 后训练的主流选择，推理端几乎都接 vLLM 或 SGLang。到 2026 年，智能体 RL 把 rollout 变成“多轮工具调用 + 沙箱执行”，单条轨迹可达百万 token：Kimi K3 报告专门描述了带持久 rollout 与沙箱状态的百万 token 智能体 RL 基础设施，以及给 RL 用的外部 KV cache 池。Kimi K3 报告摘要、§5

6. 简答题

Q43同步 RL 训练的 GPU 空转从何而来？异步 RL 如何控制样本陈旧度并修正 off-policy？

同步 RL 里生成与训练交替进行：一批轨迹的长度差异很大，必须等最长的那条生成完才能训练，先完成的卡只能等；训练时生成引擎又闲着。而且生成被摊到所有卡上，每卡 decode batch 变小、处于带宽受限区，加卡不加速。异步 RL（AReaL）把 rollout 卡与训练卡分开，各自满负荷：训练每走一步就推送新权重，正在生成的序列被中断、用新权重重算 KV 后继续。

  • 陈旧度：限制训练 batch 中样本与当前策略的最大版本差 η；超出就暂停派发新生成。η = 0 即同步 RL。
  • off-policy 修正：解耦 PPO——信赖域中心用 πprox（更新前参数），行为策略 πbehav 只出现在重要性权重 πprox/πbehav 中。
  • 即使是“同步”系统，推理引擎与训练引擎的数值差异也会让样本隐式 off-policy，修正思路相同（TIS，见 Q28）。

依据：AReaL 摘要、§3.2、§4.1、§5.1–5.2。

Q44训练和生成共用一份 actor 权重时，如何在两种并行布局之间切换而不浪费显存？

训练偏好较大的 TP × PP（切模型、省显存），生成偏好较小的 TP、较大的 DP（每个副本独立解码、KV 优先）。HybridFlow 的 3D-HybridEngine 让两种布局共享同一批卡和同一份权重：生成组按固定秩间隔从训练组中划出，切换时只需在“微 DP 组”内 all-gather 权重分片，生成结束再丢弃，不常驻第二份副本。

  • 约束：Na = p·t·d = pg·tg·dg·d，其中 dg = p·t/(pg·tg)。
  • 对比：DeepSpeed-Chat 式切换需要全量 all-gather，冗余显存 1/(t·p·d)·M、通信 (tpd−1)/(tpd)·M；HybridFlow 冗余为 0、通信 (tp − tgpg)/(tgpgtp)·M。
  • 实测切换时间平均降 55.2%，70B 时最多降 89.1%（78.2 s）。
  • 另一种选择是生成与训练完全分离（各自一份权重、通过网络推送），这正是异步 RL 的做法——用更多显存换时间上的解耦。

依据：HybridFlow §5、Tab. 2、§8.4。
