2. 软件栈：ROCm 与 CUDA 的对应

2.2 推理 / 训练框架的支持现状

  • vLLM：官方 ROCm 构建与 Docker 镜像，注意力后端用 ROCm 版 FA / Triton / aiter；MI300X 单卡跑 70B 是常见配置。
  • SGLang：ROCm 支持，DeepSeek 模型在 MI300X 上有官方优化路径。
  • 训练：Megatron-LM、PyTorch FSDP、DeepSpeed 均可在 ROCm 上跑；Transformer Engine 有 ROCm 分支；FP8 训练需注意 MI300 的 FNUZ 格式。
  • 通信：RCCL 节点内走 Infinity Fabric，节点间走 RoCE / InfiniBand；与 NCCL 的 API 一致，但不能和 NVIDIA 卡组成一个通信域——这是异构 PD 分离要用厂商中立传输层的原因。

3. 简答题

Q29AMD Instinct / ROCm 与 NVIDIA / CUDA 在硬件形态和软件栈上有哪些差异？迁移时要注意什么？

硬件上 AMD Instinct 走“小芯片 + 大显存”：MI300X 用 8 个 XCD 计算芯片堆在 IO die 上，304 CU、192 GB HBM3 / 5.3 TB/s；MI355X（CDNA 4）288 GB / 8 TB/s，FP8 约 5 PFLOPS 并原生支持 FP4/FP6。软件上 ROCm 栈逐层对应 CUDA：HIP ≈ CUDA 方言（hipify 直译）、rocBLAS/hipBLASLt/CK ≈ cuBLAS/CUTLASS、RCCL ≈ NCCL、Triton 两边通用、PyTorch 的 ROCm 版保持 torch.cuda 接口。

  • 对推理最有利的点：单卡显存大、带宽高——decode 是带宽受限的，70B 模型可以单卡放下并留足 KV；vLLM / SGLang 都有 ROCm 后端。
  • 迁移时的坑：wavefront 64 vs warp 32；LDS 比 shared memory 小；没有 TMA / wgmma 的异步矩阵流水，FA3 式内核要重写（AMD 用 CK / aiter 提供）；MI300 的 FP8 是 FNUZ 变体而非 OCP E4M3；8 个 XCD 的缓存局部性影响内核性能；矩阵乘峰值可达率普遍低于 Hopper。
  • 生态差距：手写 CUDA 内核的库（部分 FlashInfer 功能、某些量化内核）需要移植；Triton 是最省力的跨平台写法。
  • 与 PD 分离的关系：NVIDIA 做 prefill、AMD 做 decode 时，RCCL 与 NCCL 不互通，KV 要经厂商中立的 RDMA 传输层并统一格式——见 PD 分离 Q15。
