1. 动机：数据并行里每张卡都存了一份完整的“模型状态”

数据并行（DP）最简单：每张卡持有完整模型，各算一部分样本，反向后 all-reduce 梯度。问题是显存：用混合精度 + Adam 训练一个 Ψ 参数的模型，每张卡要存

$$\underbrace{2\Psi}_{\text{FP16 参数}} + \underbrace{2\Psi}_{\text{FP16 梯度}} + \underbrace{4\Psi + 4\Psi + 4\Psi}_{\text{FP32 主参数、动量、方差}\;(K\Psi,\ K=12)} = 16\Psi\ \text{字节}$$

7.5B 参数就是 120 GB——单卡放不下，而 N 张卡上存着 N 份一模一样的副本。ZeRO §3、Fig. 1 Megatron 式的模型并行（张量 / 流水线）能切开模型，但要改模型代码、通信频繁、跨节点效率差。

一句话理解 ZeRO 不切计算，只切存储：每张卡仍然完整地跑前向和反向，但优化器状态、梯度、参数在 DP 维度上各只存 1/N，需要时用集合通信临时拼回来。前两级几乎“免费”（通信量与普通 DP 相同），第三级用 1.5× 通信换来显存随卡数线性下降。

3. 组件拆解

3.1 为什么 reduce-scatter + all-gather = all-reduce

环形 all-reduce 本身就是两阶段：先 reduce-scatter（每卡得到 1/N 的完整求和），再 all-gather（把各自的 1/N 广播给所有人），每阶段每卡发送 \((N-1)/N\cdot\Psi\)。ZeRO 的观察是：两阶段之间正好可以插入“只用自己那 1/N 梯度更新自己那 1/N 参数”。下面的演示可切换不同的集合通信：

3.2 剩余显存：ZeRO-R

模型状态之外还有三类“残余”显存，ZeRO 论文用 ZeRO-R 处理：激活——在模型并行下，激活检查点本身也是冗余复制的，ZeRO-R 把它们分片（必要时卸载到 CPU）；临时缓冲区——梯度融合（fused all-reduce）的缓冲区随模型变大，改为固定大小；碎片——长生命周期的张量（检查点、参数梯度）预先放进连续内存，避免分配器碎片导致的 OOM。后续工作 ZeRO-Offload / ZeRO-Infinity 再把优化器状态与参数卸载到 CPU 内存乃至 NVMe。

3.3 PyTorch FSDP：ZeRO-3 的原生实现

FSDP（VLDB 2023）把 ZeRO-3 做进 PyTorch 核心，关键工程选择：

  • 按单元（unit）分片：用户用 wrap 策略把模型切成若干 FSDP 单元（通常一个 Transformer 块一个单元）；每个单元的参数拍平成一个 FlatParameter 再均分。单元是 all-gather / 释放的粒度——单元越大，通信越高效，但峰值显存越高。
  • 预取与重叠：前向时提前 all-gather 下一个单元，反向时按执行顺序预取，让通信与计算重叠；限速器（rate limiter）防止过早预取把显存撑爆。
  • 混合分片（HSDP）：节点内分片、节点间复制——all-gather 留在 NVLink 内，跨节点只做梯度 all-reduce，适合跨节点带宽较低的集群。
  • FSDP2：改为逐参数的 DTensor 分片（按第 0 维切），不再需要 FlatParameter，与张量并行等其他 DTensor 并行更容易组合。

论文报告 FSDP 在小模型上与 DDP 性能相当，同时能训练大得多的模型，TFLOPS 随卡数近似线性扩展。FSDP 论文摘要

3.4 与张量 / 流水线并行的组合

维度切什么通信放在哪
张量并行（TP）单层内的矩阵每层 2 次 all-reduce（激活），量大且频繁节点内（NVLink）
流水线并行（PP）层相邻阶段点对点传激活跨节点
ZeRO / FSDP（DP 维）模型状态每步一次（或每层一次）参数 / 梯度集合通信，可与计算重叠最外层

常见做法：TP 在节点内，PP 跨节点，DP 维上叠 ZeRO-1（Megatron 的“分布式优化器”即 ZeRO-1 式的优化器状态分片）。流水线并行下的梯度要在多个微批间累积，ZeRO-2 / 3 每个微批都要做 reduce-scatter / all-gather，开销被放大，因此 PP 通常只配 ZeRO-1。DeepSpeed 文档称其流水线引擎不支持 ZeRO-2/3。纯 FSDP（不开 TP / PP）在百亿参数以内、单节点带宽充足时最省事，这也是很多 RL 训练框架（verl 的 FSDP worker）的默认后端。

4. 伪代码

fsdp_step.py（ZeRO-3 / FSDP 的一个训练步，按单元）
def train_step(units, batch, rank, N):
    # 每个 unit 只常驻 1/N 的 flat 参数 shard[rank]
    x = batch
    for u in units:                                  # ---- 前向 ----
        full = all_gather(u.shard)                   # 拼回完整参数（可提前预取下一个 unit）
        x = u.forward(x, full)
        free(full)                                   # 立即释放，只留 shard
    loss = x.loss()
    for u in reversed(units):                        # ---- 反向 ----
        full = all_gather(u.shard)                   # 反向还要再拼一次
        g_full = u.backward(full)
        u.grad_shard = reduce_scatter(g_full) / N    # 每卡只留自己那 1/N 的梯度和
        free(full, g_full)
    for u in units:                                  # ---- 优化器：只更新自己的 1/N ----
        adam_update(u.shard_fp32, u.grad_shard, u.m, u.v)
        u.shard = to_bf16(u.shard_fp32)

6. 简答题

Q36ZeRO 的三个阶段各切分什么？每卡显存与通信量分别如何变化？

混合精度 Adam 下每参数 16 字节：FP16 参数 2、FP16 梯度 2、FP32 主参数 + 动量 + 方差 12。ZeRO-1 切优化器状态（每卡 4Ψ + 12Ψ/N），ZeRO-2 再切梯度（2Ψ + 14Ψ/N），ZeRO-3 再切参数（16Ψ/N）。前两级通信量与普通 DP 相同（2Ψ），第三级为 3Ψ（1.5×）。

  • 前两级“免费”的原因：all-reduce = reduce-scatter + all-gather，ZeRO 只是在两步之间插入“每卡只更新自己的 1/N 参数”。
  • ZeRO-3 多出的 Ψ：参数不常驻，前向和反向各要 all-gather 一次。需要按层预取与计算重叠才能掩盖。
  • 数字例子（论文 Fig. 1）：Ψ = 7.5B、N = 64：120 → 31.4 → 16.6 → 1.9 GB。
  • 激活、临时缓冲区、碎片不在这个账本里，由 ZeRO-R（激活分片、固定缓冲区、预分配连续内存）处理。

依据：ZeRO 论文 §5（显存）、§7（通信）、Fig. 1。

Q37FSDP（ZeRO-3）与张量并行、流水线并行如何分工和组合？

三者切的东西不同：TP 切单层矩阵（激活要每层 all-reduce，必须放在 NVLink 域内），PP 切层（阶段间点对点传激活，可跨节点），ZeRO / FSDP 在 DP 维上切模型状态（通信可与计算重叠，放在最外层）。典型组合是节点内 TP、跨节点 PP、DP 维叠 ZeRO-1（Megatron 分布式优化器）。

  • PP 需要在多个微批间累积梯度，ZeRO-2 / 3 会让每个微批都触发 reduce-scatter / all-gather，所以 PP 一般只配 ZeRO-1。
  • 模型能放进“单节点 × FSDP”时，纯 FSDP 最简单，不改模型代码；跨节点带宽差时用 HSDP（节点内分片、节点间复制）。
  • FSDP2 基于 DTensor，可以与 TP 在同一个设备网格上组合（2D 并行）；MoE 模型再加专家并行（EP），见 DeepSeek-V3。

依据：ZeRO §8；FSDP 论文 §3–4；Megatron-LM（PTD-P）论文；DeepSpeed 流水线文档（ZeRO-2/3 不兼容的说法未逐字核对）。
