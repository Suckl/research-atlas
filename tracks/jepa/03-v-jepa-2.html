1. 动机：从“看懂视频”到“预测动作的后果”

V-JEPA 学到的是一个好的视频表征，但它还不是世界模型：世界模型要回答“如果我做动作 a，世界会变成什么样”，并能用来规划。难点在于：

  • 带动作标注的交互数据（机器人轨迹）很贵、很少；而无动作的互联网视频几乎无限。
  • 直接在像素空间做动作条件视频生成（如 Cosmos 这类视频世界模型）规划起来极慢。

V-JEPA 2 的策略是两阶段：先用海量无动作视频把“世界如何运动”的常识学进编码器；再冻结编码器，只用不到 62 小时的机器人视频训练一个动作条件预测器。规划时，在潜空间里搜索能让“预测的未来表征”接近“目标图像表征”的动作。

一句话理解 阶段一学“世界长什么样、怎么动”（观察）；阶段二学“我的动作会怎样改变它”（交互）。两者都发生在同一个表征空间里。

好处有二：大部分迭代在低成本设置下完成；恒定学习率阶段的检查点可以随时接一个冷却阶段，便于做规模化实验。

3.3 3D-RoPE

V-JEPA 使用加性的 3D sin-cos 绝对位置编码。V-JEPA 2 换成旋转位置编码（RoPE）的 3D 版本：把每个注意力头的特征维平均切成三段，分别按 token 的时间 t、高 h、宽 w 坐标做一维旋转：

论文指出 3D-RoPE 能稳定最大模型的训练。相对位置编码也让模型更容易处理训练时没见过的分辨率与时长（渐进分辨率训练正需要这一点）。

3.6 用世界模型规划：能量最小化 + CEM + MPC

给定当前观测 \(x_k\)、当前状态 \(s_k\) 和一张目标图像 \(x_g\)，规划就是找一串动作，使预测的未来表征尽量接近目标表征：

$$\hat a^\star_{1:T} = \arg\min_{\hat a_{1:T}}\ \mathcal E(\hat a_{1:T};\ z_k, s_k, z_g) = \Big\lVert P_\phi\big(\hat a_{1:T};\ s_k, z_k\big) - z_g \Big\rVert_1,\qquad z_k = E(x_k),\ z_g = E(x_g)$$

下面是 CEM + MPC 本身在一个玩具二维环境里的样子（动力学已知，便于观察算法；在 V-JEPA 2-AC 里，动力学换成 Pφ、代价换成表征距离）：

长程任务需要子目标 “抓取并放置”这类多阶段任务，单张最终目标图像不足以引导短视野规划。论文为其提供了两张子目标图像（物体被抓起、物体到达目标附近）再加最终目标图像，依次规划。论文也指出：模型推断出的坐标轴对相机位置敏感，更长视野的任务需要新的建模方法，目前只支持图像目标（不支持语言目标）。

5. 训练目标

阶段一与 V-JEPA 相同：掩码时空 token 上的 L1 特征回归，EMA 目标编码器 + stop-gradient。

阶段二只训练预测器 \(P_\phi\)，编码器 \(E\) 冻结：

$$\mathcal L_\text{tf}(\phi) = \frac{1}{T}\sum_{k=1}^{T}\Big\lVert P_\phi\big((a_t, s_t, E(x_t))_{t\le k}\big) - E(x_{k+1})\Big\rVert_1,\qquad T = 15$$
$$\mathcal L_\text{rollout}(\phi) = \Big\lVert P_\phi\big(a_{1:T}, s_1, z_1\big) - z_{T+1}\Big\rVert_1,\qquad T = 2$$
$$\mathcal L(\phi) = \mathcal L_\text{tf}(\phi) + \mathcal L_\text{rollout}(\phi)$$
  • teacher forcing：每一步都喂真实的历史表征，块因果掩码让 15 个“预测下一帧”的任务在一次前向中并行完成。
  • rollout：从第一帧出发，把模型自己的预测 ẑ₂ 当作输入再预测 ẑ₃（T = 2，只反向传播一个递归步）。它让模型适应推理时“吃自己输出”的分布偏移。
防坍塌：冻结即是答案 阶段二不存在坍塌问题：目标 \(E(x_{k+1})\) 由冻结的编码器给出，预测器无论怎么学都改变不了目标。代价是编码器不能根据控制任务调整——这正是 LeWM 想重新端到端训练的原因之一。

6. 伪代码

ac_train_step.py（按 app/vjepa_droid/train.py 结构整理，有简化）
TPF = (256 // 16) ** 2                                  # tokens_per_frame = 256

def ac_train_step(clips, actions, states):              # clips [B,3,16,256,256]; actions [B,15,7]; states [B,16,7]
    with torch.no_grad():                               # 编码器冻结
        c = clips.permute(0, 2, 1, 3, 4).flatten(0, 1)  # [B*16, 3, 256, 256]  逐帧
        c = c.unsqueeze(2).repeat(1, 1, 2, 1, 1)        # 每帧复制成 2 帧 → 一个 tubelet
        h = encoder(c)                                  # [B*16, 256, 1408]
        h = h.view(B, 16, TPF, -1).flatten(1, 2)        # [B, 16*256, 1408]
        h = F.layer_norm(h, (h.size(-1),))
    z = h

    # 1) teacher forcing：输入真实 z_1..z_15，并行预测 z_2..z_16
    z_tf = predictor(z[:, :-TPF], actions, states[:, :-1])
    loss_tf = (z_tf - h[:, TPF:]).abs().mean()

    # 2) rollout（T=2）：[z_1, ẑ_2] → ẑ_3，把自己的预测喂回去
    z_ar = torch.cat([z[:, :TPF], z_tf[:, :TPF]], dim=1)
    z_3 = predictor(z_ar, actions[:, :2], states[:, :2])[:, -TPF:]
    loss_ro = (z_3 - h[:, 2 * TPF:3 * TPF]).abs().mean()

    loss = loss_tf + loss_ro
    loss.backward(); optimizer.step(); optimizer.zero_grad()   # 只有 predictor 的参数
plan.py（CEM，示意）
def plan_one_action(x_now, s_now, x_goal, n=800, iters=10, T=1, k=...):
    z_now, z_goal = E(x_now), E(x_goal)
    mu, sigma = torch.zeros(T, 7), torch.ones(T, 7)
    for _ in range(iters):
        a = mu + sigma * torch.randn(n, T, 7)
        a = project_l1_ball(a, radius=0.075)            # 每步末端位移不超过约 13 cm
        z_pred = rollout(P, z_now, s_now, a)            # 潜空间 rollout，不生成像素
        energy = (z_pred[:, -1] - z_goal).abs().mean(dim=(-2, -1))
        elite = a[energy.topk(k, largest=False).indices]
        mu, sigma = elite.mean(0), elite.std(0)
    return mu[0]                                        # MPC：执行第一步后重新规划

9. 承上启下

V-JEPA 2 做到了

  • JEPA 训练可以规模化到 1B 参数、百万小时视频；
  • 同一个冻结编码器同时服务于理解、预判、问答与控制；
  • 只用几十小时无标注交互数据就得到能零样本规划的潜空间世界模型，比像素级世界模型快一个数量级以上。

留下的问题 → LeWorldModel

  • 重：1B 编码器 + 300M 预测器，每帧 256 个 1408 维 token，规划一步约 16 秒；
  • 不端到端：编码器冻结，表征不针对控制优化；
  • 启发式：阶段一的防坍塌仍靠 EMA + stop-grad。能否用一个有理论依据的正则，从像素开始稳定地端到端训练一个小而快的世界模型？
