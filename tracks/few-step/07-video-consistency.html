1. 动机：视频扩散每一步都比图像贵一个数量级

2023 年的开源文生视频模型（ModelScopeT2V、VideoCrafter、基于 SD1.5 的 AnimateDiff）基本都是“图像 U-Net + 时间层”，采样仍沿用约 50 步 DDIM VideoLCM §1。视频一次前向要处理 16 帧潜变量，再叠加 CFG 的条件 / 无条件两次前向，生成一段几秒的视频要几十秒到几分钟：VideoLCM 在 A100 上测得 8 段 16×448×256 的视频，50 步 DDIM 需 104 s VideoLCM Tab. 1。与此同时，图像侧的 LCM 已经证明：在潜空间里对“CFG 增强的 PF-ODE”做一致性蒸馏，4 步就能出可用的图。

本页覆盖把这套配方搬到视频上的第一波工作（2023-12 至 2024-10）。它们都是 SD 系 VP 扩散：\(x_t=\alpha_t x_0+\sigma_t\epsilon\)，教师预测噪声 \(\epsilon\)，时间是 1000 步离散网格上取出的子序列 \(t_1\lt\dots\lt t_N\)；学生是一致性函数 \(f_\theta(z_t,t)\)，直接把带噪视频潜变量映到 \(\hat z_0\)。 VideoLCM §1、Tab. 1 LCM §3

一句话理解 视频 U-Net 只是“膨胀”过的图像 U-Net，所以 LCM 的整套做法——潜空间、CFG 增强的 DDIM 教师一步、跳步 \(k\)、EMA 目标网络、LoRA——几乎可以原样移植，VideoLCM 就是这么做的。问题在于学生的质量被两道天花板压住：教师本身（在低质量 WebVid 上训练）和用来蒸馏的数据。AnimateLCM 把“画面”和“运动”拆开，用高质量图像学画面、用视频只学运动；T2V-Turbo 则发现计算一致性损失时本来就有一个免费的一步生成 \(\hat z_0\)，直接对它加奖励梯度，学生于是可以超过教师。

3. 组件拆解

3.1 从图像到视频：LCM 搬到视频 U-Net 后坏了什么

继承了什么。这一波方法几乎完整继承了 LCM：潜空间一致性蒸馏、把 CFG 写进 ODE 求解器、跳步网格、EMA 目标网络，以及 LCM-LoRA 式的“加速 LoRA”。视频 U-Net 本身就是图像 U-Net 加时间层，所以 cskip / cout 参数化、ε→x0 的换算都不用改。往前追溯，它们属于 一致性模型 的“蒸馏”分支（需要教师给出轨迹上的相邻点）。

哪些假设不再成立。

  • 数据质量：LCM 在 LAION 级别的图像上蒸馏；视频这边可用的公开数据（WebVid）分辨率低、带水印、字幕短而含糊 AnimateLCM §4.2。一致性蒸馏的样本来自训练数据加噪，学生的画质于是同时被“教师在 WebVid 上学到的画质”和“蒸馏数据的画质”两道天花板压住 T2V-Turbo §1。
  • 时间结构在极少步时最先崩：VideoLCM 观察到 1 步时不仅模糊，物体的时间结构也保不住，4–6 步才接近 50 步 DDIM VideoLCM §4.3；只有带深度等结构条件的组合生成能降到 1–2 步。
  • 插件生态失配：为图像扩散训练的 ControlNet / T2I-Adapter 接到视频一致性模型上还能用，但会丢细节、出现闪烁 AnimateLCM §4.3、Fig. 6；而这些插件没有对应的视频教师可蒸。
  • 显存：每个样本 16 帧，奖励反馈要把 16 帧解码回像素再过奖励模型；T2V-Turbo 每卡 batch 只能放 1 段视频 T2V-Turbo 附录 A。若像 InstructVideo 那样对整条采样链反传奖励，显存不可承受，只能截断到最后一步 T2V-Turbo §1。

具体改了什么：AnimateLCM 把“画面先验”和“运动先验”拆成两个阶段分别蒸（下节）；用一步 MCMC 近似代替教师分数，做无教师的插件适配；T2V-Turbo 把奖励梯度加在一致性损失顺带产生的一步生成上，并加入视频文奖励补时间维度；v2 再把数据按目标拆开（高质量长字幕数据只算 CD，短字幕数据算奖励），并把从训练视频提取的运动先验写进教师求解器。

3.2 VideoLCM：最直接的移植（2023-12）

VideoLCM 是一份技术报告：教师取 TF-T2V 发布的预训练视频扩散模型（文生视频与 VideoComposer 式组合生成两类），学生与教师同结构、由教师初始化，DDIM 作求解器，固定 w = 9.0 以保持与教师完全相同的网络结构——LCM 原本把 w 编码后注入网络，那需要新增模块 VideoLCM §3.2。训练规模很小：4 张 A100（1 张喂图像、3 张喂视频）、约 4k 次迭代、学习率 1e-5、EMA 0.95、16 帧 448×256 VideoLCM §4.1。它的价值在于给出了基线：文生视频 4–6 步、深度引导等组合任务 2–4 步（有时 1 步）可用 VideoLCM §4.3。作者自己列出的局限也正是后续工作的切入点：强依赖教师、在域外数据上蒸馏效果差、4–6 步仍不是实时 VideoLCM §4.5。

3.3 AnimateLCM：图像先验与运动先验解耦（2024-02）

AnimateLCM 基于 SD1.5，教师是 SD1.5 + 开源 AnimateDiff 运动模块 AnimateLCM §5.1。它的出发点是：一致性蒸馏的最终画质很大程度取决于训练数据，而高质量图文数据远多于高质量视频。于是分两阶段：

  • 为什么能解耦：视频扩散模型本来就是“冻结的图像空间层 + 训练的时间层”（AnimateDiff 正是冻结 SD 的空间权重）。把空间层的一致性先在图像上学好，视频阶段只需让时间层学会在一致性目标下建模运动。
  • 换风格：由于空间权重就是 SD1.5，可以直接换成社区的个性化 SD1.5 模型。换成 Realistic Vision V5.0 后，UCF-101 零样本 FVD 在 1 步从 1256.50 降到 1071.50 AnimateLCM Tab. 1（4、8 步反而变差，作者归因于个性化模型与 UCF-101 的域差）。
  • 无教师适配：对插件（图生视频的图像编码器、ControlNet / T2I-Adapter）没有现成的视频教师。AnimateLCM 用“同一噪声 ε0、两个时间点”的一步估计代替教师 ODE 步：若 xt = √αt x + √(1−αt) ε0，DDIM 一步恰好给出 √αt−1 x + √(1−αt−1) ε0 AnimateLCM Eq. 11–12——这本质上就是一致性模型原文的“一致性训练”（CT），以一定偏差换来不需要教师。用它从头训练了图生视频适配器，并给现有布局插件加 LoRA 微调，控制稳定性明显改善 AnimateLCM Fig. 6。

3.4 T2V-Turbo / -v2：把奖励梯度加在“免费的一步生成”上

T2V-Turbo 的观察很简单：一致性损失里的 \(f_\theta(z_{t_{n+k}},w,c,t_{n+k})\) 就是一次完整的一步生成。对它解码、打分、反传，只多一次 VAE 解码和奖励模型前向，不用穿过多步采样链 T2V-Turbo §3。两类奖励分工不同：图文奖励（HPSv2.1）只看单帧的美学与图文对齐，对随机抽的 M 帧求和；视频文奖励（InternVid2 S2 或 ViCLIP）看整段，补上帧间动态与过渡 T2V-Turbo §3.1–3.2。消融显示单用 Rimg 已带来大部分收益（VC2：Total 73.97 → 80.42），再加 Rvid 主要提升语义分（71.70 → 74.76） T2V-Turbo Tab. 2。

T2V-Turbo-v2（ICLR 2025）在三个方向上扩展：① 数据：高质量、长字幕的 VidGen-1M 与 WebVid-10M 各半；CD 损失用全部数据，奖励只在短字幕的 WebVid 上算，因为奖励模型的文本上下文只有 77（HPSv2.1 / CLIP）或 40（InternV2）个 token T2V-Turbo-v2 §4.2；② 奖励：HPSv2.1 + CLIPScore + InternV2 的组合，并指出“哪个奖励最有用”依赖于数据集；③ 条件引导：把 MotionClone 的时间注意力引导写成能量函数 \(\mathcal G\) 加进教师求解器，参考视频就是训练视频本身（生成提示正是它的字幕），并把昂贵的 DDIM 反演挪到训练前的预处理阶段 T2V-Turbo-v2 §3.2。v2 还去掉了 EMA 目标网络，改为全参数训练 T2V-Turbo-v2 §3.1。

5. 训练目标

CFG 增强的教师一步（\(\Psi\) 为 DDIM，\(k\) 为跳步）：

$$\hat z^{\Psi,w}_{t_n}=z_{t_{n+k}}+(1+w)\,\Psi(z_{t_{n+k}},t_{n+k},t_n,c)-w\,\Psi(z_{t_{n+k}},t_{n+k},t_n,\varnothing)$$

一致性蒸馏损失（VideoLCM 固定 \(w\)，学生不显式接收 \(w\)）：

$$\mathcal L_\text{CD}=\mathbb E_{z,c,w,n}\Big[\lambda_n\, d\big(f_\theta(z_{t_{n+k}},w,c,t_{n+k}),\ f_{\theta^-}(\hat z^{\Psi,w}_{t_n},w,c,t_n)\big)\Big],\qquad d(x,y)=\sqrt{\lVert x-y\rVert_2^2+c^2}-c$$

\(\lambda_n=(1-\delta n/N)^\gamma\) 只在 AnimateLCM 中使用。T2V-Turbo 的总目标：

$$\mathcal L=\mathcal L_\text{CD}-\beta_\text{img}\,\mathbb E\sum_{m=1}^{M}R_\text{img}(\hat x_0^m,c)-\beta_\text{vid}\,\mathbb E\,R_\text{vid}(\hat x_0,c),\qquad \hat x_0=\mathcal D\big(f_\theta(z_{t_{n+k}},w,c,t_{n+k})\big)$$

T2V-Turbo-v2 的两处修改：目标网络换成 \(\mathrm{sg}[f_\theta(\cdot)]\)；教师一步再加运动能量的梯度，\(\hat z^{\Psi,w,\lambda}_{t_n}=\hat z^{\Psi,w}_{t_n}+\lambda\nabla_{z}\mathcal G^m(z_{t_{n+k}},z^\text{ref}_{t_{n+k}},t_{n+k})\)，其中 \(\mathcal G^m\) 比较生成与参考视频的时间注意力图（只保留每行最大值处），只在前 \(\tau=50\%\) 的步上施加 T2V-Turbo-v2 Eq. 6–9、§4。

6. 伪代码

video_lcd_step.py（按 T2V-Turbo Algorithm 1 改写；注释标出其他两篇的差别）
def train_step(video, text):
    z = vae.encode(video)                              # [B, 4, 16, h, w]，VAE 冻结
    n = randint(1, N - k)                               # 网格下标；k = 20（T2V-Turbo）
    w = uniform(5, 15)                                  # VideoLCM：固定 w = 9，学生不接收 w
    z_tk = q_sample(z, t[n + k], randn_like(z))         # 前向加噪到 t_{n+k}
    with no_grad():                                     # 教师：CFG 增强的 DDIM 一步
        eps = (1 + w) * teacher(z_tk, t[n + k], text) - w * teacher(z_tk, t[n + k], null)
        z_tn = ddim_step(z_tk, eps, t[n + k], t[n])
        # AnimateLCM 无教师适配：z_tn = q_sample(z, t[n], 同一个噪声)，不调用教师
        target = ema_student(z_tn, w, text, t[n])       # v2：改为 student(...).detach()
    z0_hat = student(z_tk, w, text, t[n + k])           # 一步生成（LoRA 可训练）
    loss = huber(z0_hat, target)                        # AnimateLCM：再乘 λ_n
    if use_reward:                                      # 仅 T2V-Turbo / -v2
        x0_hat = vae.decode(z0_hat)                     # 16 帧解码，带梯度（显存大头）
        frames = x0_hat[:, :, randperm(16)[:M]]         # M = 6（v2：M = 2）
        loss = loss - beta_img * hps_v21(frames, text).sum() \
                    - beta_vid * video_rm(x0_hat, text)  # InternVid2 S2 或 ViCLIP
    loss.backward(); opt.step(); opt.zero_grad()
    ema_update(ema_student, student, mu)                # VideoLCM：mu = 0.95

def sample(text, steps=4):                              # 多步一致性采样，无 CFG
    z = randn(shape)
    for i, tau in enumerate(taus(steps)):               # 从大到小的时间点
        x0 = student(z, w_infer, text, tau)
        z = q_sample(x0, taus(steps)[i + 1], randn_like(x0)) if i + 1 < steps else x0
    return vae.decode(z)

简答题

Q13把 LCM 直接搬到视频 U-Net 上，学生画质为什么会被“双重封顶”？AnimateLCM 的解耦一致性学习和初始化策略是如何绕开的？

一致性蒸馏的样本是“训练数据加噪”，目标是教师在这条轨迹上的 ODE 走向，所以学生同时受限于教师的画质和蒸馏数据的画质；公开视频数据（WebVid）低分辨率、带水印、字幕短，两道上限都很低。AnimateLCM 利用“视频模型 = 冻结的图像空间层 + 时间层”这一结构，先在高质量图像上把空间层蒸成图像一致性模型（只训 LoRA），再膨胀成 3D、冻结空间部分，只让时间层在视频上学一致性——画面先验来自好数据，视频只负责运动。

  • 初始化细节：空间 LoRA 起初只插入在线模型，不插入 EMA 目标模型，避免“LoRA + 未训练时间层”的组合在训练初期给出损坏的目标；LoRA 再经 EMA 逐步流入目标。
  • 证据：同样 8 小时预算下，直接在视频上做一致性蒸馏明显不如“4 h 图像 + 4 h 视频”，去掉初始化策略也会变差（Fig. 5）。
  • 副产品：空间层仍是 SD1.5，可直接换成个性化风格模型；1 步 FVD 由 1256.50 降到 1071.50。 AnimateLCM v1 §4.2、Fig. 5 Turbo §3、Tab. 2 v2 §4.2
  • VideoLCM 的做法是混入 LAION 图像联合训练，但没有把两类先验分开蒸，因此没有获得同样的解耦收益。

依据：AnimateLCM §4.2、Fig. 3、Fig. 5、Tab. 1；VideoLCM §4.1；T2V-Turbo §1（“VCM 受教师质量所限”）。

Q14T2V-Turbo 为什么无需反传整条采样链就能把奖励梯度加进一致性蒸馏？为什么既要图文奖励又要视频文奖励，且 CD 损失不能去掉？

算一致性损失时，学生已经从 \(z_{t_{n+k}}\) 一步预测出完整的干净潜变量 \(\hat z_0\)；把它解码后直接送进可微奖励模型，梯度只穿过“学生一次前向 + VAE 解码 + 奖励模型”，不像 InstructVideo 那样要穿过整条多步采样链（后者只能截断到最后一步）。图文奖励只能逐帧评美学与对齐，看不到运动与过渡，所以再加一个整段视频的视频文模型；消融里单用 Rimg 拿到大部分 Total 提升，加 Rvid 主要提升语义分。

  • 数字（VC2，4 步）：VCM 73.97 → +Rvid 77.57 → +Rimg 80.42 → 两者 81.01；语义分 55.66 → 74.76。 AnimateLCM v1 §4.2、Fig. 5 Turbo §3、Tab. 2 v2 §4.2
  • CD 损失的作用是正则：v2 发现若把 CD 数据与奖励数据完全分开（高质量数据只算 CD、短字幕数据只算奖励），会出现颜色失真，说明 CD 防止了奖励的过度优化；因此 CD 用全部数据，奖励只在短字幕子集上算。
  • 仍有代价：16 帧解码带梯度很占显存，T2V-Turbo 每卡 batch 只能放 1 段；奖励模型的文本上下文（77 / 40 token）限制了它在长字幕数据上的效果。 AnimateLCM v1 §4.2、Fig. 5 Turbo §3、Tab. 2 v2 §4.2
  • 奖励作用在不同噪声水平的一步预测上：大 t 时 \(\hat z_0\) 接近真正的一步生成，小 t 时更接近数据重建（这一点是推论，论文未单独分析）。

依据：T2V-Turbo §1、§3、Tab. 2、附录 A；T2V-Turbo-v2 §4.2、附录 C.2。
