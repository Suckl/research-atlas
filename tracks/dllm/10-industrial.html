1. 动机：工业界为什么要做 dLLM

三家公开了技术报告的工业 dLLM 都以速度为主要卖点。DiffusionGemma 给出的论证最完整：AR 在单请求或低并发时受访存带宽限制，搬运权重与 KV cache 的时间远多于计算，加速卡的算力大量闲置；扩散一次前向处理整块 token，把解码从访存受限推向计算受限DiffusionGemma §1、§6。作为对比，推测解码在草稿长度 8 时通常只有 3–6 TPFDiffusionGemma §1（引 Li et al. 2026）。

Mercury Coder（Inception，2025-06）与 Seed Diffusion Preview（字节 Seed，2025-08）是最早的两份报告，以代码任务为主，但方法细节披露很少；DiffusionGemma（Google DeepMind，2026-07）是开放权重的通用模型，报告也最详细。本页先给出三者共同的骨架，再逐个说明它们公开了什么、没公开什么，以及速度数字分别是怎么测的。

一句话理解 工业 dLLM 的骨架大致相同：从 AR 权重出发，按块（画布）生成以复用 KV cache，再用蒸馏或在线学习把去噪步数压到十步量级。不同之处在于噪声类型（掩码、均匀、编辑）和压缩步数的手段；而速度数字只有在写明硬件、精度、batch、基准与 AR 基线之后才有意义。

记号：画布 \(x_t\in\mathcal V^{C}\)，\(t=1\) 为全噪声；DiffusionGemma 的画布长 \(C=256\)，最大步数 \(N\)，熵预算 \(b\)；论文用 \(\tau_t\) 表示温度，本页写作 \(\mathrm{temp}(t)\)，以免与本轨道的置信度阈值 \(\tau\) 混淆DiffusionGemma §2.1、§3.2。

3.2 DiffusionGemma 的噪声：均匀，不是掩码

前向过程对每个位置独立地以 \(\kappa_t\) 保留原 token、以 \(1-\kappa_t\) 替换成均匀随机 token，\(\kappa_0=1,\ \kappa_1=0\)：

$$\mathbb P(X_t=x_t\mid X_0=x_0)=\prod_{i=1}^{C}\Big[\kappa_t\,\delta(x_t^i,x_0^i)+(1-\kappa_t)\tfrac{1}{V}\Big].$$

报告在 §3.2 明确写道，去噪迭代使用多项式（均匀）扩散而不是掩码扩散，理由是所有 token 之间都可以相互转移，模型能持续纠正自己的错误；SFT 一节也写明从词表均匀采样噪声 token；Alg. 1 的初始化与“未接受位置重新加噪”同样是均匀分布DiffusionGemma 式 (1)、§3.2、§4、Alg. 1 第 7、30 行。

冲突的处理：以技术报告为准第三方分析 Neither Parallel Nor Sequential（arXiv 2606.14620，2026-06-12 提交，早于技术报告的 2026-07-31）在摘要中把 DiffusionGemma 26B 称为“masked discrete-diffusion MoE”。这与报告原文不符，本页以报告为准。报告 §3.2 在可解释性说明中引用了这篇分析，但没有采用“masked”的说法。推测：第三方分析统计的是采样器每步的“接受”位置；熵界采样器源自掩码扩散文献，可能因此被归为掩码扩散。这一点未在其正文中核实。2606.14620 摘要；DiffusionGemma §3.2

3.3 DiffusionGemma 的两段训练：SFT 与 SD·RL

SFT：从 Gemma 4 26B A4B 出发，用块对角注意力让每个 256 token 画布块内双向、块间互不可见，前面的干净 token 通过编码器 KV 提供条件；每个画布采样 \(t\sim\mathrm U[0,1]\)，每个 token 以概率 \(t\) 被替换。损失是画布上全部位置的交叉熵（均匀噪声下，没被替换的位置也必须判断“是否已正确”）。非思考模式只需中等量的 SFT，思考模式需要长时间 SFT，否则推理链容易陷入重复或循环§4、式 (11)、Fig. 6–7。

SD·RL：SFT 模型在步数多时质量好，但在少步区间会崩（陷入重复 token，熵骤降、提前触发停止）。SD·RL 用在线教师（步数多、温度退火温和）生成去噪轨迹，同一次梯度更新中同时做奖励最大化与采样器蒸馏。随着熵下降，自适应停止越来越早触发，训练分布自动转向更短的轨迹，形成一种隐式课程。结果是 GPQA-Diamond + LiveCodeBench-v6 的综合分提高约 10 分，TPF 从约 5 提高到接近 20，输出长度约缩短一半，总前向次数不到 Gemma 4 AR 基线的 5%§5、Fig. 8–9。SD·RL 的目标函数没有以公式形式公开。

微调后的权重仍能装回原架构做因果 AR 生成，分数介于扩散模式与原 Gemma 4 之间§3.5、Tab. 3。

3.4 Mercury Coder：公开了什么

Mercury 是 Inception Labs 的商用 dLLM，报告只覆盖代码模型 Mercury Coder Mini 与 Small。公开内容有：Transformer 架构；训练是在一般形式的加权去噪损失 \(\mathcal L=-\mathbb E_t[\gamma(t)\,\mathbb E_{z_t}\log p_\theta(x\mid z_t)]\) 上进行的，“扩展了 SEDD”；训练数据为数万亿 token 量级；上下文 32,768，借助扩展方法可到 128kMercury §2.1。没有公开的内容包括：参数量、噪声类型、步数、TPF、少步化方法。速度来自自研推理引擎（动态 batching、分页、定制 kernel）Mercury §2.2。

代码能力的亮点是 FIM（填空）：Small 在单行 / 随机片段上为 93.1 / 76.5，Codestral 2501 为 93.0 / 72.0Mercury Tab. 3。Copilot Arena 上 Mini 的 Elo 993，与 Codestral 并列第 2；延迟排名第 1Mercury Tab. 4。

3.5 Seed Diffusion Preview：两段课程、受限顺序与 on-policy

两段课程（TSC）：前 80% 的训练步用标准掩码噪声；后 20% 再加入基于编辑的噪声，编辑操作数 \(k_t=\lfloor |x_0|\,\alpha_t\rfloor\)，\(\alpha_t\in[0,0.1]\)，近似控制 Levenshtein 距离。作者不采用“carry-over unmasking”（未掩码 token 直接复制到输出），理由是纯掩码训练会让模型认为“未被掩码的 token 都是对的”，从而过度自信、无法自我纠错Seed §3.1、Remark 3.1。

受限顺序：掩码扩散等价于对所有顺序的任意顺序 AR，其中很多顺序与语言结构不符。作者用预训练好的扩散模型大规模生成候选轨迹，按 ELBO 最大化挑选，再用这些轨迹微调Seed §3.2 式 (7)(9)。on-policy 学习：直接优化 \(\mathbb E[|\tau|-V(\tau[0])]\)，即在验证器 \(V\) 保证答案合理的前提下缩短采样轨迹；直接最小化 \(|\tau|\) 不稳定，改用基于轨迹内 Levenshtein 距离的渐进代理目标Seed §3.3 式 (10)(11)。推理是块级半自回归，前面的块用 KV cache；块长按单步耗时与每步产出 token 数的权衡选取，数值未给出Seed §3.4、Fig. 2。

报告给出的效率口径（\(C_k\) 为第 k 块的有效 token 数，\(N_k\) 为其步数，\(K\) 为块数）：

$$\mathrm{TPF}=\frac{\sum_k C_k}{\sum_k N_k+K-1},\qquad \mathrm{TPS}=\frac{\mathrm{TPF}}{t_{\text{fwd}}},\qquad \frac{\mathrm{TPS}_{\text{diff}}}{\mathrm{TPS}_{\text{AR}}}=\frac{\mathrm{TPF}}{r}.$$

5. 训练目标与似然

DiffusionGemma 的 SFT 损失没有 ELBO 时间权重，直接在全部 \(C\) 个位置上计算交叉熵，条件是噪声画布、自条件与上下文 KV：

$$L(\theta)=-\sum_{i=1}^{C}\log p_\theta\big(x_0^i\mid x_t,z_t,H\big),\qquad t\sim\mathrm U[0,1].$$

其中 \(x_t\) 由干净画布逐 token 以概率 \(t\) 替换为均匀随机 token 得到DG §4。

反向一步用离散流匹配的 Euler 更新：\(\mathbb P(X_{t-\Delta t}^i=v\mid x_t)\approx\delta(v,x_t^i)-\Delta t\,\frac{\dot\kappa_t}{1-\kappa_t}\big[p_\theta(v\mid x_t)-\delta(v,x_t^i)\big]\)（报告脚注 1 的示例；实际采样用的是 Alg. 1 的熵界规则）DG §2.1.2。Seed Diffusion 的目标把 ELBO 的重建项换成编辑噪声下的去噪项：

$$L_{\text{diff}}=-\mathbb E_{q_{\text{edit}},t}\log p_\theta(x_0\mid x_t)-\mathbb E_{q_{\text{mask}},t}\Big[\frac{\gamma_t'}{\gamma_t}\sum_i\mathbb 1[x_t^i=[\mathrm M]]\log p_\theta(x_0^i\mid x_t)\Big].$$

其中 \(\gamma_t\) 是掩码概率Seed 式 (5)(6)。三家都没有报告精确似然；DiffusionGemma 与 Seed 的评测都基于生成结果。

论文笔误Seed 式 (6) 的掩码项写作 \(p_\theta(x_0[i]\mid x_t[i])\)，即只以第 i 个位置为条件，按上下文应为整个 \(x_t\)；正文说“由式 (6) 的 ELBO 推出”，实际是式 (5)；“langevin distance” 应为 Levenshtein distance。Seed §3.1

6. 伪代码

diffusiongemma_sample.py（技术报告 Alg. 1 + §3.1 块自回归外循环）
def generate(model, h, C=256, N=48, b=0.1, e_stop=0.005, temp_max=0.8, temp_min=0.4):
    H = model.encode(h)                          # 因果注意力，建 KV cache
    response = []
    while True:
        x = uniform_tokens(C)                    # x_1 ~ Unif(V^C)，没有 [MASK]
        z = zeros(C, d)                          # 自条件信号
        prev = None
        for n in range(1, N + 1):
            t = 1 - (n - 1) / N
            L = model.decode(x, z, H)            # 画布内双向 + 交叉注意 H -> [C, V]
            x_hat = L.argmax(-1)                 # 当前确定性预测
            temp = (temp_max - temp_min) * t + temp_min
            p = softmax(L / temp)
            e = entropy(p)                       # 每个位置的熵，形状 [C]
            if n > 1 and e.mean() <= e_stop and x_hat == prev:
                break                            # 自适应停止
            prev = x_hat
            if n < N:
                z = model.selfcond_ffw(p @ E)    # E: 嵌入矩阵
                draw = sample(p)
                order = argsort(e, stable=True)  # 熵从小到大，同熵按位置
                k = max(m for m in range(1, C + 1) if e[order[:m - 1]].sum() <= b)
                x = uniform_tokens(C)            # 未接受的位置重新均匀加噪
                x[order[:k]] = draw[order[:k]]
        response.append(x_hat)                   # 提交：画布从此冻结
        if END_OF_TURN in x_hat:
            break
        H = H + model.encode(x_hat)              # 额外一次前向，追加 K/V
    return concat(response)

简答题

Q19三家工业 dLLM 的配方有哪些共同点？DiffusionGemma、Mercury、Seed Diffusion 分别在初始化、噪声、块 / 画布、少步化与 RL 上怎样取舍，哪些环节根本没有公开？

共同点：都按块或画布生成，以复用前文的 KV cache；都把“少步”当作核心训练目标，而不只是推理技巧。区别在于：DiffusionGemma 从 Gemma 4 AR 权重出发、使用均匀噪声，并把采样器蒸馏与 RL 合并为 SD·RL；Seed 先掩码后编辑噪声，再用受限顺序蒸馏与 on-policy 学习缩短轨迹；Mercury 只公开了“扩展 SEDD”的一般形式。

  • 初始化：只有 DiffusionGemma 写明是 AR 初始化（Gemma 4 26B A4B，不到 10% 的 token）；Mercury 与 Seed 都没有写。
  • 噪声：均匀（DiffusionGemma）、掩码 + 编辑（Seed）、未披露（Mercury）。均匀噪声与编辑噪声都是为了让已写 token 可以被改写，这与 LLaDA2.1 的 T2T 出于同一动机。
  • 画布：DiffusionGemma 256 token、因果编码器 + 双向解码器；Seed 半自回归块 + KV cache，块长未给；Mercury 未披露。
  • 少步化：SD·RL 借助自适应停止形成隐式课程（TPF 约从 5 提高到 20）；Seed 直接最小化轨迹长度，由验证器约束质量。
  • 完全未公开的部分：Mercury 的参数量、噪声、步数与少步方法；Seed 的参数量、是否 AR 初始化、块长；DiffusionGemma SD·RL 的损失公式。

依据：DiffusionGemma 摘要、§3–5；Mercury §2；Seed §3。

Q20“约 1,500 tok/s（H100）”“1,109 tok/s（H100）”“2,146 tok/s（H20）”能直接比较吗？各自的测量口径是什么，缺了哪些条件？

不能直接比较。DiffusionGemma 是在单卡 H100、FP8、batch 1 下，7 个基准的平均（不含 prefill），并在同一设备上测了 AR 基线；Mercury 的数字由 Artificial Analysis 在 H100 上测得，使用其专有的约 1k 输入 / 1k 输出代码 prompt，在 Mercury 自研引擎上运行，对照对象是各家 API 的中位数；Seed 只写了 H20 与 8 个代码基准，没有 batch，也没有同条件的 AR 速度。

  • dLLM 的优势来自把访存受限的解码变成计算受限，并发一高就会消失：DiffusionGemma 自己测得约 32 并发以上 AR 总吞吐反超。所以不写 batch 的速度数字无法解读。
  • TPS 还取决于输出长度和任务：DiffusionGemma 在 IFEval 不思考模式下只有 732 TPS，GSM8K 为 1966；Seed 也提到格式约束类系统提示可能抬高速度。
  • 同一模型在不同条件下数字差异很大：LLaDA2.1 Flash 作者自报 HumanEval+ 891.74 TPS（FP8），DiffusionGemma 在 8 × B200、BF16 下测得 7 项平均 375 TPS。
  • 只有博客的数字（Gemini Diffusion 1479 tok/s 不含 0.84 s 开销；Mercury 2 在 Blackwell 上 1,009 tok/s）都属于厂商自报，硬件或负载不明。

依据：DiffusionGemma §6、Tab. 3–4、Fig. 12、App. E；Mercury §3.2.1；Seed 摘要、Fig. 1；LLaDA2.1 Tab. 3。
