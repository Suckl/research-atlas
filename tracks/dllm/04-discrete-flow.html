1. 动机：把“去噪”换成“输运”

MDLM / MD4 从“定义一个加噪过程、再学它的逆过程”出发。Meta FAIR 的离散流匹配（Discrete Flow Matching，DFM）换了一个起点：先规定一条从源分布到数据分布的概率路径，再找一个让样本沿这条路径流动的连续时间马尔可夫链（CTMC）。这样做的收益是设计空间变大——源可以是全 \([\mathrm{M}]\)、均匀噪声或二者混合，源与数据可以任意耦合，调度器与 corrector 有统一的公式——而掩码扩散只是其中一个点。DFM §1–2

一年后，同组的 Edit Flows 把 CTMC 从“定长序列上逐 token 替换”推广到“变长序列上的插入、删除、替换”，第一次在流匹配框架内原生地解决了画布长度必须预先给定的问题。Edit Flows §1、§3

时间方向与本站相反 DFM 与 Edit Flows 都用 \(t=0\) 表示源（噪声 / 全 [M] / 空序列）、\(t=1\) 表示数据，数据写作 \(x_1\)，调度器 \(\kappa_t\) 从 0 增到 1。本页公式保留原文方向；换算到本站记号时 \(t_{\text{本站}}=1-t_{\text{DFM}}\)，\(\kappa_t\) 对应 MDLM 的 \(\alpha_{1-t}\)，干净序列 \(x_1\) 对应 \(x_0\)。
一句话理解 DFM：每个 token 在一小步 \(h\) 内以概率 \(h\,u_t\) 跳到别的值，\(u_t\) 由“去噪器预测的数据分布减去当前状态”乘以调度器系数给出——和连续流匹配的速度场同形。Edit Flows：跳转不再是“改第 \(i\) 个位置的值”，而是“在某处插入 / 删除 / 替换一个 token”，用一条看不见的对齐序列把训练化成逐位置问题。

3. 组件拆解

3.1 概率路径、源与耦合

DFM 的边缘路径是条件路径对耦合 \(\pi(x_0,x_1)\) 的混合，条件路径按位置分解，每个位置是若干分布的凸组合 \(\sum_j\kappa_t^{i,j}w^j(x^i\mid x_0,x_1)\)。两种常用实例：DFM Eq. 7–10

  • Eq. 9（两项）：\((1-\kappa_t)\delta_{x_0}+\kappa_t\delta_{x_1}\)。源取全 \([\mathrm{M}]\) 时即掩码扩散；源取均匀分布时即均匀态扩散。
  • Eq. 10（三项）：在中途混入均匀噪声 \(\kappa^2_t p_{\mathrm{u}}\)，两端为 0。150M 实验里它的生成困惑度略好于 Eq. 9（见 §8）。

耦合有两种：U-coupling（源与数据独立）与 C-coupling（源本身就保留一段数据前缀，Eq. 5）。后者让模型训练时就见到“前缀已知”的状态，1.7B 条件生成上略好。App. B 给出前缀的取法：长度 \(N_0\sim U(0,N)\)，采样时每步把条件位置改回给定 token。DFM Eq. 4–5、App. B、Tab. 3（App. B 这段写作 “unconditional coupling (U-coupling), see (5)”，而式 (5) 定义的是 C-coupling，措辞自相矛盾。）

3.2 概率速度：采样公式与 NFE 上界

DFM 沿用 Campbell et al. 的 CTMC 视角，但把“速率矩阵”换成按位置的概率速度 \(u_t^i(\cdot,X_t)\)：每个位置独立地按 \(\delta_{X_t^i}+h u_t^i\) 采样。它必须满足“和为 0、非对角非负”；条件速度对后验求边缘即得边缘速度（Thm. 2.2），用离散散度写出的连续性方程证明它确实生成 \(p_t\)。对 Eq. 9 路径，去噪器参数化与噪声预测参数化给出的速度与连续流匹配逐字对应（Tab. 1）。DFM §2.4、Eq. 12–25、Tab. 1

两个实用推论：① 掩码源下去噪器与时间无关，所以训练好的模型可以在采样时换调度器而不必重训（App. B 的调度器变换公式）；② 无 corrector 时 NFE 至多为 \(N\)。DFM Prop. 3.1、App. B

3.3 corrector 与 MaskGIT 的区别

反向时间速度 \(\check u_t=\frac{\dot\kappa_t}{\kappa_t}[\delta_{z}-p_{0|t}]\)；源独立且 i.i.d. 时 \(p_{0|t}\) 可以直接换成源分布本身（Eq. 27），不需要再学一个网络。把前向与反向速度相加得到 corrector：\(\alpha_t-\beta_t=1\) 时是“带回退的采样”，\(\alpha_t=\beta_t\) 时在固定 \(t\) 反复迭代会收敛到 \(p_t\)（Thm. 2.4）。对掩码源，回退就是把已揭示 token 重新掩码——这是对 MDLM“揭示即定稿”的第一种原则性放松。DFM Eq. 25–27、Thm. 2.4

作者把 MaskGIT 看作同一框架下的特例，差别只在采样：MaskGIT 按置信度排序揭示，DFM 按概率独立揭示。在 CIFAR-10 上 MaskGIT 式排序只在很低 NFE 时更好，NFE 增大后反而变差，作者归因于置信度排序引入的偏差；DFM 在 1024 NFE 达到 FID 3.63。后来 LLaDA 等大模型普遍采用的“低置信度重掩码”恰好是这种排序思路，二者的取舍见 第 16 页。DFM §3、§4.2、Fig. 3

3.4 训练损失：交叉熵，而不是 ELBO

DFM 只学去噪器时，损失就是对所有位置的交叉熵 \(-\sum_i\mathbb{E}\log p_{1|t}(X_1^i\mid X_t)\)，\(t\) 均匀采样、不乘时间权重。它的极小点是正确的后验（Prop. 2.5），但它不是似然界——MDLM 在相关工作里正是以此区分二者。所以 DFM 论文只报生成困惑度与下游指标，不报验证困惑度。Edit Flows 进一步把“交叉熵 / ELBO”统一看作 Bregman 散度族的成员。DFM Eq. 28、Prop. 2.5、§4.1；MDLM §6；Edit Flows §2.2

3.5 Edit Flows：在序列空间上流动

为什么定长是个问题。逐 token 路径（含掩码构造）只能在固定的 \(N\) 个位置上改值：要么预设生成长度，要么训练时大量填充，模型会过度自信地预测填充 token，只好靠半自回归采样绕开（LLaDA 的做法）。DFM 自己的代码实验也显示：给出真实长度（oracle length）时 HumanEval Pass@1 从 6.7 升到 11.6。Edit Flows §2.2；DFM Tab. 4

编辑 CTMC。状态是长度 \(0\ldots N\) 的所有序列；速率只在相差一次编辑的序列之间非零：\(\mathrm{ins}(x,i,a)\) 在第 \(i\) 个 token 右侧插入 \(a\)，\(\mathrm{del}(x,i)\)，\(\mathrm{sub}(x,i,a)\)。三类结果互斥，因此可分别参数化为 \(\lambda^{\mathrm{ins}}_{t,i}Q^{\mathrm{ins}}_{t,i}(a)\)、\(\lambda^{\mathrm{del}}_{t,i}\)、\(\lambda^{\mathrm{sub}}_{t,i}Q^{\mathrm{sub}}_{t,i}(a)\)，对角项就是三者总和取负，速率条件自动满足。Edit Flows Eq. 10–16

训练为何难、如何绕开。给定 \(x_0,x_1\)，把一个序列变成另一个的编辑路径有无穷多种，直接写条件速率不可解。作者证明了一个更一般的定理：若在扩展空间 \((x,z)\) 上有生成 \(p_t(x,z)\) 的速率，那么对 \(z\) 的后验求平均就得到生成 \(p_t(x)\) 的速率，而且用任意 Bregman 散度训练时，在扩展空间上算的梯度与在 \(x\) 空间上算的相同（Thm. 3.1）。取 \(z\) 为带空位 \(\varepsilon\) 的对齐序列，\(z\) 空间里就是普通的逐位置混合路径。对齐可以随机填充，也可以用最小编辑距离；有趣的是，即使用最差的对齐（先全删再全插）训练，模型生成时也会偏好编辑更少的配对——类似连续流匹配里的动能最小化。Edit Flows Thm. 3.1、§3.2、App. F

附加技巧。局部化传播路径（某处发生编辑会带动邻近编辑，使 \(x_t\) 保持局部连贯，长代码上 MBPP Pass@1 相对提升 48%）；对 \(\lambda\) 与 \(Q\) 分别做 CFG；学一组反向速率做 corrector。训练效率上，Edit Flows 不为缺失 token 花计算，同样 50 万步、batch 4096 下“吞入”约 6T token，AR 与 Mask DFM 约 2T。Edit Flows §3.3、App. C.1、App. E

5. 训练目标与似然

DFM（Eq. 9 路径、只学去噪器）：

$$\mathcal{L}_{\mathrm{DFM}}(\theta)=-\sum_{i=1}^{N}\mathbb{E}_{t\sim U[0,1],\,(X_0,X_1)\sim\pi,\,X_t\sim p_t(\cdot\mid X_0,X_1)}\log p_{1|t}(X_1^i\mid X_t;\theta),\qquad u_t^i=\frac{\dot\kappa_t}{1-\kappa_t}\big[p_{1|t}(\cdot\mid X_t)-\delta_{X_t^i}\big].$$

与 MDLM 对照：掩码源 + Eq. 9 下两者网络、输入分布与最优解都相同，区别只在 \(t\) 的权重——MDLM 乘 \(-\alpha_t'/(1-\alpha_t)\) 得到似然界，DFM 不乘。前者能报困惑度，后者把各 \(t\) 等权，接近 2026 年 Beyond-Masked 发现“训练更省算力”的那种低方差损失（见 第 5 页）。

Edit Flows（Eq. 23，\(x(z_t,i,z_1^i)\) 表示把 \(z_t\) 第 \(i\) 位换成 \(z_1^i\) 后去空位得到的序列）：

$$\mathcal{L}_{\mathrm{EF}}(\theta)=\mathbb{E}_{t,\,(z_0,z_1)\sim\pi,\,z_t}\Big[\sum_{x\neq x_t}u_t^{\theta}(x\mid x_t)-\sum_{i=1}^{N}\mathbf{1}[z_1^i\neq z_t^i]\,\frac{\dot\kappa_t}{1-\kappa_t}\log u_t^{\theta}\big(x(z_t,i,z_1^i)\mid x_t\big)\Big].$$

第一项压低所有输出速率，第二项抬高“把 \(x_t\) 推向 \(x_1\)”的那些编辑的速率。它是 Bregman 散度的蒙特卡洛估计，不是似然界；文本基准（HellaSwag 等）的打分用的是对 ELBO 的噪声估计，作者在局限中明确指出这一点。Edit Flows §3.2、App. B.1、§6

论文内部的不一致与测量陷阱
  • DFM 的生成困惑度优势依赖低精度采样。主表 Tab. 2（150M，OWT，1024 NFE）里 DFM 的 Llama-2 生成困惑度 22.5 优于 AR 的 31.4；App. G.1 改用 fp64 类别采样重测（Tab. 5），DFM 变为 50.1、熵从 7.2 升到 8.0，SEDD、Campbell 也都在 51–56 左右，全部差于 AR。这正是 Zheng et al.（2409.02908）指出的“低精度类别采样降低有效温度”。主表的具体采样精度论文没有写明（推断为非双精度）。比较生成困惑度必须同时看熵与采样精度。DFM Tab. 2、Tab. 5、App. G.1
  • DFM App. G.1 写“big models batch 4096、1.3M 步，big models batch 512、400k 步”，第二处应为 small，但哪一组对应哪种规模需读者推断；App. C 把代码模型称为 1.5B，正文为 1.7B；App. D 写 \(\kappa_1=0\)（应为 1）。DFM App. C、D、G.1
  • Edit Flows 的“同算力”不是“同数据”。AR 与 Mask DFM 约 2T token，Edit Flows 约 6T；Mask DFM 基线训练时填充到 1024。代码基准的采样超参对每个模型在 HumanEval 上随机搜索（pass@1 200 次），再换随机种子重测；Edit Flow 用 10000 步、Mask DFM 用 1000 步。Edit Flows App. E、Tab. 5
  • DFM App. F 的延迟对比（单张 A100、batch 1、HumanEval：256 NFE 约 2.5× 快于 AR，19.97 s vs 50.94 s；512 NFE 持平）未说明 AR 是否启用 KV cache 与所用推理引擎。

6. 伪代码

dfm_sample.py（掩码源、Eq. 9 路径、去噪器 + corrector；DFM 时间方向 0 → 1）
kappa  = lambda t: t ** 2                      # text scheduler (App. D: cubic family, a=0, b=2)
dkappa = lambda t: 2 * t

@torch.no_grad()
def dfm_sample(model, N, n_steps, alpha_fn):
    x, t, h = torch.full((N,), MASK), 0.0, 1.0 / n_steps
    while t < 1.0 - 1e-9:
        p1 = model(x).softmax(-1)              # p_{1|t}(.|x): time-independent for a mask source
        k, dk = kappa(t), dkappa(t)
        a = alpha_fn(t); b = a - 1.0           # corrector: alpha_t - beta_t = 1
        fwd = a * dk / (1 - k)                 # rate [M] -> data token
        bwd = b * dk / max(k, 1e-9)            # rate data token -> [M]   (Eq. 27, mask source)
        h_t = min(h, 1.0 / (fwd + bwd), 1.0 - t)   # safe step keeps probabilities valid (Eq. 31)
        m = x == MASK
        reveal = m & (torch.rand(N) < h_t * fwd)
        remask = ~m & (torch.rand(N) < h_t * bwd)
        x = torch.where(reveal, torch.multinomial(p1, 1).squeeze(-1), x)
        x = torch.where(remask, MASK, x)       # every position decides independently
        t += h_t
    return x
edit_flow_loss.py（Eq. 23 的单样本版本；默认源为空序列）
def edit_flow_loss(x1, model, eps_id=-1):
    z0, z1 = align(x0=[], x1=x1)               # empty source: z0 is all blanks -> insert-only alignment
    t = random.random(); k, dk = t ** 3, 3 * t ** 2
    zt = [b if random.random() < k else a for a, b in zip(z0, z1)]
    xt = [tok for tok in zt if tok != eps_id]  # strip blanks: the model never sees z
    lam, Q = model(xt, t)                      # lam: [n, 3] (ins, del, sub); Q: [n, 2, vocab]
    loss = lam.sum()                           # total outgoing rate of the CTMC
    for i in range(len(zt)):
        if zt[i] != z1[i]:                     # an edit still needed between z_t and z_1
            op, pos, tok = edit_at(zt, i, z1[i])   # map aligned index -> (ins|del|sub, x-position, token)
            loss -= dk / (1 - k) * torch.log(rate(lam, Q, op, pos, tok))
    return loss

简答题

Q7离散流匹配把掩码扩散改写成“概率路径 + CTMC 概率速度”，这种写法比 ELBO 视角多给了什么，又丢了什么？

多给了一个统一的设计空间：任意源（掩码、均匀、混合）、任意耦合（含前缀条件的 C-coupling）、任意调度器，且速度公式与连续流匹配同形，可在采样时换调度器、加 corrector（可证明仍生成正确分布，并能把已揭示 token 重新掩码）。丢掉的是似然：DFM 用不加时间权重的交叉熵，不是 NLL 上界，只能报生成困惑度——而后者对采样精度极其敏感。

  • 掩码源 + 线性路径下，DFM 与 MDLM 的网络、最优解相同，区别仅在 \(t\) 的权重。
  • 调度器选择（\(\kappa_t=t^2\)）和 corrector 调度对文本质量影响显著（App. D 消融）。
  • fp64 重测后 DFM 的生成困惑度从 22.5 变为 50.1，优于 AR 的结论不再成立。

依据：DFM §2.3–2.4、§3、Thm. 2.4、Prop. 2.5、App. B、D、G.1；MDLM §6。

Q8Edit Flows 如何在不枚举编辑路径的情况下训练插入 / 删除 / 替换速率？它解决变长的方式与 FlexMDM、半自回归块采样有何不同，代价是什么？

它引入一条训练时才有的对齐序列 \(z\)（空位 \(\varepsilon\) 标出插、删、替），在 \(z\) 空间用普通的逐位置混合路径；Thm. 3.1 保证对 \(z\) 求后验平均后得到的就是序列空间的正确速率，且 Bregman 损失的梯度不变，于是模型只需看 \(x_t\)、自己学会推断对齐。与 FlexMDM（插入 [M] 再去掩码，保留任意顺序、可从 LLaDA 微调）和半自回归（按块向右延伸、长度由块数决定）相比，Edit Flows 完全不用 [M] 与填充，位置全是相对的，还能删除。代价是采样步数极多（代码 5000–10000 步）、超参需逐模型搜索，且在文本与代码上仍落后同算力 AR。

  • “同算力”下 Edit Flows 因无填充多吃了约 3× token（6T vs 2T），比较 Mask DFM 时要计入。
  • 局部化路径主要帮长序列（MBPP Pass@1 10.0 → 14.8）。
  • DFM 自己的数据显示定长的代价不小：oracle 长度使 HumanEval Pass@1 6.7 → 11.6。

依据：Edit Flows §3.2–3.3、Thm. 3.1、Tab. 3、Tab. 5、App. E；FlexMDM 摘要；DFM Tab. 4。
