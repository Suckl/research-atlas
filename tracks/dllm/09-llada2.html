1. 动机：dLLM 怎样长到 100B

LLaDA 证明了 8B 稠密掩码扩散可以从零训到与同规模 AR 相当，但继续放大有两条路。一条是从零训练稀疏 MoE：LLaDA-MoE 用约 20T tokens 训出 7B 总参、1.4B 激活的掩码扩散模型LLaDA-MoE 摘要。另一条是把现成 AR 模型转成扩散：LLaDA2.0 从 Ling-mini-2.0 / Ling-flash-2.0 出发，得到 16B 的 mini 与 100B 的 flash，两者都是 MoELLaDA2.0 摘要、§4.1。作者给出的理由是，从零训练的 MDLM 规模一直停在 ≤ 8B，数据量与基础设施都追不上 ARLLaDA2.0 §2.1。

做大之后，速度主要卡在采样器阈值：阈值越低，每次前向定稿的 token 越多，但错误也越多，而吸收态（[M]）扩散一旦定稿就不能再改。LLaDA2.1 在“[M] → token”（M2T）之外加了“token → token”（T2T）编辑，于是可以先激进起草、再回头修改，并据此给出 Speedy（S）与 Quality（Q）两种阈值模式LLaDA2.1 摘要、§2。

一句话理解 LLaDA2.x 的做法是：把 AR 权重当成块长为 1 的块扩散模型，先把块长逐步放大到整条序列，再缩回 32，从而把 AR 平滑地转成块扩散模型（块间因果、可用 KV cache）。LLaDA2.1 再让已写出的 token 可以被改写，把“质量 – 速度”的取舍做成一对可调阈值。

本页记号：干净序列 \(x_0\)（长 \(L\)），腐蚀序列 \(x_t\)，\(t=1\) 为全掩码；块长 \(B\)；去噪网络 \(p_\theta(x_0^i\mid x_t)\)；prompt \(c\)；阈值 \(\tau\)。LLaDA2.0 论文把块长写作 \(L_B\)、块数写作 \(K\)，并用保留概率 \(\alpha_t\)（掩码概率为 \(1-\alpha_t\)）；LLaDA-MoE 直接以掩码概率 \(t\) 记噪声水平LLaDA2.0 式 (1)；LLaDA-MoE 式 (1)。

3. 组件拆解

3.1 LLaDA-MoE：从零训练的稀疏 MoE 掩码扩散

LLaDA-MoE 沿用 LLaDA 的全序列掩码扩散，只是把 FFN 换成 top-k 路由的 MoE。结构为 16 层、hidden 2048、16 个注意力头、64 个专家中激活 8 个、专家维度 1024、RoPE base 50,000，激活参数 1.4B、非嵌入参数 7BLLaDA-MoE Tab. 2。训练分四段：预训练阶段 1 用 10T tokens；阶段 2 再训 10T，提高数学与代码比例；退火阶段 1 用 500B 高质量 tokens；退火阶段 2 把 RoPE base 从 10,000 调到 50,000、上下文从 4k 扩到 8k，再训 500B；最后做 SFTLLaDA-MoE §3.1、Fig. 3。

两个与扩散相关的细节：① 预训练固定 4k 长度，而推理时输入长短不一，作者在 1% 的步里随机截断到 \(\ell\in[8,4096]\) 来缩小这一差距；② SFT 时 EOS 填充被当作回答的一部分参与掩码，但样本限制在 4k，否则按 8k 填充会让模型倾向于生成过多 EOSLLaDA-MoE §3.2。负载均衡与 z-loss 的权重分别为 0.01 与 0.001LLaDA-MoE §3.2 式 (4)。

3.2 LLaDA2.0：块长 WSD，把 AR 转成块扩散

出发点是把 AR 模型视为块长 \(B=1\) 的块扩散模型（BDLM，即 BD3-LM）。直接换成扩散目标会使优化不稳、预训练知识退化LLaDA2.0 §4，因此 WSD 分三段：

  • Warmup：块长 1 → 4 → 32 → 64 → 4096，每次转换都用中等规模数据训练，并要求序列长度能被当前块长整除。到 4096 时整条序列就是一个块，等价于标准 MDLM。
  • Stable：块长固定为 4096，在大规模语料上训练。此时注意力不再需要维护 clean 副本，计算量明显下降，大部分数据放在这一段。
  • Decay：块长从 4096 逐级降到 2048 …… 直到 32，把全局去噪能力“压缩”回小块，重新获得 KV cache 复用与变长生成。LLaDA2.0 §4.1

配套措施：文档级注意力掩码把 packing 在一起的不同文档隔开，作者称它在 CPT 中比 random-length、CART 更关键；top-k checkpoint 合并按验证集指标挑出 k 个检查点做参数平均；数值稳定：AR 训练中 [M] 的嵌入从未被使用、逐渐衰减到接近 0，高掩码率时容易梯度爆炸，作者在训练初期给 [M] 的嵌入输出加独立高斯噪声，而不是重新初始化。LLaDA2.0 §4.2、§4.3、§7.1

3.3 LLaDA2.0 的后训练：互补掩码、CAP、DPO

SFT 沿用块扩散目标，只腐蚀回答；掩码率不在 \([0,1]\) 上均匀采样，而是裁剪到 \([\alpha_{\min},\alpha_{\max}]\)（具体数值未给），理由与 BD3-LM 的 clipped schedule 相同：极端掩码率的梯度方差大、信息量小LLaDA2.0 §5.1。互补掩码为同一条样本构造掩码互补的两份输入，保证每个位置恰好被监督一次；作者在 CPT 中也试过，发现超过 100B tokens 后没有优势，所以只在后训练中使用LLaDA2.0 §5.1 脚注 1。

CAP（Confidence-Aware Parallel）训练加一个辅助损失：只对本步已预测正确的 token 最小化输出熵，使模型在正确时更“笃定”，从而有更多 token 越过阈值——思路来自 dParallelLLaDA2.0 §5.2。DPO 用 1.5M 偏好对，把对数似然换成单样本 MC 估计的块扩散 ELBO，\(\beta=0.1\)，参考模型取 SFT 后的权重LLaDA2.0 §5.3 式 (7)(8)。

3.4 LLaDA2.1：Token-to-Token 编辑与两种阈值模式

作者观察到，并行解码一旦出错，后续步骤会变得越来越保守（置信度下降），整体反而变慢；AR 模型则可以靠长思维链自行纠正LLaDA2.1 §2。LLaDA2.1 因此在每一步同时计算两个集合：

$$\Gamma_t=\{i: x_t^i=[\mathrm{M}],\ p_\theta(v_t^i\mid x_t)>\tau_{\text{mask}}\},\qquad \Delta_t=\{i: x_t^i\neq v_t^i,\ p_\theta(v_t^i\mid x_t)>\tau_{\text{edit}}\},$$

其中 \(v_t^i=\arg\max_v p_\theta(v\mid x_t)\)，然后只在 \(\Gamma_t\cup\Delta_t\) 上更新LLaDA2.1 式 (1)–(3)。S 模式压低 \(\tau_{\text{mask}}\)，依靠 T2T 收拾残局；Q 模式用保守阈值换分数LLaDA2.1 摘要。训练上，CPT 与 SFT 都混合两路监督：drafting 流从 [M] 预测正确 token，editing 流从随机扰动的 token 恢复原文，另用 Multi-turn Forward（MTF）增强覆盖更多编辑场景LLaDA2.1 §3.1。RL 用 EBPO：裁剪代理目标中的概率比 \(\rho\) 用离散时间点上的块级 ELBO 差估计，借助 BD3-LM 的向量化似然在一次前向中算出所有块条件项LLaDA2.1 §3.2 式 (4)(5)。

论文 vs 官方代码① 式 (2) 只写了 \(x_t^i\neq v_t^i\)，[M] 位置也满足这一条件；HF generate() 把编辑限制在当前块内非 [M]、非 prompt 的位置，并以本步更新前的 token 判断“是否改变”。② 论文没有给出 S / Q 模式的阈值数值；模型卡推荐 S：threshold=0.5, editing_threshold=0.0，Q：0.7 / 0.5，max_post_steps=16。③ generate() 的签名默认 editing_threshold=0.9，docstring 却写默认 0.5。复现时请显式传参。LLaDA2.1 式 (2)；HF LLaDA2.1-flash 模型卡与 modeling_llada2_moe.py

5. 训练目标与似然

LLaDA2.0 的块扩散目标（Warmup 与 Decay 阶段；\(K=L/B\) 个块，\(x_0^{\lt k}\) 为前面的干净块）：

$$\mathcal L_{\text{BDLM}}(\theta)=\mathbb E_{t,x_0,x_t}\Big[w(t)\sum_{k=1}^{K}\sum_{i=1}^{B}\mathbb 1[x_{t,k}^i=[\mathrm M]]\,\big(-\log p_\theta(x_{0,k}^i\mid x_0^{\lt k},x_{t,k})\big)\Big],\qquad w(t)=-\frac{\alpha_t'}{1-\alpha_t}.$$

\(K=1\) 时退化为 MDLM 目标；线性调度 \(\alpha_t=1-t\) 下 \(w(t)=1/t\)，与 LLaDA-MoE 的式 (2) 一致。SFT 只把 prompt \(c\) 加进条件；CAP 为 \(\mathcal L=\mathcal L_{\text{SFT}}+\lambda\mathcal L_{\text{conf}}\)（\(\lambda\) 未给）；DPO 把 \(\log\pi\) 换成单样本块扩散 ELBO \(B_{\text{BDLM}}\)：

$$\mathcal L_{\text{DPO}}=-\mathbb E\Big[\log\sigma\big(\beta[\Delta B(x_w\mid c)-\Delta B(x_l\mid c)]\big)\Big],\quad \Delta B=B_{\text{BDLM}}(\theta)-B_{\text{BDLM}}(\theta_{\text{ref}}),\ \beta=0.1.$$

LLaDA2.1 的 EBPO 用 \(N\) 个时间点、权重 \(w_n\) 近似 \(\log\rho\approx\sum_n w_n\sum_b[\log p_\theta(y^b\mid z_n,x)-\log p_{\theta_{\text{old}}}(y^b\mid z_n,x)]\)，其中 \(z_n=y_{t_n}\oplus y_0\)，再代入 PPO 式的裁剪目标LLaDA2.1 式 (4)(5)。所有这些都只是似然的下界或代理，不是精确似然。

符号提示LLaDA2.0 式 (1)(2) 在期望前写了负号，同时权重写作 \(\alpha_t'/(1-\alpha_t)\)；由于 \(\alpha_t'\lt 0\)，按字面计算会得到负的损失。正文说明“时间权重为 \(-\alpha_t'/(1-\alpha_t)\)”，本页按此写成正的 \(w(t)\)。另外，§6.3 正文引用的“Figure 5”实为 Fig. 4（阈值 / 块长分析）；引言称“两阶段 CPT”，§3 称“三阶段流程”，摘要称“三相 WSD”，指的是同一流程的不同切分。LLaDA2.0 式 (1)(2)、§1、§3、§6.3

6. 伪代码

llada21_generate.py（按 HF 官方 generate() 改写，batch = 1）
def generate(model, prompt, gen_len, B=32, tau_mask=0.5, tau_edit=0.0,
             max_post_steps=16, min_accept=1):
    # S 模式：tau_mask=0.5, tau_edit=0.0；Q 模式：0.7 / 0.5（模型卡推荐）
    P = len(prompt)
    n_blocks = ceil((P + gen_len) / B)
    x = [MASK] * (n_blocks * B); x[:P] = prompt
    attn = block_causal(n_blocks, B)               # 块内双向，块间因果
    for k in range(P // B, n_blocks):              # prompt 占满的块直接预填
        lo, hi = k * B, (k + 1) * B
        post = 0
        while True:
            masked = [i for i in range(lo, hi) if x[i] == MASK]
            if not masked:
                post += 1                          # 无 [M]：纯编辑阶段
                if post > max_post_steps:
                    break
            logits = model(x[:hi], attn[:hi, :hi])[lo:hi]   # 服务端：只算当前块 + 读 KV
            v, p = top1(logits, temperature=0.0)            # 候选 token 及其概率
            # M2T：过阈值的 [M]；不足 min_accept 个时取置信最高者
            gamma = [i for i in masked if p[i - lo] > tau_mask]
            if masked and len(gamma) < min_accept:
                gamma = top_k(masked, key=lambda i: p[i - lo], k=min_accept)
            # T2T：本步更新前已写、非 prompt、候选改变且置信 > tau_edit
            delta = [i for i in range(max(lo, P), hi)
                     if x[i] != MASK and v[i - lo] != x[i] and p[i - lo] > tau_edit]
            for i in gamma + delta:
                x[i] = v[i - lo]
            if not masked and not delta:            # 块收敛
                break
        # 块定稿：服务端在此把块 k 的 K/V 追加进缓存（MBE 允许之后再回改）
        if eos_early_stop and EOS in x[P:hi] and MASK not in x[P:hi]:
            break
    return cut_after_first_eos(x[P:P + gen_len])

LLaDA2.0 的解码是 tau_edit = +inf（无 T2T）、tau_mask = 0.95 的特例；它的回退规则是“按固定个数接受最可能的 token”，具体个数由 steps 与块长决定LLaDA2.0 §5.4；官方代码 _get_num_transfer_tokens。

简答题

Q17LLaDA2.0 为什么不直接用目标块长 32 做 AR → 扩散的持续预训练，而要先把块长从 1 升到 4096、再降回 32？三个阶段各解决什么问题？

AR 模型就是块长为 1 的块扩散模型。一下子换成块长 32 的目标，会同时改变注意力模式与训练分布，作者称这会导致优化不稳、知识退化。Warmup 逐级放大“联合去噪”的范围，让表示平滑适应；Stable 在块长 = 序列长（即 MDLM）时训练，不需要 clean 副本，单位 token 成本更低，适合承载大规模数据；Decay 再缩回小块，换回 KV cache 复用与变长生成。

  • Warmup：1 → 4 → 32 → 64 → 4096，每次转换都用中等规模数据，序列长度需能被块长整除。
  • Stable：块长 4096，全序列双向；文档级掩码防止 packing 后跨文档的虚假依赖。
  • Decay：4096 → 2048 → … → 32，逐级而非一步缩小；推理块长 32 是在 B = 16 / 32 / 64 的分数与 TPF 之间权衡后选定的。
  • 工程细节同样关键：AR 中 [M] 嵌入衰减到接近 0，高掩码率时会梯度爆炸，因此在训练初期给 [M] 的嵌入输出加高斯噪声。
  • 需要说明的是：论文没有给出“直接用块长 32 转换”的对照数字，所以“WSD 更好”是作者的论证，本页无法核实其增益大小。

依据：LLaDA2.0 §4、§4.1、§4.2、§6.3、§7.1。

Q18LLaDA2.1 的 T2T 编辑为什么能让 M2T 阈值大幅降低而不崩？S / Q 两种模式各换来多少 TPF、付出多少分数，速度数字又是在什么条件下测的？

吸收态掩码扩散中，token 一旦从 [M] 落定就无法更改，低阈值带来的错误会永久保留，还会拉低后续步骤的置信度，使解码变慢。T2T 让候选已改变且足够自信的位置被改写，于是 M2T 可以先粗糙起草（S 模式 τ_mask 0.5），错误由后续步骤回收。训练时同时监督“从 [M] 预测”和“从随机替换的噪声复原”两路，模型才学会识别错字。

  • flash：2.0 为 72.43 | 3.08 TPF；2.1 S 为 72.34 | 5.93；Q 为 73.54 | 3.64。mini：63.39 | 2.60 → S 62.07 | 5.34 / Q 63.90 | 3.12。S 模式约把 TPF 提高到 1.9–2.1 倍，分数持平或略降。
  • 摘要中的“892 TPS（HumanEval+）”是 S 模式 + 按块 FP8 量化 + Alpha-MoE megakernel + 定制 SGLang 下的数字；不量化时为 746.66。论文未写硬件与 batch。
  • DiffusionGemma 报告在 8 × B200、BF16、batch 1 下测得 LLaDA2.1 Flash S 模式为 375 TPS、4.63 TPF，与作者自报的条件不同。
  • 局限：S 模式在通用对话中可能出现 n-gram 重复，作者建议改用 Q 模式；代码、数学等结构化任务的提速最明显，IFEval 只有约 219–248 TPS。

依据：LLaDA2.1 §1–3、§4.2、§6、Tab. 1–3；HF 模型卡；DiffusionGemma 报告 Tab. 3。
