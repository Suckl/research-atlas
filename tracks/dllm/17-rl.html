1. 动机：RL 算法都要 log π，dLLM 给不出来

PPO / GRPO 需要逐 token 的概率比 \(\pi_{\theta}(o^k\mid c,o^{<k})/\pi_{\mathrm{old}}(\cdot)\) 和序列级 KL；DPO 需要序列对数似然之差。AR 模型一次因果前向就能给出全部条件概率。dLLM 没有这种分解：一条回答可以由许多种揭开顺序生成，序列似然是对所有去噪轨迹求和（长度 \(N\) 时轨迹数为 \(O(N!)\)）；能算的只有 ELBO 这个下界，而且要对时间 \(t\) 和掩码样本做双重蒙特卡洛。LLaDA 原文的似然估计用 128 个 MC 样本，放进在线 RL 的计算图里太贵。d1 §3、§3.1；Flexibility Trap §4.1；LLaDA 1.5 §2.2

本页三篇分别给出一种 log π 的估计方式，代表三种取舍：

  • d1 / diffu-GRPO：只做一次前向——随机掩码部分提示、回答全掩码，把这一步的逐 token 预测当作 \(\log\pi\)，序列似然取均场乘积。最便宜，偏差最大。d1 §3.1
  • LLaDA 1.5 / VRPO：老老实实用 ELBO 做 DPO，然后证明估计方差同时决定损失的偏差与方差，再用增加预算、最优分配与对偶采样三招无偏地降方差。LLaDA 1.5 §3
  • TraceRL：不再随机掩码，而是沿模型实际的推理轨迹，用“前几步已定稿的 token”作条件计算每一步定稿 token 的概率，并训练扩散价值模型做逐步优势。TraceRL §3–4
一句话理解 dLLM 的 RL 难点不在优化器，而在“被优化的到底是哪个分布”：d1 优化的是“一步全掩码”时的边缘，VRPO 优化的是 ELBO，TraceRL 优化的是实际采样器走过的那条轨迹上的条件概率。离实际采样器越近，估计越贴切，但需要的前向次数通常也越多。

记号：提示 \(c\)，回答 \(o\)（第 \(k\) 个 token \(o^k\)），组大小 \(G\)，优势 \(A\)，裁剪 \(\varepsilon\)，KL / DPO 系数 \(\beta\)，去噪网络 \(f_{\theta}\)（即 \(p_{\theta}(x_0^i\mid x_t)\)），第 \(k\) 步同步定稿的 token 集合 \(S_k\)。d1 用 \(q\) 表示提示；LLaDA 1.5 用 \(x\) 表示提示、\(y_w,y_l\) 表示偏好对；TraceRL 用 \(\tau\) 表示轨迹、\(\mathcal T\) 表示阈值、\(Q\) 表示提示。

3. 组件拆解

3.1 核心问题：用什么代替 log π

三个层次的困难：① 序列似然对所有去噪轨迹求和，不可解；② 逐 token 的条件概率没有唯一定义（“第 \(k\) 个 token 在什么状态下被生成”取决于轨迹），因此 GRPO 的 token 级比值也没有唯一定义；③ 即使有好的似然近似，rollout 用的是置信度驱动的采样器，被优化的却是模型分布，两者并不一致。Flexibility Trap §4.1ELBO \(\mathcal B_{\pi}(y\mid c)=\mathbb E_{t}\mathbb E_{y_t}[\ell_{\pi}(y_t,t,y\mid c)]\le\log\pi(y\mid c)\) 可以无偏估计，但它是下界而非似然本身，且估计方差随样本数 \(n\) 按 \(\Theta(1/n)\) 下降。LLaDA 1.5 Eq. 4–6、Prop. 1

3.2 d1：掩码 SFT + diffu-GRPO

第一阶段在 s1K（1000 条带验证、回溯的推理轨迹）上做掩码 SFT，序列长 4096；作者发现必须对 PAD / EOS 计损失并填充到最大长度，LLaDA 才能正确终止生成。d1 §3.3、App. D.2第二阶段 diffu-GRPO 如图 1。单步估计让每次梯度更新只需一次前向，随机提示掩码使内循环更新次数 μ 可以从常见的 2 提高到 12 甚至 24 而不过拟合当前批次，从而减少昂贵的在线生成；图 5 显示更大的 μ 在更短墙钟时间内达到相同奖励。d1 §3.2、§4.4、Fig. 5

3.3 LLaDA 1.5：VRPO，给 ELBO 偏好优化降方差

把 DPO 中的对数似然换成 ELBO，得到偏好分数 \(s_{\theta}\)（四个 ELBO 的线性组合）；实际训练中每个 ELBO 用 \(n=n_t\times n_{y_t}\) 个掩码样本估计。估计量 \(\hat s_{\theta}\) 本身无偏，但套上非线性的 \(\log\sigma\) 后损失有偏，且有方差。Theorem 1：损失的偏差不超过 \(\sqrt{\mathbb V\hat s_{\theta}}\)，方差不超过 \(4\,\mathbb E[\mathbb V\hat s_{\theta}]\)；梯度有类似结论。所以只需压低 \(\hat s_{\theta}\) 的方差。LLaDA 1.5 Eq. 7–8、Thm. 1、App. B.4

三种无偏降方差手段：① 加大预算 \(n\)（方差 \(\Theta(1/n)\)）；② 固定总预算时全部分给时间步，\(n_t=n\)、每个时间步只取 1 个掩码样本（Prop. 1 证明这是最优分配）；③ 对偶采样：同一个回答 \(y\) 在当前策略与参考策略上共享相同的 \((t,\text{掩码})\)，两者正相关时差值的方差变小（Prop. 2）。后两项不增加计算，是“免费”的。LLaDA 1.5 §3.2、Prop. 1–2默认 \(n=8\)，计算约为 \(n=1\) 的 8 倍，但总成本不到预训练的 0.5%（约 405 H100 GPU 小时）。LLaDA 1.5 §4、App. D.3作者指出同样的技巧可以用于 PPO / GRPO 中的 ELBO 似然或似然比项。LLaDA 1.5 §3.3

消融（固定其余设置）：score 估计量方差在 \(n_t=1\) 时为 44.0，\(n_t=4\) 时 2.2，\(n_t=8\) 时 1.0；同样预算 4 下 \((n_t,n_{y_t})=(1,4)\) 为 7.3、(2,2) 为 4.7；去掉对偶采样（\(n_t=4\)）高达 2183.7。GSM8K 依次为 80.1 / 82.8 / 83.3 / 81.4 / 82.3 / 82.0。LLaDA 1.5 Tab. 2

评测口径（LLaDA 1.5 App. D.4） ① 两个模型的答案长度（64–1024）与块长（8–128）按任务分别调优后取最好，配置不同（如 GSM8K：LLaDA 块 8、LLaDA 1.5 块 16）。② 评测时把 EOS 的置信度置零，LLaDA 的 HumanEval 从 47.6 升到 49.4，表中基线用的是后者。③ HumanEval 基线 49.4 来自低置信度重掩码，LLaDA 1.5 的 52.4 来自半自回归采样；同一采样器下比较时 LLaDA 1.5 在低置信度重掩码上反而略低（47.0 vs 49.4）。三次种子重跑：GSM8K 82.9 ± 0.6、HumanEval 52.0 ± 0.7。LLaDA 1.5 App. D.4、Tab. 4–6

3.4 TraceRL / TraDo：沿推理轨迹做 RL，配扩散价值模型

先看训练–推理不一致。在“无 CoT 提示下学会 CoT”的 SFT 实验里（2000 条 Qwen2.5 生成数据，MATH500），等计算量下按模型自己偏好的推理轨迹微调最好：Dream-7B-Instruct（全注意力）轨迹 54.4%、半自回归 52.6%、完全随机掩码（扩增 35 倍到相同前向量）45.1%；SDAR-4B-Chat（块注意力，块 4）轨迹 71.3%、半自回归 70.0%。TraceRL §3、Tab. 1RL 的 rollout 本身就产生这些轨迹，因此直接在轨迹上做 RL。TraceRL §3.3

目标。把一条 rollout 记成各步定稿集合 \((S_1,\dots,S_K)\)，第 \(k\) 步 token 的概率以前 \(k-1\) 步已定稿的 token 为条件（其余位置为 \([\mathrm M]\)）计算；为了减少前向次数，把相邻 \(s\) 步合并（收缩参数 \(s\)），计算量降为 \(1/s\)。块扩散模型还可以把各块的第 \(l\) 步拼成一个“切片”，借块注意力一次前向算完。TraceRL §4.1、§4.3、Eq. 3

扩散价值模型。只给最后一步的 token 记整条轨迹的奖励，其余为 0；冻结的旧价值网络对每步 token 估值并取平均作为步值，再按步计算回报与 GAE，映射回 token 级优势；价值网络用裁剪回归损失训练。作者报告加价值模型后训练曲线波动更小（4B 数学任务）。TraceRL §4.2、§5.7、Eq. 4、Fig. 6

结果与副作用。以 SDAR-4B / 8B-Chat（块 4）为底座，只用 TraceRL 训练得到 TraDo-4B / 8B-Instruct；再加长 CoT SFT 与课程得到 TraDo-8B-Thinking。RL 后动态解码每步定稿 token 数在 MATH500 上从 2.28 升到 2.63（+15.4%）；用 TraceRL 还能把块大小从 4 适配到 8（块 8 推理时 MATH500 60.2 → 67.7）。TraceRL §5.2–5.3、§5.8–5.9、Tab. 3–4

论文内部不一致（TraceRL v1） ① §5.3 称 TraDo-8B-Thinking 的 MATH500 为 85.8%，Tab. 2 与 Fig. 1 为 87.4%（摘要“比 Qwen2.5-7B-Instruct 相对高 18.1%”与 87.4 / 74.0 一致）。② Tab. 2 图注把长 CoT 模型写成 “TraDo-8B-Instruct”，应为 Thinking。③ §5.4 称 TraDo-4B 动态解码 MATH500 提升 4.2，表中为 71.8 − 67.4 = 4.4。TraceRL 摘要、§5.3–5.4、Tab. 2

5. 训练目标与似然估计

diffu-GRPO（最大化；\(\phi^{\pi}(o^k\mid c')=f(o^k\mid c'\oplus[\mathrm M]\cdots[\mathrm M])\)）：

$$\mathcal J(\theta)=\mathbb E\Big[\frac1G\sum_{i=1}^{G}\frac{1}{|o_i|}\sum_{k}\min\big(\rho_i^kA_i,\ \mathrm{clip}(\rho_i^k,1-\varepsilon,1+\varepsilon)A_i\big)-\beta\,\mathrm{KL}\big(\phi^{\pi_{\theta}}\,\|\,\phi^{\pi_{\mathrm{ref}}}\big)\Big],\qquad \rho_i^k=\frac{\phi^{\pi_{\theta}}(o_i^k\mid c')}{\phi^{\pi_{\mathrm{old}}}(o_i^k\mid c')}.$$

VRPO（\(\hat{\mathcal B}\) 为 \(n\) 个掩码样本的 ELBO 估计）：

$$\hat\ell=-\log\sigma\big(\hat s_{\theta}\big),\quad \hat s_{\theta}=\beta\big[\hat{\mathcal B}_{\pi_{\theta}}(y_w)-\hat{\mathcal B}_{\pi_{\mathrm{ref}}}(y_w)\big]-\beta\big[\hat{\mathcal B}_{\pi_{\theta}}(y_l)-\hat{\mathcal B}_{\pi_{\mathrm{ref}}}(y_l)\big],$$
$$\mathbb V\hat s_{\theta}=\beta^2\sum_{y\in\{y_w,y_l\}}\Big[\mathbb V\hat{\mathcal B}_{\pi_{\theta}}(y)+\mathbb V\hat{\mathcal B}_{\pi_{\mathrm{ref}}}(y)-2\,\mathrm{Corr}\big(\hat{\mathcal B}_{\pi_{\theta}}(y),\hat{\mathcal B}_{\pi_{\mathrm{ref}}}(y)\big)\sqrt{\mathbb V\hat{\mathcal B}_{\pi_{\theta}}(y)\,\mathbb V\hat{\mathcal B}_{\pi_{\mathrm{ref}}}(y)}\Big].$$

前两项靠增大预算与最优分配降低，第三项靠对偶采样提高相关性。LLaDA 1.5 Eq. 9

TraceRL（\(S^{s}_{i,k}\) 为第 \(i\) 条轨迹合并后的第 \(k\) 步集合，\(C_{\epsilon}(r,A)=\min(rA,\mathrm{clip}(r,1-\epsilon,1+\epsilon)A)\)）：

$$\mathcal J_{\mathrm{policy}}=\mathbb E\Big[\sum_{i=1}^{G}\sum_{k}\frac{1}{|S^{s}_{i,k}|}\sum_{o\in S^{s}_{i,k}}C_{\epsilon}\Big(\frac{\pi_{\theta}(o\mid S^{s}_{i,1:k-1})}{\pi_{\mathrm{old}}(o\mid S^{s}_{i,1:k-1})},A\Big)\Big]-\beta\,\mathrm{KL}(\pi_{\theta}\,\|\,\pi_{\mathrm{old}}).$$

使用价值模型时 \(A\) 换成按步 GAE 映射回 token 的 \(A_j\)，默认 \(\gamma=\lambda=1\)。TraceRL Eq. 3–4、§4.2、§5.1.2

def onestep_logp(model, c, o, seed, p_mask=0.15):
    g = Generator().manual_seed(seed)
    c_ = where(rand(len(c), generator=g) < p_mask, MASK, c)        # 随机掩码提示
    x = cat([c_, full((len(o),), MASK)])                             # 回答全掩码
    lp = log_softmax(model(x)[len(c):], dim=-1)                      # 单次前向
    return lp.gather(-1, o[:, None]).squeeze(-1)                     # 均场：逐 token

def diffu_grpo_batch(pi, ref, c, opt, G=6, mu=12, eps=0.5, beta=0.04):
    old = frozen_copy(pi)
    outs = [diffusion_generate(old, c, L=256, B=32, steps=128) for _ in range(G)]
    r = tensor([reward(c, o) for o in outs])
    A = r - r.mean()                                                 # 不除以标准差
    for _ in range(mu):                                              # 内循环：每次换掩码
        seed, loss = randint(2**31), 0.0
        for o, a in zip(outs, A):
            lp = onestep_logp(pi, c, o, seed)
            with no_grad():
                lp_old, lp_ref = onestep_logp(old, c, o, seed), onestep_logp(ref, c, o, seed)
            ratio = (lp - lp_old).exp()
            kl = (lp_ref - lp).exp() - (lp_ref - lp) - 1             # k3 估计
            surr = minimum(ratio * a, ratio.clamp(1 - eps, 1 + eps) * a)
            loss = loss - (surr - beta * kl).mean() / G
        opt.zero_grad(); loss.backward(); opt.step()

def vrpo_loss(pi, ref, c, yw, yl, n=8, beta=0.2):
    s = 0.0
    for y, sign in ((yw, 1.0), (yl, -1.0)):
        ts = rand(n)                                                 # n_t = n，每个 t 一个掩码
        masks = [rand(len(y)) < t for t in ts]
        b_pi = stack([elbo_term(pi, c, y, t, m) for t, m in zip(ts, masks)]).mean()
        with no_grad():                                              # 对偶：共享 (t, 掩码)
            b_ref = stack([elbo_term(ref, c, y, t, m) for t, m in zip(ts, masks)]).mean()
        s = s + sign * beta * (b_pi - b_ref)
    return -logsigmoid(s)                                            # 另加 0.05 × SFT 损失

简答题

Q33为什么“算 log π”是 dLLM 做 RL 的核心难题？比较 d1 的单步均场估计、VRPO 的 ELBO 降方差与 TraceRL 的轨迹条件概率在偏差、方差与计算量上的取舍。

dLLM 的序列似然是对所有揭开顺序求和，逐 token 条件概率也依赖于“在什么状态下生成”，所以 GRPO 的比值与 DPO 的对数似然差都只能近似。d1 只做一次前向，把“提示部分掩码、回答全掩码”时的逐 token 预测当作 log π，序列似然取均场之和：计算最省，但估计的是“一步全掩码”的边缘，不等于实际多步采样器的概率，有系统性偏差。VRPO 用 ELBO（似然下界）的无偏估计，并证明 DPO 损失的偏差与方差都受估计方差控制，用 n=8 个时间步、每步一个掩码样本及对偶采样把方差压低（score 方差 44.0 → 1.0），代价是约 8 倍计算。TraceRL 沿实际推理轨迹，以前几步已定稿的 token 为条件计算每步 token 的概率，与采样器一致，前向次数随步数增长，靠合并相邻 s 步与块注意力切片控制。d1 §3.1；LLaDA 1.5 Thm. 1、Tab. 2；TraceRL §4.1、§4.3

  • “采样器与被优化分布不一致”是 d1 与 ELBO 类方法共同的问题；TraceRL 与 JustGRPO 从两个方向消除它（前者跟随采样器，后者把采样器改成左到右）。
  • 三篇的底座（LLaDA / SDAR）、生成长度与解码设置都不同，论文间分数不能直接比较；统一协议的对比见 Flexibility Trap。
  • d1 发现随机提示掩码让内循环可以更新 12 次，这是单步估计特有的“免费”数据增强。

依据：d1 §3、Fig. 5；LLaDA 1.5 §3、Tab. 2；TraceRL §3–4、Tab. 1；Flexibility Trap §4.1。

Q34VRPO 的对偶采样为什么几乎不增加成本就能降方差？如果当前策略与参考策略差别很大，它还有效吗？

偏好分数里每个回答都以“当前策略 ELBO − 参考策略 ELBO”的差出现；差值的方差等于两者方差之和减去两倍协方差。对偶采样让两个 ELBO 估计共享同一组时间步与掩码，本来就要算的前向一次也没多，只是把随机性对齐，于是两者高度正相关，差值的方差大幅下降：去掉对偶采样时 score 方差为 2183.7，加上后为 2.2（\(n_t=4\)）。这个收益依赖正相关的假设（Prop. 2）：DPO 中参考策略就是初始模型，训练只跑 1 个 epoch、学习率 5e-7，当前策略始终离参考很近。若两者差别很大，对同一掩码的损失响应不再同步，相关系数下降，收益随之消失；相关为负时共享样本反而会增大方差（由方差分解式推得，论文未做实验）。LLaDA 1.5 Eq. 9、Prop. 2、Tab. 2、App. D.3

  • 另外两招中，预算 n 让每个 ELBO 的方差按 1/n 下降但成本 ×n；最优分配（\(n_t=n,n_{y_t}=1\)）同样不加成本。
  • 同一思路可以用到 PPO / GRPO 中的 ELBO 似然比项，作者在 §3.3 讨论但未实验。

依据：LLaDA 1.5 §3.2–3.3、Prop. 1–2、Tab. 2、App. D.3。
