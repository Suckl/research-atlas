1. 动机：双向注意力没有“现成的”缓存

AR 的 KV cache 成立有两个前提：因果掩码使已生成 token 的 K/V 不再变化；下一个要算的位置是确定的。LLaDA、Dream 这类全双向 dLLM 两条都不满足：每一步去掩码都会改变所有位置的表示，下一步要更新哪些位置也要等前向结束才知道。dKV-Cache §3.2于是生成长 \(L\) 的序列若用 \(N=L\) 步、每步全量重算，注意力总代价为 \(O(L^3)\)，而带缓存的 AR 为 \(O(L^2)\)。dKV-Cache §1开源 dLLM 每步多定稿几个 token 又会掉点，所以实际速度常常不如同尺寸 AR。Fast-dLLM §1

要提速只有两个杠杆：少算（复用 K/V）和少走步（每步定稿多个 token）。本页三篇代表三种做法：

一句话理解 双向模型的 K/V “会变，但变得不多”：Fast-dLLM 赌块内几步之间前后文的 K/V 几乎不变，块完了再统一刷新；dKV-Cache 发现 token 被定稿那一步变化最大、之后就稳定，于是晚一步再缓存；D2F 干脆把学生模型改成块因果，用蒸馏换来精确缓存，再让后面的块不等前面的块写完就开始去噪。

3. 组件拆解

3.1 Fast-dLLM 的块级近似缓存

块式生成本来是 LLaDA 的半自回归采样方式；Fast-dLLM 利用它划定“在哪段时间里假装 K/V 不变”。提示和已完成块在当前块解码期间几乎不受影响，后缀全是 [M]，也几乎不变；当前块解码完再统一刷新。论文称单独加缓存通常有 2–3.6× 加速（HumanEval 仅 1.3–1.6×），主要设置为前缀缓存、块长 32。Fast-dLLM §3.2、§4.1–4.2DualCache 在生成长度 512 / 1024 时优势明显：8-shot GSM8K、生成 1024，前缀缓存 18.6×、DualCache 27.6×（均已叠加并行解码，相对原始 LLaDA）。Tab. 5

3.2 置信度阈值并行解码及其依据

并行解码的诅咒。同一步独立采样两个位置，相当于从 \(p(x^i\mid x_t)\,p(x^j\mid x_t)\) 采样，而真实联合是 \(p(x^i\mid x_t)\,p(x^j\mid x_t,x^i)\)。论文的例子：“由两个英文单词组成的扑克牌型”可以是 high card、two pair、full house……独立采样可能拼出 high house。同步定稿的位置越多，这种不一致越严重。Fast-dLLM §2.2

为什么阈值能缓解。记 \(q(\boldsymbol X\mid E)=\prod_j p_j(X_{i_j}\mid E)\) 为边缘乘积，\(p(\boldsymbol X\mid E)\) 为模型的联合分布，\(E\) 为提示与已生成 token。若存在 \(x^*\) 使每位 \(p_j(x^*_{i_j}\mid E)>1-\epsilon\)，则：Thm. 1

$$(n+1)\epsilon\le1\ \Rightarrow\ \arg\max_{\boldsymbol z}p(\boldsymbol z\mid E)=\arg\max_{\boldsymbol z}q(\boldsymbol z\mid E)=x^*,\qquad D_{\mathrm{TV}}(p,q)<\tfrac{3n-1}{2}\,\epsilon,\qquad D_{\mathrm{KL}}(p\Vert q)<(n-1)\big(H_b(\epsilon)+\epsilon\ln(|\mathcal V|-1)\big).$$

两点限定：定理假设模型给出一个自洽的联合分布、边缘由它导出，掩码扩散模型未必严格满足；界来自最坏情况，实际依赖往往更弱。App. A Remark 1它保证的是“与模型自己的联合 argmax 一致”，并不保证答案正确。据此提出的因子规则在 GSM8K 生成 256 时吞吐 78.5 tok/s（11.7×），比阈值规则的 54.4 tok/s 高约 1.4–1.5 倍，准确率低 1–3 分。App. C.2、Tab. 11与固定每步 2 / 4 / 8 个 token 的做法相比，阈值规则在相同平均每步 token 数下准确率更高。§4.3、Fig. 5

下面是一个可解析的玩具画布：几个位置之间有强相关的 token 对。调节阈值，可以看到每步定稿数（TPF）上升的同时，相关位置被同一步定稿时会拼出不一致的组合。

阈值能调低步数，但无法知道一个请求“有多难”：ParallelBench 专门构造 token 相关性强的任务来检验这一点；学习式并行解码则通过训练让模型更早变得高置信。

3.3 dKV-Cache：延迟且条件化的缓存

观察。在 LLaDA 上（\(L=T=128\)、块长 64）跟踪每个 token 的 K/V：相邻步整体高度相似；一个 token 被定稿之后表示趋于稳定，仍是 [M] 的位置则持续波动；变化最大的是它被定稿的那一步。dKV-Cache §3.2、Fig. 2

dKV-Cache-Decode。只缓存已定稿的 token，并且延迟一步：第 \(t\) 步用第 \(t-1\) 步的未定稿集合 \(\mathcal M_{t-1}\) 判断谁可缓存，未定稿位置与刚定稿位置每步重算；为维持一致性，每隔若干步整体刷新。去掉这一步延迟，缓存比例一高准确率就崩到接近 0。§3.3、Fig. 3它不要求预知解码顺序，适用于置信度重掩码；借助 concat_reorder 把缓存 K/V 与新算 K/V 按位置重排拼接（与 RoPE 兼容）。§3.3、App. A两个变体：Prefill 只缓存提示且永不刷新，PD 缓存提示并只间歇刷新新解码的 token——依据是提示 token 主要彼此注意。§3.3

$$\mathbf z_t=\mathrm{softmax}\!\Big(\frac{\mathbf Q_t^{\mathcal M_{t-1}}(\mathbf K_t^{\mathcal I})^{\top}}{\sqrt{d_k}}\Big)\mathbf V_t^{\mathcal I},\qquad \mathbf K_t^{\mathcal I}=\mathrm{concat\_reorder}\big(\mathbf K_{t-1}^{\mathcal I\setminus\mathcal M_{t-1}},\ \mathbf K_t^{\mathcal M_{t-1}}\big)$$

dKV-Cache-Greedy。上式每步仍要重算 \(|\mathcal M_{t-1}|\) 个位置，起初接近 \(L\)，总复杂度仍是 \(O(L^3)\)。Greedy 版每步只重算当前定稿位、上一步定稿位和一个大小不超过 6 的局部窗口，复杂度降为 \(O(L^2)\)；但它依赖预先确定的（如随机）解码顺序，准确率低于置信度重掩码。§3.4、§4.2

系统层面的提醒。大量 gather / scatter 让 batch 1 时访存不连续，缓存版有时反而比基线慢；增大 batch 后加速才稳定。App. D、Fig. 7

3.4 D2F：训练出块因果学生，换精确缓存

离散扩散强制。把回答切成大小为 \(k\) 的 \(N\) 块，块 \(i\) 的掩码率 \(t_i\) 单调递增（\(t_1<\dots<t_N\)）：前面的块更完整，后面的块更模糊。学生模型的注意力块内双向、块间因果，学习

$$p_\theta(Y^0\mid Y^t)=\prod_{i=1}^{N}p_\theta\big(Y_{B_i}^0\mid Y_{B_1}^{t_1},\dots,Y_{B_i}^{t_i}\big),$$

即在前序块尚未写完时就预测后续块——这是 BD3-LM 式“前序块干净”的 teacher forcing 学不到的能力，思路对应连续扩散里的 Diffusion Forcing。D2F §4.1、Eq. 2

非对称蒸馏。学生 \(p_\theta\) 由原双向 dLLM \(p_{\phi^-}\) 初始化，二者只差注意力掩码；教师看到全部加噪块，学生只看因果视野，对掩码位置最小化 KL：§4.2、Eq. 3

$$\mathcal L_{\mathrm{D2F}}=\mathbb E_{t_1<\dots<t_N}\Big[\sum_{i=1}^{N}D_{\mathrm{KL}}\big(p_\theta(Y_{B_i}^0\mid Y_{B_{\le i}}^{t})\,\Vert\,p_{\phi^-}(Y_{B_i}^0\mid Y_{B_{1:N}}^{t})\big)\Big]$$

实现：LoRA（秩 32、缩放 32、dropout 0.1）作用于 q / k / v / o 投影；数据为 Bespoke-Stratos-17k 题目上由 Qwen2.5-7B 生成、长度不超过 600 的回答（第三方整理）；序列 512、块长 16、块掩码率在 0.3–0.7 之间单调；8 张 A100-PCIe-40GB 训练 12 小时，学习率 \(10^{-5}\)。用同样数据和 LoRA 直接微调 Dream 不带来加速，说明加速来自 D2F 结构而非数据。§5.1、App. A.2

流水线并行解码。维护一个活动块窗口：最后一块定稿比例超过 \(\tau_{\mathrm{add}}\)（默认 0.1）就追加一个全 [M] 新块，先处于“半激活”（只定稿置信度 \(>\tau_{\mathrm{conf}}\) 的位置，可以一个都不定）；前一块定稿比例超过 \(\tau_{\mathrm{act}}\)（默认 0.95）后转为“全激活”（没有位置过阈值时强制定稿最高者）。完成的块写入精确 KV。§4.3、Alg. 2、§5.1消融显示：只开缓存（逐块串行）在 GSM8K 上相对原始 LLaDA 为 2.4×，加上流水线并行为 7.3×。App. A.1、Tab. 5

5. 训练目标与似然

Fast-dLLM 与 dKV-Cache 不训练，所服务的模型训练目标都是掩码扩散上界：Fast-dLLM Eq. 2

$$-\log p_\theta(x_0)\le\int_0^1\frac1t\,\mathbb E_{q(x_t\mid x_0)}\Big[\sum_{i:\,x_t^i=[\mathrm M]}-\log p_\theta(x_0^i\mid x_t)\Big]dt$$

D2F 的学生不再直接拟合数据，而是拟合双向教师在“更完整视野”下的预测（§3.4 的 \(\mathcal L_{\mathrm{D2F}}\)），因此它的分布上限是教师；块因果结构让似然可按块分解，但论文未报告学生的 ELBO 或困惑度。D2F §4.2

def fast_dllm(model, c, L, B=32, tau=0.9, dual=True):
    x = c + [MASK] * L
    cache = model.prefill(x)                                   # 全序列一次前向，存全部 K/V
    for s in range(len(c), len(c) + L, B):
        e = s + B
        while any(x[i] == MASK for i in range(s, e)):
            span = (s, e) if dual else (s, len(x))             # DualCache 只算当前块
            logits = model.forward_span(x, span, cache)        # 其他位置读缓存 K/V（近似）
            masked = [i for i in range(s, e) if x[i] == MASK]
            conf = {i: logits[i].max() for i in masked}
            sel = [i for i in masked if conf[i] >= tau] or [max(masked, key=conf.get)]
            for i in sel:
                x[i] = logits[i].argmax()                       # 同步定稿（独立的逐位 argmax）
        cache = model.refresh(x)                                # 块末全量刷新
    return x

def d2f_decode(student, c, k=32, t_conf=0.9, t_add=0.1, t_act=0.95):
    kv = student.prefill(c)                                    # 块间因果：前缀 KV 精确
    blocks = [Block(k, state="full")]
    while not finished(blocks):
        last = blocks[-1]
        if last.decoded_ratio() > t_add and not has_eos(blocks):
            blocks.append(Block(k, state="semi"))              # 追加新块：半激活
        act = [b for b in blocks if not b.cached]
        logits = student(act, kv)                              # 一次前向覆盖所有活动块
        for prev, b in zip([None] + act[:-1], act):
            J = [p for p in b.masked() if conf(logits, p) > t_conf]
            if not J and b.state == "full":
                J = [argmax_conf(logits, b.masked())]
            b.fill(J, logits)
            if prev is not None and prev.decoded_ratio() > t_act:
                b.state = "full"                               # 前块够完整，后块转激进
        for b in act:
            if b.complete():
                kv = kv.extend(student.kv_of(b)); b.cached = True   # 完成块写入精确 KV
    return tokens(blocks)

简答题

Q27全双向 dLLM 为什么没有精确 KV cache？Fast-dLLM 的块级缓存 / DualCache 与 dKV-Cache 的延迟缓存各近似了什么？D2F 又如何用训练换来精确缓存？

双向注意力下，任何位置被去掩码都会改变其他所有位置的表示，已算过的 K/V 不再有效；下一步要更新哪些位置也要等前向后才知道。Fast-dLLM 假设在一个块的解码期间，前缀与后缀 [M] 的 K/V 不变，块末统一刷新；dKV-Cache 假设 token 定稿后表示基本稳定，但定稿当步变化最大，所以晚一步再缓存并定期刷新。二者都免训练、都是近似。D2F 把学生的注意力改成块间因果、块内双向，通过对双向教师的非对称 KL 蒸馏学会“前块未完成时预测后块”，于是完成块的 K/V 与 AR 一样精确，并能多块流水线并行。

  • 近似的证据：Fast-dLLM 的 K/V 相邻步余弦相似度接近 1；dKV 去掉一步延迟后准确率随缓存比例上升而崩溃。
  • 精确的代价：D2F 需要蒸馏（LoRA，8 × A100 训 12 小时），且学生上限是教师。
  • 加速口径都相对原始 dLLM：Fast-dLLM 27.6×、dKV 10.19×、D2F 52.9×，测量条件各不相同。

依据：dKV-Cache §3.2–3.4、Fig. 2–3；Fast-dLLM §3.2、Fig. 3；D2F §4.1–4.3、§5.1。

Q28置信度阈值并行解码的理论依据是什么？它在什么情况下失效？为什么报告加速比时必须同时给出基线、生成长度和 batch？

Fast-dLLM 定理 1：若要同时定稿的 \(n\) 个位置各自的边缘置信度都高于 \(1-\epsilon\) 且 \((n+1)\epsilon\le1\)，则逐位 argmax 拼出的序列等于模型联合分布的 argmax，且两分布的 TV / KL 距离被 \(\epsilon\) 控制。阈值 \(\tau=1-\epsilon\) 把“只并行定稿高置信位”落到实处；因子规则按 \((n+1)(1-c^{(n)})<f\) 直接控制 \(n\)。

  • 失效：定理假设联合分布自洽、只保证与模型自己的 argmax 一致；阈值规则本身不限制 \(n\)（\(\tau=0.9\) 时最坏情况只保证 \(n\le9\)，推导）；强相关、多解的位置（“high house”）恰好置信度不高或被错误地高置信；阈值过低时错误还会抬高后续不确定性（SDAR 在块扩散上观察到同样现象）。
  • 口径：Fast-dLLM 的 27.6× 是 batch 1、生成 1024、8-shot 相对原始 LLaDA；生成越长、提示越长，缓存收益越大；batch 增大后 AR 进入算力受限、吞吐反超。
  • D2F 对 AR 的 2.5× 未写明 AR 引擎与 batch，与 WeDLM 以 vLLM 为基线的比较不在同一口径。

依据：Fast-dLLM Thm. 1、App. A、App. C.2、App. C.5、Tab. 5；SDAR §5.2.3；D2F §5.2。
