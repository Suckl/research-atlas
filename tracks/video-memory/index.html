视频记忆：离开视野以后，世界还在吗？

历史上下文 · 循环状态 · 流式缓存 · 历史检索 · 三维状态 · 叙事记忆（时间线 2022 → 2026-10）

这条路线在讲什么

视频生成器一次只能“看见”有限的历史。镜头离开一个房间、人物下场、墙被拆掉之后，模型还能不能在回来时给出一致的画面？这条路线把 2025–2026 年的工作按记忆存什么、怎么被找回分成六类：把历史压缩后留在上下文里（FramePack、LCT / MoC）、写进定长循环状态（TTT、SSM、RAD）、留在流式 KV 缓存里并管理淘汰（Self Forcing / LongLive / Rolling Forcing → WorldKV / Memory Forcing）、存成可检索的帧库（WorldMem、Context-as-Memory、VMem、HyDRA）、写成三维状态（GEN3C、Voyager、PERSIST、Honeycomb、Matrix-Game 3.x），以及多镜头叙事里的关键帧与角色槽位（Captain Cinema、StoryMem、SlotMem、ShotStream）。每页都用同一张“记忆的四个操作”表拆解，并区分“画面一直稳定”与“真的记住了某件事”。每页末尾附两道简答题，共 36 题。

演化图

每一列是一种记忆机制（存什么、怎么读），时间自上而下按季度分段——这个方向几乎全部发生在 2025–2026 年。实线箭头表示方法上的直接继承，点线表示“以前者为主要对照”（不代表沿用其权重或代码）；悬停节点会高亮它的上游与下游；同一页上的多篇论文各占一个节点，点击进入该论文所在的小节。

六种记忆机制：各自存什么、付出什么

“记忆”在这里统一拆成四个操作：写（存什么、用生成的还是真实的帧、干净还是带噪）、寻址（按时间、位姿 / 视野、内容还是实体去找）、读（注意力、拼接、渲染成条件还是门控）、淘汰 / 覆盖。六种机制在这四步上的选择不同，代价落在不同的地方。

节点（建议阅读顺序）

怎么测“记住了”

“生成了十分钟还很稳定”不等于“记住了十分钟前的某件事”。专门的记忆评测都在构造一个离开 → 回来的协议，再比较回来时的画面；但它们测的东西差别很大，分数不能互相换算。

评测测什么指标读分数时要注意
Memory Maze / TECO 导航（见 04）沿已走轨迹回溯、继续在已观察环境中导航PSNR / SSIM / LPIPS回溯已见画面与推理新视角是两种任务
LoopNav（见 09）A→B→A 原路返回、A→B→C→A 绕圈返回，按路程分层PSNR、DreamSim、FVDFVD 只反映整体分布，单独不能证明“记住了”
VMem 循环相机（见 10）沿轨迹前进再原路返回起点LPIPS / PSNR / SSIM，相机误差单列轨迹简单、遮挡少，主要反映低层纹理相似
GameWorld Score（Matrix-Game，见 15）对称转回相机、共视区域的空间关系场景一致性（成对 MSE）、物体重投影误差相机估计与配准误差也计入分数；不涉及事件逻辑
HM-World（HyDRA，见 11）主体离开画面后再回来，相机与主体轨迹解耦主体裁剪的 CLIP 相似度，另报 VBench测外观吻合，不直接验证离屏期间的运动是否合理
MIND把记忆放进明确的世界模型任务（对称往返、同动作未来）与真值 / 对称帧的 MSE，动作精度单列像素误差混入相机执行与配准误差
MBench让实体离开、之后触发读取，并防止“干脆不动”逃避触发覆盖率 C、可靠性 S、M-Score = 2CS/(C+S)可靠但很少触发不算强记忆，覆盖率必须一起报
MemoBench主体离屏期间仍在变化，回来时检验新状态物体重现分 ORS、分阶段 PSNR / LPIPS、四类 VQA 通过率“保住旧外观”和“正确推出离屏变化”是两种能力
WRBench隐藏 → 返回 → 目标可辨认后才评估返回状态六个维度分开报，不合成总分；不满足条件记 NA可评估样本的比例不能被条件分数掩盖
R2M-Bench场景回访，用间隔匹配的对照去掉“低运动”捷径MG（回访优势）、DR（动态范围）、NMR = MG / DR短间隔只是参考尺度，不是上界；DR 很小时 NMR 不稳定
EntityBench（见 17）按实体时间表，人物跨多个镜头后回归跨镜头一致性（DINOv2 + LLM 判断），按回归间隔分层预先给定的人物参考不等于从生成的过去里自己记住
读结果的三条规则 ① 看信息条件：真值历史 / 真值位姿 / 预写参考测的是“读的上限”，自生成历史测的是“写错以后怎么办”，两者不能混。② 看分母：只在“触发了记忆”的样本上算的分数，必须配上触发率或可评估率。③ 画质指标（FVD、VBench 一致性、FaceID）只是辅助，要和“离开窗口的事件 → 读回 / 更新是否正确”配对才说明记忆。

贯穿路线的几条线索

线索 1

持续生成 ≠ 持久记忆

attention sink、滚动窗口和抗漂移训练能让几分钟的视频不崩，但没有“离开再回来”的测试，就不能从输出长度推断旧事件被保存。Genie 3 只有官方演示，内部机制未公开。

线索 2

“固定预算”要说清是哪一层

活跃上下文、循环状态、归档容量、总显存 / 内存、原始历史帧、地图面积是不同的量。稀疏读取不等于存储恒定，固定大小的三维表示在场景扩大时用分辨率换容量。

线索 3

存不下、找不到、读不出、用不上

失败要拆开：信息被淘汰（容量）、检索错了（寻址）、旧 KV 的位置编码不兼容（WorldTrace）、找回来但生成器没采纳。L2R 让循环状态带着“何时该回忆”的门控去读。

线索 4

静态回访之外：离屏的世界也在变

大多数方法保证“回到原地看到同样的东西”。HyDRA 开始测离屏主体，ActWorld 测动作的后果，MemoBench 要求回来时看到更新后的状态——这需要预测，而不只是存储。

线索 5

记住身份，也要允许它变

叙事记忆用关键帧和角色槽位稳住人物，但人物会换装、受伤、拿起东西。保守写入能提高身份分数，也可能压制合法的变化；身份一致不等于故事状态正确。
