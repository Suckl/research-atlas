1. 动机：持久的是表面记录，还是世界的当前状态？

人背对一棵树移动，碰撞仍应存在；转身期间洞穴的水可能继续上涨。增长的空间点缓存能记住见过的表面，但“追加新观察”与“主动预测未被观察区域如何变化”是不同能力。PERSIST 将下一 3D world-frame 和相机状态本身作为学习目标，再从它生成 RGB。PERSIST §4–5、Fig. 8

Honeycomb 解决另一项持续性问题：新空间不断进入记忆时，特征容量如何保持固定？它把 chunk 的 latent 证据融合进 HexMemory 的六个空间 / 时空平面。扩域时平面格子数不变，因此覆盖范围、分辨率和保留细节之间必须作取舍。Honeycomb §3.2–3.4

一句话理解 PERSIST 学“世界状态怎样随动作改变”，但只覆盖 agent 周围的有限区域；Honeycomb 学“新观测怎样进入固定特征预算”，但扩域会让空间和写入时间的地址变粗。两者的“固定”分别限定区域与特征张量。

2. 全局架构：主动状态转移与观测写回

视频时间为 \(t\)，扩散 / flow 时间为 \(\tau\)，当前像素 latent 为 \(x_t\)，近期窗口为 \(H_t\)，动作是 \(a_t\)，文本是 \(c_t\)，相机状态为 \(p_t\)，记忆为 \(M_t\)，查询为 \(q_t\)，读出为 \(r_t\)。Honeycomb 平面的额外时间轴记为 \(s\)：它是源观测写入时间，不是去噪时间 \(\tau\)。

$$r_t=\mathrm{Read}(M_t,q_t),\quad x_{t+1}\sim G(H_t,r_t,a_t,c_t),\quad M_{t+1}=\mathrm{Write}(M_t,x_{t+1},a_t,p_{t+1})$$

这一通用骨架适合 Honeycomb 的生成后写回。PERSIST 则先预测下一世界状态，再读它生成观测：\(M_{t+1}\sim F(M_{t-K:t},H_t,a_t,p_t)\)，预测 \(p_{t+1}\)，然后 \(r_t=\mathcal R(M_{t+1},p_{t+1})\)。近期 RGB 也进入 world-frame 条件，不能把它说成完全脱离像素的纯动力学模拟器。PERSIST §5.1–5.2

观测 / latent / 噪声生成器主干（可训练） 冻结 VAE / 几何估计可训练记忆模块 记忆本身相机 / 动作 / 文本损失

3. 组件拆解

3.1 PERSIST：world-frame 是有限的状态代理

world-frame \(w_t\) 是围绕 agent 的体素区域，结合相机 \(p_t\) 成为隐藏环境状态的代理。训练轨迹直接给出 RGB、动作、GT 体素和 GT 相机；3D-VAE 将 voxel 类别编码成 latent。3D flow denoiser 学习下一 world-frame，动作和相机经嵌入 / AdaLN 输入，近期 RGB 与相机 Plücker 信息通过 cross-attention 进入。PERSIST §4、§5.1

这里的“world-frame”并不等于永不移动的无限全局地图：区域以 agent 为中心，随着移动丢掉远处内容。稳定的三维语义有助于在当前区域内保留离屏碰撞和变化；离开其覆盖范围的地点没有自动获得永久归档。PERSIST App. E

相机由独立模型根据最近相机、世界与动作预测。相机状态包含位置、连续旋转和 FoV；让 GT 相机强行穿过模型生成的障碍，可能产生物理不相容。论文展示这一案例，并指出 FVD 未能充分惩罚它。PERSIST §5.1、§6.1、Fig. 11

3.2 从世界到像素：不是把 voxel 类别直接染色

3D-VAE 将 world latent 恢复到较高三维分辨率，再对每个像素形成按深度排序的多层 voxel 特征堆叠，同时保留线性深度。将特征和深度拼接、映射为像素生成条件后，独立 pixel flow denoiser 合成观测。它类似 learned deferred shader，补上纹理、光照、粒子效果与屏幕叠加等 3D 状态未显式给出的信息。PERSIST §5.2、Fig. 4、App. A.1

这使“状态正确”和“像素渲染正确”可以分别诊断：错误方块来自 world model，正确几何但纹理漂移来自像素侧。论文给出的长 rollout 有两类现象，不应把所有视频错误都归因于“记忆不够大”。PERSIST App. E、Fig. 13

3.3 Honeycomb：HexMemory 用空间与写入时间分解特征

HexMemory 沿世界坐标 \((x,y,z)\) 与写入时间 \(s\) 的坐标对建立平面，组合为 \((S_{XY},T_{ZS})\)、\((S_{XZ},T_{YS})\)、\((S_{YZ},T_{XS})\)。在同一地址查询成对平面，做逐元素乘积后拼接：

$$\phi(x,y,z,s)=\big[S_{XY}(x,y)\odot T_{ZS}(z,s);\ S_{XZ}(x,z)\odot T_{YS}(y,s);\ S_{YZ}(y,z)\odot T_{XS}(x,s)\big]$$

空间平面共享跨时间信息，时空平面区分不同写入时刻；不是六份完整体素地图。writer 将新 chunk 的 latent、反投影位置、源相机和射线映射为各平面贡献，通过 bilinear splatting 聚合到网格。每格累积插值权重作为置信图，再通过轻量网络形成特征。Honeycomb §3.2–3.3、Fig. 4

reader 先投影空间点并选目标 latent 单元前方最近的点，取该点的世界位置与源写入时间查询平面，再结合目标射线与相机解码成 latent，附上 visibility mask 送往 Wan 侧分支。因此定长特征平面不意味着系统不再需要几何点与可见性信息。Honeycomb §3.5

3.4 扩域 warp 与融合：固定格数意味着格距改变

新 chunk 超出旧空间或时间边界时，先扩大 bounds，把旧平面及置信图按相同世界地址重采样到新坐标范围。平面 dimensions 保持不变；未覆盖区域置信度为零。新 writer 只处理新 chunk，避免每步重编码完整历史。Honeycomb §3.4

$$P_{\mathrm{pool}}=\frac{N_oP_o+N_nP_n}{N_o+N_n},\qquad P'=P_{\mathrm{pool}}+h_\theta(P_o,P_n,P_{\mathrm{pool}},N_o,N_n),\quad N'=N_o+N_n$$

上式是按论文的置信池化与残差修正作的示意；无置信格保留旧值，修正网络输出层零初始化。历史内容不会因“张量没变大”而无损保存：反复 warp 的插值、贡献碰撞和低秩表示都限制细节。空间范围变大时相同格子的物理跨度变大，时间范围变长时写入时间分辨率也下降。Honeycomb §3.4；容量解释为机制分析

Honeycomb 写入不排除动态主体和天空，时空平面能编码随写入时间变化的观测；但这没有把 writer 变成预测离屏演化的动作条件世界转移。PERSIST 的离屏水流案例与 Honeycomb 的回访重建实验回答不同问题。Honeycomb §3.1、§4.2；PERSIST Fig. 8

5. 训练目标：GT 状态转移与潜变量重建

5.1 PERSIST：世界、相机、像素分别受监督

3D-VAE 用 voxel 类别交叉熵与 KL；2D-VAE 用像素重建 MSE 与 KL。world / pixel flow 模型各自预测从噪声向 clean latent 的速度，camera 模型对位置与旋转 / FoV 残差做 MSE。训练用 GT 世界与相机，并非只用最终 RGB 损失识别三维状态。PERSIST §3、§5、App. A.1

$$x^{\tau}=(1-\tau)x+\tau\epsilon,\qquad \mathcal L_{\mathrm{flow}}=\mathbb E\|v_\theta(x^{\tau},\tau,\mathrm{conditions})-(x-\epsilon)\|_2^2$$

此处采用论文向 clean 方向的速度约定，积分时要与该符号配套。默认推理仅需首帧 RGB 与初始相机即可采样 \(w_0\)；\(\mathrm{PERSIST}+w_0\) 是额外给 GT 3D 初始化的另一条件，分数不能当成普通首帧版。PERSIST §3、§5.1、§6.2

训练与推理之间有 GT / generated 分布差异。作者用 diffusion forcing、略加噪的历史条件与跨模块随机噪声增强缓解；各模块独立训练后组合，没有证明所有自生成长 rollout 上的误差传播已经消失。PERSIST §5.3、App. E

5.2 Honeycomb：writer / fusion / reader 联合重建 latent

记忆模型从训练 clip 依次写入首帧和后续 chunks，每次写后查询相机视图，对投影可见点对应的原始 latent 做归一化空间 MSE。writer、融合网络和 reader 联合训练，因此平面学的是支持读回的特征，而不是直接 RGB 颜色。Honeycomb §3.3

$$\mathcal L_{\mathrm{memory}}=\mathbb E\!\left[\frac{\sum_{i\in\mathcal V}\|\mathrm{Reader}_\theta(M_t,P_i,s_i,p_q)-f_i\|_2^2}{|\mathcal V|}\right]$$

上式为目标的讲解记号，\(\mathcal V\) 是当前投影可见点。随后冻结 memory 模型、预计算 readouts 来适配生成器：先训练 ControlNet branch，再冻结 branch 训练 backbone LoRA。写入训练主要读 GT 观测；推理读 generated chunk，近期条件加入噪声增强以缓解偏移。Honeycomb §3.6、§4.1、App. A

6. 伪代码：先更新世界，或先完成观测

两个独立循环，突出顺序差异；初始状态及重编码细节遵循论文的条件划分。

# PERSIST: actions update the 3D state before pixels are generated.
M, pose = initialize_world_from_rgb(seed_rgb, initial_camera)
H = encode_pixel_context(seed_rgb)
world_history = [M]
for action in action_stream:
    next_M = denoise_world(noise(), world_history, H, pose, action)
    next_pose = camera_model(pose, next_M, action)
    world_features = decode_world_vae(next_M)
    layers, depths = depth_peel_project(world_features, next_pose)
    r = embed_depth_stack(layers, depths)
    x = denoise_pixels(noise(), H, r, action)
    rgb = decode_pixel_vae(x)
    M, pose = next_M, next_pose
    world_history = roll_world_context(world_history, M)
    H = roll_pixel_context(H, x)
    yield rgb

# Honeycomb: only the new observed/generated chunk enters the writer.
M, geometry = initialize_hexmemory(seed_rgb, initial_camera)
H = encode_pixel_context(seed_rgb)
for target_poses, text in camera_requests:
    visible_points = zbuffer_project(geometry, target_poses)
    r, mask = reader(M, visible_points, target_poses)
    x = denoise_chunk(noise(), H, r, mask, text)
    rgb = vae_decode(x)
    depth = estimate_depth_at_latent_timesteps(rgb)
    new_points = lift_new_latents(x, depth, target_poses)
    new_bounds = expand_space_and_write_time(M.bounds, new_points)
    old_planes, old_conf = warp_same_shape(M, new_bounds)
    new_planes, new_conf = writer(new_points, new_bounds)
    pooled = confidence_pool(old_planes, new_planes, old_conf, new_conf)
    M = residual_fusion(pooled, old_planes, new_planes,
                        old_conf, new_conf, new_bounds)
    geometry = update_geometry_for_visibility(geometry, new_points)
    H = reencode_boundary_and_recent_frames(rgb)
    yield rgb

  • Voyager / LSM 增长的空间点缓存提供可检查的地址与具体特征。

  • PERSIST 主动演化局部世界；有限区域、GT 3D 监督与 exposure bias 限制推广。

简答题

Q27为什么 PERSIST 的动作条件 3D 状态比“生成后追加点云”更接近可变化的世界？代价是什么？

PERSIST 在合成下一 RGB 前就预测 world-frame 与相机，离屏区域仍可通过状态转移改变，也能影响碰撞与之后的可见画面。追加点缓存通常等新观测出现才写入证据。代价是需要 GT 3D / 相机监督、独立世界与像素模型，并且只维护 agent 周围的有限区域。

  • 默认推理可从首帧推断初始 3D，不能因此抹去训练的特权监督。
  • 显式 3D 初始化是另一条件，不能与普通首帧版合并分数。
  • 离屏动态的定性案例支持能力方向，尚未证明所有隐藏过程正确。

依据：PERSIST §4–5、§6.2、Fig. 8、App. E。

Q28Honeycomb 保持六个平面尺寸不变，为什么扩域仍可能遗忘？与 PERSIST 的有限区域有什么不同？

HexMemory 把更多空间与写入时间重采样进相同格数，地址分辨率下降，插值和融合也会压缩旧细节；定长存储不等于无限信息容量。PERSIST 通常维持局部区域的粒度，却在 agent 离开时丢掉远处状态。前者摊薄表示，后者截断覆盖。

  • Honeycomb 的 source write time 只是观测地址，不是离屏动力学预测器。
  • 平面尺寸消融与连续写入 probe 支持有限长度下的容量取舍。
  • 固定的是 HexMemory features；整个系统的几何和峰值显存需另算。
