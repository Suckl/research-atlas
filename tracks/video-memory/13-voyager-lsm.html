1. 动机：把缓存接到生成器前，为什么还要走一遍 RGB？

几何缓存为旧内容提供持久空间地址，却引入另一条计算链：渲染地图得到 RGB，再经 VAE 编码成生成器的条件。Voyager 改善写入端，让生成器同时产生对齐的 RGB-D，直接重建点缓存；Latent Spatial Memory 改变保存的内容，把原生 VAE 特征放到空间地址上，直接读取 latent 条件。Voyager §4；LSM §4

两篇论文在同一页，是为了比较缓存表示与读写开销。Voyager 使用 Hunyuan-Video；LSM 使用 Wan2.2。LSM 把 Voyager 作为主要基线对照，没有使用 Voyager 的模型权重。Voyager §3；LSM §5.1、App. C

一句话理解 Voyager 让“生成颜色”和“生成几何”共同完成；LSM 让“保存场景”和“读取生成条件”留在原生 latent 网格。后者减少的是缓存读条件的像素往返，仍需要解码输出和估计写回几何。

2. 全局架构：同样是点，存的东西不同

记视频时间为 \(t\)、flow 时间为 \(\tau\)，当前 latent 为 \(x_t\)，近期窗口为 \(H_t\)，相机为 \(p_t\)，文本为 \(c_t\)，记忆为 \(M_t\)，相机查询为 \(q_t\)，读出为 \(r_t\)。本页核心控制是相机轨迹，通用骨架中的动作 \(a_t\) 不代表系统已经建模了任意物体交互。

$$r_t=\mathrm{Read}(M_t,q_t),\quad x_{t+1}\sim G(H_t,r_t,a_t,c_t),\quad M_{t+1}=\mathrm{Write}(M_t,x_{t+1},a_t,p_{t+1})$$

Voyager 的 \(M_t\) 是有颜色的世界点缓存，\(r_t\) 包括 partial RGB-D 条件；LSM 的 \(M_t\) 是带 VAE 特征的空间点，\(r_t\) 直接是目标视角 latent 与可见性 mask。图中分别注明两套实现，不把两条路线拼成一套联合模型。Voyager §4.1–4.3；LSM §4.2–4.4

3. 组件拆解

3.1 Voyager：联合 RGB-D 生成是写入能力的一部分

初始图像估深度后反投影成世界点。目标相机读取缓存，形成对齐的 partial RGB、partial depth 和 mask。仅有 RGB 重投影时，模型可能在缺失区域误解遮挡关系；Voyager 把深度也作为生成目标，让颜色与几何共同参与 DiT 的注意力。Voyager §4.1–4.2

它不是单纯给 RGB latent 增加一个深度输入 channel：RGB 与深度图沿高度拼接，中间放 placeholder row；对应的条件和 mask 也按相同空间布局排列，再由 VAE 编码。当前 noisy latent、条件 latent 和 mask 才在模型输入端沿 channel 拼接。此区别决定 RGB 与深度 token 可以互相注意。Voyager §4.2、Fig. 9

轻量 Control blocks 将早层条件特征继续注入主干。生成完整 RGB-D 后，深度直接提供新点位置，省去“只生成 RGB，再运行多视图重建才能写图”的依赖；这不代表训练不需要几何标注，初始图像也仍需深度估计。Voyager §4.2、§4.4、App. A

3.2 World cache：减少重复点，不能把世界压成无限定长

逐帧写入前先从已有 cache 渲染当前覆盖 mask。新露出的区域加入点；已覆盖区域还检查已有表面法线与当前视线的夹角，超过 90°时也纳入新视角的点，避免只按 mask 保留了当前看不见的旧表面。作者报告相较保留所有点约减少 40%存储。Voyager §4.3、§5.4 Fig. 8

这里主要是选择哪些新点进入 cache，不是论文给出了任意地图增长下的严格固定容量上限。覆盖新空间仍会增加点数，错误 RGB-D 也可能进入持久条件。法线检查旨在减少视角冗余和噪声，不能替代“物体被搬走后删除旧状态”的一般机制。

几何一致不等于 chunk 边界颜色完全一致。Voyager 的 smooth video sampling 让相邻段有半段 overlap，借上一段初始化重叠区域；合并时平均、注入轻噪声并再去噪，以减轻独立生成段的颜色跳变。它处理边界拼接，长期空间信息仍来自 world cache。Voyager §4.3

3.3 Latent Spatial Memory：原生网格抬升与直接读出

LSM 把初始帧编码为 \(f\in\mathbb R^{C\times h\times w}\)，将深度降采样到同一网格，并按 VAE stride 缩放内参 \(K^\ell\)。每个 latent 单元对应世界点及其特征：

$$M_t=\{(P_i,f_i)\}_i,\qquad P_i=E_t^{-1}\!\begin{bmatrix}d_i(K_t^\ell)^{-1}[u_i+\tfrac12,v_i+\tfrac12,1]^\top\\1\end{bmatrix}$$

\(E_t\) 是 world-to-camera 外参。保存的是 VAE 特征，不是 DiT 各层 KV，也不是网络学习出的动态体素状态。读时将空间点投影到目标 latent 网格，z-buffer 留下正深度中最前的点，直接取其特征；无点单元补零，并另给 binary mask，避免把“未知”误解为合法的零特征。LSM §4.2–4.3、App. A

同一源视图读回在可见单元上可以保留原特征，仍受离散化和遮挡影响。侧分支将读出和 mask 注入生成器，不将投影条件当作永远正确的硬约束。原生网格原则是让几何匹配 latent，而非先上采样 latent 再把大量像素点降回去。LSM §4.3、§5.3

写回仍要解码 chunk、估深度和相机、分割动态主体 / 天空、重编码 RGB，然后抬升有效 latent。动态过滤可防止旧移动主体反复投影，但也明确不保存这些主体的跨 chunk 状态；后续出现运动不能证明它们被长期记住。LSM §4.4、App. C、§6 Limitations

5. 训练目标与读写的监督

Voyager 沿用 Hunyuan-Video 的 flow matching：目标是 RGB-D 联合 latent 的速度场。为了统一本 track 的符号，\(\tau\) 表示 flow 时间，\(t\) 仅表示视频进程：

$$\mathcal L_{\mathrm{flow}}=\mathbb E\!\left[\left\|v_\theta(x_{t+1}^{\tau},\tau,H_t,r_t,c_t)-v_{\mathrm{target}}\right\|_2^2\right]$$

Voyager 先训练 RGB，再加入深度，最后冻结 DiT 只训练 Control blocks。真实视频的相机 / 深度由 VGGT、MoGE 与 Metric3D 标注和对齐；最终控制阶段采用有 GT 深度的 UE 数据。这些几何标注也是系统能力的来源。Voyager §3、§4.4、App. A–C

LSM 的点写入与几何投影没有单独学习一个 writer。先冻结 VAE 和主干、训练条件侧分支，再冻结侧分支、训练主干 LoRA；两阶段均以 target flow matching 监督。缓存中的 latent 来自冻结 VAE，避免将“特征缓存”说成端到端学出的 3D 动力学状态。LSM §4.5、App. C

LSM 训练几何由预处理 ViPE 得到，默认重建器为 Depth Anything 3；动态 / 天空 mask 由实体抽取与视频分割生成。推理仍需要这些外部感知步骤，免去的是每次读取条件的 RGB render → VAE encode。LSM §5.3、App. C

6. 伪代码：把读条件与写缓存的成本拆开

下面是语义示意，smooth sampling 和 segment-aware RoPE 由相应函数封装；没有声称是官方代码逐行转写。

rgb = seed_image
depth, pose = initial_geometry(rgb)
M = lift_rgb(rgb, depth, pose) if mode == "voyager" else \
    lift_native_latent(vae_encode(rgb), depth, pose)
H = initial_context(rgb)

for target_poses, text in requests:
    if mode == "voyager":
        partial_rgb, partial_depth, mask = render_rgbd(M, target_poses)
        condition = vae_encode(stack_height(partial_rgb, partial_depth))
        x = denoise_rgbd(noise(), condition, mask, H, text)
        rgb, depth = decode_rgbd(x)
        rgb, depth = smooth_overlap_and_refine(rgb, depth, H)
        for image, d, p in zip(rgb, depth, target_poses):
            covered = render_coverage(M, p)
            keep = unseen(covered) | normal_backface_check(M, p)
            M.add(lift_rgb(image, d, p, keep))
    else:
        condition, mask = project_latent_zbuffer(M, target_poses)
        x = denoise_with_side_branch(noise(), condition, mask, H, text)
        rgb = vae_decode(x)                    # pixel operations remain
        depth, estimated_poses = reconstruct(rgb)
        dynamic, sky = segment_for_update(rgb)
        clean_latents = vae_encode(rgb)         # chunk-level re-encoding
        depth_l = resize_depth_to_native_grid(depth)
        K_l = scale_intrinsics_to_latent_grid()
        valid = valid_depth(depth_l) & ~resize_mask(dynamic | sky)
        points = lift_native_latent(clean_latents, depth_l,
                                    estimated_poses, K_l, valid)
        M.add(points)                           # cache can grow

    H = recent_clean_context(x, rgb)
    yield rgb

简答题

Q25Voyager 和 LSM 都有 3D 点缓存，为什么读写路径仍有本质区别？

Voyager 缓存颜色点，读时渲染 partial RGB-D 再编码，并联合生成完整 RGB-D 后写回；LSM 缓存 native VAE 特征点，按目标相机直接投影成 latent 条件。LSM 省掉每次读条件的像素往返，但 chunk 写入仍需输出 RGB、外部深度 / 分割与重编码。

  • RGB-D 高度拼接让 Voyager 的视觉与几何共同参与注意力。
  • LSM 将深度与内参缩放到 native 网格，不把特征先放大到像素分辨率。
  • Voyager 是 LSM 的 baseline；两者使用不同生成基座，没有权重继承证据。

依据：Voyager §4.2–4.3；LSM §4.2–4.5、§5.1、App. C。

Q26为什么不能把 LSM 的缓存显存节省解释为整个系统显存同倍率下降？

论文的显存倍率针对 3D cache pipeline。更少的空间点和更小的读出 buffer 不会同步缩小生成器权重、denoising 激活、VAE、深度与分割模型；而且 latent cache 仍随探索增长。必须先确定账本边界，才能解释“memory saving”。

  • 每点从颜色变成更宽的特征，点数压缩比例并非字节比例。
  • 读出计时、端到端生成时间和 GPU peak memory 是不同指标。
  • 若要证明整机收益，应报告相同模型、轨迹和部署策略下所有驻留模块的峰值。

依据：LSM §5.1–5.2、Fig. 6、App. B；Voyager §4.3。
