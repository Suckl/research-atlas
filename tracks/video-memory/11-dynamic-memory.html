1. 动机：记住旧外观，还要记住变化

人物走出画面后，相机再转回来：他不该突然消失、变脸或停在原处。另一类问题是打开门、拿走物品之后离开，再回来时应该保留动作后果。HyDRA 研究前者的主体 exit–entry 一致性；ActWorld 研究后者所需的互动关键帧与事件证据，并在混合导航 / 动作生成中评估。两个任务与输入条件不同，不合并成单一“动态记忆分”。HyDRA §3–5；ActWorld §3.3、§4.2–4.3

一句话理解 HyDRA 问“该找哪段过去的运动线索，才能让离屏主体合理回来”；ActWorld 问“哪些互动阶段改变了后续状态，应该保留得更清楚、更久”。两者都超出静态复刻，但都没有形式化保证任意离屏世界状态正确。

静态检索的失败很具体：与目标相机最相近的旧画面可能恰好没有主体；或者它记录的是操作前的物体。提高 FoV 相似度，可能更准确地取回错误时刻。这里衔接CaM和VMem，讨论“地址相近”之外的证据与更新。

2. HyDRA：从历史运动到当前读出

统一符号：视频时间 \(t\)，flow 时间 \(\tau\)，当前 latent \(x_t\)，近期窗口 \(H_t\)，动作 \(a_t\)，文本 \(c_t\)，相机 \(p_t\)，记忆 \(M_t\)，query \(q_t\)，readout \(r_t\)。HyDRA 中 \(M_t\) 是历史视频 token 化结果，\(q_t\) 随当前去噪隐藏特征变化；ActWorld 另有局部历史与持久 event / object bank。

$$r_t=\mathrm{Read}(M_t,q_t),\quad x_{t+1}\sim G_\theta(H_t,r_t,a_t,c_t),\quad M_{t+1}=\mathrm{Write}(M_t,x_{t+1},a_t,p_{t+1}).$$

这个骨架不是两篇共享实现：HyDRA 定义给定历史 video 和 camera 的未来段预测，没有一个明确的 action writer；ActWorld 的 Write 则依赖 interaction flags、phase transitions 和 action labels。HyDRA §4；ActWorld §3.3、App. D

3. 组件拆解：motion cues 与 event evidence

3.1 HM-World：分离相机运动和主体运动

HM-World 在 Unreal Engine 中组合场景、主体动画路径和相机轨迹，刻意制造主体离开画面后重返的事件。数据还保存主体位置与 exit / entry 时间戳，帮助定义评测；但 HyDRA 模型接口只列历史视频和历史 / 目标 camera trajectories，不能把这些渲染与评测标注误当成模型的未来主体控制输入。HyDRA §3.2、§4

这要求模型从过去视频推断身份、速度和运动模式，同时把相机自运动与主体运动分开。论文没有给出显式主体位置状态递推式；“跟踪离屏主体”是针对输出与评测的能力描述。它不证明模型逐帧维护了可查询的物理运动状态。

3.2 Memory Tokenizer：先让历史具有时间感受野

直接在原始 latent 上检索容易把主体和背景混在一起。HyDRA 先经 causal VAE 编码历史，再用 3D convolution tokenizer 融合空间与时间线索。输出 \(M_t\) 保留时序片结构；卷积的时间感受野让查询看到运动关联，而不是只有单帧外观。HyDRA §4.2、Eq. 3

运动感知表示本身不等于分离好的主体 slot，也不是未来轨迹标签。它仍是从视觉历史学出的稠密记忆；是否用到了有帮助的 motion cues，需要 temporal kernel 和 retrieval 消融支持。HyDRA §5.3、App. B

3.3 Dynamic Retrieval Attention：目标 query 查时间片

每个目标 latent 帧的 query 经空间 pooling 对齐 memory 分辨率，对各 memory temporal slice 做通道内积与空间求和，取相关性最高的时间片。随后展开这些片的全部空间 K/V，与强制保留的目标局部窗口 K/V 拼接做 attention。HyDRA §4.3、Eq. 4–6

$$S_{ij}=\frac{1}{\sqrt D}\sum_{u,v}\langle\mathrm{Pool}(q_i)_{uv},k_j(u,v)\rangle,\quad \mathcal I_i=\mathrm{TopK}_j S_{ij},\quad r_i=\mathrm{Attn}\big(q_i,[K_{\mathcal I_i},K_{\mathrm{local}}],[V_{\mathcal I_i},V_{\mathrm{local}}]\big).$$

\(D\) 为特征通道，\(i\) 为目标 latent 时间，\(j\) 为记忆时间片。论文把 retrieval length 简称为 tokens，但算法实际按时间片打分、再展开空间 tokens；不能把活动记忆规模直接写成只有 K 个 scalar tokens。query 随层与去噪步骤变化，选择也随之变化，区别于固定的 FoV context 子集。HyDRA §4.3、App. B Fig. 10

3.4 ActWorld：动作改变了状态，关键时刻必须活得更久

ActWorld 独立基于 Helios chunk-AR checkpoint。它的输入含 chunk caption、高层 action class、低层 camera control，以及 interaction flag / symbolic phase 流。phase 包含 approaching、reaching、contact、manipulating、completing、post-action，参与历史重排和 writer；不是只给一个自由文本提示就让系统自行发现全部事件。ActWorld §3.1–3.3、App. D、G

EAFR 以固定 phase prior 与 recency 混合评分，把 contact / manipulating 历史迁到精细压缩档，而非默认越老越粗；迁移保持原时间 RoPE 地址。ACHA 用 action embedding 生成各 attention head 的 history-key amplifier，提高动作相关历史的权重，不增加历史 token。ActWorld §3.3 Eq. 1–2

$$w_k=\lambda_\phi\phi(y_k^{\mathrm{int}},y_k^{\mathrm{ph}})+\lambda_r e^{-(t-k)/\beta},\qquad K'_{\mathrm{hist}}=\alpha(e_{a_t})\odot K_{\mathrm{hist}}.$$

本页用 \(\beta\) 表示 recency timescale，避免把原文的时间常数与 flow 时间 \(\tau\) 混淆。EAFR 的重要性并非视觉 learned retrieval；其 phase prior 来自结构标签。ACHA 的 amplifier 则通过训练学习。ActWorld §3.3

持久 bank 存两类紧凑 token：event token 在 Enter-Manip、Enter-Complete、Release 边界触发，组合 transition / phase / action embedding 与触发 chunk 的 attention-pool 视觉摘要；object token 从 frozen DINOv3 的高范数 patches 取视觉锚，再经可训练 projection 加 phase / action embedding。高范数是 saliency proxy，不是已经验证的物体实例分割。ActWorld §3.3 Eq. 3–4、App. D

bank 置于 DiT input 前部，进入 self-attention；segment embedding 区分 event 与 object 类型，RoPE indices 置零。它不进入承载 caption 的 cross-attention。关键 phase 来源 token 在 rollout 中被 pin，其余按 FIFO 回收。ActWorld App. D

5. 训练目标：由目标视频监督读出的价值

HyDRA 用 flow matching 训练 tokenizer、retrieval attention 与生成主干。为清楚说明方向，本页将 flow 时间重参数化为 \(\tau=0\) 噪声、\(\tau=1\) 数据，速度目标是 clean − noise，与论文 Eq. 1 的目标方向一致：HyDRA §4.1

$$x^\tau=(1-\tau)\epsilon+\tau x^{\mathrm{clean}},\qquad \mathcal L_{\mathrm{HyDRA}}=\mathbb E\left[\left\lVert v_\theta(x^\tau,\tau,M_t,p,c_t)-(x^{\mathrm{clean}}-\epsilon)\right\rVert_2^2\right].$$

它没有单列未来主体轨迹 loss 或实体跟踪 state loss；主体位置标注支持数据与评估，不能将这些标注扩写成生成器的输入。Top-K 是离散选择，梯度可更新被选 K/V 和投影，但不应把离散排序写成处处可微的检索监督。HyDRA §4、Eq. 4–6；梯度边界为算子解读

ActWorld 的 memory additions 从零初始化接口开始，通过条件生成训练学会使用事件 / 对象证据；阶段式训练继续保留 caption、action、camera、memory 条件。蒸馏使用真实历史的 pure teacher forcing，仅生成一个 chunk，不是训练时长程 self-generated bank rollout。ActWorld App. B、E、G

ActWorld 实现语义与文内不一致§3.3 的 event token 包含 AttnPool(h_k)，但 App. D 将 online event 计算描述为纯 symbolic embedding 查表；主文写 100K synthesized clips，App. H 的子集加总为 90,000。bank 固定容量且关键 tokens 整段 pin，全部槽位 pin 满后的处理未核验，论文也未说明。这里不补造解法，复现需核对官方实现 / 作者说明。ActWorld §3.3、§4.1、App. D/H

9. 承上启下：取回旧事实与更新当前事实

静态证据检索

  • CaM按 FoV 取旧画面，HyDRA 将其重训为主要动态对照。
  • VMem按可见表面取旧 views，仍需判断状态是否过时。

动态线索与事件锚

  • HyDRA 从历史视频 token 查询运动证据；ActWorld 保留阶段边界与对象视觉锚。
  • 空间缓存与持久状态还需定义动态删除、覆写与状态转移。
  • 交互游戏记忆把这些问题放到持续行动与预算约束下。

HyDRA 与 ActWorld 的并置是任务对照，不画直接继承边。它们共同揭示：找到同一物体不等于读到最新状态；保持身份也不意味着合法变化应被冻结。

简答题

Q21为什么在离屏主体重新出现时，HyDRA 的动态 query 可能比固定 FoV 帧选择更合适？

相机相近的历史可能没有主体，FoV 无法区分相同背景中的不同运动时刻。HyDRA 先将历史融合为 motion-aware tokens，再按当前目标特征选相关时间片，读取主体外观与运动线索，同时保留局部 target window 稳定生成。

  • 选择可随 denoising 与 DiT 层变化。
  • 模型得到历史 video 和 camera，并未得到未来主体路径。
  • DSC 改善支持该任务的效果，仍不保证任意遮挡、多主体或物理轨迹正确。

依据：HyDRA §4、§5.1–5.3、App. B。

Q22ActWorld 的 event memory 与 HyDRA 的 motion-aware memory 各自记住什么，怎样避免把动作完成率当成状态持久化？

HyDRA 读取历史视觉运动线索以恢复返回主体；ActWorld 根据 action / phase 条件保留关键互动帧、event transitions 和对象视觉锚。前者评 exit–entry feature consistency，后者主要评脚本动作完成与控制，分数不可互换。

  • ActWorld 的结构条件与新增标注数据必须列入信息预算。
  • 比较 event memory 消融时保留已有 caption / camera 基座。
  • 还需操作→离开→返回终态专测，并明确 bank 里新旧事件冲突如何更新。

依据：ActWorld §3.3、§4.2–4.5、App. D；HyDRA §5.1。
