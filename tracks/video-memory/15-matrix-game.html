1. 动机：游戏需要记住“刚才那里有什么”

玩家转身、绕路、再回到同一地点时，生成器面对的是两个要求：新动作要及时改变画面，旧场景要在当前窗口之外仍可找回。只把上一段末尾当条件，可以延续运动，却不能保证远处建筑、角色外观或已经发生的变化被保存。Matrix-Game 3.0 用相机寻址历史帧；Matrix-Game 3.5 进一步把历史拆成可重投影的静态 patch 与独立的主体外观参考。3.0 §3.2；3.5 §1、§2.2

一句话理解 3.0 回答“哪个旧视角值得看”，3.5 进一步回答“旧视角中的哪块内容应该落在新画面的哪里”。两者都把记忆交给生成器作为条件；三维地址和动态参考并不等于完整、可随动作演化的世界状态。3.0 §3.2；3.5 §2.2、§6

3. 组件拆解：寻址、几何对齐与状态有效性

3.0：相机感知帧检索与共同去噪

3.0 不把记忆做成额外 cross-attention 分支，而将检索旧 latent、recent latent 和当前噪声共同送入 DiT。作者报告曾尝试基于噪声特征的稀疏路由与外部 memory branch，前者在高噪声阶段选择不稳，后者对齐与收敛较慢；这是本系统的设计观察，不是所有内容检索都必然失效的结论。3.0 §3.2

$$j_i^\star=\arg\max_{j\in\mathcal C_t}s(i,j),\qquad s(i,j)=\frac{\operatorname{Vol}(\mathcal F_i\cap\mathcal F_j)}{\operatorname{Vol}(\mathcal F_i)}.$$

\(\mathcal F_i\) 是目标视锥，\(\mathcal C_t\) 是历史候选。CPU 精确求视锥交集；GPU 在目标视锥采样，估计落入旧视锥的比例。候选库随迭代增长，GPU 优化因此关系到持续吞吐量，但它没有把总候选存储变成常数。相对 Plücker 告诉网络旧证据与当前视角的关系；原始帧号与 head-wise RoPE base 扰动则帮助区分远近历史。3.0 §3.2、§3.4、Eq. 7、9–11

Matrix-Game 3.5：让记忆地址落到三维 patch

完整旧帧可能混入无关区域，而且需要生成器自行学跨视角对应。3.5 明确采用 MosaicMem 的 patch 粒度：以深度、内参、相机 pose 将旧 latent cell 抬升到世界坐标，再投影至目标视图。保留的是 latent 特征，作为 detached condition 读入，不必把 RGB 渲染后重新 VAE 编码。3.5 §2.2.1

$$X_w=T_j^{cw}\!\left(D_j(u_j)K_j^{-1}\bar u_j\right),\qquad \bar u_{\mathrm{target}}\propto K_t(T_t^{cw})^{-1}X_w.$$

此式是论文抬升 / 重投影的讲解写法；齐次坐标与 perspective divide 按实现处理。每个目标先选择能增加有效覆盖的历史帧，再用 z-buffer 消除遮挡竞争。patch 获得目标帧的时间、相机与浮点空间位置，不是沿用其旧存储顺序；原视角 context 则保留真正的历史时间。3.5 §2.1.2、§2.2.1、Fig. 3–4

静动分离：外观持久与状态演化分开

YOLO 检出的“可移动类别”不一律删除：将 mask 用深度和相机重投影后，与邻帧 mask 做双向重叠检查。稳定物体可保留；移动或不确定 track 不进入静态库，避免同一角色的不同位置被当成多处静态表面。动态分支用固定参考 tokens 保存可控角色外观，并以主体区域附加 flow loss 强化训练。3.5 §2.2.3、Eq. 3–5

边界：过滤旧动态像素可以减少 ghosting，却没有为离屏角色的速度、目标、交互后果建立持续更新的 state。论文结论也把“离屏时继续演化并正确返回”的动态状态列为后续方向。全片 prompt 的 VLM 重写还提供额外语义状态，不能把其贡献全部归给 patch memory。3.5 §4.3、Fig. 10、§6

5. 训练目标：让生成器采纳不完美记忆

使用 \(\tau=0\) 为 clean、\(\tau=1\) 为 noise 的约定，\(x^\tau=(1-\tau)x+\tau\epsilon\)。3.0 只对当前目标回归 flow；GT recent 与 memory 加入误差库中的残差，训练模型应对推理时不完美的历史。3.0 Eq. 4–6

$$\delta=\hat x-x,\quad \widetilde H=H+\gamma_h\delta,\quad\widetilde r=r+\gamma_m\delta,\qquad \mathcal L_{\mathrm{mem}}=\mathbb E\left\|v_\theta(x^\tau,\tau\mid\widetilde H,\widetilde r,a,g)-(\epsilon-x)\right\|_2^2.$$

这里的误差注入仍以真值条件为底，和完整 self-generated rollout 不同。蒸馏阶段才让学生连续生成多段、从在线库检索，随机停止于一段做 DMD；3.0 保持师生窗口架构一致。3.5 则先用 teacher-forced perceptual flow matching 做因果初始化，再用 self-rollout DMD 逐步开放记忆条件。3.0 §3.3；3.5 §2.3

$$\mathcal L_{\mathrm{3.5}}=\mathcal L_{\mathrm{full}}+\lambda_{\mathrm{sub}}\frac{\sum_u M_{\mathrm{sub}}(u)\|v_\theta(u)-v(u)\|_2^2}{\sum_u M_{\mathrm{sub}}(u)+\varepsilon}.$$

subject mask 增加人物区域梯度；anchor / context 的主体替换和训练时 mask 扰动迫使模型读取参考。patch correspondence 是几何计算、记忆作为 detached condition，不通过重投影学习 writer。3.5 §2.2.1、§2.2.3、Eq. 5

3.5 的 DMD 条件需要按文字理解 Eq. 11 将师生写成共享条件的 KL；紧随其后的实现说明又明确：student 在线更新记忆，scorer 记忆保持固定，只共享初始记忆、anchor、prompt 与轨迹等稳定条件。不能据公式省略这项差别，或宣称教师读取了学生全部更新后的 bank。3.5 §2.3，Eq. 10–11 后文

简答题

Q29为什么实时 FPS 高、视频能持续生成，都不足以证明游戏世界有长程记忆？

FPS 衡量计算吞吐量，持续输出主要检验漂移控制；长程记忆还要求窗口外的具体观察被写入、在回访时找到并被采用。3.0 的 FoV 检索与 3.5 的空间 patch 才提供这种证据路径，仍应将相机执行、静态再现、动态更新和动作延迟分别测量。3.0 §3.2、§5.2；3.5 §4.2、§4.4

  • 重复同一个错误场景也可能获得高自一致；需要 GT、受控事件或独立状态核验补充。
  • 实时演示与记忆主表的 checkpoint、GPU 和预算必须匹配；稳态 FPS 也不等于首帧或按键响应延迟。

依据：3.0 Fig. 9、Tab. 1；3.5 §4.2–4.4、Tab. 1；GameNGen §7。

Q30为什么 3.5 要把移动主体从三维 patch 库分离？固定外观参考能否替代动态世界状态？

把同一移动对象在不同时间的位置融合成静态观察，会产生重复对象、ghosting 和错误遮挡；运动一致性过滤排除这些候选，参考 prefix 则保存主体身份。固定外观不包含离屏期间的运动或动作后果，所以它不能独立替代动态状态转移。3.5 §2.2.3、§6

  • 过滤依据是几何运动，静止车辆或人物仍可能是有效空间证据。
  • 合法状态变化需要带时间的写入、覆盖或独立实体 state；本论文未以通用事件持久化协议证明这些能力。
