1. 动机：历史不再是越来越长的 token 列表

若过去视频只存在注意力窗口里，窗口移走就失去直接读取路径；若全部保留，计算和 K/V 存储不断增长。循环方法换一个存储对象：让历史改写固定形状的状态，后续生成查询这个状态。本页比较 TTT-Video 的小网络权重、SSM-WM 的分块状态，以及 RAD 的逐帧 RNN 读写协议。它们是不同方案，合页不表示互相继承。TTT-Video §2–3；SSM-WM §4；RAD §4

一句话理解 固定的是状态的形状，不是可精确记住的事件数。状态如何更新、更新什么噪声水平的输入，以及局部 attention 是否替它承担细节传递，都会改变实际记忆能力。

沿用视频时间 \(t\)、扩散时间 \(\tau\)、latent \(x_t\)、近期窗口 \(H_t\)、动作 \(a_t\)、文本 \(c_t\)、相机 \(p_t\)、状态记忆 \(M_t\)、query \(q_t\) 和读出 \(r_t\)。TTT 公式内部再用 \(u_i\) 表示扫描序列的第 \(i\) 个 token，避免把 token 次序、视频时间与扩散时间混为一谈。

3. 组件拆解

3.1 TTT-Video：小 MLP 的权重就是隐藏记忆

普通 RNN 把历史写入向量或矩阵；TTT 把隐藏状态设为一个小网络 \(f(\cdot;W)\) 的权重。当前 token 经 K 投影提供输入，经 V 投影提供自监督标签；内层梯度步改写 \(W\)，Q 投影再向这个已经更新的小网络提问。它没有在测试时获得真实未来帧标签。TTT-Video §2.1–2.2

$$\ell_i(W)=\left\|f(\theta_Ku_i;W)-\theta_Vu_i\right\|_2^2,\qquad W_i=W_{i-1}-\eta\nabla_W\ell_i(W_{i-1}),\qquad r_i=f(\theta_Qu_i;W_i)$$

外层生成训练学习 Q/K/V 投影、初始化与其他主干参数；内层只更新序列自己的 \(W\)。外层需要通过“梯度更新这个计算”学习有效写入，并不是推理时对整个视频生成器继续训练。小模型包含 residual、LayerNorm 和带 GELU 的双层 MLP；内层 mini-batch 把 token 更新合并以便并行。TTT-Video §2.3、§3.4

模型从 CogVideo-X 基座出发，attention 限制在局部 segment，TTT 跨全序列扫描。每个块加入带门控的正向扫描与反向扫描，后者能读取后续带噪内容。这是一种双向整段扩散架构，不是像 流式 KV 一样只见完成历史的在线生成。TTT-Video §3.1–3.2

3.2 SSM-WM：分块 scan 为什么同时改变容量与路径

SSM-WM 使用因果 Mamba scan 和 frame-local attention。将整个帧的空间 token 都放在相邻视频帧之间，会把同一空间位置在时间上的距离拉得很长。方法沿空间划分块，每块独立扫描其全部时间序列；相邻时刻 token 之间的扫描距离降为块面积，且每个块获得独立状态。SSM-WM §4.1、Fig. 3

小块缩短时间路径，也扩大总状态预算，却削弱块间空间通信；大块有利于空间关系，但时间记忆更难。论文在不同层使用不同块尺寸，并在每个 Mamba 后接局部因果 attention，允许同帧双向交换和读取近期帧。它保存的是特征状态，空间块地址仍是图像坐标划分，并非一个显式三维地图。SSM-WM §4.1；最后一句为表示解释

训练混入随机长度的完全 clean 前缀，对后续帧独立加噪、只计算带噪帧损失。这样较远 clean 观测可能比近处 noisy 帧更有用，减少仅靠近邻完成去噪的捷径。推理每层保存固定数量的局部 K/V 与各块 SSM state。SSM-WM §4.2–4.3、Fig. 4

3.3 RAD：比较 RNN 前，先比较它被要求传递什么

RAD 在 DiT 中加入沿时间更新的 RNN，比较 LSTM、Mamba2 和 TTT。chunk-wise 模式的 attention 窗口互不重叠，跨窗口视觉信息全靠状态；frame-wise 模式每次只滑动一帧，近期细节可以通过重叠 attention 直接传递，状态不必承担全部像素信息。RAD §4.1–4.2

frame-wise 推理有两个关键约束：每个窗口只由第一帧负责推进持久状态；只在最后去噪步提交更新，输入来自 clean 帧。窗口里其他帧可以参与当前计算，但不能在每个去噪步被反复写成新历史。RAD §4.2、Alg. 1

训练先用真实 clean 序列、单帧窗口预取各层各时刻隐藏状态，再把这些状态送到正常窗口的并行 attention／扩散训练里。它缓解顺序 attention 的训练瓶颈，但训练写入仍来自 GT，推理写入来自生成历史；“结构和处理粒度对齐”不等同于 Self Forcing 式的自生成训练历史。RAD §4.3、Alg. 2；对比为信息条件解释

论文伪代码与正文的提交粒度 Alg. 1 用一个返回的隐藏状态符号概括窗口计算；正文 §4.2 明确规定仅窗口第一帧推进持久记忆。本页伪代码展开这条正文规则，把整窗临时计算与提交状态分开；不据简写推断整窗会被重复写入。

5. 训练目标：内层写入与外层监督分开

TTT 的自监督重建是内层记忆更新目标，外层仍是视频扩散生成训练。SSM-WM／RAD 用动作条件的 diffusion forcing 去噪目标；状态没有独立的“旧事件列表”标签。以统一符号写成：TTT §2；SSM §3.1、§4.2；RAD §3.2、§4.3

$$r_t=\mathrm{Read}(M_t,q_t),\qquad \mathcal L_{\mathrm{video}}=\mathbb E\sum_{t\in\mathcal T_{\mathrm{noisy}}}w(\tau_t)\left\|\epsilon_\theta\big(x_t(\tau_t),H_t,r_t,a_t\big)-\epsilon_t\right\|_2^2$$

公式是比较骨架，不强行统一各论文的参数化与权重。SSM 的 clean 前缀不计算去噪损失；RAD 先构造 clean hidden bank，再训练带噪窗口。前向读取得到 GT 状态、后向是否完整跨越其构造过程，是不同问题；RAD 预取 bank 的完整跨时刻梯度边界尚未逐行核对实现，本页不宣称所有预取帧都接受完整回传。SSM §4.2；RAD Alg. 2

6. 伪代码：两种不同的记忆生命周期

recurrent_memory.py（TTT 前向与 RAD frame-wise 生成；按正文展开）
def ttt_pass(tokens, initial_W):
    W = copy(initial_W)                    # 当前层、当前前向自己的状态
    result = []
    for batch in token_minibatches(tokens):
        K, V, Q = project_views(batch)
        loss = mse(small_mlp(K, W), V)
        W = W - eta * grad(loss, W)        # self-supervised 写入
        result.append(small_mlp(Q, W))     # 读取更新后状态
    return concat(result)

def ttt_video_block(noisy_video, storyboard):
    X = pack_tokens(noisy_video, storyboard)
    tokens = local_segment_attention(adaptive_ln(X))
    fwd = gated_residual(tokens, ttt_pass(tokens, W_init))
    rev = reverse(ttt_pass(reverse(fwd), W_init))
    # 正反扫描共享 TTT 参数，使用不同门控；保留外侧 residual
    return gated_residual(fwd, rev) + X   # 包含后续带噪内容

def rad_generate(clean_context, actions, window_size):
    state = zero_state_per_layer()
    # 历史超出局部窗口的部分逐帧预填持久状态
    state, recent = prefill_oldest_first(clean_context, state,
                                        keep=window_size - 1)
    for action in actions:
        window = concat(recent, sample_noise())
        stable_state = copy(state)
        for tau in denoise_schedule:
            pred = rad_forward(window, tau, action, stable_state)
            window = denoise_step(window, pred, tau)
            # 中间步骤的临时 state 不提交
        emit(window[-1])
        oldest_clean = window[0]
        # 对应正文 §4.2：最后去噪步的 clean 特征，只提交第一帧
        state = commit_first_frame_clean_features(oldest_clean,
                                                   stable_state)
        recent = window[1:]
    return state

伪代码省略每层递归、调度器和模型细节；RAD 的提交行表达最后去噪步的更新语义，不主张必须额外调用一次全模型。

9. 承上启下：从状态容量到写入规则

保留或选择历史 token

  • LCT / MoC仍有可直接细读的历史 token，存储随 context 扩大。
  • TTT-Video、SSM-WM 与 RAD 分别检验不同状态及读写协议；这里不画未经论文声明的继承箭头。

把写入边界说清楚

  • 后续 ARL2（2026-05）将跨帧分支改为 gated linear state：同帧 token 共用更新前状态，只在最终 clean pass 写入。ARL2 v2 §3.2–3.3；首发月取 abs v1
  • ARL2 的固定状态承诺绑定被替换的 hybrid 层；部分未替换 softmax 层的 KV 仍需另计。
  • 流式 KV保留近期具体帧；L2R进一步研究相机条件的状态读回。

简答题

Q7TTT 把网络权重当作状态，是否意味着测试时在重新训练整个生成器？与 SSM 存历史有什么区别？

TTT 在网络前向内部用当前序列构造自监督任务，只更新该序列的小模型权重 W；主干和 Q/K/V 投影来自外层训练。SSM 按学习好的状态转移规则累计输入，两者都压缩历史，但更新算子和状态表达方式不同。TTT-Video 还采用双向整段扫描，不能直接当作因果流式 writer。

  • 内层目标重建的是 V 投影特征，不是真实未来视频。
  • 小 MLP 更丰富的表达并不保证任意旧细节可被精确找回。
  • 状态维度、更新成本、任务与 context 长度都要一起比较。

依据：TTT-Video §2–3、§4.4；SSM-WM §3.2、§4。

Q8为什么 RAD 中切换 chunk-wise 与 frame-wise 后，LSTM、Mamba、TTT 的差距会改变？固定状态是否保证无限记忆？

互不重叠的 chunk 把局部像素传递也交给状态；逐帧重叠窗口让 attention 承担这些细节，状态主要保存更远信息，因而三种 RNN 的差距缩小。固定状态只保证存储形状不随时间增长，信息覆盖、干扰与训练长度外推仍限制有效记忆。

  • RAD 比较对齐数据与训练步数，参数与运行时间并不完全相同。
  • 只提交最旧 clean 帧，避免滑窗重复写入或混入去噪中间状态。
  • SSM-WM 明确报告超过训练 context 后记忆仍有限，不能从恒定每帧成本推断无限准确。

依据：RAD §4.2、§5.2–5.5、Tab. 3、Tab. 5；SSM-WM §6。
