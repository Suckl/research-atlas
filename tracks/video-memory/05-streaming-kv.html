1. 动机：缓存里的帧，到底能记住多久

Self Forcing 的蒸馏与训练历史对齐已在 少步生成轨道拆解。本页只沿记忆的数据流看它与 LongLive、Rolling Forcing：过去帧怎样变成 K/V，哪些保留、哪些淘汰，文本变化后缓存为何需要重算，以及多帧联合去噪如何稳定持续生成。Self Forcing §3.2、§3.4；LongLive §3；Rolling Forcing §3

一句话理解 KV cache 既是省掉历史重算的计算缓存，也是当前能直接读取的视觉记忆。rolling window 记近期，sink 记开头；它们稳定画面，但没有自动为中途事件建立可长期查询的档案。

记视频时间为 \(t\)，扩散时间为 \(\tau\)，clean latent 为 \(x_t\)，带噪状态为 \(x_t(\tau)\)，近期窗口为 \(H_t\)，文本为 \(c_t\)，缓存记忆为 \(M_t\)，query 为 \(q_t\)，读出为 \(r_t\)。本页 \(t\) 可以指 latent 帧或生成 chunk，具体数量注明粒度；这些 T2V 模型没有单独的动作 \(a_t\)／相机 \(p_t\) 检索索引。

2. 全局架构：读缓存、生成、clean 写入与淘汰

观测帧 / latent / 噪声生成器主干（可训练） 冻结网络（VAE 等）记忆模块可训练部分 记忆本身文本 / 动作 / 相机条件损失

3. 组件拆解

3.1 Self Forcing：缓存 clean 表示，不沿用 noisy 中间态

SF 去噪当前生成块时，历史 K/V 作为条件被读取；完成以后再以 \(\tau=0\) 做前向，把完成 latent 编成历史 K/V。训练也使用自己生成的历史，缓存写入停止梯度；推理则维护固定长度 FIFO。SF §3.2、§3.4、Alg. 1–2

“clean”是没有扩散噪声的模型输出，不等于真值正确。错误外观也会被 clean pass 编成后续条件；所以 clean 写入解决表示的噪声水平一致性，自生成历史训练解决另一种分布偏差。蒸馏损失、随机截断和教师规模见 已有训练目标页。

SF 特别指出：首个 VAE latent 帧只编码初始图像，与时间压缩后的其他 latent 统计不同。若训练时一直能看见它、推理滚动后却淘汰它，会产生闪烁。原方法训练时屏蔽“最后 chunk 看首 chunk”的路径来模拟丢失首帧，并没有把永久 sink 作为唯一解。SF §3.4

3.2 LongLive：近期窗口、frame sink 与 prompt re-cache

LongLive 在近期 KV 之外保留首个 frame chunk 作永久 sink，让当前 query 始终能够读取开头的身份、背景和色调证据。训练也用短窗口和 sink，并通过 streaming long tuning 继续沿用跨迭代 KV 生成后续片段，使训练见到长期自生成历史。LongLive §3.2–3.3

prompt 切换时有一个信息冲突：保留原 KV 会留下旧语义；彻底清空又丢掉视觉连续性。KV re-cache 用已有 generated 帧 + 新 prompt重新计算表示，保留可见内容，刷新文本影响。实现成本绑定仍持有的近期窗口；它不为所有旧帧建立检索索引，也不会凭空恢复已淘汰的事件。LongLive §3.1、§3.3

$$M_t^{\mathrm{recent,new}}=\mathrm{KV}_{\theta}\big(H_t,\tau=0,c_{\mathrm{new}}\big),\qquad r_t=\mathrm{Attn}\big(q_t,[M_t^{\mathrm{sink}},M_t^{\mathrm{recent,new}}]\big)$$

上式概括近期 re-cache 与锚点读取的分工。论文后文明确以最近窗口重建 cache；本次核对的官方 LongLive1.0 交互配置设 global_sink: true，保留原 sink，只刷新近期表示。关闭该选项时，交互 pipeline 传入 sink 重建标记，允许覆盖 sink。不能从“整个 prefix”这句概括推定所有路径都刷新初始锚。LongLive §3.3；官方 c6a27e7：LongLive1.0/pipeline/interactive_causal_inference.py、wan/modules/causal_model.py

论文内部：sink 粒度描述不一致 §3.3 的一般训练段落写 “first two frames”，但 Fig. 5、§4 Implementation 与 §4.5 的具体配置是首个 chunk，实验比较为 9 个近期 latent 帧 + 3 个 sink latent 帧。LongLive v2 §3.3、Fig. 5、§4.5 官方原版配置也设 local_attn_size: 12、sink_size: 3、context_noise: 0。官方 c6a27e7：LongLive1.0/configs/longlive_interactive_inference.yaml 本页按具体实验与该配置解释粒度，不能把 RGB 帧、latent 帧与 chunk 混算。

3.3 Rolling Forcing：多个未来块共同去噪

RF 不只是换了缓存淘汰规则。它维护一个滚动去噪窗口：越靠后的块噪声越高，当前窗口内部双向注意力，让相邻块共同修正；每次推进所有块的噪声水平，释放最前面的 clean 块，再在末尾加入新噪声。历史 KV 仍只被因果读取。RF §3.2、Fig. 3

窗口长度按去噪阶段数设置；实际 chunk 包含多个 latent 帧。这个未完成窗口是工作区，近期与开头 KV 是持久可读上下文，三者不能叫成同一个“历史窗口”。未来内容已经部分计算，会影响 interactive prompt 切换延迟；这是论文明确列出的取舍。RF §3.2、§4.1、App. E

RF 的开头锚还有地址管理：保存 global context 的未施加 RoPE 的 K，每次读取时把它重定位到近期历史之前，使相对距离处于训练范围内。保留内容与修复地址缺一不可；若原始开头索引一直不动，随生成变长可能产生位置外推伪影。RF §3.3、App. D、Fig. 7

写入近期缓存时，RF 的 clean pass 只看近期上下文，排除 global context；global anchor 单独保留。这样生成时的“全局 + 近期”读取，和近期 KV 的构造范围也必须分开。RF App. A：KV Cache

3.4 稳定画面，为什么仍会忘掉中途事件

如果开头是一件红外套，中途换成蓝外套并离开视野，sink 保留的是开头信息；近期窗口最后也不含换装帧。模型可能维持稳定色调与流畅运动，却没有可寻址的证据回答回来以后应穿哪件衣服。这个例子是机制推断；RF 附录则明确承认中段内容离开 temporal context 后被丢弃，没有中段记忆。RF App. E

因此需区分三个检查：写入是否 clean、缓存地址是否可用、需要的事件是否仍被保留。re-cache 能刷新存着的信息；sink 能保留指定初始锚；联合去噪能减缓误差传播。它们都不自动提供“按事件检索全部远程历史”的能力。

4. 缓存预算与张量形状

设每帧 token 数为 \(P\)，头数为 \(h\)，每头宽度为 \(d\)，层数为 \(L\)，近期帧数为 \(w\)，sink 帧数为 \(s\)，去噪工作区 latent 帧数为 \(u\)。形状是机制推导，具体配置来自各论文。

对象形状 / 数量解释
每层近期 K、V各 [B, wP, h, d]存储量约 2B·L·wP·h·d 个元素；固定 w 后不随时长增长。由 SF Alg. 2 推导
sink K、V各 [B, sP, h, d]独立于 FIFO；其保留内容来自开头而不是自动摘要。
LongLive 实验短窗口w = 9，s = 3 latent 帧活动历史共 12 latent 帧，与 21-frame 长窗口作比较。LongLive Fig. 5、§4.5
RF 历史与工作区w = 3，s = 3，u = 15 latent 帧5 阶段 × 3 latent 帧／chunk 的工作窗口；总活动范围 21 latent 帧。RF §4.1、App. A；乘加为推导
流式训练resident：近期 + sink + 当前监督片段历史缓存截断梯度；当前片段的训练图另占显存。LongLive §3.2–3.3

固定 KV 不等于整个应用固定内存：保存全部输出视频、prompt 记录或用于重建的原始帧另计。窗口的 token 数也受分辨率和 VAE 压缩率影响；不能只比较“记住多少秒”。

5. 记忆怎样进入训练

SF 的要点是训练 rollout 读取自己写出的历史；缓存写入停止梯度。LongLive 将缓存跨训练迭代保留，继续生成新片段，只在当前片段接受教师监督，并把 prompt switch 的 re-cache 纳入训练。RF 使用滚动生成历史，联合窗口和 SF 目标交替以稳定运动；损失与蒸馏推导见 少步轨道的长视频后训练。SF §3.2；LongLive §3.1–3.2；RF §3.4

$$r_t=\mathrm{Read}(M_t,q_t),\qquad x_{t+1}\sim G_\theta(H_t,r_t,c_t),\qquad M_{t+1}=\mathrm{EvictAppend}\!\left(M_t,\mathrm{KV}_{\theta}(x_{t+1},0,c_t)\right)$$

上式是本页统一的记忆骨架；RF 的 \(G\) 同时更新整个带噪工作区，仅释放的 clean 块进入 \(M\)。LongLive 遇 prompt switch 还插入 \(\mathrm{Recache}\)；sink 的保留策略由方法决定。训练输出更稳定，不直接意味着模型优化了特定远程事件的召回损失。

9. 承上启下：从活跃缓存到被逐出的记忆

能持续读写的有限上下文

  • 循环状态压缩旧内容；本页 K/V 保留近期具体 token。
  • SF 提供自生成历史与滚动缓存；LongLive 扩展长期训练和 prompt 适配。

固定 sink 之外的事件

  • RF 改变工作窗口，配合初始 sink 与动态位置，降低长期漂移。
  • WorldKV / Memory Forcing KV进一步保存或重读被活动窗口逐出的内容。
  • 可寻址记忆讨论内容仍在却读不到的问题；帧库检索显式选择更早视觉证据。

简答题

Q9为什么写 KV 需要 clean pass？prompt 变化时，clean 缓存又为什么还要 re-cache？

clean pass 让持久缓存表示完成帧而不是某个去噪中间态；但完成帧的层内 K/V 仍受生成时文本条件影响。切换 prompt 后重新用已有帧与新文本计算缓存，能保留视觉历史同时减弱旧语义惯性。clean 与 condition-compatible 是不同要求。

  • 这里的重编码是 clean latent 的生成主干前向，不是必须每次走 RGB–VAE 循环。
  • 清空缓存提高新条件影响，却破坏视觉连续性；保留原缓存可能迟迟不跟新条件。
  • re-cache 只更新仍持有的上下文，不是远程事件检索。

依据：SF Alg. 1–2；LongLive §3.1、§3.3、Tab. 4；RF App. A。

Q10滚动窗口、sink 和联合去噪为什么能稳定长视频，却仍不等于记住一个中途发生的远程事件？

滚动 KV 保存近邻，sink 保留指定开头，联合去噪让相邻未来块共同修正。它们控制局部连续性与全局外观漂移，但没有为所有中段事件保留可寻址证据。事件帧一旦不属于近期窗口也不属于 sink，后续只能依赖残留影响或模型先验。

  • RF 动态重定位 global K 解决地址外推，不扩充中段档案。
  • ΔDrift 比较首尾画质，不验证特定对象返回时状态正确。
  • 要测具体记忆，必须确保事件真正离窗，再要求恢复更新后的状态。

依据：LongLive §3.3；RF §3.3、§4.1、App. D–E；事件例与评测建议为机制推断。
