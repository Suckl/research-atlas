1. 动机：扩散负责快，AR 负责对

小 batch 解码时 AR 是访存受限的：每步搬一遍权重和 KV，却只算 1 个 token。TiDAR 在单张 H100、batch 1、FlashAttention 2 下测 Qwen3-32B：一次前向多塞一批 token，延迟几乎不变，直到进入算力受限区。作者把这些多出来的位置叫作“免费 token 槽”。TiDAR §1、Fig. 1掩码扩散正好能一次填满多个槽，但开源 dLLM 每步多定稿就掉点：TiDAR 引用 APD 的数据，Dream-7B 在 GSM8K 上从每步 1 个 token 改为 2 个，准确率降约 10%。TiDAR §2.1

投机解码提供了另一半：草稿随便猜，目标模型一次前向验证，输出分布由验证规则保证。但 EAGLE-3 这类草稿器仍自回归地一个一个猜，起草时间随草稿长度线性增长。本页三篇把“扩散并行起草”和“AR 验证”拼在一起，区别在于草稿器和验证器是否同一个模型、是否在同一次前向里：

一句话理解 扩散擅长“同时猜很多个”，AR 擅长“判断猜得对不对”。TiDAR 把两件事塞进同一次前向，用二次方个掩码位为每种可能的接受结果提前起草；Nemotron-Labs-Diffusion 把同一权重训练成能在 AR、扩散、自推测之间切换；DFlash 干脆只让一个小扩散模型当草稿器，目标模型原封不动，因而能直接装进 SGLang / vLLM。

3. 组件拆解

3.1 TiDAR：同一前向里“想”和“说”

训练。在 Block Diffusion 的双倍长度输入上改一处：前缀全部因果，只有末尾的扩散段块内双向。前缀可以算标准 next-token 损失（Block Diffusion 的块内双向会泄漏标签，做不到），扩散段全部设为 [M]，于是两种损失的项数都等于序列长度，用一个系数 \(\alpha\) 平衡即可，默认 \(\alpha=1\)。TiDAR §3.1、§3.31.5B 从 Qwen2.5-1.5B 继续预训练 50B tokens（块长 4 / 8 / 16），8B 从 Qwen3-8B 训 150B tokens（块长 16）；全局 batch 2M tokens，学习率 \(10^{-5}\to3\times10^{-6}\) 余弦，序列长 4096，H100，BF16。§4.1

解码对比。在同一个全掩码训练的 1.5B 模型上比较解码策略：置信度 > 0.9 的阈值解码 T/NFE 2.63、GSM8K 51.40；左到右每步 1 token 为 53.37；TiDAR 8 草稿 T/NFE 5.49、GSM8K 54.74，16 草稿 6.97、53.90。阈值越低（0.6）T/NFE 3.81 但 GSM8K 跌到 37.60。也就是说，同一模型用“AR 验证”去收割并行度，比单靠置信度阈值稳得多。TiDAR Tab. 4把扩散段从随机掩码改为全掩码，4 草稿时平均分 45.45 → 48.42。Tab. 5

测量口径。所有效率数字在单张 H100、batch 1、原生 PyTorch + FlexAttention 下测得；AR、EAGLE-3、Block Diffusion 都开精确缓存。EAGLE-3 用的是第三方发布的 Qwen3-8B Instruct 草稿权重（基座版没有公开权重），而 TiDAR 8B 的主表对照是 Qwen3 8B 基座。§4.3 及脚注作者在局限中承认只测了 batch 1，也尚未写专用 kernel。§5

3.2 Nemotron-Labs-Diffusion：一套权重，三种解码模式

联合目标与训练配方。\(\mathcal L=\mathcal L_{\mathrm{AR}}+\alpha\,\mathcal L_{\mathrm{diff}}\)，\(\alpha=0.3\)；扩散项是块扩散的 \(1/t\) 加权 NELBO。训练沿用双流输入，但干净流内部改成严格因果（沿用 Set Block Decoding 的做法），这样同一次前向既算扩散损失、又算无泄漏的 AR 损失。从 Ministral3 Base 出发，阶段 1 纯 AR 训 1T tokens，阶段 2 联合训练 300B tokens；SFT 45B tokens、序列 16k；256 张 H100。Nemotron §2.1–2.2、§5.1–5.2在 Ministral3-8B 上 25B tokens 的逐项消融里，加入 AR 损失的单项提升最大（平均 +7.48），两阶段训练 +5.74，全局 token 平均（而非按序列平均）+2.12；\(\alpha\) 扫描中 AR 模式与扩散模式在 0.3 同时最好。Tab. 1–2、§2.3–2.4

三种模式。① AR：普通左到右，适合高并发。② 扩散：逐块阈值解码，块完成后刷新 KV；可换成一个 4.8M 参数、4 层的小 Transformer 采样器，预测“当前 top-1 是否等于最终会提交的 token”，在同样准确率下 TPF 约 1.3×。③ 自推测（线性 SS）：在已验证前缀后接 \(k\) 个 [M]，用扩散模式一次前向起草；再用 AR 模式对草稿做一次因果前向，接受 \(x^{\mathrm{AR}}_{n+j}=\hat x_{n+j}\) 的最长前缀，外加首个不一致位的 AR 预测，每轮产出 1 到 \(k+1\) 个 token。§3.1–3.3、App. A、Fig. 7草稿路径上另挂一个只作用于 \(o_{\mathrm{proj}}\) 的 LoRA（秩 128，约 36M 参数，占骨干 0.4%），用 LK-hybrid（KL 与 TV 的自适应混合）加交叉熵对齐 AR 验证器，只在“已接受 + 第一个被拒”位置计损失；3B / 8B / 14B 的 TPF 分别相对提升 14.4% / 32.5% / 27.6%。§3.3、Eq. 6–9、§6.1二次型 SS 沿用 TiDAR 的单前向布局，并可用 AR 与扩散预测的加权混合作验证器。§3.4、App. C

Speed-of-light 分析。以“每步只定稿最高置信一位”的串行去噪结果为目标，搜索每步最多能安全并行提交多少位（递归动态压缩，每块模拟预算 5000 次前向）。在 SPEED-Bench 713 条样本上，\(B=32\) 时平均每步可提交 7.60 个，多语种 11.26、角色扮演 3.49；线性 SS 的接受长度 6.82 已接近，但它每轮要两次前向、且只能接受连续前缀，真实 TPF 为 3.41，而 SOL 为 6.02，差 76.5%。§4.1–4.2、Tab. 4、Fig. 6

Nemotron-Labs-Diffusion：TPF 与“4×”的口径 ① §4 明确说线性 SS 每轮两次前向，真实 TPF = 接受长度 / 2（6.82 → 3.41）；Tab. 5 给线性 SS 标的 “TPF 5.99” 论文没说口径；官方 evaluate.py 按“生成 token 数 ÷ 前向次数”计，起草和验证各算 1 次前向，且仓库 README 的 GSM8K 示例（93.78%、TPF 5.89）与 Tab. 5 一致，所以 5.99 应当已经是每次前向的数（对应每轮约 12 个 token，数学、代码类基准输出规整、好猜；推断依据见 精读页 §3.5）。② 摘要称 GB200 上吞吐为 Qwen3-8B 的 4×；§6.5 的数字是相对本模型 AR 模式最高 3.3×，使用优化 kernel 时 3.97×、1015 tok/s。③ 自推测与 AR 模式的小幅精度差，作者归因于单 token 解码与多 token prefill 的 kernel 数值差异。Nemotron 摘要、§4.2、Tab. 5、§6.1、§6.5

3.3 DFlash：只当草稿器的块扩散模型

为什么扩散适合起草。每轮平均每 token 延迟为 \(L=(T_{\mathrm{draft}}+T_{\mathrm{verify}})/\ell_{\mathrm{acc}}\)。自回归草稿器 \(T_{\mathrm{draft}}=\gamma\,t_{\mathrm{step}}\)，只能做得很浅（EAGLE-3 为单层）；扩散草稿器一次前向出整块，\(T_{\mathrm{draft}}=t_{\mathrm{parallel}}\)，块长适中时几乎与草稿长度无关，因此可以加深到 5 层。作者测得 5 层 DFlash 生成 16 个 token 的起草延迟低于 1 层 EAGLE-3 生成 8 个。DFlash §3.1–3.2、Eq. 1–3、Fig. 3

“目标最懂行”：KV 注入。目标模型做验证前向时，从第 2 层到倒数第 3 层均匀取 5 层隐状态，拼接后经一个投影 \(\mathbf H_t=\mathrm{RMSNorm}(W_c[\mathbf H^{(l_1)};\dots;\mathbf H^{(l_5)}])\) 得到上下文特征，再作为额外的 K/V 注入每一层草稿网络（而不是像 EAGLE-3 那样只在输入层融合）；这些 K/V 存在草稿模型自己的 KV cache 里。嵌入层和 LM head 与目标共享并冻结，只训练草稿 Transformer 层。没有目标特征时，同样 5 层的扩散草稿器只有约 2–3× 加速。§4.1、App. A.2–A.3、Tab. 10

训练对齐推理。回答由目标模型自己生成（约 80 万条，来自 Nemotron 后训练数据 V2 与 CodeAlpaca 的提示）；每条序列随机取 512 个“锚点”，锚点是干净 token（对应推理时上一轮验证给出的修正 token），其后 \(k-1\) 个位置为 [M]；块与块之间互不可见，块内双向。块内第 \(j\) 位的交叉熵乘 \(w_j=\exp(-(j-1)/\gamma)\)，\(k=16\) 时 \(\gamma=7\)：越靠前的错误越会让整块作废。6 个 epoch，学习率 \(6\times10^{-4}\)。§4.2、Eq. 4、App. A.1

进入服务框架。论文在 SGLang（单张 B200、FlashAttention-4 后端、Spec-v2 调度重叠）上报告并发 1–32 的吞吐，在 vLLM 上报告 Qwen3.5-9B 的结果；官方仓库给出 SGLang 与 vLLM 的接入方式。§5.3、App. A.4；官方 README训练块长 16 的草稿器可在推理时改用块长 8，反之不行，便于高并发时缩短块以减少验证开销。§5.5.4、Tab. 8

5. 训练目标与“无损”的含义

TiDAR（\(S\) 为序列长，\(\mathcal L_{\mathrm{AR}}\)、\(\mathcal L_{\mathrm{Diff}}\) 分别在干净段、全掩码段上用不同注意力计算交叉熵）：TiDAR §3.1

$$\mathcal L_{\mathrm{TiDAR}}=\frac{1}{1+\alpha}\Big(\sum_{i=1}^{S-1}\frac{\alpha}{S-1}\mathcal L_{\mathrm{AR}}(x_i,x_{i+1})+\sum_{i=1}^{S-1}\frac{1}{S-1}\mathcal L_{\mathrm{Diff}}([\mathrm M],x_i)\Big)$$

Nemotron-Labs-Diffusion（块 \(b\) 被腐蚀，前序块干净）与其 LoRA 草稿对齐项（\(\tilde p_j,\tilde q_j\) 为截断到 top-200 并集后的验证器 / 草稿器分布，温度 3）：Nemotron Eq. 2–3、Eq. 6

$$\mathcal L=\mathcal L_{\mathrm{AR}}+\alpha\,\mathbb E_t\Big[-\frac1t\sum_b\log p_\theta\big(x^{b}\mid\tilde x_t^{b},x^{<b}\big)\Big],\qquad \mathcal L^{\mathrm{LK}}_j=\lambda_j\,\mathrm{KL}(\tilde p_j\Vert\tilde q_j)+(1-\lambda_j)\,\mathrm{TV}(\tilde p_j,\tilde q_j)$$

其中 \(\mathrm{TV}=1-\alpha_j\)，\(\alpha_j=\sum_v\min(\tilde p_j,\tilde q_j)\) 正是投机采样的接受概率，\(\lambda_j=\exp(-0.5\,\mathrm{sg}[\alpha_j])\)。DFlash 对块内第 \(j\) 位用 \(w_j=\exp(-(j-1)/\gamma)\) 加权交叉熵。DFlash Eq. 4

无损指什么。标准投机采样以概率 \(\min(1,p(x)/q(x))\) 接受草稿 \(x\)，被拒时从 \((p-q)_+\) 重采样，输出分布与目标模型 \(p\) 完全一致；温度 0 时退化为“草稿等于目标 argmax 才接受”，输出与目标的贪心解码逐 token 相同。DFlash 的目标模型冻结，作者称无损，并在温度 0 与 1 下都报告了加速。TiDAR 的验证器是同一模型的 AR 视角，还可混入扩散 logits，输出等于“这个混合模型的贪心结果”，不等于某个外部 AR 基座——DFlash 也指出 TiDAR 尚非无损。Nemotron 的线性 SS 以本模型 AR 模式的 greedy 输出为准。DFlash §2.3、§5.1；TiDAR §4.3；Nemotron §3.3投机解码的接受规则推导见 AI Infra 投机解码页。

6. 伪代码

hybrid_decode.py（TiDAR 一步 + DFlash 一轮；依据 TiDAR §3.2–3.3、DFlash §4.1、App. A.3）
def tidar_step(model, kv, drafts, k, beta=1.0):
    groups = [[MASK] * k for _ in range(k)]                 # 第 j 组：假设接受 j 个草稿
    x = drafts + sum(groups, [])                            # k + k*k 个 query
    mask = sliced_mask(len(kv), k)                          # 预建掩码按前缀长度切片
    logits_ar, logits_diff, kv_new = model(x, kv, mask)    # 一次前向
    mixed = beta * logits_ar[:k] + (1 - beta) * logits_diff[:k]
    j = longest_prefix(argmax(mixed) == drafts)             # 接受 j 个（各组首位与 AR 预测同一位置）
    kv = kv.append(kv_new[:j])                              # 只保留被接受 token 的 KV
    next_drafts = argmax(logits_diff[group_slice(j, k)])    # 一步扩散：直接取第 j 组
    return kv, drafts[:j], next_drafts

def dflash_round(target, drafter, kv_t, kv_d, bonus, k=16, temp=0.0):
    block = [bonus] + [MASK] * (k - 1)                      # 锚点 = 上轮目标给出的 token
    q = drafter(block, kv_d)                                # 一次前向，块内双向，读注入的目标特征
    draft = sample(q, temp)
    p, feats, kv_t = target.verify([bonus] + draft[1:], kv_t)   # 目标一次前向
    acc, bonus = speculative_accept(draft[1:], p, q, temp)  # min(1, p/q) 规则；temp=0 时为相等即收
    h = rms_norm(W_c @ concat(feats.layers(5)))             # 5 层特征融合
    kv_d = kv_d.append(project_kv_all_layers(h[:len(acc) + 1]))  # 注入每层草稿 K/V
    return acc, bonus, kv_t, kv_d

解决了什么

  • AR→块扩散的模型仍要用阈值赌并行度；这里用 AR 验证收割并行度，质量由验证规则兜底。

简答题

Q25TiDAR 如何在一次前向里同时验证上一轮草稿、又为下一轮起草？为什么要为每种可能的接受长度各准备一组掩码，代价是什么？

输入由三段组成：已缓存的前缀、上一轮的 \(k\) 个草稿、\(k\) 组各 \(k\) 个 [M]。结构化掩码让草稿段按因果注意力计算——其 AR logits 用来逐位验证；第 \(j\) 组 [M] 组内双向、只看前缀和前 \(j\) 个草稿，用一步扩散给出“若接受 \(j\) 个”时的下一块草稿。前向结束后按实际接受长度取对应一组，因此起草永远不必等验证结果，也不需要第二次前向。

  • 代价：每步 query 数 \(k(1+k)\)（\(k=16\) 为 272），只有在“免费 token 槽”内才不增延迟；论文仅测了 batch 1。
  • 验证用的是同一模型的（可混合）argmax，不保证与外部 AR 基座逐 token 相同；8B 平均 65.31 低于 Qwen3-8B 的 68.09。
  • Nemotron-Labs-Diffusion 的二次型自推测沿用这一布局；其线性模式改为两次前向，换来更小的单步计算。

依据：TiDAR §1、§3.1–3.3、§4.3、§5、Tab. 2；Nemotron §3.4。

Q26让扩散模型只当 AR 的草稿器（DFlash）与让同一模型三模式切换（Nemotron-Labs-Diffusion）各有何取舍？“无损”在哪些设置下成立，接受长度与端到端加速为何随并发下降？

DFlash 冻结目标模型，只训一个读目标多层特征的 5 层块扩散草稿器，验证走标准投机规则，所以输出分布等于目标模型（温度 0 时逐 token 相同），并能直接接入 SGLang / vLLM；代价是每个目标都要单独训草稿器，草稿器容量有限。Nemotron 把草稿器做成基座本身，接受长度更高（LoRA 后 6.82）且一套权重可在 AR、扩散、自推测之间按并发切换；代价是需要 1T + 300B tokens 的联合训练，“无损”只相对于它自己的 AR 模式。

  • 并发升高后，每轮多出的验证与起草 token 占用真实算力，单位时间收益被摊薄：DFlash 在 Qwen3-8B Math500 上从 5.1× 降到 2.8×（并发 1 → 32）。
  • 接受长度依赖任务熵：DFlash 在 MT-Bench 上约 4.2，在数学上 6.5–7.9；Nemotron 角色扮演 5.54、多语种 10.06。
  • TiDAR 的验证可混入扩散 logits，严格说不是无损。

依据：DFlash §4、§5.1–5.3、Tab. 1、Tab. 3；Nemotron §3.3、§6.5、Tab. 10；TiDAR §4.4.3。
