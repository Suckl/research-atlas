这条路线在讲什么

自回归 LLM 一次只写一个 token，而且写下就不再改。扩散语言模型把生成改成在一张画布上反复去噪：一次可以定好多个位置（并行）、能同时看左右两边（双向）、迭代中还能回头改（可修改）。代价是没有精确似然、没有现成的 KV cache，并且同一步里并行定下的位置彼此独立采样，会出现“因子分解误差”。这条路线按六个方向梳理 2021–2026 年的工作：噪声与训练目标（SEDD → MDLM → 离散流匹配 → 均匀噪声）、规模与配方（LLaDA、Dream、LLaDA2.x、DiffusionGemma / Mercury / Seed）、块扩散与 AR 混合（BD3-LM → SDAR / WeDLM → TiDAR / DFlash）、缓存与并行解码（Fast-dLLM、dParallel、对并行上限的分析）、后训练（d1 → LLaDA 1.5 → TraceRL、代码模型）与多模态。每页都有一张“与自回归模型对照”的表，并把每个速度数字的测量条件写清楚。共 19 页、47 篇论文、38 道简答题。

节点（建议阅读顺序）

读速度与分数时的检查清单

扩散 LLM 的速度和分数很容易被测量条件改变。每页的结果表都附了测量条件；读别处的数字时，可以对照这份清单：

  1. NFE 与每次前向定稿的 token 数（TPF）要成对看：同一个模型每步定几个 token 取决于采样器阈值，单报一个数没有意义。
  2. AR 基线用的是什么引擎：应当是带 KV cache 的 vLLM / SGLang / TensorRT-LLM，而不是 HuggingFace 的 generate。多页指出论文用后者做基线（见 15、14）。
  3. batch 与并发：扩散 LLM 的优势来自低并发下的访存受限；batch 变大后缓存与并行解码的收益明显缩小。硬件、精度（FP8 / BF16）也要写清。
  4. 生成长度与画布：掩码扩散要预设生成长度，太长浪费计算、太短截断答案；变长方法改变了这一口径。
  5. 块大小：块扩散与半自回归采样里，块大小在 AR（块长 1）与全扩散之间插值，跨论文比较要对齐。
  6. 似然评测：ELBO 只是上界，不同噪声族的 ELBO 不可直接比；选择题用 MC-ELBO 还是置信度打分也会改变分数（见 06）。
  7. 生成困惑度的陷阱：必须和熵一起看；fp32 类别采样相当于降温，会让少步结果显得更好（见 02、04）。
  8. 标准基准看不见并行退化：数学与代码是低熵、强结构任务；需要针对 token 相关性的测试（见 ParallelBench）。
  9. 评测设置是否按模型调过：采样步数、阈值、EOS 处理按模型和任务分别调参很常见（见 17）。
  10. 厂商自报 vs 第三方测量：Gemini Diffusion、Mercury 2 等主要是自报；部分 Mercury 数字来自第三方测量，要分开看（见 10）。

悬而未决的问题

问题 1

掩码、均匀还是连续噪声？

掩码扩散目标最简单、困惑度最好，是 LLaDA / Dream / LLaDA2.x 的选择；2026 年的均匀噪声扩展律与 DiffusionGemma（技术报告写明用均匀 / 多项式噪声）又把问题打开，并且指出跨噪声族比较困惑度会误导。

问题 2

训练到底比 AR 贵多少？

SMDM 的“约 16× 计算”、数据受限时扩散反超 AR 的交叉点、两篇论文之间的方法学之争，以及 2026-10-13 才发布的重新测算（尚未复现）——各页并列给出，不合成一个数字。

问题 3

真实服务里更快吗？

单请求、低并发时的 tok/s 很亮眼；对齐到 vLLM 级 AR 基线、拉高 batch 之后，收益会缩小甚至反转。速度数字必须带上硬件、batch 与基线引擎。

问题 4

任意顺序：资产还是陷阱？

自适应顺序能绕开难子问题（Sudoku 类任务）；但 Flexibility Trap 指出 RL 中任意顺序让模型躲开高不确定性 token、解空间过早塌缩，左到右 GRPO 反而更好；快速 dLLM 实际也常退化为近似左到右。

问题 5

独立范式，还是 AR 的加速器？

DFlash 进入 vLLM / SGLang、Nemotron 的自推测模式都让扩散为 AR 起草；DiffusionGemma、Mercury 2、LLaDA2.1 坚持纯扩散生成。两条路线都在时间线上标出。
