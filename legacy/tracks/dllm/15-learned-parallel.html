1. 动机：模型“知道”得太晚，阈值再低也救不回来

掩码扩散每次前向都给出全部 \([\mathrm{M}]\) 位置的预测，理论上一步可以定稿很多 token；但开源 dLLM（LLaDA、Dream）要保住精度，步数 \(N\) 几乎要等于生成长度 \(L\)。免训练的置信度阈值能省一些步：LLaDA-8B-Instruct 在 GSM8K 上平均只到 3–4 TPF，再激进就掉点。dParallel §1、§5.2、Tab. 1dParallel 给出的诊断是：确定性按从左到右的次序收敛——每步只有紧挨已知上下文的少数位置置信度高，其余位置要等新上下文出现才会变确定。dParallel §4.1、Fig. 2

因此本页三篇都不改采样器的“胆量”，而是改模型本身：让模型在更早的步、更多的位置上真的变得确定。三条路线：dParallel 沿模型自己的轨迹自蒸馏并直接压低熵；d3LLM 用教师的解码顺序构造中间态并配多块解码；CDLM 把图像侧的一致性蒸馏（一致性模型）搬到离散 token 轨迹上，并顺手把注意力改成块因果以拿到精确 KV cache。

一句话理解 并行解码的上限首先取决于“模型在第几步对哪些位置有把握”。训练式方法把多步才收敛的确定性压到前几步：dParallel 用熵项“逼”出确定性，d3LLM 教模型按什么顺序可以早定稿，CDLM 让较少信息的状态与块完成态的预测一致。它们都只在数学 / 代码等低熵任务上报告，且无法消除条件独立带来的因子分解误差。

记号：干净序列 \(x_0\)（长 \(L\)），腐蚀态 \(x_t\)，\(t\in[0,1]\) 为掩码率（\(t=1\) 全掩码），去噪网络 \(p_{\theta}(x_0^i\mid x_t)\)，块大小 \(B\)，步数 \(N\)，每次前向定稿 token 数 TPF，阈值 \(\tau\)，提示 \(c\)。dParallel 把块长记作 \(L_b\)、掩码率记作 \(q\)、温度记作 \(T\)；d3LLM 用 \(t\) 表示掩码率、\(k\) 表示解码窗口；CDLM 把阈值记作 \(\tau_{\mathrm{conf}}\)、把中间态记作 \(y\)。

3. 组件拆解

3.1 瓶颈：确定性是“逐个传递”的

dParallel 的两组观察（LLaDA-8B-Instruct、GSM8K）：① 用不同置信度阈值解码时，定稿 token 的平均置信度与答案正确率正相关，低置信度定稿常导致错误；② 每一步只有邻近已知上下文的一小段位置达到高置信度，平均置信度呈从左到右推进的“波前”，单个 token 的置信度轨迹也按先后次序收敛。dParallel §4.1、Fig. 2、Fig. 6由此推出：阈值调低只是提前定稿低置信 token（错误级联），真正要改的是收敛动力学本身；仅做轨迹对齐的 teacher forcing / diffusion forcing 不针对确定性，作者认为不足。dParallel §4.1

3.2 确定性强制蒸馏（Certainty-Forcing Distillation）

两项损失分工明确：交叉熵把学生钉在原模型的生成轨迹上（保精度），熵项让已经对的预测更早变尖（提并行）。消融说明两者缺一不可：只有一致性项 53 步 / 73.5%，只有熵项 23 步 / 57.8%，再去掉半自回归掩码（两项都在）44 步 / 73.3%，三者齐全 30 步 / 76.1%（GSM8K）。dParallel Tab. 3掩码率消融中固定 50% 最好（76.3%，训 1 epoch），随机掩码率 72.4%、100% 掩码 71.1%。dParallel Tab. 4作者把 50% 解释为“掩码与未掩码 token 的平衡”，属于经验结论。

与它对比的“一致性蒸馏”基线（训练模型从轨迹中间态直接预测全部剩余掩码，类似 LCM）在 LLaDA 上几乎无效：64 步时 GSM8K 69.9%、MBPP 25.0%，与直接把步数砍到 64 的结果接近。dParallel §5.1、Tab. 1这与后文 CDLM 的结论（单独一致性损失会崩）相互印证。

3.3 d3LLM：伪轨迹蒸馏、课程与多块解码

伪轨迹。教师（块大小 32 的块扩散 LLaDA / Dream）每步只定稿 1 个 token，并在 EOS 之后继续生成以填满长度 \(n\)，记录每个位置在第几步被定稿——只取顺序，不取内容。训练时取解码窗口 \(w=\{s,\dots,s+k\}\) 与掩码率 \(t\)：窗口之前保留真值，窗口之后全掩码，窗口内按教师在第 \(s+\lceil kt\rceil\) 步时的掩码状态决定哪些位置可见，内容一律用数据集真值 \(\mathbf y\)。相对随机掩码，TPF 提高约 18%。d3LLM §3.1、Tab. 5作者承认这样窗口内的实际掩码率不精确等于 \(t\)，但选择保留全局顺序。d3LLM App. A.11

课程。掩码率 \(t\) 在训练中从 0.0 线性升到 0.8（相对固定 \(t=0.5\)，TPF 7.49 → 9.11），窗口 \(k\) 从 16 升到 32（固定 \(k=32\) 时 TPF 8.22、精度 69.8%）。d3LLM §3.1、Tab. 6–7损失仍沿用 dParallel 的确定性强制（温度 0.5，熵权重 LLaDA 2.0 / Dream 1.0）与互补掩码，蒸馏数据也直接用 dParallel 的数据集。d3LLM App. A.11

多块解码 + KV 刷新。受 D2F 启发，前一块完成 10% 时激活下一块（只按熵阈值保守解码），前一块完成 95% 时转为“完全激活”（每次前向至少定稿 1 个）；块写满后先进入“完成但稳定中”状态，1–2 轮不用缓存的前向后才写入 KV cache，并定期全量刷新缓存；生成 EOS 即停止。多块解码使 TPF 约 +30%，早停约 +5%。d3LLM §3.2

3.4 AUP：把“精度–并行度曲线”压成一个数

扫描阈值得到一组点 \((\rho_i,y_i)\)，\(\rho\) 为 TPF、\(y\) 为精度（%），按 \(\rho\) 升序；只保留 \(y_i\ge y_{\min}=y_1-5\) 的点。d3LLM §2

$$\mathrm{AUP}=\rho_1y_1+\sum_{i=2}^{m}(\rho_i-\rho_{i-1})\,\frac{y_iW(y_i)+y_{i-1}W(y_{i-1})}{2},\qquad W(y)=\min\!\Big(e^{-\alpha(1-y/y_{\max})},\,1\Big),\ \alpha=3.$$

\(y_{\max}\) 是该任务上所有方法达到的最高精度，所以一个方法的 AUP 会随参照集合变化。只有一个点（TPF=1）时 AUP 就等于精度：原始 LLaDA 在 GSM8K-CoT 上 AUP=72.6=精度。d3LLM §2、Tab. 1若精度在 TPF 1→9 区间完全不掉，AUP 约为 \(9\times y\)（推算）；d3LLM-LLaDA 的 637.7 接近这个上界。作者在附录换用指数 / 幂 / 线性三类 \(W\)、\(\alpha\in\{1,\dots,10\}\) 与 \(\Delta y\in\{1,\dots,10\}\)，方法排序不变。d3LLM Tab. 8、Tab. 10–13注意：§2 把 \(y_1\) 定义为最低并行度点的精度，App. A.6 却称其为“最高精度”。d3LLM §2、App. A.6

AUP 基于 TPF 而非墙钟，作者以此称其“与硬件无关”。d3LLM App. A.4 Remark 3代价是它不计每次前向的成本：一次多块前向处理的 token 数、推测解码的草稿开销都不进 TPF。作者自己也指出与 EAGLE-3 的对比未约束总 FLOPs。d3LLM App. A.7

3.5 CDLM：一致性蒸馏 + 块因果学生

离线轨迹。双向教师按块解码，块大小 \(B=32\)、生成长 \(L_g=256\)、步数 \(N=L_g\)（每步只定稿 1 个最高置信 token），温度取 \(\{0,0.5\}\) 各生成一条（\(\tau=1.0\) 会破坏推理链）。每定稿一个 token 就把教师最后一层隐状态写入长 \(L_g\) 的缓冲，蒸馏时用 lm_head 重建教师分布；存隐状态比存 logits 约省 30 倍，每 15k 样本的分片约 25–30 GiB。CDLM §4.1、Alg. 1、App. A.1

三项损失。从轨迹上取中间态 \(y\) 及其“块完成态” \(y^{\star}\)（把 \(y\) 的活动块全部揭开）。\(\mathcal U_y\)=两者之间新揭开的位置，\(\mathcal S_y\)=到 \(y^{\star}\) 仍是掩码的位置。蒸馏项在 \(\mathcal U_y\) 上让学生匹配教师分布（前向 KL），提供“一次多定几个”的监督；一致性项在 \(\mathcal S_y\) 上让学生在 \(y\) 处的预测对齐自己在 \(y^{\star}\) 处的预测（目标停梯度）；DLM 项是标准掩码去噪损失，真值文本是 Qwen2.5-7B 的回答。CDLM §4.2、Eq. 4–7、App. A.1、App. C与图像一致性模型不同，这里没有 PF-ODE，“一致”的是同一块内“少信息态”与“块完成态”。只开一致性项会崩（GSM8K 6.9%、HumanEval 0.0%），只开蒸馏项收敛快但略掉点。CDLM §2.4、Tab. 3

块因果学生。学生只看提示、已完成块与当前块，因此提示与已完成块的 KV 可以精确缓存，并能在块边界遇到 EOS 早停；推理时块内用 Fast-dLLM 式置信度阈值 \(\tau=0.9\) 并行定稿，不用块间并行。CDLM §4.3、Fig. 2代价是看不到后续块：HumanEval-Instruct 上 CDLM-Dream 的有效生成长度只有 96.9（其他方法约 200），作者归因于失去了全局“长度预算感”。CDLM §5.2.1、Tab. 1

算术强度。以 \(L_p=512\)、\(L_g=256\) 建模（A100，脊点约 153 FLOP/Byte）：batch 1 时 AR 解码约 1.0，全注意力 dLLM 约 438.9（已算力受限），块因果 \(B=4/16/32\) 分别为 4.0 / 15.8 / 31.1；\(B=32\) 约在 batch 8 越过脊点。CDLM §5.4、App. B.4这解释了块式 dLLM 的优势集中在小 batch（与 访存受限的解码同理）。

5. 训练目标

dParallel。\(\tilde Y\) 为半自回归掩码后的画布，\(\mathcal M_a\) 为活动块掩码位置，\(\mathcal M_c\subseteq\mathcal M_a\) 为 argmax 已等于目标的位置：

$$\mathcal L_{\mathrm{CFD}}=\underbrace{-\frac{1}{|\mathcal M_a|}\sum_{i\in\mathcal M_a}\log p_{\theta}(y_i\mid\tilde Y)}_{\text{一致性}}+\beta\underbrace{\frac{1}{|\mathcal M_c|}\sum_{i\in\mathcal M_c}H\big(p_{\theta}(\cdot\mid\tilde Y;T)\big)_i}_{\text{确定性强制}},\qquad T=0.5,\ \beta=2.$$

d3LLM。窗口 \(w=\{s,\dots,s+k\}\)，\(\mathcal T_j\) 为教师第 \(j\) 步的掩码状态：位置 \(i\) 在 \(i\le s\) 或 \(\mathcal T_{s+\lceil kt\rceil}\) 中已揭开时取真值 \(\mathbf y_i\)，在 \(i>s+k\) 或仍被掩码时为 \([\mathrm M]\)；再对掩码位置做交叉熵并叠加确定性强制项。d3LLM §3.1、App. A.11

CDLM。\(y\) 与块完成态 \(y^{\star}\)，\(q_{\phi^-}\) 为停梯度目标，\(p^{(T)}_i=\mathrm{softmax}(\texttt{lm\_head}(\mathbf h_{x,i}))\)：

$$\mathcal L=w_{\mathrm{d}}\frac{1}{|\mathcal U_y|}\sum_{i\in\mathcal U_y}\mathrm{KL}\big(p^{(T)}_i\,\|\,q_{\phi}(\cdot\mid y,c)_i\big)+w_{\mathrm{c}}\frac{1}{|\mathcal S_y|}\sum_{i\in\mathcal S_y}\mathrm{KL}\big(q_{\phi^-}(\cdot\mid y^{\star},c)_i\,\|\,q_{\phi}(\cdot\mid y,c)_i\big)+w_{\mathrm{dlm}}\mathcal L_{\mathrm{DLM}}.$$

三者都没有改变“各位置独立采样”的解码形式：训练只让边缘分布更早变尖，联合分布中的相关性仍要靠步数来处理（见 ParallelBench 的下界）。

6. 伪代码

dparallel.py（机制示意；对应 dParallel Alg. 1 与官方 llada_train.py / generate.py）
def cfd_train_step(student, Y, plen, L=256, B=32, q=0.5, T=0.5, beta=2.0):
    # Y: [b, plen + L]，提示 + 教师自生成且答案正确的回答
    n = randint(0, L // B - 1)                      # 活动块编号
    s, e = plen + n * B, plen + (n + 1) * B
    x = Y.clone()
    act = zeros_like(Y, dtype=bool)
    act[:, s:e] = rand(Y.size(0), B) < q            # 活动块 50% 掩码
    x[act] = MASK
    x[:, e:] = MASK                                 # 未来块全掩码
    logits = student(x)                             # 全双向，一次前向
    ce = cross_entropy(logits[act], Y[act])         # 一致性：贴住原轨迹
    correct = act & (logits.argmax(-1) == Y)        # M_c：已预测正确
    pT = softmax(logits[correct] / T, dim=-1)
    ent = -(pT * log(pT)).sum(-1).mean()            # 确定性强制
    return ce + beta * ent                          # 官方代码再对 ~act（互补掩码）算一遍

@torch.no_grad()
def decode(model, c, L=256, B=32, tau_H=0.45):
    x = cat([c, full((L,), MASK)])
    for blk in range(L // B):
        lo, hi = len(c) + blk * B, len(c) + (blk + 1) * B
        while (x[lo:hi] == MASK).any():
            p = softmax(model(x)[lo:hi], dim=-1)    # 每步重算整张画布
            H = -(p * log(p)).sum(-1)
            m = x[lo:hi] == MASK
            pick = m & (H < tau_H)                  # 低熵位置同步定稿
            if not pick.any():
                pick[where(m, H, inf).argmin()] = True
            x[lo:hi][pick] = p.argmax(-1)[pick]
    return x

  • D2F 已用蒸馏训出块因果学生与块间流水线，但并行度提升以精度为代价（d3LLM 的对照）。
  • 图像侧的一致性模型与 DMD 证明了“少步蒸馏”可行，但语言 token 是离散的、彼此强相关。

本页：把确定性训进模型 → 留下的问题

  • 三篇都只在数学 / 代码上报告，且训练数据多为数学提示；在高相关、低结构的任务上，ParallelBench 显示并行解码仍会系统性出错。
  • 块因果（CDLM）与 AR→块扩散转换、BD3-LM 殊途同归：越接近 AR，越容易拿到精确缓存，越远离全局双向。

简答题

Q29dParallel 为什么只对“已经预测正确”的掩码位置最小化熵？如果去掉一致性交叉熵、只保留熵项，会发生什么？

熵项的作用是把“已经对的预测”更早推到高置信度，让熵阈值解码敢在同一步定稿更多位置；若对所有掩码位置压熵，错误预测也会被变尖，模型会自信地输出错 token，正好放大并行定稿时的错误级联。交叉熵负责把学生锁在原模型的生成轨迹上，它一旦预测正确梯度就变小，不会主动提升确定性，所以两项缺一不可：只用熵项时 GSM8K 只需 23 步，但精度从 76.1% 跌到 57.8%；只用交叉熵则 53 步、73.5%，并行度几乎没变。dParallel Eq. 5–8、Tab. 3

  • “正确”由 argmax 与教师 token 是否一致判定，教师 token 本身来自过滤后的正确回答。
  • 熵在温度 \(T=0.5\) 下计算；argmax 不受温度影响，温度只改变熵项的梯度强度。
  • d3LLM 直接沿用了这一损失（LLaDA 权重 2.0、Dream 1.0），并换掉了构造中间态的方法。

依据：dParallel §4.2、Alg. 1、Tab. 3；官方代码 llada_train.py；d3LLM App. A.11。

Q30AUP 相比单报 TPF 或 TPS 解决了什么、又漏掉了什么？为什么“TPF 更高”不等于“更快”？

AUP 对精度–并行度曲线下的面积做指数加权：精度掉得越多，增加的并行度贡献越小，并截掉比最低并行度点精度低 5 分以上的点，因此不能靠牺牲精度刷 TPF；它基于 TPF，不受 GPU 与推理框架影响。漏掉的是每次前向的成本：全注意力 dLLM 每步重算整张画布，多块解码一次处理更多 token，推测解码要另跑草稿模型，这些都不进 TPF；作者也承认与 EAGLE-3 的对比没有约束 FLOPs。墙钟上，d3LLM-LLaDA 对 AR 的加速在 H100 上是 5.0×，在 A100 上只有 3.6×（HF 后端），AR 基线也不是 vLLM / SGLang。d3LLM §2、App. A.4、A.7、A.8、Tab. 3

  • AUP 依赖 \(y_{\max}\)（该任务所有对比方法的最高精度），换一组对比方法，同一模型的分数会变。
  • 评估墙钟收益时需同时写出硬件、batch、生成长度、块长与 AR 引擎；CDLM 的算术强度分析说明，块式 dLLM 的优势集中在小 batch。
  • TPF 也依赖计数口径：dParallel 自测约 8.5 token/步，在 d3LLM 的评测里是 5.14。

依据：d3LLM §2、Tab. 1、Tab. 3、Tab. 14–15；CDLM §5.4；dParallel Tab. 1。
