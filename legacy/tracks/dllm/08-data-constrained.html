1. 动机：16× 计算，还是 16× 数据？

SMDM 的“掩码扩散约需 16 倍计算”是在数据充足、每个 token 只看一遍的设定下测得的：计算增加时，模型和独特数据同比放大。Prabhudesai 等指出这把两件事混在了一起——扩散到底是计算效率低，还是样本效率低？如果独特数据有限、只能重复训练，结论可能相反。Data-Constrained §1、§3.1这个问题并非学术游戏：高质量公开文本被预测将在几年内耗尽，机器人、医疗等领域一开始就是数据稀缺。Data-Constrained §1

两篇论文给出同一方向的结论：Diffusion Beats Autoregressive in Data-Constrained Settings（CMU，2025-07，NeurIPS 2025）拟合了数据受限扩展律并给出扩散反超 AR 的临界计算量闭式；Diffusion Language Models are Super Data Learners（NUS / Sea AI Lab 等，博客 2025-08-09，arXiv 2025-11）在更大规模上观察到下游任务的“交叉点”，并公开批评前者的方法学。两者给出的数字不能合并，本页把它们并列。两篇论文摘要；Super Data 官方博客

一句话理解 同一条序列，AR 每个 epoch 做的都是同一套“从左往右猜下一个”的题，重复几遍就背熟了；掩码扩散每个 epoch 重新抽掩码比例和位置，等于从同一数据里出新题。代价是单位计算学得更慢——所以数据充足时 AR 赢，数据稀缺、计算充裕时扩散赢。

记号：独特 token 数 \(U\)，epoch 数 \(E\)，总训练 token \(D=UE\)，非嵌入参数 \(N\)，计算 \(C\approx6ND\)。掩码比例在 Data-Constrained 论文中记为 \(r\)，等同于本 track 的 \(t\)（\(t=1\) 全掩）。Data-Constrained §2

3. 组件拆解

3.1 实验设定：把计算和数据拆开

以往比较（SMDM，以及多模态上的 Swerdlow 等）都在单 epoch 下按 \(C\sim6ND\) 同时放大 \(N\) 与 \(D\)，所以分不清扩散是缺计算还是缺数据。这里固定 \(U\)、变化 \(N\) 与 \(E\)，让总计算可以在不增加独特数据的情况下继续增长。Data-Constrained §3.1超参：batch 256 条序列，AdamW \((0.9,0.95)\)、\(\epsilon=10^{-8}\)，峰值学习率 2e-4、最低 2e-5，1% warmup，余弦衰减，wd 0.1，梯度裁剪 1.0；随 epoch 数调整学习率调度；Megatron-DeepSpeed 实现。Data-Constrained §2.2、App. 8–9

3.2 数据受限扩展律：重复数据还值多少

Muennighoff 等对 AR 的结论是：重复约 4 个 epoch 与新数据几乎一样好，之后迅速贬值。本文对扩散拟合同一形式，结论是扩散的重复数据在约 100 个 epoch 内都接近新数据，\(R_D^{*}\) 比 AR 大一个数量级以上。Data-Constrained §3.2、Fig. 5在固定计算（\(10^{19}\)、\(3\times10^{19}\)、\(10^{20}\) FLOPs）下改变“独特数据 × epoch”的组合，AR 的验证损失随 epoch 增加而上升，扩散的几条曲线几乎重合。Data-Constrained Fig. 3–4

同一论文中的三组 \(R_D^{*}\)引言写扩散约 500、AR 约 15（AR 的 15 引自 Muennighoff 等）；§3.2 正文写 512.85 vs 31.93；Tab. 1(b) 写 493.89 vs 31.19。三处出自不同的拟合轮次或来源，论文没有统一说明；本页图中取“约 500 vs 约 31”的量级。Data-Constrained §1、§3.2、Tab. 1(b)；读 arXiv v7

3.3 临界计算量的闭式

由拟合式 \(\log_{10}U=0.460\log_{10}C-1.050\) 反解：

$$C_{\mathrm{crit}}(U)=10^{1.050/0.460}\,U^{1/0.460}\approx 1.9\times10^{2}\,U^{2.174},$$

论文写作 \(2.12\times10^{1.956}\cdot U^{2.174}\)，数值相同。Data-Constrained §3.3按此推算（\(U\) 为 token 数）：\(U=25\)M 时约 \(2.3\times10^{18}\)，50M 约 \(1.0\times10^{19}\)，100M 约 \(4.7\times10^{19}\) FLOPs——独特数据翻倍，临界计算约增 4.5 倍。这只在拟合范围（25–100M）内可靠，作者也承认外推到大数据规模需要更多实验。Data-Constrained App. 11；推算致谢中提到 Stella Biderman 指出过该式的单位不一致，说明早期版本有改动。Data-Constrained §5

3.4 “任意顺序 = 隐式数据增强”

作者的解释：掩码目标让模型在大量随机的条件预测任务上训练，等于对数据做了增强；AR 的固定左到右分解没有这种多样性。证据是 §2 图中的对照：常见的扰动（注意力 dropout、token 掩码）不能阻止 AR 过拟合，而让 AR 在多种 token 顺序上训练能持续降低验证损失、推迟过拟合。Data-Constrained §3.5、Fig. 7–8附录还讨论了反面——AR 为什么更省计算：每次更新都强化同一种顺序，便于“专精”；每个 token 都是监督目标、梯度稠密，而扩散每条序列只在被掩的部分算损失。Data-Constrained App. 10

需要注意：主文说“随机排列”，附录的实现是在左到右位置上加噪声后排序，噪声越大越乱，因此 \(N=16\) 的顺序集合仍偏向近似左到右；评测也只按左到右。Data-Constrained App. 12、Alg. 1–2它支持“顺序多样性有用”，但没有分离出“任意顺序”与“随机正则”各占多少。

3.5 Super Data Learners：更大规模的交叉点

Ni 等在 Megatron-LM 上训练，交叉点实验用 Nemotron-CC 子集；batch 256、长度 2048，WSD 学习率峰值 2e-4、1000 步 warmup、最后 10% 指数衰减到 2e-5；GPT-2 tokenizer、RoPE、SwiGLU、RMSNorm、无 bias、qk-norm；扩散目标与 LLaDA 相同。超参主要为 AR 调过，作者认为这低估了扩散。Super Data §3.1

  • 独特数据：1B 模型、总 96B token，独特 token 从 0.5B 到 96B。数据少时扩散反超，\(U\) 越大交叉点越晚，1.5B 以上在 96B token 内没出现。0.5B 独特 token 的扩散（未收敛）与 1.5B 独特 token 的 AR（已收敛）相当，作者据此称扩散有超过 3 倍的“数据潜力”。Super Data §3.2、Fig. 1
  • 质量、规模、稀疏：1B 独特 token × 96 epoch 下，数据质量越高交叉点越晚；模型越大（1B→8B）交叉点越早，且最小的扩散模型也胜过所有尺寸的 AR；8B 总参 / 1B 激活的 MoE 下扩散同样领先。Super Data §3.3–3.5
  • 噪声注入：给 AR 输入随机掩码 10–90% 或 dropout 10–90%，低噪声时有明显帮助（掩码 10% 最好），但都追不上扩散。Super Data §3.6、Fig. 5–6
  • 代码规模实验：1.7B，独特数据 10B Python token（9B + 1B 退火数据），约 150 epoch、总计约 1.5T token 的计算，长度 4096、batch 1024；MBPP 上交叉点出现得早，HumanEval 只在退火末尾才相交，作者认为与 3-shot / 0-shot 协议有关。Super Data §4、Fig. 7、Fig. 13
  • 扩散也会过拟合：1B 模型在 1B token 上训 480 epoch，HellaSwag 56%、MMLU 33%（AR 为 41%、29%），仍未饱和；但数据更少、模型更大时，最多到 1000 epoch 会出现验证损失回升。Super Data §6、Fig. 10–11
  • 验证损失上升 ≠ 能力下降：AR 在验证集上“过拟合”后，选择题中正确与错误选项的 NLL 差仍在扩大，下游准确率继续升。Super Data §5、Fig. 8–9

他们把扩散的优势拆成三部分：任意顺序建模减少归纳偏置；“超稠密”计算——训练与推理都花更多 FLOPs；以及目标中的期望让每条数据被多次以不同掩码使用（MC 增强）。代价也很直白：初步实验显示扩散需要至少约 100 倍于 AR 的训练 FLOPs 才发挥全部潜力；推理在步数等于长度时，FLOPs 是带 KV cache 的 AR 的 16–4700 倍（长度 16–4096）。Super Data §7.1、Fig. 12

3.6 方法学分歧：两篇论文、16× 与 2026 的复核

Super Data 的官方博客（2025-08-09 发布，针对 Prabhudesai 等的 arXiv v2）列出五点批评：Super Data 官方博客 §3

  1. 损失缺 \(1/t\) 权重：博客认为 v2 的实验用的是不加权的掩码交叉熵，它不是似然的上界；Prabhudesai 等之后在 v3 中加入了按时间的权重，并于 8 月底公开代码。当前 v7 正文的目标含 \(1/r\)。博客 §3.1a 及其更新；Data-Constrained v7 §2.2
  2. 验证损失不可比：AR 是精确 NLL，扩散是上界；且损失更低不代表能力更强。
  3. AR 下游结果取了早期检查点：Tab. 2 按“最佳验证损失”选模型，AR 因早早过拟合被选在早期，而其下游指标此后仍在上升。
  4. 过拟合对比不公平：博客称 Fig. 4–5 中 AR 用了更大的模型和更少的独特数据，二者都会让过拟合提前。
  5. 扩展律形式：Chinchilla 式损失对 \(N\)、\(D\) 单调不增，无法描述过拟合导致的损失回升，外推（Fig. 5–6）可能偏乐观。

反过来看，Super Data 的“3 倍数据潜力”也只来自 1B 模型、96B 总 token 的一组对比，没有拟合扩展律。第三方的 What Makes Diffusion Language Models Super Data Learners?（2510.04071）在消融后认为主要来源是输入 token 的随机掩码，而 MLP dropout 与 weight decay 也能带来类似收益——这更像“随机正则化”而非“任意顺序”本身。2510.04071 摘要它与 Super Data“噪声帮助 AR 但追不上扩散”的结论并不一致。

与 SMDM 的关系：两篇数据受限论文都不否认单 epoch 下扩散更费计算，只是认为“16×”不是固有常数。2026-10-13 的 Revisiting the 16x Compute Gap 从另一个方向复核：沿用 SMDM 的数据与超参、约 1700 个模型，ELBO 读数为 17.8×，同一批模型改用“按置信度解码顺序的精确似然”降到 12.8×，再换成块扩散 / 编码器-解码器，块长 32 时 7.8×、块长 4 时 3.0×。2610.17590 摘要、§4这篇结论太新，尚无复现。

5. 训练目标与似然

两族的训练目标（\(\mathcal{M}\) 为被掩位置集合，\(\tilde x\) 为掩码后序列）：Data-Constrained §2.2

$$\mathcal{L}_{\mathrm{AR}}=-\sum_{j=1}^{L}\log p_{\theta}(x_j\mid x_{<j}),\qquad \mathcal{L}_{\mathrm{Diff}}=-\mathbb{E}_{r\sim U(0,1),\,\tilde x\sim q_r}\Big[\frac{1}{r}\sum_{i\in\mathcal{M}}\log p_{\theta}(x_i\mid\tilde x)\Big].$$

数据受限扩展律（Muennighoff 等的形式，\(R_N^{*}\) 对参数侧同理）：Data-Constrained §2.3

$$D'=U+U R_D^{*}\big(1-e^{-(E-1)/R_D^{*}}\big),\qquad \mathcal{L}(N,D)=\frac{A}{(N')^{\alpha}}+\frac{B}{(D')^{\beta}}+E_0,\qquad \Delta\mathcal{L}(C_{\mathrm{crit}},U)=\mathcal{L}_{\mathrm{Diff}}-\mathcal{L}_{\mathrm{AR}}=0.$$

当 \(E\to\infty\) 时 \(D'\to(1+R_D^{*})U\)：无论重复多少次，有效数据有上限。扩散的 \(R_D^{*}\) 大一个数量级，意味着这个上限高得多。由于两族的 \(E_0\)（不可约熵项）不同，外推得到的损失值不能直接互比，论文在比较时忽略了这一项。Data-Constrained §2.3、Fig. 5 图注

版本与口径 ① 损失版本。Super Data 博客指出 Prabhudesai 等 v2 的实验损失缺少时间权重；v3 起正文加入了加权，v7 为 \(1/r\)。读该论文的数字时应注意版本（本页读 v7）。博客 §3.1a；Data-Constrained v7 ② 似然口径。两篇都用 ELBO 与 AR 的精确 NLL 比；Tab. 4 的下游 NLL（如 WikiText 4.50 vs 4.94）也是这种比较。2610.17590 表明同一扩散模型的 ELBO 与按解码顺序的精确似然会给出不同的计算倍数。Data-Constrained Tab. 4；2610.17590 §4 ③ 顺序扰动。正文称 AR 的 \(N\) 种顺序为“随机排列”，附录实现为“左到右位置 + 递增高斯噪声后排序、首 token 固定”。Data-Constrained §3.5、App. 12

def train(family, N, data, E, n_orders=1):
    model = init_transformer(N, causal=(family == "ar"))
    orders = make_orders(L, n_orders)          # 第 0 个为左到右，其余加噪声 argsort
    for epoch in range(E):                     # 同一份 U 个 token 重复 E 遍
        for x0 in shuffle(data):
            if family == "ar":
                pi = choice(orders)            # n_orders = 1 即标准 AR
                x, pos = permute_keep_first(x0, pi)
                loss = cross_entropy(model(x[:-1], pos[:-1]), x[1:]).sum()
            else:                              # MDM：每个 epoch 重新抽掩码
                r = uniform(0, 1)
                m = rand(L) < r
                logits = model(where(m, MASK, x0))
                loss = cross_entropy(logits[m], x0[m]).sum() / r
            step(loss)
    return val_loss(model)                     # AR：精确 NLL；MDM：ELBO 的 MC 估计

records = []
for U in [25e6, 50e6, 100e6]:
    data = sample_unique_tokens("c4-en", U)
    for N in model_sizes:                      # 7M ... 2.5B
        for E in epoch_grid:                   # 1 ... 800
            for fam in ["ar", "mdm"]:
                records.append((fam, U, N, E, train(fam, N, data, E)))

law = {fam: fit_muennighoff(records, fam)      # A, B, alpha, beta, E0, R_N*, R_D*
       for fam in ["ar", "mdm"]}
C_crit = {U: solve(lambda C: law["mdm"](C, U) - law["ar"](C, U), 0)
          for U in U_grid}                     # 论文拟合：C_crit ∝ U ** 2.174

9. 承上启下

解决了什么

  • 把 SMDM 的“16× 计算”拆成计算效率与样本效率两件事，给出“计算受限用 AR、数据受限用扩散”的经验规则与 \(C_{\mathrm{crit}}(U)\)。
  • 为从零训练路线（iLLaDA 12T、多 epoch SFT）提供了数据侧的理由——iLLaDA 正是引用这两篇来解释多 epoch SFT 的收益。

  • 扩展律只拟合到 100M 独特 token、验证损失口径有争议；Super Data 只有经验交叉点。真正大规模、同口径（精确似然或下游）的对比仍缺。
  • “任意顺序”与“随机正则”的贡献没有分开；块扩散（第 11 页）引入左到右偏置后在单 epoch 下更省计算，在数据受限下是否仍占优未见报告。
  • 多 epoch 优势依赖更多训练 FLOPs；推理侧的计算代价见 第 14 页与 第 16 页。

简答题

Q15为什么在重复数据、多 epoch 训练时掩码扩散能反超 AR？“任意顺序 = 隐式数据增强”这个解释有哪些证据，又有哪些竞争解释？

AR 每个 epoch 面对的是完全相同的输入与目标，几遍之后开始记忆、验证损失回升；掩码扩散每遍重新抽掩码比例与位置，同一序列变成不同的条件预测题，因此重复数据贬值得慢（\(R_D^{*}\) 约 500 vs 约 31）。支持“增强”解释的证据是：让 AR 在多种 token 顺序上训练能持续降损失，\(N=16\) 时接近扩散。

  • 竞争解释一：Ni 等认为还有“超稠密计算”（训练、推理都花更多 FLOPs）与 MC 增强两项；给 AR 加输入掩码或 dropout 有帮助但追不上。
  • 竞争解释二：2510.04071 的消融认为主要是输入随机掩码这一正则，MLP dropout、weight decay 也能给出类似收益——这削弱了“任意顺序本身”的作用。
  • Prabhudesai 等的顺序集合是对左到右加噪声得到的、评测仍按左到右，且在 140M / 278M 小模型上做，无法区分两种解释在大规模下的比重。

依据：Data-Constrained §3.2、§3.5、App. 10、App. 12；Super Data §3.6、§7.1；2510.04071 摘要。

Q16两篇数据受限论文的“交叉点”与 SMDM 的“16×”为什么不能合并成一个数字？比较这类结论时必须对齐哪些口径？

三者测的不是同一个量：16× 是单 epoch、相同验证损失下的计算之比；Prabhudesai 等的 \(C_{\mathrm{crit}}(U)\) 是拟合损失曲线在固定独特数据下的相交点；Ni 等的交叉点是固定总 token、按训练过程画出的下游准确率曲线的相交。数据（SlimPajama / C4 / Nemotron-CC）、模型规模、学习率调度、检查点选择也都不同。

  • 指标：ELBO 与精确 NLL 不同量；验证损失与下游准确率可能背离（AR 损失回升时准确率仍升）。
  • 选模：按“最佳验证损失”选 AR 会选到早期检查点；应同时报告最终检查点或按下游选择。
  • 公平性：两族模型规模、独特数据量应一致；超参通常为 AR 调过；目标是否含 \(1/t\) 要看版本。
  • 结构：2610.17590 显示改用精确似然与块扩散可把单 epoch 倍数从 17.8× 降到 3.0×，所以“扩散”本身也要说明是全序列还是块扩散。

依据：SMDM §3；Data-Constrained §3.3、Tab. 2；Super Data §3.2、§5；Super Data 官方博客 §3；2610.17590 §4。
