1. 动机：代码不是严格从左到右写出来的

写代码时人们先定签名和控制流，再回头填细节；补全、改写、填空都需要右侧上下文。双向、可并行、可回改的 dLLM 看起来天然适合代码。但 2025 年中的开源 dLLM 在代码上明显落后同规模 AR：DiffuCoder 论文中 Dream-7B 与 LLaDA-8B 的 EvalPlus 分别为 53.7 与 36.3，而 Qwen2.5-Coder-7B 为 56.6DiffuCoder Tab. 1。本页三篇论文各回答一个问题：

  • DiffuCoder（Apple + 港大）：从 AR 改造来的 dLLM 解码时到底有多“自回归”？能否不用半自回归块解码就做 RL？
  • Dream-Coder（港大 + 华为诺亚）：完全用公开数据的配方能做到什么程度？解码顺序会不会随任务自适应？
  • Stable-DiffCoder（华中科大 + 字节 Seed）：把扩散训练插进一条成熟的 AR 代码模型流水线，能否胜过它自己的 AR 版本？
一句话理解 掩码扩散 dLLM 会保留不少左到右偏置，代码比数学更少受这种偏置约束，采样温度越高，解码顺序就越乱。DiffuCoder 利用这种多样性做 RL，用互补掩码降低 \(\log\pi\) 估计的方差。Stable-DiffCoder 则说明：在相同的模型骨架和数据来源上，把最后一段持续预训练换成块大小为 4 的扩散目标，多数代码基准会变好。但那个对照并没有控制住所有变量（见 §3.5）。

记号沿用本 track：干净序列 \(x_0\)（长度 \(L\)），腐蚀序列 \(x_t\)，\(t\in[0,1]\) 为掩码率（\(t=1\) 全为 \([\mathrm{M}]\)），去噪网络 \(p_\theta(x_0^i\mid x_t)\)，prompt \(c\)，块大小 \(B\)，步数 \(N\)，每次前向定稿 token 数 TPF。DiffuCoder 用离散步 \(t\in\{1,\dots,T\}\) 并令 \(t+\hat t=T\)；Stable-DiffCoder 在 §3.3 把掩码率写成 \(u(t)=1-t\)，与本页方向相反，下文统一改写。

3. 组件拆解

3.1 AR 性：dLLM 解码到底有多“自回归”

论文在“一步只揭开一个 [M]”的设定下（步数 = 生成长度，低置信度重掩码），记第 \(n\) 步揭开的位置为 \(p_n\)，定义两个指标DiffuCoder §4.1、§A.2：局部 AR 性 Local@\(k\)：新揭开的位置与前 \(k\) 步恰好构成连续递增序列的比例，衡量“接着写下一个”；全局 AR 性 Global@\(k\)：新揭开的位置落在剩余 [M] 中最靠左的 \(k\) 个之内的比例，衡量“总是先填最左边”。纯 AR 解码两者都恒为 1。

$$\mathrm{Local@}k=\frac{1}{N}\sum_{n=1}^{N}\mathbf{1}\Big[\{p_{n-i}\}_{i=1}^{k}=\{p_n-i\}_{i=1}^{k}\Big],\qquad \mathrm{Global@}k=\frac{1}{N}\sum_{n=1}^{N}\mathbf{1}\Big[p_n\in\{m^{(1)}_{n-1},\dots,m^{(k)}_{n-1}\}\Big]$$

其中 \(m^{(1)}_{n-1}<m^{(2)}_{n-1}<\dots\) 是第 \(n\) 步之前仍被掩的位置（论文用 \(t\) 记步号，这里改用 \(n\)，避免与掩码率混淆）。举一个自己构造的例子：6 个位置的揭开顺序为 1, 2, 5, 3, 4, 6。第 3 步跳到位置 5，之后再回填 3、4。Global@1 = 5/6，只有第 3 步不是最左；而 Local@1 在第 2–6 步中只有 2 步（2 接 1、4 接 3）满足，为 2/5。可见“先写后面一行”对局部指标的影响远大于全局指标。

  • dLLM 并不纯 AR，但离 1 更近。不论 LLaDA（从零训练）还是 Dream / DiffuCoder（AR 改造），两种 AR 性都更接近 1 而非 0；AR 改造来的模型 AR 性更高，论文认为是继承了 AR 权重的左到右依赖。DiffuCoder §4.2、Fig. 3
  • 代码比数学“更不 AR”。代码生成的全局 AR 性均值更低、方差更大，即常常先生成后面的 token，把前面的 [M] 留到很晚再填。数学推导本质上是顺序计算。DiffuCoder §4.2、Fig. 3、App. C.2
  • 熵汇（entropy sink）。条件生成的第一步，各位置置信度呈“L 形”：紧挨 prompt 的位置置信度明显更高。论文把它视为 AR 性的来源，并推测与 attention sink 相关（未验证）。DiffuCoder §4.2、Fig. 3(a)
  • 训练阶段会改变 AR 性。Stage 1 训到 65B token 时 AR 性已较低；延长到 700B 后 AR 性上升而下游性能下降，论文怀疑数据质量是原因，因此选用 65B 的检查点。中期训练和 SFT 的第一个 epoch 会学到很强的因果偏置，之后随训练继续而回落；GRPO 之后全局 AR 性进一步下降。DiffuCoder §4.2、Fig. 4、Tab. 4

3.2 温度同时改变“写什么”和“先写哪”

对 AR 模型，温度只影响每个位置选哪个 token。DiffuCoder 观察到，把温度从默认的 0.2 升到 1.2，base 与 instruct 模型的 AR 性都显著下降，生成顺序更随机：模型常先确定右侧（包括决定长度的 pad），关键逻辑反而最后才填。DiffuCoder §4.3、Fig. 1(a)、Fig. 5、App. C.2机制上，下一步揭开哪个位置由温度缩放后的置信度或熵决定，采到的 token 又会改变后续各位置的条件分布，所以温度会通过两条路径影响顺序（本页推论）。

这种多样性正是 RL 需要的：低温下 pass@1 高但 pass@\(k\) 几乎不随 \(k\) 增长，温度 1.0–1.2 时 pass@\(k\) 明显上升DiffuCoder §4.3、Fig. 5–6。RL 之后，最优评测温度从 0.2 移到 0.3–0.4，说明训练让逐 token 分布变尖锐；把扩散步数减半（TPF 从 1 变为 2）时，RL 后模型的掉分也更小，论文据此认为模型变得更不依赖 AR 顺序、更可并行DiffuCoder §5、Fig. 1(c)、App. C.3。这些结论都只来自图，论文正文没有给出 AR 性的具体数值。

3.3 coupled-GRPO：给每个 token 一份部分可见的似然估计

dLLM 没有逐 token 的 \(\log\pi\)。d1 的做法是把补全全部掩掉、做一次前向，相当于只在 \(t=1\) 处采样一次 ELBO 项（详见 17 页）。d1 还随机掩掉 15% 的 prompt 来增加多样性，但 DiffuCoder 在代码上发现这样奖励不能稳定上升，于是以“全掩码补全、不掩 prompt”的 \(\mathcal P_{t=T}\) 作为基线。论文同时指出，这个基线有偏：熵汇使高熵 token 集中在左侧，RL 会更激进地更新前面的 token。DiffuCoder §5、Fig. 7

coupled-GRPO 取 \(\lambda\) 对时间 \((t,\hat t)\)，\(t+\hat t=T\)，配一对互补掩码，并保留全掩码项，再求平均；实践中 \(\lambda=1\)。官方实现中的逐 token 估计如下，§5 给出方差分析：

$$\widehat{\log\pi}_\theta(o^k)=\tfrac12\Big[\log p_\theta(o^k\mid c,x_1)+\tfrac{\mathbf{1}[k\in M]}{t}\log p_\theta(o^k\mid c,x^{M})+\tfrac{\mathbf{1}[k\notin M]}{1-t}\log p_\theta(o^k\mid c,x^{\bar M})\Big]$$

其中 \(x_1\) 为全掩码补全，\(x^{M}\) 掩掉集合 \(M\)，\(x^{\bar M}\) 掩掉其补集。消融在同样采样次数下比较“互补”与“独立随机掩码”（decoupled），并比较只用全掩码的版本。在论文的设置下，只有 coupled 版本的奖励稳定上升，最终分数也最好（见 §8 表 2）。DiffuCoder §5、Fig. 7、Tab. 2

3.4 Dream-Coder：开放配方与自适应的生成顺序

Dream-Coder 7B 同样从 Qwen2.5-Coder-7B 初始化，沿用 Dream 的 shift 参数化（位置 \(i\) 的输出预测位置 \(i+1\) 的 token，以保留 AR 头）和上下文自适应的 token 级噪声重排（见 07 页）。预训练使用 322B token 的公开数据（OpenCoder、Stack-Edu、Dolmino、DCLM），官方 README 给出通用文本 : 代码 : 数学 = 2 : 7 : 1。Dream-Coder §2.2、§3 官方 base/README.md

  • SFT：使用 Ling-Coder-SFT 中的 500 万条样本。为避免大量 [PAD] 浪费计算并带偏损失，训练时把每条回答随机截断到同批另一条样本的长度（random truncation）；推理时对 [PAD] logit 施加逐渐衰减的惩罚，防止高温下过早结束。Dream-Coder §4.1、Fig. 1
  • RL：从 KodCode、DeepCoder、Guru 中筛出 17k 道题，要求至少 5 个单元测试，经过去重，并剔除 Qwen2.5-Coder-7B-Instruct 8 次采样全对的简单题。用 GRPO 训练，不加 KL 与熵项，采用 clip-higher（\(\varepsilon_{\text{low}}=0.2,\varepsilon_{\text{high}}=0.28\)），沿用 DiffuCoder 的互补掩码；零优势样本替换为高优势样本的副本；rollout 用 Fast-dLLM 加速（见 14 页）。Dream-Coder §4.2
  • 三种生成模式：在需要完整程序结构的题上（LiveCodeBench）先写签名、控制流等骨架，再填细节（sketch-first）；在独立函数补全上接近左到右；在 CRUXEval 这类推理题上交错生成。Dream-Coder §5.4、Fig. 3
论文内部：生成顺序只有定性证据 “草图优先”等模式只来自 Fig. 3 中的单个可视化样例，论文没有像 DiffuCoder 那样给出顺序指标的统计。“各模式在对应基准上表现好”只是相关性陈述，并没有做固定顺序的消融。正文的“Left-to-Right Completion”一段引的是图 3(b)，但以 HumanEval/MBPP 举例，而图 3(b) 的样例取自 BigCodeBench。官方演示统一使用 temperature=0.1, diffusion_steps=512, max_new_tokens=512, alg="entropy"，也是一步一 token。Dream-Coder §5.4、Fig. 3 官方 README.md

3.5 Stable-DiffCoder：在 AR 流水线中插入块扩散 CPT

起点是 Seed-Coder-8B 退火前的检查点（Llama-3 结构，8.2B 参数）。在 8192 上下文的打包序列上，用块大小 \(B=4\) 的块扩散目标持续预训练 1.3T token。这些数据由 Seed-Coder 多阶段持续预训练语料子采样得到。之后完全复用 Seed-Coder 的 SFT 数据做 SFT，没有偏好优化或 RL。最终采用不做 logit shift 的参数化（同 LLaDA、SDAR），并让同一打包序列中的不同样本互相可见，以便复用 flex attention 的编译结果。Stable-DiffCoder §1、§4.1 Seed-Coder §2.3

为什么选小块。论文用“token 推理知识”来解释：一个被掩 token 的上下文 \(c\) 所对应的候选集越小（\(K(c)\) 小），梯度方向越一致，越像在学规则。全双向或大块随机掩码常常制造证据被抹掉的上下文，模型只能学到共现关系，甚至学到错误关联。小块扩散与 AR 都有长而干净的左侧证据，训练时的上下文分布也更接近块式推理。2.5B 规模的同算力对照中，“AR → 双向 dLLM”优于“因果 dLLM → 双向 dLLM”，后者又优于“直接双向 dLLM”（只有图）。由此得到的配方是：先用 AR 压缩新知识，再用小块扩散做 CPT，需要更大块时再继续 CPT。Stable-DiffCoder §3.1、Fig. 2–3

两个稳定性技巧。(1) Warmup：从 AR 切到 dLLM 时，损失与梯度范数都会尖峰。论文不对注意力掩码做退火（不便使用 FlashAttention），而是对腐蚀程度做退火：掩码率上限从 \(10^{-3}\) 线性升到 1，并在 warmup 期间去掉 \(w(t)=1/t\)（掩码率 10% 时权重约为 10，相当于放大损失）。(2) 块级截断噪声：块内只有 \(B\) 个 token 时，线性调度下“整块一个都没被掩”的概率为 \(1/(B+1)\)，\(B=4\) 时为 1/5，这些步没有监督信号。于是把块内掩码率截断到 \(\ge 1/B\)，并在没有任何位置被掩时强制掩掉一个。Stable-DiffCoder §3.2–3.3、Fig. 4

5. 训练目标、似然估计与方差

预训练 / SFT 目标。三篇都使用掩码扩散的加权交叉熵（Dream-Coder 把 \(1/t\) 推广为依赖上下文的 \(w(t,x_t,i)\)），它是负对数似然的上界：

$$\mathcal L(\theta)=\mathbb E_{t\sim\mathcal U(0,1),\,x_t\sim q(x_t\mid x_0)}\Big[\frac{1}{t}\sum_{i=1}^{L}\mathbf{1}\big[x_t^i=[\mathrm M]\big]\big(-\log p_\theta(x_0^i\mid c,x_t)\big)\Big]\ \ge\ -\log p_\theta(x_0\mid c)$$

对偶变量为什么降方差。记逐 token 打分 \(g(t,M,k)=M_k\,\tfrac1t\,\ell(o^k\mid c,o_{\bar M})\)，目标 \(v_k=\mathbb E[g]\)。耦合估计 \(\hat v_{\text{AV}}=\tfrac1N\sum_i\tfrac12[g(t_i,M_i,k)+g(1-t_i,\mathbf 1-M_i,k)]\)。两项中恰有一项非零，所以乘积恒为 0，协方差为 \(-v_k^2<0\)：

$$\mathrm{Var}(\hat v_{\text{MC}})-\mathrm{Var}(\hat v_{\text{AV}})=\frac{\sigma_g^2}{2N}-\frac{\sigma_g^2-v_k^2}{2N}=\frac{v_k^2}{2N}>0$$

这里比较的是“\(2N\) 个独立样本”与“\(N\) 对互补样本”，前向次数相同。DiffuCoder §A.4、Eq. 14–28

Stable-DiffCoder 的块级掩码率（改写为本 track 记号，掩码率 = \(t\)）：

$$\Pr[\text{块内无 }[\mathrm M]]=\mathbb E_t\big[(1-t)^B\big]=\frac{1}{B+1},\qquad t_{\text{blk}}=\min\!\big(1,\max(t,\tfrac1B)\big),\qquad w=\frac{1}{t_{\text{blk}}}$$

warmup 阶段 \(t\sim\mathcal U(0,u_{\max}(s))\)，\(u_{\max}\) 从 \(10^{-3}\) 线性升到 1，且不乘 \(w\)。Stable-DiffCoder §3.2–3.3、Eq. 10–11

论文 vs 官方代码 / 论文内部不一致
  • 符号：DiffuCoder Eq. 4 / Eq. 13 把加权交叉熵 \(\mathcal L_t\)（正的损失）直接写成 \(\log\pi\)。官方代码对加权的 log-softmax 取平均，符号是对的：\(\widehat{\log\pi}=\tfrac12[\log p_0+w\log p_{1|2}]\)，\(w\in\{1/t,1/(1-t)\}\subset[1.25,5]\)。因此比值 \(\rho=(p_0/p_{0,\text{old}})^{1/2}\,(p_{\text{part}}/p_{\text{part,old}})^{w/2}\) 是两种上下文下概率比的加权几何平均，指数 \(w/2\) 会放大部分可见那一项，它并不是真实的 token 概率比（本页推论）。coupled_grpo.py selective_log_softmax
  • 证明与实现的差别：§A.4 的无偏性与方差证明针对 \(t\sim\mathcal U(0,1)\) 的互补对；实现中 \(t\sim\mathcal U[0.2,0.8]\)，并额外加上全掩码项求平均。全掩码项与截断区间不在证明范围内。
  • rollout 温度：正文 §B.1 和 Fig. 7 写 1.2，官方配置 generation_temperature: 1.0。复现以哪一个为准不明。
  • Stage 1 token 数与硬件：§3 写 700B，Tab. 4 写 720B。§3 称“所有实验在 8–10 个节点的 H100 上进行”，而 §B.1 的中期训练写的是 8×8 A100、90 小时。
  • Stable-DiffCoder 记号：§3.2 混用 \(u_{\max}\) 与 \(q_{\max}\)，§3.3 混用 \(u_{\text{blk}}\) 与 \(q_{\text{blk}}\)；§3.2 的腐蚀程度 \(t\) 与 §3.3 的 \(u(t)=1-t\) 方向相反。

6. 伪代码

coupled_grpo_step.py（据 apple/ml-diffucoder 改写，λ=1；末尾附 Stable-DiffCoder 的块级掩码）
def coupled_logp(model, c, o, seed):
    rng = Random(seed)                       # 同一种子：π_θ / π_old / π_ref 使用同一组掩码
    t = rng.uniform(0.2, 0.8)                # 掩码率，避开两端的极端权重（§B.1）
    u = rng.rand(len(o))
    m1 = u < t                               # v1：按 t 掩
    m2 = u > t                               # v2：互补掩码
    x0 = c + [MASK] * len(o)                 # v0：d1 式全掩码
    x1 = c + where(m1, MASK, o)
    x2 = c + where(m2, MASK, o)
    lp0, lp1, lp2 = model.batch([x0, x1, x2]).log_softmax(-1).gather(o)
    part = where(m1, lp1 / t, lp2 / (1 - t)) # 每个 token 恰在 v1、v2 之一中被掩
    return (lp0 + part) / 2

def grpo_step(policy, ref, c, G=10, mu=2, eps=0.5, beta=0.01):
    outs = [policy.diffusion_generate(c, max_new=256, steps=256, temperature=1.2)
            for _ in range(G)]               # 一步定 1 个 token
    r = [2.0 * code_reward(o) + 0.5 * format_reward(o) for o in outs]
    A = [ri - mean(r) for ri in r]           # 不除以 std
    seeds = [randint(0, 4096) for _ in range(mu)]
    old = {(i, j): coupled_logp(policy, c, o, s).detach()
           for i, o in enumerate(outs) for j, s in enumerate(seeds)}
    rf = {(i, j): coupled_logp(ref, c, o, s).detach()
          for i, o in enumerate(outs) for j, s in enumerate(seeds)}
    for j in range(mu):                      # 每次内循环换一组掩码
        loss = 0
        for i, o in enumerate(outs):
            lp = coupled_logp(policy, c, o, seeds[j])
            ratio = exp(lp - old[i, j])
            pg = -minimum(ratio * A[i], clip(ratio, 1 - eps, 1 + eps) * A[i])
            kl = exp(rf[i, j] - lp) - (rf[i, j] - lp) - 1
            loss = loss + mean(pg + beta * kl)
        loss.backward(); opt.step(); opt.zero_grad()

def block_mask(B=4, warm_cap=None):          # Stable-DiffCoder §3.2–3.3（掩码率 = t）
    t = uniform(0, warm_cap if warm_cap else 1.0)
    rate = min(1.0, max(t, 1.0 / B))         # 块内掩码率至少 1/B
    m = rand(B) < rate
    if not m.any(): m[randint(0, B)] = True  # 兜底：每块至少一个被监督的位置
    return m, (1.0 if warm_cap else 1.0 / rate)  # warmup 期间不乘 w

之前：通用 dLLM 与依赖半 AR 的 RL

  • LLaDA、Dream 在代码上落后同规模 AR；LLaDA 常常需要半自回归块解码才能拿到好分数。
  • d1 的 diffu-GRPO 用全掩码单步估计 \(\log\pi\)，并依赖小块解码。
  • DiffuLLaMA 给出了 AR→扩散的改造配方（注意力掩码退火 + shift）。

本页之后 / 仍未解决

  • 用 AR 性这个视角看解码顺序；顺序灵活是否真的有利于推理，Flexibility Trap 给出了反面证据。
  • RL 中的似然估计继续演进：VRPO、TraceRL 等见 17 页、TraceRL。
  • Stable-DiffCoder 代表“AR 权重 + 小块扩散 CPT”路线，与 块扩散、AR→块扩散一脉相承。
  • 三篇的质量数字都在 TPF≈1 下取得，并行解码能保住多少质量，要看 14 页、15 页。多模态骨干见 19 页。

简答题

Q35coupled-GRPO 为什么用一对互补掩码来估计 token 似然？与 d1 的全掩码单次估计相比，它改变了什么，代价是什么？

dLLM 没有逐 token 的 \(\log\pi\)，只能用掩码交叉熵的蒙特卡洛估计。只看全掩码状态，相当于只在 \(t=1\) 采一个点，信息少且有偏：熵汇使左侧高熵 token 主导更新。独立随机掩码会让一部分 token 在某次采样中没有信号。互补的一对掩码保证每个 token 恰好在一份部分可见的上下文中被评估一次，两项估计负相关，方差严格下降 \(v_k^2/2N\)。代价是每次更新多 2 次前向，端到端训练时间约为 AR 的 2 倍；而且估计的仍是加权的 ELBO 项，不是真实概率比。

  • 同采样数下，消融（Tab. 2）中 coupled 优于“只用全掩码”和“独立随机掩码”；后两者奖励曲线不稳定（Fig. 7）。
  • rollout 温度很关键：高温让 token 与生成顺序都更多样，pass@\(k\) 上升，RL 才有可以强化的对象。
  • RL 后，步数减半造成的掉分更小，说明模型对 AR 顺序的依赖减弱。

依据：DiffuCoder §4.3、§5、§A.3–A.4、§C.4、Tab. 2、Fig. 1(c)、Fig. 7；官方 coupled_grpo.py。

Q36Stable-DiffCoder 的“同数据、同架构”对照到底控制了哪些变量、没有控制哪些？它能否证明扩散目标本身优于 AR？

受控的是：参数形状（同一 8.2B Llama-3 式骨架）、共享的退火前检查点、预训练语料来源与 SFT 数据。没有受控的是：最后一段预训练的 token 数与上下文长度（1.3T@8K 子采样 vs Seed-Coder 的 400B+600B，上下文 8K→32K）、AR 侧额外的 DPO、base 评测的提示模板；AR 基线数字直接取自 Seed-Coder 报告，8B 规模也没有在同一 1.3T 数据上继续做 AR 训练的对照。因此结论只能表述为：在这条流水线上，把最后一段换成小块扩散 CPT 后，多数代码基准变好；不能说明扩散目标在等算力下普遍优于 AR。

  • 胜负并非一边倒：LiveCodeBench、Aider、NaturalCodeBench、MBPP+（base）更低，CanItEdit 与 MHPP 提升最大。
  • 作者的机制解释（小块扩散 = 左侧证据充分 + 随机掩码带来数据增强）有 2.5B 规模的课程对照支持，但只有图。
  • 选择 \(B=4\) 意味着它更接近 AR，这本身就是论文的论点：扩散的收益依赖于把上下文保持在“推理区”。

依据：Stable-DiffCoder §3.1、§4.1、§4.3–4.4、Tab. 1–9；Seed-Coder §2.3、§3.1、§5.1.1。
