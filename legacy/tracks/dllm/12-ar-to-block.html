1. 动机：块扩散不必从零训练

BD3-LM 把序列切成长度为 \(B\) 的块：块间自回归（前序块的 KV cache 精确、长度可变），块内掩码扩散（\(B\) 个位置并行去噪）。但从零预训练这种模型很贵：同一样本要同时喂加噪流与干净流，每样本计算接近翻倍；掩码扩散目标本身也比 next-token 交叉熵更费算力。SDAR §1、§4 另一条路 Dream 把 Qwen2.5 转成全双向 dLLM，用了 580B tokens。SDAR §5.1；Fast-dLLM v2 摘要

本页三篇都从现成 AR 检查点出发，只改注意力掩码与训练目标，用 1B–100B tokens 完成转换。记号沿用本路线：干净序列 \(x_0\)（长 \(L\)），腐蚀态 \(x_t\)（\(t\in[0,1]\)，\(t=1\) 全掩码），掩码 \([\mathrm{M}]\)，去噪网络 \(p_\theta(x_0^i\mid x_t)\)，块长 \(B\)，步数 / NFE \(N\)，每次前向定稿数 TPF，置信度阈值 \(\tau\)，提示 \(c\)。Fast-dLLM v2 把块长记作 \(D\)、块数记作 \(B\)；WeDLM 的 \(\tau\) 是熵阈值（越小越保守），掩码率记作 \(\gamma\)。

3. 组件拆解

3.1 SDAR：先做 AR 预训练，再短程转换

该从 AR 还是从掩码扩散出发？作者用同一 1T tokens 语料、同一架构与分词器、上下文 4096，各预训练一个 2B 的 AR 和一个 MDLM；再各做 100B tokens 退火，得到 AR、AR→块扩散（即 SDAR，\(B=16\)）、MDLM、MDLM→块扩散四个底座，统一 4B tokens SFT。结论：AR 底座整体最强，SDAR 与之基本持平（MMLU 50.9 vs 48.7，MATH 26.8 vs 29.9），MDLM 转块扩散虽有提升（MATH 12.6→23.3）但仍落后。SDAR §4.1、Tab. 1作者的解释：AR 交叉熵是精确 NLL，每个 token 都贡献梯度；掩码扩散只有被掩的子集贡献，且优化的是上界。

转换配方。改掩码、把 NLL 换成块条件 NELBO，不做 logits shift 和注意力退火；Qwen3 系列先 50B tokens CPT（上下文 4096、序列打包），再 4B tokens SFT。同一管线也训练了一组 AR-Chat 对照。作者另试了 20B / 30B / 40B 的转换预算，模型可用但略差，且后续 SFT 时放大块长的余地更小。SDAR §3.1、§5.1.1、§5.1.2

解码。静态模式每步定稿 \(\lceil B/N\rceil\) 个最高置信位；动态模式定稿所有置信度 \(\ge\tau\) 的位，不足时至少定稿 1 个。注意：主表用的是静态、块长 4、4 步，即 TPF = 1，衡量的是质量而不是并行加速。SDAR §3.2、§5.1.1

规模与块长。1.7B / 4B 在 \(B>4\) 时明显掉点，8B / 30B-A3B 对块长和较低的 \(\tau\) 都更稳健；TPF 随 \(B\) 单调上升，也随模型变大而上升，作者归因于大模型预测熵更低、更多位置越过阈值。TPF 与 \(\tau\) 却不是单调关系：阈值过低会接受高熵的块，错误使后续块的置信度下降，反而要更多步。SDAR §5.2.2–5.2.3、Fig. 3–6

真实引擎上的吞吐。在 LMDeploy、单张 H200、Math-500、\(\tau=0.9\) 下，SDAR-8B-Chat 的峰值吞吐为 6600 / 5510 / 4236 / 2520 / 1509 tok/s（\(B\) = 4 / 8 / 16 / 32 / 64，动态解码）；batch 从 4 扫到 512，小 batch 明显快于 AR，随 batch 增大优势消失，且块越大越早进入算力受限区。SDAR §5.2.4、Fig. 7–8把单次前向时间记为 \(t_f\)、batch 为 \(b\)、每块平均前向数为 \(\bar n\)（论文用 \(\alpha,\beta,\gamma\)），作者给出：

$$\mathrm{TGS}_{\mathrm{AR}}=\frac{b}{t_f},\qquad \mathrm{TGS}_{\mathrm{dyn}}=\frac{b\,B}{(\bar n+1)\,t_f},\qquad \mathrm{TPF}=\frac{B}{\bar n}.$$

分母里的 “+1” 是每块定稿后写 KV 的那次前向。访存受限时两种解码的 \(t_f\) 相近，加速约为 \(B/(\bar n+1)\)；算力受限后 SDAR 每次前向处理 \(B\) 个 token、\(t_f\) 先涨，优势被吃掉（推导自上式）。

科学推理版。SDAR-30B-A3B-Sci：Qwen3-30B-A3B 先做 1T tokens 科学语料 AR 继续预训练，再用其中 50B 转换、0.5B 长思维链 SFT；对照 AR-30B-A3B-Sci 走完全相同的数据，只是不转换。贪心解码下 GPQA-diamond 66.7 vs 61.2、ChemBench 72.3 vs 60.5，但 LCB-v5 40.7 vs 51.5。SDAR §6.1、Tab. 4–5这个开源系列后来是 TraceRL / TraDo 的底座。

SDAR 论文内部不一致 ① Tab. 7 把 GPQA（G）的提升写成 +5.9，Tab. 5 写 +5.5（66.7 − 61.2 = 5.5）；Tab. 6 的 “SDAR (S)” 行 GPQA 填的是贪心值 66.7，而 Tab. 5 的采样值为 66.0。② §4.1 称受控模型为 2B，§5 引言称其为 “1.7B parameter model trained on 1T tokens”。③ SDAR-4B 的 HumanEval 在 Tab. 2 为 72.8、Tab. 3 为 72.0。本页分别标注出处，不混用。SDAR Tab. 2、3、5、6、7；§4.1、§5

3.2 Fast-dLLM v2：互补掩码、token shift 与分层缓存

训练。以 Qwen2.5-1.5B / 7B-Instruct 为底，在 LLaMA-Nemotron 后训练数据上做 SFT：batch 256，1.5B 用学习率 \(2\times10^{-5}\) 训 6000 步，7B 用 \(1\times10^{-5}\) 训 2500 步，64 张 A100 分别约 8 / 12 小时；块长 \(D=32\)。Fast-dLLM v2 §4.1摘要称约 1B tokens、比 Dream 少约 500 倍；附录 A.1 按序列长度 2048 核算：7B 约 1.31B、1.5B 约 3.15B tokens（步数 × 256 × 2048）。三个配方要素：

  • 样本 pad 到块长整数倍：不 pad 时，打包后一条样本的 EOS 可能和下一条的 BOS 落在同一块，块内双向注意力会跨样本泄漏。
  • 互补掩码：\(m\) 与 \(1-m\) 两个视图同批训练，所有 token 都被监督到。1.5B 消融：朴素 token shift 41.3 → 加 pad 42.2 → 再加互补掩码 45.0。Tab. 2
  • token shift：被掩位置 \(i\) 用位置 \(i-1\) 的隐状态出 logits，与 AR 的“下一 token”头对齐（SDAR 恰好相反，不用 shift）。§3.2

推理：两级缓存。块级缓存：已完成块作为只读前缀，KV 精确复用。子块缓存：32-token 块内按子块（默认 8）推进，块内未定稿部分沿用 Fast-dLLM 的 DualCache（近似）；子块内按置信度阈值并行定稿。推理时直接改块长（与训练不一致）会掉点，例如 GSM8K 从子块方案的 62.0 降到 58.5，所以要改粒度只改子块。子块缓存在小 batch 下几乎无收益，在 batch 32 这类算力受限设置下明显提速，对精度无可见影响。§3.3、§4.3、Tab. 3–4、Fig. 6

3.3 WeDLM：在因果注意力下做掩码恢复

问题的重新表述。WeDLM 认为，接上 KV cache 之后速度取决于“有多少预测能尽快变成可缓存的左到右前缀”，而不只是每次前向预测几个 token。它定义前缀可缓存率 \(p_{\mathrm{cache}}=N_{\mathrm{gen}}/N_{\mathrm{fwd}}\)：生成 token 数除以 prefill 之后网络处理过的 token 实例总数，倒数就是平均重算倍数。全双向模型（LLaDA、Dream）每步可能猜很多 token，但很少能立刻进缓存；块扩散（SDAR）靠整块提交提高了 \(p_{\mathrm{cache}}\)，但块内双向使任何 token 都要等整块定稿。WeDLM §3.1、Eq. 4

拓扑重排。掩码恢复真正需要的是“每个 [M] 能看到全部已观测 token”，不需要 [M] 之间互相可见。把已观测 token 按序放到物理前缀、[M] 放到后面，位置 id 仍取逻辑位置，标准因果掩码就满足这一点；[M] 之间则变成按某个顺序的单向依赖 \(q_\theta(x_{\mathcal M}\mid x_{\mathcal O})=\prod_j q_\theta(x_{\pi(j)}\mid x_{\mathcal O},x_{\pi(<j)})\)。作者明确说这不等价于双向 MDLM，是否够用要看实验。§3.2、§4.1、Eq. 5–7

双流掩码训练。推理时未定稿 token 集中在右侧后缀，训练若在全序列上均匀掩码会有分布差。WeDLM 把干净的记忆流 \(x_o\) 与预测流 \(x_t\) 拼接（两者位置 id 相同），预测流按块长 \(B=32\) 分块、块内掩码后重排；块 \(k\) 只看记忆流中逻辑位置在它之前的干净 token 与本块内物理上更早的 token。推理时丢掉记忆流，单序列因果解码。另在同一序列上加 AR 辅助损失以保留原 NTP 能力。§4.2、§6.1消融显示块内双向的变体整体更差，且 0.6B / 1.5B 底座转换后分别掉 3.9 / 0.6 分、7B 涨 3.6 分。§6.5、Fig. 5c

流式并行解码。维护 \(W\) 个槽位的窗口：每步把已填 token 重排到 [M] 之前做一次带缓存的因果前向（相当于一次小 prefill）；最左侧连续已填部分立即提交进 KV cache；在剩余 [M] 中按带距离惩罚的熵 \(\tilde H_i=H_i+\lambda d_i\) 选出低于阈值 \(\tau\) 的位置填入；再在窗口末尾补等量新 [M]，保持每步工作量恒定，避免块解码在块边界“停下等待”。因为始终是标准因果掩码，FlashAttention、PagedAttention、CUDA Graphs 可以不改 kernel 直接用。§5.2、Alg. 1、Eq. 11同为 \(\tau=0.9\)，流式比块式解码快 1.9×（423 vs 221 tok/s）。§6.4、Fig. 4c

WeDLM：论文内部与 README 的出入 ① SFT 规模：§1 写 “10B tokens for SFT”，§6.1 写 “10K internal instruction-response pairs”。② 平均分：§1 称 WeDLM-8B 平均 77.36，Tab. 2 为 77.53。③ 加速：论文正文为 GSM8K 约 3×（Pareto 上 1.97×–3.2×），官方 README 写数学推理 “3-6×”、计数类 “up to 10×”。④ 论文称 WeDLM 模型 “served via vLLM”，README 的 wedlm 推理库注明构建在 nano-vllm 之上。⑤ 论文的速度实验没有写 GPU 型号、batch 与并发；README 的示例输出标注 NVIDIA H20、单条 prompt（218 tokens，689.18 tok/s）。WeDLM §1、§6.1、Tab. 2、Fig. 5a；官方 README

5. 训练目标与似然

把序列分成 \(K=L/B\) 块，第 \(k\) 块记作 \(x^{(k)}\)。三篇的目标都可以写成“以干净前序块为条件，对块内被掩位置做交叉熵”，差别在权重与条件集合：

$$\mathcal L_{\mathrm{SDAR}}=\mathbb E_{k,t,x_t^{(k)}}\Big[-\frac1t\sum_{i\in x^{(k)}}\mathbf 1[x_t^i=[\mathrm M]]\log p_\theta\big(x_0^i\mid x_t^{(k)},x_0^{(<k)}\big)\Big]$$
$$\mathcal L_{\mathrm{v2}}=\mathbb E_{x,m}\Big[-\sum_i \mathbf 1[x_t^i=[\mathrm M]]\log p_\theta\big(x_0^i\mid x_0^{(<k(i))},x_t^{(k(i))}\big)\Big],\quad m\ \text{与}\ 1-m\ \text{各算一次}$$
$$\mathcal L_{\mathrm{WeDLM}}=\mathbb E\Big[\sum_{k=1}^{K}\frac{1}{\gamma_k}\sum_{j\in\mathcal M_k}-\log P_\theta\big(x_0^{j}\mid x_o^{(<k)},\tilde x_t^{(k,<j)}\big)\Big]+\mathcal L_{\mathrm{AR}}$$

按块分解后 \(\log p_\theta(x)=\sum_k\log p_\theta(x^{(k)}\mid x^{(<k)})\)，每一块的项仍只能由 NELBO 给上界，所以块扩散的似然介于 AR（\(B=1\)，精确）与全序列扩散之间。WeDLM 的 \(\tilde x_t^{(k,<j)}\) 指重排后物理上位于 \(j\) 之前的 token；AR 辅助损失的权重论文未给出。SDAR Eq. 4–5；Fast-dLLM v2 §3.2；WeDLM Eq. 10、§6.1

式子与实现的细节 SDAR 的 Eq. 7 把转换目标写成 \(\mathbb E[\log P(b_k^0\mid b_k^t,b_{<k})]\)，省去了 Eq. 5 中的负号与 \(1/t\) 权重；本页以 Eq. 5 为准。Fast-dLLM v2 §3.1 的预备知识里有 \(1/t\)，但 §3.2 的训练目标式没有，本页按 §3.2 书写。两者的官方训练代码未逐行核对。SDAR Eq. 5、7；Fast-dLLM v2 §3.1–3.2

ar_to_block.py（转换训练一步 + WeDLM 流式解码；依据 SDAR §3、Fast-dLLM v2 §3.2、WeDLM Alg. 1）
def convert_step(model, x0, B, variant="sdar"):          # model 由 AR 检查点初始化
    if variant == "v2":
        x0 = pad_to_multiple(x0, B, pad=MASK)              # 块不跨样本；pad 位不计损失
    t = uniform(0, 1, size=num_blocks(x0, B))              # 每块独立掩码率
    m = bernoulli(repeat_per_block(t, B))                  # 1 = 掩码
    views = [m, 1 - m] if variant == "v2" else [m]         # 互补视图
    loss = 0
    for mv in views:
        xt = where(mv, MASK, x0)
        h = model(cat(xt, x0), attn=block_causal_dual_stream(B))  # 长 2L 的一次前向
        logits = h[:, :L]
        if variant == "v2":
            logits = shift_right(logits)                   # 位置 i 用 i-1 的隐状态
        ce = cross_entropy(logits, x0, reduce=False) * mv
        w = 1.0 / repeat_per_block(t, B) if variant == "sdar" else 1.0
        loss += (ce * w).sum() / mv.numel()
    return loss

def wedlm_stream(model, prompt, W, tau, lam):
    kv = model.prefill(prompt); y = []
    win = [Slot(MASK, pos=len(prompt) + i) for i in range(W)]
    while win and not ended(y):
        win = [s for s in win if s.filled] + [s for s in win if not s.filled]  # 拓扑重排
        logits, kv_win = model.forward_causal(win, kv)     # 一次小 prefill，位置 id = 逻辑位置
        n = first_unfilled(win)                            # 最左连续已填段
        y += win[:n]; kv = kv.extend(kv_win[:n]); win = win[n:]   # 立即提交、写 KV
        masks = [i for i, s in enumerate(win) if not s.filled]
        H = entropy(logits[masks]) + lam * distance_to_leftmost(masks)
        for i in select(masks, H < tau, at_least_one=True):
            win[i] = Slot(sample(logits[i]), pos=win[i].pos, filled=True)
        win += [Slot(MASK, pos=next_pos(win, y)) for _ in range(n)]       # 补齐窗口
    return y

9. 承上启下

解决了什么

  • 把 BD3-LM 的块扩散从小规模验证推到 1.5B–30B 的实用模型，转换数据比 Dream 少一到三个数量级。
  • 块级 KV 精确，可直接接 PagedAttention / LMDeploy / vLLM 类服务栈。
  • WeDLM 把评价指标从 TPF 改成“可缓存前缀增长率”，并要求以 vLLM 上的 AR 为基线。

留下的问题 → 下一步

  • 块越大越快，但质量与大 batch 吞吐都会下降；块内仍是独立采样的因子分解误差 → 顺序与并行上限。
  • 转换后模型仍要逐块等待；TiDAR / Nemotron-Labs-Diffusion / DFlash 改用“扩散起草、AR 验证”拿回 AR 的分布保证。
  • LLaDA2.0 在相关工作中把 SDAR 列为由 AR 初始化块扩散的先例并扩到 100B；SDAR 也是 TraceRL 的底座；块内近似缓存见 KV cache 页。

简答题

Q23把现成 AR 权重转成块扩散，为什么 1B–100B tokens 就够，而 Dream 式全双向转换要 580B？SDAR 与 Fast-dLLM v2 在掩码、shift 与损失上的取舍各带来什么代价？

块扩散保留了块间的左到右因果，网络只需在长度 \(B\) 的局部窗口里学会“看左边 + 部分块内 token 填空”，表征与原 AR 的 next-token 结构大体一致；全双向转换则要让每个位置都适应看见整段未来，改动是全局的。SDAR 在 2B 受控实验中还发现，AR 预训练本身比掩码扩散更省算力，AR 底座转出的块扩散也更强，于是“先 AR、后短程转换”成为划算路线。

  • SDAR：不 shift、不退火，50B CPT 即与同管线 AR-Chat 基本持平；代价是小模型对块长敏感，双流训练使吞吐减半。
  • Fast-dLLM v2：保留 token shift 贴近原 LM 头，互补掩码让每个 token 都有监督，7B 约 1.3B tokens 完成；代价是推理块长必须与训练一致，且 7B 的 MATH 比同数据 AR 低 10.4。
  • 两者都只在块级获得精确 KV，块内仍要近似缓存或整块等待。

依据：SDAR §4、§5.1.2、Tab. 1–2、§10.1；Fast-dLLM v2 §3.2、Tab. 1–4；Dream 数据量引自 SDAR §5.1。

Q24WeDLM 为什么坚持因果注意力？拓扑重排如何让 [M] 在下三角掩码下看到全部已观测 token？它“比 vLLM 快约 3×”应在什么测量条件下理解？

在带 KV cache 的部署里，只有依赖已提交上下文的 KV 才能复用；块内双向让每个 token 都要等整块定稿才能入缓存。WeDLM 把已观测 token 移到物理前缀、[M] 放后面，位置 id 保持逻辑位置，于是标准因果掩码下每个 [M] 都能看到全部观测，而 [M] 之间按顺序单向依赖；最左连续已填段立刻可缓存，配合滑动窗口持续补 [M]，避免块边界停顿。

  • 速度数字：GSM8K 上 272–445 tok/s，对 vLLM 上的 Qwen3-8B 为 1.97×（92.3%）到 3.2×（> 79%），随熵阈值折中。
  • 论文未给出 GPU、batch、并发；质量主表又统一每步 1 token，与速度设置不同。README 示例为 H20、单条请求。
  • 收益强依赖熵：计数 1673.3 tok/s，开放问答 197.8 tok/s；高并发下多出的 query 不再“免费”（与 SDAR Fig. 7 同理，推断）。

依据：WeDLM §3.1–3.2、§4.1、§5.2、§6.2–6.6、Fig. 5a；官方 README；SDAR §5.2.4。
