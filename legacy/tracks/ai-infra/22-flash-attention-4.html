1. 动机：硬件的“非对称扩展”

FlashAttention 1–3 的前提是：注意力的瓶颈在 HBM 读写，只要 tile 化并把 softmax 融合进来，就能让矩阵乘跑满张量核。FA3 为 Hopper 做了异步化与 warp 特化，但它跑不了 Blackwell。Blackwell（B200）把每个 SM 的张量核吞吐从 4096 提到 8192 FLOPs/时钟，共享内存读带宽仍是 128 B/时钟，exp 单元（MUFU）仍是 16 次/时钟。FA4 §2.2

一句话理解 在 Blackwell 上，一个 128×128×128 的注意力 tile 里，两次矩阵乘要 1024 个时钟，算 16384 个 exp 也要 1024 个时钟——softmax 已经和矩阵乘一样贵。FA4 的所有设计都围绕一件事：让 exp、重缩放、共享内存搬运躲到矩阵乘背后，或者干脆少做。

2. 瓶颈与前向流水线

张量核 MMAsoftmax（exp）重缩放 张量内存 TMEM数据搬运

3. 组件拆解

3.1 为什么 exp 变成了瓶颈

一个 M × N 的分数 tile 需要 M·N 次 exp，两次矩阵乘（QKᵀ 与 PV）各要 2·M·N·d 次浮点运算。两者之比 \(\frac{4MNd}{MN} = 4d\)：每个 exp 对应 4d 次矩阵乘运算。d = 128 时是 512 FLOPs / exp。Hopper 上张量核每时钟 4096 FLOPs、MUFU 每时钟 16 次 exp，比值 256——矩阵乘慢，exp 有富余；Blackwell 上比值变为 512，与 4d 恰好相等，两者同时成为瓶颈。而且 softmax 还有求最大值、减法、求和、类型转换等非矩阵乘运算，它们也在 CUDA 核上与 exp 抢时间。

$$\frac{\text{MMA 周期}}{\text{exp 周期}} = \frac{4MNd / 8192}{MN / 16} = \frac{d}{128}\qquad(\text{B200})$$

这个比值由论文给出的每 SM 吞吐推出，与 Tab. 1 中 d = 128 时两者都是 1024 周期一致；d 更小时 exp 会成为唯一瓶颈。

3.2 用 CuTe-DSL 写内核

FA4 整个用 CuTe-DSL（嵌在 Python 里的 CUTLASS DSL）实现。论文 Tab. 4：单个内核的编译时间前向 55 s → 2.5 s（22×）、反向 45 s → 1.4 s（32×），摘要称 20–30×。FA2 / FA3 用 C++ 模板时往往要预编译数百个变体，DSL 让按需 JIT 变得可行——这与 FlashInfer 的 JIT 思路一致。

3.3 需要注意的地方

  • 论文的所有结果都是 BF16 / FP16，没有评测 FP8；FA3 无法在 B200 上运行，所以对比对象是 cuDNN 与 Triton。
  • 论文附录 A.1 写测试卡为 “B100 180GB SXM6”、测试时间为 2025-03，与正文的 B200 及 2026-03 的 arXiv 日期不一致 （以正文为准，未能核实）。
  • 新版 cuDNN 已吸收了许多同类技巧，性能与 FA4 接近（Fig. 4 图注）。
  • 2-CTA 模式要求 CTA 成对启动、MMA 在执行期间对方 CTA 必须存活，且整个内核只能用一种 2-CTA 模式。

4. 伪代码

fa4_forward_softmax_wg.py（一个 softmax warpgroup 处理一行；示意）
TAU = 8.0                                      # log2(256)
def softmax_row(S_row_tmem, state, frac_emulated=0.15):
    s = load_from_tmem(S_row_tmem) * scale_log2e   # 一行 128 个分数，进寄存器
    m_new = max(state.m, s.max())
    if m_new - state.m > TAU:                      # 条件重缩放：涨幅够大才更新
        signal_correction_wg(factor=exp2(state.m - m_new))
        state.m = m_new
    x = s - state.m                                # 涨幅 ≤ τ 时沿用旧最大值
    k = int(len(x) * frac_emulated)
    p_sw = poly_exp2(x[:k])                        # FMA 单元：Cody-Waite + 多项式
    p_hw = mufu_exp2(x[k:])                        # MUFU 单元
    p = concat(p_sw, p_hw)
    state.l = state.l * correction + p.sum()
    store_to_tmem(to_bf16(p))                      # P 复用 S 的 TMEM 空间，MMA 直接读
    return state                                   # 最后 O / l 自动抵消多余的缩放

5. 关键结果

  • B200、BF16 前向：最高 1613 TFLOPS，约 71% 理论峰值；比 cuDNN 9.13 快 1.1–1.3×（头维 128），比 Triton 快 2.1–2.7×。FA4 摘要、§5.1、Fig. 4
  • 反向：论文只给出“持续加速”的图，没有文字数字；确定性反向最高可达非确定性 1-CTA 版的 75%。FA4 §5.2
  • 测试设置：总 token 固定 32K，序列 1K–32K，头维 64、128、(192, 128)。

6. 简答题

Q32在 Blackwell 上，注意力内核的瓶颈为什么从矩阵乘转移到了 exp 与共享内存？FlashAttention-4 分别如何应对？

Blackwell 把每 SM 的张量核吞吐翻倍（4096 → 8192 FLOPs/时钟），而 exp 单元（16 次/时钟）与共享内存带宽（128 B/时钟）不变。注意力里每个 exp 对应 4d 次矩阵乘运算，d = 128 时一个 tile 的 MMA 与 exp 都要 1024 周期，共享内存也要 768 周期——三者几乎同时到顶，“只要喂饱张量核”不再成立。

  • exp：一部分元素（每行 10–25%）改用 FMA 单元上的多项式软件计算，两类单元并行；条件重缩放（涨幅 > τ = 8 才做）减少非矩阵乘运算。
  • 重缩放与关键路径：交给独立的 correction warpgroup 异步完成；两个 Q tile 乒乓，让一个 tile 的 softmax 与另一个 tile 的 MMA 重叠。
  • 共享内存：P 经张量内存交给 MMA（不绕共享内存）；反向用 2-CTA MMA，每个 CTA 只存一半操作数，共享内存周期 3328 → 2688，dQ 原子加减半。
  • 结果：B200 BF16 前向最高 1613 TFLOPS（71%）。
