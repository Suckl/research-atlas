1. 动机：解码时 GPU 在等内存，不在算

前文算过：batch 为 1 的 decode，每读 2 字节权重只做 2 FLOP，算术强度 ≈ 1，而 H100 的脊点约 300。换句话说，目标模型一步前向处理 1 个 token 和处理 8 个 token耗时几乎一样——都是把权重搬一遍。投机解码的想法：既然验证 γ 个 token 的代价 ≈ 生成 1 个，那就让一个便宜的草稿模型先猜 γ 个，大模型一次验证。

难点不在“猜”，而在保证输出分布和大模型自己采样完全一致（而不是“差不多”）。两篇论文（Google 的 Leviathan et al. 与 DeepMind 的 Chen et al.，几乎同时）给出的答案是同一套“修正拒绝采样”。

一句话理解 小模型提议、大模型批改。批改规则设计成：按 min(1, p/q) 接受、被拒绝时从“p 比 q 多出来的那部分”补采——这样无论草稿多差，最终每个 token 都严格服从 p；草稿越好，一步接受的 token 越多。

3. 收益公式

设逐 token 接受率 \(\alpha = \mathbb E_{x\sim q}[\min(1, p(x)/q(x))] = \sum_x \min(p(x), q(x))\)（Leviathan 等证明它等于 \(1 - D_{LK}(p,q)\)，一个与总变差距离相关的散度）。假设各位置接受独立同分布，一步期望产出：

$$\mathbb E[\#\text{tokens}] = \frac{1-\alpha^{\gamma+1}}{1-\alpha}\ \xrightarrow{\gamma\to\infty}\ \frac{1}{1-\alpha}$$

设草稿一步耗时 / 目标一步耗时 = c，则一步投机的耗时 ≈ (γc + 1) 个目标步，理论加速比：

$$\text{speedup} \approx \frac{1-\alpha^{\gamma+1}}{(1-\alpha)(\gamma c + 1)}$$

论文实测（T5-XXL 11B，TPU-v4，batch 1）：

WMT En→De 翻译1T5-small0.6272.6×
CNN/DM 摘要0T5-small0.6553.1×
CNN/DM 摘要1T5-small0.5352.3×

α 随草稿变大而升（翻译 temp 0：small 0.75 / base 0.80 / large 0.82），随温度升高而降。Chen et al.（Chinchilla 70B + 4B 草稿，K = 4，batch 1，16 TPU v4）：XSum 1.92×（nucleus）/ 2.01×（greedy），HumanEval 2.46×。

4. 为什么“接受 + 残差补采”恰好等于 p

固定某个位置，草稿 x ~ q。最终输出 y 的分布由两部分组成：

$$P(y) = \underbrace{q(y)\min\!\Big(1, \frac{p(y)}{q(y)}\Big)}_{\text{接受 } x = y} + \underbrace{\Big(1 - \sum_x q(x)\min\!\big(1, \tfrac{p(x)}{q(x)}\big)\Big)}_{\text{被拒的概率 } 1-\alpha}\cdot \underbrace{\frac{\max(0, p(y)-q(y))}{\sum_{x}\max(0, p(x)-q(x))}}_{\text{残差分布}}$$

第一项 \(= \min(q(y), p(y))\)。被拒概率 \(1-\alpha = 1 - \sum_x\min(p,q) = \sum_x \max(0, p(x)-q(x))\)（因为 \(\sum p = \sum q = 1\)），正好与残差分布的分母相消，第二项 \(= \max(0, p(y)-q(y))\)。于是

$$P(y) = \min(p(y), q(y)) + \max(0, p(y)-q(y)) = p(y)\quad\checkmark$$

这解释了为什么必须是残差分布：接受步骤只覆盖了 min(p, q) 这部分质量，p 比 q 多出的那部分（q 低估的 token）只能靠补采补回来；若补采直接用 p，q 高估的 token 会被重复计入，分布就不再是 p。注意上式对任意 q 成立——草稿模型再差也不影响正确性，只影响 α。

5. 伪代码

speculative_step.py
def speculative_step(prefix, M_p, M_q, gamma):
    # 1) 草稿：自回归 γ 步，保留每步分布
    drafts, qs = [], []
    for i in range(gamma):
        q_i = M_q.next_dist(prefix + drafts)          # 便宜
        x_i = sample(q_i); drafts.append(x_i); qs.append(q_i)

    # 2) 目标模型一次前向：γ+1 个位置的分布
    ps = M_p.next_dists(prefix + drafts)              # 长度 γ+1，耗时 ≈ 单步

    # 3) 逐个验证
    accepted = []
    for i in range(gamma):
        x = drafts[i]
        if random() < min(1.0, ps[i][x] / qs[i][x]):
            accepted.append(x)
        else:
            residual = clip(ps[i] - qs[i], min=0)
            accepted.append(sample(residual / residual.sum()))   # 残差补采
            return accepted                              # 后面的草稿作废
    accepted.append(sample(ps[gamma]))                   # 全接受：免费多拿一个
    return accepted

7. 简答题

Q8投机解码的草稿被拒绝后，KV cache 需要怎样“回退”？分页 KV 下为什么不需要搬数据？

把“有效长度”指针退回到最后一个被接受的位置即可，不需要搬数据：验证前向已经把 γ 个草稿位置的 KV 写进了 cache，被拒绝位置的槽位在下一步被新 token 的 KV 覆盖。

  • 目标模型：验证时序列长度临时为 t+γ；接受 n−1 个草稿 + 补采 1 个后，长度设为 t+n。位置 t+n 的 token 来自残差采样，它的 KV 尚未计算，会在下一步前向（作为“新输入 token”）时写入；位置 > t+n 的旧 KV 作废但无需清除。
  • 草稿模型：同样退回到 t+n−1 并用目标模型确认的第 n 个 token 前向一步，使两边 cache 同步。
  • 分页 KV（vLLM / SGLang）：块表不变；若多分配的块整块空出则归还；块按 token 槽位寻址，“覆盖”即回滚。见 vLLM 页 Q8。
  • 树状草稿（Medusa / EAGLE 的多分支）：多条候选共享前缀但占不同槽位，接受某条路径后需要把该路径的 KV 压缩到连续位置（或用块稀疏掩码避免搬动，FlashInfer 的做法）。

依据：算法本身（Leviathan Algorithm 1）；vLLM / SGLang 的实现思路。

Q9投机解码的加速来自哪里？为什么说它是用算力换延迟？

来源是 decode 阶段的算力闲置：小 batch 解码是带宽受限的，目标模型一次前向验证 γ+1 个 token 的耗时与生成 1 个几乎相同，于是把“多次串行的目标模型前向”换成“一次并行验证 + 几次便宜的草稿前向”。

  • 目标模型的前向次数从“每 token 一次”降到“每 (1−α^(γ+1))/(1−α) 个 token 一次”；α = 0.75、γ = 7 时每步期望约 3.6 个 token。
  • 代价是总算术量上升（草稿 + 被拒绝的验证都是浪费的 FLOPs），所以它是用算力换延迟，不是减少计算。
  • 输出分布严格不变（修正拒绝采样），所以收益不以质量换取。

依据：Leviathan et al. §1、§3.2（期望 token 数）、§3.4（c 与加速比）。

Q10论文报告的加速比是在什么条件下测得的？在高并发服务中还成立吗？

论文的加速比是 batch size = 1 的单请求延迟（wall-time）加速，在带宽受限、有闲置算力的设置下测得：Leviathan 用单 TPU-v4 跑 T5-XXL 11B，Chen 用 16 TPU v4 跑 Chinchilla 70B。它不是吞吐指标。

  • 论文明确说方法“对没有额外计算资源的配置没有帮助”；被拒绝的草稿是浪费的算术量。
  • 在高并发服务里 batch 已经把算力用满，投机解码每步多验证的 token 会直接增加每步耗时，吞吐可能不升反降；vLLM 文档也把它定位为“中低 QPS、带宽受限负载”的延迟优化，高 QPS 收益标为“中等”。
  • 加速比依赖 α（任务、温度、草稿质量）与 c（草稿相对开销），同一方法在不同任务上差异很大（翻译 3.4× vs 摘要 temp 1 的 2.3×）。

依据：Leviathan et al. §4（实验设置、Table 2）、§5；Chen et al. §3 与 Table 1；vLLM speculative decoding 文档。

Q11接受率 α 由什么决定？哪些任务受益最多？

任务无关（对任何自回归采样都保持分布），但收益取决于草稿和目标在该任务上的分布有多接近（α）：确定性强、可预测的生成受益最大。

  • 论文实验：翻译（WMT En-De）α 0.75–0.82、摘要（CNN/DM）0.65–0.74；贪心解码比温度 1 更高。Chen et al. 在 HumanEval（代码）上 2.46× 高于 XSum 的 1.92×，他们推测代码有大量常见子序列、被切成较短 token。
  • 一般规律：代码补全、翻译、格式化输出、含大量复述（摘要、RAG 回答引用原文）的任务 α 高；开放式创作、高温度采样 α 低。
  • QA 类任务并不特殊：答案可预测的部分（引用上下文）加速明显，自由发挥的部分收益小。n-gram 类草稿正是利用了“输出复述输入”这一点。

依据：Leviathan et al. Table 1（各任务 α）；Chen et al. §3.2。

Q12草稿被拒绝后为什么必须从残差分布 norm(max(0, p−q)) 补采？证明最终输出严格服从 p。

因为接受步骤只能覆盖 min(p, q) 这部分概率质量；p 比 q 多出的部分（q 低估的 token）只有从残差分布 norm(max(0, p−q)) 补采才能恰好补齐，使总分布等于 p。

  • 流程：草稿 x ~ q → 以 min(1, p(x)/q(x)) 接受。被拒绝时：丢弃 x 及其后所有草稿，从残差分布采一个 token 作为本位置的输出，本步结束。全部接受时从 p_{γ+1} 采一个额外 token。
  • 为什么不能“被拒后从 p 重采”：q 高估的 token 在接受步骤已按 p/q 的比例保留了 p(x) 的质量，再从 p 采会重复计入它们，最终分布 ≠ p。残差分布正好只包含 q 低估的 token。
  • 证明见 §4：P(y) = min(p, q) + max(0, p−q) = p。对任意 q 成立，草稿质量只影响 α。
  • 贪心（温度 0）是特例：p 是 one-hot，接受当且仅当草稿等于 argmax，残差分布也是 one-hot——退化为“逐 token 比对”。

依据：Leviathan et al. §3.1、Appendix A.1 定理 1；Chen et al. §2.2、Theorem 1。
