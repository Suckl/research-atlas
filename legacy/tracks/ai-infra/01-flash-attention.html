1. 动机：注意力慢，不是因为算得多，而是因为搬得多

标准实现把 \(S = QK^\top\)（N×N）写进 HBM，再读出来做 softmax，再写回 P，再读出来乘 V。对 N = 4K、d = 64，S 和 P 各 32M 个数——而 Q、K、V 本身只有 256K 个数。注意力的 FLOPs 是 O(N²d)，但 HBM 访问也是 O(N²)，而 GPU 的 SRAM（A100 每 SM 192 KB，总共 ~20 MB，带宽 ~19 TB/s）比 HBM（40–80 GB，1.5–2 TB/s）快一个数量级：这个算子是内存受限的。

一句话理解 FlashAttention 不改变注意力的数学，只改变“什么时候把什么搬到哪里”：把 Q 的一块留在 SRAM，流式地读 K、V 块，在片上完成 softmax 与加权求和，从不把 N×N 矩阵写回 HBM。

3.1 FA2 的三处改动为什么有效

  1. 减少非矩阵乘 FLOPs：A100 的矩阵乘吞吐 312 TFLOPS，非矩阵乘只有 19.5 TFLOPS——每个标量 exp / 除法的代价相当于 16 次乘加。FA2 把 O 的重缩放推迟、只在块末尾做一次，并把 ℓ 的除法移到最后。
  2. 沿序列维度并行：FA1 只在 batch × heads 上并行，长序列、小 batch 时线程块数不够用（A100 有 108 个 SM）。FA2 把不同的 Q 块分给不同线程块（反向则沿 K/V 块并行），占满 SM。
  3. warp 间按 Q 切分：FA1 在一个线程块内把 K、V 切给 4 个 warp，每个 warp 得到部分的 QKᵀ 后要通过共享内存同步求和；FA2 改为把 Q 切给各 warp，每个 warp 独立完成自己几行的全部计算，不再有 warp 间通信。

3.2 FA3：把 Hopper 的异步用起来

H100 的 Tensor Core（wgmma）和 TMA 都是异步指令；FA2 的同步写法只能用到 35% 的峰值。FA3：

  • 生产者 / 消费者 warp 专业化：一组 warp 专门发 TMA 把 K、V 块搬进共享内存（环形缓冲），其余 warp 组专门算；用寄存器重分配让计算 warp 拿到更多寄存器。
  • 乒乓调度：两个 warp 组交替执行“GEMM”与“softmax”，一个在 Tensor Core 上乘时另一个在多功能单元上算 exp，掩盖 softmax 的延迟。
  • FP8：按块量化（block quantization）配合随机正交变换（incoherent processing）把离群值摊开，降低量化误差。

5. 伪代码

flash_attention_forward.py（FA2 顺序，单头）
def flash_attention_forward(Q, K, V, Br, Bc):          # Q,K,V: [N, d] in HBM
    N, d = Q.shape
    O = zeros(N, d); L = zeros(N)
    for i in range(0, N, Br):                           # 每个线程块一个 Q 块（并行）
        Qi = load(Q[i:i+Br])                            # SRAM 常驻
        Oi = zeros(Br, d); mi = full(Br, -inf); li = zeros(Br)
        for j in range(0, N, Bc):                       # 内循环：流式读 K/V 块
            Kj, Vj = load(K[j:j+Bc]), load(V[j:j+Bc])
            Sij = Qi @ Kj.T / sqrt(d)                   # [Br, Bc]，片上
            m_new = maximum(mi, Sij.max(axis=1))
            P = exp(Sij - m_new[:, None])               # 未归一化
            li = exp(mi - m_new) * li + P.sum(axis=1)
            Oi = exp(mi - m_new)[:, None] * Oi + P @ Vj # 重缩放 + 累加
            mi = m_new
        store(O[i:i+Br], Oi / li[:, None])              # 最后归一化
        store(L[i:i+Br], mi + log(li))                  # 供反向重算 P
    return O, L

6. 关键结果

  • FA1：BERT-large（序列 512）端到端比 MLPerf 1.1 纪录快 15%；GPT-2（1K）快 3×；Long-Range Arena（1K–4K）快 2.4×；Path-X（16K）61.4%、Path-256（64K）63.1%，首次超过随机。
  • FA2：比 FA1 快约 2×；A100 上前向达到理论峰值的 50–73%；GPT 训练端到端 225 TFLOPS/GPU（72% MFU）。
  • FA3：H100 上 FP16 前向 740 TFLOPS（75% 利用率），FP8 接近 1.2 PFLOPS；比 FA2 快 1.5–2.0×。

7. 简答题

Q3FlashAttention 为什么能在不写出 N×N 矩阵的前提下得到精确的 softmax 注意力？FA2 与 FA3 各自改进了什么？

靠在线 softmax：分块载入 K、V，每块只需当前行的最大值 m 与未归一化的和 ℓ 就能算出 e^{s−m}；当新块把最大值抬高时，把已累加的输出乘 e^{m_old−m} 重新对齐再加上新块的贡献，最后统一除以 ℓ——结果与一次算完整行完全相同，而 N×N 的分数矩阵从未离开片上内存。

  • IO 从标准实现的 Θ(N² + Nd) 降到 Θ(N²d²/M)，并被证明在 M ∈ [d, Nd] 内渐近最优；反向只存每行一个 logsumexp，用重算换掉 O(N²) 的存储。
  • FA2：减少非矩阵乘 FLOPs（重缩放推迟到块末尾）、沿序列维跨线程块并行、warp 之间按 Q 切分避免共享内存同步 → A100 上 50–73% 峰值。
  • FA3：Hopper 的 warp 专业化 + TMA 异步搬运、GEMM 与 softmax 乒乓交错、带块量化与非相干处理的 FP8 → H100 FP16 75% 峰值、FP8 接近 1.2 PFLOPS。

依据：FA1 §3 与定理 2–3；FA2 §3；FA3 §3。

Q4FlashInfer 与 FlashAttention 分别解决什么层面的问题？FlashInfer 用什么抽象统一了分页、基数树、树状等 KV 布局？

FlashAttention 解决的是“一个注意力算子怎么算得快”；FlashInfer 解决的是“推理服务里成百上千条长度不一、KV 布局各异的请求，怎么一起算得快”。

  • 数学相同：FlashInfer 的核心内核本身就建立在 FA2 / FA3 的分块 + 在线 softmax 之上（FlashInfer 论文 §3.2）。
  • FlashAttention 的输入假设：稠密或 varlen 的连续张量；主要面向训练（前向 + 反向），对分页 / 基数树 / 树状共享前缀这类 KV 布局没有统一抽象；解码场景下 tile 选择并不最优（FlashInfer §4.2 的测量）。
  • FlashInfer 增加的三层：① 块稀疏格式统一各种 KV 布局并支持不同块大小的组合；② JIT 模板生成注意力变体（自定义 logits 变换 / 掩码，可去掉 softmax）；③ plan/run 调度：按请求长度做负载均衡、固定 grid 以兼容 CUDAGraph、确定性输出。详见 FlashInfer 页。
  • 一句话：FlashAttention 是算子，FlashInfer 是围绕算子的“服务引擎”——它调用 FA 风格的内核，但负责批处理、布局和调度。

依据：FA1 §2–3；FA2 §3；FA3 §3；FlashInfer §3.1–3.4、§4.2、附录 B。
