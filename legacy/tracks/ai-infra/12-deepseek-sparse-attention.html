1. 动机：128K 上下文里，每个 query 真的需要看全部 128K 个 KV 吗

MLA 已经把每 token 的 KV 压到 576 个数，但 decode 每步仍要读完整个 cache（O(L)），prefill 的注意力仍是 O(L²)。经验上注意力分布高度稀疏——多数 query 的质量集中在少数 KV 上。问题是怎么便宜地找到这少数几个，又不破坏已经训好的模型。

一句话理解 再训练一个极轻的“索引器”给每对 (query, key) 打分（少头、ReLU、FP8），只取分最高的 k = 2048 个 KV 做真正的注意力；先用 KL 让索引器模仿稠密注意力的分布，再带着稀疏模式继续训练。V4 把它搬到压缩后的 KV 上，1M 上下文只需 V3.2 的 10% KV、27% FLOPs。

3.1 V4 的 KV 为什么能再降一个数量级

DSA 减少的是读取（每步只读 k 条），但 KV 仍要存完整的 L 条。V4 的 CSA 在存储层面压缩：每 m 个 token 合成一条压缩 KV，于是 cache 长度变为 L/m；再对压缩条目做 DSA。HCA 层压得更狠（m′ ≫ m），不做稀疏选择。配合混合精度存储（RoPE 的 64 维 BF16，其余 FP8），vLLM 测得 V4 在 1M 上下文每序列约 9.6 GiB KV。位置编码：对每个 query / KV 条目的最后 64 维做 RoPE，并对核心注意力输出的最后 64 维施加 −i 位置的旋转，使输出携带相对位置。

4. 伪代码

dsa_decode_step.py（单 token，MQA 模式）
def dsa_step(h_t, latent_cache, idx_key_cache, k=2048):
    # latent_cache: [L, 576]  MLA 潜向量（所有头共享）；idx_key_cache: [L, d_I] 索引键
    q_heads = mla_query(h_t)                              # [H, 576]（上投影已吸收）
    q_idx, w = indexer_query(h_t)                         # [H_I, d_I], [H_I]

    scores = (relu(q_idx @ idx_key_cache.T) * w[:, None]).sum(0)   # [L]  FP8，极轻
    S = topk(scores, min(k, L)).indices                   # [k]  离散选择
    kv = latent_cache[S]                                  # gather：只读 k 条

    out = flash_mla_attention(q_heads, kv)                # 所有头共用这 k 条 KV
    return out                                            # 读取量 k×576 而非 L×576

5. 简答题

Q23线性注意力混合路线（Qwen3.5）与稀疏注意力路线（DeepSeek / GLM）各自的取舍是什么？

DeepSeek 保留精确 softmax 注意力但让它变便宜：MLA 压 KV 存储、DSA 压 KV 读取与计算、V4 CSA 再压 KV 序列长度。优势是长上下文的细粒度检索不打折（这也是 GLM-5 弃用 GDN 改用 DSA 的理由）；代价是 KV 仍随长度增长、需要专用稀疏内核与两阶段训练。对比表见 Gated DeltaNet 页 Q23。

Q26DSA 如何把注意力从 O(L²) 降到 O(Lk) 而不损失质量？它与 NSA、DeepSeek-V4 的关系是什么？

DSA = 闪电索引器 + 细粒度 token 选择：一个极轻的索引头（少头、ReLU 点积、FP8）给当前 query 对所有历史 token 打分，只取 top-2048 个 MLA 潜向量做真正的注意力，核心注意力从 O(L²) 降到 O(Lk)；训练分“稠密预热（KL 对齐索引器）→ 稀疏训练”两步，从 V3.1-Terminus 继续训练而质量持平。

  • 为什么能便宜：选择发生在 MLA 的共享潜向量上——一个 KV 条目同时是所有头的 K 和 V，选一次全头共用；索引器虽是 O(L²) 但每对只有几十维 FP8。
  • 为什么不端到端训索引器：top-k 不可微。索引器只用 KL 向主注意力的分布对齐；预热阶段 2.1B token 就够。
  • 与 NSA 的区别：NSA 是从预训练开始的三分支块级稀疏（压缩 + 选择 + 滑窗）；DSA 是单机制、token 级、可后装到已训模型。
  • V4 的延伸：CSA 先按 m 压缩 KV 再做 DSA，HCA 重压缩稠密分支，两者交错；1M 上下文 KV 仅为 V3.2 的 10%（Pro）/ 7%（Flash），FLOPs 27% / 10%。
  • 被采用：GLM-5 在对比滑窗与 GDN 后选择了 DSA，理由是“构造上无损”，对所有层生效，长序列注意力计算降约 1.5–2×。
  • 工程：需要稀疏 gather 的注意力内核（FlashMLA）与高效 top-k；vLLM / SGLang 已支持 V3.2 / V4。
