1. 离开以后，什么应该保持？

先想两件事：走出房间，探索别处，再回到原来的位置，桌子与门应当还是原来的桌子与门；看着一堵墙被拆掉，转身离开，再回来，那里应当保持为空。前者要求找回旧证据，后者要求把旧证据改掉。把“最像现在视角的旧帧”读回来，在第二个任务中反而可能恢复一堵已经不存在的墙。

再把拆墙事件移到代理离开之后：没有观察、没有动作或事件消息，记忆模块无法知道这次变化。此时需要对隐藏状态演化的预测，或明确承认不确定性。这个信息边界与记忆容量无关；静态回访和离屏动态应分别测试。TECO §1；MemoBench §3；WRBench 评测协议

一句话理解视频记忆是“保存什么 → 用什么地址找 → 读到什么 → 如何更新”的机制；持续出图只是运行方式。
概念实际承诺仍需补的证据
长输出生成循环持续运行，画质、动作衔接不过早崩溃窗口外的具体物体或事件是否被正确找回
长 context一次计算能读取较多历史 token，或较长时段的压缩特征相关证据是否仍有细节、被选中并被生成器采纳
长程具体记忆某个地点、实体或事件离开活跃窗口后，仍能按任务读取正确状态真实离开与回访、明确的状态更新、与普通时间相似性的对照

这一区分是本轨道的比较框架。TECO 已指出滑动窗口可生成长视频却丢失回访一致性；FramePack 将遗忘与误差漂移分开；R2M-Bench 进一步用同 rollout 的非回访对照排除“几乎没动”的捷径。TECO §1；FramePack v3 §1；R2M-Bench §4.2–4.3

2. 一个带记忆的生成循环

视频时间为 \(t\)，扩散 / flow 时间为 \(\tau\)；当前 latent 为 \(x_t\)，近期窗口为 \(H_t\)，动作、文本、相机位姿分别为 \(a_t,c_t,p_t\)。持久记忆是 \(M_t\)，查询是 \(q_t\)，读出是 \(r_t\)。下面是讲解骨架，各论文会省略或替换其中的操作。

$$r_t=\mathrm{Read}(M_t,q_t),\quad q_t=\mathrm{Query}(p_{t+1},a_t,c_t),\qquad x_{t+1}\sim G(H_t,r_t,a_t,c_t)$$
$$M_{t+1}=\mathrm{Evict}\bigl(\mathrm{Write}(M_t,x_{t+1},a_t,p_{t+1})\bigr)$$
观测 / latent / 噪声生成器主干 冻结编码网络可训练记忆模块 记忆本身动作 / 相机 / 文本损失

GT / generated 与 clean / noisy 是两条轴

GT 历史来自数据或外部真实观测，适合测读回能力，但可能绕过写入误差；generated 历史是模型自己生成的结果，错误会随记忆进入下一轮。teacher forcing 与 self rollout 因而测试不同分布。Self Forcing §1、§3；MAG §3.6

clean指当前扩散时间已到干净端点，不代表场景事实正确；一张不存在的墙也可以是 clean generated frame。noisy指记录或条件尚有扩散噪声。历史重加噪、离散化与 clean-pass re-cache 改变条件分布；prompt re-cache 重新编码条件，无法自动找回已删除内容。FramePack v3 §4.2、§5.4；Self Forcing §3；LongLive §3

4. 记忆预算与容量

保真度决定有没有保存细节；容量决定能保留多少历史；查询准确率决定能否命中；更新正确性决定证据是否仍适用于现在。压缩可能保住场景而抹去小字，扩大 bank 可能增加错检索，保留旧帧可能保护身份却阻碍合法变化。这些是独立的设计轴。FramePack §3；TinyHistory v6 §4.5；WRBench 评测协议；本文机制归纳

对象示意形状 / 规模预算含义
近期 latent[B, W, h, w, d]W 是窗口，超出后不能直接访问
KV（每层）K、V：[B, N, nₕ, dₕ]层数、精度与 token 数共同决定显存
帧库 MₜT 条 (latent, key, time, provenance)T 可增长；查询只读 k 条，k 与 T 分开
循环状态固定维度 state / 快权重字节数固定，不等于有效信息无限
地图覆盖坐标 × 每位置特征固定分辨率时，探索面积通常增加存储
活跃 readout[B, Nᵣ, d]只计进入当前生成器的证据；另计 bank / 索引

以上为符号化的预算追踪，未给任何论文设定具体尺寸。按 SSM-WM §4、WorldMem §3、FramePack §3 整理

$$B_{\mathrm{total}}=B_{\mathrm{weights}}+B_{\mathrm{active\ GPU}}+B_{\mathrm{archive}}+B_{\mathrm{index}}+B_{\mathrm{raw\ history}}$$

这是系统记账示意，实际各项可能共享存储，不能重复相加。报告“固定内存”时必须写明是哪一项，还应记录历史编码、检索、搬运、重新缓存与地图更新的延迟。

5. 训练到底教了哪种记忆？

同样的去噪目标，若历史永远来自 GT，主要教模型如何读可靠上下文；自生成训练还让模型面对自身错误。随机历史位置的重建查询可以训练覆盖与保真；闭环回访、事件更新目标才更直接约束读回和新状态。Self Forcing §3；TinyHistory v6 §3.2–3.3；MemoBench §3

$$\mathcal L_{\mathrm{flow}}=\mathbb E\left\|v_\theta(x_{t+1}^{\tau},\tau,H_t,r_t,a_t,c_t)-(\epsilon-x_{t+1})\right\|_2^2,\quad x_{t+1}^{\tau}=(1-\tau)x_{t+1}+\tau\epsilon$$

此式只是条件 flow matching 的比较模板，\(\tau=0\) 为 clean、\(\tau=1\) 为噪声。并非所有工作使用 flow matching，也不是所有 writer 都从最终视频损失得到梯度。冻结编码器、启发式检索、可训练打分与可训练 writer 必须分别标记。TinyHistory v6 式 (1)–(6)，本页统一符号

  • 训练是否提供未来关键帧？若提供，它是规划条件，不能当成在线过去记忆。
  • GT 位姿 / 深度是否替代了需要从生成帧估计的量？这会改变读取难度。
  • 梯度是否真正穿过历史 writer？截断历史反传与端到端更新不同。
  • 是否分别测 oracle bank、估计地址与 self-generated bank？这有助于拆开读写失败。

6. 读写循环：先查询，再写当前帧

memory_loop.py（机制骨架；观测更新与隐藏状态预测分开）
M = empty_memory()
H = recent_window()
for obs, pose in initial_observations:
    M = write(M, obs, pose, source="GT", noise="clean")
    H.push(obs)

for t, (action, text, target_pose) in enumerate(controls):
    M = evict_to_budget(M)               # 存储淘汰，不等于状态删除
    q = query(target_pose, action, text)
    candidates = address(M, q)
    valid = filter_by_time_and_visibility(candidates, q)
    r = read(valid, active_budget)       # 查询当前观测写入前的历史
    x_next = denoise(H, r, action, text) # noisy -> clean
    log_recall(q, valid, x_next)          # 检索命中与生成采纳分别记录

    observed_cells = visible_evidence(x_next, target_pose)
    # 若是仿真生成，这里只是自生成证据，不是物理真值
    M = write(M, observed_cells, target_pose,
              source="generated", noise="clean")
    M = overwrite_observed_absences(M, observed_cells)
    # 未观察区域不能伪装成新观测；可另行做不确定的状态预测
    if transition_model is not None:
        M = predict_hidden_state(M, action, elapsed_time,
                                 mark_as_predicted=True)
    H.push(x_next)
    H.evict_oldest()
    render(x_next)

简答题

Q1为什么能持续生成长视频，还不能证明长程记忆？

持续生成只说明循环和局部质量维持；长程记忆要求具体证据离开活跃窗口后，仍能被正确寻址、读回并用于当前状态。长 context 也可能压掉细节或读错对象。

  • 用离开 / 返回任务，确认实际离屏与间隔。
  • 将回访相似性与同 gap 非回访相似性比较，排除静止捷径。
  • 分别报告存储预算、活跃读出、命中与最终画面。

依据：TECO §1；FramePack §1、§3；MBench §4.1；R2M-Bench §4。

Q2为什么找回完好的旧墙，有时是记忆成功，有时却是状态失败？

静态世界回访时，旧墙是正确证据；若拆除已经被看见，系统应把旧墙标成过时并写入空位置；若变化发生在视野外且无事件消息，旧记忆不可能知道新的事实，需要预测与不确定性处理。

  • 保存旧帧不等于维护最新状态。
  • 时间新鲜度与视角相似性可能冲突。
  • 离屏动态、可见动作后果与静态回访应分协议评测。

依据：本站 memory-toy 信息协议；MemoBench §3.4–3.5；WRBench 返回状态与 support 评测。
