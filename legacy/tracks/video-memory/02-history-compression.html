1. 历史越来越长，下一段却很短

自回归视频生成每次只生成下一小段，却可能需要远处的旧人物、房间布局或道具。把全部历史原样拼进 DiT，token 数随视频增长；只留近期窗口则直接删除早期证据。FramePack 的选择是给重要历史更多 token、给其余历史更粗的表示；TinyHistory 的选择是先学会从短嵌入中查询任意历史位置，再把这套表示用于生成。FramePack v3 §1、§3；TinyHistory v6 §1、§3

一句话理解FramePack 设计“每条历史占多少 token”；TinyHistory 训练“有限 token 应保住什么”。二者都压缩历史证据，尚未把证据维护成可覆写的世界状态。

遗忘与漂移也要分开：更强历史依赖能减少不一致，却可能把自生成错误一路传播。压缩结构解决读取预算；抗漂移采样和历史表示训练解决误差传播。它们不是同一个开关。FramePack §1、§4

论文版本 TinyHistory 的首版题名为 Pretraining Frame Preservation in Autoregressive Video Memory Compression（PFP），首发 2025-12；v6 在 2026-06 改为当前题名。首版突出任意帧重建 / 保真预训练，v6 强调随机查询覆盖与内容一致性两阶段训练。本页机制与生成分数以 v6 为准，不把首版重建指标拼进当前结果表。arXiv 2512.23851 submission history、v1 §3–4、v6 §3–4

3.1 FramePack：importance 是预算排序

设 \(T\) 个历史 latent 帧、\(S\) 个目标帧，每个未压缩帧含 \(L_f\) 个 token。按重要性从高到低排列 \(F_i\)，为其分配 \(L_f/\lambda^i\)，其中 \(\lambda>1\)。重要性最简单来自时间邻近；也可按当前目标估计的特征相似性排序，再用时间项平滑排序跳变。FramePack §3.1–3.2、式 (1)–(5)

$$L_T=S L_f+L_f\sum_{i=0}^{T-1}\lambda^{-i}=S L_f+L_f\frac{1-\lambda^{-T}}{1-\lambda^{-1}},\qquad \lim_{T\to\infty}L_T=L_f\left(S+\frac{\lambda}{\lambda-1}\right)$$

有限上限来自几何级数，不是任意长历史的无损编码。实际 patch 至少得形成一个 token；尾部必须采用额外策略，理论分数 token 不能无限缩小。FramePack §3.1 Tail options

压缩不是统一 resize：三维 patch kernel \((p_f,p_h,p_w)\) 在时间、空间上划分历史，kernel 的乘积决定 token 缩减，同样 token 数可以用不同空间 / 时间取舍实现。不同档位使用独立投影参数；超大档先池化再使用最大投影。RoPE phases 也按对应 kernel 平均池化对齐。FramePack §3.1

论文内部的单位v3 §3.1 在极限式文字中省去了 \(L_f\)，但其式 (2) 明确包含 \(L_f\)。本页按式 (2) 保留该因子，避免把“帧等价长度”误写成 token 数。tail 逐帧追加模式也不能引用固定上限作为无限长保证。FramePack v3 §3.1，式 (2) 与 Tail options

3.2 抗漂移采样：改变依赖图

  • 双向端点：先建立开头和结尾，再填中间；目标同时受两侧锚点约束，减少单向错误链。论文特别讨论重复或运动幅度较小的情况。FramePack §4.1、Fig. 2(b)
  • Inverted I2V：首帧是用户给的可靠图像，尾端是生成的；倒序生成逐步靠近可靠首帧，改变误差传播方向。FramePack §4.1、Fig. 2(c)
  • 多端点：先按 prompts 规划稀疏端点，再填间隔。端点链仍可能漂移；生成顺序与播放顺序不同。FramePack §4.1、Fig. 2(d)
  • 历史离散化：将 latent 映到 K-means codebook 并还原为量化 latent，减少训练真值与推理生成历史的差异；同时牺牲细节。FramePack §4.2、Fig. 2(e)

这些设计改善作者的画质漂移测试；在线交互时不能等待未知未来动作，更不能把预计划终点视作已经记住的过去。因果 streaming 与端点填空应分开比较。

3.3 TinyHistory：先学任意位置的保真查询

首版 PFP 把压缩质量直接变成“能否恢复任意历史帧”的预训练目标，而不只靠下一段生成的间接梯度。v6 保留这一路线，但把任务明确为随机帧查询覆盖，然后在生成训练中重用表示；“fidelity-preserving”意为努力保留感知细节，不是可逆或无损保证。PFP v1 §3.1、§4.2；TinyHistory v6 §3.2–3.3

LR 支路对低分辨率、低帧率输入复用基座 VAE、patchifier 与第一层投影；HR 支路用轻量卷积、SiLU 和 attention 编码原分辨率残差。二者在 DiT 输入投影之后相加，绕过仅靠 VAE latent 通道表达的瓶颈。输出是 DiT 隐层特征，不是把所有像素保存在几条 VAE 通道里。TinyHistory v6 §3.1、Fig. 2

Stage I：随机选历史时间位置 \(\Omega\)，保留所选帧 clean，其他历史以噪声遮蔽；让 DiT 从压缩表示中生成所选帧。只查询固定末尾会鼓励编码器将容量全花在末尾；随机位置使全历史具有被监督机会。TinyHistory v6 §3.2

Stage II：输入完整且无噪声的历史，训练生成下一段；编码器与带新 LoRA 的 DiT 共同适配，编码器并不冻结。学习目标从帧查询转向内容、衣着、对象和人物一致性。TinyHistory v6 §3.3

推理：新生成段追加到历史；作者说明近乎全卷积的编码器允许新段独立编码并拼接，减少全历史重算。这是增量计算优势，不是固定总存储或随机访问地图。TinyHistory v6 §3.4

5. 查询覆盖与下一段生成

为避免与视频时间混淆，原文的 diffusion timestep 在此写作 \(\tau\)。flow 约定为 \(x^\tau=(1-\tau)x^0+\tau\epsilon\)，\(\tau=0\) 是 clean，\(\tau=1\) 是噪声，目标速度是 \(\epsilon-x^0\)。TinyHistory v6 式 (1)–(2)

$$\mathcal L_{\mathrm I}=\mathbb E\left\|\epsilon-H_{[\Omega]}-v_\theta\left(H_{[\Omega]}^\tau,\tau,c,\phi(\mathrm{mask}(H,\Omega))\right)\right\|_2^2$$

所选历史帧作为生成目标，随机时间位置承担覆盖监督；非查询位置的 history noise-as-mask 与目标自身的扩散噪声是两件事。Stage I 的这个查询不代表推理时拥有“输入任意时间戳就无损取帧”的保证。TinyHistory v6 §3.2、式 (3)–(4)

$$\mathcal L_{\mathrm{II}}=\mathbb E\left\|\epsilon-x_{t+1}-v_\theta\left(x_{t+1}^\tau,\tau,c_t,\phi(M_t)\right)\right\|_2^2$$

Stage II 的历史完整、noise-free，编码器仍可训练；后续内容一致性的梯度会适配其特征。FramePack 的 pack 也在生成微调中学习输入投影，但并不具有相同的任意帧查询预训练。TinyHistory v6 §3.3；FramePack §3.1、§5.2

$$Q(F)_p=\arg\min_k\|F_p-\Omega_k\|_2,\qquad F\mapsto\Omega_{Q(F)}$$

这是 FramePack 可选的历史离散化，\(\Omega_k\) 在此表示 codebook 向量，与 TinyHistory 的查询集合 \(\Omega\) 不同。它降低表示敏感度以抑制历史分布差异；细节与时间依赖也可能被削弱。FramePack §4.2、式 (6)

9. 压多少，还要问给谁压

历史压缩带来的改变

  • FramePack 用分层 patch 控制活动 context，并独立调整采样顺序以抑制漂移。
  • TinyHistory 用随机位置预训练与生成适配提高压缩历史的内容保真。

还剩的设计问题

  • WorldPack：从时间重要性转向目标 pose / FoV 相关性，给相关视角更多压缩预算。WorldPack §4.2
  • MoC：压缩之外，还可选择当前 query 应读哪些 chunk。
  • WorldMem / VRAG 与 动态记忆：旧证据的新鲜度和状态更新依然需要专门机制。

TinyHistory 对 FramePack 是直接 baseline 比较与范式发展，不能据此认定沿用了其 checkpoint；WorldPack 的 pose-aware 分配也不等于 FramePack 原方法本来就用 GT pose。回到 基础页评测索引，检查各方法是否真正测了离窗回访与合法状态改变。

简答题

Q3为什么 FramePack 能固定 context，而不能保证无限历史都可精确恢复？

重要性越低的历史用越大的 patch，token 预算形成收敛级数，但这是有损压缩。实际 token 不可无限细分，tail 仍需删除、池化或追加；原始历史与索引存储也须另计。

  • 固定 pack 长度限制的是活跃生成上下文。
  • 空间与时间 kernel 的分配决定丢哪些细节。
  • 抗漂移端点采样改变误差链，没有恢复被压掉的原始信息。

依据：FramePack §3.1–3.2、§4.1。

Q4TinyHistory 为什么先训练随机历史查询，还要让编码器参与生成微调？

随机历史查询使不同时间位置都获得保真监督，减少只记末尾的捷径；生成微调再将这些特征适配到人物、场景和对象一致性。预训练后冻结编码器会阻止这种任务适配。

  • LR 支路对齐基座特征，HR 残差补细节。
  • 完整 embedding 固定压缩率仍随时长增长，与 FramePack 全历史固定 pack 不同。
  • 生成分数的改善并不证明离屏变化或动作后果正确。
