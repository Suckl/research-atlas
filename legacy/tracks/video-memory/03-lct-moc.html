1. 动机：同一个场景，为什么换镜头就忘了

单镜头模型只需维持连续运动；多镜头叙事却会切换景别、视角和人物组合。人物暂时离开镜头后再出现，生成器需要找到较早镜头里的身份和环境证据，最近一帧未必有这些信息。LCT 将单镜头的全注意力扩展到整个 scene，让跨镜头关系直接参与生成；MoC 再把这个昂贵的全量读取改为内容路由。LCT §1、§3.2；MoC §1、§3

一句话理解 LCT 先让各镜头有共同的上下文与可辨认的位置；MoC 在这份上下文中先找相关块，再细读块内 token。它改变的是读取路径，并没有把所有历史压成一个固定大小的摘要。

记视频时间为 \(t\)，扩散时间为 \(\tau\)，当前 latent 为 \(x_t\)，近期窗口为 \(H_t\)，文本为 \(c_t\)，记忆为 \(M_t\)，查询与读出为 \(q_t,r_t\)。本页的 \(t\) 可按镜头或块计数；\(M_t\) 是被保留的文本／视频 token 与相应 K/V。它没有动作 \(a_t\) 或相机位姿 \(p_t\) 的专门索引；镜头描述是文本条件。LCT §3.2；MoC §3.1–3.2

3. 组件拆解

3.1 LCT：扩大的是 scene-level 信息交换

LCT 把同一 scene 的全部文本与视频 token 合入 MMDiT 注意力序列，沿用原模型权重，不增加专门的身份网络。全局描述规定共享内容，逐镜头描述引用一致的人物 ID，使“本镜头该出现谁”与“这个人长什么样”有共同上下文。训练还混合单镜头数据以保留基座能力。LCT §3.2.1–3.2.2、§3.4

这份记忆首先是可见上下文：只要相关镜头进入窗口，其所有 token 都有参与注意力的机会。论文对更长故事提出历史池加人工选择；因此长演示同时受益于用户选对参考，不能解释成自动检索能力。LCT §3.4

3.2 Interleaved 3D RoPE：不让不同镜头共用地址

直接拼接镜头会混淆“哪段文本属于哪个视频”。LCT 为文本赋予三个轴相同的坐标，把对应视频放到文本结束后的空间对角线位置；后续 text–video 对沿对角线继续排列。这样不同镜头有不同绝对坐标，而每对内部的相对布局与单镜头阶段保持兼容。全局 prompt 配 dummy video token，按同一规则放置。LCT §3.2.2、Fig. 3

这是模型内部的位置地址，不是世界坐标地图：相同人物换视角以后，仍要由注意力识别内容关联。它不能直接回答“相机现在回到了哪个三维位置”。由 LCT Fig. 3 的位置规则推断

3.3 异步噪声与 context-causal 微调

训练时每个镜头独立采样 \(\tau\)，同一个接口同时处理低噪声条件和待生成样本。联合采样可以同步各镜头的去噪进度；条件采样让部分镜头保持低噪声。历史来自真实镜头的训练，与历史来自自生成镜头的推理，应分别说明。LCT §3.2.3–3.4

接着，context-causal 版本保留镜头内双向注意力，只允许读取前面的 context。已完成历史不会被后面的新镜头反向改变，历史 K/V 因而可以缓存。缓存资格来自因果结构，不能仅凭“当前镜头的噪声更高”就复用双向模型中所有中间表示。LCT §3.3、Fig. 4；后一句为计算依赖解释

3.4 MoC：路由怎样把注意力变成检索

MoC 从 LCT 权重初始化，把 dense attention 换成 sparse routing。块的边界对齐帧、镜头和模态；先取块内 K 的均值作为 descriptor，query 根据内积选择 top-k 块，再读取这些块的全部细粒度 K/V。检索 key 是 descriptor，返回内容是选中块的 token；两者不应混为一个压缩向量。MoC §3.1–3.2、§4

$$\bar K_j=\frac{1}{|C_j|}\sum_{u\in C_j}K_u,\quad J(q_t)=\operatorname{TopK}_{j\in\mathcal C_{\mathrm{allowed}}}(q_t^\top\bar K_j),\quad \Omega(q_t)=\bigcup_{j\in J(q_t)}C_j\ \cup\ \mathcal A_t$$
$$r_t=\operatorname{softmax}\!\left(\frac{q_tK_{\Omega(q_t)}^\top}{\sqrt d}\right)V_{\Omega(q_t)}$$

\(C_j\) 是候选块，\(\mathcal A_t\) 是强制锚点集合：文本，以及属于当前镜头的局部视觉 token。因果限制作用于动态跨块路由，不取消镜头内强制读取。多层多头分别选择，覆盖的历史并非一个全局固定 top-k 清单。MoC §3.1–3.3

“可学习”不表示新增一个检索打分 MLP。Q/K 投影会训练，mean pooling 没有参数；hard top-k 的离散索引本身不可微。选中块经注意力接受梯度，context drop-in 增加被忽视块获得学习信号的机会，drop-off 训练模型应对漏路由。MoC §3.1

3.5 可能漏掉什么，为什么还要强制锚点

  • 小而重要的细节：块均值可能突出背景而淡化短暂动作、文字或道具。内容仍在 K/V 中，但若路由没选中，本 query 就读不到它。这是机制风险，不能当作论文已证明的全部失败原因。
  • 闭合路由圈：论文无因果约束的消融观察到镜头互相选择、与更早上下文脱离，出现停滞／重复。动态边只指向前序候选可排除此类路由环；这里的 loop closure 指路由关系中的互选环，不是相机回访任务。MoC §3.2、Fig. 2
  • 局部运动被路由挤掉：强制镜头内连接提供稳定的短程通路，文本锚保持条件。过小块或过少路由会提升表观一致性，却让运动不足；高 consistency 不能单独算作记忆胜利。MoC Tab. 3–4

5. 训练目标与路由怎样学会读

LCT 使用 flow matching，令 \(x_t(\tau)=(1-\tau)x_t+\tau\epsilon_t\)，\(\tau=0\) 为 clean、\(\tau=1\) 为噪声。每个镜头独立采样噪声水平，预测速度 \(\epsilon_t-x_t\)，镜头损失先计算再平均。LCT Eq. 1、§3.4

$$\mathcal L=\mathbb E_{\{\tau_t,x_t,\epsilon_t\}}\frac{1}{S}\sum_{t=1}^{S}\left\|v_\theta\big(\{x_j(\tau_j),c_j\}_{j=1}^{S}\big)_t-(\epsilon_t-x_t)\right\|_2^2$$

这是以统一记号重写的镜头平均目标，\(S\) 为镜头数。MoC 沿用 LCT 的训练方案，改动可被访问的 K/V 集合，逐渐缩小块以提高稀疏度；没有单独的“检索命中标签”或事件正确性损失。训练信号首先是生成去噪误差，记忆读取能力由这个目标间接塑造。MoC §3.1、§4、§11

def context_attention(X, meta, mode, k):
    Q, K, V = project_qkv(X)             # 每层、每头独立
    Q, K = interleaved_rope(Q, K, meta)
    if mode == "LCT":
        return full_attention(Q, K, V, meta.context_mask)
    chunks = partition_by_content(meta)  # 不跨 shot / modality 边界
    key_desc = segment_mean(K, chunks)
    outputs = []
    for q, q_meta in queries(Q, meta):
        mandatory = caption_and_intra_shot(q_meta, chunks)
        allowed = earlier_chunks(q_meta, chunks) - mandatory
        chosen = topk(dot(q, key_desc[allowed]), k)
        token_ids = union(chosen, mandatory).all_token_ids()
        outputs.append(attention(q, K[token_ids], V[token_ids]))
    return stack(outputs)

9. 承上启下：压缩、检索与故事规划

可见历史与全量读取

  • 历史压缩缩减输入 token；LCT 扩大跨镜头通信，代价是密集注意力。
  • LCT → MoC 是明确的权重继承，MoC 从 LCT 初始化。

选择读取什么

  • MoC 保留具体块内容，动态选择通信路径；没有独立世界状态更新器。
  • 循环状态把历史压入状态，改变存储对象而非只改变读取路径。
  • Captain Cinema采用 LCT 视频骨干，另由 planner／GoldenMem 组织关键帧和镜头计划。Captain Cinema §3.3、§4

简答题

Q5把全注意力扩到多个镜头，为什么还需要位置设计、异步噪声和因果微调？

全注意力提供通信机会；位置设计区分镜头与对应文本；异步噪声让已有镜头可成为低噪声条件；因果微调才使历史表示不依赖未来，从而能够复用 KV。它们分别解决通信、地址、条件接口和缓存资格，不能互相替代。

  • 保留 text–video 对内部相对位置有助于沿用单镜头对齐。
  • 联合生成仍能读取其他待生成镜头；在线 AR 则只读取已提供的前序 context。
  • 人工从历史池选参考的能力，应与模型自动寻址分开。

依据：LCT §3.2.2–3.4、Fig. 3–4。

Q6MoC 为什么可以称为内部检索？如果相关块没入选，记忆是真的被删除了吗？

query 先用块 descriptor 选来源，再读取选中块内原 K/V，这就是“定位证据—细读证据”的检索结构。未入选只表示本层本头的这个 query 没读到该块；原内容可能仍被保留，也可能被其他头选择。若外层 context 管理已经排除了它，内层路由才无从访问。

  • mean K 可能漏掉小而重要的特征；这是寻址风险，与只存摘要造成的信息损失不同。
  • 文本与镜头内强制链接保留基本条件和局部运动，不保证远程事件全部命中。
  • 因果路由避免动态路由关系中的互选环；它不是显式的事件更新或删除规则。

依据：MoC Eq. 2–3、§3.1–3.3、§6、§14；细节遗漏为机制推断。
