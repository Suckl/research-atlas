1. 动机：时间远，不一定空间远

转身离开房间，过一段时间再回到原处，需要的证据可能是很早的那一帧，而非最近几帧。滑动窗口按时间删历史；WorldMem、VRAG 与空间版 Memory Forcing 把历史保存为可查询证据，让当前视角决定读哪些旧帧。WorldMem §3.3；VRAG §3.3；Memory Forcing 2025 §3.4

一句话理解 帧库保存“过去看到了什么”，pose/time 指明“在哪里、何时看到”，retrieval 决定“这次值得读什么”。空间索引可以让找证据更精确，但最终生成器仍要学会使用证据，而非把检索命中当成生成成功。

视频时间 \(t\) 与去噪时间 \(\tau\) 分开；\(x_t\) 是 latent，\(H_t\) 是近期窗口，\(a_t,c_t,p_t\) 是动作、文本、相机，\(M_t\) 是记忆，\(q_t\) 为目标查询，\(r_t\) 为读出：

$$r_t=\mathrm{Read}(M_t,q_t),\quad x_{t+1}\sim G(H_t,r_t,a_t,c_t),\quad M_{t+1}=\mathrm{Write}(M_t,x_{t+1},a_t,p_{t+1}).$$

本页 \(q_t\) 通常含目标视角；WorldMem 另含 timestamp。空间版 Memory Forcing 用几何找来源帧，读出的仍是帧特征；它与直接渲染三维状态作为图像条件的 几何缓存路线不同。WorldMem §3.3–3.4；Memory Forcing 2025 §3.2、§3.4

3. 组件拆解：帧、位置、时间与空间索引

3.1 WorldMem：相同视角，不同年代

记忆单元 \((x_i^m,p_i,t_i)\) 同时保存视觉证据和状态。Minecraft pose 使用位置、pitch、yaw；FoV overlap 由空间采样估计，confidence 兼顾 overlap 与时间邻近，再贪心去相似候选。它不会把相同 pose 的旧状态自动覆盖成最新状态，时间 embedding 让生成器有机会区分它们。WorldMem §3.3、Alg. 1、§7.2 Alg. 2

$$\alpha_i=w_o\,\mathrm{Overlap}_{\mathrm{FoV}}(p_i,p_{t+1})-w_t|t_i-t_{t+1}|,\qquad Q=W_q(X_q+E_q),\ K=W_k(X_m+E_m),\ V=W_vX_m.$$

\(E\) 结合 dense Plücker pose 与 timestamp MLP；Q/K 含状态，V 保留视觉内容。相对状态将 query 置为原点。世界发生合法变化时，读到旧外观并不一定是正确答案；timestamp 只是变化建模的条件，不是隐藏状态更新的形式化保证。WorldMem Eq. 3–5、§3.4、§4.1

3.2 VRAG：取到帧还要训练怎么用

VRAG把历史帧与当前窗口拼接，直接进入时空 DiT self-attention。Minecraft 全局状态为 \([x,y,z,\mathrm{yaw}]\)，对各状态维度加权后与目标状态比较，取最相近历史帧并排序；状态和动作通过 AdaLN 注入。它不是 WorldMem 的专用 memory cross-attention。VRAG §3.2–3.3、§4.2

专门的 retrieved-context 训练包含：为历史帧设置时间 RoPE offset；历史帧加较低噪声以适应不完美生成证据；历史帧不进入 diffusion loss；历史 action 条件置空、global state 条件保留，避免跨时间拼接造成虚假的动作连续性。VRAG §3.3、Eq. 6–7

默认输入由 10 个 retrieved frames 和 10 个当前 context frames 构成。论文称历史 buffer 固定长度，但不应把 History Buffer baseline 的 124 帧分段采样设置当成 VRAG 的已核验永久容量或淘汰规则。VRAG §3.3–3.4、§4.2内容相似检索属于论文讨论的候选方案；主 VRAG 用 global-state 条件的排名。

3.3 Memory Forcing：Spatio-Temporal Memory（2025 空间版）

同名方法请按编号区分本节为 2510.03198 的 Minecraft 空间记忆与训练框架。2610.11756 的 2026 版在流式 KV 内维护 archive/working banks；本节没有这一缓存协议，也未声明继承 2026 版。

Point-to-Frame Retrieval：维护带 source frame ID 的全局点云，投影到当前相机，统计可见点的来源帧，选择覆盖最多可见区域的历史视图。生成器读取这些帧的 latent / features，并在 memory cross-attention 的 Q/K 加入相对 Plücker 信息。几何负责索引，不是完整世界状态。Memory Forcing 2025 §3.2、§3.4 Eq. 5

Selective write：新区域覆盖足够或历史候选不足时保存关键帧；重建窗口联合新关键帧、相关历史与上一窗口重叠帧。VGGT 输出深度与置信度，通过重叠区域估计尺度因子，再按 pose extrinsics 反投影，voxel sampling 限制局部点密度。Memory Forcing 2025 §3.4、App. A.1

“查询不逐帧扫描全部历史”与“地图随探索空间增长”可以同时成立。论文的 \(O(1)\) 描述依赖可见区域与点密度控制，不能据此宣称点云、关键帧库、重建开销或全系统总内存均为常数。Memory Forcing 2025 §3.4、§4.3

3.4 位姿来自哪里？

WorldMem：Minecraft 主实验使用 simulator GT pose；交互版轻量预测器输入前一图像、前一 pose 与下一动作，输出下一 pose。RealEstate10K 使用带注释相机。WorldMem §4.1、§7.1 Fig. 9

VRAG：主表训练和推理都提供 GT global state；Appendix C.4 另训图像+动作到 pose increment 的预测器，将增量加到当前 pose。预测位姿的消融不能自动变成主表的输入条件。VRAG §4.2、App. C.4

2025 Memory Forcing：用 predicted depth 与 pose-derived camera extrinsics；其 MineDojo 评测提供 pose 条件，未独立给出 action-only 在线 pose predictor 的性能表。不能把 VGGT 深度预测误写为“所有 camera pose 也无需给定”。Memory Forcing 2025 §3.4 Eq. 7、§4.1、App. A.2

5. 训练目标与记忆采纳

WorldMem：Diffusion Forcing 的逐帧独立噪声目标，memory 保持最低噪声；特殊时间 mask 防止 memory 帧彼此串扰，专用 cross-attention 学习跨视角与时间读回。它不是在推理中持续优化模型权重。WorldMem §3.1、§3.4 Eq. 6

VRAG：retrieved 与 target 的噪声不同，loss mask 只监督当前 context/target。以下是讲解形式，\(\epsilon_i\) 为对应帧噪声：

$$\mathcal L_{\mathrm{VRAG}}=\mathbb E\sum_i m_i\left\|\epsilon_i-\epsilon_\theta([X_{\mathrm{hist}}^{\tau'},X^{\tau}],\,[\varnothing,A],\,[P_{\mathrm{hist}},P])_i\right\|^2,\quad m=[0_{\mathrm{hist}},1_{\mathrm{current}}].$$

公式改用 \(\tau\) 避免与视频时间混淆；历史帧噪声水平低于当前帧。无需新增“检索命中标签”，生成目标训练模型使用证据。VRAG Eq. 6–7

2025 Memory Forcing：Hybrid Training 在 VPT 人类探索数据用 temporal-only，在 MineDojo 回访数据用 spatial+temporal；固定上下文的一部分用于近期，另一部分灵活分配。CFT 按窗口链式训练，前窗预测在无梯度少步生成后替换下一窗口对应 GT context；后续 denoising loss 仍有监督目标，区别于 DMD 的无配对分布匹配。Memory Forcing 2025 §3.3、Eq. 3–4、Alg. 1

新场景没有可信空间证据时应允许依赖 temporal context；回访时再依赖 spatial memory。让模型无条件“更多复制旧帧”会妨碍探索和合法状态变化，这是该文训练设计针对的取舍。Memory Forcing 2025 Fig. 1、§3.3

9. 承上启下

按时间决定可见历史

  • 流式 KV保留内部表征，读取受缓存与地址规则约束。
  • WorldMem 与 VRAG 建立帧级证据库，但 FoV/pose 相近不一定代表真实可见内容相同。

空间查询与更新仍需区分

  • 空间版沿用 WorldMem 式 memory cross-attention 并对照 WorldMem，新增 geometry index 与 Hybrid/CFT。空间版 §3.2–3.4、Tab. 1
  • Context as Memory / WorldPack比较挑哪些视图与给多少压缩预算；VMem进一步处理 surfel 可见性。
  • 动态记忆要求恢复更新后的主体与动作状态；旧帧复刻只是其中一个环节。

简答题

Q15为什么历史帧库还要保存 pose 和 timestamp？GT 位姿、预测位姿与自生成历史应如何分别评测？

pose 让当前视角能定位相关证据，timestamp 区分同一地点的不同时刻；仅看外观可能取回错误视角或过时状态。GT pose 与 GT bank 给更强查询和证据条件；预测 pose 会影响查询与生成，自生成历史还会把早期错误写回库，三者应分别报告。

  • WorldMem 主表与 predicted-pose 消融分别引用，不能混算。
  • VRAG 主表提供 global state，另有预测增量的消融。
  • 先固定 bank 测地址误差，再固定地址比较 GT/generated bank，可定位错误来源；这是建议的诊断实验。

依据：WorldMem §3.3–3.4、§4.1、Tab. 8；VRAG §3.3、App. C.4。

Q16空间索引怎样避免扫描全部旧帧？为什么快速查询与更少关键帧仍不能证明常数总内存或正确动态更新？

空间版 Memory Forcing 把可见点映射回 source frame ID，按覆盖计数选择历史帧，并仅为新覆盖或不足历史写关键帧。查询围绕当前可见空间，帧库不必每步线性扫描；但点云与关键帧随新空间增长，降采样只限制局部密度，旧表面及图像也未必代表变化后的状态。

  • 论文报告减少的是 memory frame count，总 bytes 还包括几何与索引。
  • 重建+检索吞吐与完整视频生成吞吐分开。
  • 与 2026 同名 Memory Forcing 区分：后者维护固定 KV bank，满后 FIFO 丢中段事件。

依据：Memory Forcing 2025 §3.4、§4.3、Tab. 2；Memory Forcing 2026 §3.3。
