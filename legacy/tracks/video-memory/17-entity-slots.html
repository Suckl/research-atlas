1. 动机：人物有地址，记忆才知道该找谁

故事先拍女主，切到别处，再让她回来。近期窗口已经没有她，最新画面又可能只有男主：按时间保留最近帧、按整体画面相似度查历史，都可能找不到正确人物。关键帧记忆提供了视觉证据，但“这帧包含谁”和“从这帧提取谁的身份”仍是不同问题。

IAMFlow把自然语言指代对齐为持久 entity ID，再按 ID 从整帧 KV 档案召回；SlotMem进一步把角色相关的 DiT 特征编码成独立槽位，用保守 writer 吸收新观察，并只向同角色位置注入。前者改变历史的组织与选择，后者还训练了记忆表示和读写接口。IAMFlow §3.1、App. A；SlotMem §3

本页的关键区别 用人物 ID 选中一张历史帧，并没有把人物从背景、姿态和其他人物中分离出来。角色槽位试图缩小这种耦合；身份保持得更好，也仍需另测换装、持物、受伤和关系变化等故事状态。

以下用 \(t\) 表示视频 chunk 时间，\(\tau\) 表示去噪时间，\(x_t\) 是视频 latent，\(H_t\) 是近期窗口，\(c_t\) 是文本，\(M_t\) 是持久记忆，\(q_t\) 是查询，\(r_t\) 是读出。\(a_t\)、\(p_t\) 分别保留给动作和相机位姿；本页两种方法不要求它们作为独立输入。角色索引记为 \(e\)，避免与文本 \(c_t\) 混淆。

$$r_t=\mathrm{Read}(M_t,q_t),\qquad x_{t+1}\sim G(H_t,r_t,c_t),\qquad M_{t+1}=\mathrm{Write}(M_t,x_{t+1}).$$

这是比较骨架。IAMFlow 的读出是选定帧的 KV；SlotMem 的读出是随 \(\tau\) 和层变化的角色特征，不是生成前一次性取出的静态参考图。IAMFlow Eq. 4、App. A；SlotMem §3.2–3.5

3.1 IAMFlow：ID 覆盖和帧重要性是两层决策

先解决该找谁：文本中“young man”“the protagonist”“he”可以对齐到同一 ID；明确的 novelty marker 则创建新人物。再解决留哪帧：用人物名字和属性的加权 text keys 与每帧平均 visual keys 做匹配，融合 VLM 外观分数。它是轻量的内部兼容性代理，不能当成精确人物检测器。IAMFlow §3.1、App. A/C

$$s(f)=(1-\lambda)\widehat{s}_{\mathrm{entity}}(f)+\lambda s_{\mathrm{visual}}(f),\qquad \lambda=0.3.$$

实现对同一 chunk 的 entity score 做 min–max 归一化，再融合视觉核验。检索则优先新覆盖的 ID 数目，并用 entity score 打破平局；不是只按上述融合分数取全库最高帧。IAMFlow App. A；\(\lambda\) 见 §4 / App. A

3.2 SlotMem：从角色相关 token 到独立 slots

SlotMem v2的 Character-Semantic Probe 平均指定层、头和角色名称 token 的 cross-attention 响应。多人物场景减去其他人物的平均响应，再选 top-\(p\) 区域并过滤孤立 token；不调用外部检测器，也没有独立分割标签监督。选择的是模型对角色语义敏感的位置，不保证完美实例分割。SlotMem §3.1，Eq. 3–5

Memory Encoder 将局部特征投影到 bottleneck，按 \(\tau\) 调制，用可学习查询池化为 \(R\) 个槽位，再映回 DiT 特征维。当前角色区域从自身槽位读取；背景和其他角色不会被同一记忆残差直接修改。注入 mask 滞后一个去噪 forward，读取对应当前阶段的历史 slots；每个 chunk 首步没有上一 mask 时跳过注入。在线 slots 在去噪中积累，chunk 完成后才更新持久 bank。SlotMem §3.2.1、§3.3、App. A，Algorithm 1

3.3 保守 writer：先确认相容，再残差更新

旧槽位作查询，从同角色新槽位读取对齐上下文 \(u_{e,j}\)；writer 预测残差 \(\Delta_{e,j}\)。更新门由相似度硬阈值和学习到的 sigmoid 系数相乘。以下省略层和 \(\tau\) 下标，\(\gamma_{\mathrm{prec}}\) 对应论文的相似度阈值，避免将它误写成去噪时间。SlotMem §3.2.2，Eq. 12–15

$$g_{e,j}=\mathbf 1[\cos(S_{e,j},u_{e,j})>\gamma_{\mathrm{prec}}],\sigma(\mathrm{MLP}_g([\mathrm{LN}(S_{e,j});\mathrm{LN}(u_{e,j})])),\qquad S'_{e,j}=S_{e,j}+g_{e,j}\Delta_{e,j}.$$

它有助于避免不可靠观察污染身份记忆，但“保守”不等于具有服装、受伤或道具状态的显式更新规则。相似度阈值会不会拒绝合法的大幅变化，是需专门测试的假设；不能由架构直接认定为已证失败。

5. 训练目标：外部组织与可学习读写

IAMFlow 是运行时增强。复用 MemFlow 权重，用冻结 LLM / VLM 组织人物地址和核验生成结果，没有为 ID 检索训练新 loss。APT 平滑文本 cross-attention K/V，异步核验、TinyVAE 和量化属于部署路径；这些组件的总体效果不能全部归因于记忆选择。IAMFlow §3.2、§4、App. B

SlotMem 先学构建与注入，再学更新。前一阶段用真实视频的前序 memory chunk 与目标 chunk 训练 Encoder / 角色 cross-attention，并适配 DiT；角色与背景 slots 的 prototype 对比损失帮助分离。后一阶段加入同人物 update chunk，让 writer 的更新通过目标去噪任务获得监督。SlotMem §3.4，Eq. 20–21

$$\mathcal L_{\mathrm{stage1}}=\mathcal L_{\mathrm{diff}}+\lambda_{\mathrm{slot}}\mathcal L_{\mathrm{slot}},\qquad \lambda_{\mathrm{slot}}=0.02.$$

角色标签来自 caption 中一致的名称；背景特征从角色 mask 外抽样。它训练的是身份特征的区分与后续生成利用，并没有物体所有权或事件终态的结构化监督。SlotMem §3.4、App. B（权重）

论文内部描述需核对 SlotMem v2 §3.4 先称第二阶段冻结 Memory Encoder 与 Character-Wise Cross-Attention，随后同段又称继续微调第一阶段模块和 DiT。§4.1.2 则具体说明冻结预训练骨干、使用 LoRA 适配。本页按明确的两阶段目的讲解；第二阶段参数冻结列表尚未逐项对照官方代码，不把相互冲突的句子合成确定训练配置。

registry, archive, local = {}, [], empty_cache()
for prompt in streaming_prompts:
    ids = llm_match_or_create(prompt, registry)
    refs = greedy_id_cover(archive, ids, max_active_frames)
    active_kv = concat_in_time_order(refs)
    for _ in chunks_for(prompt):
        x = denoise(prompt, sink_kv, local, active_kv)
        verification.submit(x, check_attributes=is_first_chunk())
        evicted = local.append_clean_context(x)
        source = evicted if evicted is not None else local.clean_context
        scores = verification.collect_needed(source)
        registry.correct_attributes(scores)
        frame = choose_representative(source, ids, scores)
        archive.append(frame.with_ids_and_kv(ids))

# SlotMem: collect noisy-step slots; commit only after finishing the chunk.
bank, image_condition = {}, initial_image
for prompt in narrative_chunks:
    roles = consistent_character_names(prompt)
    retrieved = retrieve_role_slots(bank, roles)
    previous_masks, online_buffer = {}, []
    z = initial_noise()
    for tau in denoising_schedule:
        # Normal forward uses retrieved slots + lagged masks for injection.
        z, masks, new_slots = memory_aware_forward(
            z, tau, prompt, image_condition, retrieved, previous_masks)
        previous_masks = masks
        online_buffer.append(new_slots)  # no permanent bank update here

    insert_or_writer_update(bank, online_buffer)
    image_condition = ending_frame(chunk)

8.3 EntityBench / EntityMem：预写参考的另一种信息条件

EntityBench: Towards Entity-Consistent Long-Range Multi-Shot Video Generation是实体回归评测论文，EntityMem 是该论文内提出的 baseline 系统。EntityMem 在视频生成前为人物 / 物体 / 地点生成、选择并核验独立视觉参考；后续按实体 schedule 组合关键帧。它提供预先确立的身份，不等同于 IAMFlow / SlotMem 从自生成过去中在线记住角色。EntityBench §3–4、App. C

跨镜头指标包含 canonical crop 对 DINOv2 centroid 的相似度，以及按实体类型设计的 LLM 判断；地点用全帧和相机视角不变的 rubric。fidelity gate 过滤错误呈现后，需把 coverage 与条件相似度一起统计，不能只展示通过 gate 的样本。高 embedding 相似仍可能只是重复同一种错误外观。EntityBench §3.2、App. B.4

把“像同一个人”和“经历了同一故事”拆开本页主表支持身份再认与视觉一致性。若要证明故事状态正确，还需规定变化、确认发生、让人物离开，再检验返回后的终态；姓名一致、FaceID / 特征相似或总体 VLM 分数都不能独自完成这条证据链。

简答题

Q33既然 IAMFlow 已经按人物 ID 召回，为什么 SlotMem 还要改成角色槽位？

ID 解决“选哪张帧”，整帧 KV 仍混有背景、姿态和其他人物。SlotMem 再定位角色 token、编码独立 slots，并只向当前同角色区域注入，把寻址粒度和读写粒度都下沉到角色。

  • IAMFlow 用外部 LLM / VLM 管理指代和代表帧，生成器权重保持原样。
  • SlotMem 训练 Encoder / Writer / 角色 cross-attention，并用一致 caption 名称定位角色。
  • 直接对照支持特征一致性提升，不能推出所有背景耦合已消失或任意角色都可正确分离。

依据：IAMFlow §3.1 / App. A；SlotMem §3、Tab. 1 / App. E。

Q34如果人物换装后离开再回来，身份一致性分高能否证明记忆更新正确？

不能。人物仍像同一个人，并不能确定换装已经发生且新衣服被保存。需要同时检查指令执行、离开 / 返回触发、返回后的新状态，以及可评样本覆盖。

  • CLC 比较人物出现组的视觉特征；无 valid recurrence group 的样本不进该均值。
  • Writer 保守更新旨在防污染；是否拒绝合法变化必须用受控变化任务检验。
  • EntityMem 预写身份参考提供额外信息，不能直接当作在线自写记忆能力的证据。

依据：IAMFlow App. E（CLC）；SlotMem §3.2.2、Tab. 1；EntityBench §4 / App. B.4。
