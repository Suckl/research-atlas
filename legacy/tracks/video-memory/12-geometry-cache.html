1. 动机：回来时，已见表面应该从哪里取回？

相机离开房间再回来，近期窗口 \(H_t\) 可能已没有这间房的图像。VMem 用几何索引找回历史视图；本页把被读取的对象进一步改成世界坐标中的表面：先保存几何，再按目标相机渲染，生成器接到的是已经对齐目标视角的条件。

GEN3C 将输入或已生成帧的深度反投影成 3D cache，减少生成器自行推断相机与布局的负担；Video World Models with Long-term Spatial Memory（下称 Spatial Memory）额外区分静态地图、近期工作记忆和稀疏 episodic 帧，让几何、局部运动和远期细节分别进入模型。二者是机制对照，不能仅按日期画成直接继承。GEN3C §4；Spatial Memory §3

一句话理解 地图负责告诉模型“这个视角已经知道什么”；生成器负责补洞、纠正不完美条件和合成当前画面。缓存能固定已见表面的地址，却不会自动给出未知区域的真值或离屏主体的下一状态。

2. 全局架构：读路径与写路径分开

记视频时间为 \(t\)、扩散时间为 \(\tau\)，当前 latent 为 \(x_t\)，目标相机（含内参）为 \(p_{t+1}\)，长期记忆为 \(M_t\)，近期窗口为 \(H_t\)，文本为 \(c_t\)，动作可记为 \(a_t\)。这里主要控制是相机，不能把它等同于一般物体交互动作。查询 \(q_t\) 由目标相机决定，读出 \(r_t\) 是渲染条件。GEN3C §4.2；Spatial Memory §3.3

$$r_t=\mathrm{Read}(M_t,q_t),\quad x_{t+1}\sim G(H_t,r_t,a_t,c_t),\quad M_{t+1}=\mathrm{Write}(M_t,x_{t+1},a_t,p_{t+1})$$

这是比较骨架。GEN3C 的动态 NVS 先有输入动态视频，再沿另一轨迹重拍；Spatial Memory 才显式利用近期帧和文本继续时间进程。不要把“给定运动的换视角”与“自主预测运动”混在一起。GEN3C §4.1、§6 Limitations；Spatial Memory §3.3

观测 / latent / 噪声生成器主干（可训练） 冻结 VAE / 几何估计可训练记忆模块 记忆本身相机 / 动作 / 文本损失

3. 组件拆解

3.1 GEN3C：保留分视图证据，不强行融合成一张完美地图

对深度 \(d_t(u,v)\)、内参 \(K_t\) 和 world-to-camera 外参 \(E_t\)，反投影的空间地址为：

$$P_t(u,v)=E_t^{-1}\!\begin{bmatrix}d_t(u,v)K_t^{-1}[u,v,1]^\top\\1\end{bmatrix}$$

点同时携带 RGB。GEN3C 将缓存组织成“时间 × 输入视图”的点云数组：静态输入可以沿时间复制；动态输入则保留每个时间的独立点云。这是时空证据，不是把所有时间的运动物体叠成静态墙。相机可随输入给定；缺少时论文采用 DROID-SLAM 估计。GEN3C §4.1

多视图深度可能错位，光照也可能不同。GEN3C 分别渲染各点云、用冻结 VAE 编码，在输入层之后以跨视图 max-pooling 汇集特征；它让视频模型处理证据冲突，避免在三维空间先硬融合出重影。这样输入视图数可变，但并不保证错误几何总能被纠正。GEN3C §4.3、Tab. 6

3.2 读出的空洞：已知区域与生成区域的边界

每个缓存视图投影得到 RGB 和覆盖 mask。GEN3C 将 mask 保守降采样到 latent 网格，直接乘到渲染 latent 上，再与当前噪声 latent 按 channel 拼接；论文选用这一方式而非额外学习 mask 通道。生成器仍必须处理反投影拉伸、薄结构、遮挡显露和此前完全没有观察过的区域。GEN3C §4.2–4.3、App. C.1

“这个像素没有被地图覆盖”只说明没有证据，并不决定应补什么。背后的房间、物体背面和新街道由生成先验提出；它们一旦被写回，就成为后续的自生成证据。一个反复出现的幻觉可以很一致，因此回访一致性与真实重建准确性需要分别评测。

3.3 Spatial Memory：静态空间、近期运动、远期细节

空间记忆以 TSDF 融合抑制时间上不一致的动态区域，再提取静态点图。TSDF 对观测做置信加权平均，可写为 \(D'(v)=[W(v)D(v)+w_i d_i(v)]/[W(v)+w_i]\)。动态点被过滤后，地图主要保存背景，无法独自决定角色当前动作。Spatial Memory §3.2

working memory 将最近 5 帧的 source tokens 与 target tokens 沿时间拼接，为局部运动提供连续性；episodic memory 在新露出未知区域超过阈值时加入历史关键帧，经历史 cross-attention 用目标 tokens 作 Q、参考 tokens 作 K/V，补地图过于稀疏时的纹理与身份细节。阈值的具体值及统一关键帧容量尚未核实，所读全文未给出。Spatial Memory §3.2–3.3、§4 Implementation

静态渲染经冻结 3DVAE 编码，用 CogVideoX 条件 DiT 注入主干；条件分支复制前 18 个 blocks并以零初始化线性层连接。训练数据由 Mega-SaM 提供几何；在线生成改用带持续状态的 CUT3R，让相邻写入共享坐标。切换估计器是为了在线对齐和资源开销，不应写成推理也调用完整视频的未来帧重建。Spatial Memory §3.3、App. A

3.4 几何错误在哪进入，怎样被放大？

  • 深度：尺度错使点的世界位置错，边缘深度错会制造拉伸或前景遮挡；读条件的误差随后进入生成。
  • 相机：pose 错使同一表面投影到不同地址；渲染图不再与真正目标视角对齐。
  • 融合：空间错位可造成重影；过强静态筛选也会删除本来应保留的表面。Spatial Memory 的急转 / 大位移失败案例正出现这一链条。Spatial Memory Fig. 6、§5
  • 写回：生成错误经深度估计进入地图，下一轮又成为条件。该传播链是架构分析；不能仅凭它断言某一具体失败一定由深度引起。

5. 训练目标与记忆的训练方式

GEN3C 用缓存渲染作为条件，微调视频扩散模型，SVD 配置预测干净 target latent：

$$\mathcal L_{\mathrm{GEN3C}}=\mathbb E\!\left[\left\|G_\theta(x_{t+1}^{\tau},\tau,r_t,c_t)-x_{t+1}\right\|_2^2\right]$$

几何缓存不是可学习 writer；深度和相机由外部估计 / 数据给定。训练多视图取自同序列，可包括 target 的过去或未来帧，这是 NVS 配对构造。它不意味着在线回访推理可以访问未来观测。GEN3C §4.4、§5.1

Spatial Memory 的监督是包含动态主体的完整 GT target 视频，条件则主要来自 source 的静态几何、近期帧和历史参考。视频生成器学会在静态约束下预测画面；TSDF 与关键帧触发规则没有由端到端记忆损失学出来。训练几何与在线几何的来源也不同。Spatial Memory §3.3–3.4、§4、App. A

论文内部：GEN3C 写回粒度 §4.5 描述 chunk 内每帧估深度并更新；App. A.1 用 chunk 末帧详细说明尺度 / 偏移拟合与追加。下方按附录写末帧示意，不把它称为唯一公开实现。尚未逐行核对官方代码的写帧策略。

6. 伪代码：完成 chunk 后再写几何

读写语义示意；两种方法的差异以分支表示，阈值来自配置，未填入论文没有给出的数值。

M = unproject(seed_rgb, estimate_depth(seed_rgb), seed_pose)
H, E = recent(seed_rgb), [seed_rgb]
cut3r_state = initialize_reconstructor(seed_rgb)

for target_poses, text in rollout_requests:
    if mode == "gen3c":
        rgb_views, covered = render_each_view(M, target_poses)
        cond = vae_encode(rgb_views) * latent_mask(covered)
        readout = fuse_after_input_layer(cond)
    else:
        static_rgb = render_static_map(M, target_poses)
        readout = vae_encode(static_rgb)
        refs = vae_encode(E)                 # episodic cross-attention

    x = denoise(noise(), readout, H, text,
                refs=refs if mode != "gen3c" else None)
    frames = vae_decode(x)                  # clean RGB, not noisy x_tau

    if mode == "gen3c":
        rgb, pose = frames[-1], target_poses[-1]  # App. A.1 example
        depth = estimate_depth(rgb)
        old_depth, valid = render_depth(M, pose)
        scale, shift = fit_affine_depth(depth, old_depth, valid)
        M.append(unproject(rgb, scale * depth + shift, pose))
    else:
        points, poses, cut3r_state = cut3r(frames, cut3r_state)
        static_points = tsdf_filter_and_extract(points)
        new_area = [newly_visible_area(M, p) for p in poses]
        M = fuse_static_points(M, static_points)
        for rgb, area in zip(frames, new_area):
            if area > episodic_threshold:
                E.append(rgb)
        H = recent(frames)                  # roll the working window
    yield frames

简答题

Q23如果已经能把历史点云渲染到目标相机，为什么还需要视频生成器？

历史图像只观察到部分表面，反投影还带有深度误差。渲染只能重排已有证据，无法给出遮挡后新显露的纹理和从未观察过的区域；生成器负责补全、修复投影瑕疵并形成当前画面。动态任务还要区分运动已由输入给定，还是需要根据近期帧和文本预测。

  • GEN3C 的动态 NVS 重拍输入视频，运动不是完全从静态缓存自主推断。
  • Spatial Memory 以静态地图约束背景，以 working / episodic 流补运动和远期细节。
  • 新区域写回后可以长期一致，但一致性本身不证明第一次补全是真的。

依据：GEN3C §4.1–4.4、§6；Spatial Memory §3.2–3.3。

Q24为什么一次深度或相机估计错误可能变成长期记忆错误？TSDF 能否彻底解决？

深度和 pose 决定点的世界地址与遮挡关系；地址错误被渲染成下一轮条件，再影响生成和新点写入。TSDF 可以抑制部分时间不一致的观测，却也可能把因重建错位而不一致的真实静态点过滤掉，因此不是无损纠错器。

  • GEN3C 先拟合深度尺度 / 偏移，且用分视图特征融合缓解硬融合冲突。
  • Spatial Memory 用 CUT3R 持续状态维持在线坐标，但急转和大位移仍可能令地图变稀疏。
  • 应分别检查估计、渲染条件、生成采纳和写回；不能从最终回访失败直接锁定唯一原因。

依据：GEN3C App. A.1、Tab. 5–6；Spatial Memory Fig. 6、App. A、§5。
