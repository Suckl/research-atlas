1. 动机：流式生成需要知道什么时候继续，什么时候切镜头

持续生成同一场景可以依靠近期 KV 延续动作。多镜头叙事还要求模型接受新 prompt、切换视角、引入新人，并在旧人物再次出现时取回相关证据。旧镜头的最后一帧有助于连续运动，却可能妨碍真正的 cut；只保留开场锚点，又不能保证找到后来才出场的人物。

ShotStream将任务变成由历史条件驱动的 next-shot generation：global cache 管跨镜头，local cache 管当前镜头，再用镜头 RoPE offset 区分二者。CausalCine把远程读取变成每层内容路由，选 top-\(k\) 历史帧，并在读取时重新分配 Block-Relative RoPE。它在原论文中直接以 ShotStream 为自回归 baseline。ShotStream §4；CausalCine §3.3、§4

缓存、寻址与训练必须配套 缓存回答“历史能否留下”，路由回答“当前该读哪段”，位置编码回答“取回的旧内容放在哪个注意力地址”，自生成训练回答“读到带错误的历史后如何继续”。这几个环节共同影响结果，不能用一个 FPS 或一致性分数互相替代。

统一记号：视频 chunk 时间为 \(t\)，去噪 / flow 时间为 \(\tau\)，当前 latent 为 \(x_t\)，近期上下文为 \(H_t\)，文本为 \(c_t\)，记忆为 \(M_t\)，查询为 \(q_t\)，读出为 \(r_t\)。镜头编号记为 \(s\)；\(a_t\)、\(p_t\) 分别保留给动作与相机位姿，本页方法主要通过文本控制，不要求独立的动作 / pose 流。

$$r_t=\mathrm{Read}(M_t,q_t),\qquad x_{t+1}\sim G(H_t,r_t,c_t),\qquad M_{t+1}=\mathrm{Write}(M_t,x_{t+1}).$$

ShotStream 在镜头边界重采历史并重建 global KV，镜头内部持续写 local；CausalCine 持续保存历史 KV，每个当前 chunk 从中挑选活动读取集合。这是两种不同的 \(\mathrm{Read}/\mathrm{Write}\) 实例。ShotStream §4.2、Supp. §9；CausalCine §3.3

3.1 ShotStream：稀疏历史不是固定开场 sink

给定历史镜头数 \(S_{\mathrm{hist}}\) 和条件预算 \(f_{\mathrm{ctx}}\)，每个旧镜头分配 \(\lfloor f_{\mathrm{ctx}}/S_{\mathrm{hist}}\rfloor\) 帧，余数留给最新镜头。历史条件帧保留自身 shot caption 与 global caption，目标帧读取自己的 shot caption；这样人物与背景证据不会被当前镜头文本错误重标。ShotStream §4.1

镜头内需要连续，镜头间需要可切换。ShotStream 对镜头 \(s\) 中位置 \(u\) 的 temporal rotation 写为 \(\Theta_{u,s}=\phi u+s\theta\)：\(\phi\) 是时间频率，\(\theta\) 是镜头跳变偏移。这里是论文标量形式的重写，不把它解释成查询后的检索重编号。ShotStream §4.2

3.2 CausalCine：内容路由替代位置优先读取

CausalCine的 Content-Aware Memory Routing（CAMR）在每个 self-attention 层工作。设历史帧 \(f\) 的空间 token 数为 \(P\)，chunk 包含 \(L\) 个 latent frames；每头保留平均 key 描述符 \(d_f\)，当前查询 \(q_t\) 对 chunk 的时空 token 平均。CausalCine §3.3，Eq. 6–8

$$d_f=\frac1P\sum_{p=1}^{P}K_{f,p},\qquad q_t=\frac1{LP}\sum_{u,p}Q_{t,u,p},\qquad s_{t,f}=\sum_{h,d}q_{t,h,d}d_{f,h,d}.$$

从 local window 外挑 top-\(k\) 帧，与最近 \(W\) 个 chunks 和当前 chunk 合并。路由本身无新参数，top-k 不可微；它依赖训练后的 Q/K 表征，不能把“parameter-free”误读成“无需训练生成器”。同一 chunk 内各帧共享选择，但不同层可以得到不同历史帧。CausalCine §3.3

3.3 Block-Relative RoPE：读出时换地址

旧帧原始位置可能远超训练范围。CausalCine 在 cache 里保留未旋转 K，选中后才把 memory、local、current 依次分配紧凑的时间位置。空间位置仍由原有 RoPE 处理；以下只写 temporal indices。CausalCine §3.3，Eq. 9

$$[0,k-1]_{\mathrm{memory}}\;\Vert\;[k,k+WL-1]_{\mathrm{local}}\;\Vert\;[k+WL,k+(W+1)L-1]_{\mathrm{current}}.$$

同一个旧 key 在不同查询中可能被分到不同块位置，故不能写入时一次性预旋转。此机制修复读地址范围，不恢复已删的内容，也不建立显式事件状态。CausalCine §3.3；能力区分为机制推导

5. 训练目标：让读到的历史接近推理条件

5.1 ShotStream：先镜头内，再镜头间 self-forcing

5.2 CausalCine：先学长多镜头因果结构，再压缩步数

真实视频的 clean 与 noisy chunks 打包为 \(2N\) 段并行 teacher forcing。noisy chunk 只读前序 clean 历史和自身 noisy token，禁止未来泄漏；每段文本仅路由到所属镜头。CAMR 在训练和推理采用相同规则，源侧 clean KV 与 noisy query 是不同噪声条件。CausalCine §3.2–3.3，Eq. 4–5

$$x_t^{\tau}=(1-\sigma_{\tau})x_t+\sigma_{\tau}\epsilon,\qquad \mathcal L_{\mathrm{FM}}=\mathbb E\left\|v_{\theta}(x_t^{\tau},\tau,c_t)-(\epsilon-x_t)\right\|^2.$$

\(\sigma_{\tau}=0\) 表示 clean，\(\sigma_{\tau}=1\) 表示 noise。先训练 full-step causal model，再做因果 ODE 初始化和 self-forced DMD，使用推理 KV 与路由生成训练样本；fake denoiser 的中间特征接 GAN head，约束长 rollout 的构图和运动漂移。CausalCine §3.1–3.4，Eq. 1–2 / 10–11

没有独立检索标签或显式故事状态 loss；生成任务学习 Q/K，再由不可微 top-k 选择记忆。训练数据、模型规模、因果调优和蒸馏都贡献主表性能，只有同配置记忆消融更接近隔离读取机制。

简答题

Q35为什么 ShotStream 既要分 global / local cache，又要分镜头内 / 镜头间 self-forcing？

缓存分工处理不同历史尺度，训练分阶段处理不同来源的历史错误。local 支持当前镜头连续性，global 支持旧镜头外观；先在 GT global 下学镜头内自生成，再让 global 也来自学生，以接近真正跨镜头推理。

  • 镜头边界重采 global、清空 local，避免把新镜头强制当成旧镜头延伸。
  • RoPE offset 区分旧镜头条件与当前镜头位置，消除混合读取的地址歧义。
  • 只做首阶段，global 仍是 GT，不能称全部历史都已对齐推理。

依据：ShotStream §4.1–4.2、Tab. 4、Supp. §9。

Q36CausalCine 每次只读 top-k 历史帧，是否意味着总记忆不增长，并已解决故事状态正确性？

两者都不能推出。top-k 限制活动注意力，完整历史 KV / 描述符仍增长；Block-Relative RoPE 修复位置范围。专用消失 / 再现消融支持角色外观召回，持续物理状态仍有明确失败例子。

  • 候选帧要保存并按 Q/K 相似度打分，archive 存储和路由成本需另算。
  • 未旋转 K 在检索后重定址；同一旧帧的读取位置可随当前查询改变。
  • 切镜头 SCA、身份相似和动作状态正确是不同指标，咖啡制作失败说明它们可分离。

依据：CausalCine §3.3、Tab. 3（Memory）、App. D / Fig. S3。
