1. 动机：滑窗逐出的 KV，还能再用吗？

滚动缓存让生成器持续运行，但近期窗口淘汰某段视频后，相应场景就失去可读取的证据。固定 opening sink 只能保留开场；中途出现、离开、再返回的对象未必仍在缓存里。WorldKV 将淘汰改成归档与召回；Memory Forcing 的流式版本将有限缓存分出 archive，让中段事件继续参与注意力。WorldKV §4；Memory Forcing 2026 §3.3

一句话理解 WorldKV 的问题是“这次回访要把哪段旧 KV 装回窗口”；Memory Forcing 的问题是“固定窗口内，怎样让近期运动与中段事件共存”。前者有外部候选历史，后者直接注意有限 archive；两者都不能承诺无限历史的逐细节恢复。

统一记号：视频时间为 \(t\)，去噪时间为 \(\tau\)；\(x_t\) 为当前视频 latent，\(H_t\) 为近期窗口，\(a_t,c_t,p_t\) 分别为动作、文本和相机位姿。\(M_t\) 是记忆，\(q_t\) 是查询，\(r_t\) 是读出。一次迭代也可生成一个 chunk：

$$r_t=\mathrm{Read}(M_t,q_t),\qquad x_{t+1}\sim G(H_t,r_t,a_t,c_t),\qquad M_{t+1}=\mathrm{Write}(M_t,x_{t+1},a_t,p_{t+1}).$$

WorldKV 的 \(q_t\) 可由位姿或累计动作构成；Memory Forcing 没有单独的几何检索器，\(q_t\) 是当前去噪窗口的 attention query。记忆中的 KV 是生成网络形成的层级表征，不能当作独立于模型、文本与位置编码的通用图像数据库。WorldKV §4.2；Memory Forcing 2026 §3.3–3.5

3. 组件拆解：外部召回与有限 archive

3.1 WorldKV：保留“与 anchor 不同”的 token

压缩不是按 attention 重要性永久删帧。令每帧有 \(n\) 个 token，首帧为 anchor，非 anchor token 的冗余分数为 \(s_j=n^{-1}\sum_i\cos(k_j,k_i^{\mathrm{anchor}})\)。保留低分 token，优先留下新显露区域与局部变化。各层可以选择不同索引；必须成对取对应的 K 和 V。WorldKV Eq. 5、§4.3

默认 chunk 含 3 个 latent 帧，anchor 全保留，其余 token 保留 25%，因此从 \(3n\) 变成约 \(1.5n\)；这是约 2 倍缓存压缩，不是整个生成系统内存减半。WorldKV §4.3、§5.1低冗余也不保证未来必需的小细节一定留下，这是压缩启发式的能力边界。

3.2 Memory Forcing：Attendable Mid-Horizon History（2026）

此文是 2610.11756，与 2025 年 Minecraft 空间版 Memory Forcing同名但不同。它明确沿用 Rolling Forcing 的滚动窗口联合去噪与 DMD，改的是后续步骤读取的缓存内容及其位置。Memory Forcing 2026 §3

Archive & Working Banks：opening chunk 填入 sink 后固定；新 clean chunk 进入 working。working 满时，将与新块 key 最不相似的旧块移入 archive，再让新块占 working 尾部。archive 满时 FIFO 删除最老 archive 块。当前 query 直接注意 sink、archive、working 与 current，不需要 camera Top-k 从更大外部库召回。Memory Forcing 2026 §3.3、Eq. 5、Alg. 1

Bank-aware RoPE：Rolling Forcing 只允许 sink 原始 key 重定位，其他 key 带写入时的绝对时间旋转。新版把整个窗口存成未旋转 key，在每次注意力前按 bank 重新旋转；sink、archive、working 的时间角色因此可以保持可区分。Memory Forcing 2026 §3.4

$$\iota(\mathrm{sink})=0,\quad \iota(\mathrm{archive}_j)=\frac{j-1}{N_a-1},\quad \iota(\mathrm{working}_w)=w,\quad \widetilde K=R(\iota)K_{\mathrm{raw}}.$$

这里 \(\iota\) 是虚拟视频位置，避免与去噪时间 \(\tau\) 混淆；\(N_a\) 计 archive 帧，单帧退化情形映射到零。current 排在 working 后。Memory Forcing 2026 Eq. 9

论文内部的边界表述正文多处把 archive 描述为开区间 \((0,1)\)，但式 (9) 均匀映射实际包含端点 \([0,1]\)。本页以式 (9) 为准；不能据文字宣称所有 bank 的每个位置绝不重合。Memory Forcing 2026 §3.4、Eq. 9、消融讨论

3.3 MAG：把压缩改成可监督 writer

Memorize-and-Generate（MAG）用独立 memory model 承担最终 KV 写入：块内全注意力把内容压入末帧 KV，再由该缓存重建整块来训练 writer。之后冻结 memory model，训练生成器读取其压缩缓存。论文默认块级 3 倍 KV 压缩，与 WorldKV 的运行时删冗余不同。MAG §3.3–3.5、Fig. 2–3、Tab. 4

MAG 保留逐块压缩历史；常数压缩率不能把随块数增长的历史变成常数总存储。它还在部分后续片段训练时移除生成器文本条件，促使模型使用历史。回访任务 MAG-Bench 区分真值历史与自生成历史，不能将两者视作同一记忆能力。MAG §3.2、§3.5–3.6

5. 训练目标与写入协议

WorldKV：直接改变推理缓存管理，不训练检索器或压缩器，没有新的记忆损失。高质量回访并不构成压缩 token 保真度的独立监督。WorldKV §4

Memory Forcing：继承 DMD 的分布匹配与 flow critic；训练混合滚动窗口和 self-forcing 窗口，等概率抽样，推理只用 rolling。生成器在自生成历史上学习，archive 晋升规则本身是 key similarity 启发式。Memory Forcing 2026 §3.1–3.2、§3.5

$$\nabla_\theta\mathcal L_{\mathrm{DMD}}\approx\mathbb E\!\left[(s_{\mathrm{gen}}(\hat x^{\tau},\tau)-s_{\mathrm{data}}(\hat x^{\tau},\tau))\frac{\partial\hat x}{\partial\theta}\right].$$

上式沿用通用 score 记号，省略前向加噪权重；不是新增 paired return 重建损失。Aligned cache insertion要求提交 KV 的前向也能看到 sink、archive、working 和 current，与去噪前向的可见集合对齐，避免“生成时使用记忆、写入时没有记忆”的表征失配。Memory Forcing 2026 Eq. 3、§3.5

简答题

Q11归档全部逐出 KV 与固定 archive bank 有何区别？为什么“活跃缓存固定”不足以说明总内存固定？

WorldKV 将活跃窗口与候选档案分开，限定本次 attention 的大小，但旧 chunk 可以继续积累在 GPU/CPU。Memory Forcing 把 archive 也限定在缓存内，直接参与 attention，容量满就永久删除旧事件。两者的区别在保存范围和删除规则，不能只比较当前 GPU 活跃 token。

  • CPU offload 减少 GPU 驻留量，完整历史仍占 CPU 容量。
  • 固定比例压缩减小增长斜率，不能消除历史增长。
  • 固定 bank 真实限制了缓存，但远程召回能力也受到容量与晋升规则限制。

依据：WorldKV §4.1–4.3、Fig. 2；Memory Forcing 2026 §3.3、Alg. 1；MAG §3.3–3.4。

Q12为什么把旧块放进 archive 还不够？Memory Forcing 对 Rolling Forcing 的位置与写入协议改了什么？

旧 key 若仍绑定原绝对时间，后续 query 可能读到训练范围之外的旋转相位；写缓存的前向若缺少生成时使用的上下文，KV 也会失配。新版存整个窗口的 raw K，在读取时按 bank 重定位，并让 clean insertion 看到与去噪相同的上下文集合。

  • 继承 rolling joint denoising 与 DMD；改动发生在缓存管理和读取地址。
  • bank-aware 位置区分 opening、mid-horizon 与近期；没有几何 Top-k 外部召回。
  • Aligned cache insertion 对齐写入与去噪的可见集合，不能恢复已 FIFO 删除的 archive。

依据：Memory Forcing 2026 §3.3–3.5、Eq. 9、Alg. 1。
