1. 动机：看到同一视锥，不一定看到同一表面

相机回到厨房附近时，FoV 检索可能选中墙另一侧的历史视图：两个视锥在空间交叠，实际可见表面却不同。VMem 把“以前哪张图见过这块表面”写成三维索引；它按目标相机可见的 surfels 找旧视图，再把这些二维证据交给生成器。VMem §1、§3.1

一句话理解 Surfel 是历史视图的地址索引。它帮助回答“哪张旧图真的看见了这里”，不负责把过去的图像融合成供生成器直接渲染的完整世界。

这使 VMem 位于历史检索路线：它使用几何，但核心读出仍是 past views。与显式三维 cache相比，几何误差首先影响证据选择，而不是直接变成输入生成器的像素重投影误差；这不等于完全不受几何质量影响。VMem §1–3

2. 一次生成：渲染索引、读视图、更新表面地址

视频时间 \(t\)，扩散时间 \(\tau\)，当前 latent \(x_t\)，近期历史 \(H_t\)，相机 \(p_t\)，查询 \(q_t\)，记忆 \(M_t\)，读出 \(r_t\)。动作 \(a_t\) 与文本 \(c_t\) 是轨道通用符号，本作生成接口主要由相机和 reference images 控制，不加入动作事件 writer。

$$M_t=(\mathcal V_t,\mathcal S_t),\quad r_t=\mathrm{Read}(M_t,q_t),\quad x_{t+1}\sim G_\theta(r_t,p_{\mathrm{target}}),\quad M_{t+1}=\mathrm{Write}(M_t,x_{t+1},p_{t+1}).$$

一次生成实际可输出一组目标视图，因此 \(t+1\) 在这个骨架里表示下一生成步；论文另用 step 与 view index 区分。它不用必须连续的近期窗口 \(H_t\)，而用稀疏、无序的检索 views。VMem §3、§3.2

3. 组件拆解：表面只是指路，图像才是证据

3.1 两份数据结构：视图库与 surfel 索引

视图库 \(\mathcal V_t\) 保存 \(v_i=(I_i,p_i)\)：RGB 图像 \(I_i\) 与 camera。surfel 集 \(\mathcal S_t\) 保存每块粗表面的中心、法向、半径和 view ID 集，octree 帮助按空间位置找到候选。论文用 surfel 的 \(\mathbf p_k\) 表示位置；为避免和相机 \(p_t\) 混淆，本页改写为 \(\mathbf u_k\)。VMem §3.1

$$s_k=(\mathbf u_k,\mathbf n_k,\rho_k,\mathcal I_k),\qquad \mathcal I_k=\{i:\text{历史视图 }i\text{ 曾观察表面 }k\}.$$

索引并不储存一套可精确渲染的纹理世界。surface → IDs 的关系是可见证据的关联：同一块表面可以指向多个历史视图，同一幅视图也覆盖多块表面。这比用一幅图一个 FoV key 更细，但并非 learned entity slots。VMem Fig. 3、§3.1

3.2 阅读路径：可见性投票与 NMS

先计算下一组相机的平均 pose，从该 pose 将 surfels splat 到网格。深度决定前后遮挡；落在像素上的属性是过去视图索引集合。统计 ID 在渲染像素中出现的频率，取 Top-K，并对相近 pose 做 non-maximum suppression，减少重复回访区域占满名额。VMem §3.1、App. B

$$\mathrm{vote}(i)=\sum_{u,v}\mathbf 1[i\in\mathcal A_t(u,v)],\qquad \mathcal I^*=\mathrm{NMS}_{\mathrm{pose}}\big(\mathrm{rank}_i\,\mathrm{vote}(i)\big),\qquad r_t=\{(I_i,p_i):i\in\mathcal I^*\}.$$

\(\mathcal A_t(u,v)\) 是索引渲染的像素属性，上式是讲解级概括。关键区别是“render IDs → retrieve RGB”，不是“render RGB → inpaint”。对新视角中从未看过的区域，表面索引没有对应证据，仍需依赖生成先验。VMem Fig. 4、§3.1–3.2

3.3 写入路径：新视图估几何，合并地址关联

新目标组完成后，RGB / camera 加入视图库。point-map estimator（如 CUT3R）联合估计新视图与本轮检索到的旧视图，以对齐已有坐标系。App. C 固定用户相机，冻结旧帧深度，仅保存新帧优化结果。这保留了因果的旧几何锚。VMem §3.1、App. C

降采样 point map 产生 surfels，邻域位移的叉积给法向，深度、焦距和法向朝向决定半径。若新旧中心足够近且法向余弦相符，给旧 surfel 的 ID 集追加新 view index；否则创建新 surfel。相机极相近时去掉较旧关联，降低反复访问造成的冗余。VMem §3.1

这是一种几何地址维护：它没有额外的“门已打开”符号状态，也没有普遍的运动物体旧表面失效机制。把旧地址映到正确状态仍是动态更新需要另解的问题。

3.4 Generator 读取什么？

SEVA 是 camera-conditioned image-set generator，可以使用稀疏、无序 references。VMem 把所取 RGB 与 reference camera、target camera 的 Plücker embeddings 送入它。surfel normals / radii / ID 渲染不作为一幅完整场景图像交给它。VMem Fig. 2、§3.2

记忆模块本身可插拔；论文还单独训练少 reference 的轻量 SEVA。减少 reference 数和额外 LoRA 微调共同改变推理速度及质量，因此速度收益不能全部归为索引算法更快。VMem §4.1、§4.4、App. A

5. 学习什么，哪些读写不求梯度？

VMem 索引建立、可见性投票、NMS 与 surfel 合并都是几何规则，不通过它们反传生成损失。point-map estimator 是现成几何工具；生成器本身是预训练 SEVA。少 reference 配置通过 LoRA 在 RealEstate10K 上微调，训练时随机抽取 context views。VMem §3.1、§4.1、App. A

因此“plug-and-play memory”与“轻量生成器额外训练”应分开：索引负责让既有模型拿到更有用 evidence；训练负责让该模型适应更少 references。论文没有定义独立的 memory reconstruction loss、learned retriever 或状态持久化辅助损失。VMem §3.2、§4.1

$$\mathcal I^*=\mathrm{Retrieve}_{\mathrm{geometry}}(\mathcal S_t,p_{\mathrm{target}}),\qquad x_{t+1}\sim G_{\theta+\Delta\theta_{\mathrm{LoRA}}}(\mathcal V_t[\mathcal I^*],p_{\mathrm{target}}).$$

上式只标注梯度职责，不新增一个论文未定义的训练目标。自生成视图写入造成的误差会影响以后检索；粗几何降低对精确重建的要求，但并未消除该反馈环。

论文内部配置需复核§3.1 用 H′=H/σ 表达降采样，App. A 却将 point-map scaling factor 写为 σ=0.03；两处的比例语义不能直接按同一公式实施。本页只保留“粗化 point map”，具体缩放方向需核对官方实现。VMem §3.1、App. A

9. 承上启下：索引维护成本与持久状态

从 FoV 到表面

  • CaM / WorldPack按视角相关性选择或压缩帧。
  • VMem 用可见 surfel 关联历史 views，允许遮挡参与证据选择。

两条不同后续

  • 显式 3D cache直接投影空间内容作为生成条件。
  • L2R把相机引导读取内化到循环 state，避免外部 view index。
  • 动态记忆需要决定旧表面 / 旧外观何时失效。
L2R 的比较绑定其实现L2R §4.5 在匹配分辨率、相机和 chunk 的单 H100 比较中，描述自己的 VMem baseline 每步对全部 stored frames 做 point-map / global alignment。原 VMem §3.1 写的是新视图与 retrieved views 联合估计，App. C 固定旧深度。两处不能直接等同；L2R 的维护开销评价不应改写成 VMem 原方法必然每步重建全部历史。L2R §4.5；VMem §3.1、App. C

VMem → L2R 是主要 baseline 对照关系，不意味着后者继承 surfel 数据结构或权重。索引路线的成本还取决于具体几何工具与实现，循环 state 路线也仍有有效容量与读取正确性的取舍。

简答题

Q19VMem 明明使用三维 surfels，为什么仍归为历史视图检索，而不是完整三维世界缓存？

Surfel 保存的是表面到过去视图 IDs 的关联。渲染时输出索引属性，之后按 IDs 取回 RGB / camera 送进 image-set generator；真正读入的证据是 past views。它没有把 surfels 渲染成完整 RGB 世界直接交给生成器。

  • 几何在这里决定“找哪张旧图”。
  • 显式 3D cache 的典型读出是投影 / 渲染的空间内容。
  • VMem 仍依赖粗几何质量，但其误差传递路径首先是检索。

依据：VMem §1、§3.1–3.2、Fig. 2–4。

Q20若固定检索 views 的数量，是否就能保证常数总内存、实时生成和动态状态正确？

不能。K 只限制 generator 活动 reference 数；视图库与 surface 索引仍可扩展，几何维护和多步采样也有成本。表面地址能找旧视图，却不自动告诉模型动作后哪些旧内容失效。

  • 分别统计生成器输入、图库、surfel 数与 ID 关联。
  • 速度必须绑定 K、LoRA 配置、几何实现与硬件。
  • 需要动态删除 / 覆写和动作后回访实验，静态 cycle 指标不足以替代。

依据：VMem §3.1、§4.4、App. D；L2R §4.5 的实现差异。
