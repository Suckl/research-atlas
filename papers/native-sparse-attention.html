大模型要处理的文本越来越长：一整本书、一个完整的代码仓库、几万 token 的思维链。标准的注意力机制让每个新 token 都和它前面的所有 token 打一次分，所以训练和预填充时的计算量随长度按平方增长；逐个生成 token 时，每一步都要把前面所有 token 的 KV 缓存从显存里读一遍。论文引用的一个理论估算是：在 64K 长度的上下文上解码，注意力占总延迟的 70–80%。

一个自然的想法是稀疏注意力：每个 query 只和少数最重要的 key 计算，其余的跳过。这类方法已经有很多，但作者认为它们有两个共同的缺陷。第一，理论上省掉的计算，常常没有变成实际的提速：有的方法只加速预填充或只加速解码，有的方法和当时主流的 GQA 结构冲突。第二，几乎所有方法都只在推理时启用，模型训练时用的仍是完整注意力；推理时突然“少看”一部分，模型并没有为此做过准备，而训练阶段本身的长序列开销也一点没省。

论文提出的 NSA（Natively trainable Sparse Attention）从预训练开始就让模型使用稀疏注意力。它给每个 query 准备三份精简过的 KV：一份是把每段 token 压缩成一个代表的压缩分支，用来粗略地扫一遍全文；一份是从全文中挑出 16 个最相关的连续块的选择分支，用来细看关键内容；一份是最近 512 个 token 的滑动窗口分支，专管局部。三路注意力的结果用可学习的门控加权求和。选择以 64 个连续 token 为单位，并且同一个 GQA 组里的所有注意力头共用一套选择，这两条约束让它能写成高效的 GPU 内核。

实验用一个总参数 27B、每 token 激活 3B 的 MoE 模型，分别用全注意力和 NSA 各训练一遍。NSA 版本在通用基准、长上下文基准 LongBench 和蒸馏后的数学推理 AIME 上都不差于、甚至高于全注意力版本；在 A100 上，64K 序列的注意力内核前向快 9.0 倍、反向快 6.0 倍，解码按访存量估计可快 11.6 倍。这篇论文获得了 ACL 2025 最佳论文奖，它的思路后来演变成 DeepSeek-V3.2 的 DeepSeek Sparse Attention（DSA）。

1 引言：长上下文为什么需要稀疏注意力，现有方法又差在哪

这一节要回答的问题：推理模型、仓库级代码生成、多轮智能体都需要很长的上下文，而标准注意力的开销随长度快速增长，成了延迟的主要来源。注意力的权重本身是高度集中的，大部分权重落在少数 key 上，所以“只算重要的那部分”看起来顺理成章。那么，已有的稀疏注意力方法为什么在实际部署中表现不佳？一个好的稀疏注意力需要满足哪些条件？这一节先把长上下文下注意力的两种开销讲清楚，再看作者提出的两条要求。
先补一点背景：长上下文下，注意力在两个阶段分别贵在哪里。

注意力的计算可以想成一次查资料。每个 token 算出一个 query（我想找什么）、一个 key（我能提供什么的标签）和一个 value（我携带的内容）。处理第 \(t\) 个 token 时，用它的 query 和前面 \(t\) 个 token 的 key 逐个求点积，得到的分数经过 softmax 变成权重，再按权重把这些 token 的 value 加起来。（更细的讲解见本站 vLLM 精读 §2.1。）

训练和预填充：贵在计算。这两个阶段一次处理整段序列，所有 token 同时算。第 \(t\) 个 token 要和前面 \(t\) 个 token 各算一次，长度为 \(N\) 的序列一共约 \(N^2/2\) 对。长度翻倍，注意力的计算量变成 4 倍；而模型其他部分（线性层、MoE 专家）的计算量只和 token 数成正比，长度翻倍只变成 2 倍。所以序列越长，注意力在总计算量里占的比例越大。这个阶段的数据可以大块地喂给矩阵乘法单元，GPU 主要被算力限制，减少注意力的计算量就能直接提速。

解码：贵在读显存。逐个生成时，每一步只算一个新 token，但它要和前面所有 token 的 key、value 做注意力。这些 key 和 value 早就算好存在显存里（即 KV 缓存），每一步都要整份读一遍。读的数据很多、做的计算很少，GPU 的计算单元大部分时间在等数据，速度由显存带宽决定。这个阶段要提速，就得减少每一步读的 KV 数量。还有一点：模型参数是一个批里所有序列共用的，读一遍就能服务整批；KV 缓存却是每条序列各读各的。所以批越大，读 KV 在总读取量里的比例越高。

用论文实验模型的配置算一笔账（推算，只算矩阵乘法，按 BF16 每个数 2 字节）：这个模型有 30 层，每层 64 个 query 头，每个头的 query / key 是 192 维、value 是 128 维；KV 按 GQA 分成 4 组。

  • 每一对 (query, key) 在一层里要做 \(64\times(192+128)\times 2=40{,}960\) 次浮点运算。一条 64K 序列的前向，注意力部分约 \(2^{31}\) 对 × 40,960 × 30 层 ≈ 2,639 TFLOP；线性层按“2 × 激活参数 × token 数”估算约 393 TFLOP。注意力占了约 87%。
  • 每个 token 每层要缓存 4 组 × (192 + 128) = 1,280 个数，30 层合计约 75 KiB。一条 64K 序列的 KV 缓存约 5.03 GB，解码时每一步都要读完它；这已经接近每 token 激活的约 30 亿参数（约 6 GB）的读取量。

回到论文。作者指出，softmax 注意力天生是稀疏的：对一个 query 来说，大部分权重集中在少数几个 key 上，其他 key 的权重接近于零。只计算这些关键的 (query, key) 对，就能在几乎不损失效果的前提下大幅省掉计算。已有的方法大致分三类：

  • KV 缓存淘汰：在解码过程中把“不太重要”的 token 从 KV 缓存里删掉，比如 H2O、SnapKV（本站有 SnapKV 精读）。
  • 按块选择 KV：把 KV 缓存切成块，每一步按 query 估计每块的重要性，只读最重要的几块，比如 Quest、InfLLM。
  • 采样、聚类或哈希：用局部敏感哈希、k-means 聚类等手段快速找出和 query 最像的 key，比如 MagicPIG、ClusterKV、HashAttention。

但作者观察到，这些方法在实际部署中常常不如预期。很多方法的实际加速远小于理论上省掉的计算量；而且大多数方法没有训练期的支持，不能让模型在训练中适应并利用稀疏的模式。

由此，作者提出一个实用的稀疏注意力必须满足的两条要求：

  1. 推理加速要与硬件对齐：省下的计算要真的变成速度，预填充和解码两个阶段都要快，算法设计必须照顾到显存访问和 GPU 调度的特点。
  2. 算法设计要考虑训练：稀疏操作要能参与端到端训练，既降低训练开销，又不损失模型能力。

NSA 针对这两条各给了一个答案。硬件方面，它把稀疏的单位定为连续的块，让每次访存都是连续的大块读取，并且平衡计算和访存，充分利用 Tensor Core。训练方面，它设计了高效的前向、反向算子，让稀疏注意力可以从头稳定地训练。论文用一个 27B 参数的 Transformer 做预训练实验，引言里写的训练量是 260B token（§4.1 写的是 270B，两处不一致，以下按 §4.1 的 270B），并在 A100 上与 Triton 实现的注意力内核比较速度。

读的时候容易误解的地方：
  • 这里的“稀疏”指的是每个 query 只看一部分 key，不是把模型权重剪成稀疏矩阵。模型参数是完整的、稠密的。
  • 引言里“64K 解码时注意力占延迟的 70–80%”是论文所说的理论估算，没有给出是哪个模型、什么批大小下算的，只能当作量级的提示。

2 重新审视稀疏注意力：两个“看上去成立”的假设

这一节要回答的问题：已有的稀疏注意力大多是在一个用全注意力训练好的模型上，推理时再加稀疏。作者认为这种做法有两处想当然的地方，并分别给它们起了名字。第一处叫“高效推理的错觉”：算得少了，不等于跑得快了。第二处叫“可训练稀疏的迷思”：把推理期的方法直接拿去训练，会遇到不可导和反向传播低效两个障碍。这一节逐个拆开，它们正是 NSA 每个设计决定的出发点。

2.1 高效推理的错觉：算得少了，为什么没变快

先补一点背景：MHA、MQA 与 GQA。

标准的多头注意力（MHA）里，每个注意力头都有自己的一套 key 和 value。解码时，每一步要读的 KV 缓存量正比于头数。MQA（Multi-Query Attention）让所有 query 头共用同一套 key 和 value，KV 缓存一下子缩小到原来的“头数分之一”，但模型效果往往会打折扣。GQA（Grouped-Query Attention）是折中：把 query 头分成若干组，组内的头共用一套 key 和 value。论文的实验模型有 64 个 query 头、4 组，也就是每 16 个头共用一套 KV。按上面的维度推算，每个 token 每层只需缓存 1,280 个数；如果改成 MHA，需要 \(64\times(192+128)=20{,}480\) 个，是 16 倍。

GQA 省下的不只是显存容量，更重要的是解码时每一步读显存的量：同组 16 个头的 query 可以对着同一份 KV 一起计算，KV 只读一遍。当时的主流大模型普遍采用 GQA 或 MQA。

先补一点背景：几个推理期稀疏方法分别在做什么。
  • H2O（Heavy-Hitter Oracle，2023）：作者观察到少数 token 在注意力里贡献了大部分权重，称之为“重击者”。H2O 在解码过程中只保留这些重击者和最近的若干 token，把其余 token 的 KV 从缓存里删掉。判断谁是重击者需要统计注意力分数，所以预填充阶段仍要算完整的注意力。
  • Quest（ICML 2024）：把 KV 缓存切成页，每页记录 key 在每个维度上的最小值和最大值。解码时用当前 query 和这两个边界估计这一页里可能出现的最大注意力分数，只读分数最高的若干页。它是“按 query 动态选择”，被删掉的 KV 并不真正丢失，下一步可能又被选中。它的摘要报告自注意力最多快 2.23 倍。
  • MInference（NeurIPS 2024）：专门加速预填充。它的摘要提到，在单张 A100 上用一个 8B 模型处理 100 万 token 的输入，光预填充就要 30 分钟。它为每个注意力头离线确定一种稀疏形状（A 形、竖线加斜线、块稀疏），推理时据此只算一部分位置。

作者归纳了这些方法跑不快的两个原因。

第一，稀疏只覆盖了某一个阶段。H2O 在解码时稀疏，但预填充时要算完整注意力，还要额外统计注意力分数、建立索引；MInference 正好相反，只加速预填充。只要有一个阶段的开销和全注意力相当，整体加速就有限。而不同任务的瓶颈阶段不同：读一本书写摘要、补全代码，输入很长、输出很短，预填充占大头；长思维链推理输入不长、输出很长，解码占大头。只加速一个阶段的方法，总有一类任务吃亏。

第二，和 GQA / MQA 不兼容。以 Quest 为例，它让每个注意力头独立挑选自己要读的 KV。在 MHA 模型里，每个头本来就有自己的一份 KV，各选各的没有问题，计算量和读取量都按比例减少。但在 GQA 模型里，同一组的 16 个头共用一份 KV，每个头挑的块却各不相同。为了让这 16 个头都算得出来，必须把它们挑中的块的并集都读进来。计算量是减少了，读显存的量却可能接近不稀疏的时候，而解码偏偏是被读显存卡住的。

示意图：同一 GQA 组里，“每个头各选各的”和“全组共用一套选择”，要读的 KV 块差多少
怎么看：横向 16 格是一个 GQA 组共用的 KV 缓存，按块切开。(a) 里 4 个头（实际一组有 16 个）各自挑 2 块，蓝色是各头的选择；最下面一行橙色是这一步必须从显存读进来的块，也就是并集，共 6 块。每个头只“算”了 2 块，但读显存的量是 6 块，头越多、选择越分散，并集越接近全部。(b) 里全组用同一套选择，读 2 块就够了，每块被 16 个头复用。这就是 NSA 在 §3.3.2 里强制组内共享选择的原因。本站示意图，原文没有对应的图。

作者的总结是：很多方法关注的是 KV 缓存缩小了多少、理论计算量少了多少，却没有在真正先进的推理框架和硬件后端上兑现为延迟的降低。要真正提速，算法必须同时照顾到先进的模型结构（GQA / MQA）和高效的硬件实现。

2.2 可训练稀疏的迷思：推理时才稀疏，有什么问题

作者坚持“训练时就稀疏”，有两方面的理由。

其一，事后稀疏会损害效果。一个模型在全注意力下训练好，它的所有参数都是按“能看到全部上下文”优化的。推理时突然只让它看一部分，相当于把它推离了训练时走过的优化轨迹。论文引用 MagicPIG 的发现：注意力分数最高的 20% 只覆盖了全部注意力分数的约 70%，剩下的 30% 分散在大量低分 token 上。一些专门负责从长文中检索信息的注意力头（“检索头”），在推理期剪枝时尤其容易受损。

其二，训练本身也需要省。现代大模型的开发里，长序列训练越来越多：用更长的文档预训练，以及长上下文微调、强化学习等后续阶段。现有稀疏方法主要瞄准推理，训练期的长序列开销基本没人解决。

那么，能不能直接把推理期的稀疏方法拿来训练？作者列出了两个障碍。

障碍一：选择过程里有不可导的部件。ClusterKV 用 k-means 聚类决定哪些 key 归为一组，MagicPIG 用 SimHash 哈希挑选 key。这些离散操作在计算图里是断开的，梯度传不过去，模型没法通过训练学会“该看哪里”。

障碍二：反向传播的效率太低。有些方法理论上可以训练，但它们按单个 token 挑选（比如 HashAttention），计算时要从 KV 缓存的各个角落零散地读取 token。这种不连续的访存没法套用 FlashAttention 这类快速注意力的做法，只能退回到硬件利用率很低的实现，训练反而更慢。

先补一点背景：FlashAttention 为什么依赖“连续的块”。

GPU 上有一块很大但较慢的显存（HBM），和每个计算单元旁边一块很小但很快的片上存储（SRAM）。FlashAttention 把 query、key、value 切成固定大小的块：一次把一块 query 和一块 key / value 搬进 SRAM，在片上算完这一块的分数、softmax 和加权和，再换下一块 key / value，用“在线 softmax”把各块的结果正确地合并起来。这样完整的 \(N\times N\) 注意力矩阵从来不需要写回显存。这套做法高效的前提是：每次搬进来的是显存里连续存放的一整块数据，搬进来之后又能交给 Tensor Core 做一次规整的小矩阵乘法。如果要读的 token 东一个西一个，就既不能整块搬，也凑不成规整的矩阵乘法。（详见本站 FlashAttention 精读 §3；FlashAttention 原文也讨论过“块稀疏”的版本，见 §6。）

方法稀疏发生在哪个阶段论文指出的问题

2.3 结论：稀疏应该是“原生”的

推理效率和训练可行性两方面的局限，促使作者从头重新设计稀疏注意力，而不是在已有方法上修补。NSA 要同时满足两条：算得快（预填充、解码、训练三处都快），以及能端到端地训练。

读的时候容易误解的地方：“可训练”在这一节里有两层意思，要分开看。一层是梯度能不能流到决定“看哪里”的那部分参数；另一层是训练能不能真的跑得快。后面会看到，NSA 的 top-n 选块这一步本身仍然是离散、不可导的；它绕过不可导的办法，不是让选择可导，而是让打分直接复用一个本来就在被语言模型损失训练的分支（§3.3.2）。

3 方法：三个分支、一个门控，再加一个专门的内核

这一节要回答的问题：NSA 具体怎么为每个 query 准备一份精简的 KV？三个分支各自怎么构造，为什么需要三个而不是一个？选择分支用什么给块打分，打分的开销从哪里省下来？这些设计又怎样落实成一个在 GPU 上真正快的内核？这一节是全文的核心，按论文的顺序分成背景、总体框架、三个分支和内核设计四部分。

3.1 背景：注意力公式与算术强度

论文先写下标准注意力。第 \(t\) 个 query \(\mathbf{q}_t\) 和它之前的所有 key \(\mathbf{k}_{:t}\)、value \(\mathbf{v}_{:t}\) 做注意力：

$$\mathbf{o}_t=\operatorname{Attn}(\mathbf{q}_t,\mathbf{k}_{:t},\mathbf{v}_{:t})=\sum_{i=1}^{t}\frac{\alpha_{t,i}\,\mathbf{v}_i}{\sum_{j=1}^{t}\alpha_{t,j}},\qquad \alpha_{t,i}=e^{\mathbf{q}_t^{\top}\mathbf{k}_i/\sqrt{d_k}}$$

这里 \(\alpha_{t,i}\) 是第 \(t\) 个 query 对第 \(i\) 个 key 的未归一化权重，\(d_k\) 是 key 的维度。分母把权重归一化，相当于 softmax。

接着论文引入算术强度：一个计算任务做的运算次数除以它读写显存的字节数。每块 GPU 有一个临界值，等于峰值算力除以显存带宽。任务的算术强度高于临界值，就是算力受限；低于临界值，就是带宽受限。（这个概念在本站 FlashAttention 精读 §2.2 里有图解。）对注意力来说，训练和预填充一次处理大批 token，算术强度高，是算力受限；自回归解码每次只算一个 token 却要读整份 KV 缓存，算术强度低，是带宽受限。所以两个阶段的优化目标不同：训练和预填充要减少计算，解码要减少访存。NSA 想用同一套设计同时做到这两件事。

3.2 总体框架：给每个 query 换一份更紧凑的 KV

NSA 的出发点是：不让 \(\mathbf{q}_t\) 面对全部的 \(\mathbf{k}_{:t},\mathbf{v}_{:t}\)，而是根据 \(\mathbf{q}_t\) 和上下文，动态构造一份更紧凑、信息更密集的 \(\tilde K_t,\tilde V_t\)，再在这份精简的 KV 上做注意力：

$$\tilde K_t=f_K(\mathbf{q}_t,\mathbf{k}_{:t},\mathbf{v}_{:t}),\quad \tilde V_t=f_V(\mathbf{q}_t,\mathbf{k}_{:t},\mathbf{v}_{:t}),\qquad \mathbf{o}^{*}_t=\operatorname{Attn}(\mathbf{q}_t,\tilde K_t,\tilde V_t)$$

构造方式可以有好几种，每种叫一个“映射策略” \(c\)。NSA 用了三种：压缩（cmp）、选择（slc）和滑动窗口（win）。每种策略各自算一次注意力，再用门控加权求和：

$$\mathbf{o}^{*}_t=\sum_{c\in\{\text{cmp},\,\text{slc},\,\text{win}\}} g_t^{c}\cdot\operatorname{Attn}\big(\mathbf{q}_t,\tilde K_t^{c},\tilde V_t^{c}\big),\qquad g_t^{c}\in[0,1]$$

门控分数 \(g_t^{c}\) 由当前 token 的输入特征经过一个 MLP 和 sigmoid 得到。注意这里用的是 sigmoid 而不是 softmax：三个门各自在 0 到 1 之间取值，互不约束，加起来不必等于 1。模型可以同时开大三个分支，也可以把某个分支几乎关掉。论文没有说明门控是每个头一个值还是所有头共用；第三方实现 fla-org/native-sparse-attention 的接口里，门控是每个 query 头各一个值。

记 \(N_t\) 为三个分支的 key 总数，NSA 要保证 \(N_t\ll t\)。按论文的超参数推算：在 64K 位置上，压缩分支约 4,096 个压缩 token、选择分支 1,024 个 token、滑动窗口 512 个 token，合计约 5,632 个，只有全部 65,536 个的约 8.6%。

示意图：NSA 一层注意力的三条路径（数字按论文 §4.1 的超参数）
怎么看：最上面一排是当前位置之前的所有 token。它们分三路进入三个分支：蓝色的压缩分支把全文粗略地压成少量代表，橙色的选择分支挑出最相关的 16 个原始块，绿色的滑动窗口分支只看最近 512 个 token。三个分支用的 K、V 各自有独立的投影（§3.3.3 解释原因）。每个分支各做一次注意力，结果乘上各自的门控后相加。中间那条虚线表示选择分支的块分数直接取自压缩分支的注意力分数，不另设打分网络。本站示意图，对应 原文图 2 左 ↗。

3.3 第一个分支：把每段 token 压成一个代表（Token Compression）

压缩分支把连续的一段 key（或 value）聚合成一个块级的表示，用它代表整段的信息：

$$\tilde K^{\text{cmp}}_t=f^{\text{cmp}}_K(\mathbf{k}_{:t})=\Big\{\varphi\big(\mathbf{k}_{id+1:\,id+l}\big)\ \Big|\ 0\leqslant i\leqslant\Big\lfloor\frac{t-l}{d}\Big\rfloor\Big\}$$

逐项解释：\(l\) 是块长，\(d\) 是相邻两块之间的步长，\(\varphi\) 是一个可学习的 MLP，并带有块内位置编码（让它知道一个 key 在块里的第几个位置），它把一块里的 \(l\) 个 key 映射成 1 个压缩 key。value 同理。条件 \(id+l\leqslant t\) 保证只压缩已经完整出现的块，不会偷看未来的 token。论文取 \(l=32\)、\(d=16\)，所以每块 32 个 token、相邻块重叠一半。

为什么要让块重叠（\(d<l\)）？论文的说法是“减少信息碎片化”。可以这样理解：如果块不重叠，一个关键的短语正好跨在两块的边界上，就会被拆成两半，分别稀释在两个压缩表示里。块重叠一半后，任何一段长 16 的连续 token 都完整地落在某一个块内部，不会被切断。代价是压缩 token 的数量翻倍：位置 \(t\) 处大约有 \(t/16\) 个，而不是 \(t/32\) 个。

压缩 token 承载的是更粗粒度、更偏高层语义的信息，计算量也小：在 64K 位置上，query 只要和约 4,096 个压缩 key 打分。但只靠压缩一定会丢掉细节：把 32 个 token 压成一个向量，某个具体的数字、某个变量名很可能就模糊了。这就引出了第二个分支。

3.4 第二个分支：挑出最相关的原始块（Token Selection）

选择分支的任务是：在全文中找出对当前 query 最重要的部分，把这部分的原始 key 和 value 原样拿来做注意力，保住细节。设计上有两个关键决定：按块选，以及用压缩分支的分数来打分。

决定一：按连续的块来选，而不是按单个 token。论文给了两个理由。硬件方面，GPU 读一整段连续内存比按索引零散地读快得多，而且按块计算才能凑成规整的矩阵乘法，用满 Tensor Core；FlashAttention 也正是建立在按块访存和计算之上。数据方面，已有工作（MInference）和本文 §6.2 的可视化都显示，注意力分数在空间上是连续的：相邻的 key 往往重要程度相近。既然重要的 token 本来就成片出现，按块选不会损失多少。

决定二：块的重要性分数直接取自压缩分支。给每个块打分本身可能很贵。但压缩分支在做注意力时，本来就要算出 \(\mathbf{q}_t\) 对每个压缩 key 的注意力概率：

$$\mathbf{p}^{\text{cmp}}_t=\operatorname{Softmax}\big(\mathbf{q}_t^{\top}\tilde K^{\text{cmp}}_t\big)$$

这个向量说明了“当前 query 有多关注全文的每一段”，正好可以拿来当选择分支的块分数，几乎不增加计算。剩下的问题是，压缩块和选择块的切法不一样，需要换算。

如果两者的切法完全相同（\(l'=l=d\)，\(l'\) 是选择块的长度），分数可以直接沿用。论文的设置是压缩块长 32、步长 16，选择块长 64，切法不同，于是按位置关系把分数折算过去：一个选择块的分数，等于和它在位置上重叠的那些压缩块的分数之和，重叠得越多，加的份量越多。论文用一个双重求和写出这个折算（式 9，要求 \(l\leqslant l'\)，且 \(d\) 能整除 \(l\) 和 \(l'\)）。

GQA 下的组内共享。§2.1 讲过，如果同一 GQA 组里的每个头各选各的块，解码时就要读并集。所以 NSA 强制组内的所有头使用同一套选择：把组内 \(H\) 个头（论文设置下 \(H=16\)）各自的块分数加起来，作为全组共同的分数：

$$\mathbf{p}^{\text{slc}\,\prime}_t=\sum_{h=1}^{H}\mathbf{p}^{\text{slc},(h)}_t$$

取前 n 块。最后按全组分数从高到低排序，保留排名前 \(n\) 的块，把这些块的原始 key 拼接起来（value 同理）：

$$\mathcal{I}_t=\{\,i\mid \operatorname{rank}\big(\mathbf{p}^{\text{slc}\,\prime}_t[i]\big)\leqslant n\,\},\qquad \tilde K^{\text{slc}}_t=\operatorname{Cat}\big[\{\mathbf{k}_{il'+1:(i+1)l'}\mid i\in\mathcal{I}_t\}\big]$$

论文取 \(l'=64\)、\(n=16\)。这 16 块里有 3 块是固定激活的：序列开头的 1 块，以及离当前位置最近的 2 块；真正按分数挑出来的是另外 13 块。选中的 key 一共 \(16\times64=1{,}024\) 个。论文没有解释为什么要固定这 3 块，可以这样理解：固定选中开头块，对应 StreamingLLM 观察到的“注意力汇聚点”（模型习惯把多余的注意力权重放在最开头几个 token 上）；固定选中最近的块，则保证紧挨着当前位置的细节总能被选择分支细看。

先补一点背景：top-n 不可导，那这个分支是怎么“学会”挑块的？

“取分数最高的 16 块”是一个离散的决定：分数稍微变一点，选中的集合要么不变、要么突然换一块，没有平滑的梯度可言。所以梯度确实传不过“选哪几块”这一步。NSA 的巧妙之处在于，它根本不需要让梯度穿过这一步。下面是本站按论文公式梳理的梯度路径：

  • 压缩分支的参数（它的 K、V 投影和 MLP \(\varphi\)）通过压缩分支自己的输出接收语言模型损失的梯度。为了让压缩分支的输出有用，模型必须学会让 \(\mathbf{q}_t\) 对真正相关的段落给出高注意力。这些注意力概率恰好就是选择分支的块分数。于是“打分器”是被语言模型损失间接训练的。
  • 选择分支的参数（它自己的 K、V 投影，以及共用的 query）通过被选中的那 1,024 个 token 接收梯度，学会怎样利用挑出来的细节。
  • 门控接收梯度，学会在不同情况下更依赖哪个分支。

对比 §6.1 里作者试过的两条路：一条是另设一个打分网络，再用辅助损失去监督它（因为选择不可导，打分网络得不到语言模型损失的梯度）；另一条是像 Quest 那样用无参数的启发式打分。NSA 两者都不是：打分来自一个本身就在被主损失训练的分支，不需要额外的损失，也不需要额外的计算。

3.5 第三个分支：最近的 512 个 token（Sliding Window）

为什么还需要一个专门的滑动窗口分支？论文的解释是“捷径学习”。在注意力里，局部模式（紧挨着的几个 token 之间的关系）学得最快，在训练早期就会主导学习过程。如果只有压缩和选择两个分支，模型很可能主要靠它们来处理局部依赖，压缩和选择这两条处理长距离信息的路就学不好。把局部信息单独交给一个窗口大小 \(w=512\) 的分支，压缩和选择分支就能专心学习各自擅长的长距离模式，不会被局部模式“走捷径”抢走梯度。

为了进一步防止分支之间互相走捷径，NSA 给三个分支各配了独立的 key 和 value（各自的投影），额外开销很小。这样三个分支的梯度不会因为共用同一份 K、V 而互相干扰。三路结果最后通过门控融合，构成完整的 NSA。

读的时候容易误解的地方：
  • NSA 减少的是每一步要“读”和“算”的 KV，不是要“存”的 KV。选择分支随时可能挑中历史上的任何一块，所以全部原始 K、V 都得留着；再加上三个分支各有独立的 K、V，压缩分支还要存约 \(t/16\) 个压缩 token。按本站推算，NSA 的 KV 缓存存储量约为同样结构的全注意力的 1.06 倍，再加上窗口的固定开销，并不比全注意力小。论文没有讨论 KV 存储。（后来 DeepSeek-V4 的 CSA 改为直接在存储层面压缩，见文末。）
  • 短序列上 NSA 并不稀疏。当 \(t\leqslant 1{,}024\) 时，16 个 64 token 的块已经覆盖全部历史，选择分支等于细看所有 token。所以在大多数几百到一两千 token 的普通基准上，NSA 实际上是“全注意力 + 压缩分支 + 窗口分支 + 门控”的组合，而不是一个稀疏模型。这一点对理解 §4 的通用基准结果很重要。

3.6 内核设计：按 GQA 组装载 query

算法定下来之后，要让它在 GPU 上真的快。NSA 的内核用 Triton 编写（Triton 是 OpenAI 开源的一种用 Python 写 GPU 内核的语言，按“块”来描述计算，由编译器负责底层优化）。因为 MHA 解码时访存量太大、效率低，论文只针对 GQA 和 MQA 这类共享 KV 的结构设计内核。压缩分支和滑动窗口分支的注意力本质上是普通的稠密注意力（只是 key 少了），可以直接用现成的 FlashAttention-2 内核；真正需要专门设计的是选择分支。

为什么不能照搬 FlashAttention 的切法？FlashAttention 的做法是：每个线程块负责一个头里一段连续位置的 query（比如 64 或 128 个相邻位置），把这块 query 装进 SRAM，然后依次装入 KV 块计算。对稠密注意力这很理想：相邻位置的 query 要看的 KV 几乎相同，一块 KV 装进来能被整块 query 复用。但在选择分支里，每个位置都有自己的一套 16 块。同一块里的 64 个相邻 query 挑中的块往往各不相同，要么把它们的并集都装进来（大部分计算被掩码丢掉），要么就得频繁地装入、换出，访存效率都很差。

NSA 换了一种分组方式。它不按“同一个头的连续位置”分组，而是按“同一个位置、同一个 GQA 组的所有头”分组。这些头恰好共用同一套选中的块（§3.4 的组内共享），于是：

  • 以组为中心装载数据：每次内层循环开始时，装入位置 \(t\) 上这一组所有头的 query，构成一个 \(h\times d_k\) 的小矩阵（论文设置下是 \(16\times192\)），以及它们共用的块索引 \(\mathcal{I}_t\)。
  • 共享地读取 KV：内层循环按 \(\mathcal{I}_t\) 依次把选中的连续 KV 块装进 SRAM，每次一个大小为 \(B_k\times d_k\) 的 K 块和 \(B_k\times d_v\) 的 V 块（\(B_k\) 能整除选择块长 \(l'\)）。每块只读一次，被组内所有头复用。
  • 外层循环交给网格调度：每个位置的内层循环长度都约等于 \(n\) 个块，几乎相同，所以论文把“遍历位置 / 输出”的外层循环直接放进 Triton 的网格（grid）里并行，由 GPU 调度到各个流多处理器（SM）上，负载天然均衡。

论文说，这个设计通过两点达到“接近最优的算术强度”：组内共享消除了重复的 KV 传输；各 SM 之间的计算负载均衡。

示意图：两种 query 分组方式下，一个线程块需要装入多少 KV 块

读的时候容易误解的地方：
  • 这个内核依赖“每组的头足够多”。右图那个小矩阵的行数等于每组的头数。Tensor Core 做矩阵乘法有最小尺寸（Triton 的矩阵乘要求每一维至少 16），论文的模型每组正好 16 个头，刚好满足。如果换成每组只有 4 个头的常见模型（例如 Llama-3-8B 有 32 个 query 头、8 组 KV），就得补零凑到 16 行，四分之三的算力白白浪费。后来的 FSA 正是针对这个问题提出了另一种循环顺序（见文末）。
  • “接近最优的算术强度”要读仔细。它的意思是：在给定的稀疏模式下，没有多读一个不需要的 KV 块。这并不等于这个内核像稠密的 FlashAttention-2 那样被算力限制。按本站推算，右图里每读入一个 key 只被 16 个头使用，每字节数据对应的运算远少于稠密注意力（一个 query 块有 64–128 行），单看这一步更接近带宽受限；相邻位置挑中的块往往大量重叠，重复读取有一部分可能落在 L2 缓存里。论文没有给出内核达到的 TFLOPs 或带宽利用率。
  • 论文只描述了前向内核。反向传播时，许多 query 要把梯度累加到同一个被选中的 KV 块上，写回的冲突和调度都更复杂。论文没有介绍反向内核的做法，§5 测得的反向加速也明显低于前向。

4 实验：同样的数据和训练量，NSA 比全注意力差吗

这一节要回答的问题：NSA 让模型每个位置只看一小部分 KV，代价是不是效果变差？论文的对照办法是：用同一个骨干模型、同样的数据和训练量，分别训练一个全注意力版本和一个 NSA 版本，再从三个角度比较：通用能力、长上下文能力、经过推理数据微调后的数学推理能力。长上下文部分还加入了几种推理期稀疏方法作为对手。读这一节时要一直问：比较的两边是否只差注意力这一处？评测的输入有多长？

4.1 预训练设置：一个 27B 的 MoE 模型

先补一点背景：MoE 骨干与 YaRN。

MoE（混合专家）把前馈层换成很多个“专家”小网络，每个 token 只交给其中少数几个专家处理，所以总参数很大，每个 token 实际用到的参数（激活参数）却很少。本文用的是 DeepSeekMoE 结构：专家切得很细，另有少数几个所有 token 都会经过的“共享专家”。这一结构的来龙去脉见本站 DeepSeek-V3 精读 §2.1.2。

YaRN 是一种扩展 RoPE 位置编码适用长度的方法。RoPE 用不同频率的旋转来表示位置（见本站 RoFormer 精读），模型在 8K 长度上训练后，直接用到 32K 会遇到没见过的旋转角度。YaRN 按频率分段调整这些角度，再配合少量继续训练，就能把上下文窗口扩展开。

实验骨干结合了 GQA 和 MoE，这也是当时先进大模型的常见做法。具体配置如下：

4.2 对照的基线

除了全注意力，长上下文评测还加入了四种推理期稀疏方法，它们都作用在训练好的全注意力模型上：

  • H2O：KV 缓存淘汰，保留重击者和最近的 token（§2.1）。
  • InfLLM：不需要训练的长上下文方法。它保留开头的“汇聚点”token 和局部上下文，把更早的内容切块存起来，从每块里选几个代表 key 来估计这块的重要性，按需取回。
  • Quest：按页记录 key 的最小、最大值，按 query 估计每页的上界分数，只读最高的几页（§2.1）。
  • Exact-Top：先算出完整的注意力分数，再为每个 query 精确地挑出分数最高的 \(n\) 个 key，只在这些位置上做注意力。它不省任何计算，是一个“如果能完美地按 token 挑选会怎样”的参照。

三类评测的对照方式不同。通用评测的大部分样本都短于这些基线的局部窗口，基线和全注意力实际上没有区别，所以只比 NSA 和全注意力。长上下文评测比较所有方法，并把所有稀疏方法的稀疏度设为相同。思维链推理需要在长文本上微调，而推理期稀疏方法不支持训练，所以只比 NSA 和全注意力。

4.6 结果的份量

这一组实验设计得比多数稀疏注意力论文更有说服力：两个模型用同样的骨干、同样的数据和训练量，从头训练，只有注意力不同。但下面几点会影响这些数字的分量。

  • 两个模型并非只差“稀疏”这一处。NSA 多了两套独立的 K、V 投影、压缩用的 MLP 和门控 MLP，论文没有报告两个模型的参数量差别。如果每个分支都有和全注意力同样大小的 K、V 投影，多出来的参数约为 2 亿（推算：\(2560\times1280\times2\) 个分支 × 30 层 ≈ 1.97 亿），约占 30 亿激活参数的 6.6%。所以“NSA 比全注意力好”不能全部归功于稀疏。
  • 通用基准上的比较几乎不涉及稀疏。如 §4.3 所说，这些输入短到 NSA 的选择分支能覆盖全部历史。它们说明的是“换成 NSA 的结构没有伤害短文本能力”，而不是“稀疏让模型更聪明”。
  • 每个结果只有一次运行。论文没有给出多次训练或多次评测的方差。通用基准上不少差距只有千分之几到百分之一左右（比如 MATH 0.263 对 0.264、MMLU 0.567 对 0.565），落在一般评测噪声的范围里。
  • LongBench 的对照有两种性质。和 H2O、InfLLM、Quest、Exact-Top 的比较，是“同一个全注意力模型，推理时换不同的稀疏方法”，激活的 token 数对齐在 2,560；而和全注意力的比较，是两个分别训练出来的模型之间的比较。另外，子集是在看过所有模型的分数之后才剔除的。
  • 大海捞针只展示了 NSA。论文没有给出全注意力模型的大海捞针结果；单根针的检索也是相对容易的长上下文测试。还要注意模型只微调到 32K，64K 已经超出训练长度。
  • AIME 的样本很小、分数很低。30 道题、两种上限、各一个模型，差距相当于平均多做对 1–2 道。生成长度又被截断在 8K 和 16K，比训练时的 32K 短得多。附录的例子里 NSA-R 的思考过程短得多（2,275 对 9,392 个 token），如果这是普遍现象，那么 8K 上限下的优势有一部分可能来自 NSA-R 的推理更短、更容易在截断前给出答案，而不完全是推理能力更强。附录的两道题是挑选出来的展示，不能当作统计证据。
  • 规模有限。27B（激活 3B）、270B token 的训练量，比当时一线模型小一到两个数量级。这篇论文本身没有更大规模的证据；后来 DeepSeek 在 671B 的 V3.2 上用的是另一套机制（DSA，见文末）。

5 效率分析：训练和解码分别快了多少

这一节要回答的问题：NSA 少看了很多 KV，这些省下来的计算和访存，在 GPU 上变成了多少实际的速度？训练时（前向、反向）和解码时的加速比分别是多少，随长度怎样变化？这些数字是怎么得到的，哪些是测出来的，哪些是算出来的？

效率测试在一台 8 卡 A100 的机器上进行。模型配置和 §4 相同：GQA 4 组、每组 16 个头，query / key 维度 192、value 维度 128；NSA 的超参数也相同（\(l=32\)、\(d=16\)、\(l'=64\)、\(n=16\)、\(w=512\)）。

5.1 训练速度：注意力内核的前向和反向

为了在同一个后端上公平比较，作者把 Triton 实现的 NSA 注意力，和 Triton 实现的 FlashAttention-2（代表全注意力）放在一起比。原文图 6 是两张柱状图，分别画前向和反向的耗时（毫秒），横轴是 8K、16K、32K、64K 四种上下文长度；NSA 的柱子由“稀疏选择内核”和“压缩与滑动窗口注意力”两部分叠成，柱子上标着相对 FlashAttention-2 的加速比：

上下文长度8K16K32K64K
前向加速（实测）2.1×3.8×6.3×9.0×
反向加速（实测）1.1×2.0×3.4×6.0×
注意力计算量之比（推算）2.3×4.0×6.4×9.1×

前两行来自原文图 6。论文把加速归功于两点：按块访存让读取是合并的连续读，用满了 Tensor Core；内核里精心安排的循环顺序消除了重复的 KV 传输。加速比随长度增长，因为全注意力的计算量按平方涨，NSA 的选择和窗口两部分却是固定的。

第三行是本站推算的理论上限，用来判断实测数字离理想有多远。全注意力里，长度为 \(N\) 的序列约有 \(N^2/2\) 对 (query, key)。NSA 里，位置 \(t\) 的 query 大约要看 \(t/16\) 个压缩 token、1,024 个选中 token 和 512 个窗口 token，对所有位置求和约为 \(N^2/32+1536N\)。两者相除：

$$\frac{N^2/2}{N^2/32+1536\,N}=\frac{16N}{N+49152}$$

代入四个长度，得到 2.3、4.0、6.4、9.1。前向的实测值（2.1、3.8、6.3、9.0）几乎贴着这个理论值，说明 NSA 的前向内核把省下的计算基本都兑现了。反向的实测值低得多，64K 时只有 6.0 倍，论文没有解释原因（§3.6 提到论文没有描述反向内核）。

这个公式还揭示了一个论文没有明说的性质：NSA 的计算量仍然是 \(O(N^2)\)，只是常数小了 16 倍，因为压缩分支的 key 数随位置线性增长。长度趋于无穷时，加速比的上限是 16 倍（对应步长 \(d=16\)）。比如到 100 万 token，理论比值约 15.3 倍（推算）。

5.2 解码速度：每一步要读多少 KV

解码时注意力的速度主要由读显存决定，也就是每一步要加载多少 KV 缓存。设已缓存的序列长度为 \(s\)，NSA 每一步最多只需读取约 \((s-l)/d\) 个压缩 token、\(nl'=1{,}024\) 个选中 token 和 \(w=512\) 个窗口 token。原文表 4 列出了“等效 token 数”的访存量：

上下文长度8,19216,38432,76865,536
全注意力（要读的 token）8,19216,38432,76865,536
NSA（要读的 token）2,0482,5603,5845,632
预期加速4×6.4×9.1×11.6×

本站核对过，表中 NSA 一行恰好等于 \(s/16+1{,}024+512\)：比如 64K 时是 4,096 + 1,024 + 512 = 5,632。预期加速就是两行之比。论文的理由是：解码的算术强度低、受带宽限制，所以耗时近似和访存量成正比。同样的推算可以写成 \(16s/(s+24576)\)，它的上限也是 16 倍；到 128K 约 13.5 倍，到 100 万 token 约 15.6 倍（推算）。

5.3 结果的份量：这些速度数字测的是什么

  • 只测了注意力内核，没有端到端的数字。9.0 倍和 6.0 倍是注意力这一个算子的耗时之比，不是整个模型训练一步的提速，也不是推理服务的吞吐或延迟。论文没有报告端到端的训练吞吐、MFU，也没有报告端到端的解码延迟。
  • 解码的 11.6 倍不是测出来的。它是按每一步读多少 KV 推出的预期值，前提是“解码耗时和访存量成正比”。真实的解码还要读模型参数、做 top-n 选择、跑门控和压缩 MLP，这些都会摊薄加速。原文图 1 把这个预期值和两个实测值并排画，正文里也写成“实现了最多 11.6 倍的加速”，读者很容易以为它是实测。
  • 基线是 Triton 版的 FlashAttention-2，硬件是 A100。作者选 Triton 版是为了“同一个后端”公平比较，NSA 自己也是 Triton 写的。论文没有和更常用的 CUDA 版 FlashAttention-2 比较，也没有交代 Triton 版和它的速度差距。DeepSeek 自己训练模型用的是 H800（Hopper 架构），在 Hopper 上全注意力的强基线是 FlashAttention-3（见 FA3 精读），论文没有给出 Hopper 上的数字。批大小、序列条数等测试参数也没有给出。
  • NSA 那根柱子包含什么，交代得不完全。按图例，NSA 的耗时包含选择分支内核和压缩、窗口两部分注意力；压缩用的 MLP、块分数的换算与 top-n 排序、门控是否计入，论文没有说明。
  • “降低预训练计算”在本文的设置下收益有限。论文的预训练是在 8K 长度上做的。按原文图 6，8K 时注意力前向只快 2.1 倍、反向只快 1.1 倍；按 §1 的推算，8K 时注意力只占前向计算的约 46%。所以这次预训练实际省下的计算并不多，NSA 训练端的优势要在更长的序列上才明显。论文没有给出预训练总耗时的对比。
  • 速度与质量是同一套超参数下的。效率测试和 §4 的质量评测用的是同一组 NSA 超参数和同一个模型结构，这一点是对齐的。但质量最突出的长上下文结果是在 32K 以内（LongBench）和 64K（大海捞针），而最大的速度数字在 64K，两者对应的长度不完全一致。

6 讨论：走过的弯路，和“注意力是成块的”这个观察

这一节要回答的问题：在设计出 NSA 之前，作者试过把已有的稀疏方法改造成可训练的版本，它们为什么失败了？“按连续块选择”这个设计又是从哪里得到的启发？这一节回顾了开发过程，说明了 NSA 的几个关键选择是被哪些失败逼出来的。

6.1 其他选择策略遇到的困难

基于 key 聚类的方法（如 ClusterKV）把同一类的 key 和 value 放在连续的显存区域里，理论上既能训练也能推理，但有三个实际困难。第一，动态聚类本身的计算开销不小。第二，各个簇的大小不均衡，算子很难优化；在 MoE 系统里，专家并行（EP）各组的执行时间本来就可能不均，再叠加上簇的不均衡，会造成持续的负载失衡。第三，实现上要求定期重新聚类，训练也得按块顺序进行，限制很多。

其他按块选择的方法（如 Quest、InfLLM）为每个 KV 块计算一个重要性分数，按和 \(\mathbf{q}_t\) 的相似度选出前 \(n\) 块。作者指出两种常见的打分方式各有问题：

  • 用神经网络打分，靠辅助损失训练。因为选择不可导，打分网络从语言模型损失那里拿不到梯度，只能另设一个辅助损失来监督它。这增加了算子开销，往往还会降低模型效果。作者实现了一个版本：为每个 token 增加额外的 query，为每个块增加代表 key，用它们估计块的重要性；监督信号是把真实注意力分数在每个 key 块内做平均池化得到的块级分布，用 KL 散度让打分去拟合它。为了照顾解码效率，query 保持逐 token 的粒度，而不是按块平均。论文说这个思路和 SeerAttention 类似。
  • 用无参数的启发式打分。照 Quest 的办法，直接用 query 和每块 key 逐维度的最小、最大值相乘来估计分数，不引入任何参数。问题是召回率低：真正重要的块经常没被选上。作者还试了“冷启动”：前 1,000 步先用全注意力，之后再切换到启发式选块。

作者在一个结构相似的 3B 模型上比较了这两种方法、NSA 和全注意力的训练损失（原文图 7，约 3 万步）。两种替代方法的损失都比 NSA 高；图中 NSA 的曲线也低于全注意力。见 原文 §6.1 与图 7 ↗。

示意图：给块打分的几种办法，以及它们怎么得到训练信号

6.2 可视化：注意力分数是成块出现的

为了寻找设计灵感，作者把预训练好的 27B 全注意力模型的注意力图画了出来（原文图 8）。图的纵轴是 query 位置（0 到约 256），横轴是 key / value 位置（0 到约 1,024），颜色越亮表示注意力分数越高（色标从 −3 到 −1，看起来是对数刻度）。图上可以看到，高分区域往往成片地聚在一起：相邻的 key 常常有相近的注意力分数，形成竖条或小块。这说明在序列中相邻的 token 可能和 query 有某种共同的语义关系，具体是什么关系，作者说还需要进一步研究。正是这个观察让作者决定按连续的 token 块而不是单个 token 来选择，既提高计算效率，又能保住高注意力的区域。见 原文图 8 ↗。

7 相关工作与结论

这一节要回答的问题：NSA 在稀疏注意力的谱系里处于什么位置？和已有的三类方法相比，它的差别到底在哪里？论文最后承认了哪些局限？

论文把已有的稀疏注意力分成三类。

  • 固定的稀疏模式。最常见的是滑动窗口，每个 query 只看固定窗口内的 token。StreamingLLM 把开头的“注意力汇聚点”和局部窗口结合起来处理连续的文本流；MoA、DuoAttention 也利用了类似的局部加汇聚点信息；更早的 Longformer 把局部窗口注意力和少数全局 token 交替使用。和它们相比，NSA 不依赖预先规定的模式，而是让模型自己学会看哪里，因此有可能利用到完整的上下文。
  • 动态的 token 剪枝。H2O、BUZZ、SepLLM 在解码时自适应地淘汰被认为不重要的 token，减少 KV 缓存；FastGen、HeadKV 给不同的注意力头分配不同的策略；SnapKV 在预填充时根据注意力权重选出关键的 KV 保留下来。它们都只在推理时起作用，NSA 则在训练阶段就原生地引入稀疏。
  • 按 query 选择。Quest 用 query 与每块 key 的逐维最小、最大值估计块的重要性；InfLLM 结合固定模式和检索，保留汇聚点、局部上下文和可检索的块；HashAttention 把找关键 token 看成推荐问题，用学到的函数把 query 和 key 映射到汉明空间；ClusterKV 先对 key 聚类，再按 query 和簇的相似度挑簇；MInference 和 TokenSelect 按 token 级的重要性挑选 KV；SeerAttention 把 query 和 key 切成空间块，做块级选择。NSA 的不同在于，它在模型的整个生命周期（训练、预填充、解码）里都实现了与硬件对齐的稀疏计算。

结论。NSA 是一种与硬件对齐的稀疏注意力结构：在一个可训练的结构里，把分层的 token 压缩和按块的 token 选择结合起来，在保持全注意力水平的同时加速训练和推理。论文报告它在通用基准上和全注意力相当，在长上下文评测上更强，推理能力也有提升，同时注意力计算的延迟明显下降。

局限。ACL 正式版增加了一段局限说明：本文只考虑了单层注意力图内部的稀疏，跨层的稀疏留待以后研究；Triton 实现相对原生 CUDA 内核有一些抽象开销，还有进一步做硬件优化的空间。

同期工作：Kimi 的 MoBA

NSA 首版发布两天后（2025-02-18），月之暗面（Moonshot AI）发布了 MoBA（Mixture of Block Attention），思路相近但更简单。它把 MoE 的路由思想用到注意力上：把上下文切成块，每个 query 用自己和每块 key 的平均值做内积，选出分数最高的 k 块，当前所在的块总是被选中；打分没有任何可学习参数。MoBA 强调可以在全注意力和稀疏注意力之间无缝切换，实践中还让最后几层保持全注意力；它在实现上复用 FlashAttention 的变长内核，论文报告 100 万 token 时预填充的注意力最多快 6.5 倍，并称已用于支持 Kimi 的长上下文请求。和 NSA 相比，MoBA 没有压缩分支的输出（块的平均 key 只用来打分）、没有独立的滑动窗口分支，也没有按 GQA 组共享选择的专门设计。

DeepSeek Sparse Attention（V3.2）：从块选择到 token 选择

2025 年 9 月，DeepSeek 发布 V3.2-Exp，同年 12 月发布 DeepSeek-V3.2 的技术报告。和前一版 V3.1-Terminus 相比，V3.2 唯一的结构改动是引入 DeepSeek Sparse Attention（DSA）。DSA 由两部分组成：一个“闪电索引器”，用少量的头、ReLU 激活、FP8 精度给当前 query 和每个历史 token 打分；以及一个细粒度的 token 选择机制，每个 query 只取分数最高的 2,048 个 KV 条目做注意力。这样主注意力的复杂度从 \(O(L^2)\) 降到 \(O(Lk)\)，索引器本身仍是 \(O(L^2)\)，但计算量小得多。

和 NSA 的关系可以从三处看：

  • 继承：选择必须被多个 query 头共享。V3.2 报告在说明为什么基于 MLA 的“MQA 模式”实现 DSA 时，直接引用了 NSA：在内核层面，每个 KV 条目必须被多个 query 共享，计算才高效。在 MLA 的 MQA 模式下，一个潜向量同时是所有头的 key 和 value，所以选一次、所有头共用，这正是 NSA“组内共享选择”的极端形式。
  • 改变一：按 token 选，而不是按块选。NSA 为了让访存连续而按 64 个 token 成块选择；DSA 回到逐 token 选择，靠专门写的稀疏注意力内核（FlashMLA 在 2025-09-29 开源了 token 级稀疏内核）和高效的 top-k 内核来弥补访存的不连续。
  • 改变二：从已训练好的模型继续训练，打分器用蒸馏训练。NSA 从预训练开始就稀疏，打分复用压缩分支。DSA 从 V3.1-Terminus 的检查点出发：先冻结主模型、保持稠密注意力，只训练索引器 1,000 步（每步 16 条 128K 序列，共 2.1B token），用 KL 散度让索引器的分布去拟合主注意力在各头上求和后的分布；再打开稀疏选择，训练全部参数 15,000 步（每步 480 条 128K 序列，共 943.7B token）。索引器的输入与主模型的计算图断开，只受 KL 损失训练，主模型只受语言模型损失训练。这正是 NSA §6.1 里试过并认为不如 NSA 的“辅助损失”路线，只是场景换成了“改造一个已训练好的 671B 模型”，而 V3.2 报告称效果与 V3.1-Terminus 持平。

这条路线的细节、伪代码和简答题，见本站DSA 结构拆解页。

DeepSeek-V4：压缩 + 选择 + 滑动窗口的再组合

2026 年 4 月的 DeepSeek-V4 采用了混合注意力：CSA（Compressed Sparse Attention）先把每 \(m\) 个 token 的 KV 压成一个条目（V4-Flash 与 V4-Pro 都取 \(m=4\)，相邻条目有重叠），再在压缩条目上做 DSA 式的稀疏选择；HCA（Heavily Compressed Attention）用大得多的压缩率（128）压缩、不做稀疏选择；两者交替使用，并且每层都另配一个小的滑动窗口分支补回最近 token 的细节。压缩、按分数选择、滑动窗口，这三种成分和 NSA 的三个分支如出一辙，但组合方式不同：V4 是在存储层面压缩，KV 缓存本身变短了，这弥补了 NSA 和 DSA“只减少读取、不减少存储”的不足。V4 报告称在 100 万 token 上下文下，V4-Pro 的单 token 推理 FLOPs 只有 V3.2 的 27%，KV 缓存只有 10%。需要说明的是，本站检索 V4 报告全文没有找到对 NSA 的引用，“如出一辙”是本站的解读。V4 的完整拆解见DeepSeek-V4 拆解页。

其他跟进

  • DSA 被其他模型采用。GLM-5（2026-02）在摘要中写明采用 DSA 来降低训练和推理成本、同时保持长上下文能力。DeepSeek 在 2026 年 9 月开源的 DeepSelect（DSA 用的 top-k 内核）说明，DSA 用在了 V3.2、V4 和 V4.1 上。
  • 对 NSA 的批评与改进：InfLLM-V2。MiniCPM 团队的 InfLLM-V2（2025-09）认为，NSA 引入了过多额外参数（三套 K、V、压缩 MLP、门控），并且打破了“先在短文本上预训练、再在长文本上微调”的常规流程，导致收敛慢、难以加速。它的做法是不加参数、复用稠密注意力的参数，短输入时用稠密注意力，长输入时平滑切换到稀疏；论文报告比稠密注意力快 4 倍，在长上下文理解和思维链推理上分别保留 98.1% 和 99.7% 的效果。MiniCPM4 与 MiniCPM4.1 用的就是这套机制。
  • 内核层面的改进：FSA。FSA（Flash Sparse Attention）（2025-08）指出，NSA 的内核强制了一种只有在每个 GQA 组的 query 头较多时才高效的循环顺序（§3.6 的注意事项），而主流模型每组的头数要少得多。FSA 换了一种循环顺序，报告内核延迟最多降低 3.5 倍（平均 1.6 倍），端到端训练最多快 1.25 倍（平均 1.09 倍），预填充最多快 1.36 倍（平均 1.11 倍）。

回头看，NSA 留下的最持久的东西，可能不是三个分支这个具体结构，而是两条原则：稀疏的选择必须和 KV 的共享方式（GQA / MQA / MLA）对齐，否则访存省不下来；以及稀疏要在训练中出现，模型才能真正适应它。DSA、CSA 都保留了这两条，而在“按块还是按 token”“从头训练还是继续训练”“只减读取还是连存储也压缩”这些问题上做了不同的选择。
