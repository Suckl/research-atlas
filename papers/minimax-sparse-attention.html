0 导读：这篇论文解决什么问题

大模型正在从“一问一答”变成长时间干活的智能体：读整个代码仓库、连续调用几百次工具、把几十万 token 的历史记在上下文里。标准的 softmax 注意力让每个新 token 都要和前面所有 token 打一次分，预填充的计算量随长度按平方增长，解码时每一步都要把整份 KV 缓存从显存里读一遍。到了 100 万 token，这两笔开销都成了部署时的主要成本。

MiniMax 在这个问题上走过一段弯路。2025 年初的 MiniMax-01 和年中的 M1 用的是“线性注意力 + 少量 softmax 注意力”的混合结构；但到 2025 年 10 月的 M2，他们又退回了标准的全注意力，理由是混合结构在大规模下的多步推理上有明显短板，而且配套的推理基础设施不成熟。这篇论文是他们给出的新答案：不替换 softmax 注意力，而是让它只看一小部分 KV，也就是稀疏注意力。

论文提出的 MSA（MiniMax Sparse Attention）建在 GQA 之上，结构刻意做得很简单。每一层多出一个很轻的索引分支：它给每 128 个连续 token 组成的 KV 块打一个分，每个 GQA 组各自挑出得分最高的 16 块（当前所在的块必选）。然后主分支只在这 16 块、最多 2,048 个 token 上做普通的、精确的 softmax 注意力。索引分支不能靠语言模型损失直接学（挑前 k 个这个操作没有梯度），作者用一个 KL 损失让它去模仿主分支的注意力分布，并配上“截断梯度”和“先用全注意力预热”两个稳定训练的手段。为了让省下的计算真正变成速度，他们还专门写了 GPU 内核：选前 k 个时不算指数，做注意力时把循环顺序反过来，“让 KV 块去找选了它的 query”。

实验在一个总参数 109B、每 token 激活 6B 的多模态 MoE 模型上进行，共训练 3T token。从头用 MSA 训练（MSA-PT）和从全注意力检查点转过来继续训练（MSA-CPT）两条路线，在文本、代码、图像、视频和长上下文检索的基准上都和全注意力基线相当。在 100 万 token 的上下文上，MSA 每个 token 的注意力计算量是 GQA 的 1/28.4；在 H800 上，单个注意力算子的预填充快 14.2 倍、解码快 7.6 倍。这套机制后来用在了 MiniMax-M3（总参数约 428B）上。

1 引言：MiniMax 为什么从线性注意力走到稀疏注意力

这一节要回答的问题：长上下文的智能体任务让 softmax 注意力的平方代价变得难以承受，业界有两条降低代价的路：把一部分注意力层换成更便宜的结构（线性注意力、滑动窗口），或者保留 softmax 注意力、让它只看一部分 token。MiniMax 两条路都走过。这一节先讲清楚这两条路各自省在哪里、丢掉了什么，再看论文为什么选第二条，以及它给自己定下的设计原则。
先补一点背景：长上下文下，注意力在两个阶段分别贵在哪里。

注意力可以想成一次查资料：每个 token 算出一个 query（我想找什么）、一个 key（我这里有什么的标签）和一个 value（我携带的内容）。处理第 \(t\) 个 token 时，用它的 query 和前面所有 token 的 key 逐个求点积，经过 softmax 变成权重，再按权重把前面 token 的 value 加起来。（更细的讲解见本站 vLLM 精读 §2.1。）

预填充（以及训练）贵在计算。这两个阶段一次处理整段序列，长度为 \(N\) 的序列约有 \(N^2/2\) 对 (query, key) 要算。长度翻倍，注意力的计算量变成 4 倍，而线性层和 MoE 专家的计算量只变成 2 倍，所以越长，注意力占的比例越大。

解码贵在读显存。逐个生成时每一步只算一个新 token，但它要和前面所有 token 做注意力，这些 token 的 key、value 早已算好存在显存里（KV 缓存），每一步都要整份读一遍。读得多、算得少，速度由显存带宽决定。

本站的 NSA 精读 §1 用一个 27B 模型的配置把这两笔账算过一遍：64K 长度时，前向计算里注意力已经占约 87%。到了本文关心的 1M 长度，这个比例只会更高。

先补一点背景：线性注意力和 MiniMax 的“闪电注意力”。

softmax 注意力之所以贵，是因为每个 query 都要和所有 key 单独算一次相似度。线性注意力把相似度 \(\exp(q^{\top} k)\) 换成两个特征向量的内积 \(\phi(q)^{\top}\phi(k)\)。这样一换，求和的顺序就可以调过来：先把前面所有 token 累加成一个固定大小的“状态矩阵” \(S_t=\sum_{i\le t}\phi(k_i)v_i^{\top}\)，每来一个新 token 只需更新一次 \(S_t\)，再用 \(\phi(q_t)^{\top} S_t\) 得到输出。每个 token 的代价不再随长度增长，解码时也不用读一份越来越长的 KV 缓存。

代价是：不管上下文多长，所有历史都被压进同一个大小固定的矩阵里。打个比方，全注意力像一本可以随时翻回任何一页的笔记本，线性注意力像一张固定大小的便签，新内容只能叠写在旧内容上。需要“精确找回很久以前的某句话”时，便签就不够用了。所以实际的模型通常把线性注意力层和少量 softmax 层混着用。

MiniMax-01（2025-01）是这类混合结构里规模最大的开源模型之一：总参数 456B、每 token 激活 45.9B，每 7 层“闪电注意力”（Lightning Attention，MiniMax 对线性注意力的一种按块计算、注意 I/O 的高效实现）之后接 1 层 softmax 注意力，共 80 层；训练长度可达 1M token，推理时可外推到 4M。2025 年 6 月的 MiniMax-M1 在同一底座上做大规模强化学习，原生支持 1M 上下文。同一路线的其他工作，见本站 Gated DeltaNet 精读（Qwen3-Next / Qwen3.5 的 3:1 混合）和 Kimi Linear 精读。

为什么 M2 要退回全注意力？MiniMax 在 2025-10-29 发表了一篇说明（署名为 M2 预训练负责人 Haohai Sun，他也是本文作者之一）。要点可以归纳成三条。第一，评测会骗人：在当时常用的基准上，闪电注意力混合模型和全注意力打平，但模型放大以后，混合模型在复杂的多步推理任务上出现了明显短板，而要在这类难任务上得到统计上可靠的结论，实验成本高得惊人。第二，基础设施不成熟：很多线性注意力结构在训练时就受显存带宽限制，算力用不满；它们对数值精度比全注意力敏感得多，不方便用低精度存状态；推理服务里非常重要的前缀缓存和投机解码，在线性注意力上还没有成熟的方案。第三，他们也试过滑动窗口混合，发现上下文越长效果掉得越明显，并且猜测“检索头”“归纳头”这类全局注意力模式在预训练早期就成形了，事后靠继续训练很难改过来。

论文的引言把这段历史放在一个更大的背景里。为了在质量和效率之间找到更好的平衡，业界大致有两条路。一条是混合结构：把一部分 softmax 层换成线性注意力（Kimi Linear、Gated DeltaNet、Mamba 等）或滑动窗口注意力（gpt-oss、MiMo-V2-Flash 等）。另一条是把 softmax 注意力本身稀疏化：DeepSeek 的 DSA（V3.2）、V4，MiniCPM4 用的 InfLLM-v2，Kimi 的 MoBA 都属于这一类。

MSA 选择了第二条路，并给出两个理由。其一，稀疏化之后注意力仍然是精确的 softmax 注意力，只是范围变小了，所以 KV 缓存的格式、分页管理、前缀缓存、FlashAttention 一类的内核写法，都能最大限度地沿用现有的软硬件基础设施，这正好对上了 M2 说明里列出的基础设施顾虑。其二，KV 缓存完整保留，任何一个历史 token 都“有机会被选中”，不像线性注意力那样从结构上丢掉了信息。

作者把设计原则称为“奥卡姆剃刀”：做了大量消融之后，只保留必不可少的部件。具体有三处取舍。第一，按块选、并用较小的 top-k：块大（128 个 token）、块数少（16 块），让内核在更多种类的 GPU 上都能高效运行，也放宽了以往设计对注意力头维度的限制。第二，每个注意力组各自挑块：用块内最大分数（max-pooling）给块打分。第三，当前块总是保留：最近的那一块无论分数如何都被选中，用来保证训练稳定。

要把“少算”变成“真的快”，算法必须和 GPU 上的执行方式一起设计。作者为此做了三件事：一个专门针对小 k 的 top-k 内核，利用块级打分直接跳过 softmax；一个“KV 在外层”的稀疏注意力内核，让被选中的 KV 块收集选了它的 query、拼满 Tensor Core 的矩阵乘，并用预先排好的分块和两阶段合并，在不用原子操作的前提下处理“有的块被极多 query 选中”的倾斜；训练时，把 KL 损失需要的辅助量顺手在前向里算好，反向用持久化的负载均衡。

论文列出的贡献有三条：提出 MSA，既能从头训练，也能把已训练好的 GQA 检查点近乎无损地转换过来；设计配套的训练和推理内核，把理论上的计算节省变成实际的墙钟加速；在最大 109B 参数、原生多模态训练的 MoE 模型上做了大量消融，分析 MSA 在不同规模和模态下的表现。

读的时候容易误解的地方：
  • “稀疏”指的是每个 query 只看一部分 key，不是把权重剪稀疏，也不是把 KV 缓存删掉一部分。MSA 的 KV 缓存一个不少，还要多存一份索引用的 key（§5 会算这笔账）。所以它省的是计算和每步的读取量，不省 KV 缓存的容量。
  • 引言里说的 14.2× 和 7.6× 是“1M 上下文时单个注意力算子的耗时之比”，不是整个模型的推理吞吐。整模型还有线性层、MoE 专家、通信等开销，那部分 MSA 没有改变。
  • M2 说明里的反思针对的是线性注意力和滑动窗口混合；它并没有说稀疏注意力已经被证明可行。本文才是 MiniMax 关于稀疏注意力的正式论证，证据的分量要看 §7。

2 预备知识：GQA，以及把稀疏注意力拆成“挑”和“算”两步

这一节要回答的问题：MSA 是建在 GQA 上的，GQA 是什么，它的“组”为什么天然适合当作共享选择结果的单位？任何稀疏注意力都可以拆成“先挑出要看的 key，再在这些 key 上做注意力”两步，那么“挑”的粒度应该多细：每个头各挑各的 token，还是一整组头共用、按块来挑？这一节给后面所有设计准备概念和记号。

2.1 因果注意力与 GQA

记号如下：序列长度 \(N\)，隐藏维度 \(d_{\text{model}}\)，每个注意力头的维度 \(d_h\)。对位置 \(t\)、第 \(h\) 个头，因果 softmax 注意力是：

$$o_t^{(h)}=\sum_{i\le t}\alpha_{t,i}^{(h)}\,v_i^{(h)},\qquad \alpha_{t,i}^{(h)}=\frac{\exp\big(\langle q_t^{(h)},k_i^{(h)}\rangle/\sqrt{d_h}\big)}{\sum_{j\le t}\exp\big(\langle q_t^{(h)},k_j^{(h)}\rangle/\sqrt{d_h}\big)}$$

“因果”指位置 \(t\) 只能看 \(i\le t\) 的 token，不能偷看后面。论文把它的计算量写成 \(\Theta(2H_qN^2d_h)\)，\(H_q\) 是 query 头的个数，随 \(N\) 按平方增长。

先补一点背景：MHA、MQA 与 GQA。

最早的多头注意力（MHA）里，每个 query 头都有自己的一套 key 头和 value 头。KV 缓存要存所有头的 key、value，很占显存，解码时每步也要读这么多。MQA 走到另一个极端：所有 query 头共用一个 key 头和一个 value 头，KV 缓存缩小到 \(1/H_q\)，但效果有损失。GQA（Grouped-Query Attention）取中间：把 \(H_q\) 个 query 头分成 \(H_{kv}\) 组，每组的 \(G=H_q/H_{kv}\) 个 query 头共用一个 key 头和一个 value 头。一个 KV 头就定义了一个 GQA 组。

本文实验模型的配置是 \(H_q=64\)、\(H_{kv}=4\)、\(d_h=128\)，所以一共 4 个组，每组 \(G=16\) 个 query 头。每个 token 在每一层要缓存 \(2\times4\times128=1{,}024\) 个数（key 和 value 各 512 个），按 BF16 每个数 2 字节就是 2 KiB（推算）。

GQA 对稀疏注意力有一个天然的好处：同一组的 16 个 query 头读的是同一份 key 和 value。如果这 16 个头约定“看同一批 key”，那么这批 key、value 从显存里读一次，就能供 16 个头一起用；如果它们各看各的，同一份 KV 缓存就得按 16 种不同的方式去零散地读。这就是 MSA 把选择结果在组内共享的原因。

2.2 稀疏注意力是两步：挑，然后算

论文把一层稀疏注意力统一写成两个阶段。对位置 \(i\)：

$$\mathcal{I}_i=\mathrm{Index}_{\phi}\big(q_i,K_{\le i}\big),\qquad o_i=\mathrm{Attn}\big(q_i,K[\mathcal{I}_i],V[\mathcal{I}_i]\big)$$

第一步由一个索引器 \(\mathrm{Index}_{\phi}\) 决定要看哪些 key，结果是位置集合 \(\mathcal{I}_i\subseteq\{1,\dots,i\}\)。索引器可以没有参数（比如固定规则“只看最近 512 个”），也可以有要学习的参数 \(\phi\)。第二步就是普通的缩放点积 softmax 注意力，只是限制在 \(\mathcal{I}_i\) 里。论文把第一步叫索引分支（Index Branch），第二步叫主分支（Main Branch）。在多头注意力里，每个 (位置, 头) 原则上都可以有自己的 \(\mathcal{I}_i^{(h)}\)，公式里只是为了简洁省掉了头的下标。

2.3 挑的粒度：按 token 还是按块，每个头各挑还是整组共用

最细的选法是每个头各自按 token 挑。它最灵活，但很难映射成 GPU 擅长的矩阵运算：每个头要从显存的不同位置零散地取 key，凑不成规整的数据块，Tensor Core（GPU 上专做小矩阵乘法的硬件单元，要求输入是成块的矩阵）也就用不满。为了效率，基于 GQA 的稀疏注意力可以让同一组的头共用一个选择结果：

$$\mathcal{I}_i^{(r)}=\mathcal{I}_i^{(h)}=\mathcal{I}_i^{(h')},\qquad h,h'\in\mathcal{H}_r$$

这里 \(\mathcal{H}_r\) 是第 \(r\) 个 KV 头服务的那 \(G\) 个 query 头。再进一步，按块挑而不是按 token 挑，能减少“路由”的开销，让访存更规整。设块大小为 \(B_k\)，把序列切成 \(B=\lceil N/B_k\rceil\) 块：

$$\mathcal{B}_b=\{(b-1)B_k+1,\dots,\min(bB_k,N)\},\qquad b=1,\dots,B$$

此时 \(\mathcal{I}_i^{(r)}\subseteq\{1,\dots,B\}\) 是选中的块号集合。组 \(r\) 里任何一个 query 头的输出，都只在选中块里因果可见的 token 上计算，用的是这个组自己的 KV 头。MSA 采用的就是这种“GQA 组内共享 + 按块选”的形式。

示意图：三种选择粒度，读 KV 的方式完全不同（16 个历史 token、4 个 query 头、两组）
怎么看：每一行是一个 query 头眼里的 16 个历史 token，涂色的是它要参与计算的 token。①里四个头各挑各的，每个头都要单独去显存里零散地取数据。②是 DeepSeek DSA 的做法：DSA 建在 MLA 的“MQA 模式”上，所有头共用一份潜在 KV，于是所有头共用一份 token 级的选择，读一次就够，但读的是散落各处的单个 token。③是 MSA：虚线把 token 切成 4 块（真实块大小是 128），同一组的头共用一个选择，不同组各挑各的，读的是整块连续的内存。块越大，访存越规整，但每块里和 query 不相关的 token 也要白算。本站示意图。
容易混淆的一点：“组内共享”和“按块选择”是两个独立的维度。NSA 也是组内共享、按块选（块长 64）；DSA 是全部头共享、按 token 选；MoBA 是按块选（块很大），没有专门的打分参数。MSA 自称的区别在于“两件事同时做，并且各组独立选”：同一层的 4 个组各自挑 16 块，彼此不必相同。§8 有一张对照表。

3 MSA 的结构：一个很轻的索引分支，加一个只看选中块的主分支

这一节要回答的问题：MSA 具体怎么给块打分、怎么挑块、挑完之后主分支怎么算？它比标准 GQA 多了哪些参数，多了多少？一个 query 在 1M 长的上下文里最终会看多少 token？这一节对应论文 §3.1，§3.2 的训练方法放到下一节。

MSA 在一个标准 GQA 层上只加了两个投影矩阵，组成索引分支；主分支就是原来的 GQA 注意力，只是范围变了。对每个 query token，索引分支为每个 GQA 组挑出 \(k\) 个大小为 \(B_k\) 的 key 块，主分支只在这些块里的 token 上做注意力，所以每个 query 最多看 \(kB_k\) 个 token。论文的设置是 \(B_k=128\)、\(k=16\)，预算为 2,048 个 token。

3.1 索引分支：每组一个索引 query 头，全层共用一个索引 key 头

索引分支给每个 GQA 组配一个索引 query 头，再配一个所有组共用的索引 key 头：

$$Q^{\text{idx}}=XW_q^{\text{idx}}\in\mathbb{R}^{N\times H_{kv}\times d_{\text{idx}}},\qquad K^{\text{idx}}=XW_k^{\text{idx}}\in\mathbb{R}^{N\times 1\times d_{\text{idx}}}$$

这里 \(X\) 是这一层的输入隐藏状态，\(d_{\text{idx}}\) 是索引头的维度。原文图 1 还画出，索引 query 和索引 key 在打分前也像主分支一样做归一化和 RoPE 位置编码。论文正文没有写 \(d_{\text{idx}}\) 的值；MiniMax-M3 公开的 config.json 里是 128，本站用这个值代入论文式 12，能精确复现原文图 4 左图的 28.4 倍（见 §5），所以实验模型大概率也是 128（推算）。

打分分两步。先在 token 级别算出索引 query 和每个可见 key 的点积，再把每一块里的分数取最大值，得到块分数：

$$S^{\text{idx},(r)}_{i,j}=\frac{\big(Q^{\text{idx}}\big)^{(r)}_i\big(K^{\text{idx}}\big)_j^{\top}}{\sqrt{d_{\text{idx}}}},\qquad M^{\text{idx},(r)}_{i,b}=\max_{j\in\mathcal{B}_b,\;j\le i}S^{\text{idx},(r)}_{i,j}$$

\(r\) 是组号，\(j\le i\) 保证因果；一个块里如果没有任何可见 token（整块都在 \(i\) 之后），它的分数记为 \(-\infty\)，永远不会被选中。然后取分数最高的 \(k\) 个块：

$$\mathcal{I}_i^{(r)}=\mathrm{TopK}_{b\in\{1,\dots,B\}}\big(M^{\text{idx},(r)}_{i,\cdot},\,k\big)$$

另外有一条硬规则：位置 \(i\) 所在的那一块（论文叫当前块或局部块）总是被选中，不管它的分数是多少；它占掉一个名额，其余 \(k-1\) 个名额由分数决定。选出来的 \(\mathcal{I}_i^{(r)}\) 由组 \(r\) 的全部 \(G\) 个 query 头共用。

为什么用块内最大值，而不是平均值？论文没有专门做这个对比，下面是本站的理解。一块 128 个 token 里，往往只有一两个 token 真正和当前 query 相关（比如一个变量名、一个数字）。取平均会把这一两个 token 的高分和其余 126 个无关 token 的低分搅在一起，块越大稀释得越厉害；取最大值则只要块里有一个 token 匹配得好，整块就会被选中，正好符合“找回某个具体细节”的需要。Kimi 的 MoBA 用的是块内 key 的平均值来打分，它的块更大（512–4,096），这也是两者的一个重要差别。

索引分支有多轻？按实验模型的配置（\(d_{\text{model}}=3072\)，并按 \(d_{\text{idx}}=128\)），\(W_q^{\text{idx}}\) 是 \(3072\times512\)，\(W_k^{\text{idx}}\) 是 \(3072\times128\)，每层合计约 197 万个参数，41 层约 8,100 万个，相当于 109B 总参数的 0.07%、6B 激活参数的约 1.3%（推算）。计算上，它只有 4 个索引 query 头、1 个索引 key 头，而且只算分数、不用 value 做加权求和。

3.2 主分支：在选中块上做精确的 softmax 注意力

给定组 \(r\) 的块集合 \(\mathcal{I}_i^{(r)}\)，组内每个 query 头 \(h\in\mathcal{H}_r\) 在这些块里因果可见的 token 上做标准注意力，用的是这个组自己的 key 和 value：

$$O_i^{(h)}=\mathrm{softmax}\!\left(\frac{Q_i^{(h)}\big(K^{(r)}[\mathcal{I}_i^{(r)}]\big)^{\top}}{\sqrt{d_h}}\right)V^{(r)}[\mathcal{I}_i^{(r)}]$$

\(K^{(r)}[\mathcal{I}_i^{(r)}]\) 表示把选中块里可见的 token 收集起来。块集合在组内共用，但每个头仍然有自己的 query 投影，所以同一组的 16 个头看的是同一批 token，各自给它们的权重可以完全不同。选中的块最多含 \(kB_k\) 个可见 token，所以每个 query 的注意力代价从 \(O(N)\) 降到 \(O(kB_k)\)，不再随序列变长而增长。

3.3 走一遍：1M 上下文里的一个 query

  1. 索引分支用这个位置的 4 个索引 query 头，分别和前面全部约 105 万个索引 key 求点积，得到 4 行、每行 105 万个分数。
  2. 每行按块取最大值，压成 8,192 个块分数。
  3. 每组从 8,192 块里挑 16 块：当前块固定占 1 个名额，另外 15 块按分数选。选中比例约为 0.2%。4 个组的选择互相独立。

和 GQA 相比，这个 query 的主注意力从“和 105 万个 token 算”变成了“和 2,048 个 token 算”。但要注意第 1 步：索引分支仍然要和全部历史 token 打分，只是每次打分很便宜（4 个头、只算点积）。§5 会看到，正是这一步决定了 MSA 加速比的上限。

4 训练：挑前 k 个没有梯度，索引分支靠什么学会挑块

这一节要回答的问题：主分支的参数可以照常用语言模型损失训练，但索引分支只输出“选哪几块”这个离散结果，选择操作本身不可导，语言模型损失的梯度传不到 \(W_q^{\text{idx}}\)、\(W_k^{\text{idx}}\)。那么索引分支从哪里得到学习信号？训练初期索引分支还是随机的，它乱挑的块会不会把主模型带坏？这一节讲论文 §3.2 的四个部件：KL 损失、截断梯度、索引器预热、强制选当前块。
先补一点背景：KL 散度、“老师—学生”对齐与截断梯度。

KL 散度衡量两个概率分布有多不一样。\(D_{\text{KL}}(P\,\|\,Q)=\sum_j P_j\log(P_j/Q_j)\)，两者相同时为 0。把 \(P\) 当作“老师”、\(Q\) 当作“学生”，最小化它就是让学生的分布去贴近老师的分布；这个方向的 KL 会重罚“老师认为重要、学生却给了很低概率”的位置，所以学生会尽量把老师关心的地方都覆盖到。这正是挑块需要的：宁可多照顾一些，也别漏掉主分支真正在看的 token。

截断梯度（stop-gradient，记作 stopgrad）是一个“前向照常计算、反向不传梯度”的操作。把它套在某个量上，相当于告诉优化器：这个量在这次更新里当常数看待。它常用来防止一个辅助损失去改动不该改动的参数。

4.1 KL 损失：让索引分数去模仿主分支的注意力

KL 损失直接给索引分支一个学习信号：在选中的 token 上，让索引分数的分布去匹配主分支的注意力分布。记 \(\mathcal{I}_{i,\text{tok}}^{(r)}=\big(\bigcup_{b\in\mathcal{I}_i^{(r)}}\mathcal{B}_b\big)\cap\{1,\dots,i\}\) 为选中块里因果可见的 token。在这些 token 上定义学生分布（索引分支）和老师分布（主分支）：

$$P^{\text{idx},(r)}_{i,j}=\frac{\exp\big(S^{\text{idx},(r)}_{i,j}\big)}{\sum_{u\in\mathcal{I}^{(r)}_{i,\text{tok}}}\exp\big(S^{\text{idx},(r)}_{i,u}\big)},\qquad P^{(r)}_{i,j}=\frac{1}{G}\sum_{\ell\in\mathcal{H}_r}\frac{\exp\big(S^{(\ell)}_{i,j}\big)}{\sum_{u\in\mathcal{I}^{(r)}_{i,\text{tok}}}\exp\big(S^{(\ell)}_{i,u}\big)}$$

其中 \(S^{(\ell)}_{i,j}=Q_i^{(\ell)}\big(K_j^{(r)}\big)^{\top}/\sqrt{d_h}\) 是主分支第 \(\ell\) 个头的分数。老师分布是把组内 16 个头各自的注意力分布在概率层面取平均。这样做的理由是：选择结果由整组共用，索引分支要照顾的是“这一组整体需要什么”；按概率平均，意味着只要组里有一个头很看重某个 token，这个 token 在老师分布里就有分量。损失是对所有位置和所有组取平均的 KL：

$$\mathcal{L}_{\text{KL}}=\frac{1}{NH_{kv}}\sum_{i=1}^{N}\sum_{r=1}^{H_{kv}}D_{\text{KL}}\Big(\mathrm{stopgrad}\big(P^{(r)}_{i,\cdot}\big)\,\Big\|\,P^{\text{idx},(r)}_{i,\cdot}\Big)$$

老师分布外面套了 stopgrad，所以这个损失不会反过来改动主分支。注意 KL 是在token 级别上算的，而选择是在块级别上做的（块内取最大）。本站的理解是：只要索引分数在 token 层面学会了“哪些 token 被主分支看重”，块内最大值自然就会把含有这些 token 的块排在前面。

4.2 截断梯度：KL 只许更新索引投影

老师分布已经截断了梯度，但 KL 损失还可能经过另一条路影响主模型：索引分支的输入是隐藏状态 \(X\)，梯度会沿 \(X\) 流回前面各层，再经残差流影响整个骨干网络。论文在索引分支的输入上也加了截断：

$$Q^{\text{idx}}=\mathrm{stopgrad}(X)\,W_q^{\text{idx}},\qquad K^{\text{idx}}=\mathrm{stopgrad}(X)\,W_k^{\text{idx}}$$

两处截断合起来，\(\mathcal{L}_{\text{KL}}\) 就只更新 \(W_q^{\text{idx}}\) 和 \(W_k^{\text{idx}}\)，成了一个只管索引器的、“干净”的对齐信号。附录 B.3 说明了不截断会出什么事（本页 §10）：KL 系数大时，KL 梯度的尖峰会传进骨干，几百步内训练发散；系数稳定时，短上下文基准也会慢慢落后。作者把后者解释为一种“自蒸馏”效应：骨干发现，把主分支的注意力分布变简单，也能让 KL 变小，这比把索引器练好更容易。

4.3 索引器预热，以及强制选当前块

预热。新加的索引投影一开始是随机的，如果一上来就让它决定主分支看哪些块，主分支等于在看随机挑的内容。论文用两段式训练：前一段，主分支和索引分支都用全注意力，只用 \(\mathcal{L}_{\text{KL}}\) 训练新加的索引投影（此时 KL 在全部可见 token 上算）；预热结束后切换到稀疏注意力，KL 改为只在选中的 top-k 位置上算。从全注意力检查点转换（MSA-CPT）时也用同样的预热，让索引投影在接管路由之前先对齐。实验里两条路线的预热都是 40B token（§7.1）。附录 B.4 给了理由：训练最开始的几百步里，主分支的注意力分布变化极快（注意力熵从约 6.3 迅速掉到约 2，读图），索引器要追一个飞快移动的目标，而它自己的选择又接近随机，坏的选择会同时拖累骨干的学习和索引器得到的监督。

强制选当前块。对每个位置 \(i\) 和每个组，\(i\) 所在的块在训练和推理时都被强制选中，占掉一个名额，剩下的名额交给索引分支。这样可以避免一种退化：索引器把 query 紧邻的上下文漏掉。附录 C.2 还试过另外强制选“序列的第一块”（注意力汇）和一个更大的固定局部窗口，结论是不需要（§10）。

4.4 一层 MSA 的训练前向（算法 1）

  1. 照常算主分支投影：\(Q,K,V\leftarrow XW_q,\,XW_k,\,XW_v\)，形状分别是 \((N,H_q,d_h)\)、\((N,H_{kv},d_h)\)、\((N,H_{kv},d_h)\)。
  2. 在截断梯度的输入上算索引投影 \(Q^{\text{idx}},K^{\text{idx}}\)，形状 \((N,H_{kv},d_{\text{idx}})\) 和 \((N,1,d_{\text{idx}})\)。
  3. 按组、按因果算块内最大分数 \(M^{\text{idx}}\)，形状 \((N,H_{kv},B)\)。
  4. 每组取 top-k 块号 \(\mathcal{I}\)，当前块包含在内。
  5. 只在选中块上做注意力，得到 \(O\)，形状 \((N,H_q,d_h)\)；再乘输出投影 \(W_o\)。
  6. 用 \(Q^{\text{idx}},K^{\text{idx}}\) 和截断梯度的 \(Q,K\) 在 \(\mathcal{I}\) 对应的 token 上算 \(\mathcal{L}_{\text{KL}}\)，和这一层的输出一起返回。
对照：DeepSeek-V3.2 的 DSA 是怎么训练索引器的。

DSA 的“闪电索引器”（lightning indexer）也不能靠语言模型损失训练。DeepSeek 的做法是：先做一个短的稠密预热，保持全注意力、冻结除索引器以外的所有参数，用 KL 让索引器的分布贴近主注意力（把所有头的注意力分数相加后归一化），共 1,000 步、约 2.1B token；然后进入稀疏训练，每个 query 选 2,048 个 token，KL 只在选中的 token 上算，并且“把索引器的输入从计算图上分离”，约 943.7B token。（数字取自 DeepSeek-V3.2 论文 §2.1，详见本站 DeepSeek-V3.2 精读。）

和 MSA 对比：KL 对齐、稠密预热、截断索引输入这三件事一一对应，预算也同为每个 query 2,048 个 token。不同之处在于：DSA 的老师分布是所有头相加（因为所有头共用一套选择），MSA 是组内 16 个头取平均；DSA 的索引器是多个头的 ReLU 打分加权求和、按单个 token 选，MSA 是每组一个点积头、按块取最大；DSA 是从已训练好的稠密模型（V3.1-Terminus）继续训练得到的，MSA 额外给出了“从头稀疏训练”的路线。MSA 论文在相关工作里只把 DSA 当作架构上的近邻，没有讨论训练流程上的这种相似。

读的时候容易误解的地方：
  • KL 损失只在训练时存在。推理时索引分支只做“打分—块内取最大—取 top-k”，不算 softmax，也不算 KL。
  • “从头训练”的 MSA-PT 并不是第一步就稀疏：它的前 40B token 是全注意力（预热），之后才切到稀疏。
  • 附录里的先导实验最初还给索引分支配了一个 value 头，让它也贡献一份注意力输出，从而能从语言模型损失拿到梯度（B.2）。最终方案在加入预热之后把这个 value 头去掉了（C.3），所以正文的 MSA 里索引分支是“纯选择器”。

5 计算量：能省多少，省到哪里为止

这一节要回答的问题：在同样的头数、头维度和序列长度下，MSA 的注意力计算量是多少，和 GQA 比省了多少？省下的比例会随长度一直变大吗？解码时每一步要读的数据又少了多少？这一节对应论文 §3.3 的一个公式，本站把它代入实验配置，并补算论文没有写出的两个上限。

论文给出的因果注意力计算量（FLOPs，浮点运算次数）是：

$$F_{\text{GQA}}(N)=2H_qd_hN^2,\qquad F_{\text{MSA}}(N)=\underbrace{H_{kv}d_{\text{idx}}N^2}_{\text{索引分支}}+\underbrace{4H_qd_hNkB_k}_{\text{主分支}}$$

逐项看来源。每一对 (query, key) 在一个头上要做两次长度为 \(d_h\) 的点积（算分数一次，按权重汇总 value 一次），每次乘加算 2 次运算，共 \(4d_h\)；因果注意力约有 \(N^2/2\) 对，所以 GQA 是 \(2H_qd_hN^2\)。MSA 的主分支里，每个 query 都看满 \(kB_k\) 个 token（选中的块大多整块可见），所以是 \(4H_qd_hNkB_k\)，和 \(N\) 成正比。索引分支每组每对 (query, key) 只做一次长度为 \(d_{\text{idx}}\) 的点积，即 \(2d_{\text{idx}}\) 次运算，乘以 \(N^2/2\) 对和 \(H_{kv}\) 个组，得 \(H_{kv}d_{\text{idx}}N^2\)：它仍然随长度按平方增长，只是系数小。论文的结论是：当 \(kB_k\ll N\) 且 \(H_{kv}d_{\text{idx}}\ll H_qd_h\) 时，两者的差距随 \(N\) 变大。

代入实验配置（\(H_q=64\)、\(H_{kv}=4\)、\(d_h=128\)、\(B_k=128\)、\(k=16\)，并取 \(d_{\text{idx}}=128\)），每个 token 每层的注意力计算量是：GQA 为 \(16{,}384N\)，MSA 为 \(512N\) 加上约 6,710 万。下表是本站推算的结果；其中“1M”按 \(2^{20}\) 计，这样算出的 28.4 倍与原文图 4 完全一致（若按 \(10^6\) 计约为 28.3 倍）。

读的时候容易误解的地方：“每 token 注意力计算量降低 28.4 倍”是一个公式算出来的理论值，不是测量值；而且它只算注意力，不算线性层和 MoE 专家。实际墙钟时间的加速比要看 §7.4。

6 内核设计：把“少算”变成“真的快”

这一节要回答的问题：稀疏注意力常见的尴尬是“理论上省了很多，实际上没快多少”，因为零散的访存和不规整的计算喂不饱 GPU。MSA 的选择方式（按块、每组独立、每个 query 各不相同）给内核带来了哪些具体困难？论文 §4 用三组设计来应对：一个专门的 top-k 内核，一个“KV 在外层”的稀疏注意力前向，以及训练时 KL 损失的融合与负载均衡。这一节逐个讲清楚它们解决的是什么问题。
先补一点背景：写 GPU 内核时要关心的几件事。

执行层级。GPU 上的程序以“线程块”（CTA）为单位分派到各个流式多处理器（SM）上；一个线程块由若干个 warp 组成，一个 warp 是 32 个一起执行同一条指令的线程（论文叫 lane）。数据放在三层存储里：每个线程私有的寄存器最快；同一线程块共享的共享内存（shared memory）次之，它被分成 32 个 bank，多个线程同时访问同一个 bank 的不同地址会排队（bank conflict）；显存（HBM）最大也最慢。

Tensor Core 与算术强度。Tensor Core 只做固定形状的小矩阵乘（论文称 MMA），要用满它，送进去的矩阵必须足够“高”和“宽”，比如 128×128。一个内核每从显存读 1 字节数据能做多少次运算，叫算术强度。它低于某个临界值时，速度由显存带宽决定；高于时，由算力决定。以 H800 为例，BF16 稠密算力约 989 TFLOP/s、HBM3 带宽约 3.35 TB/s（NVIDIA 规格），临界值约为每字节 295 次运算（推算）。下面的小工具可以直观看到这个“屋顶”：横轴是算术强度，纵轴是能达到的算力，左边斜坡受带宽限制，右边平顶受算力限制。

FlashAttention 与 LSE。FlashAttention 把 query 和 KV 切成小块，在片上逐块算 softmax（在线 softmax：一边扫一边维护当前最大值和指数和），从不把完整的注意力矩阵写回显存。一段 KV 上的部分结果可以用它的 log-sum-exp（LSE，即 \(\log\sum_j e^{s_j}\)）记下“这段的归一化分母有多大”；几段部分结果之后可以按各自的 LSE 精确地合并成整体结果，这就是 FlashDecoding 的“split-K”思路（见本站 FlashAttention 精读、FlashAttention-3 精读）。

其他术语。TMA 是 Hopper 架构上的异步拷贝引擎，能把显存里的一块数据搬进共享内存而不占用计算线程。持久化内核（persistent kernel）只启动和 SM 数量相当的线程块，每个线程块循环从工作列表里领任务。原子操作（atomic）保证多个线程同时改同一个地址时不出错，但它们会互相排队，浮点累加的顺序也不确定。

6.1 索引与 top-k：不算指数，用寄存器盯住堆顶

不算 softmax 就选。softmax 是单调的：分数大的，概率也大，\(s_i\le s_j\iff\mathrm{softmax}(s)_i\le\mathrm{softmax}(s)_j\)，所以按原始分数排出来的前 k 名和按概率排的完全一样。前向时就可以跳过 softmax 的“求最大值—算指数—求和”三步，直接把块分数交给 top-k。这一步省的不少：1M 上下文时，每层要比较的块分数有 \(2^{20}\times8{,}192\times4\approx344\) 亿个（推算），全都不用算指数。

为小 k 量身定做的 top-k。块大小和 k 是和 top-k 内核一起定下来的。\(B_k\) 大，主注意力的算术强度高（§6.2）；在 \(B_k=128\) 时，每行的候选块数 \(B\)（1M 时为 8,192）和 \(k=16\) 都偏小，低于通用 top-k 算法的舒适区：基数选择（radix select）要在很多候选上分摊多轮分桶的开销，双调排序的代价是 \(O(B\log^2B)\)。论文的做法是一个 warp 处理一行：

  • 32 个 lane 各自按步长 32 扫这一行的 1/32，各维护一个 k 个元素的小顶堆（堆顶是当前前 k 名里最小的那个）。新候选只要不比堆顶大，就直接丢掉；堆顶缓存在寄存器里，所以绝大多数候选只需一次寄存器比较。
  • 真要插入时采用延迟写回，减少共享内存的读写。
  • 扫完后，用 k 轮 warp 内的 shuffle 把 32 个局部结果合并成整行的前 k 名。
  • 共享内存的布局让每个 lane 固定对应一个 bank，避免 bank conflict。

论文在 H800 上把它和 torch.topk、TileLang 的基数选择 top-k 比较（FP32 输入、输出不排序、取 50 次预热后运行的中位数；三者选出的集合完全相同）：

6.2 稀疏注意力：让 KV 块去找 query

写注意力内核首先要决定两层循环谁在外面。常规的 FlashAttention 是“query 在外层”：一个线程块负责一段 query，循环读入 KV 块。论文比较了稀疏预填充（query 和 KV 一样长）时两种顺序的算术强度，按每个数 2 字节估算显存读写量（换成 FP8 只是把绝对数减半，不改变两者的比较）。

query 在外层。每个 query 位置去读它选中的 \(kB_k\) 个 token：

$$\text{FLOPs}=4H_qNd_hkB_k,\qquad \text{IO}=\underbrace{2\cdot2\cdot H_qNd_h}_{\text{读 }Q+\text{写 }O}+\underbrace{2\cdot2\cdot H_{kv}NkB_kd_h}_{\text{读 }K+V}$$

两者之比约等于 \(G\)。直观地说：每读进一块 K、V，只能给“这一个位置、这一组的 16 个头”用，因为相邻位置选的块通常不一样，没法共享。代入实验配置，约为每字节 15.9 次运算（推算），远低于 H800 的临界值，是严重受带宽限制的。

KV 在外层。反过来，每个 KV 块去收集“选了它的那些 query”，这需要一个中间输出缓冲区：

$$\text{IO}=\underbrace{2\cdot2\cdot H_{kv}Nd_h}_{\text{读 }K+V}+\underbrace{2\cdot2\cdot H_qNkd_h}_{\text{读 }Q+\text{写 }O_{\text{buf}}}+\underbrace{2\cdot H_qN(k+1)d_h}_{\text{读 }O_{\text{buf}}+\text{写 }O}$$

计算量不变，两者之比约等于 \(\tfrac{2}{3}B_k\)。直观地说：现在每块 K、V 只读一次；代价变成每个 query 要被读进来 \(k\) 次（它选了几块，就被几个块各收集一次），每次产生一份部分结果，写出去再读回来合并。每读一个 query（连同它那份部分结果的一写一读，共 3 份同样大小的数据），它都要和块里的 128 个 key 算一遍，于是比值约为 \(4B_k/6=\tfrac{2}{3}B_k\)。代入配置约为每字节 83 次运算（推算；\(\tfrac{2}{3}\times128\approx85\)）。因为 \(\tfrac{2}{3}B_k\gg G\)，论文选择 KV 在外层，并按 query 收集（Q gather）。

按这个只计显存流量的粗略模型，KV 在外层的约 83 仍低于约 295 的临界值（推算），但已是 query 在外层的 5 倍多；真实内核还会受益于缓存，这个模型只用来比较两种顺序的相对好坏。它也解释了为什么块要大：\(B_k\) 每翻一倍，这个比值跟着翻一倍。

示意图：两种循环顺序，数据被重复使用的方式不同
怎么看：左边是常规写法：线程块以一个 query 位置为单位，去读它选中的 16 块 K、V；每块 K、V 读进来只服务这一个位置的一组头，复用倍数就是组大小 \(G\)。右边是 MSA 的写法：线程块以一个 KV 块为单位，按“反向索引”（由 top-k 结果转置得到：每个块被哪些 query 选中）把这些 query 收集进来，一次读入的 K、V 被很多 query 共用；为了填满 Tensor Core，内核把 8 个位置的 16 个头拼成 128 行。代价是每个 query 会被它选中的 16 个块分别处理，产生 16 份部分结果，需要另一个内核合并。本站示意图；比值按论文式 13–16 推算。

执行方式。内核以持久化网格的方式在 (KV 块, KV 头) 组成的任务上运行。每个任务先从 top-k 结果的反向稀疏索引里查到相关的 query 位置，再由一个 warp 的 32 个 lane 并行发起 TMA 拷贝，每个 query 位置一次，把这些 query 搬进共享内存。（公开代码里，这个反向索引以 CSR 格式存放，叫 k2q。）

预先排好的分块。如果一个 (KV 块, KV 头) 任务只交给一个线程块，整个内核会被“汇聚行”拖住：序列开头的那一块几乎被每个 query 都选中（注意力汇，见附录 A），处理它的线程块要服务约 \(N\) 个 query，别的线程块早就干完了在等它。其他特别热门的块也会造成同样的热点。论文用一个 GPU 上的调度内核预先把每个任务沿 query 方向切成小段，每段最多约 \(2kB_k\)（即约 4,096）个 query，让热点任务分散到很多线程块上，这些线程块各自读同一份 K、V。以 1M 上下文的第一块为例，它会被切成约 256 段（推算）。

切段之后，一个 query 的 \(k\) 份部分结果由 \(k\) 个不同的线程块产生。为了不用原子操作，调度内核还给每个 (query, 段) 对预先分配好它在缓冲区 \(O_{\text{buf}}\) 里的槽位 \(s\in[0,k)\)，并把槽位和 query 编号打包进一个 32 位的“句柄”。注意力内核把部分结果直接写到预先分配的位置；合并内核读每个 query 的有效槽位数，就知道要合并几份。

两阶段前向。因为一个 query 的 16 份部分结果分散在 16 个线程块里，softmax 的归一化没法在注意力内核里一次做完。前向因此拆成两个内核，中间隔着两个显存缓冲区：\(O_{\text{buf}}\in\mathbb{R}^{k\times n\times H_q\times d}\) 存各段在本段内已归一化的部分输出，\(\mathrm{LSE}_{\text{buf}}\in\mathbb{R}^{k\times n\times H_q}\) 存各段的 LSE。合并内核对每个 (query \(i\), 头 \(h\)) 读出有效槽位，计算

$$a=\max_s\mathrm{LSE}_s,\quad \mathrm{LSE}[i,h]=a+\log\sum_s\exp(\mathrm{LSE}_s-a),\quad w_s=\exp\big(\mathrm{LSE}_s-\mathrm{LSE}[i,h]\big),\quad O[i,h]=\sum_sw_s\,O_{\text{buf}}[s,i,h]$$

举个小例子（推算）：两段部分结果的 LSE 分别是 2.0 和 1.0，那么总 LSE \(=2+\log(1+e^{-1})\approx2.313\)，两段的权重是 \(e^{-0.313}\approx0.731\) 和 \(e^{-1.313}\approx0.269\)，加起来正好是 1。先减去最大值 \(a\) 是为了数值稳定，避免指数溢出。合并内核同时输出最终的 LSE，供训练的反向使用。两个内核之间用 Programmatic Dependent Launch（让后一个内核提前启动，等前一个写完数据再继续）来藏住启动延迟。

拼接 query。KV 在外层时，一个 KV 块往往只关联几个到几十个 query 位置。如果一个位置一个位置地算，分数矩阵乘的 M 维只有 \(G=16\) 行，Tensor Core 大半空着。在 query 在外层的写法里，不能把不同位置的 query 拼在一起，因为它们选的 KV 一般不同；而在 KV 在外层的写法里，被收集到同一块的所有位置用的是同一份 KV，正好可以拼。内核把 \(\lceil128/G\rceil=8\) 个位置连同各自的 16 个头（同属一个 KV 头）拼成 128 行，做一次 128×128 的分数矩阵乘。

6.3 训练时的稀疏 KL 损失

把 LSE 的计算融合进主前向。KL 损失只影响反向的梯度，它本身的数值并不参与前向。最初的实现用一个单独的内核算 KL 的前向，并存下主分支和索引分支的 LSE 给反向用。优化后的做法是：主分支前向时顺手把 \(\mathrm{LSE}_{\text{main}}\) 写到显存；索引分支计算时保存每一块的 LSE，再在选中的 top-k 块上做一次归约，得到 \(\mathrm{LSE}_{\text{idx}}\)。这样 KL 的前向内核整个省掉，反向内核直接读这几个标量来重建 softmax 概率（概率等于 \(\exp(s-\mathrm{LSE})\)），没有重复计算。

动态负载均衡。在变长序列和数据决定的稀疏模式下，每个任务的工作量可以相差几个数量级。反向内核以持久化网格运行，线程块通过一个全局原子计数器领任务；每个任务沿收集到的 query 方向切成若干子任务，子任务数随这个任务的 query 数增长，但每个子任务不小于一个最小粒度，以摊薄每个子任务的固定开销。

读的时候容易误解的地方：
  • 论文 §4 描述的是预填充（和训练）的内核。解码内核没有描述，但 §5.4 报告了解码加速。
  • 公开的 MiniMax-AI/MSA 只面向 NVIDIA SM100（Blackwell），包含稠密 FMHA、稀疏 top-k 选择、用 CuTe-DSL 写的稀疏预填充（BF16 / FP8 / NVFP4）、分页 FP8 解码和 FP4 索引器；没有 H800（SM90）版本，也没有训练用的反向内核（截至 2026-10-20）。所以论文在 H800 上的数字不能直接用公开代码复现。
  • 公开代码的 README 注明，sparse_topk_select 有部分代码源自 TensorRT-LLM 的 indexerTopK（直方图加插入排序），和论文描述的“每个 lane 一个小顶堆”不完全是同一种写法；表 1 测的是哪一版实现，论文没有说明。

先补一点背景：块召回率与分数召回率。

对一个 query 和一个组，先假设能看到全部注意力：按主分支的注意力，把每块里所有 token 的注意力概率加起来，记作块的“质量” \(P_b\)，取质量最大的 16 块作为“理想选择” \(\mathcal{I}^{\star}\)。索引器实际挑出的是 \(\widehat{\mathcal{I}}\)。

  • 块召回率 \(=|\mathcal{I}^{\star}\cap\widehat{\mathcal{I}}|/|\mathcal{I}^{\star}|\)：理想的 16 块里，索引器找到了几块。
  • 分数召回率 \(=\sum_{b\in\mathcal{I}^{\star}\cap\widehat{\mathcal{I}}}P_b\big/\sum_{b\in\mathcal{I}^{\star}}P_b\)：找到的那几块，占理想 16 块总质量的多少。

举个例子：理想的 16 块里索引器找到了 12 块，块召回率是 0.75；如果漏掉的 4 块恰好是理想集合里质量最小的，它们加起来只占理想集合质量的 8%，那么分数召回率就是 0.92。

图 3 右图里，块召回率在约 0.72–0.75 之间，分数召回率在约 0.90–0.94 之间（读图），整个稀疏训练阶段基本持平。也就是说，索引器大约漏掉理想 16 块中的 4 块，但漏掉的多是不太重要的块，被找到的块承载了理想集合九成以上的注意力质量。论文据此认为预热提供了一个干净的转换阶段，转换后索引器也一直和主分支对得很齐。

读这两张图时要注意：
  • 分数召回率的分母是“理想 16 块”的质量，不是全部注意力的质量。如果主分支的注意力本来就分散在很多块上，理想 16 块本身也只覆盖一部分，分数召回率再高也不代表“没丢信息”。
  • 当前块是强制选中的，它几乎必然也在理想集合里，这会让两个召回率都略微偏高。
  • 图 3 的纵轴标注是“层/区间平均”，论文没有说明是在什么数据、多长的序列上测的。
  • 预热阶段的 KL 是在全部可见 token 上算的，稀疏阶段是在选中 token 上算的，两段的数值不能直接比较。

论文对“实测加速小于理论计算量之比”的解释是：稀疏注意力引入了构建索引、top-k 选择、物化反向索引、收集 query 和负载均衡等额外开销，访存也不如稠密注意力规整；但随着长度增加，稠密基线的开销按全长增长，MSA 的主注意力预算却固定，所以实测加速也随长度上升。

本站再从绝对时间上做两个核对（推算，前提是这些耗时对应单层、单卡，数据精度为 BF16，论文都没有写明）。预填充：1M 长度下 GQA 的注意力计算量约为 \(2\times64\times128\times(2^{20})^2\approx1.8\times10^{16}\) 次运算，耗时约 29.1 s，相当于每秒约 620 万亿次，是 H800 BF16 稠密峰值的六成多，说明对照的稠密内核并不弱；MSA 约 \(6.3\times10^{14}\) 次运算用了约 2.04 s，有效算力约每秒 310 万亿次。解码：GQA 每一步要读约 2 GiB 的 BF16 KV（\(2^{20}\) 个 token × 1,024 个数 × 2 字节），耗时约 0.83 ms，相当于约 2.6 TB/s；MSA 每一步读约 256 MiB 的索引 key 加 4 MiB 的选中 KV，耗时约 0.11 ms，相当于约 2.5 TB/s。两者都在用满显存带宽，所以解码加速基本就是读取量之比，7.6 倍贴近 8 倍的上限。

7.5 结果的份量

这组实验的设计强于多数稀疏注意力论文：从头训练的对比在 109B 规模上做，同一架构家族、同一份数据、同样 3T token、同一套评测和对齐的检查点，唯一的差别是注意力层（MSA 多了约 8,100 万个索引参数，约占激活参数的 1.3%，推算）。再加上“从全注意力转换”这条更贴近工业实践的路线，可信度相当高。但下面几点会影响这些数字的分量。

  • 每个结果只有一次运行，评测的是基座模型。论文没有给出多次训练或多次评测的方差。表 2 里不少差值在 1 分以内；而 VisualWebBench +12.8、EgoSchema +8.0（同一基准上 MSA-CPT 却是 −3.8）这样的大幅波动，更像是预训练检查点在个别基准上的不稳定，而不是稀疏带来的系统性提升。两条损失曲线几乎重合（§7.2），也说明两者在训练数据分布上的建模能力相当。所以“MSA-PT 在 24/30 项上更高”最稳妥的读法是“不比全注意力差”，而不是“比全注意力好”。
  • 预训练的序列长度没有公开。MSA 每个 query 看 2,048 个 token；序列不超过 2,048 时，MSA 其实就是全注意力，8K 序列也要看到 1/4。多数短上下文基准（MMLU、GSM8K 等）的输入远短于此，它们说明的是“换成 MSA 的结构不伤害短文本能力”，基本不涉及稀疏本身。真正考验稀疏的，是 RULER-32K 和表 3 的 128K 评测。
  • 长上下文的证据止于 128K，而且只有 MSA-CPT。速度数字报告到 1M，但效果没有任何 128K 以上的评测；MSA-PT 也没有 128K 的结果。表 3 里的全注意力基线是否同样做了 140B token 的长上下文训练，论文没有交代；HELMET 只列了 ICL 和重排/RAG 两个子项。
  • 智能体能力只用困惑度衡量。论文动机里反复强调智能体任务，但实验只报告了这些任务数据上的困惑度，没有任务完成率。困惑度相差 0.001 量级，说明不了多步工具调用这类能力。MiniMax 在 M2 的说明里恰恰指出过，多步推理上的短板在常规基准上看不出来。
  • 速度测的是单个注意力算子，不是整个模型。图 4 的配置只有注意力的形状（64/4/128），没有批大小、数据精度、是否包含 top-k 和合并内核的说明（正文的措辞暗示包含了这些开销）。这些是算子级的预填充和解码延迟，不是端到端的吞吐量、首 token 时间或每 token 时间，也没有在服务等级目标下测。端到端能拿到多少，取决于注意力在全模型中的占比。按实验模型粗算（推算，只算浮点运算、按 41 层和 60 亿激活参数）：32K 时注意力约占前向计算的 65%，MSA 整体最多快约 2.2 倍；128K 时约 5.7 倍；1M 时注意力占 98%，整体最多约 19.5 倍。中等长度下的端到端收益远小于算子级数字。
  • 稠密基线的内核没有点名。论文没有说 GQA 用的是 FlashAttention-3、cuDNN 还是自研内核。按上面的推算，它在 1M 预填充时达到约 620 TFLOP/s（若为 BF16），不是一个弱基线；但版本和精度未知，换成别的实现，倍数会变。
  • 硬件只有 H800。H800 是 Hopper 架构，显存带宽与 H100 相同（NVLink 带宽被削减，单卡注意力不受影响）。公开的内核只支持 Blackwell（SM100），论文没有在 Blackwell 上的数字；vLLM 的实现又是另一套 Triton 内核（见“后来怎么样了”）。不同硬件和实现上的倍数需要各自测量。

8 相关工作与结论：MSA 在稀疏注意力家族里的位置

这一节要回答的问题：降低长上下文代价的方法很多，MSA 和它们的根本区别是什么？在“训练时就稀疏”的几种方法（NSA、MoBA、DSA、InfLLM-v2）里，MSA 到底改了哪几个设计选择？论文最后对下一步的展望是什么？

两大方向。论文把高效注意力分成两类。一类是用更便宜的结构替换 softmax 注意力：线性注意力用线性复杂度的核函数近似 softmax，Mamba 这类状态空间模型用选择性的递推代替注意力；混合结构（MiniMax-01、M1）把线性层和全注意力层交错，减少平方复杂度的层数，同时保留一部分精确 softmax 的能力。另一类保留 softmax 注意力、限制它能看的范围：固定模式的做法用局部窗口、全局 token（Longformer、BigBird）或“注意力汇 + 滑动窗口”（StreamingLLM），这些模式与内容无关。

按内容决定看哪里。自适应的稀疏注意力让可见范围取决于输入，区别主要在“什么时候决定”和“选择器是否参与训练”。一类是推理时才稀疏：在训练好的全注意力模型上，只在服务时构造稀疏模式。H2O 和 SnapKV 在解码时根据累积的注意力统计裁剪 KV 缓存（见本站 SnapKV 精读）；Quest 对每个 query 按页估计重要性；MInference 和 FlexPrefill 在预填充时为每个头分派稀疏内核（同类方法还有本站的 XAttention 精读）；InfLLM 维护注意力汇、局部窗口和可检索的块。论文指出，这些方法继承了全注意力的训练代价，而且至少有一个推理阶段的速度接近全注意力。另一类是原生训练的稀疏注意力，在预训练中就训练索引器，这是和 MSA 最接近的一类。

论文对近邻的概括是：NSA 有三个并行分支（粗粒度的压缩注意力、细粒度的选块注意力、局部滑动窗口）；InfLLM-v2 把无参数的块选择和局部滑动窗口统一起来，可以零样本地从稠密切换到稀疏；MoBA 同样建在 GQA 上，但用很大的 KV 块、用块内 key 的平均值打分，选择器只通过语言模型的梯度学习；DSA 建在 MLA 的 MQA 模式上，用多头的 ReLU 闪电索引器逐个 token 打分，所有 query 头共用一个 top-k 结果，按 token 选择。MSA 自认的区别在于同时做两件事：每个 GQA 组独立挑 top-k，并且按块选择。前者让不同组可以看不同的远处内容（附录 A 的可视化支持这一点），后者让 KV 的读取保持连续。

关于论文对近邻的描述，有两处值得核对：
  • 论文说 NSA “面向 MQA/MHA 的底座”。但 NSA 论文自己的实验模型就是 GQA（4 组、64 头），选择也在 GQA 组内共享（见本站 NSA 精读 §3.6）。MSA 和 NSA 真正的区别在于：NSA 还有压缩分支和滑动窗口分支，块分数来自压缩分支的注意力，并且固定选中开头块和局部块；MSA 只有一个纯选择器，用 KL 单独监督。
  • MSA 的训练配方（KL 对齐 + 稠密预热 + 截断索引输入）和 DSA 的几乎一样（§4 的对照框），论文没有在这一点上做比较，也没有和任何原生稀疏方法在相同设置下直接比效果或速度。表 2、表 3 的对照只有全注意力一家。

内核方面。要把理论上省的计算变成墙钟时间，高效内核必不可少。FlashAttention 与 FlashAttention-2 提出了注意 I/O 的分块 softmax 注意力，FlashDecoding 把它推广到受显存带宽限制的解码。开源的块稀疏内核，如 Flash-Sparse-Attention 和 FlashMoBA，提供了这类递推的块稀疏版本。MSA 的内核沿用 FlashAttention 的算法骨架，只是把循环顺序调整到适合 GQA、按块访问的模式（§6）。

结论与展望。论文的结论是：MSA 是一种和 GQA 一起设计的稀疏注意力，在标准 GQA 层上挂一个轻量的索引分支，每个组通过块级点积索引器独立挑选少量 KV 块，主分支只在选中块上做 softmax 注意力；索引分支是纯选择器，在两阶段预热和输入截断梯度的配合下，用 KL 对齐损失向主分支学习。在 109B MoE 规模上，MSA 在多数预训练和智能体相关基准上保住了全注意力基线的能力，同时在 1M 上下文把每 token 的注意力计算降低 28.4 倍，而这正是长上下文推理成为部署瓶颈的区间。作者认为，这些核心决定都和当前多数开源前沿模型共用的 GQA 底座兼容，迁移起来改动很小。下一步有两个方向：一是缩小剩余的长上下文检索差距，办法可以是更长的稀疏训练、推理时更大的选择预算，或者更丰富的索引打分函数；二是把同样的“纯选择器”设计推广到预训练之外，包括强化学习后训练和智能体部署，在那里长上下文的成本是主要的运营约束。

9 附录 A：索引分支到底学会了挑什么

这一节要回答的问题：训练好的索引分支挑出来的块，有没有可以解释的规律？4 个组是真的各挑各的，还是退化成了同一种选法？论文没有强制选序列的第一块，那么“注意力汇”还在吗？
先补一点背景：注意力汇（attention sink）。

softmax 要求每个 query 的注意力权重加起来等于 1。当一个头在当前位置“没什么想看的”时，它也必须把权重放到某处。实践中很多头会把大量权重堆在序列的第一个 token 上，那个 token 本身的内容并不重要，它只是充当一个“垃圾桶”。StreamingLLM 发现，如果在滑动窗口里把开头几个 token 去掉，模型会崩溃，所以很多稀疏或流式注意力的设计都强制保留开头的 token。

原文图 5 画出了索引分支对所有 (query 块, key 块) 组合的选择概率，取一个浅层（第 1 层）和一个深层（第 18 层），每层 4 个头，分别属于 4 个 GQA 组（图中每个方向约 500 个块，按 128 token 一块折合约 64K token，推算）。图里有三种结构：所有头都在对角线上有很高的概率，即“当前块和紧邻的几块”；所有头都稳定地选中最左边一列，即序列开头的块（注意力汇）；剩下的预算用在少数几个“固定相对距离”上，表现为与对角线平行的斜条纹。关键在第三点：不同组的条纹位置不同，第 18 层更明显，长距离的选择收缩成每组几条清晰的条纹，4 个组挑的条纹肉眼可见地不一样。论文据此认为，索引器学到的是各组特有的稀疏模式，而没有坍缩成一种全局统一的选法，这正是“每组独立挑选”的价值所在。

原文图 6 看的是注意力汇。即使没有强制选第一块，学到的索引分支在所有层、所有头上都给开头的块很高的选择概率。论文取第 4 层和第 24 层，各抽 8 个头，画出每个头分给第一个 token 的平均注意力：第 4 层在 0.29 到 0.61 之间，第 24 层在 0.38 到 0.69 之间（读图）。也就是说，很多头有三到七成的注意力落在第一个 token 上。这说明注意力汇在 MSA 里同样普遍存在，而且索引器自己学会了保留它；这也解释了 §6.2 为什么要专门处理“几乎被所有 query 选中的第一块”。

读的时候要注意：这些可视化来自少数几个层和头，没有说明用的是什么输入；斜条纹（固定相对距离）也可能和训练数据的格式（比如固定长度的模板、图像 patch 的行宽）有关，论文没有分析条纹的来源。

本站注：“只用语言模型损失、索引分支自己有输出”的配置，结构上很像 NSA 的压缩分支（它也既产出注意力结果、又为选块提供分数）。这组结果说明，单靠语言模型损失训练这样的打分器，长上下文检索会吃亏；NSA 论文在 64K 的大海捞针上表现很好，两者的设置差别很大（规模、块大小、是否有滑动窗口），不能直接互推。

10.3 截断 KL 的梯度（B.3）

默认的自动求导图里，KL 的梯度会穿过索引投影流回隐藏状态，再经残差流进入整个骨干网络。这样 KL 就从“索引器的局部监督”变成了“骨干的额外目标”。论文观察到两种失败。KL 系数较大时，偶发的 KL 梯度尖峰传进骨干，几百步内梯度范数暴涨、语言模型损失发散：原文图 8 里，不截断的那次运行在第 300 到 500 步之间梯度范数冲到约 \(4\times10^5\)，损失停在约 8–9 下不来；截断后约 8,600 步时损失已降到约 2.1（读图）。系数稳定时，短上下文基准也会逐渐落后：原文图 9 里，训练到 400B token 时，截断与不截断分别是 MMLU 37.4 对 33.3、HellaSwag 39.4 对 33.7、ARC-Challenge 42.8 对 38.9、BBH 32.2 对 31.3（读图）。论文把后者归因于前面说的“自蒸馏”：骨干可以通过把主分支的注意力变简单来降低 KL。截断之后，两种失败都消失了，此后所有运行都用截断。

补一句：论文正文说不截断时短上下文基准会“逐渐退化”，但图 9 里两条曲线都在上升，只是不截断的那条明显涨得慢。

10.4 索引器预热（B.4）

原文图 10 画了先导模型第 2、7、12 层主分支注意力的熵（熵越高，注意力越分散）：最初约 6.3，几百步内掉到约 2，之后部分回升，稳定在约 3–4（读图）。这说明训练最初主分支的注意力从“很平”迅速变成“很尖”，然后才进入较慢的表示学习阶段。在这个阶段就开启 top-k，索引器要追一个飞快移动的目标，而它自己的选择又接近随机；坏的选择把主分支引向没用的 token，同时削弱骨干的学习和索引器得到的 KL 监督。

预热的做法是：一开始主分支用全注意力，索引分支在全序列上用 KL 对齐主分支；\(T_{\text{warm}}\) 步之后再开启 top-k，KL 限制在选中的范围内。原文图 11 比较了有无预热的预训练：约 400B token 时，有预热与无预热分别是 MMLU 39.5 对 39.0、ARC-Challenge 43.4 对 43.0、BBH 32.4 对 32.2、HumanEval 24.4 对 17.7、RULER 55.0 对 47.0（读图）。通用基准差得很少，差距主要在代码和长上下文检索上；而且这些曲线波动很大（RULER 在约 47 到 58 之间来回跳），单个检查点的差值要打折扣。论文据此在从全注意力检查点转换时也采用预热。

10.5 可学习的注意力汇（B.5）

既然第一个 token 天然充当注意力汇，能不能给它一个专门的、可学习的位置？作者试了 gpt-oss 式的可学习注意力汇：每个头多一个可学习的 logit，在 softmax 里和正常的 key 一起竞争权重。原文图 12 显示，它在一些头里吸收了大量注意力，但没有完全取代第一个 token；在可学习汇分到权重很少的头里，第一个 token 仍然是主要的汇。原文图 13 比较了智能体任务数据上的困惑度，加了可学习汇并没有带来一致的改进（例如约 370B token 时，AgentCompany 上 MSA 为 1.359，加了可学习汇为 1.367，读图）。考虑到额外的参数和实现复杂度，最终方案没有采用。

10.6 动态选择 vs 滑动窗口（B.6）

为了确认“按内容选”有价值，作者构造了一个计算量对齐的滑动窗口基线：去掉索引分支，每个 query 固定看第一个块，加上一个以自己结尾、token 数与 MSA 预算相同的局部窗口。两者的预算一样，区别只在选哪些 token 是按位置固定，还是按内容动态决定。原文图 14 显示，在整个训练过程中滑动窗口模型在智能体任务数据上的困惑度都更高，约 370B token 时差约 0.003–0.008（读图）。论文的结论是：对这些智能体任务，固定位置的稀疏模式不如依内容的选择合适。

本站核对时发现的问题：原文图 14 里滑动窗口基线的图例写作“Hybrid-SWA”，正文没有解释“Hybrid”指什么。更重要的是，在 AgentCompany、BrowseComp、HLE 三项上，图 14 中 Hybrid-SWA 的曲线和图 13 中“MSA + 可学习汇”的曲线逐点相同（本站读图比对，例如 AgentCompany 都是 1.382、1.375、1.373、1.372、1.367、1.367）；SWE 一项两图不同，而且连 MSA 自己的曲线在两张图里也不一样。这很可能是作图时数据放错了。在作者更正之前，B.5 和 B.6 两个结论都应打折扣；另外两者的困惑度差本来就只有千分之几。

10.8 强制选开头块和局部窗口（C.2）

早期的稀疏训练里，作者强制选择器包含两类块：序列的第一块（对应注意力汇），以及 query 周围一个固定的局部窗口（保住短距离建模，也给索引器提供稠密的监督）。这主要是一个稳定措施：在索引器变可靠之前，减少漏掉基本上下文的机会。后来他们发现这些先验不必写死：去掉强制选择之后，训练出的模型仍然会在需要时关注开头，邻近的 token 也仍然常被选中（附录 A）。对比表（论文正文误写为表 6，实为表 5）里，推理、代码、多模态和困惑度几乎都相同，例如 MMLU 都是 60.5、BBH 都是 58.2。于是最终方案不再强制选第一块或大的局部窗口，只强制选“未满的当前块”。这和 MiniMax-M3 的 config.json 一致（不强制开头块、强制当前块）。

容易忽略的一处：同一张表里，长上下文的 RULER-32K 是 61.5（不强制）对 65.8（强制），差了 4.3 分，是附录所有表格里最大的长上下文差距之一，而论文的文字说长上下文检索“也相当”。RULER-8K 两者相同（71.6 对 71.7）。正式实验里 MSA-PT 的 RULER-32K 并不差（§7.3），但这一项说明“去掉强制选择不影响长距离检索”的证据并不充分。

10.9 索引分支的 value 头（C.3）

B.2 里 value 头帮助模型从第一步开始稀疏训练，但它带来额外的计算和复杂度。既然预热已经解决了初始化问题，作者在继续预训练的设置下比较了“带 value 头”和“不带 value 头、只靠 KL 训练”：结果有升有降，没有系统性的差别。例如不带 value 头时 MMLU 66.4 → 67.3、PerceptionTest 45.0 → 47.3、RULER-32K 79.7 → 80.4 略好，GSM8K 77.6 → 76.4、BigCodeBench 46.0 → 44.0、RULER-8K 84.1 → 83.0 略差。论文的结论是：先前方案里 \(O^{\text{idx}}\) 的主要作用是提供一个早期训练信号，而不是在收敛时提供必需的容量。最终方案出于效率去掉了 value 头。推理时，top-k 索引器只需要 \(Q^{\text{idx}}K^{\text{idx}\top}\) 的块内最大值，完全不需要汇总 value，也不需要算指数。

MiniMax-M3：MSA 的生产落地

论文摘要说“一个由 MSA 驱动的、生产级的原生多模态模型已经公开发布”，指的是 2026 年 6 月发布并开放权重的 MiniMax-M3。按 Hugging Face 模型卡，它是一个原生多模态模型，支持 1M 上下文，总参数约 428B、激活约 23B。它的 config.json 证实了 MSA 的参数：64 个 query 头、4 个 KV 头、头维度 128，索引维度 128、4 个索引头，块大小 128、每组选 16 块，块分数取最大值，不强制选开头块、强制选当前块，MSA 层没有索引 value 头。和论文实验模型不同的是，M3 共 60 层，前 3 层仍用稠密注意力，其余 57 层用 MSA；而论文说实验模型的每个注意力层都是 MSA。

模型卡给出的效率数字是：在 1M 上下文时，相比 M2，预填充快约 9 倍、解码快约 15 倍，每 token 的计算降到约 1/20。这是厂商自报的模型级数字，和论文的算子级数字不是一回事，测量方法也没有公开。本站可以从配置上解释它为什么和论文不同（推算）：M2 是 48 个 query 头、8 个 KV 头，每个 token 每层的 KV 有 \(2\times8\times128=2{,}048\) 个数，是 M3 索引 key（128 个数）的 16 倍，所以解码读取量之比的上限是 16 倍，高于论文里以同配置 GQA 为基线时的 8 倍；每 token 每层的注意力计算量在 1M 时，M2 约为 \(2\times48\times128\times2^{20}\approx129\) 亿次，M3 的 MSA 层约 6 亿次，相差约 21 倍，与“1/20”相符。但 M2 的配置只支持 196,608 个位置，“M2 在 1M 上下文”只能是外推或合成的测量；M3 的 3 层稠密注意力也会把整模型的倍数拉低。这些数字宜当作厂商声明看待。

推理框架与内核

M3 发布当天，vLLM 就提供了支持（vLLM 博客，2026-06-12）。博客描述的实现是：预填充用 Triton 写的索引打分、top-k 选块和稀疏 GQA 内核，在 SM100 上也可以调用 MiniMax 的 CuTe 内核；解码用分段式的索引打分内核合并 top-k 结果，再用 GQA 解码内核合并部分输出；KV 仍以标准的分页缓存存放，建议把页大小设为 128，与 MSA 的块对齐；主注意力的 KV 缓存和索引 key 缓存分开记账；前缀缓存和 EAGLE3 投机解码都可用；发布时在 NVIDIA H200、GB200、B300 和 AMD MI350、MI300 系列上验证过，FP8 的索引器和 KV 缓存路径还在规划中。这在一定程度上印证了论文“最大限度沿用现有基础设施”的判断：MiniMax 在 M2 说明里担心的前缀缓存和投机解码，在 MSA 上都能直接用。M3 的模型卡还列出了 SGLang、Transformers、KTransformers、unsloth 和 AMD 的 ATOM 等部署方式。

官方内核仓库 MiniMax-AI/MSA（MIT 许可，2026-06-11 创建）面向 Blackwell（SM100）：稠密 FMHA、稀疏 top-k 选择、BF16 / FP8 / NVFP4 的稀疏预填充、分页 FP8 解码和 FP4 索引器，也上架了 Hugging Face 的 kernels 库。它不包含论文测速用的 H800 版本和训练内核（§6）。

独立验证与同期路线

截至 2026-10-20，本站没有找到第三方从头复现 MSA 训练、或在相同设置下独立核对表 2、表 3 的公开结果。各推理框架报告的是自己的服务吞吐与正确性检查（例如 vLLM 在 B300 上的 GSM8K 校验），不是对论文结论的复现。

放到更大的图景里看，2025–2026 年几家公司在长上下文注意力上的选择并不一致。DeepSeek 从 NSA（块选择 + 压缩 + 窗口）走到 V3.2 的 DSA（token 级选择），再到 V4 的压缩与稀疏组合（见本站 DeepSeek-V3.2 精读、DeepSeek-V4 精读）。Kimi 在 MoBA（块稀疏）之后发布了线性注意力混合的 Kimi Linear（见 MoBA 精读、Kimi Linear 精读），方向恰好和 MiniMax 相反。Qwen3-Next / Qwen3.5 用 Gated DeltaNet 的 3:1 混合（见 Gated DeltaNet 精读）。MiniMax 自己则从线性注意力混合（01、M1）退回全注意力（M2），再走到建在 GQA 上的块稀疏（M3）。MSA 的特点是改动最小：底座仍是普通 GQA，KV 缓存格式不变，可以从现成的稠密检查点转换过来，代价是 KV 缓存一点不省，加速比被索引分支的平方项封顶。
