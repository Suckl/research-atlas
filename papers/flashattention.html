0 导读：这篇论文解决什么问题

Transformer 里的注意力，要让序列中的每个 token 去“看”所有其他 token。序列长度记为 \(N\)，那么每一层每个注意力头都要算出一张 \(N\times N\) 的分数表。\(N\) 翻一倍，这张表就变成 4 倍大。2022 年前后，GPT-2 的上下文是 1024 个 token，BERT 是 512 个；想把上下文拉到上万个 token，最先撞上的就是这张表带来的时间和显存开销。

当时已经有大量“近似注意力”方法，用稀疏或低秩的办法把计算量从 \(N^2\) 降到接近 \(N\)。奇怪的是，它们大多在实际计时上并没有比标准注意力快多少，所以很少被真正采用。这篇论文给出的解释是：注意力慢，主要不是因为算得多，而是因为搬得多。标准实现会把那张 \(N\times N\) 的表写进 GPU 显存（HBM），然后为了做 softmax、mask、dropout 等操作再一遍遍读出来、写回去；GPU 的计算单元大部分时间都在等这些数据。

论文提出的 FlashAttention 计算的仍然是一模一样的注意力，没有任何近似，但换了一种组织计算的方式：把 Q、K、V 切成能放进芯片上那块小而快的存储（SRAM）的小块，在片上把一小块分数算完、用完就扔，靠一个叫“在线 softmax”的技巧把各块的结果正确地拼起来，从而从头到尾都不把 \(N\times N\) 的表写进显存。反向传播需要这张表时，也不去读存档，而是在片上重新算一遍。结果是对显存的读写量大幅下降（论文的例子里少了约 9 倍），注意力算子本身快了 2–4 倍左右，显存占用从随 \(N^2\) 增长变成随 \(N\) 线性增长。论文还证明了这种做法在某种意义上已经是最优的，并把它推广到了块稀疏注意力。

实际效果上，BERT-large 的训练比当时 MLPerf 1.1 的纪录快 15%，GPT-2 的训练比 HuggingFace 实现快 3 倍；更重要的是，省下来的时间和显存让模型可以用更长的上下文训练，Transformer 第一次在长度 16K 的 Path-X 和 64K 的 Path-256 任务上做到了比随机猜更好。

1 引言：近似注意力为什么没有变快

这一节要回答的问题：想让 Transformer 处理更长的序列，就得让注意力更快、更省显存。此前的思路是减少注意力的计算量（FLOPs），可这些方法在实际计时上往往并不更快。问题出在哪里？作者认为缺了一条原则：算法要考虑数据在 GPU 不同层级存储之间的读写（IO）。这一节交代这个判断，以及论文据此做了什么。
先补一点背景：注意力到底在算什么。

对一个注意力头，输入是三个矩阵：查询 \(Q\)、键 \(K\)、值 \(V\)，形状都是 \(N\times d\)。\(N\) 是序列长度，\(d\) 是每个头的维度（GPT-2 里 \(N=1024\)、\(d=64\)）。计算分三步：

$$S=QK^{\top}\in\mathbb{R}^{N\times N},\qquad P=\mathrm{softmax}(S)\in\mathbb{R}^{N\times N},\qquad O=PV\in\mathbb{R}^{N\times d}$$

第一步，用每个 token 的查询向量和所有 token 的键向量做点积，得到 \(N\times N\) 的分数表 \(S\)，第 \(i\) 行第 \(j\) 列表示“第 \(i\) 个 token 有多关注第 \(j\) 个 token”。第二步，对 \(S\) 的每一行做 softmax，把分数变成一行加起来等于 1 的权重 \(P\)。第三步，用这些权重对值向量加权平均，得到输出 \(O\)。（实际实现里分数还要乘一个缩放系数，通常是 \(1/\sqrt{d}\)，论文在主体部分为了简洁省略了它。）

要注意两个尺寸的反差：输入 \(Q,K,V\) 和输出 \(O\) 都只有 \(N\times d\)，而中间的 \(S\) 和 \(P\) 是 \(N\times N\)。当 \(N=1024\)、\(d=64\) 时，中间矩阵比输入大 16 倍；当 \(N=16384\) 时，大 256 倍。这个反差是整篇论文的出发点。

论文先回顾了此前的努力。为了降低注意力 \(O(N^2)\) 的代价，人们提出了稀疏近似（每个 token 只看一部分 token）、低秩近似（用一个小矩阵去逼近 \(N\times N\) 的注意力矩阵）以及两者的组合。这些方法把计算量降到了线性或接近线性，但很多并没有带来实际的加速。作者认为原因在于它们只盯着 FLOPs，而 FLOPs 和实际耗时并不总是对应；它们忽略了另一项开销：内存访问。

由此引出全文的核心主张：注意力算法应该是 IO 感知（IO-aware）的，也就是在设计算法时，仔细计算数据在快慢不同的存储之间读写了多少次。在 GPU 上，这指的是芯片上又快又小的 SRAM 和芯片外又大又慢的 HBM（高带宽显存）之间的数据搬运。作者指出，GPU 的计算速度增长得比显存速度快，Transformer 里大部分操作的瓶颈已经是访存；而在数据库连接、图像处理、数值线性代数等领域，IO 感知的算法早就是标准做法。问题是 PyTorch、TensorFlow 这类框架不让用户精细控制数据放在哪一级存储里，所以作者直接用 CUDA 写了一个内核。

要做到“不把注意力矩阵写进 HBM”，有两个技术难点：

  1. softmax 需要整行数据。softmax 要用一整行的所有分数来归一化，可是一整行（长度 \(N\)）不一定放得进 SRAM。论文用分块（tiling）解决：把输入切成块，分几遍扫过，逐步完成 softmax 的归一化。
  2. 反向传播需要中间矩阵。训练时，反向传播通常要用到前向算出的 \(P\)。论文用重算（recomputation）解决：前向只存下 softmax 的归一化统计量（每行两个数），反向时在 SRAM 里把需要的那一块注意力矩阵重新算出来，这比从 HBM 读回存档还快。

两者结合，整个注意力可以在一个 CUDA 内核里完成。虽然重算让 FLOPs 变多了，但因为 HBM 读写大幅减少，FlashAttention 反而更快（论文图 1 右：GPT-2 的注意力计算快了 7.6 倍），显存占用也只随序列长度线性增长。

论文的贡献可以归纳为四点：

  • IO 复杂度分析。FlashAttention 需要 \(O(N^2d^2M^{-1})\) 次 HBM 访问（\(M\) 是 SRAM 大小），标准注意力需要 \(\Omega(Nd+N^2)\) 次；在典型的 \(d\) 和 \(M\) 下前者少很多（论文图 2 的例子少了约 9 倍）。论文还给出了一个下界：对所有 SRAM 大小，没有精确注意力算法能在渐近意义上做得更好。
  • 块稀疏 FlashAttention。把同样的思路用到块稀疏注意力上，得到比 FlashAttention 还快 2–4 倍的近似注意力，序列长度可到 64K。
  • 训练更快。BERT-large（序列 512）比 MLPerf 1.1 的训练速度纪录快 15%；GPT-2（序列 1K）比 HuggingFace 的实现快 3 倍、比 Megatron-LM 快约 1.7 倍（引言把两者并在一起说成“快 3 倍”，具体数字见第 7 节）；Long-Range Arena（序列 1K–4K）快 2.4 倍。
  • 模型更好、能做新任务。上下文变长后，GPT-2 的困惑度改善 0.7，长文档分类提升 6.4 个点；Transformer 第一次在 Path-X（16K）和 Path-256（64K）上超过随机水平。
读的时候容易误解的地方：“精确注意力”（exact attention）的意思是 FlashAttention 和标准注意力计算的是同一个数学公式，没有近似，换掉之后模型定义不变、不需要重新训练，这与 Linformer、Performer 等近似方法有本质区别。但“精确”不等于“逐位相同”：两者做加法的顺序不同，浮点舍入误差也不同，输出会有舍入量级的微小差别（这是浮点计算的一般性质，论文没有专门讨论）。论文用 GPT-2 训练曲线几乎重合来说明这种差别不影响训练（见第 7 节）。

2 背景：GPU 的存储层次，以及标准注意力慢在哪里

这一节要回答的问题：上一节说注意力的瓶颈在“搬数据”，那数据在 GPU 上是从哪里搬到哪里？什么叫一个操作受计算限制或受访存限制，怎么判断？标准注意力具体怎么实现，它读写了多少数据？后面所有的设计和分析，都建立在这一节的硬件模型上。

2.1 存储层次：小而快的 SRAM，大而慢的 HBM

先补一点背景：GPU 上的数据放在哪里。

一块 GPU 由很多个流式多处理器（SM）组成，每个 SM 里有自己的计算单元、寄存器和一小块片上 SRAM（在 CUDA 编程里通常作为“共享内存”使用）。所有 SM 共用芯片外的一大块HBM（高带宽显存），也就是我们平常说的“显存”：模型参数、激活值、注意力矩阵都存在这里。计算单元只能直接处理寄存器和 SRAM 里的数据，所以任何计算都要先把数据从 HBM 读进来，算完再写回 HBM。

可以把它想成厨房：HBM 是很大的仓库，SRAM 是灶台边的小案板。案板上切菜飞快，但一次只能放一点东西；仓库什么都放得下，但每次去取都要走一趟。一道菜做得慢，往往不是因为切得慢，而是因为在仓库和案板之间来回跑了太多趟。

示意图：GPU 的存储层次（数字为论文给出的 A100 参数）
怎么看：从下往上，每一级存储更快、更小。最上面的 SRAM 带宽约 19 TB/s，是 HBM（1.5–2.0 TB/s）的 10 倍左右，但容量只有约 20 MB，比 40–80 GB 的 HBM 小三个数量级以上。CPU 内存更大但慢得多，注意力计算不涉及它。FlashAttention 要做的，就是让注意力的中间结果只在最上层流转，尽量少碰中间那一层。本站示意图，对应 原文图 1 左 ↗。“108 个 SM × 192 KB ≈ 20 MB”是推算，与原图标注的 20 MB 一致。

论文以 NVIDIA A100 为例：HBM 有 40–80 GB，带宽 1.5–2.0 TB/s；SRAM 每个 SM 有 192 KB，一共 108 个 SM，带宽估计约 19 TB/s。SRAM 比 HBM 快一个数量级，但小了好几个数量级。论文还指出了一个趋势：GPU 的计算能力增长得比显存带宽快，于是越来越多的操作被 HBM 访问卡住，用好 SRAM 就越来越重要。

GPU 执行一个操作的方式也很固定：启动一个内核（kernel），由成千上万个线程一起执行；每个内核从 HBM 读入输入、放进寄存器和 SRAM 计算，再把输出写回 HBM。一个内核结束后，它在 SRAM 里的东西就没了，下一个内核要用的话只能再从 HBM 读。

2.2 计算受限与访存受限：用“算术强度”来判断

一个操作的耗时，取决于“算”和“搬”哪个更慢。论文用算术强度（arithmetic intensity）来刻画：每从 HBM 读写 1 个字节，要做多少次运算。

  • 计算受限（compute-bound）：运算很多、访存相对很少，耗时由运算量决定。典型例子是内维很大的矩阵乘法、通道数很多的卷积。
  • 访存受限（memory-bound）：访存很多、每个数据只做几次运算，耗时由读写量决定。典型例子是大多数其他操作：逐元素操作（激活函数、dropout）和归约操作（求和、softmax、batch norm、layer norm）。
先补一点背景：roofline 模型。

把硬件的两项能力放在一起看：A100 的 FP16 矩阵乘法峰值约 312 TFLOPS（这个数取自 FlashAttention-2 论文），HBM 带宽按 1.5 TB/s 算。如果一个操作的算术强度是 \(I\)（FLOPs/字节），那么光是搬数据就限制了它最多只能达到 \(1.5\times I\) TFLOPS。两项上限取较小的那个，画在对数坐标上就像一个“屋顶”：左边是斜坡（受带宽限制），右边是平顶（受算力限制）。两段的交点在 \(312\div1.5\approx208\) FLOPs/字节（推算）：算术强度低于 208 的操作，再怎么优化计算也快不过搬数据的时间。这个模型来自 Williams 等人的 Roofline 论文，FlashAttention 引用了它。

示意图：A100 的 roofline，以及注意力相关操作各自在哪里（全部为推算）
怎么看：横轴是算术强度，纵轴是这个强度下最多能跑到的速度，两轴都是对数刻度；粗黑线是“屋顶”。圆点的位置是本站按 FP16（每个数 2 字节）粗算的：softmax 这类逐元素操作每读写 4 个字节只做几次运算，强度约为 1，远在斜坡的最底端；\(S=QK^{\top}\) 虽然是矩阵乘法，但内维只有 \(d=64\)，而输出是 \(N\times N\) 的大矩阵，强度约 57，也落在斜坡上；把标准注意力前向的三步合起来算，强度约 30。相比之下，4096×4096 的方阵乘法强度约 1365，稳稳在平顶上。FlashAttention 做的事情在这张图上就是“同样的运算量、少得多的字节”，把整个注意力往右推到拐点附近（约 186；这个数假设 SRAM 能放下约 10 万个数，见第 3、5 节的块大小与 IO 推导）。图中只计 HBM 读写和矩阵乘法的运算量，忽略了 L2 缓存、指数运算的开销等细节，用来看数量级。

这张图解释了为什么“减少 FLOPs”的近似方法常常不见效：如果一个操作本来就在斜坡上，它的耗时由读写量决定，计算量减半并不会让它快一倍；反过来，如果能大幅减少读写，哪怕多做一些计算，也会变快。FlashAttention 的反向传播正是后一种情况（第 4 节）。

2.3 内核融合：一次读入，做完多件事

加速访存受限操作最常用的办法是内核融合：如果对同一份输入要连续做好几个操作，就把它们写进同一个内核，输入只从 HBM 读一次，所有操作都在片上做完，再写回最终结果。编译器可以自动融合许多逐元素操作。

但在训练中，简单的融合效果有限：反向传播需要用到前向的中间结果，所以这些中间值仍然要写进 HBM 存起来。对注意力来说，这意味着即使把 mask、softmax、dropout 融合在一起，\(N\times N\) 的 \(P\) 还是得写出去，供反向使用。FlashAttention 后面用“重算”绕开了这个限制。

2.4 标准注意力：\(N\times N\) 的矩阵进出 HBM 几次

论文把标准实现写成 Algorithm 0，只有三步：

  1. 从 HBM 分块读入 \(Q\)、\(K\)，算出 \(S=QK^{\top}\)，把 \(S\) 写进 HBM。
  2. 从 HBM 读出 \(S\)，算 \(P=\mathrm{softmax}(S)\)，把 \(P\) 写进 HBM。
  3. 从 HBM 分块读入 \(P\) 和 \(V\)，算出 \(O=PV\)，把 \(O\) 写进 HBM。

\(N\times N\) 的矩阵在这里被写了两次、读了两次。如果还有 mask 和 dropout，每多一个逐元素操作，就要多一轮完整的读和写（除非把它们和 softmax 融合，已有工作就是这么做的）。而 \(S\)、\(P\) 本身要 \(O(N^2)\) 的显存。下面按 GPT-2 的尺寸算一下读写量：

3 核心算法：分块计算，用在线 softmax 拼出精确结果

这一节要回答的问题：要让 \(N\times N\) 的矩阵不进 HBM，就得把计算拆成能放进 SRAM 的小块。矩阵乘法很容易分块，难的是 softmax：它要用一整行的所有分数来归一化，而一块只能看到一行的一部分。FlashAttention 怎么一块一块地算，最后仍然得到和一次性算完整行完全相同的结果？块要切多大、按什么顺序扫？这一节是全文的核心，对应论文 §3.1 的前半部分和 Algorithm 1。

3.1 难点：softmax 把一整行绑在了一起

对一个长度为 \(B\) 的向量 \(x\)，softmax 的定义是 \(\mathrm{softmax}(x)_i=e^{x_i}/\sum_j e^{x_j}\)。分母要把整行所有元素的指数加起来，所以在看到最后一个元素之前，没法确定任何一个元素的最终值。论文的说法是：softmax 把 \(K\) 的各列“耦合”在了一起。如果只能一块一块地看 \(K\)，就必须想办法先算部分结果，之后再修正。

先补一点背景：为什么 softmax 要先减去最大值。

指数函数增长极快。FP16 能表示的最大数是 65,504，而 \(e^{11.1}\) 就已经超过它（推算：\(\ln 65504\approx11.09\)）。注意力分数稍大一点，直接算 \(e^{x}\) 就会溢出成无穷大。所以实际实现都用“安全 softmax”：先找出这一行的最大值 \(m\)，所有元素减去 \(m\) 再取指数。这样最大的那一项变成 \(e^0=1\)，其余都在 0 和 1 之间，不会溢出；而分子分母同乘了 \(e^{-m}\)，比值不变。论文把这个过程写成三个量：

$$m(x)=\max_{i}x_{i},\qquad f(x)=\big[e^{x_{1}-m(x)},\dots,e^{x_{B}-m(x)}\big],\qquad \ell(x)=\sum_{i}f(x)_{i},\qquad \mathrm{softmax}(x)=\frac{f(x)}{\ell(x)}$$

这里 \(m\) 是最大值，\(f\) 是减去最大值后的指数，\(\ell\) 是它们的和（归一化分母）。麻烦在于：安全 softmax 似乎比普通 softmax 更依赖整行，因为连最大值都要先扫完整行才知道。

3.2 在线 softmax：两块结果怎么合并

关键的观察是：只要每一块额外记住两个数（这一块的最大值 \(m\) 和指数和 \(\ell\)），两块的结果就能事后精确合并。设一行被切成两段 \(x^{(1)}\) 和 \(x^{(2)}\)，各自算出了 \(m\)、\(f\)、\(\ell\)。整行的最大值显然是两段最大值中较大的那个；而每一段的指数，原来是以自己的最大值为基准算的，现在只要乘一个修正系数 \(e^{m(x^{(k)})-m(x)}\)，就换成了以整行最大值为基准：

$$m(x)=\max\big(m(x^{(1)}),\,m(x^{(2)})\big),\qquad f(x)=\big[e^{m(x^{(1)})-m(x)}f(x^{(1)}),\ e^{m(x^{(2)})-m(x)}f(x^{(2)})\big]$$ $$\ell(x)=e^{m(x^{(1)})-m(x)}\,\ell(x^{(1)})+e^{m(x^{(2)})-m(x)}\,\ell(x^{(2)}),\qquad \mathrm{softmax}(x)=\frac{f(x)}{\ell(x)}$$

为什么乘这个系数就对了？因为 \(e^{x_i-m_1}\cdot e^{m_1-m}=e^{x_i-m}\)：先以 \(m_1\) 为基准算，再乘 \(e^{m_1-m}\)，结果和一开始就以 \(m\) 为基准算完全一样。由于 \(m\ge m_1\)，这个系数不超过 1，也不会溢出。这种“只保留几个汇总量就能把部分结果合并”的计算方式，论文脚注称之为代数聚合（algebraic aggregation，来自数据库里的 data cube 文献）；把它用在 softmax 上的想法，论文引用的是 Milakov 和 Gimelshein 2018 年的“在线归一化”工作，以及 Reformer、Rabe 和 Staats 等工作中的用法。

下面用一个小例子走一遍。一行只有 4 个分数，切成两块；为了顺便演示输出怎么合并，再给每个位置配一个一维的值 \(v\)：

3.3 把 V 也带上：输出的增量更新

注意力要的不是 softmax 本身，而是 softmax 权重乘上 \(V\) 之后的输出 \(O\)。上面的例子已经展示了怎么做：输出也是一种“加权和”，同样可以先以块内最大值为基准累加，合并时乘修正系数。论文的 Algorithm 1 选择在每处理一块之后都保持 \(O_i\) 是已经归一化好的，更新公式是（第 12 行）：

$$O_{i}\leftarrow \mathrm{diag}\big(\ell_{i}^{\mathrm{new}}\big)^{-1}\Big(\mathrm{diag}(\ell_{i})\,e^{m_{i}-m_{i}^{\mathrm{new}}}\,O_{i}\;+\;e^{\tilde{m}_{ij}-m_{i}^{\mathrm{new}}}\,\tilde{P}_{ij}V_{j}\Big)$$

这个式子看着复杂，拆开就是四个动作，每个都对应例子里的一步：

  1. 乘 \(\ell_i\)：撤销旧的归一化。旧的 \(O_i\) 已经除过旧的分母 \(\ell_i\)，先乘回来，变回“未归一化的加权和”。例子里是 \(12.689\times1.3679=17.358\)。
  2. 乘 \(e^{m_i-m_i^{\mathrm{new}}}\)：把旧结果换到新的最大值基准。例子里是 \(17.358\times0.3679=6.386\)。
  3. 加上新块的贡献 \(e^{\tilde{m}_{ij}-m_i^{\mathrm{new}}}\tilde{P}_{ij}V_j\)。\(\tilde{P}_{ij}\) 是新块以自己的最大值 \(\tilde{m}_{ij}\) 为基准算的指数，同样乘系数换到新基准。例子里是 \(1\times31.991\)，合计 38.377。
  4. 除以新的分母 \(\ell_i^{\mathrm{new}}\)。例子里是 \(38.377/1.5530=24.711\)。

这里的 \(\mathrm{diag}(\cdot)\) 只是“每一行乘或除以自己的那个数”的矩阵写法，因为块里有 \(B_r\) 行，每行有自己的 \(m\) 和 \(\ell\)。处理完所有块之后，\(O_i\) 就是精确的注意力输出。

顺带说一下数值上的安全性（本站的分析，论文没有单独讨论）。每一步取指数时，减去的都是“到目前为止见过的最大值”，所以指数的参数总是不大于 0，不会上溢；修正系数 \(e^{m_i-m_i^{\mathrm{new}}}\) 也不大于 1，只会把旧结果缩小。如果某一块的分数比之前见过的最大值小很多，这一块的指数会下溢成 0，但一次性算整行的安全 softmax 遇到同样的分数也会下溢，两者结果一致。所以分块并没有带来新的数值风险，这也是后面 GPT-2 训练曲线能和基线重合的前提。

3.4 分块：块切多大，按什么顺序扫

有了合并规则，就可以分块了。FlashAttention 把 \(Q\) 按行切成 \(T_r\) 块，每块 \(B_r\) 行；把 \(K\)、\(V\) 切成 \(T_c\) 块，每块 \(B_c\) 行。分数矩阵 \(S\) 因此被切成 \(T_r\times T_c\) 个小块，第 \((i,j)\) 块 \(S_{ij}=Q_iK_j^{\top}\) 的大小是 \(B_r\times B_c\)。

示意图：FlashAttention 前向的分块与循环顺序（论文 Algorithm 1 的顺序）
怎么看：中间的虚线网格是 \(N\times N\) 的分数矩阵，它只是一个“概念上的”表，从不完整地存在于任何地方。上方是 \(K\)、\(V\) 的块，左侧是 \(Q\) 的块，右侧是输出 \(O\) 和每行的统计量 \(\ell,m\)。外循环从左到右一次取一对 \(K_j,V_j\)（蓝色），在这一轮里它们一直留在 SRAM；内循环从上到下依次取每个 \(Q_i\)，与 \(K_j\) 算出一个小块 \(S_{ij}\)（橙色），用它更新对应的 \(O_i,\ell_i,m_i\) 后写回 HBM。右边的方框列出了某一时刻 SRAM 里的全部内容。图中 \(K\)/\(V\) 的块画得比 \(Q\) 的块宽，是因为论文的设定里 \(B_c\) 通常大于 \(B_r\)。本站示意图，对应 原文图 1 左 ↗。

块的大小由 SRAM 的容量 \(M\) 决定。论文取 \(B_c=\lceil M/4d\rceil\)，\(B_r=\min(\lceil M/4d\rceil,d)\)。附录 C 只给出了量级上的条件，本站对常数 4 的理解是：SRAM 里要同时放下 \(K_j,V_j\)（各 \(B_c\times d\)）和 \(Q_i,O_i\)（各 \(B_r\times d\)），四块加起来不能超过 \(M\)，所以每个块的行数大约是 \(M/4d\)；同时分数块 \(S_{ij}\)（\(B_r\times B_c\)）也要放得下，这要求 \(B_r\) 不能太大，于是再和 \(d\) 取较小值。举个例子，如果把 \(M\) 粗略取为 10 万个数、\(d=64\)，就有 \(B_c=391\)、\(B_r=64\)；对 \(N=1024\)，\(K,V\) 被切成 \(T_c=3\) 块，\(Q\) 被切成 \(T_r=16\) 块（推算）。

循环顺序是：外循环遍历 \(K,V\) 的块，内循环遍历 \(Q\) 的块。这样每个 \(K_j,V_j\) 只从 HBM 读一次；代价是 \(Q_i\)、\(O_i\)、\(\ell_i\)、\(m_i\) 在每一轮外循环里都要读一次、写一次，一共 \(T_c\) 遍。第 5 节会看到，HBM 访问量正是由这个 \(T_c\) 决定的。

3.5 逐行走一遍 Algorithm 1

  1. 第 1–4 行：准备。按上面的公式定块大小；在 HBM 里把 \(O\) 初始化为 0、\(\ell\) 初始化为 0、\(m\) 初始化为 \(-\infty\)（“还没见过任何分数”）；把 \(Q,K,V,O,\ell,m\) 都按块划分好。
  2. 第 5–6 行：外循环第 \(j\) 轮。把 \(K_j,V_j\) 从 HBM 读进 SRAM。
  3. 第 7–8 行：内循环第 \(i\) 轮。把 \(Q_i,O_i,\ell_i,m_i\) 读进 SRAM。
  4. 第 9 行：在片上算分数块 \(S_{ij}=Q_iK_j^{\top}\)，大小 \(B_r\times B_c\)。
  5. 第 10 行：对这个小块，算每行的最大值 \(\tilde{m}_{ij}\)、减去最大值后的指数 \(\tilde{P}_{ij}=\exp(S_{ij}-\tilde{m}_{ij})\)、每行的指数和 \(\tilde{\ell}_{ij}\)。这就是 3.2 节里“只看一块”的那一步。
  6. 第 11 行：合并统计量：\(m_i^{\mathrm{new}}=\max(m_i,\tilde{m}_{ij})\)，\(\ell_i^{\mathrm{new}}=e^{m_i-m_i^{\mathrm{new}}}\ell_i+e^{\tilde{m}_{ij}-m_i^{\mathrm{new}}}\tilde{\ell}_{ij}\)。
  7. 第 12 行：按 3.3 节的公式更新 \(O_i\)，写回 HBM。
  8. 第 13 行：把新的 \(\ell_i,m_i\) 写回 HBM。内循环、外循环都结束后，\(O\) 就是最终输出。

下面是本站用 NumPy 写的一个等价实现（单头，不含缩放、mask 和 dropout），只为说明逻辑，不代表 GPU 上的实际写法。本站核对过，它的输出与直接计算 \(\mathrm{softmax}(QK^{\top})V\) 的差别在 \(10^{-14}\) 量级，即浮点舍入误差。

import numpy as np

def flash_attention_alg1(Q, K, V, Bc, Br):
    # Q, K, V: [N, d]，看作放在 HBM 里
    N, d = Q.shape
    O = np.zeros((N, d)); l = np.zeros(N); m = np.full(N, -np.inf)
    for j in range(0, N, Bc):                  # 外循环：K/V 块
        Kj, Vj = K[j:j+Bc], V[j:j+Bc]          # 读入 SRAM，整个算法里只读这一次
        for i in range(0, N, Br):              # 内循环：Q 块
            Qi, Oi = Q[i:i+Br], O[i:i+Br]      # 读 Q_i、O_i、l_i、m_i
            li, mi = l[i:i+Br], m[i:i+Br]
            Sij = Qi @ Kj.T                    # [Br, Bc]，只在片上
            m_t = Sij.max(axis=1)              # 这一块的行最大值
            P_t = np.exp(Sij - m_t[:, None])   # 以块内最大值为基准的指数
            l_t = P_t.sum(axis=1)
            m_new = np.maximum(mi, m_t)
            a, b = np.exp(mi - m_new), np.exp(m_t - m_new)   # 两个修正系数
            l_new = a * li + b * l_t
            O[i:i+Br] = ((li * a)[:, None] * Oi + b[:, None] * (P_t @ Vj)) / l_new[:, None]
            l[i:i+Br], m[i:i+Br] = l_new, m_new  # 写回 HBM
    return O, l, m

3.6 一个内核做完，以及定理 1

因为每一步的数据都只有一小块，整个计算（矩阵乘、可选的 mask 和 dropout、softmax、再一次矩阵乘）可以放进一个 CUDA 内核：从 HBM 读输入，在片上做完所有步骤，只把结果写回 HBM。论文附录 E.4 说明，这个实现以 NVIDIA Apex 里的 FMHA 内核为起点；FMHA 本身已经把注意力融合成了一个内核，但它仍把注意力矩阵写进 HBM 供反向使用，而且只支持长度不超过 512、头维度 64、A100。

论文的定理 1总结了 Algorithm 1 的性质：它返回的正是 \(O=\mathrm{softmax}(QK^{\top})V\)；FLOPs 是 \(O(N^2d)\)，和标准实现同一个量级；除了输入输出之外只需要 \(O(N)\) 的额外显存，也就是每行的 \(\ell\) 和 \(m\)。正确性的证明（附录 C）用的是对外循环轮数 \(j\) 的归纳：每完成一轮外循环，HBM 里的 \(m,\ell,O\) 恰好等于“只用前 \(j\) 块 \(K,V\)”时的精确 softmax 统计量和注意力输出；做完全部 \(T_c\) 轮，就是完整的结果。

论文写法 vs 后来的实现Algorithm 1 把 \(K,V\) 放在外循环、\(Q\) 放在内循环，因此每处理一个小块都要把 \(O_i,\ell_i,m_i\) 读进来再写回 HBM。FlashAttention-2 论文（§3.2）指出，后来的做法把循环顺序反过来：外循环遍历 \(Q\) 的块，内循环遍历 \(K,V\) 的块，这样 \(O_i\) 和统计量可以一直留在片上，内循环结束才写一次；不同的 \(Q\) 块之间互不依赖，还能分给不同的线程块并行。FA2 论文说这个调换循环顺序、沿序列长度并行的想法最早由 Phil Tillet 在 Triton 的实现里提出。FA2 还把“每步都归一化”改成只在最后除一次 \(\ell\)，反向只存每行一个 logsumexp \(m+\log\ell\)，以减少非矩阵乘法的运算。读论文的 Algorithm 1 时把它当作分析用的形式更合适；本站没有核对 FA1 发布时 CUDA 代码的具体循环结构。
读的时候容易误解的地方：在线 softmax 和分块都不是这篇论文发明的，论文自己也称之为“两个成熟的技术”。这篇论文的贡献在于：把它们组合成一个以减少 HBM 读写为目标的内核，配上解析推导的反向传播（第 4 节），并给出 IO 复杂度分析（第 5 节）。在它之前，Rabe 和 Staats 已经用类似的分块做到了 \(O(N)\) 显存，但速度和标准实现差不多甚至略慢（第 4 节末尾比较了两者）。

4 反向传播：不存注意力矩阵，用的时候再算

这一节要回答的问题：训练时，反向传播通常要用前向算出的 \(N\times N\) 矩阵 \(P\)。如果为了反向把它存进 HBM，前向省下的读写和显存就白费了。FlashAttention 怎么在不存 \(P\) 的情况下算出梯度？多算一遍为什么反而更快？这一节对应论文 §3.1 的后半部分和附录 B。
先补一点背景：梯度检查点（重算）。

反向传播要用到前向的中间结果。最直接的做法是前向时全部存下来，代价是显存。另一种做法叫梯度检查点（gradient checkpointing）：前向只存一部分，反向需要时再把缺的部分重新算出来，用计算换显存。按以往的经验，这种做法总是更慢，因为多做了计算。论文强调，FlashAttention 的重算是个例外：多出的计算在 SRAM 里进行，省掉的却是 HBM 读写，所以反而更快。

4.1 标准反向要读写哪些 \(N\times N\) 矩阵

设损失对输出的梯度是 \(dO\)（形状 \(N\times d\)），要求 \(dQ,dK,dV\)。附录 B.4 把标准实现写成 Algorithm 3：

  1. 读 \(P\) 和 \(dO\)，算 \(dV=P^{\top}dO\)。
  2. 读 \(dO\) 和 \(V\)，算 \(dP=dO\,V^{\top}\)，写出 \(N\times N\) 的 \(dP\)。
  3. 读 \(P\) 和 \(dP\)，算 \(dS_{ij}=P_{ij}\big(dP_{ij}-\sum_{l}P_{il}dP_{il}\big)\)，写出 \(N\times N\) 的 \(dS\)。
  4. 读 \(dS\) 和 \(K\)，算 \(dQ=dS\,K\)；读 \(dS\) 和 \(Q\)，算 \(dK=dS^{\top}Q\)。

第 3 步的公式来自 softmax 的导数：如果 \(y=\mathrm{softmax}(x)\)，它的雅可比矩阵是 \(\mathrm{diag}(y)-yy^{\top}\)。整个过程要读 \(P\) 两次，还要写、读 \(dP\) 和 \(dS\) 两个新的 \(N\times N\) 矩阵。

4.2 FlashAttention 怎么做

前向结束时，FlashAttention 只存下这些东西：输出 \(O\)（\(N\times d\)）、每行的 \(\ell\) 和 \(m\)（各 \(N\) 个数）、以及 dropout 用的随机数生成器状态。反向时，对每一个小块，它在片上把需要的量重新算出来。附录 B.4 的 Algorithm 4 用了三个技巧：

  • 用统计量直接还原精确的 \(P\)。前向结束时 \(\ell_i\) 和 \(m_i\) 已经是整行的最终值，所以对任何一个小块，\(P_{ij}=\mathrm{diag}(\ell_i)^{-1}\exp(S_{ij}-m_i)\) 直接就是最终的注意力权重，不需要再做在线合并。重算 \(S_{ij}=Q_iK_j^{\top}\) 只用到片上的两个小块。
  • 把需要整行的那个求和换掉。\(dS\) 的公式里有 \(D_i=\sum_l P_{il}dP_{il}\)，它要对一整行（长度 \(N\)）求和，一行不一定放得进 SRAM。论文附录 B.2 推导出一个等价的形式：
$$D_{i}=\sum_{j}P_{ij}\,dP_{ij}=\sum_{j}P_{ij}\,(do_{i}^{\top}v_{j})=do_{i}^{\top}\Big(\sum_{j}P_{ij}v_{j}\Big)=do_{i}^{\top}o_{i}$$

也就是说，这个长度为 \(N\) 的求和恰好等于第 \(i\) 行输出梯度和输出的点积，只是两个长度为 \(d\) 的向量相乘。\(O\) 前向已经存下来了，所以 \(D_i\) 可以用 \(O_i\) 和 \(dO_i\) 在片上直接算，不再需要整行的 \(P\) 和 \(dP\)。有了它，\(dS_{ij}=P_{ij}\circ(dP_{ij}-D_i)\) 就可以逐块计算。

  • dropout 的掩码也不存，重新生成。dropout 需要一个 \(N\times N\) 的随机掩码，存下来又是 \(O(N^2)\) 的显存。FlashAttention 只存前向时随机数生成器的状态，反向时把状态恢复，按同样的顺序生成随机数，就得到一模一样的掩码。

4.4 和 Rabe 与 Staats（2021）有什么不同

附录 B.5 专门比较了一个非常接近的前人工作：Rabe 和 Staats 的《Self-attention Does Not Need \(O(n^2)\) Memory》。两者都用分块（softmax 缩放）避免存储完整的注意力矩阵，也都在反向时重算。区别有三点：

  • 目标不同。Rabe 和 Staats 关注的是显存的总占用（峰值需要多少显存），FlashAttention 关注的是显存的访问次数。论文认为访问次数才是决定耗时的主要因素，而且访问次数少必然意味着占用也少。结果是 FlashAttention 比标准实现快 2–4 倍，Rabe 和 Staats 的方法与标准实现速度相当或略慢。
  • 块之间传递信息的方式不同。Rabe 和 Staats 让每一块先各自保存一份临时输出和统计量，最后再统一合并，\(K\) 块就要 \(K\) 份临时输出；FlashAttention 每处理一块就增量更新唯一一份输出，所需显存更少。
  • 反向的做法不同。Rabe 和 Staats 用通用的梯度检查点，重算注意力矩阵和每一块的临时输出；FlashAttention 解析地化简了反向（上面的 \(D_i\) 技巧），只重算注意力矩阵，不重算临时输出。
读的时候容易误解的地方：“\(O(N)\) 额外显存”指的是输入、输出和梯度之外的额外部分，并且是按一个注意力头算的；\(Q,K,V,O\) 本身仍然是 \(O(Nd)\)。另外，“重算反而更快”成立的前提是注意力处在访存受限区。如果头维度 \(d\) 很大、SRAM 很小，块就得切得更小，读写的节省会变少（第 5 节和第 7 节会看到 \(d=128\) 和 T4 上加速变小）。

5 IO 复杂度：少了多少次读写，还能不能更少

这一节要回答的问题：前面用例子说明了 FlashAttention 读写更少，能不能把“少多少”精确地写成公式？公式里的 SRAM 大小 \(M\) 起什么作用？有没有可能设计出读写更少的精确注意力算法？这一节对应论文 §3.2 和附录 C 的证明。
先补一点背景：IO 复杂度。

通常说一个算法的复杂度，是数它做了多少次运算。IO 复杂度换了一个计数对象：假设有一块容量为 \(M\) 的快速存储和一块无限大的慢速存储，只数数据在两者之间搬了多少次，运算本身不计成本。这个模型来自 Aggarwal 和 Vitter 1988 年对排序等问题的分析，论文直接沿用。在这里，快速存储是 SRAM，慢速存储是 HBM，“一次访问”是读或写一个数。

定理 2：设序列长度为 \(N\)，头维度为 \(d\)，SRAM 大小为 \(M\)，且 \(d\le M\le Nd\)。标准注意力需要 \(\Theta(Nd+N^2)\) 次 HBM 访问，FlashAttention 需要 \(\Theta(N^2d^2M^{-1})\) 次。

标准注意力那一半很好理解：读 \(Q,K,V\)、写 \(O\) 是 \(Nd\) 量级，读写 \(S\) 和 \(P\) 是 \(N^2\) 量级（第 2.4 节的三步）。FlashAttention 那一半可以按 Algorithm 1 一步步数出来：

  1. 每个 \(K_j,V_j\) 只从 HBM 读一次，合计 \(\Theta(Nd)\)。
  2. 外循环有 \(T_c\) 轮，每一轮都要把整个 \(Q\) 读一遍、把整个 \(O\) 读写一遍，每轮 \(\Theta(Nd)\)，合计 \(\Theta(Nd\,T_c)\)。
  3. 块大小 \(B_c=\Theta(M/d)\)，所以外循环轮数 \(T_c=N/B_c=\Theta(Nd/M)\)。
  4. 代入得 \(\Theta(Nd\cdot Nd/M)=\Theta(N^2d^2/M)\)。

两者相比，当 \(N\) 远大于 \(d\) 时，标准实现由 \(N^2\) 项主导，比值大约是 \(M/d^2\)。论文说典型的 \(d\) 是 64–128、\(M\) 约 100 KB，\(d^2\) 比 \(M\) 小很多倍，所以 FlashAttention 的访问次数少很多倍。代入数字感受一下：\(d=64\) 时 \(d^2=4096\)，若 \(M\) 取 10 万个数，比值约 24；\(d=128\) 时 \(d^2=16384\)，比值只剩约 6（推算，忽略常数）。这正好解释了附录 E.5 的观察：头维度 128 时加速变小，SRAM 更小的 T4 上加速也更小。

这个比值还有一个值得注意的推论：当 \(N\) 远大于 \(d\) 时，它和 \(N\) 无关。也就是说，FlashAttention 并不会因为序列更长而“越来越划算”，节省的倍数会趋于一个由 \(M/d^2\) 决定的常数，只是绝对节省的时间随 \(N^2\) 增长。实验数据也大致符合这个规律（本站的解读）：附录表 11 里，FlashAttention 相对 PyTorch 标准实现的加速，从序列长度 128 时的约 2 倍，增长到 1K–4K 时稳定在约 3.3 倍（推算）。短序列时加速较小，是因为 \(Nd\) 那一项和内核启动之类的固定开销占比较大。

对照实测：第 2.4 节按 Algorithm 1 估算的前向读写量是标准实现的约六分之一；论文图 2 左实测的前向加反向 HBM 读写是 40.3 GB 对 4.4 GB，约 9 倍。论文摘要里“少 9 倍”的说法就来自这里。

论文图 2 中间进一步验证了块大小的作用：固定序列长度 1024、头维度 64，把 \(B_c\) 从 64 增大到 512，外循环轮数变少，HBM 访问量随之下降，前向耗时也下降；但块大小超过 256 之后，耗时不再明显下降，因为瓶颈变成了其他因素（比如运算本身），而且更大的块也放不进 SRAM 了。

命题 3（下界）：对 \(M\in[d,Nd]\) 中的所有取值，不存在 HBM 访问次数为 \(o(N^2d^2/M)\) 的精确注意力算法。证明很短：取 \(M=\Theta(Nd)\)，此时 \(N^2d^2/M=\Theta(Nd)\)；而任何算法至少要把 \(Q,K,V\) 读进来、把 \(O\) 写出去，这本身就是 \(\Omega(Nd)\) 次访问。所以如果某个算法对所有 \(M\) 都比 \(N^2d^2/M\) 渐近地更少，在 \(M=\Theta(Nd)\) 这一点就会少于读输入的量，矛盾。

这个“最优”要读得很仔细：命题 3 只说明不存在一个在所有 SRAM 大小上都渐近更好的算法，它的证明只用到了 \(M\) 大到能放下整个输入的那个极端情形。对于实际的 \(M\)（约 100 KB，远小于 \(Nd\)），论文并没有证明 \(\Theta(N^2d^2/M)\) 是下界；作者自己也说，按 \(M\) 参数化的下界留作未来工作，并指出这种“只在一个子区间成立的下界”在流算法文献中很常见。所以摘要里的“对一定范围的 SRAM 大小是最优的”是一个比较弱的结论。另外，IO 复杂度只数访问次数，不考虑常数、计算量和并行度；FlashAttention-2 后来正是在这些被忽略的地方又快了一倍。

6 扩展：块稀疏 FlashAttention

这一节要回答的问题：第 1 节说近似注意力“减了 FLOPs 却不快”，是因为忽略了访存。那么把 FlashAttention 的 IO 感知思路用到近似注意力上，能不能让稀疏注意力真正变快？论文用块稀疏注意力做了一个概念验证。
先补一点背景：稀疏注意力。

稀疏注意力让每个 token 只关注一部分 token，而不是全部。比如只看附近的一个窗口，或者按某种固定的图案跳着看。被跳过的位置，分数直接设为 \(-\infty\)，softmax 之后权重为 0。这样理论上计算量可以从 \(N^2\) 降下来。但它改变了模型（不再是精确的注意力），而且如果稀疏的图案是零散的单个位置，GPU 很难高效地跳过它们；按整块跳过则容易得多。

论文定义：给定一个 \(N\times N\) 的 0/1 掩码 \(\tilde{\mathbf{M}}\)，掩码为 0 的位置分数设为 \(-\infty\)，再做 softmax 和乘 \(V\)。并且要求掩码是块状的：按 \(B_r\times B_c\) 的块来看，每一块要么全是 1、要么全是 0，于是可以用一个小得多的块掩码 \(\mathbf{M}\in\{0,1\}^{N/B_r\times N/B_c}\) 来描述。

算法（附录 D.1 的 Algorithm 5）和 Algorithm 1 完全一样，只多了一个判断：内循环里如果块掩码 \(\mathbf{M}_{ij}=0\)，就整块跳过，不读 \(Q_i\)，不算，也不写回。

示意图：块稀疏 FlashAttention 只处理掩码为 1 的块
怎么看：左边是一个 8×8 的块掩码，每个方格代表一个 \(B_r\times B_c\) 的分数块；绿色是要算的块，斜纹是跳过的块。这里随手构造了一个“块下标的二进制异或为 0、1、2 或 4 时保留”的图案，让它有点像论文使用的蝴蝶（butterfly）稀疏结构，并不是原文的具体图案。这个例子里一半的块被跳过，按命题 4，主要那一项 HBM 读写也大约减半。本站示意图；原文图 2 右给出的是实测：序列长度 4K 时，块稀疏 FlashAttention 的耗时随非零块比例成比例下降，见 原文图 2 右 ↗。

命题 4：设非零块的比例为 \(s\)，块稀疏 FlashAttention 需要 \(\Theta(Nd+N^2d^2M^{-1}s)\) 次 HBM 访问。也就是说，IO 复杂度里大的那一项直接乘上了稀疏比例；\(Nd\) 那一项还在，是因为不管多稀疏，输出 \(O\) 总要写出去。对很长的序列，常见的稀疏设定是 \(s=N^{-1/2}\) 或 \(s=N^{-1}\log N\)，代入后 IO 复杂度分别变成 \(\Theta(N\sqrt{N})\) 和 \(\Theta(N\log N)\)（把 \(d\)、\(M\) 看作常数）。

一个很常见的特例是语言模型用的因果 mask：每个 token 只能看它前面的 token，分数矩阵的上三角全部被遮掉。按块来看，对角线以上的块整块都是 0，不需要计算，大约一半的块被省掉，相当于 \(s\approx1/2\)。附录 E.5 提到，A100 上头维度 128 时 FlashAttention 的加速整体变小，但用因果 mask 时仍能达到约 3 倍，原因就是一半的块被整块遮掉。

下游实验用的是固定的蝴蝶稀疏图案，出自同一研究组此前的 Pixelated Butterfly 工作；论文引用的理论结果表明，蝴蝶矩阵的组合可以近似任意的稀疏结构。在 Long-Range Arena 上，块稀疏 FlashAttention 比标准注意力快 2.8 倍，准确率相当（第 7 节表 3）。

读的时候要注意：一是符号重名：论文里 \(M\) 既表示 SRAM 大小，又表示块掩码 \(\mathbf{M}\)，读公式时要看清是哪个。二是块稀疏 FlashAttention 是近似注意力，换上它等于换了模型；而且稀疏图案是事先固定的，不是根据内容学出来的。三是在短序列上它没有优势：附录表 20（无 dropout、无 mask）里，序列长度 128 时块稀疏版本耗时 0.74 毫秒，反而比稠密的 FlashAttention（0.31 毫秒）慢；加速只在序列变长、非零块比例变小时才显现。

把前向和反向分开看，还能看出重算的代价。附录表 18、19 是不含 dropout 与 mask 的前向、反向耗时：长度 4096 时，前向 PyTorch 16.47 毫秒、FlashAttention 8.42 毫秒，快约 2.0 倍；反向 33.87 对 21.57 毫秒，只快约 1.6 倍（推算）。反向的加速更小，是因为它要在片上重算 \(S\) 和 \(P\)，而且 \(dQ\) 要在每一轮外循环里读写一次 HBM（第 4 节）。这和附录 E.4 中“前向比 FMHA 略快、反向略慢”的观察是一致的。

“最多快 3 倍”是在什么条件下测的：上面的耗时图带 dropout 和 mask。附录表 20 是同样的测试去掉 dropout 和 mask：长度 2048 时，PyTorch 13.22 毫秒、FlashAttention 7.64 毫秒，只快约 1.7 倍；带上 dropout 和 mask 时是 31.75 对 9.56 毫秒，约 3.3 倍（均为推算）。原因是标准实现每多一个逐元素操作就多一轮 \(N\times N\) 的读写，而 FlashAttention 把它们都融合在片上，额外成本很小。附录 E.5 也说，加了 dropout 和 masking 时加速更明显。所以如果你的模型不用 dropout、也不需要 mask，应参考较低的那个数。

7.4 附录里的补充：和 Apex FMHA 比，换不同的 GPU

和 Apex FMHA 比。FMHA 是项目开始时作者所知最快的注意力实现，几乎所有在 NVIDIA GPU 上提交的 MLPerf BERT 都在用它，但它只支持长度不超过 512、头维度 64、A100。在 BERT-large 的尺寸下（批大小 64，16 个头，头维度 64，带 mask 和 dropout），FlashAttention 的前向比 FMHA 略快，反向略慢（因为要重算注意力矩阵）；前向加反向合计，长度 128 时慢约 4%，256 时快约 8%，512 时快约 5%。FlashAttention 额外支持头维度 16、32、64、128，以及当时所有的 Turing 和 Ampere 架构 GPU，序列长度可到 64K。

换不同的 GPU。加速比取决于 HBM 带宽和 SRAM 大小：

  • A100，头维度 64：一般是 2–4 倍，加了 dropout 和 mask 时更多。
  • A100，头维度 128：每个块占的空间更大，只能用更小的块，加速整体变小；但用因果 mask（一半的块被整块跳过）时仍能到 3 倍左右。
  • RTX 3090：2.5–4.5 倍，比 A100 还高一些，因为它的显存带宽更低（约 900 GB/s 对 A100 的 1.5 TB/s），访存受限更严重，省读写的收益更大。
  • T4：SRAM 比 A100 小，块只能切得更小，加速更少，和第 5 节的 IO 复杂度分析一致。T4 常用于推理，所以论文也单独报告了只跑前向的加速。

8 局限、相关工作与可能的扩展

这一节要回答的问题：作者自己认为这个方法有哪些不足？IO 感知的思路还能用到哪里？这篇论文在已有工作中处于什么位置？这一节合并了论文 §5、附录 A 的相关工作和附录 D.2 的扩展讨论。

作者列了三条局限和方向：

  • 要手写 CUDA。每出现一种新的注意力变体，就要重新写一个 CUDA 内核。这需要用比 PyTorch 底层得多的语言，工程量很大，而且写好的内核不一定能移植到其他 GPU 架构上。作者希望有一种方法，能用 PyTorch 这样的高级语言写注意力算法，再自动编译成 IO 感知的 CUDA 实现，就像图像处理里的 Halide 那样。
  • IO 感知不止于注意力。注意力是 Transformer 里最吃内存访问的部分，但深度网络的每一层都要读写 HBM。附录 D.2 举了两个例子：稀疏的 MLP 层往往是访存受限的，加速比远低于稀疏程度，IO 感知的实现可能改善这一点；核方法里的 \(N\times N\) 核矩阵和注意力矩阵一样，每个元素都由两个长度为 \(d\) 的向量算出，可以反复读入输入、按需重算，KeOps 库就是这样做的。
  • 多 GPU。FlashAttention 在单张 GPU 上是常数意义下最优的，但大模型训练常把注意力拆到同一节点的 4–8 张 GPU 上。这时存储层次又多了一层（其他 GPU 的 HBM），IO 分析需要把 GPU 之间的数据传输也算进去。

相关工作方面，论文把自己放在四条线索的交汇处：一是 IO 复杂度、数据局部性、roofline 等由来已久的存储层次分析；二是结构化矩阵（稀疏、低秩、蝴蝶矩阵等），它们理论上高效，但很难把理论上的效率变成实际的加速，块稀疏 FlashAttention 用的蝴蝶图案就来自这条线；三是稀疏训练，比如剪枝和彩票假设，块稀疏 FlashAttention 可以看作在注意力上固定了一张“彩票”；四是各种高效 Transformer（Reformer、Performer、Longformer、BigBird 等）和替代注意力的序列模型（如 S4）。

读的时候要注意：“在单张 GPU 上常数意义下最优”是作者在 §5 里的说法，它依赖第 5 节那个比较弱的下界，并且只针对 HBM 访问次数这一个指标。后来的 FlashAttention-2 在同样的 IO 量级下又快了约 2 倍，说明在 IO 之外，并行方式和计算单元的利用率同样重要。

9 后来怎么样了

FlashAttention 很快成了注意力计算的默认实现。官方仓库的采用列表记录了它被整合进 PyTorch、HuggingFace Transformers、DeepSpeed、Megatron-LM、MosaicML Composer、GPT-NeoX、PaddlePaddle 等框架；PyTorch 2.0 推出的 scaled_dot_product_attention 就利用了 FlashAttention 的融合内核。仓库还记录了它在 MLPerf 训练 2.0（2022 年 6 月）和 2.1（2022 年 11 月）中帮助实现了云实例上最快的 BERT 训练。截至 2026-10-19，Dao-AILab/flash-attention 有约 2.5 万个 star。

在算法上，后续三代都保留了这篇论文的核心（分块、在线 softmax、反向重算、从不把 \(N\times N\) 矩阵写进 HBM），每一代解决的是新一代硬件上暴露出来的新瓶颈：

示意图：FlashAttention 四代的主线
FA1 · 2022-05A100；IO 感知：分块 + 在线 softmax + 反向重算；约 25–40% 峰值→FA2 · 2023-07A100；重新划分并行与 warp 分工；50–73% 峰值→FA3 · 2024-07H100；异步、warp 专业化、FP8→FA4 · 2026-03B200；应对指数单元与共享内存成为瓶颈
怎么看：从左到右按时间排列，每个方框写了发布时间（arXiv 首版）、主要面向的 GPU 和这一代的核心改动。“峰值”指 GPU 理论最大 FLOPs/s 的百分比，FA1 的 25–40% 和 FA2 的 50–73% 都是 FA2 论文摘要给出的数字。本站示意图。
  • FlashAttention-2（Tri Dao 单独署名，arXiv 2023-07，ICLR 2024）。FA2 论文指出 FA1 只达到 A100 理论峰值的 25–40%，远不如矩阵乘法，原因是线程块和 warp 之间的工作划分不够好。它做了三处改动：减少非矩阵乘法的运算（A100 上 FP16 矩阵乘法峰值 312 TFLOPS，非矩阵乘法的 FP32 运算只有 19.5 TFLOPS，每次非矩阵乘法运算的代价相当于 16 次矩阵乘法运算）；即使只有一个头，也沿序列长度切分给不同的线程块，提高 GPU 的占用率；在线程块内部把 \(Q\) 而不是 \(K,V\) 分给各个 warp，免去 warp 之间通过共享内存的通信。结果比 FA1 快约 2 倍，达到 A100 峰值的 50–73%，端到端训练 GPT 类模型可达每张 A100 225 TFLOPs/s（模型 FLOPs 利用率 72%）。
  • FlashAttention-3（Shah、Bikshandi、Zhang、Thakkar、Ramani、Dao，arXiv 2024-07，NeurIPS 2024）。FA2 在 H100 上只能用到 35% 的算力，因为它没有利用 Hopper 架构的新能力。FA3 利用 Tensor Core 和 TMA（张量内存加速器）的异步执行：用 warp 专业化让数据搬运和计算重叠，让分块的矩阵乘法和 softmax 交错执行；再用块量化和非相干处理（incoherent processing）支持 FP8 低精度。arXiv 版摘要报告：H100 上比 FA2 快 1.5–2.0 倍，FP16 最高 740 TFLOPs/s（75% 利用率），FP8 接近 1.2 PFLOPs/s，FP8 的数值误差比基线 FP8 注意力低 2.6 倍。NeurIPS 正式版摘要的数字更高：BF16 最高 840 TFLOPs/s（85% 利用率），FP8 达到 1.3 PFLOPs/s。两版数字不同，引用时要注明版本。
  • FlashAttention-4（Zadouri、Hoehnerbach、Shah、Liu、Thakkar、Dao，arXiv 2026-03，MLSys 2026）。Blackwell 架构（B200、GB200）的 Tensor Core 吞吐翻倍，而共享内存带宽和指数运算单元的吞吐增长更慢或不变，于是瓶颈从矩阵乘法转移到了 softmax 的指数运算和共享内存。FA4 重新设计了完全异步的流水线并使用更大的块，用软件模拟一部分指数运算并有条件地跳过 softmax 的重缩放，反向则利用张量内存（TMEM）和 2-CTA 矩阵乘法模式减少共享内存流量和原子加。arXiv 摘要报告：B200、BF16 下比 cuDNN 9.13 最多快 1.3 倍，比 Triton 最多快 2.7 倍，最高 1613 TFLOPs/s（71% 利用率）；它整个用嵌在 Python 里的 CuTe-DSL 编写，编译速度比传统的 C++ 模板方式快 20–30 倍。这也部分回应了本文第 8 节“要手写 CUDA”的局限。详见本站的 FlashAttention-4 拆解页。

想看 FA1–FA3 的可交互架构图、FA2 顺序的分步演示和配套简答题，见结构拆解页。推理服务方面，FlashInfer 在 FlashAttention 式的分块内核之上，用块稀疏格式统一了分页 KV 缓存等各种布局；vLLM 精读页讲的则是注意力内核之外的另一半问题：KV 缓存的显存管理。
