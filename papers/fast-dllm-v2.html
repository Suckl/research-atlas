0 导读：这篇论文解决什么问题

今天的大语言模型几乎都是自回归（autoregressive，AR）模型：从左到右一次写一个 token，每写一个就要把整个模型算一遍。这种写法质量好、工程上也成熟，但一次只出一个 token，意味着回答越长越慢，而且一次只服务一个用户时，GPU 的算力大部分时间在等数据。扩散语言模型（diffusion LLM，下文简称 dLLM）提供了另一种写法：先在答案的位置放一排 [MASK]，再反复让模型去猜，每一轮可以同时定下好几个位置。理论上它能比自回归快，可开源的 LLaDA、Dream 实际跑起来往往更慢：它们用双向注意力，没法像自回归模型那样把算过的 key/value 存起来复用；而从零训练这样一个模型又非常贵，LLaDA 8B 用了 2.3T token。

Fast-dLLM v2 走的是一条折中的路。它不从零训练，也不像 Dream 那样用 5800 亿 token 把自回归模型改成全注意力的扩散模型，而是把现成的 Qwen2.5-Instruct 改造成块扩散模型：把输出切成每块 32 个 token，块与块之间仍然从左到右，所以写完的块可以像自回归一样被精确地缓存；块内部用掩码扩散，所以一块里可以一步定下好几个 token。因为这种结构离原来的自回归模型很近，改造只需要一段很短的监督微调（SFT）。摘要说约 10 亿（1B）token；附录给出的精确数字是 7B 模型约 13.1 亿、1.5B 模型约 31.5 亿。训练上有三个要点：把每条样本补齐到块长的整数倍、互补掩码、token shift。推理上，作者把块级精确缓存、块内置信度阈值并行解码和“子块缓存”叠在一起，后者是把前作 Fast-dLLM 的 DualCache 搬进了块内。

主要结果有两组。质量上，7B 模型在 9 列基准上平均 60.3 分，与“同样的数据、同样的步数、做普通自回归微调”的 Qwen2.5-7B（59.6）相当。速度上，在 A100、一次一条请求、GSM8K 上，它每秒约生成 100 个 token，约是 Qwen2.5-7B-Instruct 的 2.5 倍；批大小增加到 64 时，倍数降到 A100 上 1.5、H100 上 1.8。读这些数字要记住三件事，第 10 节会展开：质量表是在“每步只定稿 1 个 token”（阈值 1，不并行）下测的，2.5 倍的速度则来自阈值 0.9；平均分里代码题占了 9 列中的 4 列，而 Fast-dLLM v2 恰好在代码上领先、在 MATH 和 IFEval 上明显落后；速度对手用的是什么推理实现，论文没有说明。

1 引言：自回归太慢，扩散模型又用不上缓存，块扩散能不能两头都占

这一节要回答的问题：自回归模型一次只能写一个 token，速度天生受限；扩散语言模型号称能并行，实际却常常更慢，还很难灵活地决定写多长。作者认为块扩散能同时缓解这两边的问题，但此前的块扩散只在小模型上验证过。这一节交代：两种写法各自卡在哪里，块扩散为什么能兼得，Fast-dLLM v2 打算怎样把它做到 7B 规模，而且训练很便宜。
先补一点背景：自回归模型为什么慢，KV 缓存又是什么。

自回归模型写第 \(i\) 个 token 时，要用注意力去看前面所有 token 在每一层的 key 和 value 向量。因为它的注意力是因果的（每个位置只看左边），前面 token 的 key/value 一旦算出来就不会再变，推理系统于是把它们存起来，这份存储叫 KV 缓存。有了它，每写一个新 token 只需要为这一个位置做计算。可是每一步仍然要把全部参数从显存读一遍，只为算出一个 token；一次只服务一个用户时，GPU 的大部分时间花在搬数据上，算力闲着。所以自回归的瓶颈在于“一步只出一个”。KV 缓存的来龙去脉见本站 vLLM 精读 §2.2。

再补一点背景：掩码扩散语言模型怎么写字，为什么用不上 KV 缓存。

掩码扩散模型（LLaDA、Dream 等）先在答案的位置放一排 [MASK]，每一轮让模型对所有 [MASK] 位置同时给出预测，把其中有把握的几个定下来，剩下的下一轮再猜。它用双向注意力：每个位置既看左边也看右边。这带来一个麻烦：每定下一个 token，其他所有位置的中间结果都会跟着变，所以前一轮算出的 key/value 下一轮就过时了，不能像自回归那样精确地复用，每一轮都得把提示和整段答案重算一遍。前作 Fast-dLLM 利用“相邻几轮的 key/value 变化很小”这一观察做近似，强行复用缓存（见 Fast-dLLM 精读 §3）；但近似毕竟和原来的计算不等价，这正是本文想从根上解决的地方。

再补一点背景：块扩散。

块扩散（BD3-LM）把序列切成长度为 \(D\) 的块（本文 \(D=32\)），整句话的概率写成各块条件概率的乘积：

$$p_\theta(x)=\prod_{b=1}^{B}p_\theta\big(x^{b}\mid x^{<b}\big)$$

其中 \(x^{b}\) 是第 \(b\) 块，\(x^{<b}\) 是它前面的所有块，\(B\) 是块的个数。块与块之间按顺序生成，像自回归；每一块内部则用掩码扩散去噪。这样一来，注意力在块与块之间是因果的：写第 \(b\) 块时，前面的块已经定稿，它们的 key/value 不会再变，可以精确缓存；块内部是双向的，可以一步定稿多个位置。块长 \(D=1\) 时它退化成自回归，\(D\) 等于整个序列时就是全序列扩散，所以块长是在两者之间调节的旋钮。详见本站 BD3-LM 精读。

论文的引言先把两边的问题摆出来。自回归模型一次只能出一个 token，没法利用并行。扩散语言模型理论上可以一次预测、修改很多个 token，但实际有三个毛病：因为双向注意力，往往用不好 KV 缓存；推理延迟常常比自回归还高；很多模型还要事先固定生成长度，不够灵活。Fast-dLLM 的 DualCache 这类近似缓存能省掉不少重复计算，但作者指出，近似缓存与原来的计算并不等价，并没有从根上解决“双向模型与 KV 缓存不兼容”的问题。

块扩散正好同时缓解这几点：块间因果带来精确的块级 KV 缓存；一块写完再写下一块，写到结束符就可以停，不必事先固定长度。问题是 BD3-LM 只在小模型、只用困惑度这类传统语言建模指标验证过，放到今天的大模型和真实任务上能不能保住生成质量、能不能扩展，此前并不清楚。

Fast-dLLM v2 的回答是：不从零训练，而是把预训练好的自回归模型直接改造成块扩散模型。作者强调它的数据效率：Dream 这类全注意力扩散模型需要五千亿量级的 token 来改造，而 Fast-dLLM v2 只用约 1B token 的微调，就能做到“无损”改造。作者给出的原因是：块状的注意力结构比 Dream 的全注意力更接近原来的自回归模型，所以改造天然更顺、更省数据。训练配方上，它把块扩散与互补掩码结合；推理上，它设计了两级缓存：块级缓存保存已完成块的上下文，子块缓存（沿用 Fast-dLLM 的 DualCache）让未完成的块内部也能高效地并行解码。论文列出的三条贡献依次是：一种只需微调的 AR → 块扩散改造方法（约 1B token，对比 Dream 约 500B）；分层缓存加块内并行解码的推理策略；在最大 7B 的模型和多种任务上的实验，速度最高是标准自回归解码的 2.5 倍，质量相当。

读的时候要注意的几个数字：
  • “约 1B token”指的是 7B 模型。附录 A.1 写明：上下文 2048、批 256，每步 524,288 个 token；7B 训练 2,500 步，约 1.31B token；1.5B 训练 6,000 步，约 3.15B token。这里数的是打包后的全部位置，包括提示和补齐用的填充，真正算损失的 token 更少（本站推断）。
  • “比 Dream 少 500 倍”：摘要写 Dream 用了 580B token，580 ÷ 1.31 ≈ 443（推算）。更重要的是两者不在同一个阶段：Dream 是在基座模型上做大规模继续预训练，Fast-dLLM v2 是在已经做完后训练的 Instruct 模型上只做 SFT，而且改造的目标（块长 32 的块扩散）离自回归近得多。第 2 节会讲为什么这个差别很关键。
  • “最高 2.5 倍”是 A100、批大小 1、GSM8K 上和 Qwen2.5-7B-Instruct 比的结果；批大小 64 时降到 1.5 倍（A100）和 1.8 倍（H100），见第 8 节。

2 相关工作：三条工作线，以及“改造为什么便宜”

这一节要回答的问题：Fast-dLLM v2 站在哪几条工作线的交汇处？同期还有谁在做“把自回归模型改成块扩散”？已有的扩散模型加速方法分哪两类，本文用了其中哪些？另外有一个论文没有展开、但读懂全文必须先想清楚的问题：为什么改造一个现成的自回归模型，会比从零训练一个扩散模型便宜几个数量级？

2.1 三条工作线

掩码扩散语言模型。离散数据上的扩散最早由 Sohl-Dickstein 等人和 Hoogeboom 等人提出；D3PM 用一般的转移矩阵定义离散的加噪过程，CTMC 把它推广到连续时间，SEDD 改为估计两个序列的概率之比。其中最常用的一支是掩码扩散（也叫吸收态扩散）：训练时按比例 \(t\) 随机把 token 换成 [MASK]，\(t=0\) 是原文，\(t=1\) 是整句全遮。它已经做到了 7B 规模：LLaDA 从零开始训练，Dream 则从 Qwen2.5-7B 改造而来。本站有 D3PM、SEDD、MDLM、LLaDA、Dream 的精读页。

介于自回归和扩散之间的方法。SSD-LM 最早把高斯扩散做成按块生成；AR-Diffusion 在它的基础上加了从左到右的噪声调度；对掩码扩散，BD3-LM 用“块内扩散、块间从左到右”在两者之间插值。与本文同期，SDAR 也从预训练的自回归模型微调出了块扩散模型（本站 SDAR 精读，两者的区别见第 12 节）；D2F 借鉴 Diffusion Forcing 和 CausVid，把一个大的扩散模型蒸馏成更高效的块扩散模型（D2F 精读）；Set Block Decoding 把下一个 token 预测和掩码 token 预测放进同一个网络，一次生成多个 token。作者认为自己与这些同期工作的区别在于数据效率：只需约 1B token 的微调。

扩散语言模型的加速。一类是缓存：Fast-dLLM 的 DualCache 同时缓存前缀和后缀 [MASK] 的 KV；dKV-Cache 等一个 token 定稿之后才缓存它（dKV-Cache 精读）；dLLM-Cache 缓存提示，并自适应地决定每一步回答部分重算多少；Sparse-dLLM 按注意力分数丢掉不重要的缓存项；DPad 只让注意力看最近一小段后缀。另一类是解码策略：Fast-dLLM 的置信度阈值并行解码；EB-Sampler 按熵的上界决定一步揭开几个；Dimple 动态调整每步的 token 数；WINO 先激进地起草、再用双向上下文把可疑的位置重新遮住；SlowFast Sampling 在探索和加速两种阶段之间切换；LaViDa 试了时间步偏移；Temporal Self-Consistency Voting 汇总多个去噪步的预测；Prophet 判断何时可以把剩下的位置一步全部定稿。本文在推理时直接沿用了 Fast-dLLM 的两件工具：DualCache 和阈值并行解码。

ICLR 2026 正式版在这一节末尾加了一段：块扩散也能和自回归模型的加速技术（比如投机解码）结合。DiffuSpec 用 Dream-7B 这样的扩散模型给 Qwen2.5-32B 当草稿模型，得到 3.1 倍加速；作者说 Fast-dLLM v2-7B 比 Dream-7B 快近 10 倍（依据图 1a），拿它当草稿模型是一个值得做的方向。后来的 DFlash 正是用块扩散模型来做投机解码的草稿器。

2.2 为什么改造一个自回归模型，比从零训练扩散模型便宜几个数量级

先想清楚：训练到底在“教”模型什么。

一个语言模型的能力，绝大部分来自预训练：在海量文本上学到的词汇、语法、事实和推理模式，都存在权重里。Qwen2.5 的预训练用了 18T token。从零训练一个扩散模型，就要把这些全部重新学一遍，所以 LLaDA 8B 用了 2.3T token，LLaDA 论文的结论是它与同规模的 LLaMA3 8B 大致相当。

如果从一个训练好的自回归模型出发，知识已经在权重里了，要教的只是“换一种用法”。这种改造要花多少数据，取决于新用法离旧用法有多远：

  • 改成全注意力扩散（Dream）：距离远。自回归模型第 \(i\) 个位置的表示只依赖左边的内容，所有层都是这样训练出来的。改成全注意力之后，每个位置突然能看到右边，而右边大部分是 [MASK]；模型还要学会在任意位置、任意遮挡比例下补全。几乎每一层的内部表示都得重新适应，所以 Dream 用了 580B token 的继续预训练。
  • 改成块长 32 的块扩散（本文）：距离近。块与块之间仍然是因果的，和原模型完全一样；只有每 32 个 token 的小窗口内部变成双向，而且窗口里有一部分是 [MASK]。再加上 token shift（第 4 节）保留了“每个位置的输出预测下一个 token”这一约定，输出头也不用重新学。新任务只是旧任务的一个小扩展。
  • 起点是 Instruct 模型。Fast-dLLM v2 从 Qwen2.5-Instruct 出发，这个模型已经做过监督微调和强化学习（Dream 论文引用的数字是约 100 万条 SFT 数据加 15 万条 RL 数据，见 Dream 精读 §5.3）。所以本文的 SFT 主要是教它“按块填空”这一新格式，而不是从头教它听指令、做数学。

这三点合起来，解释了为什么 SFT 规模的数据就够了。代价是：块长被固定在 32 附近，模型只学会了“小窗口里的并行”，得不到全序列扩散那种任意顺序生成、全局修改的能力。本站 LLaDA2.0 精读 讲了另一种折中：从块长 1 开始逐级放大到全序列再缩回 32，在 100B 规模上完成改造。

3.1 预备知识：自回归与掩码扩散各自在优化什么

这一节要回答的问题：自回归模型和掩码扩散模型的训练目标分别是什么？掩码扩散损失里的 \(1/t\) 是什么意思？这两个式子是理解 Fast-dLLM v2 训练目标的起点：它的损失介于两者之间，而且去掉了 \(1/t\)。

记一段 token 序列为 \(x=\{x^1,\dots,x^L\}\)。自回归模型按顺序建模条件分布 \(P_\theta(x^i\mid x^{<i})\)，训练时最小化交叉熵：

$$\mathcal L_{\text{AR}}(\theta)=-\sum_{i=1}^{L}\log P_\theta\big(x^{i}\mid x^{<i}\big)$$

每个 token 恰好贡献一项损失，这一点后面会用到。

掩码扩散模型先定义一个前向的加噪过程：取一个时间 \(t\in(0,1)\)，把原文 \(x_0\) 的每个 token 独立地以概率 \(t\) 换成 [MASK]，得到 \(x_t\)。反向模型 \(p_\theta(x_0\mid x_t)\) 看着被遮的句子，猜回原来的 token。训练目标是：

$$\mathcal L(\theta)=-\,\mathbb E_{t,\,x_0,\,x_t}\Big[\frac{1}{t}\sum_{i=1}^{L}\mathbf 1\big[x_t^{i}=\texttt{[MASK]}\big]\log p_\theta\big(x_0^{i}\mid x_t\big)\Big],\qquad t\sim\mathrm{Uniform}(0,1)$$

损失只在被遮住的位置上算。\(1/t\) 的作用可以这样理解：遮挡比例为 \(t\) 时，平均只有 \(tL\) 个位置被遮，求和里只有这么多项；乘上 \(1/t\) 之后，每种遮挡比例下的损失在量级上都相当于 \(L\) 个 token。例如 \(L=10\)、\(t=0.3\)，平均 3 个位置被遮，乘上 \(1/0.3\approx 3.3\) 后相当于 10 个位置（推算）。更重要的是，MDLM 等工作证明了带 \(1/t\) 的这个式子是负对数似然的一个上界，所以训练它就是在做最大似然；推导见 MDLM 精读。

记住两点，后面要用：第一，LLaDA 这类掩码扩散模型在位置 \(i\) 上预测的是位置 \(i\) 自己的 token，自回归模型在位置 \(i\) 上输出的却是对下一个 token 的预测，两者“输出对准哪个位置”的约定不同，这就是 4.4 节 token shift 要处理的问题。第二，Fast-dLLM v2 的训练目标去掉了 \(1/t\)，所以它不再是这个似然上界，作者给的理由在 4.5 节。

4.2 块对齐的打包：别让一块横跨两条样本

先补一点背景：序列打包。

SFT 数据里的样本长短不一。如果每条样本单独占一行、用填充补到上下文长度，会浪费大量计算。常见的做法是打包：把很多条样本首尾相接拼成一条长流，再按固定长度（这里 \(L=2048\)）切成训练序列。对自回归模型来说这样做问题不大，因为因果注意力只看左边，最多是后一条样本的开头能看到前一条样本的末尾（很多实现还会额外加文档掩码把它挡住）。

块扩散的块内是双向注意力，打包就会出问题：如果一条样本的结束符 <EOS> 和下一条样本的开始符 <BOS> 落在同一块里，两条毫不相干的样本就会在这一块里互相“看见”，前一条样本的结尾能看到后一条样本的开头，作者称之为跨样本泄漏。Fast-dLLM v2 的做法很简单：打包之前，先在每条样本末尾补 [MASK]，把它的长度补到块长 32 的整数倍。这些填充位置不算损失、不产生梯度。补齐之后再打包、切成长 2048 的序列，每条序列自然分成 \(L/D=64\) 个块（推算），块边界一定和样本边界对齐。

4.3 互补掩码：让每个 token 都被监督到

对每一块，随机抽一个 0/1 向量 \(m\in\{0,1\}^{D}\)，\(m_j=1\) 表示第 \(j\) 个位置换成一个可学习的 [MASK] 嵌入。如果只用这一个视图训练，一条样本里只有被遮住的那部分位置会产生损失，没被遮住的位置这一次什么也没学到；遮挡比例在 0 到 1 之间均匀抽取时，平均只有一半的 token 得到监督（推算）。

互补掩码的做法是：把每条训练样本复制成两份，一份用掩码 \(m\)，另一份用它的“反面” \(\bar m=1-m\)，两份放进同一个批里一起训练。这样，在这一对视图里，每个位置恰好被遮一次（产生一项损失），也恰好被看见一次（给别的位置当上下文）。这个技巧来自多模态扩散模型 LaViDa（本站 LaViDa 精读）。直观地说，它把“遮哪些位置”的随机性用到了极致：同一条样本的两半互相当答案、互相当提示，既不浪费数据，也减小了梯度的随机波动（和蒙特卡洛方法里的对偶采样是同一种思路）。

它的代价是计算量：每条样本要过两遍网络。在数据少的场景里，这笔交易很划算；数据很多时就未必。LLaDA2.0 的报告在脚注里提到，他们在继续预训练中也试过互补掩码，发现只在语料少于 100B token 时有效。Fast-dLLM v2 只用 1–3B token，正好落在有效的范围里。

4.4 token shift：被遮的位置，用前一个位置的输出去预测

先补一点背景：输出“对准”哪个位置。

自回归模型在位置 \(i-1\) 的最后一层隐状态，经过输出头之后给出的是对第 \(i\) 个 token 的预测，这个约定贯穿了它全部的预训练。LLaDA 这类从零训练的掩码扩散模型则约定：位置 \(i\) 的输出预测位置 \(i\) 自己。如果把自回归模型改成后一种约定，所有层、尤其是靠近输出的几层，都要重新学习“对准”另一个位置。Dream 的实验表明，保留原来的约定（Dream 称之为 shift）对用自回归模型初始化至关重要，见 Dream 精读 §4.1。

Fast-dLLM v2 也保留了这个约定，论文称为 token shift：如果位置 \(i\) 被遮住，就用位置 \(i-1\) 的隐状态（经输出头得到的 logit）来预测 \(x_i\)。这和因果语言模型的下一个 token 预测完全一致，作者认为这能让改造后的模型保留自回归式的表示，同时支持块内扩散。据官方代码，这一点是直接复用 Hugging Face 因果语言模型的损失函数实现的：那个函数本来就会把标签向左挪一位，再与每个位置的输出对齐。

这个约定有两个不太直观的推论。第一，被遮住的位置自己的输出，预测的是它后面那个位置的 token；如果后面那个位置也被遮了，这个 [MASK] 位置的输出就负责猜它。第二，每一块的第一个 token 要靠上一块最后一个位置的输出来预测。推理时这一点正好变得很方便：上一块定稿后写缓存的那次前向，最后一个位置的输出直接给出下一块的第一个 token（第 5 节）。

4.5 训练目标：只在被遮的位置算交叉熵，而且没有 \(1/t\)

论文的训练目标是：

$$\mathcal L_{\text{block}}(\theta)=-\,\mathbb E_{x,\,m}\Big[\sum_{i=1}^{L}\mathbf 1\big[x_t^{i}=\texttt{[MASK]}\big]\log p_\theta\big(x_0^{i}\mid x_{<i},\,x_{\text{block}(i)}\big)\Big]$$

这里 \(x_{\text{block}(i)}\) 是位置 \(i\) 所在块的全部 token（包括被遮的和没被遮的），\(x_{<i}\) 是前面各块的干净 token。也就是说：预测某一块里被遮的位置时，模型能看到前面所有块的原文，加上本块被部分遮住的样子。

和 3.1 节的掩码扩散损失相比，这里没有 \(1/t\)。附录 A.3 承认这看起来少了一个系数，并解释说这是有意为之，理由是互补掩码：每条样本总是成对出现，一个视图用 \(m\)（相当于遮挡比例 \(t\)），另一个用 \(1-m\)（相当于 \(1-t\)），两个视图的损失加起来

$$-\Big[\sum_{i=1}^{L}\mathbf 1\big[x_t^{i}=\texttt{[MASK]}\big]\log p_\theta(\cdot)\Big]-\Big[\sum_{i=1}^{L}\mathbf 1\big[x_{1-t}^{i}=\texttt{[MASK]}\big]\log p_\theta(\cdot)\Big]$$

恰好包含 \(L\) 项，每个位置一项，不管 \(t\) 抽到多少。这样每对样本的损失量级是固定的，不需要再用 \(1/t\) 去拉平。

本站补充两点理解。第一，这个目标在形式上很像自回归的交叉熵：每个 token 恰好贡献一项，只是条件从“左边所有 token”换成了“前面各块的原文，加上本块里另一半没被遮的 token”。这和作者“保留 AR 训练目标”的说法是一致的。第二，去掉 \(1/t\) 之后，它就不再是 3.1 节那个负对数似然的上界了，严格来说已经不是最大似然目标；不过本文只关心生成质量、不报告困惑度，这一点不影响结论。据官方代码，实际的损失是对两个视图里所有被监督的 token 取平均，和论文的式子只差一个归一化常数。

4.6 一次前向训练所有块：加噪流、干净流与那张 \(2L\times2L\) 的掩码

先补一点背景：为什么要把干净序列也送进网络。

按上面的目标，预测第 \(b\) 块时，模型要看到前面各块的原文和第 \(b\) 块的加噪版本。最笨的做法是对每一块单独做一次前向，一条序列有 64 块就要 64 次，太慢。BD3-LM 的做法是把加噪序列 \(x_t\) 和干净序列 \(x_0\) 拼在一起，变成长 \(2L\) 的输入，再用一张特制的注意力掩码规定“谁能看谁”，一次前向就让每一块都以干净的前文为条件去噪（详见 BD3-LM 精读 §4.2）。Fast-dLLM v2 直接沿用了这个设计。

附录 A.2 把这张 \(2L\times 2L\) 的掩码写成四块：

$$\mathcal M_{\text{full}}=\begin{bmatrix}\mathcal M_{BD}&\mathcal M_{OBC}\\ 0&\mathcal M_{BC}\end{bmatrix}$$
  • 块对角 \(\mathcal M_{BD}\)（左上，加噪流看加噪流）：同一块里的加噪 token 互相可见，块内双向。块内去噪就发生在这里。
  • 错位块因果 \(\mathcal M_{OBC}\)（右上，加噪流看干净流）：加噪的第 \(b\) 块可以看干净流里第 1 到第 \(b-1\) 块，也就是前文的原文。“错位”指不包括自己这一块，否则它就直接看到了自己的答案。
  • 块因果 \(\mathcal M_{BC}\)（右下，干净流看干净流）：干净流里的每个 token 看自己这一块和前面所有块。它的作用是给加噪流准备“前文”的键和值，就像推理时逐块写 KV 缓存那样。
  • 左下全零：干净流看不到任何加噪 token，保证前文的表示不被噪声污染。

3.3 推理：块级缓存、块内并行、子块与子块缓存

这一节要回答的问题：训练好的模型怎样生成文字？块与块之间的缓存为什么是精确的？块内怎么决定一步定稿几个 token？论文说的“分层缓存”和“子块”具体是什么，各省掉了哪部分计算？最后算一笔账：平均每个 token 要几次前向，这决定了速度的上限。论文正文对推理只写了几段话，本站结合附录 A.2 和官方生成代码把流程走一遍。

5.1 块与块之间：和自回归一样精确的块级缓存

生成一块一块地进行。推理时的注意力掩码是：当前块内部双向，对前面的块因果，这和训练时干净流的块因果模式一致。所以一块写完以后，它的 key/value 不会再因为后面的内容而改变，可以作为只读的上下文缓存起来，供后面所有块使用。这就是块级缓存。和前作 Fast-dLLM 不同，这份缓存是精确的：它和不用缓存、每次整段重算得到的结果完全一样，因为模型本来就是按块因果训练的。

据官方代码，一块的流程是这样的。提示先做一次预填充（取块长的整数倍部分），写入缓存。每当当前块的所有位置都定稿，就把这一块再送进网络算一次，把它的 key/value 追加进缓存；这次前向最后一个位置的输出，按 token shift 的约定正好是对下一个 token 的预测，代码直接取其中概率最大的词作为下一块的第一个 token。所以每一块的第一个 token 实际上是“自回归式”写出来的，剩下的 31 个位置从 [MASK] 开始去噪。

5.2 块内：置信度阈值并行解码

块内的去噪沿用 Fast-dLLM 的置信度感知并行解码：每一步，模型对当前允许范围内所有还是 [MASK] 的位置给出预测；每个位置的置信度是它预测分布里最大的那个概率；置信度超过阈值 \(\tau\) 的位置全部定稿，其余的留到下一步；如果一个都没超过，就只定稿置信度最高的那一个，保证每步至少前进一个 token。为什么只定稿“有把握”的位置，以及背后的定理，见 Fast-dLLM 精读 §4。

两个取值要特别记住。\(\tau=1\) 时，没有哪个位置的概率会严格超过 1，所以每步恰好定稿 1 个，也就是完全不并行，按置信度的顺序一个一个填；论文的质量表（表 1）用的就是这个设置。\(\tau=0.9\) 是论文测速度时选的设置。论文 §4.2 说阈值设为 1 时“恢复为标准的非并行解码”，后半句又说所有 token 走完全部去噪步、只在最后定稿，这个说法容易误读：按官方代码，阈值 1 时每一步仍会定稿置信度最高的那 1 个位置，块内要走 31 步才填满。

5.3 子块：在 32 个位置里再分段推进

论文默认的推理设置是块长 32、子块大小 8。子块的意思是：当前块的 32 个位置被分成 4 段，每段 8 个；先只在第一段里按上面的规则定稿，第一段全部填满后再进入第二段，依此类推。后面几段在这期间仍然是 [MASK]，但它们仍然留在块里、参与注意力，块的形状和训练时完全一样，变的只是“这一步允许在哪些位置里挑”。

为什么不干脆把块长改成 8？因为模型是在块长 32 下训练的。直接改块长会改变注意力的模式：每个位置只能看到块内的 8 个邻居，前面已定稿的部分也变成每 8 个一块，这是模型训练时没见过的情形。第 9 节的消融会显示，这样做会明显掉点，而子块不会。

5.4 子块缓存：把 DualCache 搬进块内

先补一点背景：Fast-dLLM 的 DualCache。

在全注意力的扩散模型里，Fast-dLLM 写某一块的那几步，把块外所有位置（前面已定稿的部分和后面的 [MASK]）的 key/value 当作不变，直接从缓存里读，只重算当前块；这一块写完再整段重算一次，刷新缓存。它同时缓存了前缀和后缀，所以叫 DualCache。它是近似的：当前块里每定稿一个 token，块外位置的表示本来都该跟着变一点，只是变化很小。详见 Fast-dLLM 精读 §3.4。

在 Fast-dLLM v2 里，块外的前缀已经有了精确的块级缓存，DualCache 被用到了更小的尺度上：一个 32-token 块的内部。据官方代码，在一个子块里，只要它的第一个位置还是 [MASK]，每一步都把整块 32 个位置送进网络，同时存下块内所有位置的 key/value；一旦这个子块的第一个位置定稿，之后的迭代就只把这个子块的 8 个位置送进网络，块内其他 24 个位置（已定稿的前几段和还是 [MASK] 的后几段）的 key/value 直接读刚才存下的缓存。第一个子块的第一个位置总是由上一块的收尾前向直接给出，所以它只需要整块算一次。前缀缓存（精确）和块内缓存（近似）合在一起，就是论文说的分层缓存。

这里的近似只发生在一个 32-token 的块内部，范围比 Fast-dLLM 在整段答案上的近似小得多；论文的实验（图 6a）也显示它对准确率几乎没有影响。它省下的是计算量：子块内的迭代只算 8 个位置而不是 32 个。一次只服务一条请求时，GPU 的时间主要花在读参数上，算 8 个还是 32 个位置差别不大，所以几乎不加速；批很大、GPU 的算力被占满时，少算四分之三的位置就能明显提速（第 9 节）。

5.5 批量解码与一笔账：每个 token 要几次前向

批量解码。为了一次处理多条长短不同的请求，每条序列在右边补 [MASK]，补到块长的整数倍，然后所有序列一起逐块解码：每一步，批里每条序列都在写自己的下一块，不管它还剩多少真正的 token。据官方代码，一条序列写出结束符后，会在本块结束时被移出批，它的缓存也随之删除。

一笔账（推算）。以块长 32 为例。阈值为 1 时，块的第一个 token 来自上一块的收尾前向，剩下 31 个位置每步定稿 1 个，需要 31 次前向，再加 1 次收尾前向，一共 32 次前向产出 32 个 token，和自回归一样是“一次前向一个 token”。阈值为 0.9 时，图 4 标注每步平均定稿约 2.64 个 token，31 个位置大约需要 12 步，加上收尾约 13 次前向产出 32 个 token，平均每次前向约 2.5 个 token。

这笔账直接决定了加速的上限。一次只服务一条请求时，一次前向的耗时主要由读参数决定，处理 32 个位置和处理 1 个位置相差不多，所以块扩散的速度大约是自回归的“每次前向 token 数”倍。论文的数字正好吻合：阈值 1 时吞吐 39.1 token/秒（图 4），与 Qwen2.5-7B-Instruct 在 A100、批大小 1 时的 39.5（图 1b）几乎相同；阈值 0.9 时每步约 2.64 个，吞吐提高到 2.6 倍。反过来，当批很大、GPU 已经算力受限时，块扩散每次前向要处理的位置数是自回归的 32 倍（用子块缓存时是 8 倍），多出来的计算不再免费，优势就会缩小。第 8 节的批大小实验正好体现了这个规律。

4.2 主结果二：快了多少，在什么条件下

这一节要回答的问题：并行解码的阈值怎样在速度和准确率之间取舍？“2.5 倍”在批大小变大、换成 H100 时还剩多少？论文首页图 1 的那几个点，各是在什么条件下测的？

8.1 阈值：用多少准确率换多少速度

论文在 GSM8K 上扫了 0.5 到 1.0 的阈值（原文图 4）。阈值越低，每一步越多的位置能过阈值、被提前定稿，需要的步数越少，吞吐越高；代价是更多没把握的位置被一起定稿，准确率下降。作者选了 0.9：吞吐从 39.1 提高到 101.7 token/秒，即 2.6 倍，准确率只略有下降。

4.4 结果的份量：这些数字说明了什么、没说明什么

这一节要回答的问题：这一部分是本站补充的，不打分，只把每个结论背后“和谁比、在什么条件下比、哪些条件对齐了”说清楚。

和自回归模型比，对齐了什么。最有价值的对照是 Nemo-FT：同一个 Qwen2.5 起点模型、同样的 Nemotron 数据、同样的训练步数、同样的评测协议，只换训练目标和注意力结构。参数量和数据量两边完全相同，这个设计是公平的，也是本文最站得住的证据：在这种对齐下，块扩散改造的平均分与自回归微调相当。但有两处没有对齐。其一是计算量：Fast-dLLM v2 每条样本要过两个互补视图，每个视图是两倍长的双流输入，同样步数下送进网络的 token 约是自回归的 4 倍（推算）。其二是解码：Fast-dLLM v2 的分数是在阈值 1、即不并行时测的，那时它的速度和自回归差不多；2.5 倍速度对应的阈值 0.9 下，只报告了 GSM8K 一项。至于和 LLaDA、Dream 的比较，就不再对齐了：那几行数字来自各自的论文、各自的协议。

平均分是怎么算的。9 列平均里，HumanEval 和 MBPP 的 Base、Plus 各算一列，代码题占了 4/9 的权重。Fast-dLLM v2 恰好在代码上领先、在 MATH（−10.4）和 IFEval（−8.1）上明显落后。换成按 7 个基准平均，7B 上的次序就反过来了（约 60.5 对 61.8，推算）。所以更准确的说法是：改造后的 7B 模型在代码上更好，在数学竞赛题和指令遵循上更差，平均下来大致持平。

“约 1B token”与“500 倍”。7B 约 1.31B token、1.5B 约 3.15B token（附录 A.1），数的是打包后的全部位置。拿它和 Dream 的 580B 比，是 SFT 对继续预训练、块长 32 的块扩散对全序列扩散，两边做的不是同一件事。比较有意义的结论是：如果只需要一个块长固定、块间从左到右的扩散模型，从一个已经后训练好的 Instruct 模型出发，SFT 规模的数据就够了。

速度：硬件、批大小、对手。2.5 倍是 A100、批大小 1、GSM8K、阈值 0.9 下和 Qwen2.5-7B-Instruct 比的；批大小 64 时是 1.5 倍（A100）和 1.8 倍（H100）。论文没有说明自回归一侧用的是什么推理实现，也没有给出生成长度上限。有一个线索：Qwen2.5-7B 的 BF16 参数约 15 GB，A100 的显存带宽约 1.5–2 TB/s，单条请求的理论上限约为每秒 100–130 个 token（推算）；图里的自回归基线只有约 40 token/秒，约为上限的三分之一，说明基线是没有专门优化过的实现（比如 Hugging Face 的 generate）。这不代表比较不公平，Fast-dLLM v2 自己的官方代码也是基于 Hugging Face Transformers 的 PyTorch 实现；但它意味着在 vLLM、SGLang 这类做了 CUDA Graph、连续批处理等优化的推理引擎里，自回归的数字会高得多，结论需要在那样的环境里重新测。官方仓库 README 的待办清单里，“vLLM 支持”仍标为进行中（2026-10-20 查看）。

吞吐怎么数 token。官方评测代码 v2/eval.py 统计吞吐时，把生成部分里所有不是 [MASK] 的位置都算作生成的 token；而按 generation_functions.py，一条序列写出结束符后，同一块里剩下的位置会被替换成填充符（不是 [MASK]），因此也会被计入。每条序列最多多算约 31 个位置；相对于 GSM8K 几百 token 的回答，这可能让吞吐偏高几个到十几个百分点（本站读代码所见并推算；论文的图是否用这段代码统计，论文没有说明，自回归一侧怎么数也没有说明）。

图 1 的几处出入。见 8.3 节：Fast-dLLM v2 的点很可能把阈值 0.9 的速度和阈值 1 的准确率画在了一起；Qwen 的点与表 1 的 Nemo-FT 数字相同；LLaDA、Dream 的点沿用前作 5-shot 的设置。首页这张图适合当作直观印象，不适合当作定量证据。

基准的性质。七个基准都是标准的代码、数学、知识和指令遵循题，没有填空、反向生成、数独这类最能体现“非从左到右”优势的任务。这和本文的定位一致：块长 32 的块扩散在宏观上仍是从左到右写的，它要证明的是“能在不丢质量的前提下更快”，而不是“能做自回归做不了的事”。

样本量与随机性。所有评测都用贪心解码，结果基本是确定的，但论文没有报告多次训练的波动。HumanEval 164 题，1 题约 0.6 分；GPQA 是四选一，随机水平 25%，表里各模型在 24 到 37 之间。9.3 节还显示，仅仅改变批大小，准确率就能变 1–2 个点。综合来看，小于 1–2 个点的差距都应视为持平。

5 结论与附录：作者的总结、案例与正式版的补充

这一节要回答的问题：作者最后怎样概括自己的贡献？附录里的案例和 ICLR 正式版新增的实验补充了什么？

作者的结论是：Fast-dLLM v2 是一个可扩展的块扩散语言模型框架，能把预训练好的自回归模型改造成高效的扩散式解码器；块扩散机制配合互补掩码，让模型在块内获得双向上下文，同时保留原自回归模型的预测能力；分层缓存（块级缓存复用块间上下文，基于 DualCache 的子块缓存加速块内迭代）配合并行解码，在 Qwen2.5-Instruct 1.5B 和 7B 上做到最高 2.5 倍于标准自回归解码的速度，质量与强自回归基线相当，效率超过以往的扩散方法。作者认为这说明块扩散是部署高质量、低延迟大模型的一条实用路线。

附录 B 的案例。作者给了 7B 模型的几段对话：单轮的有一道求有理函数垂直渐近线条数的数学题（分解分母、求零点，答 2 条）和一段用递归解汉诺塔的 Python 代码；多轮的有一段关于 NVIDIA 成立年份和周年计算的问答，以及一道分两轮问的运货趟数与总耗时的应用题。这些例子说明模型能保持多轮上下文、给出格式规范的分步推理，但它们是挑选出来的展示，不构成定量证据。

后来怎么样了

Fast-dLLM v2 于 2025-09-30 上传 arXiv，官方仓库在 2025-10-08 宣布开源代码与模型，2026 年 1 月与前作 Fast-dLLM 一起被 ICLR 2026 接收。截至 2026-10-19 的 Semantic Scholar 快照，它被引用 148 次。它代表的“从自回归模型出发、改成块扩散”这条路线，之后成了扩散语言模型的主流做法之一：

  • 同一团队的后续。官方仓库后来加入了 Fast-dVLM（arXiv 2604.06832），把同样的思路直接用在视觉语言模型 Qwen2.5-VL 上，README 称最高比自回归基线快 6.18 倍；以及面向自动驾驶的 Fast-dDrive（arXiv 2605.23163）。这两项的数字都是作者自述。
  • 更大规模的改造。LLaDA2.0 在 16B 和 100B 的 MoE 模型上做 AR → 块扩散改造，最终块长同样是 32，SFT 阶段也用了互补掩码；它的报告指出互补掩码只在数据少于 100B token 时有用，正好解释了它为什么适合 Fast-dLLM v2 这种小数据的场景。
  • 同期的其他改造。SDAR 走“继续预训练 + SFT”的路线并扩展到 30B MoE，其开源模型后来成为强化学习工作 TraDo 的底座（见旧版 TraceRL / TraDo）；D2F 用蒸馏得到块因果的扩散模型，并让多个块流水线式地同时解码。
  • 把块扩散当草稿器。ICLR 版提到的“用块扩散模型给自回归模型起草”这条思路，后来由 DFlash 做成了投机解码的草稿器，并进入了 vLLM、SGLang 等推理引擎。
