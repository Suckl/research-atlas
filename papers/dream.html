0 导读：这篇论文解决什么问题

今天几乎所有大语言模型都是自回归（autoregressive，下文简称 AR）模型：从左到右，每次根据前面已经写出的内容预测下一个 token（词或词的一部分），一个接一个地往后写。扩散语言模型换了一种生成方式：先准备一张写满“空白”（[MASK]）的画布，然后反复地看整张画布、猜出其中一部分空白该填什么，几轮之后把整段话填满。因为每一轮都能同时看到左右两边的内容，而且一轮可以填好几个位置，人们期待它在需要“通盘考虑”的任务上更强，并且能用更少的轮数生成，从而更快。

问题在于训练成本。2025 年初，LLaDA 从零训练出了一个 8B 规模、能和 LLaMA3 8B 相提并论的扩散语言模型，用了 2.3T 个 token。与此同时，开源社区已经有大量花巨资训好的 AR 模型，例如在 18T token 上训练的 Qwen2.5。于是一个很自然的想法是：能不能不从零开始，而是拿一个现成的 AR 模型做底子，只继续训练一段时间，就把它改造成扩散模型？港大 NLP 组参与的 DiffuLLaMA（2024）已经在 7B 规模上做过这件事，但改造出的模型在知识类任务上掉得很厉害。

Dream 7B 把这条路线推到了实用水平。它用 Qwen2.5-7B 的权重初始化，原样保留 AR 模型“在位置 \(i\) 预测第 \(i+1\) 个 token”的输出约定（称为 shift），然后在 580B 个 token 上用掩码扩散的目标继续训练；训练时还把“同一条序列里所有被遮住的 token 共用一个权重”改成按每个 token 周围有多少已知内容来分别定权重，作者称为 CART。按作者自己统一重测的结果，Dream 7B 在通用、数学、代码任务上和它的出发点 Qwen2.5 7B 接近，全面高于从零训练的 LLaDA 8B；在数独、Countdown 这类规划任务上则大幅领先同规模的 AR 模型（数独 81.0 对 21.0）。

1 引言：为什么还要做扩散语言模型

这一节要回答的问题：既然 AR 模型已经非常强，为什么还要研究另一种生成方式？作者认为 AR 模型在复杂推理、长程规划和长文本的前后一致性上有先天的局限，而扩散模型的“看全局、多轮修改”正好可能弥补这些局限。但到 2025 年初，扩散语言模型在常规基准上还明显落后于 Qwen2.5 这样的顶级 AR 模型。这一节交代动机，并说明 Dream 想填补的就是这个差距。
先补一点背景：自回归模型为什么只能“边写边想”。

AR 模型把一整句话的概率拆成一串条件概率的乘积：先猜第 1 个 token，再在第 1 个 token 已知的条件下猜第 2 个，依此类推。训练时，模型内部用一个“因果掩码”保证每个位置只能看到它左边的内容；生成时，它每写一个 token 就把它接到输入末尾，再写下一个。这种方式的好处是训练信号密集、生成过程简单，配合 KV 缓存（把前面 token 的中间结果存下来，见 vLLM 精读）推理也很高效。

代价是写下去的 token 不能改，而且写某个 token 时看不到后面还没写出来的部分。如果一道题的前半部分答案取决于后半部分的约束（比如数独里第一格填什么，取决于后面几格），AR 模型只能要么在“脑子里”先把后面想清楚，要么先写出来再用思维链（chain-of-thought）的方式回头修正。

作者从两个方面论证扩散模型值得研究。第一是能力上的：扩散模型每一轮都能同时利用左右两边的上下文，理论上更容易生成前后一致的内容，也更适合需要同时满足多个约束的规划问题。第二是灵活性上的：生成是“多轮修改”，所以可以方便地加入控制条件，还可以通过调整轮数（步数）在速度和质量之间权衡，这给“测试时多花计算换质量”提供了一个新维度，可以和长思维链这类做法互补。

作者也承认差距：DiffuLLaMA 和 LLaDA 已经把离散扩散做到了 70–80 亿参数，商业公司 Inception Labs 的 Mercury Coder 展示了很快的代码生成速度，但在通用基准上，开源扩散模型和 Qwen2.5 这类顶级 AR 模型还有明显距离。Dream 7B 的目标就是缩小这个差距，同时展示扩散模型特有的能力。论文的贡献可以概括为三条：一套“用 AR 模型初始化 + 上下文自适应噪声重排”的训练方法；一个在常规任务上接近同规模 AR 模型、在规划任务上明显更强的 7B 模型；开源 Base 和 Instruct 两个版本的权重。

关于时间线：Dream 先以博客形式在 2025-04-02 发布，2025-04-05 放出权重和推理代码，技术报告直到 2025-08-21 才上传到 arXiv，但报告首页印的日期仍是 2025-04-02。所以报告里“迄今最强的开源扩散大语言模型”这类说法，对应的是 2025 年 4 月的情况。

读的时候要注意：引言里“AR 模型在推理、规划和长文本一致性上有先天局限”是作者引用他人工作提出的动机，不是这篇论文要证明的结论。这篇论文给出的直接证据只有第 5 节的三个规划任务（Countdown、数独、旅行规划）；它们的输出都很短，而且评测时不允许 AR 模型写思维链。

2 相关工作：扩散语言模型怎么走到 70 亿参数

这一节要回答的问题：把扩散模型用到文字上，经历了哪几步？“从零训练”和“从 AR 模型改造”这两条路线分别是谁在走？Dream 直接继承了哪项工作的哪些做法？论文本身的相关工作写得很简短，这里把对理解 Dream 最关键的前身 DiffuLLaMA 单独展开讲。

2.1 从连续扩散到掩码扩散

扩散模型最早是在图像这类连续数据上成功的：给图片逐步加高斯噪声，再训练网络一步步去噪。最先搬到文字上的做法是在词向量空间里加连续噪声（例如 Diffusion-LM），但文字本身是离散的，最后还得把向量“取整”回词，效果和效率都不理想。于是 Austin 等人的 D3PM 等工作提出直接在离散的词表上定义加噪过程：要么把 token 换成一个特殊的 [MASK]（称为吸收态，因为一旦变成 [MASK] 就不会再变回去），要么换成随机的其他 token（称为均匀态）。之后，SEDD 改进了离散扩散的训练目标，在 GPT-2 规模上做到了与 AR 模型相当、部分数据集上更好的困惑度；MDLM / MD4、RADD 等工作则把吸收态（也就是掩码）扩散的目标化简成一个加权的交叉熵，第 3 节会讲这个形式。

再往后是规模化。Nie 等人先在 1.1B 规模上展示了掩码扩散模型能做问答等任务；Gong 等人的 DiffuLLaMA 走“从 AR 模型改造”的路线，把 GPT-2 和 LLaMA-2 改成了扩散模型；同期的 LLaDA 走“从零训练”的路线，训练出 8B 模型，表现和 LLaMA3 8B 有来有回。Dream 的作者团队此前还做过 RDM（重参数化离散扩散）、扩散模型上的思维链（Diffusion of Thoughts），以及《Beyond Autoregression》——后者在小规模、专门训练的设定下发现扩散模型在规划任务上明显强于 AR 模型。Dream 第 5 节用的 Countdown 和数独任务就来自这篇工作。

2.2 前身 DiffuLLaMA：第一次把 7B 的 AR 模型改成扩散模型

DiffuLLaMA（Gong 等，arXiv 2410.17891，ICLR 2025）提出的问题和 Dream 完全一样：既然开源社区已经有训好的 AR 模型，能否只做一段继续预训练，就把它变成扩散模型？作者指出 AR 模型和掩码扩散模型之间有两处结构上的不匹配，并给出了三个对策。

  • 注意力不匹配，对策是“注意力掩码退火”。AR 模型用因果掩码，每个位置只看左边；扩散模型要求双向注意力。如果一下子把因果掩码去掉，模型内部的表示会突然面对从没见过的输入分布。DiffuLLaMA 的做法是在训练初期逐渐放开“看右边”的权限，直到变成全注意力（GPT-2 版用了 1 万步）。
  • 输出位置不匹配，对策是“保留 shift”。AR 模型在位置 \(i\) 输出的是对第 \(i+1\) 个 token 的预测；常规掩码扩散模型在位置 \(i\) 预测的是第 \(i\) 个 token 本身。DiffuLLaMA 不去改这个约定，而是把输出整体错开一格来对齐训练目标。这正是 Dream 沿用的做法，第 4.1 节详细讲。
  • 不加时间嵌入。很多扩散模型会把当前噪声水平 \(t\) 作为额外输入告诉网络。DiffuLLaMA 认为对掩码扩散来说，网络数一数有多少个 [MASK] 就能推断出 \(t\)，而 AR 模型本来也没有这一层，所以干脆不加，保证网络结构和原 AR 模型完全一样。

它的数据规模不大：GPT-2 版（DiffuGPT）用 FineWeb 中随机抽取的 300 亿 token、训练了不止一轮（有效 token 超过 1000 亿）；LLaMA-2-7B 版（DiffuLLaMA）从 SlimPajama 和 Starcoder 按 7:3 抽了 650 亿 token，上下文长度 2048，在 16 个各含 4 张 GH200 的节点上训练，学习率恒定为 2e-5。7B 版为了能用 FlashAttention-2，干脆跳过了退火，直接用全注意力。

它在 GPT-2 上做的消融实验，是后来 Dream 敢于“只保留 shift”的依据。实验是在 GSM8K 的符号化增强数据上微调，比较不同的改造方式：

3 预备知识：自回归和掩码扩散各自怎么建模一句话

这一节要回答的问题：AR 模型和掩码扩散模型分别把“一句话的概率”拆成什么样的计算？掩码扩散的训练目标为什么是一个“只在被遮住的位置上算、并且乘了 \(1/t\)”的交叉熵？这个目标和似然是什么关系？第 4 节的两个改动（shift 和 CART）都是在这个目标上动手，所以要先把它讲透。

3.1 自回归：从左到右的条件概率

设一条序列是 \(\mathbf{x}=(x^{1},\dots,x^{N})\)，长度为 \(N\)（论文用 \(N\) 表示序列长度，本页沿用）。AR 模型把它的概率写成：

$$p_{\theta}(\mathbf{x})=p_{\theta}(x^{1})\prod_{n=2}^{N}p_{\theta}\big(x^{n}\mid x^{1:n-1}\big)$$

每一项都只以左边的内容为条件，所以论文把它称为“逐步的左侧上下文预测”。训练时，模型在每个位置都做一次“猜下一个 token”，整条序列的每个位置都提供训练信号。

3.2 掩码扩散：先遮住，再学着还原

先补一点背景：掩码扩散的“加噪”就是随机遮词。

图像扩散的加噪是往像素上叠高斯噪声；文字没法这样做，掩码扩散的加噪就是把一部分 token 换成 [MASK]。用一个连续的“时间” \(t\in[0,1]\) 表示噪声水平：\(t=0\) 时序列完全干净，\(t=1\) 时全部是 [MASK]。在时刻 \(t\)，每个 token 独立地以概率 \(t\) 被换成 [MASK]，以概率 \(1-t\) 保持原样（论文写作噪声调度 \(\alpha_{t}=1-t\)，\(\alpha_{t}\) 是 token 保持原样的概率）。一旦变成 [MASK]，它在更大的 \(t\) 下也一直是 [MASK]，所以叫“吸收态”。

反向过程就是生成：从全是 [MASK] 的序列出发，网络每次看着当前这张部分被遮住的画布，预测被遮住的位置原本是什么，把其中一部分填上，\(t\) 逐步减小到 0。网络只需要学会一件事：给定一张部分被遮住的序列 \(\mathbf{x}_{t}\)，输出每个被遮位置上原 token 的概率分布 \(p_{\theta}(x_{0}^{n}\mid\mathbf{x}_{t})\)。

训练时，对每条训练序列随机抽一个 \(t\)，按上面的规则遮住一部分 token，让网络预测被遮住的那些，计算交叉熵。论文把这个目标写成：

$$L(\theta)=-\,\mathbb{E}_{\mathbf{x}_{0}\sim q(\mathbf{x}),\;t\sim\mathcal{U}(0,1),\;\mathbf{x}_{t}\sim q(\mathbf{x}_{t}\mid\mathbf{x}_{0})}\;w(t)\sum_{n=1}^{N}\mathbf{1}\big[x_{t}^{n}=[\mathrm{M}]\big]\,\log p_{\theta}\big(x_{0}^{n}\mid\mathbf{x}_{t}\big)$$

读这个式子要抓住三点。第一，示性函数 \(\mathbf{1}[x_{t}^{n}=[\mathrm{M}]]\) 表示只在被遮住的位置上算损失，没被遮住的位置答案已经摆在输入里，不需要学。第二，网络看到的是整条带 [MASK] 的序列，用的是双向注意力。第三，前面乘了一个只和 \(t\) 有关的权重 \(w(t)\)；当噪声调度取 \(\alpha_{t}=1-t\) 时，\(w(t)=1/t\)。

先补一点背景：\(1/t\) 从哪来，它和似然有什么关系。

生成模型最想优化的是数据的负对数似然 \(-\log p_{\theta}(\mathbf{x}_{0})\)。扩散模型的似然要对所有可能的“遮住—还原”路径求和，没法直接算。标准做法是推导一个变分上界（负 ELBO）：它一定大于等于负对数似然，所以把它压低，似然也会被推高。对掩码扩散，这个上界在连续时间下恰好化简成上面的加权交叉熵，权重是 \(-\alpha_{t}'/(1-\alpha_{t})\)；代入 \(\alpha_{t}=1-t\)，就得到 \(1/t\)。论文说明这个形式引自 Shi 等人和 DiffuLLaMA 的推导。

直观地看，\(1/t\) 做了一件“记账”的事：在时刻 \(t\)，平均有 \(tN\) 个 token 被遮住；每个乘上 \(1/t\) 后，总权重平均是 \(N\)，与 \(t\) 无关（推算）。所以无论抽到哪个噪声水平，一条序列对总损失的贡献大致一样多；而在 \(t\) 很小时被遮住的那一两个 token，每个都分到很大的权重。被遮得少，意味着这个 token 周围几乎全是已知内容，相当于“低噪声”的样本。

由此还有一个重要推论：扩散模型报告的“困惑度”通常是从这个上界算出来的，只是真实困惑度的上界；AR 模型的困惑度则是精确值。两者不能直接比大小。

为了理解后面 DiffuLLaMA 和 Dream 的做法，还有一个角度很有用：AR 模型可以看成一种特殊的扩散模型。设想一个“加噪”过程，它不随机遮词，而是从右往左、确定性地一次遮一个；那么对应的“去噪”过程就是从左往右一次填一个，共 \(N\) 步，它的训练目标就是普通的下一个 token 交叉熵（DiffuLLaMA §3.2 引 Austin 等人的论证）。一般的掩码扩散则允许以任意顺序、一次多个地填。这说明两类模型的目标在形式上很接近，差别在于：AR 只看左边、目标错开一格、每个位置都算损失；掩码扩散看两边、目标在原位、只在被遮位置算损失并乘以 \(1/t\)。改造 AR 模型时要处理的，就是这几处差别。

两个小地方：原文 §3.2 有一句说加噪过程在 \(t=T\) 时“完全去噪”（fully denoised），按上下文应是“完全被遮住”。另外，原文 §3.2 先用离散时间 \(t\in(0,T)\) 介绍，再说明实际采用连续时间 \(t\in[0,1]\)，因为离散时间只允许几个固定的噪声水平；后文的公式都是连续时间的写法。

4 方法：用 AR 权重起步，再按上下文给每个 token 定权重

这一节要回答的问题：Dream 的训练方法由两部分组成。第一，怎样把一个 AR 模型的权重“接”到扩散训练上，而不浪费它已经学到的东西？答案是保留 AR 的 shift。第二，第 3 节的目标里，同一条序列中所有被遮住的 token 共用一个 \(t\)、共用一个权重，但它们的实际难度并不一样，能不能按每个 token 的处境分别定权重？答案是 CART。最后是具体的模型结构、数据和指令微调。原文图 2 和图 3 分别对应前两部分。

4.1 AR 初始化：为什么必须保留 shift

先补一点背景：AR 模型每个位置的输出“属于”下一个 token。

一个 AR 语言模型由很多层 Transformer 和最后的一个输出层（LM head）组成。最后一层在位置 \(i\) 的隐藏状态记为 \(h_{i}\)，输出层把它变成一个词表上的概率分布。训练时，这个分布被要求去预测第 \(i+1\) 个 token。在 Qwen2.5 这样的模型上，这条规则执行了 18T 个 token，所以 \(h_{i}\) 已经被塑造成“对下一个 token 有用的信息摘要”，输出层也习惯于把 \(h_{i}\) 读成“下一个 token 是什么”。

常规的掩码扩散模型（例如 LLaDA）采用原位预测：位置 \(n\) 是 [MASK]，就由位置 \(n\) 自己的输出来预测它。如果拿 AR 权重直接这样训练，一开始模型在位置 \(n\) 给出的其实是“第 \(n+1\) 个 token 的猜测”，整个输出系统性地错了一格。网络必须先把“输出属于下一个位置”这个约定整体改掉，才能开始学扩散，这等于把 AR 权重里最核心的一部分推倒重来。上一节 DiffuLLaMA 的消融（去掉 shift 掉 15.2 分）就是这个代价。

Dream 沿用 DiffuLLaMA 的做法：不改约定，改对齐。位置 \(n\) 被遮住时，它的预测从位置 \(n-1\) 的输出读出来，也就是继续让 \(h_{n-1}\) 负责第 \(n\) 个 token。这样扩散训练和预训练的输出约定完全一致，变化的只有两点：注意力从因果变成了全双向，以及被预测的那个位置本身可能看不到（是 [MASK]）。

本站示意图，对应 原文图 2 ↗（原图只画了 ① 和 ②，③ 是本站为对照加的）。下排是输入，上排是每个位置的输出；红框表示这个输出参与计算损失。② 和 ③ 遮住的是同样三个位置，区别在于由谁来报告答案：② 里第 2 个位置的答案 “is” 由第 1 个位置报告，③ 里由第 2 个位置自己报告。

用图里的例子走一遍 ②。原句是 “Dream is a text diffusion model”，第 2、4、5 个位置被遮住。按 shift 的约定，第 1 个位置的输出负责第 2 个 token，所以它要预测 “is”，并计入损失；第 2 个位置的输出负责第 3 个 token “a”，但 “a” 在输入里是可见的，不需要学，所以不计损失；第 3、4 个位置的输出分别负责被遮住的 “text” 和 “diffusion”，计入损失；第 5 个位置负责 “model”，可见，不计；第 6 个位置的输出没有对应的目标，被丢弃。官方代码的实现只有一行：把整个输出沿序列方向向右挪一格，第一个位置复制它自己的输出来补位。

这里有两个细节值得想一想。第一，负责第 4 个 token “diffusion” 的是第 3 个位置，而第 3 个位置的输入 “a” 是可见的；但负责第 5 个 token 的是第 4 个位置，它的输入本身就是 [MASK]。所以在 Dream 里，一个 [MASK] 位置的处境有点特别：它自己的答案由左边的位置来报告，而它自己的隐藏状态又要负责报告下一个位置的答案，尽管它的输入里没有任何关于自己的信息。全注意力让每个位置都能看到整个序列（包括右边的已知词），这才使它有可能完成后一件事。第二，序列的第一个位置没有左邻，它的 token 永远无法被预测；实际中第一个位置是 BOS 或 prompt 的开头，训练和生成时都不会被遮住，官方评测代码的注释也明确说第一个位置的输出不会被用到。

作者给出的好处有两条。其一是省计算：模型不必从零学习语言的统计规律，第 5.4 节在 1B 规模上用损失曲线验证了这一点。其二是“搭便车”：以后有了更强的 AR 模型，可以用同一套流程快速得到更强的扩散模型，而不必每次都从零训练。论文没有提 DiffuLLaMA 用过的注意力掩码退火，只在图 4 的说明里提到，从因果注意力切换到全注意力时，训练开头的损失会先冲高一下。

容易误解的地方：
  • shift 只是“由哪个位置报告答案”的记账方式，不意味着 Dream 从左往右生成。生成时先填哪些位置，由第 4.4 节的解码策略决定。
  • 但 shift 和“保住 AR 知识”的训练方式确实让模型带有一定的从左到右倾向。后来的 DiffuCoder 用“AR 程度”指标测量了解码顺序，发现从 AR 改造来的模型（Dream、DiffuCoder）比从零训练的 LLaDA 更接近从左到右，原因是它们继承了原 AR 训练里的左右依赖（见“后来怎么样了”）。

4.2 CART：按上下文给每个被遮的 token 重新定“噪声水平”

回到第 3 节的目标。标准训练对一条序列只抽一个 \(t\)，所有被遮住的 token 都乘同一个权重 \(1/t\)。作者指出，学习实际上发生在单个 token 上，而每个 token 面对的“真实噪声”并不等于这个全局的 \(t\)。原文图 3 的例子是 “Dream [M] a [M] [M] model”：三个被遮住的位置共用一个 \(t\)，但第一个 [MASK] 左右都是已知词，线索最多；后两个 [MASK] 挨在一起，每个都只有一侧有已知词。前者实际上处在更低的噪声水平。作者认为忽略这种差别会让学习不够有效。

CART（Context-Adaptive noise Rescheduling at Token-level，上下文自适应的 token 级噪声重排）的做法是：把权重从“只和 \(t\) 有关的 \(w(t)\)”换成“和 \(t\)、当前遮法、位置都有关的 \(w(t,\mathbf{x}_{t},n)\)”，目标变成

$$L(\theta)=-\,\mathbb{E}_{\mathbf{x}_{0},\,t,\,\mathbf{x}_{t}}\sum_{n=1}^{N}\mathbf{1}\big[x_{t}^{n}=[\mathrm{M}]\big]\;w(t,\mathbf{x}_{t},n)\;\log p_{\theta}\big(x_{0}^{n}\mid\mathbf{x}_{t}\big)$$
先补一点背景：几何分布。

几何分布描述“每次以概率 \(p\) 成功，第一次成功前失败了 \(k\) 次”的概率：\(\mathrm{Geo}(p,k)=p(1-p)^{k}\)，\(k=0,1,2,\dots\)。它随 \(k\) 增大按固定比例 \(1-p\) 衰减，所有 \(k\) 加起来等于 1。\(p\) 越大，衰减越快，概率集中在 \(k=0\) 附近；\(p\) 越小，衰减越慢，分布越平。例如 \(p=0.5\) 时依次是 0.5、0.25、0.125……；\(p=0.1\) 时依次是 0.1、0.09、0.081……

Dream 用几何分布来衡量“一个已知 token 能给远处的被遮 token 提供多少信息”：距离为 \(d\) 的已知 token 贡献 \(\mathrm{Geo}(p,d-1)\)，紧挨着的贡献最大，越远越小。把所有已知 token 的贡献加起来、再乘 \(\tfrac12\)，就是这个被遮位置的权重：

$$w(t,\mathbf{x}_{t},n)=\frac12\sum_{i=1}^{N}\mathbf{1}\big[x_{t}^{i}\neq[\mathrm{M}]\big]\;p\,(1-p)^{|n-i|-1}$$

乘 \(\tfrac12\) 是因为左右两侧各有一条几何级数，每条最多加到 1，所以无论怎样 \(w\le1\)；只有当一个位置两侧无限远都是已知词时才达到 1。\(p\in(0,1]\) 控制“锐度”：\(p\) 小，已知词对整条序列的被遮位置贡献得比较均匀；\(p\) 大，已知词只照顾身边的几个位置。权重通过“哪些位置被遮住”间接依赖 \(t\)：\(t\) 越大，被遮的越多，已知词越少，权重整体越小。这一点和 \(1/t\) 的方向一致（噪声越低权重越大），只是现在细到了每个 token。

换句话说，CART 让模型在训练时更看重“有线索可依”的位置，相对少看重被埋在长空白中间、几乎没有线索的位置。为什么这样可能有帮助，论文只说“标准做法对上下文信息量不同的 token 学得不好”。本站的理解是：一个周围全是 [MASK] 的位置，即使模型完美，答案也有很大的不确定性，它的交叉熵大而且波动大；给它和“左右都是已知词”的位置一样的权重，会让梯度被这些几乎没法学的样本主导。降低它们的权重，类似于把这些位置当作“噪声更高”的样本来对待（本站解读，论文没有给出分析或实验）。

官方代码怎么实现。开源的训练代码把公式 (5) 写成一个 \(N\times N\) 的矩阵 \(W\)，\(W_{nj}=\tfrac12p(1-p)^{|n-j|-1}\)，对角线为 0；每条序列的权重向量就是“未被遮住的指示向量”乘以 \(W\)，再只保留被遮位置上的值。开源的指令微调脚本选用 CART，配置文件里的 \(p\) 默认是 0.1（函数自身的默认值是 0.8）。预训练阶段用的 \(p\) 是多少，论文和代码都没有给出。

关于 CART，论文没有说清楚的几件事：
  • 没有消融实验。报告里没有任何一个数字单独衡量 CART 的作用；博客只说它是在 1B 规模上筛选出来的有用组件之一。所以 Dream 的成绩里有多少来自 CART、多少来自 AR 初始化和数据，无从拆分。
  • 换了权重之后，训练损失就不再是似然的上界（本站推断）。第 3 节的 \(1/t\) 是从 ELBO 推出来的，而 CART 的权重处处 \(\le1\le1/t\)，所以 CART 损失逐项小于负 ELBO，只是一个重新加权的去噪目标，不能当成似然或困惑度来读。论文称公式 (5) 是 \(w(t)\) 的“推广”，但没有讨论这一点。官方评测里做选择题时，用的仍是标准 \(1/t\) 权重的似然估计。
  • 论文第 4.3 节说预训练“用蒙特卡洛方法估计公式 (3)”，而不是带 CART 的公式 (4)；博客则说 CART 让 7B 的训练变得有效。7B 预训练到底在哪个阶段、以什么 \(p\) 用了 CART，报告没有交代。

4.3 训练：模型结构、580B token 与指令微调

模型结构。Dream 7B 的配置与 Qwen2.5-7B 完全相同，所以可以直接载入它的权重。按官方发布的配置文件：隐藏维度 3584，28 层，28 个注意力头，其中键值头只有 4 个（分组查询注意力 GQA），前馈层维度 18,944，词表 152,064，RoPE 位置编码的基频 \(\theta=10^{6}\)；新增的 [MASK] 的 token id 是 151666。和 DiffuLLaMA 一样不加时间嵌入。官方 README 说明当前的上下文长度（输入加输出）是 2048 个 token。

预训练。训练语料共 5800 亿 token，覆盖文本、数学和代码，来自三个开源数据集：Dolma v1.7（通用文本）、OpenCoder（代码）、DCLM-Baseline（经过筛选的高质量文本和数学内容）。作者强调只用开源数据，以便他人复现。博客补充说训练总体平稳，偶有节点故障，没有出现无法恢复的损失尖峰。训练硬件、时长、学习率和批大小都没有公开。

先补一点背景：指令微调（SFT）为什么只遮“回答”。

预训练得到的 Base 模型只会续写文本，要让它按用户指令作答，需要在“指令—回答”配对数据上继续训练，这叫监督微调（SFT）。对 AR 模型，SFT 通常只在回答部分计算损失；对扩散模型，对应的做法是只给回答部分加噪（随机遮住），指令部分始终保持完整。这样模型学到的是条件分布 \(p_{\theta}(r_{0}\mid p_{0})\)：看着完整的指令 \(p_{0}\)，还原被遮住的回答 \(r_{0}\)。生成时也正是这样用的：指令完整给出，回答部分从全 [MASK] 开始填。

指令微调。作者从 Tulu 3 和 SmolLM2 的数据中整理出 180 万条指令—回答对，训练 3 轮，得到 Dream-Instruct。开源的微调脚本用的是 CART、学习率 2e-6、最大长度 2048，但它是给用户自己微调用的示例，是否就是 Dream-Instruct 当时的配置，没有说明。

4.4 生成时怎么一步步填（论文没细写，依据官方代码）

论文正文没有描述采样算法，但第 5 节的“步数—质量”权衡完全取决于它，所以这里按官方推理代码（diffusion_generate）讲清楚。

  1. 准备画布。把指令（prompt）放在前面，后面接 max_new_tokens 个 [MASK]。也就是说，生成长度是事先定死的；模型如果想早点结束，就在后面填上结束符，使用时再把结束符之后的部分切掉。
  2. 每一步看整张画布。把 prompt 和画布一起送进网络做一次完整的前向计算（双向注意力，没有 KV 缓存），把输出整体右移一格（shift），得到每个被遮位置的预测分布。
  3. 决定这一步填几个。时间从 1 线性地走到 0.001，共 steps 步；从 \(t\) 走到 \(s\) 时，填上“当前被遮个数 \(\times(1-s/t)\)”个位置。算下来每一步大约填 max_new_tokens / steps 个，最后一步把剩下的全部填完。
  4. 决定填哪几个。由参数 alg 选择：origin 是完全随机地挑位置（函数的默认值，README 提醒它在部分任务上会掉分）；maskgit_plus 挑最大概率最高的；topk_margin 挑“第一名与第二名概率之差”最大的；entropy 挑预测分布熵最小、也就是最笃定的。官方评测和示例都用 entropy。被选中的位置按 temperature、top_p 等常规采样参数取值，其余位置继续保持 [MASK]。

5.1 评测设置：考了哪些题，每道题怎么打分

评测分四类：通用能力（MMLU、BBH、ARC-E、ARC-C、HellaSwag、WinoGrande、PIQA、RACE），数学与科学（GSM8K、MATH、GPQA），代码（HumanEval、MBPP），以及规划（Countdown、数独、旅行规划）。指令模型另外测了 MMLU-Pro 和考察指令遵循的 IFEval。表 1 中带星号的四个模型（Dream、LLaDA、Qwen2.5、LLaMA3）是作者在同一套协议下重新测的；Mistral 7B 和 DeepSeek 7B 两列没有星号，是取自其他来源的参考数字，下文不讨论。

先补一点背景：两种评测方式，以及扩散模型怎么做选择题。

语言模型的基准大体分两种。一种是比概率：给出题目和若干选项，看模型认为哪个选项的概率最高，MMLU、ARC、HellaSwag 等选择题通常这样测。另一种是让模型自由生成，再从输出里抽取答案判对错，GSM8K、MATH、HumanEval 等这样测。括号里的数字（如 “5”）是 few-shot 示例的个数：在题目前面放几道带答案的例题，让模型照着格式答。

AR 模型比概率很简单，把选项接在题目后面，一次前向就能精确算出选项的对数概率。扩散模型算不出精确概率，只能估计第 3 节那个上界。按 Dream 的官方评测代码，做法是：题目保持完整，只把选项部分的 token 随机遮住，按 \(1/t\) 加权算交叉熵，重复 128 次取平均，作为这个选项的负对数似然估计。所以做一道 4 选项的 MMLU 题，Dream 要做 \(4\times128=512\) 次前向（推算）。

读规划结果时要注意：
  • 所有模型都是 few-shot 直接给答案，没有针对任务训练，也不允许写推理过程。AR 模型如果能先写思维链，结果可能完全不同；DeepSeek-V3 一列也只是在同样的直接作答格式下作为参照。
  • 输出很短：数独 24 个 token、Countdown 32 个 token，扩散模型都是一步一个 token 地填，只是填的顺序不同。所以这里的优势来自“顺序”，不来自“并行”。
  • LLaMA3 8B 在数独上几乎全是 0，论文没有分析它为何完全失败。

速度结论的条件没有交代：原文图 7 没有说明硬件、批大小、Dream 和 Qwen2.5 各自用什么推理实现（例如 Qwen2.5 是否开了 KV 缓存、是否用了 vLLM 这类推理引擎），也没有说明 Qwen2.5 的输出长度。Countdown 的输出只有 32 个 token，在这么短的输出上，AR 模型的逐 token 开销和扩散模型的整段前向开销之间的对比，与长文本生成时很不一样。所以“5–20 步时又快又准”只对这个任务、这个设置成立，不能推广成“Dream 比 Qwen2.5 快”。

5.7 任意顺序生成：补全、填空与可调的解码顺序

因为生成不受从左到右的限制，Dream 不需要专门训练就能做几类 AR 模型不方便做的事。论文列了三种，博客里有动态演示：

  • 补全：给出开头，让模型接着写。这和 AR 模型的用法一样。
  • 填空：给出开头和结尾，让模型填中间缺的部分，还可以要求填出的内容正好衔接到一个指定的结尾句。AR 模型要做到这一点，需要专门的“中间填充”训练和改写输入顺序。
  • 可调的解码顺序：通过解码参数（第 4.4 节的 alg，以及给置信度加随机性的 alg_temp）让生成过程更像 AR 的从左到右，或者引入不同程度的随机顺序，直到完全随机。官方代码还提供了钩子函数，可以在每一步干预 token 或 logits，用来实现填空和其他控制。

需要注意的一个限制是：画布长度在生成前就定死了。填空时，中间要填多少个 token 必须事先指定，模型不能自己决定“这里要多写几句”。同一团队后来的 DreamOn 专门处理了这个变长填空的问题（见“后来怎么样了”）。

5.8 结果的份量：这些数字说明了什么、没说明什么

把前面各小节的条件放在一起，Dream 的结果可以这样掂量：

  • 和 LLaDA 的比较不是同等条件。“只用了 LLaDA 1/4 的数据”只计算了扩散阶段的 0.6T token。Dream 的权重在此之前已经在 Qwen2.5 的 18T token 上训练过，加起来约 18.6T，是 LLaDA 2.3T 的 8 倍左右（推算）；数据来源、词表和参数量（7B 对 8B）也都不同。后来从零训练的 iLLaDA 在对比表里就把 Dream 记为 “18T + 0.6T”。所以这组比较支持的结论是“已经有一个强 AR 模型时，改造它得到扩散模型的额外成本远低于从零训练”，而不是“扩散目标比 AR 目标更省数据”。Dream 的训练硬件和 GPU 小时数没有公开，额外成本具体是多少也无法核算。
  • 最该看的对照是它自己的出发点 Qwen2.5 7B。同协议下，Dream 在 13 项常规基准里 8 项更低、5 项更高，下降最多的是 MBPP、BBH 和 HellaSwag（5.7–7.4 分），提高最多的是 ARC-C 和 ARC-E（6.5–8.3 分）。改造换来的是规划任务上的大幅提升和填空、调步数这些新能力，代价是常规任务上一定程度的退步。
  • “同协议重测”会改变 AR 基线的绝对分数。在 Dream 的协议下，Qwen2.5 7B 的分数明显低于 Qwen 官方报告的数字（经 LLaDA 论文表 1 转引）：GSM8K 78.9 对 85.4、MATH 41.1 对 49.8、BBH 63.9 对 70.4、MMLU 71.9 对 74.2。两边的示例数和答案抽取方式不同，不能直接相减，但这说明“Dream 与 Qwen2.5 相当”这个判断依赖于评测协议。同样，表 1 里 LLaDA 的数字也和 LLaDA 自己论文报告的不完全一样（例如 BBH 47.4 对 49.7、GPQA 30.4 对 25.2，后者取 LLaDA 论文当前版本）。
  • 选择题的打分方式本身就不同。Dream 用 128 次随机遮盖估计出的似然上界给选项打分，AR 模型用精确的对数概率。Dream 相对 Qwen2.5 的提高恰好集中在这类选择题上，打分方式有没有影响，论文没有分析。
  • 所有生成分数都是在最慢的设置下测的。按官方脚本，生成类任务一律是步数等于生成长度，也就是每次完整前向只定一个 token，而且没有 KV 缓存。表 1 和表 2 的准确率都不附带任何速度优势；在这个设置下，Dream 比带 KV 缓存的 AR 模型慢。论文唯一的“又快又准”证据是 Countdown 上的图 7，其硬件、批大小和 AR 一侧的推理实现都没有交代。
  • 规划任务偏向扩散模型的长处。三个规划任务都是短输出的约束满足问题，评测时不允许写推理过程，AR 模型必须一上来就写最难的那一格；前两个任务还来自作者团队自己此前的工作。这些结果有力地说明了“生成顺序”在这类问题上的价值，但不能直接推广成“扩散模型更会规划”。
  • 指令模型的比较混合了不同来源。表 2 中 LLaDA、LLaMA3、Qwen2.5 的数字是从其他论文和报告里取来的，不是同协议重测；而且 Dream 只做了 SFT，Qwen2.5 和 LLaMA3 还做了强化学习。
  • 两项方法贡献都没有被单独量化。CART 没有任何消融；AR 初始化只在 1B 规模上比了损失曲线，没有下游任务的对照。
  • 有第三方的部分印证。DiffuCoder 论文在自己的评测里测得 Dream-Base 的 HumanEval 为 56.7（Dream 自报 57.9）；Fast-dLLM 论文测得 Dream-Base 在 GSM8K 5-shot、生成长度 256 时为 75.0。这些数字和 Dream 自报的量级一致，说明表 1 的成绩大体可以复现；其中 Fast-dLLM 的 75.0 是它没有加任何加速手段时的基线。
  • 上下文只有 2048 个 token。官方 README 写明，输入加输出不能超过 2048；需要长上下文的任务都不在评测范围内。

6 结论：一条“站在 AR 模型肩上”的实用路线

这一节要回答的问题：作者最终主张了什么，留下了哪些方向？把前面的证据放在一起，这篇论文最站得住的贡献是什么？

作者的结论有三层。第一，Dream 7B 在常规任务上达到了与同规模顶级 AR 模型相当的水平，同时具备灵活生成的能力。第二，扩散语言模型在约束满足和规划类任务上表现突出，作者归因于双向建模和多轮修改。第三，任意顺序生成带来补全和填空这类新用法，可调的步数让用户能在速度和质量之间细粒度地取舍；而“从预训练 AR 模型初始化”被证明是一条开发更灵活、更强语言模型的可行途径。作者列出的后续方向是更好的后训练方法、更长的上下文，以及需要更强规划和推理能力的专门领域。

结合第 5.8 节，本站的看法是：这篇论文最站得住的贡献是工程配方和开源模型本身。它证明了“Qwen2.5 级别的 AR 模型 + 约 0.6T token 的扩散继续训练”就能得到一个在常规任务上只比原模型略低、在短输出规划任务上明显更强、而且权重和推理代码都公开的 7B 扩散模型，这让学术界第一次有了一个足够强、又容易拿到的扩散语言模型底座。关于扩散模型“更会规划”和“又快又准”的说法，论文提供的是在特定任务格式和设置下的证据，还不是一般性的结论；CART 和 AR 初始化各自的作用也没有被单独量化。

7 后来怎么样了

Dream 7B 很快成了开源扩散语言模型研究里最常用的底座和对照之一。下面只列本站核对过原文的后续工作。

  • 同一团队的延续。2025-07-15，团队发布了代码专用的 Dream-Coder 7B 和处理变长填空的 DreamOn；Dream-Coder 的技术报告（arXiv 2509.01142）说明它同样用 AR 初始化（这次是 Qwen2.5-Coder）加上下文自适应噪声调度，在 3220 亿 token 的开源代码、数学和通用数据上训练，再做 SFT 和基于可验证奖励的强化学习，Instruct 版在 LiveCodeBench（2410–2505）上的 pass@1 为 21.4%。2025-09-26，Dream 的训练代码开源。2025-12 的 Dream-VL / Dream-VLA（arXiv 2512.22615）以 Dream-v0-Instruct-7B 为语言模型底座，做成了扩散式的视觉语言模型，再在机器人数据上继续预训练成视觉—语言—动作模型。见旧版 代码页的 Dream-Coder 一节。
  • DiffuCoder：量化“从 AR 改造来的模型有多 AR”。Apple 与港大的 DiffuCoder（arXiv 2506.20639）按与 Dream 相似的流程在 1300 亿代码 token 上改造出 7B 代码模型，并提出“局部 / 全局 AR 程度”两个指标来衡量解码顺序有多接近从左到右。它发现从 AR 改造来的模型（Dream、DiffuCoder）比从零训练的 LLaDA 更接近从左到右，因为继承了原 AR 训练里的依赖；它还发现 Dream 这类按置信度挑位置的解码会出现“熵汇”现象：紧挨着 prompt 右边的位置置信度异常高，于是解码天然偏向从左往右。它提出的 coupled-GRPO 强化学习让 EvalPlus 提高 4.4%。见旧版 代码页的 DiffuCoder 一节。
  • Fast-dLLM：让 Dream 真的快起来。NVIDIA、港大与 MIT 的 Fast-dLLM（arXiv 2505.22618）不重新训练，给双向注意力的扩散模型加上按块近似的 KV 缓存，并且每步把置信度超过阈值的位置一起定下来。在 Dream-Base 上，GSM8K（5-shot，生成长度 256）的准确率从 75.0 变为 74.8，吞吐量从每秒 9.1 个 token 提高到 48.2 个（5.3 倍）；MBPP（生成长度 512）上提速 7.8 倍，准确率从 55.6 变为 55.2。测法是单张 A100 80GB、批大小 1、不用任何推理框架，对照是未加速的 Dream 本身，而不是 AR 模型。这正好补上了 Dream 论文“步数等于长度”的评测留下的速度空白。见旧版 KV 缓存页。
  • “从 AR 改造”成为主流路线之一。LLaDA2.0（arXiv 2512.15745）把预训练好的 AR 混合专家模型改造成扩散模型，规模到 16B 和 100B，用的是一个分三阶段、在块大小上做“预热—稳定—衰减”的训练方案。旧版 第 12 页 整理了把 AR 模型改造成块扩散模型的几项工作。
  • 从零训练的回应。iLLaDA（arXiv 2606.25331）用 12T token 从零训练扩散模型，在它的 Base 对比表里把 Dream 记为 “18T + 0.6T”；按它列出的 8 项基准平均，iLLaDA 为 63.9、Dream 为 61.4、Qwen2.5 为 63.3（Dream 和 Qwen2.5 两列取自 Dream 论文）。见旧版 LLaDA 页的 iLLaDA 一节。
