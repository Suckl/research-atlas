0 导读：这篇论文解决什么问题

扩散语言模型（diffusion LLM，下文简称 dLLM）是自回归模型之外的另一种写文字的方式。它先在要写答案的地方放一排“空格”（掩码），然后反复让模型去猜，每一轮把其中一部分空格填上，直到全部填满。因为一轮可以同时填好几个位置，人们自然期待它比一个字一个字往外吐的自回归模型更快。商业产品也确实报出了很快的数字：论文引言提到，Mercury 每秒能生成 1,000 多个 token，Gemini Diffusion 超过 1,400 个。

可是开源的 LLaDA、Dream 实际跑起来，往往比同样大小的自回归模型还慢。论文把原因归结为两件事。第一，这些模型用双向注意力，每填进一个词，所有位置的中间结果都会跟着变，所以它们没法像自回归模型那样把算过的 key 和 value 存起来复用（也就是 KV 缓存），每一轮都得把提示和整段答案从头算一遍。第二，一轮同时填好几个空格时质量会下降，所以评测时通常一轮只填一个，并行的优势根本没用上。

Fast-dLLM 不改模型、不做任何训练，只改推理的过程，针对这两件事各给了一个办法。针对第一件，它把答案切成长度 32 的块，从左到右一块一块地写；在写某一块的那几轮里，把块外位置的 key/value 当作不变，直接从缓存里读，等这一块写完再整段重算一次、刷新缓存。它的 DualCache 版本连块后面那些还没写的空格也一起缓存。针对第二件，它不再规定每轮必须填几个，而是只填模型“有把握”的位置（预测概率的最大值超过 0.9），并用一个定理说明：当每个位置的把握都足够高时，各位置分别挑最可能的词，和按整体挑最可能的一组词，结果是一样的。

两招合起来，在一张 A100 上、一次只处理一条请求时，LLaDA 做 GSM8K（8-shot、生成长度 1024）的速度从每秒 0.7 个 token 提到 19.3 个，这就是标题里的 27.6 倍，准确率从 77.3% 变为 76.0%。在更常见的生成长度 256 上，倍数是 LLaDA 约 8.1 倍、Dream 约 5.3 倍（都在 GSM8K 上）。要特别记住，这些倍数都是和“每轮只填 1 个空格、不用任何缓存”的原版扩散模型比出来的，不是和优化过的自回归推理引擎比；第 5 节的“结果的份量”会把这一点拆开讲。

1 引言：号称能并行的模型，为什么反而慢

这一节要回答的问题：扩散语言模型的卖点是“一次生成很多 token”，为什么开源模型实际跑起来反而比自回归模型慢？论文认为慢在哪两件事上？在不重新训练模型的前提下，作者打算分别怎么解决？
先补一点背景：自回归模型为什么能“越写越省”——KV 缓存。

自回归模型一个 token 一个 token 地写。每写一个新 token，模型都要通过注意力去“看”前面所有的 token，看的是前面每个 token 在每一层算出来的 key 和 value 两个向量。自回归模型用的是因果注意力：每个位置只能看它前面的位置，看不到后面。因此，前面某个 token 的 key/value 一旦算出来，就永远不会再变，因为后来写的 token 影响不到它。推理系统于是把这些 key/value 存起来，这份存储叫 KV 缓存。每写一个新 token，只需要为这个新 token 算一次 key/value，再拿它的 query 去和缓存里的内容做注意力。写 \(L\) 个 token，每个位置只需要算一遍。KV 缓存的来龙去脉，以及它为什么占显存、怎么管理，见本站 vLLM 精读 §2.2。

扩散语言模型用的是双向注意力：每个位置既看前面，也看后面。第 3 节会讲清楚，正是这一点让它没法直接用 KV 缓存。

论文开头先摆出一个反差：商业扩散模型宣称每秒上千 token，开源的 LLaDA、Dream 却常常比不上同尺寸的自回归模型。作者认为原因主要有两个。

  • 没有 KV 缓存。自回归模型靠 KV 缓存避免重复计算，而扩散模型每一轮都要把提示和整段答案重新送进模型算一遍。提示越长、答案越长，这部分浪费就越大。
  • 一轮多填几个 token，质量就掉。LLaDA 自己的实验显示，每轮只填 1 个 token 时效果最好，多填几个就开始变差。所以评测时常常把轮数设成和生成长度一样多：要生成 256 个 token，就跑 256 轮。这等于完全放弃了并行。

对应地，Fast-dLLM 有两个部件。第一个是专为双向模型设计的近似 KV 缓存：按块生成，块内复用缓存，块写完再刷新；它的 DualCache 版本把块后面那些还是掩码的位置也缓存起来。作者用可视化说明相邻几轮之间 key/value 非常接近，再用实验说明这样近似基本不伤精度。第二个是置信度感知的并行解码：作者认为一轮多填几个 token 会掉质量的根本原因，是把几个互相依赖的 token 当成了彼此独立来同时生成；于是只同时填那些置信度超过阈值的位置，并给出定理说明高置信时这样做是安全的。LLaDA 原来的做法是每轮固定挑置信度最高的 \(K\) 个位置，Fast-dLLM 改成按阈值挑，挑几个由模型的把握决定。

2 预备知识：掩码扩散模型怎样一轮轮写出答案

这一节要回答的问题：掩码扩散模型是怎么训练、怎么生成文字的？LLaDA 实际评测时用的“分块、按置信度一个个揭开”具体是怎么一回事？为什么一轮同时揭开好几个位置会出问题？这一节交代的正是 Fast-dLLM 后面要改造的那个生成过程。

2.1 掩码扩散模型：把字一个个涂掉，再学着填回去

先补一点背景：离散数据上的扩散。

图像扩散模型往图片上一点点加高斯噪声，再训练网络一步步把噪声去掉。文字是离散的 token，没法加“一点点”噪声。D3PM 等工作把“加噪”改成按某个转移矩阵随机替换 token；后来最成功的一类叫掩码扩散模型（masked diffusion model，MDM，也叫吸收态扩散）：加噪就是把 token 换成一个特殊的 [MASK] 符号，一旦换掉就不会再变回别的词（“吸收”）。本站的 D3PM、MDLM 精读页有完整推导，这里只讲用得到的部分。

前向（加噪）过程写成公式是这样的：

$$q_{t|0}(x_t\mid x_0)=\prod_{i=1}^{n}\mathrm{Cat}\Big(x_t^i;\ (1-t)\,\delta_{x_0^i}+t\,\delta_{[\mathrm{MASK}]}\Big)$$

意思是：时间 \(t\) 从 0 走到 1，每个 token 各自独立地以概率 \(t\) 被换成 [MASK]，以概率 \(1-t\) 保持原样。\(t=0\) 时是原文，\(t=1\) 时整行都是 [MASK]。

训练时，模型 \(p_\theta\) 看着一个被部分涂掉的句子 \(x_t\)，去预测每个被涂掉位置原来的 token；损失只算在被涂掉的位置上，并按 \(1/t\) 加权。MDLM、RADD 等工作证明，这个损失是负对数似然的一个上界（ELBO），所以训练它就是在做最大似然：

$$-\log p_\theta(x)\le\int_0^1\frac{1}{t}\,\mathbb{E}_{q_{t|0}(x_t\mid x_0)}\Big[\sum_{i:\,x_t^i=[\mathrm{MASK}]}-\log p_\theta\big(x_0^i\mid x_t\big)\Big]\,\mathrm{d}t$$

这里有一点后面会反复用到：模型做一次前向，会对每一个被涂掉的位置各给出一个词表上的概率分布，但这些分布是分别给出的。模型并不直接告诉你“这几个位置合起来最可能填什么”，也就是说，它输出的是每个位置的边缘分布，不是几个位置的联合分布。

2.2 生成：从一整行 [MASK] 开始，一轮轮揭开

生成时反过来走：先把答案区域全部设成 [MASK]，接在提示后面，然后一轮轮把 [MASK] 换成词。严格地反演前向过程，每一步只能改一个 token，太慢；常用的近似叫 τ-leaping，一步从噪声水平 \(t\) 跳到更小的 \(s\)（\(s<t\)）：已经填好的位置保持不变；还是 [MASK] 的位置，以概率 \(s/t\) 继续保持 [MASK]，否则按模型给出的分布采样一个词填进去。

$$q_{s|t}\big(x_s^i\mid x_t\big)=\begin{cases}1, & x_t^i\neq[\mathrm{MASK}],\ x_s^i=x_t^i\\[2pt] \dfrac{s}{t}, & x_t^i=[\mathrm{MASK}],\ x_s^i=[\mathrm{MASK}]\\[6pt] \dfrac{t-s}{t}\,q_{0|t}\big(x_s^i\mid x_t\big), & x_t^i=[\mathrm{MASK}],\ x_s^i\neq[\mathrm{MASK}]\end{cases}$$

其中 \(q_{0|t}\) 就是模型给出的那个词表上的分布；有提示 \(p\) 时，它还要以提示为条件，写作 \(q_{0|t}(x_s^i\mid x_t,p)\)。注意公式对每个位置是分开写的：同一步里被揭开的几个位置，各自独立地从自己的分布里采样。

实际的 LLaDA 并不随机挑位置，而是用低置信度重掩码：每一轮让模型对所有 [MASK] 位置给出预测，取每个位置最可能的那个词和它的概率（称为置信度），只保留置信度最高的 \(K\) 个，其余的重新盖回 [MASK]。\(K\) 等于生成长度除以总步数，步数是事先定好的超参数。

另一个实际细节是分块（半自回归）生成：把答案切成长度相同的块，从左往右一块一块地揭开，当前块全部揭开之前不碰后面的块；但后面那些 [MASK] 仍然作为输入送进模型。LLaDA 论文报告，它的指令模型用这种分块方式在 GSM8K 和 MATH 上明显更好（78.6、42.2，整段一起生成时是 69.4、31.9），原因是监督微调数据在短回答后面补了大量结束符，整段生成时模型容易过早写出结束符。Fast-dLLM 官方评测脚本里，LLaDA 的原版基线就是块长 32、每步揭开 1 个 token。

2.3 并行解码的“诅咒”：每个位置都对，拼起来却错

如果一步只揭开一个 token，下一步模型就能看到它，据此调整其他位置的预测，前后自然一致。如果一步同时揭开两个位置 \(i\) 和 \(j\)，实际是从两个边缘分布的乘积 \(p(x^i\mid x_t)\cdot p(x^j\mid x_t)\) 里采样；而正确的联合分布是 \(p(x^i\mid x_t)\cdot p(x^j\mid x_t,x^i)\)，第二个词本该取决于第一个词填了什么。两者不一样，就可能拼出单看每个位置都合理、合在一起却不成立的组合。同时揭开的位置越多，这种不一致越严重。

论文借用了 Song 与 Zhou 的一个例子：“由两个英文单词组成的扑克牌型有：__ __”。合理的答案有 high card、two pair、full house、straight flush 等，两个词之间强相关；独立地各抽一个，就可能抽出 high house 这种不存在的牌型。下面用一组本站假设的数字把这个例子算一遍。

本站示意图，用来说明 原文 §2.2 ↗ 的例子。怎么看：行是第 1 个空的候选词，列是第 2 个空的候选词。左图是模型对两个空的联合分布，只有 5 个格子不为零；最右一列 p₁ 和最下一行 p₂ 是由它算出的两个边缘分布。右图把 p₁ 和 p₂ 相乘，得到并行解码实际使用的分布 q：每个格子都不为零，概率被大量分给了不存在的牌型。

用这组数字比较三种做法：

  1. 并行地各取最可能的词（贪心）。第 1 个空最可能的是 full（0.30），第 2 个空最可能的是 flush（0.32），拼出 full flush，这不是任何牌型，它在联合分布里的概率是 0。
  2. 并行地各自抽样。两个词按各自的边缘分布独立抽取，拼出合法牌型的概率是 \(0.23^2+0.15^2+0.30^2+0.12\times0.32+0.20\times0.32\approx0.27\)（推算），也就是大约四次里有三次拼错。
  3. 一次只揭开一个。先揭开最有把握的位置，即第 2 个空的 flush（0.32）。下一步模型看到了 flush，第 1 个空的分布就变成 straight 0.375、royal 0.625（按联合分布推算），于是写出 royal flush，合法。

这个例子说明，问题不在模型“算错了”：两个边缘分布本身完全正确，错在把它们当成彼此独立来使用。论文据此判断，dLLM 并行解码掉质量的根本原因，就是这条条件独立假设；而且一步揭开的位置越多、它们之间的依赖越强，问题越严重。

先记住一个细节：这个例子里两个空的置信度都只有 0.3 左右。第 4 节会看到，Fast-dLLM 的办法正是不让没把握的位置同时揭开。反过来，如果两个位置的置信度都在 0.99 以上，联合分布几乎全部集中在同一个组合上，独立揭开也几乎不会出错。

3 块级近似 KV 缓存与 DualCache

这一节要回答的问题：双向注意力为什么让 KV 缓存失效？既然没法精确缓存，能不能退一步，在一小段时间里假装 key/value 不变？这样做的依据是什么？DualCache 又在 PrefixCache 的基础上多省了什么？省下来的计算到底有多少？

3.1 为什么双向模型没有“标准”的 KV 缓存

先补一点背景：一个位置的 key/value 取决于哪些 token。

在 Transformer 的第一层，每个位置的 key/value 只由这个位置自己的 token（和位置编码）决定。从第二层开始，每个位置的输入已经是上一层注意力混合过的结果，所以它的 key/value 取决于它在上一层“看得到”的所有位置。在因果注意力里，第 \(i\) 个位置只看得到第 1 到第 \(i\) 个位置；在双向注意力里，它看得到整段序列。

示意图：生成一个词以后，哪些位置的 key/value 会变
本站示意图。左：自回归模型写出第 4 个词时，前 3 个词看不到它，它们在每一层的 key/value 一点都不会变。右：掩码扩散模型某一步把一个 [MASK] 换成了 on，因为每个位置都看得到它，从第二层起所有位置（包括提示）的 key/value 都变了。

所以对掩码扩散模型来说，严格意义上每一步的 key/value 都和上一步不同，任何缓存都只能是近似。原版 LLaDA 干脆每一步都把“提示 + 整个答案区”全部重算。设提示长 \(P\)、答案区长 \(L\)，每步定稿一个 token 就要跑 \(L\) 步，每步处理 \(P+L\) 个位置，总共要处理 \(L\,(P+L)\) 个位置；带 KV 缓存的自回归模型总共只需处理 \(P+L\) 个位置（推算，只数位置，没算注意力随长度增长的那部分）。只看注意力这一项，原版扩散每步要做 \(O\big((P+L)^2\big)\) 的计算，总共 \(O\big(L\,(P+L)^2\big)\)；同期的 dKV-Cache 论文把这个差距概括为 \(O(L^3)\) 对自回归的 \(O(L^2)\)。

3.2 退一步：按块生成，块内假装 key/value 不变

Fast-dLLM 的做法建立在上一节的分块生成之上。设块长为 \(B\)，默认 32。生成过程是这样的：

  1. 开始写第 1 块之前，把整段（提示 + 全是 [MASK] 的答案区）送进模型算一次。这一次前向既用来揭开第 1 块的第一批 token，也顺便把所有位置的 key/value 存下来。
  2. 在第 1 块内部的后续每一步，只把“当前块 + 它后面的部分”送进模型重算，提示部分的 key/value 直接从缓存里读。这叫 PrefixCache（前缀缓存）。
  3. 当前块全部揭开之后，再把整段送进模型算一次，刷新所有位置的缓存（不只是刚生成的那些 token），同时揭开下一块的第一批 token。
  4. 如此往复，直到最后一块。前缀会越来越长：写第 \(k\) 块时，提示和前 \(k-1\) 块都在缓存里。

因为第 3 步那次整段前向同时就是下一块的第一步解码，作者说刷新缓存“相比不用缓存没有额外计算”。近似发生在第 2 步：当前块里的 token 每一步都在变，严格来说前缀的 key/value 也应该跟着变，但在一块之内，缓存里用的始终是这一块开始时的值。

3.3 凭什么可以假装：相邻几步的 key/value 几乎一样

先补一点背景：余弦相似度。

两个向量的余弦相似度是它们夹角的余弦：1 表示方向完全相同，0 表示互相垂直。拿它比较同一个位置在第 \(i\) 步和第 \(j\) 步的 key（或 value）向量，越接近 1，说明从第 \(i\) 步到第 \(j\) 步这个位置的表示变化越小。

作者在 LLaDA-Instruct 上做了这样的统计（原文图 3）：对提示里的每个 token，计算它在任意两步 \(i\)、\(j\) 之间 key/value 的余弦相似度，再对所有提示 token 取平均，画成一张以步数为横轴和纵轴的热图。另一张图对最后一块的 token 做同样的事；最后一块在轮到它之前一直属于“后缀”，所以它代表了后缀里那些 [MASK] 位置的变化。

两张图的规律相同：对角线附近（\(i\approx j\)，也就是相隔几步之内）相似度接近 1，离对角线越远越低；原图色标的下端约为 0.84（提示）和 0.88（最后一块）。作者用红框框出的正是“同一块之内的那几步”，框内几乎全是接近 1 的颜色。由此得出两个结论：在一块的解码期间，提示和后缀的 key/value 变化很小，冻结它们带来的误差可以忽略；而跨过很多块之后，变化会累积起来，所以每块结束都要刷新一次。

3.4 DualCache：后缀里的 [MASK] 也缓存起来

PrefixCache 每一步仍要重算当前块后面的所有 [MASK] 位置。生成长度 1024、块长 32 时，写第 1 块的那几步要重算约 1000 个后缀位置，这成了 PrefixCache 剩下的大头。作者注意到，在分块生成下，后缀全是 [MASK]，在当前块解码期间它们的 key/value 同样几乎不变（原文图 3b），于是把后缀也缓存起来，称为 DualCache（双向缓存）：块内的每一步只把当前块的 \(B\) 个位置送进模型，当前块的 query 去和“缓存的前缀 + 缓存的后缀 + 当前块刚算出的”key/value 一起做注意力。

在官方代码里，这一步是这样实现的：每块开头那次整段前向得到整段的 key/value 缓存；块内每一步用一个 replace_position 掩码，只把缓存里当前块那一段替换成新算的值，其余部分原样保留。

DualCache 并不总是更快：8-shot GSM8K、生成长度 256 时，PrefixCache 是 10.0 倍，DualCache 是 9.4 倍，前者反而略快；生成越长、后缀越长，DualCache 的优势才越明显（512 时 13.9 倍对 15.8 倍，1024 时 18.6 倍对 27.6 倍，原文表 5）。论文正文的主表默认用的是 PrefixCache，标题里的 27.6 倍用的是 DualCache。

3.5 算一笔账：每一步还剩多少计算（推算）

以图 1(c) 的设置为例（生成长度 \(L=1024\)，块长 32，共 32 块），只数“每一步送进模型的位置数”：

  • 原版：每一步都是“提示 + 1024”个位置。
  • PrefixCache：写第 \(k\) 块时，每步送进 \(1024-32(k-1)\) 个位置，从 1024 一路降到 32，平均约 528 个；另外每块开头还有一次整段前向。
  • DualCache：每步只送 32 个位置；另外每块开头也有一次整段前向。

由此可以看出，长生成时 DualCache 的瓶颈转移到了“刷新”上。按图 1(c) 的数字粗算：DualCache 一共约 140 步，其中 32 步是每块开头的整段前向。如果每次整段前向和原版的一步一样耗时约 0.26 秒，32 次合计约 8.3 秒，占这条样本 12 秒中的三分之二左右；剩下约 108 个块内小步一共只用了约 3.7 秒，平均每步约 0.03 秒（推算，图中数字都经过四舍五入）。这也解释了为什么块不能切得太小：块越小，整段刷新的次数越多。

4 置信度感知并行解码：什么时候可以一次揭开好几个

这一节要回答的问题：既然同时揭开互相依赖的位置会出错，那么什么时候同时揭开是安全的？论文的回答是：模型足够有把握的时候。具体规则是什么？背后的定理到底证明了什么，前提又有哪些？由定理导出的“因子规则”和阈值规则有什么不同？

4.1 规则：只揭开有把握的位置

先补一点背景：置信度和贪心解码。

模型对一个 [MASK] 位置输出的是词表上的概率分布（softmax 之后的结果）。取其中最大的概率作为这个位置的置信度：0.99 表示模型几乎肯定是某个词，0.3 表示它在几个词之间犹豫。温度为 0 时做的是贪心解码，每个位置填的正是这个最大概率对应的词。LLaDA 的官方评测代码就是温度 0。

Fast-dLLM 的规则只有三句话。每一步，对当前块里所有还是 [MASK] 的位置算出置信度；把置信度不低于阈值 \(\tau\) 的位置全部揭开；如果一个都没过阈值，就只揭开置信度最高的那一个，保证每一步至少前进一个 token，不会卡死。其余的位置留到下一步重新预测。默认 \(\tau=0.9\)。

和 LLaDA 原来的“每步揭开置信度最高的 \(K\) 个”相比，区别在于个数不固定。容易的地方（比如答案后面成片的结束符、算式里已经确定的数字）一步可以揭开很多个；难的地方（比如推理中决定方向的那个词）自动退回一步一个。回到上一节的扑克例子：两个空的置信度都只有 0.3 左右，阈值规则一步只会揭开其中一个，于是自然避开了 full flush。

下面的小演示可以直接调阈值。画布是一句订机票的话，出发地和目的地都是两个词的城市名（New York、San Diego……），同一个城市名的前后两半必须配对，出发地和目的地也不能相同。调低阈值，平均每步揭开的 token 会变多、步数变少，但两半被同一步揭开、拼出 New Diego 这类错误组合的概率也会上升（演示里的概率是精确算出来的；它按温度 1 抽样，比论文的贪心设置更容易暴露问题）。

4.2 定理 1：高置信时，“逐位取最大”等于“整体取最大”

先补一点背景：定理用到的记号和两个距离。

记已经确定的内容（提示和已揭开的 token）为 \(E\)。假设这一步要同时揭开 \(n\) 个位置，它们的取值记为 \(\boldsymbol X=(X_{i_1},\dots,X_{i_n})\)。\(p(\boldsymbol X\mid E)\) 是模型“心里”的联合分布；\(p_j(X_{i_j}\mid E)\) 是第 \(j\) 个位置的边缘分布，模型实际输出的就是它。并行解码相当于用边缘分布的乘积 \(q(\boldsymbol X\mid E)=\prod_{j=1}^{n}p_j(X_{i_j}\mid E)\) 来代替联合分布。

衡量两个分布差多远，定理用了两个量。总变差距离 \(D_{\mathrm{TV}}(p,q)\) 是两个分布给同一个事件的概率之差的最大值，在 0 到 1 之间。KL 散度 \(D_{\mathrm{KL}}(p\Vert q)\) 是用 \(q\) 去近似 \(p\) 时平均多付出的信息量，单位是 nat。

定理的前提是：存在一组取值 \(x^*\)，使每个位置的边缘概率都超过 \(1-\epsilon\)，即 \(p_j(X_{i_j}=x^*_{i_j}\mid E)>1-\epsilon\)。结论分两部分。

第一部分（贪心等价）。如果 \((n+1)\epsilon\le1\)，那么

$$\arg\max_{\boldsymbol z}\,p(\boldsymbol z\mid E)=\arg\max_{\boldsymbol z}\,q(\boldsymbol z\mid E)=x^*$$

也就是说，各个位置分别挑最可能的词，和按联合分布挑最可能的一整组词，得到同一个结果。而且这个界是紧的：只要 \(\epsilon>1/(n+1)\)，就能构造出满足前提、两者却不一致的分布。

证明很短，值得走一遍（原文附录 A）：

  1. 每个位置在 \(x^*\) 上的边缘概率超过 \(1-\epsilon\)，而 \((n+1)\epsilon\le1\) 意味着 \(\epsilon\le1/2\)，所以这个概率超过一半，\(x^*\) 在每个位置上都是唯一的最大值点，自然也是乘积 \(q\) 的最大值点。
  2. “\(n\) 件事同时发生的概率”至少是“1 减去每件事不发生的概率之和”（Bonferroni 不等式）。每个位置不取 \(x^*\) 的概率都小于 \(\epsilon\)，所以 \(p(x^*\mid E)>1-n\epsilon\)。
  3. 任何别的组合 \(\boldsymbol z\neq x^*\) 至少在一个位置上和 \(x^*\) 不同，它的联合概率不可能超过“那个位置不取 \(x^*\)”的概率，所以 \(p(\boldsymbol z\mid E)<\epsilon\)。
  4. 只要 \(1-n\epsilon\ge\epsilon\)，也就是 \((n+1)\epsilon\le1\)，\(x^*\) 的联合概率就比任何别的组合都大。
示意图：定理条件满足与不满足的两种情况
本站示意图。左：两个位置、置信度都超过 0.9 时，\(x^*\) 的联合概率超过 0.8，任何别的组合都不到 0.1。右：本站构造的紧性反例（思路与原文附录 A 第 3 步相同）：两个二值位置，联合分布为 p(0,0)=0.30、p(1,0)=p(0,1)=0.35、p(1,1)=0。两个位置的边缘分布都偏向 0，逐位取最大得到 (0,0)，但它在联合分布里并不是最大的。

把阈值规则代进来看：阈值 \(\tau\) 等于要求每个被揭开的位置满足 \(\epsilon=1-\tau\)。\(\tau=0.9\) 时 \(\epsilon=0.1\)，定理要求 \(n\le9\)；也就是说，同一步揭开 9 个以内置信度在 0.9 以上的位置，即使在最坏情况下也和联合分布的最优组合一致（推算）。但阈值规则本身并不限制 \(n\)：如果一个块里有 20 个位置的置信度都恰好是 0.93，它们会被一次全部揭开，而这时定理的保证已经覆盖不到了。下面的因子规则正是为了补上这个缺口。

第二部分（分布距离）。当 \(n>1\) 时，

$$D_{\mathrm{TV}}(p,q)<\frac{3n-1}{2}\,\epsilon,\qquad D_{\mathrm{KL}}(p\,\Vert\,q)<(n-1)\Big(H_b(\epsilon)+\epsilon\ln\big(|\mathcal V|-1\big)\Big)$$

其中 \(H_b(\epsilon)=-\epsilon\ln\epsilon-(1-\epsilon)\ln(1-\epsilon)\) 是二元熵，\(|\mathcal V|\) 是词表大小；附录还给出了一般 \(L_p\) 距离的界。代入数字看看这两个界有多松（推算，LLaDA 词表大小 126,464）：两个位置、置信度 0.99（\(\epsilon=0.01\)）时，总变差距离小于 0.025，KL 小于约 0.17 nat；置信度降到 0.9（\(\epsilon=0.1\)）时，总变差的界变成 0.25，KL 的界变成约 1.5 nat，后者主要来自 \(\epsilon\ln|\mathcal V|\) 这一项。所以对 0.9 这个阈值而言，真正有分量的保证是第一部分的贪心等价，而不是分布距离。

这个定理容易被读得太强，有三点要分清：
  • 它比较的是“并行贪心”和“按模型自己的联合分布做贪心”，保证的是两者一致，不保证答案正确。模型如果很有把握地错了，并行和逐个揭开会一起错。在这个条件下，逐个揭开的贪心解码也会得到同一个 \(x^*\)（本站补充，证明思路与上面相同）。
  • 它假设存在一个自洽的联合分布，各位置的边缘分布都由它导出。掩码扩散模型是对每个位置分别输出条件分布的，这些分布未必能拼成一个一致的联合分布。作者在附录 A 的 Remark 1 里承认这一点，并认为模型越大越接近这个假设。
  • 界来自最坏情况。实际的依赖通常比反例温和，所以 \((n+1)\epsilon\) 略大于 1 时结论往往仍成立；反过来，定理也说明不了阈值调低以后准确率会掉多少，那只能靠实验回答。

4.3 因子规则：一步揭开几个，直接跟着定理走

作者把定理的条件直接改写成一条选择规则。把当前块里各位置的置信度从高到低排成 \(c^{(1)}\ge c^{(2)}\ge\cdots\)，找出满足下式的最大的 \(n\)，然后揭开置信度最高的 \(n\) 个（至少 1 个）：

$$(n+1)\big(1-c^{(n)}\big)<f$$

这里 \(1-c^{(n)}\) 是前 \(n\) 个位置里最没把握的那一个的“不确定度”，扮演定理里 \(\epsilon\) 的角色；\(f\) 是一个超参数，叫解码因子。\(f=1\) 时，这条规则几乎就是定理第一部分的条件；\(f\) 大于 1 则是有意放宽，用一点风险换更多并行。走两个例子（推算，\(f=1\)）：

  • 置信度依次为 0.99、0.97、0.95、0.90、0.85、0.60。\(n=5\) 时 \(6\times0.15=0.9<1\)，\(n=6\) 时 \(7\times0.40=2.8\)，所以揭开前 5 个。阈值 0.9 只会揭开前 4 个：这里因子规则更大胆。
  • 20 个位置的置信度都是 0.93。阈值规则会一次全部揭开；因子规则在 \(n=13\) 时 \(14\times0.07=0.98<1\)，\(n=14\) 时 \(15\times0.07=1.05\)，所以只揭开 13 个：这里因子规则更保守。

换句话说，阈值规则给每个位置单独设门槛，因子规则给“同时揭开的这一组”整体设门槛：一次揭开得越多，要求越严。附录 C.2 比较了两者（原文表 11）：因子规则的吞吐比阈值规则高约 1.3–1.5 倍，准确率低 0.8–2.4 个点。原文图 8 标出的主结果设置是 \(f=1.0\)，平均每步约 4.41 个 token（读自原图）；官方脚本的默认值也是 1.0。

def fast_dllm_generate(model, prompt, gen_len, B=32, tau=0.9, dual_cache=True):
    x = concat(prompt, [MASK] * gen_len)            # 答案区一开始全部是掩码
    for blk in range(gen_len // B):                 # 块从左到右
        s = len(prompt) + blk * B; e = s + B        # 当前块的位置范围 [s, e)
        logits, kv = model(x, return_kv=True)       # 整段前向：刷新缓存，同时解第一批
        unmask_confident(x, logits, s, e, tau)
        if not dual_cache:
            kv = kv[:, :s]                          # PrefixCache：只保留当前块之前的部分
        while (x[s:e] == MASK).any():
            if dual_cache:                          # 只算当前块，前缀和后缀都读缓存
                logits = model(x[s:e], past_kv=kv, replace=(s, e))
            else:                                   # 算当前块和全部后缀，前缀读缓存
                logits = model(x[s:], past_kv=kv)
            unmask_confident(x, logits, s, e, tau)
    return x

def unmask_confident(x, logits, s, e, tau):
    conf, tok = softmax(logits).max(-1)             # 温度 0：每个位置最可能的词及其概率
    cand = [i for i in range(s, e) if x[i] == MASK] # 只看当前块里仍是掩码的位置
    pick = [i for i in cand if conf[i] >= tau]
    if not pick:                                    # 一个都没过阈值：只揭开最有把握的
        pick = [max(cand, key=lambda i: conf[i])]
    for i in pick:
        x[i] = tok[i]

有两点和直觉不同，后面会用到。第一，答案后面补的结束符也在被“生成”：分块生成不会在写出结束符后提前停下，而是把所有块都走完，所以答案区设得越长，后面要填的结束符就越多。第二，阈值只在当前块内比较；块后面的位置即使置信度已经很高，也要等轮到它们所在的块。

5 实验：快了多少，掉了多少，和谁比

这一节要回答的问题：在两种开源扩散模型、四个常用基准上，Fast-dLLM 到底快了多少、准确率变了多少？这些倍数是和什么比出来的，在什么条件下最大？读完主表之后，本节最后用“结果的份量”一段把每个数字背后的比较条件讲清楚。

5.1 实验是怎么设的

  • 硬件与批大小：全部在一张 NVIDIA A100 80GB 上，一次只处理一条请求（batch size 1），不用任何推理加速框架（原文图 1 图注、§4.1）。
  • 模型：LLaDA（官方脚本用的是 LLaDA-8B-Instruct），附录另测 LLaDA-1.5；Dream（Dream-v0-Base-7B）；以及多模态的 LLaDA-V。
  • 基准：GSM8K（5-shot，小学数学应用题）、MATH（4-shot，竞赛数学）、HumanEval（0-shot，补全 Python 函数）、MBPP（3-shot，写 Python 小程序），统一用 lm-eval 评测；主表的生成长度为 256 和 512，消融里还有 GSM8K 8-shot、生成长度 1024。
  • 默认超参：PrefixCache，块长 32，阈值 0.9。设置部分称块长在 4–32、阈值在 0.5–1.0 之间调整过（图 4 的块长扫描实际做到了 256）。
  • 吞吐的定义：平均每秒输出的 token 数，从开始生成一直算到结束符。官方评测代码里，GSM8K 这类任务先按停止串截断答案，再数非结束符的 token；HumanEval 则数整段生成区里所有非结束符的 token。所以不同任务之间的吞吐不宜直接比较。
先补一点背景：表格里每一列是什么。

“LLaDA”“Dream”两列是不加任何加速的原版。LLaDA 原版每步揭开 1 个 token（步数 = 生成长度），块长 32，按置信度挑位置；Dream 原版也是每步 1 个 token，但不分块，整段按熵（另一种衡量把握大小的量）挑位置。“+缓存”只加 PrefixCache（Dream 加缓存时同时改成块长 32 的分块生成），“+并行”只加阈值并行解码，最后一列两者都加，也就是 Fast-dLLM。所有倍数都是相对原版那一列算的。

5.5 结果的份量

这一部分不打分，只把每个数字背后“和谁比、在什么条件下比”说清楚。

倍数的分母是什么。所有倍数的分母都是原版扩散模型最慢的那种设置：每步只揭开 1 个 token（生成 1024 个 token 就跑 1024 步），每步整段重算，用 Hugging Face 的实现，batch size 1。这是 LLaDA、Dream 为了保证质量常用的设置，用它做分母是合理的，但它也是最容易被大幅超越的分母。把 27.6 倍拆开看：只加并行解码已经有 13.3 倍（0.7 → 9.3 token/秒），缓存在此基础上再贡献约 2.1 倍（9.3 → 19.3，推算）。

公平的对照在哪里。要判断阈值规则本身好不好，应该在“每步揭开的 token 数相同”的条件下比准确率，原文图 5 就是这样比的（第 6 节有重画的图）。平均每步 4 个左右时，阈值规则（\(\tau=0.8\)，每步 4.24 个）的 GSM8K 准确率约 77.7%，而每步固定揭开 4 个只有约 66.5%（读自原图）。这比任何加速倍数都更能说明阈值规则的价值。

倍数为什么随生成长度上涨。原文表 5（8-shot GSM8K）里，生成长度 256、512、1024 时 DualCache 版本的倍数是 9.4、15.8、27.6。但看绝对值会发现，Fast-dLLM 自己也在变慢（46.3 → 36.4 → 19.3 token/秒），倍数变大主要是因为原版垮得更快（4.9 → 2.3 → 0.7）。原因与吞吐的算法有关：GSM8K 的答案长度并不会因为“生成长度”这个设置变大而变长，设成 1024 时，答案后面是几百个结束符或被截掉的内容，原版却仍要一步一个地把它们填完。按图 1(c) 推算，原版每条样本 266 秒、0.7 token/秒，只输出了约 186 个有效 token，1024 个位置里八成以上是答案之后的部分（推算，受四舍五入影响）。这些位置大多是模型很有把握的结束符，阈值规则可以用很少几步填完一块（本站推测）。所以“生成越长加速越大”，有相当一部分是在省填充位置的步数；如果原版遇到结束符就提前停下，或者生成长度设得贴近答案长度，倍数会小得多。

吞吐不等于延迟。吞吐按“有效 token 数 ÷ 时间”计算，而不同方法输出的有效 token 数并不完全相同。按图 1(c)，只加并行时每条样本约 26 秒、9.3 token/秒，约 242 个有效 token，比原版的约 186 个多（推算）。所以按单条样本的延迟算，原版到只加并行是约 10 倍（266 → 26 秒），到 DualCache 是约 22 倍（266 → 12 秒，推算），都低于吞吐口径的 13.3 倍和 27.6 倍。

和自回归模型比。原文图 1(a) 把 LLaMA-3-8B 和 Qwen2.5-7B 也放在同一条件下测了（A100、batch 1、不用推理框架、GSM8K 5-shot、生成长度 256）：读图约为 37 token/秒、77.9%（LLaMA-3-8B）和 40 token/秒、83.5%（Qwen2.5-7B）；加速后的 LLaDA 是 54.4 token/秒、78.5%。所以“dLLM 追上甚至超过自回归模型”只在单条请求、两边都不用推理引擎时成立；论文没有和 vLLM、SGLang 这类推理引擎里的自回归模型比。附录 C.5 测了批大小，但只开缓存、不开并行（作者说批量时并行解码会受填充 token 影响，为公平起见不测）：batch 32 时 PrefixCache 约 141–211 token/秒，而 LLaMA 约 435–650 token/秒（读自原文图 9，生成长度 16–64，提示长 256）。批越大，自回归模型越占优，论文在“局限”一段里也承认了这一点。

准确率的变化。主表里 Fast-dLLM 与原版的差距大多在 2 个点以内，但并非处处如此：表 5 生成长度 512 时，PrefixCache 低 4.1 个点、DualCache 低 3.5 个点；LLaDA-V 的 MathVista 低 2.6 个点。还要记住样本量：HumanEval 只有 164 题，1 道题就是 0.61 个点（推算），所以 HumanEval 上 ±2 个点的涨落只相当于三道题左右；GSM8K 测试集有 1,319 题，1 个点约 13 题。论文没有报告多次运行或误差范围；温度为 0 时结果基本是确定的，但 1–2 个点的差异仍可能只是少数几道题的翻转。

基准的性质。四个基准都是标准的数学和代码任务，少样本提示很长，这恰好有利于缓存。这些任务里，同一步揭开的几个 token 之间很少有强依赖；后来的 ParallelBench 专门构造了依赖很强的任务，发现阈值类并行解码在上面会明显掉点（见“后来怎么样了”）。

6.2 PrefixCache 还是 DualCache

表 5 已经给出答案：短生成时两者差不多（256 时 PrefixCache 甚至略快，10.0 倍对 9.4 倍），长生成时 DualCache 明显更快（1024 时 27.6 倍对 18.6 倍）。准确率两者相近（512 时 74.8% 对 75.4%，1024 时 75.7% 对 76.0%），但在 512 和 1024 时都比“只并行、不缓存”的版本低 2–4 个点（256 时只低不到 1 个点），这部分可以看作近似缓存的代价，而且生成越长代价越明显。附录 B 的单题案例里，原版、PrefixCache、DualCache 对同一道算术题给出几乎相同的推理过程，都答对了，只是措辞略有不同。

6.5 换成更强的 LLaDA-1.5（附录 C.3）

LLaDA-1.5 是 LLaDA 经过偏好优化后的版本。用同样的 Fast-dLLM 设置，GSM8K 生成 256 时准确率 80.7%、59.4 token/秒；生成 512 时 80.4%、33.0 token/秒；MATH 生成 256、512 时分别是 32.6%、53.7 token/秒和 35.1%、41.1 token/秒（原文表 12）。说明这套免训练的加速可以直接套到改进后的模型上，准确率随底座提升，速度大致相当。

6.6 批量与局限（附录 C.5）

先补一点背景：为什么批大小会改变谁快谁慢。

自回归模型每一步只为每条请求算 1 个新 token，GPU 的时间主要花在把模型参数从显存里读出来上，算力大部分闲着；把 32 条请求放进一批，参数仍只读一遍，产出却是 32 倍，所以批越大吞吐越高，直到算力用满为止（详见 vLLM 精读 §1）。扩散模型每一步本来就要处理几十到上千个位置，单条请求时算力已经用得比较满，批再大也很难再提速。

简图：批大小从 1 到 32 时的吞吐（只开缓存，不开并行；提示长 256）
本站用读自原文附录图 9（PDF 第 20 页 ↗）的约值重画，横轴按 2 的倍数等距排列。怎么看：batch 1 时三者都在每秒 25–30 个 token；原版 LLaDA 在 batch 8 以后几乎不再增长；PrefixCache 一路上升但逐渐变平；自回归的 LLaMA 几乎随批大小成比例增长，batch 32 时远远领先。线尾数字是 batch 32 时的吞吐。

这组实验在 A100 上固定提示长度 256，生成长度取 16、32、64，批大小从 1 到 32，只比较缓存（不开并行解码）。读图结果是：batch 1 时三者都在每秒 25–30 个 token；原版 LLaDA 在 batch 8 以后基本停在每秒 36–43 个；PrefixCache 在生成长度 16、batch 32 时达到约 211 个，约为原版的 5 倍（论文原文给出的就是 211 对 43）；LLaMA 则一路增长，batch 32 时约 435（生成 16）到 650（生成 64）个。作者的结论是：小批量时 PrefixCache 能和自回归模型相当甚至更快，批量变大后就追不上了；这是扩散模型每一步都要做整段注意力计算的共性问题。

这组实验能说明什么、不能说明什么：它的生成长度只有 16–64，没有开并行解码，自回归一侧也没有说明用的是什么推理框架。所以它只能说明趋势（批越大，自回归越占优），不能直接换算成真实服务里两者的差距。

7 相关工作与结论

这一节要回答的问题：Fast-dLLM 在扩散语言模型和推理加速这两条脉络里处在什么位置？它和“块扩散”这类同样能用 KV 缓存的方法有什么本质区别？作者最后的结论是什么？

扩散语言模型这条线。论文把离散扩散的理论基础串了一遍：D3PM 用转移矩阵定义离散状态上的加噪过程，并用 ELBO 训练反向过程；CTMC 把它推广到连续时间；SEDD 换了一个思路，去学不同数据之间的概率比值；MDLM、RADD 则说明掩码扩散的几种参数化其实等价。在和预训练模型结合方面，Diffusion-NAT 把离散扩散和 BART 的非自回归解码统一起来；LLaDA 和 DiffuLLaMA 把扩散语言模型扩展到了 70 亿参数这一量级；LLaDA 和 Dream 在多个任务上和 LLaMA3 这样的自回归模型可比。

推理加速这条线。KV 缓存是自回归 Transformer 推理的基本优化，但在 LLaDA 这样的全注意力模型上用不了。块扩散（Block Diffusion）的思路是让模型一块一块地生成、块与块之间是因果的，这样已完成块的 key/value 就能精确缓存。非自回归生成最早用于机器翻译，一直面临“快但质量差”的问题；扩散语言模型是它的新形态，而 LLaDA 等先前工作恰恰因为并行时掉点而没能兑现速度。

结论。作者把开源扩散语言模型推理慢归结为两点：没有 KV 缓存，以及并行解码时的质量下降。对前者，他们利用分块生成提出了适配双向注意力的近似 KV 缓存；对后者，他们指出根源是条件独立假设破坏了 token 之间的依赖，并用置信度感知的并行解码来规避。在 LLaDA 和 Dream 上，两者合起来最高带来 27.6 倍加速，准确率损失很小。

和块扩散的区别：块扩散（BD3-LM 精读）的缓存是精确的，因为模型训练时就用了块间因果的注意力；代价是要专门这样训练模型。Fast-dLLM 面对的是已经训练好的全双向模型，不改权重，所以它的缓存只能是近似的。同一团队后来的 Fast-dLLM v2 走的正是“改成块扩散再缓存”的路线（见下一节）。

后来怎么样了

“近似缓存 + 置信度阈值并行”很快成了扩散语言模型推理加速的一个基准做法，后来的工作大致沿三个方向推进：把缓存做得更准甚至精确，把并行度通过训练提上去，以及检验阈值规则在什么任务上会失效。在本站的扩散 LLM 路线里，可以接着读这些工作（下列数字均取自各论文摘要）：

  • dKV-Cache（新加坡国立大学，arXiv 首版 2025-05-21，比 Fast-dLLM 早一周，属于同期工作）：观察到一个 token 被定稿的那一步 key/value 变化最大、之后趋于稳定，于是只缓存已定稿的 token，并且延迟一步才写入；摘要报告 2–10 倍加速。它和 Fast-dLLM 是两种不同的近似：一个按“哪些 token 已经稳定”来缓存，一个按“哪一块正在写”来缓存。
  • D2F（2025-08）：用非对称蒸馏把 LLaDA、Dream 改造成块间因果、块内双向的学生模型，换来精确的块级 KV 缓存，并让后面的块不必等前面的块写完就开始解码；摘要报告在 GSM8K 上比 LLaMA3 和 Qwen2.5 快 2.5 倍以上，比原版 LLaDA、Dream 快 50 倍以上。D2F 的实验把 Fast-dLLM 当作此前最好的加速方法来对照，并在解码时沿用了它的置信度阈值。
  • Fast-dLLM v2（同一团队，2025-09）：不再在全双向模型上做近似，而是用约 10 亿 token 的微调把 Qwen2.5 改造成块扩散模型；块与块之间有精确的块级缓存，块内再用子块缓存和阈值并行解码；摘要报告相对标准自回归解码最高 2.5 倍。它的引言直接写道，v1 的 DualCache 这类近似缓存并没有从根本上解决扩散模型和 KV 缓存不兼容的问题。块扩散的原理见 BD3-LM 精读。
  • dParallel（2025-09）：认为并行度上不去的根源是掩码位置的置信度按顺序一个个收敛，于是用“确定性强制”蒸馏让模型更早、更同时地变得有把握；在 LLaDA-8B-Instruct 上把 GSM8K 的解码步数从 256 降到 30（8.5 倍）而不掉点。这条路线说明，阈值规则能并行多少，最终取决于模型本身有多少个位置“同时有把握”。
  • ParallelBench（2025-10）：指出数学、代码这类标准基准不足以暴露并行解码的问题，构造了对人和自回归模型都很简单、但 token 之间依赖很强的任务；结论之一是，现有的并行解码策略（包括阈值类）没法按任务难度调整并行度，难以在不掉质量的前提下真正提速。它的附录还测了 Fast-dLLM 的 PrefixCache，发现在这些任务上加缓存总体上会降低准确率。这正是第 4 节定理那几条前提在实践中的反面。

工程上，官方仓库后来发展成一个系列（Fast-dLLM v2、面向图文的 Fast-dVLM、面向自动驾驶的 Fast-dDrive）。仓库公告称 Fast-dLLM 已集成进 LLaDA-V 的官方代码，把多模态推理延迟从 60 秒降到 6 秒；截至 2026-10-19，README 中“vLLM 支持”一项仍标为进行中。
