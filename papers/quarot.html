0 导读：这篇论文解决什么问题

大模型推理很贵，一个直接的降本办法是量化：把模型里的数从 16 位浮点数换成更短的整数来存、来算。只把权重压成 4 bit（“weight-only”）已经很成熟，它能省显存、加快逐 token 生成，但矩阵乘法本身仍然在 16 位精度下进行。要让矩阵乘法也用上 GPU 上更快的 4 bit 整数单元，就必须把每个矩阵乘的两个输入都变成 4 bit：权重是一个，另一个是运行时才产生的激活。难点在于激活里有极少数数值特别大的“离群值”，它们会把整组数的量化刻度撑得很粗，使其余的数几乎全被舍成 0。此前的 4 bit 方案只能把离群的那几个通道单独挑出来，用高精度另算，代价是复杂的混合精度内核。

QuaRot 换了一个角度：既然离群值集中在少数几个坐标方向上，那就把整个隐藏状态换一组坐标来表示。具体做法是乘一个正交矩阵（几何上就是“旋转”）。旋转不改变向量的长度，却会把一个方向上的巨大数值均匀地摊到所有坐标上，离群值就消失了。关键在于这个旋转要做到“模型的输出完全不变”：作者借用他们在 SliceGPT 里发现的计算不变性，把大部分旋转矩阵提前乘进权重里，推理时完全不花时间；只在少数无法提前合并的位置，插入可以快速计算的 Hadamard 变换。这样一来，所有线性层的输入、以及 KV 缓存，都能直接用最简单的逐 token 4 bit 量化，不需要保留任何高精度通道。

最重要的结果：LLaMA-2-70B 在权重、激活、KV 缓存全部 4 bit 的设置下，WikiText-2 困惑度只比 FP16 高 0.47，六项零样本任务的平均准确率保留约 99%；在 RTX 3090 上，单个 Transformer 块的 prefill 最多快 3.33 倍，decode 时的峰值显存最多省 3.89 倍。小模型的损失明显更大（LLaMA-2-7B 平均准确率低 4.18 个百分点），这一点后面会反复强调。

1 引言：为什么 4 bit 推理要连激活一起量化

这一节要回答的问题：量化的目的是同时省显存和省计算。只量化权重能省显存，却省不了计算；要省计算，就得让矩阵乘的两边都是低比特。那么，激活为什么比权重难量化得多？之前的工作又是怎么勉强绕过去的？QuaRot 打算用什么完全不同的办法？
先补一点背景：4 bit 整数量化到底在做什么。

INT4 只能表示 16 个整数：−8 到 7。要用它表示一组实数，先选一个刻度（scale）\(s\)，把每个数除以 \(s\)、四舍五入成整数存起来，用的时候再乘回 \(s\)。最常用的对称量化把这组数里绝对值最大的那个映射到 7：

$$s=\frac{\max_i |x_i|}{7},\qquad q_i=\mathrm{clamp}\Big(\mathrm{round}\big(x_i/s\big),-8,7\Big),\qquad \hat x_i=s\,q_i .$$

四舍五入带来的误差最多是半个刻度 \(s/2\)。所以误差的大小由这组数里最大的那个决定：只要有一个数特别大，\(s\) 就特别大，其余所有的数都被量得很粗。这就是“离群值”伤害量化的根本原因。非对称量化额外存一个零点，把 \([\min,\max]\) 映射到 0 到 15，适合不以 0 为中心的数据（QuaRot 用它量化 KV 缓存）。

一组数共用一个刻度，“一组”怎么划叫粒度：整个张量一个刻度（per-tensor）；权重矩阵的每个输出通道一个刻度（per-channel）；激活的每个 token（矩阵的每一行）一个刻度（per-token）；或者每连续 128 个数一个刻度（group-wise，记作 128G）。粒度越细，误差越小，但要存的刻度越多，矩阵乘内核也越复杂。

先补一点背景：只量化权重，和权重、激活都量化，差在哪。

LLM 推理分两个阶段（详见 vLLM 精读 §2.2）。prefill 一次处理整段输入，几千个 token 同时过每一个线性层，是“矩阵乘矩阵”，计算量大、数据复用多，瓶颈在算力。decode 每步只为每个请求生成一个 token，是“矩阵乘向量”，每读一遍权重只做很少的计算，瓶颈在显存带宽。

只量化权重（例如 W4A16：权重 4 bit，激活 16 bit）的做法是：权重以 4 bit 存在显存里，算之前在芯片上解压回 FP16，再用 FP16 的 Tensor Core 去乘。它省下的是显存容量和读权重的带宽，所以对 decode 很有效；但乘法仍然是 FP16 乘法，对受算力限制的 prefill 几乎没有帮助。

权重、激活都量化（W4A4）则让矩阵乘的两个输入都是 INT4，可以直接交给 GPU 的 INT4 Tensor Core。以论文用的 RTX 3090 为例，NVIDIA 白皮书给出的稠密峰值是：INT4 568 TOPS，而 FP16（FP32 累加）只有 71 TFLOPS，相差 8 倍。只有走到这一步，prefill 才能真正变快。

用 LLaMA-2-7B 的一层算一笔账（推算）。一层的线性层共有约 2.02 亿个参数（注意力 4 × 4096² + 前馈 3 × 4096 × 11008），FP16 下约 0.40 GB。prefill 2048 个 token 时，这一层要做约 \(2\times2.02\times10^8\times2048\approx8.3\times10^{11}\) 次运算，却只需要把 0.40 GB 权重读一遍，每读一个字节要做约 2000 次运算；RTX 3090 的“算力 ÷ 带宽”只有 71 TFLOPS ÷ 936 GB/s ≈ 76，所以 prefill 远远受限于算力。decode 时批大小为 1，每读一个字节只做约 1 次运算，受限于带宽，这时只要权重变小就能变快，激活是不是 4 bit 无所谓。

下面这个交互小工具可以帮你建立直觉：选一个模型和 GPU，把批大小和上下文长度拖大拖小，看 prefill 和 decode 分别落在“带宽受限”还是“算力受限”的区域。只有落在算力受限区域的部分，才能从 INT4 Tensor Core 的更高算力里获益。（工具里的 GPU 是数据中心卡、按 16 位精度计算，用来理解两个阶段的区别即可。）

论文开头的判断是：prefill 受算力限制，所以“联合量化”（权重、KV 缓存和激活都降精度、用低精度做前向计算）是降低推理成本的关键一步。但激活比权重难量化得多，因为激活里有离群值，4 bit 时尤其严重。原文图 1 展示了 LLaMA-2-7B 第 10 层前馈网络输入的数值分布：原始模型里有几个通道的数值远远高出其他通道；经过 QuaRot 处理后，所有通道的分布变得平整，没有离群值。

此前的 4 bit 工作（QUIK、Atom）的做法是：先用一小批校准数据找出哪些通道是离群通道，推理时把这些通道单独用高精度计算。QuaRot 的做法则是用随机化的 Hadamard 变换旋转模型的输入，借助 SliceGPT 提出的计算不变性，把这些变换乘进权重矩阵，得到一个输出完全等价、但没有离群特征的网络。论文列出的贡献有三条：

  • 证明随机 Hadamard 变换可以直接乘进权重矩阵，不需要改模型结构，就能彻底消除离群特征、让激活容易量化，而模型输出不变。作者把它看作 SliceGPT 计算不变性的推广。
  • 把这个思路推广到注意力模块：在线地对 key 和 value 做 Hadamard 变换，消除其中的离群特征，使 KV 缓存也能量化。
  • 在此基础上实现了权重、激活、KV 缓存全部用整数 4 bit 的推理，并给出高效内核：LLaMA-2-70B 上 prefill 最高加速 3.33 倍（批大小 64、序列长度 2048），decode 阶段显存节省 3.89 倍，WikiText-2 困惑度损失不超过 0.47；零样本任务保留 99% 的准确率；6 bit 和 8 bit 只用最简单的四舍五入（RTN）就无损。
读的时候容易误解的地方：“端到端 4 bit”指的是所有线性层的矩阵乘都在 INT4 下进行、KV 缓存以 INT4 存储。并不是所有运算都是 4 bit：RMSNorm、残差相加、注意力里 softmax 和两次批量矩阵乘、SiLU 激活、在线 Hadamard 变换，以及词嵌入和输出头，仍然在 FP16 或 FP32 下进行（见第 4 节）。另外，摘要里的“3.33 倍”是单个 Transformer 块的 prefill 加速，不是整个模型生成文本的速度。

2 相关工作：离群值这道坎，前人是怎么绕的

这一节要回答的问题：在 QuaRot 之前，量化 LLM 的工作大致分成三条线：只量化权重、权重和激活一起量化、量化 KV 缓存。每条线分别遇到了什么困难，用了什么办法？哪些工作已经用过“旋转”？QuaRot 和它们的关键区别是什么？
先补一点背景：为什么“通道离群值”偏偏对激活量化是致命的。

一个线性层算的是 \(Y = XW\)，\(X\) 的形状是“token 数 × 输入通道数 \(k\)”，\(W\) 是“\(k\) × 输出通道数”。输出的每个元素是一次沿 \(k\) 维的求和：\(Y_{ij}=\sum_{t} X_{it}W_{tj}\)。

如果 \(X\) 的第 \(i\) 行共用一个刻度 \(s^x_i\)、\(W\) 的第 \(j\) 列共用一个刻度 \(s^w_j\)，那么两个刻度可以从求和号里提出来：

$$Y_{ij}\approx\sum_t \big(s^x_i\,q^x_{it}\big)\big(s^w_j\,q^w_{tj}\big)=s^x_i\,s^w_j\underbrace{\sum_t q^x_{it}\,q^w_{tj}}_{\text{INT4 Tensor Core 里的整数累加}} .$$

这正是 W4A4 能跑在整数单元上的原因：整数乘加在 Tensor Core 里一口气做完，最后只乘一次两个刻度。但它要求刻度沿求和维 \(k\) 不变。所以激活只能“每个 token 一个刻度”，不能“每个输入通道一个刻度”。

麻烦在于 LLM 的激活离群值恰好是按通道出现的：某几个固定的输入通道，在几乎所有 token 上数值都特别大（原文图 1 里那几道尖峰）。于是每个 token 的那一行里都含有离群值，每一行的刻度都被撑大，每一行里正常通道的数都被舍得很粗。权重没有这个问题，因为权重的分布要平整得多，而且可以离线慢慢优化。

只量化权重的方法（GPTQ、AWQ、SpQR、AQLM、QuIP# 等）把每个权重压成低比特，计算前再还原成高精度，主要计算仍在高精度下进行。论文把它们作为背景，不作为直接对手。

权重和激活一起量化的方法都在和离群值较劲：

  • LLM.int8()（Dettmers 等，NeurIPS 2022）在 8 bit 下发现了这种“涌现的”离群特征，做法是推理时实时找出离群特征维度，把这几维单独拿出来做 16 bit 矩阵乘，其余超过 99.9% 的数值用 8 bit。QuaRot 的评价是这样做性能不好，因为拆分本身就有开销。
  • SmoothQuant（Xiao 等，ICML 2023）的办法是把每个输入通道的激活除以一个系数、同时把权重对应的行乘以同一个系数。数学上输出不变，但“量化难度”从激活挪到了权重上。系数要用校准数据确定，还多了一个需要调的超参数。它解决了 8 bit（W8A8），但到了 4 bit 就不够用了：表 1 里它在 LLaMA-2-7B 上的困惑度是 83.12。
  • QUIK（Ashkboos 等，2023，与本文同一第一作者）和 Atom（Zhao 等，2023）把离群通道离线找出来，推理时保留在高精度：QUIK 每层留 256 个 FP16 离群通道，并把最难的 down-projection 层留在 8 bit；Atom 把 128 个离群通道重排到矩阵末尾、用 INT8 计算，并为此写了复杂的混合精度矩阵乘内核。
  • OmniQuant（Shao 等，2023）用校准数据训练可学习的裁剪阈值和等价变换，属于“轻量重训练”。
先补一点背景：QuIP 和 QuIP# 用旋转做了什么。

QuIP（Chee 等，NeurIPS 2023）研究的是 2 bit 的只量化权重。它的出发点是：如果权重矩阵的元素大小都差不多（没有特别突出的元素），就容易量化。它把这种性质叫做“非相干”（incoherent），并提出非相干处理：在权重矩阵左右各乘一个随机正交矩阵 \(W\to UWV^\top\)，量化完再在推理时把 \(U\)、\(V\) 的作用撤销。QuIP#（Tseng 等，ICML 2024）把随机正交矩阵换成计算更快的随机 Hadamard 变换，再配上格点码本和微调。这两项工作的旋转只是为了量化权重，激活不量化；而且推理时每个权重矩阵前后都要各做一次变换来“撤销”旋转。

另外，Xi 等（NeurIPS 2023）在用 4 bit 整数训练 Transformer 时，也在每个线性层的前向计算里用了精确的 Hadamard 变换。

KV 缓存量化是另一条线。生成长文本或开大批量时，KV 缓存会成为显存的主要占用（见 vLLM 精读 §3）。FlexGen 用 4 bit 分组量化 KV 缓存；KVQuant 推到 3 bit；KIVI 做到了 2 bit（见本站 KIVI 精读）。这些工作都发现 key 里也有按通道出现的离群值，于是各自用了一套复杂的手段：按通道量化 key、非均匀量化、把离群值留成高精度。以 KIVI 为例，它的结论是 key 应该“按通道”分组量化、value 应该“按 token”分组量化，正是因为 key 的离群值固定出现在某几个通道上。QuaRot 走的是另一条路：先把 key 旋转一下，让离群通道消失，key 也就可以像 value 一样简单地按 token 量化了（第 4.5 节）。

QuaRot 的定位于是很清楚：它也用 Hadamard 变换做非相干处理，但不在推理时撤销变换，而是借助 SliceGPT 的计算不变性，尽可能把变换直接融合进权重。QuIP# 需要每个权重矩阵在前向时做两次 Hadamard 变换，QuaRot 每个 Transformer 层只需要“一个半”（第 4 节解释这个数是怎么来的）。更重要的是，计算不变性意味着激活也一起被做了非相干处理，所以激活也能被有效量化。同样的技巧用到注意力块上，就能把 KV 缓存量化到 4 bit。

容易混淆的一点：QuIP/QuIP# 的旋转是“量化前转过去、计算时转回来”，模型结构不变但推理多了开销；QuaRot 的旋转是“把转动直接写进权重，让整个网络从此就在新坐标系里运行”，大部分旋转在推理时不存在。两者用的数学工具一样，用法完全不同。

3 背景：正交矩阵、Hadamard 变换、非相干处理与计算不变性

这一节要回答的问题：QuaRot 用到的数学工具只有四样：正交矩阵（尤其是 Hadamard 矩阵）、衡量“离群程度”的非相干性、Transformer 的 pre-norm 结构，以及 SliceGPT 证明的计算不变性。这一节把它们一一讲清楚：为什么“旋转”能把离群值摊平？为什么旋转可以写进权重而不改变输出？为什么偏偏是 Hadamard 矩阵？

3.1 正交矩阵与 Hadamard 矩阵

一个方阵 \(Q\) 满足 \(QQ^\top=I\)，就叫正交矩阵。几何上，它把向量旋转（或翻转）到另一个方向，但不改变长度：\(\|xQ\|=\|x\|\)。论文把所有实正交矩阵都称为“旋转矩阵”。

Hadamard 矩阵是一种特殊的正交矩阵：它的元素全是 \(+1\) 或 \(-1\)（再乘一个归一化系数）。最常用的是 Walsh–Hadamard 矩阵，大小是 2 的幂，可以由 2×2 的“种子”反复做 Kronecker 积得到：

$$H_2=\frac{1}{\sqrt2}\begin{pmatrix}1&1\\1&-1\end{pmatrix},\qquad H_{2^n}=H_2\otimes H_{2^{n-1}} .$$

Kronecker 积 \(A\otimes B\) 的意思是：把 \(A\) 的每个元素 \(a_{ij}\) 换成一整块 \(a_{ij}B\)。所以 \(H_4\) 就是 \(H_2\) 的四个位置各放一块 \(\pm H_2\)，依此类推。这种递归结构带来一个重要好处：计算 \(Hx\) 不需要 \(d^2\) 次乘加，只需要 \(d\log_2 d\) 次加减，这就是快速 Walsh–Hadamard 变换。

示意图：d = 8 的快速 Walsh–Hadamard 变换（蝶形图）
本站示意图。d = 4096 时，快速变换只需 4096 × 12 ≈ 4.9 万次加减，而稠密矩阵乘需要 4096² ≈ 1678 万次乘加（推算）。这就是 QuaRot 在推理时坚持用 Hadamard 矩阵、而不用任意正交矩阵的原因：前者在线计算几乎免费。QuaRot 的代码用 Dao AI Lab 的 fast-hadamard-transform CUDA 库来做这一步。

大小不是 2 的幂时，Hadamard 矩阵不一定存在。论文的做法是把维度分解成 \(d=2^n m\)，其中 \(m\) 是一个已知存在 Hadamard 矩阵的大小（Sloane 维护的 Hadamard 矩阵库里查得到），再用 Kronecker 积 \(H_d=H_{2^n}\otimes H_m\)，计算量是 \(O(d(m+n))\)。从官方代码看，LLaMA-2-7B 的 FFN 中间维 11008 = 64 × 172，13B 的 13824 = 128 × 108，70B 的 28672 = 1024 × 28，代码里分别内置了 172、108、28 阶的 Hadamard 矩阵（据 hadamard_utils.py）。

最后，借用 QuIP# 的做法，QuaRot 在方便的地方用随机化 Hadamard 矩阵 \(\tilde H=H\,\mathrm{diag}(s)\)，其中 \(s\) 是一串随机的 \(\pm1\)。也就是先随机翻转每个坐标的正负号，再做 Hadamard 变换。翻转符号本身也是正交变换，所以 \(\tilde H\) 仍然正交；加入随机性是为了避免某个特定输入恰好和 Hadamard 的基方向对齐、变换后反而集中。

3.2 非相干处理：为什么旋转能把离群值摊平

QuIP 给“离群程度”下了一个定义：一个 \(m\times n\) 的矩阵 \(W\) 称为 \(\mu\)-非相干，如果

$$\max_{ij}|W_{ij}|\;\le\;\mu\,\frac{\|W\|_F}{\sqrt{mn}} .$$

右边的 \(\|W\|_F/\sqrt{mn}\) 是所有元素的均方根，也就是“典型元素有多大”。所以 \(\mu\) 就是“最大元素是典型元素的几倍”。所有元素一样大时 \(\mu=1\)；一个元素独大时 \(\mu\) 接近 \(\sqrt{mn}\)。\(\mu\) 越大，越难量化，因为刻度由最大元素决定，典型元素只能分到很少的几个量化格。

为什么乘一个随机正交矩阵能让 \(\mu\) 变小？看一个向量 \(x\) 经过 Hadamard 变换后的第 \(j\) 个坐标：\((Hx)_j=\frac{1}{\sqrt d}\sum_i \pm x_i\)。它是所有原坐标带随机符号的加权和。原来集中在一个坐标上的巨大数值，被平均分给了全部 \(d\) 个新坐标，每个新坐标只分到 \(1/\sqrt d\)；而大量小数值相加时正负抵消，结果的大小接近一个高斯分布。总长度不变，但“最大值 / 均方根”被压到了接近高斯分布的水平。QuIP 和 QuIP# 对这一点给出了概率上的保证。

示意图：同一个 8 维向量，旋转前后做 INT4 对称量化（数字为本站计算）
本站示意图，数字为推算：\(x=(0.4,-0.6,0.3,9.0,-0.2,0.5,-0.4,0.1)\)，\(H\) 是归一化的 8 阶 Walsh–Hadamard 矩阵，两边都做逐向量对称 INT4 量化。“最大值 / 均方根”从 2.81 降到 1.11。换成更接近真实模型的设置——4096 维、其中一维是 100、其余是标准正态、用随机 Hadamard 变换——本站模拟得到的“最大值 / 均方根”从 54 降到 2.9，正常通道的量化误差（均方根）从 1.00 降到 0.22（推算，随机种子 0）。

QuaRot 把这个思路同时用在权重和激活上。对权重，乘正交矩阵降低了非相干系数，这一点和 QuIP 一样；对激活，原文图 1 已经展示了效果：处理后的激活不再有离群值。

一个自然的问题是：既然任何随机正交矩阵都能“摊平”离群值，为什么偏要 Hadamard？理由有两层。第一层是速度：在线的那几处变换必须用快速算法，只有 Hadamard 这类结构化矩阵才有 \(O(d\log d)\) 的算法。第二层是效果：Hadamard 矩阵的每个元素绝对值都一样（都是 \(1/\sqrt d\)），任何一个坐标上的能量都会被严格均匀地分到所有新坐标上；而一般的随机正交矩阵只是“平均意义上”均匀，个别元素可能偏大。QuIP# 从理论上说明了随机 Hadamard 给出的最大值上界更紧。QuaRot 的消融（第 5.4 节）也证实了这一点：即使在只需离线融合、速度无所谓的残差流旋转上，随机 Hadamard 也比随机正交矩阵好得多。

3.3 Transformer 的结构：pre-norm、RMSNorm 和门控 FFN

论文假设模型是“pre-norm”结构：每个注意力块、每个前馈块之前都有一个 LayerNorm 或 RMSNorm，块的输出直接加回残差流。LLaMA-2 就是这样。它的前馈网络（FFN）是门控结构（SwiGLU）：输入先经过 RMSNorm，再分两路乘 \(W_{\text{gate}}\) 和 \(W_{\text{up}}\)，门控那一路过激活函数 \(\sigma\)（SiLU）后与另一路逐元素相乘，最后乘 \(W_{\text{down}}\) 得到输出。

$$\mathrm{RMSNorm}(x)=\frac{x}{\|x\|/\sqrt d}\odot\alpha,\qquad \mathrm{FFN}(x)=\Big(\sigma\big(\tilde xW_{\text{gate}}\big)\odot\big(\tilde xW_{\text{up}}\big)\Big)W_{\text{down}},\quad \tilde x=\mathrm{RMSNorm}(x)$$

这里 \(\alpha\) 是 RMSNorm 的可学习缩放参数，逐维相乘。原文图 2 画的就是这个 FFN，图 5 画的是带 RoPE 的注意力块：RMSNorm 之后分三路乘 \(W_q\)、\(W_k\)、\(W_v\)，\(q\)、\(k\) 加上旋转位置编码，做多头注意力，key 和 value 存进 KV 缓存，最后乘 \(W_{\text{out}}\)。量化之前，这些运算以 FP32 或 FP16 进行。

3.4 计算不变性：旋转可以“写进”权重

先补一点背景：SliceGPT 和它发现的计算不变性。

SliceGPT（Ashkboos 等，ICLR 2024，与本文第一作者、Croci、Hoefler、Hensman 共同完成）是一篇剪枝论文：它把每层的隐藏状态先转到主成分方向，再整行整列地删掉不重要的方向，最多删掉 LLaMA-2-70B 等模型 25% 的参数。为了让“转到主成分方向”不改变模型输出，作者证明了一个定理：Transformer 的权重和块与块之间传递的激活，可以用同一个正交矩阵做变换，而模型的输出保持不变。这就是计算不变性。QuaRot 把这个定理从“为了删维度而旋转”改成了“为了消离群值而旋转”。

它为什么成立？关键是 RMSNorm。暂时假设 RMSNorm 没有缩放参数 \(\alpha\)，只做“除以长度”（论文写作 \(x_i\leftarrow x_i/\|x_i\|\)）。因为正交矩阵不改变长度，\(\|xQ\|=\|x\|\)，所以

$$\mathrm{RMSNorm}(XQ)=\frac{XQ}{\|XQ\|}=\frac{X}{\|X\|}\,Q=\mathrm{RMSNorm}(X)\,Q .$$

也就是说，RMSNorm 和旋转可以交换顺序。论文的式 (3) 写成等价的形式 \(\mathrm{RMSNorm}(X)=\mathrm{RMSNorm}(XQ^\top)Q\)。

有了这个性质，就可以把整条残差流都换到旋转后的坐标里：

  • 入口：把词嵌入矩阵右乘 \(Q\)，残差流从第一层开始就是 \(XQ\)。
  • 每个块的输入一侧：块先做 RMSNorm，得到 \(\mathrm{RMSNorm}(X)Q\)；把块的输入权重（\(W_q,W_k,W_v\) 或 \(W_{\text{gate}},W_{\text{up}}\)）左乘 \(Q^\top\)，乘法结果是 \(\mathrm{RMSNorm}(X)QQ^\top W=\mathrm{RMSNorm}(X)W\)，与原模型完全一样。所以块内部的计算没有任何变化。
  • 每个块的输出一侧：把输出权重（\(W_{\text{out}}\) 或 \(W_{\text{down}}\)）右乘 \(Q\)，块的输出变成原输出乘 \(Q\)，加回残差流后，残差流仍然是“原残差流乘 \(Q\)”。
  • 出口：最后的 RMSNorm 之后，输出头左乘 \(Q^\top\)，得到的 logits 与原模型相同。

剩下的是缩放参数 \(\alpha\)。逐维缩放 \(\mathrm{diag}(\alpha)\) 和旋转不能交换，所以要先把它“搬走”：把 \(\mathrm{diag}(\alpha)\) 乘进紧随其后的权重矩阵（\(W\leftarrow\mathrm{diag}(\alpha)W\)），RMSNorm 本身只保留“除以长度”的部分。对 OPT 这类用 LayerNorm 的模型，还要先把“减均值”这一步（也是一个线性投影）乘进前一层的权重，把 LayerNorm 变成 RMSNorm；官方代码的 fuse_layer_norms 就是做这件事的。

示意图：计算不变性——整条残差流在旋转后的坐标里运行
本站示意图，蓝色框表示离线改写过的权重，推理时不需要任何额外计算。对应原文 §3.4 与图 3、图 6 中带 \(Q\) 的部分。

这一步做完之后，有两个副作用正好是量化想要的：第一，所有权重都被正交矩阵乘过一次，非相干系数降低，和 QuIP# 对权重做的处理类似，但推理时不需要任何额外操作；第二，块与块之间传递的激活变成了 \(XQ\)，也就是被做了非相干处理，离群值消失了。

容易忽略的一点：因为每一层都要把输出加回同一条残差流，所有层必须共用同一个 \(Q\)：第 3 层用的旋转和第 30 层用的旋转是同一个矩阵。这既是 QuaRot 简单的原因，也是它的约束——后来的 FlatQuant 就专门指出，残差连接把所有块的变换绑在了一起。另外，“输出不变”只在精确算术下成立；权重以 FP16 存储时，乘进 \(Q\) 会引入极小的舍入差异（官方代码用 FP64 做这些矩阵乘再转回原精度）。

4 方法：一层里的四处旋转，和三步量化

这一节要回答的问题：第 3 节的计算不变性只旋转了“块与块之间”的激活。可是一个线性层的输入并不都来自残差流：FFN 里的 down-projection 吃的是 SwiGLU 的输出，注意力的输出投影吃的是多头注意力的输出，KV 缓存里存的是投影加位置编码之后的 key 和 value。这些“块内部”的激活怎么旋转？哪些旋转能提前乘进权重，哪些必须在推理时实时算？旋转完之后，权重、激活、KV 缓存又分别用什么方法量化？

4.1 总览：先在全精度下旋转，再量化

QuaRot 分两个阶段。第一阶段在全精度下改写模型：把旋转矩阵乘进权重，并在前向计算里插入几个在线 Hadamard 变换。这一阶段做完，模型的输出（在精确算术下）不变。第二阶段才真正量化：用现成的方法（默认 GPTQ）量化权重，并在前向计算里插入在线的量化操作，现场把激活和 KV 缓存量化成 4 bit。激活的量化用最简单的四舍五入（RTN）。下图把两个阶段的结果画在一张图里。

4.2 第 1a 步：旋转残差流

先把 RMSNorm（或 LayerNorm）的线性部分并进相邻的权重矩阵，然后选一个大小等于隐藏维度的随机化 Hadamard 矩阵 \(Q\)，按第 3.4 节的方法把每个权重矩阵左乘或右乘它。以 key 投影为例：

$$W_k\;\leftarrow\;Q^\top\,\mathrm{diag}(\alpha)\,W_k ,$$

其他块输入一侧的矩阵同理；块输出一侧的矩阵右乘 \(Q\)。按计算不变性，这一步不改变模型输出（在数值精度足够的前提下）。改写后的权重和 QuIP# 处理过的权重形态相似，非相干系数降低了，但 QuaRot 在推理时不需要任何额外处理。与此同时，块与块之间传递的激活也变成了 \(X\leftarrow XQ\)，原文图 1 显示它们不再有离群值。

这一步之后，四类线性层输入中的两类已经被旋转好了：注意力的 \(W_q,W_k,W_v\) 和前馈块的 \(W_{\text{gate}},W_{\text{up}}\)，它们的输入都是 RMSNorm 之后的残差流。剩下的两类是 down-projection 的输入和输出投影 \(W_o\) 的输入，再加上 KV 缓存，需要后面三步分别处理。

4.3 第 1b 步：前馈块内部，插一个在线 Hadamard

down-projection 的输入是 \(\sigma(\tilde xW_{\text{gate}})\odot(\tilde xW_{\text{up}})\)。SiLU 和逐元素相乘都是逐坐标的非线性运算，它们和旋转不能交换：先旋转再取 SiLU，不等于先取 SiLU 再旋转。所以没法像第 1a 步那样把一个旋转从 \(W_{\text{up}}\) 的输出“推”过非线性，一直推到 down-projection 的输入。这个位置的激活没有被旋转过，而它恰恰是离群值最严重的地方之一（QUIK 也正是因此才把 down-projection 留在 8 bit）。

QuaRot 的办法是：在 down-projection 之前，在线做一次 Hadamard 变换 \(h\to hH\)，用全精度计算，并按 QuIP# 的方式用快速内核实现；然后把它的逆乘进 down-projection 的权重：\(W_{\text{down}}\leftarrow HW_{\text{down}}\)。因为这里的 \(H\) 是确定的 Walsh–Hadamard 矩阵（对称且 \(HH=I\)），\((hH)(HW_{\text{down}})=hW_{\text{down}}\)，输出不变。再叠加第 1a 步的 \(Q\)，down-projection 的权重最终是 \(HW_{\text{down}}Q\)。

这个在线变换的维度是 FFN 的中间维，LLaMA-2-7B 是 11008，不是 2 的幂，所以要用第 3.1 节的 Kronecker 构造：11008 = 64 × 172，先做 64 点的快速变换，再乘一个 172 阶的小 Hadamard 矩阵。

4.4 第 1c 步：value 与输出投影，一半离线、一半在线

输出投影 \(W_o\)（论文记作 \(W_{\text{out}}\)）的输入是多头注意力的输出，同样没有被旋转过。作者注意到，在每个头内部，\(W_v\) 和 \(W_{\text{out}}\) 实际上是被乘在一起的：

$$Y=\mathrm{concat}\big[P_1V_1,\dots,P_{n_h}V_{n_h}\big]W_{\text{out}}=\sum_{h=1}^{n_h}P_h\,X\,W_v^{(h)}\,W_{\text{out}}^{(h)} ,$$

其中 \(P_h\) 是第 \(h\) 个头的注意力权重矩阵（序列长度 × 序列长度，由 query 和 key 经 softmax 算出），\(V_h=XW_v^{(h)}\) 是这个头的 value，\(W_{\text{out}}^{(h)}\) 是 \(W_{\text{out}}\) 中对应这个头的那几行。\(P_h\) 作用在“序列”这一维上，\(W_v^{(h)}W_{\text{out}}^{(h)}\) 作用在“特征”这一维上，两者互不干扰。所以可以在中间插一对互逆的、大小为头维度 \(d_h\) 的 Hadamard 矩阵：

$$W_v^{(h)}\leftarrow W_v^{(h)}H_{d_h},\qquad W_{\text{out}}^{(h)}\leftarrow H_{d_h}W_{\text{out}}^{(h)} ,$$

代回去，结果不变。所有头的权重在矩阵里是拼在一起的，所以这等价于一次 Kronecker 结构的乘法：\(W_v\leftarrow W_v(I\otimes H_{d_h})\)，\(W_{\text{out}}\leftarrow(I\otimes H_{d_h})W_{\text{out}}\)。这一步完全离线，有两个效果：value 向量被逐头旋转了，所以 V 缓存可以量化；注意力的输出也被逐头旋转了。

但“逐头旋转”只在每个头的 \(d_h\) 维内部混合，不同头之间没有混合。如果离群值集中在某几个头上，它们仍然存在。为了对整个 \(n_hd_h\) 维的注意力输出做一次完整的 Hadamard 变换，作者用了一个恒等式（\(n_h\) 和 \(d_h\) 都是 2 的幂时成立）：

$$H_{n_h d_h}=(I\otimes H_{d_h})(H_{n_h}\otimes I) .$$

前一半 \((I\otimes H_{d_h})\) 已经离线乘进了 \(W_v\)；只需要再在推理时对注意力输出 \(Z\) 在线乘上后一半 \(Z\leftarrow Z(H_{n_h}\otimes I)\)，同时把 \(W_{\text{out}}\) 完整地换成 \(HW_{\text{out}}\)。原文图 6 把这个在线步骤叫做 “Hadamard heads”。它的计算很便宜：把 \(Z\) 重排成 \(n_h\times d_h\) 的矩阵，对每一列做一次长度 \(n_h\) 的 Walsh–Hadamard 变换即可。

4.5 第 1d 步：key 的旋转——RoPE 挡住了离线融合

先补一点背景：RoPE 为什么会挡路。

旋转位置编码（RoPE，见本站 RoFormer 精读）把 query 和 key 的每两个相邻维度看成一个二维平面，按 token 的位置转一个角度。它是在 \(XW_q\)、\(XW_k\) 算出来之后才施加的，而且转多少取决于位置。如果把一个 Hadamard 矩阵乘进 \(W_k\)，它会在 RoPE 之前生效，而 RoPE 的“两两一组按位置旋转”和 Hadamard 的“所有维度一起混合”不能交换顺序。所以 key 的旋转不能像 value 那样离线融合。

但 key 的量化同样重要：已有的 KV 缓存量化工作（KVQuant、KIVI）都发现 key 里有按通道的离群值。注意力分数是 \(P_h=\mathrm{Softmax}\big(\alpha\,\mathrm{Pos}(Q_h)\mathrm{Pos}(K_h)^\top\odot M\big)\)，其中 \(\mathrm{Pos}\) 是位置编码，\(M\) 是因果掩码，\(\alpha=1/\sqrt{d_h}\)。query 和 key 之间的关系和 value 与输出投影之间一样：只要两边乘上同一个正交矩阵，内积就不变。于是 QuaRot 在 RoPE 之后，对每个头的 query 和 key 都在线乘一个 \(H_{d_h}\)：

$$\mathrm{Pos}(Q_h)H_{d_h}\big(\mathrm{Pos}(K_h)H_{d_h}\big)^\top=\mathrm{Pos}(Q_h)\,H_{d_h}H_{d_h}^\top\,\mathrm{Pos}(K_h)^\top=\mathrm{Pos}(Q_h)\mathrm{Pos}(K_h)^\top .$$

注意力分数完全不变，而存进缓存的 key 是旋转过的，没有离群值，可以量化到 4 bit。

论文还讨论了另一种选择：Pre-RoPE 缓存（KVQuant 提出）。它把加位置编码之前的 key 存进缓存，这样旋转就能离线融进 \(W_k\)，query 也不用旋转；代价是每一步解码时，都得把缓存里所有的 key 在线反旋转、再加位置编码。解码时每步只有一个 query，却有成千上万个缓存的 key，这样做太贵。QuaRot 选择 Post-RoPE 缓存：每一步只需要对新来的那一个 token 的 query 和 key 做一次长度 \(d_h\) 的 Hadamard 变换。

到这里，第一阶段全部完成。效果可以概括成一句话：块与块之间的激活被乘上了一个 Hadamard 矩阵；块内部的激活由在线 Hadamard 变换处理，而这些变换又被对应的权重修改抵消。前向计算的结果没有变，可以开始量化了。

4.6 小结：每一处旋转放在哪、离线还是在线、各花多少

4.7 第 2a 步：量化权重（GPTQ 或 RTN）

先补一点背景：GPTQ 比“四舍五入”强在哪。

最简单的权重量化是 RTN（round-to-nearest）：每个权重独立地四舍五入到最近的格点。它不需要任何数据，但每个权重的误差都各自留在那里。GPTQ（Frantar、Ashkboos、Hoefler、Alistarh，2022）是逐层的“带补偿的量化”：它用一小批校准数据算出这一层输入的二阶统计量（近似 Hessian \(H=2XX^\top\)），然后一列一列地量化权重；每量化一列，就根据 Hessian 把这一列产生的误差分摊到还没量化的列上，让这一层的输出 \(XW\) 尽量接近原来。它能在几个 GPU 小时内量化上千亿参数的模型，是 4 bit 权重量化的标准做法之一。

经过第一阶段的改写，任何权重量化方法都能直接用。QuaRot 默认用 GPTQ，权重逐输出通道对称量化，每一列的裁剪比例用线性搜索、按平方误差最小来选。校准集是 WikiText-2 训练集的 128 条样本，每条 2048 个 token。论文给出的耗时：在一张 A100 上，用 QuaRot 改写 LLaMA-2-70B 需要 5 分钟，再用 GPTQ 量化需要 2 小时。第 5 节还会看到，换成完全不需要数据的 RTN 也能用，只是精度差一些。

4.8 第 2b 步：在线量化激活

权重量化好之后，在每个线性层前插入一个量化操作，现场把激活变成 INT4：

  • RMSNorm（已经去掉了 \(\alpha\)）按 PyTorch 的实现留在 FP32 下计算。
  • 线性层的输入逐 token 对称量化：每一行（一个 token）取绝对值最大值，除以 7（INT4 能表示的最大正数）得到这一行的刻度，再把这一行除以刻度、四舍五入。实验里对激活统一用 0.9 的裁剪比例，也就是把最大值先乘 0.9 再算刻度，让少数极端值被截断、换取其余数值更细的刻度。
  • INT4 矩阵乘的输出是 INT32。反量化时把它转成 FP16，再乘上对应的行刻度（来自输入）和列刻度（来自权重），也就是第 2 节那个公式里的 \(s^x_is^w_j\)。

举一个小例子（推算）。某个 token 的一行激活是 \((0.9,-2.1,0.3,1.4)\)。绝对值最大是 2.1，乘裁剪比例 0.9 得 1.89，刻度 \(s=1.89/7=0.27\)。各数除以 0.27 再四舍五入得 \((3,-8,1,5)\)；其中 \(-2.1/0.27\approx-7.78\) 舍入成 \(-8\)，正好用上了 INT4 最小的那个值。还原回来是 \((0.81,-2.16,0.27,1.35)\)，每个数的误差都不超过 0.09。如果这一行里有一个离群值 20，刻度就会变成约 2.6，这四个数会被量成 \((0,-1,0,1)\)，几乎全部信息都丢了。旋转的作用，就是保证每一行都更像前一种情况。

示意图：一个 W4A4 线性层在推理时的四个内核（据官方代码 quarot/nn/linear.py、quarot/kernels/）
FP16 激活每行一个 token→（可选）在线 Hadamard只在 W_down、W_o 之前→量化内核求每行最大值 → 刻度 → 四舍五入，两个 INT4 打包进一个字节→CUTLASS INT4 GEMMTensor Core，INT32 累加→反量化内核INT32 → FP16，× 行刻度 × 列刻度
四步是四个独立的内核，量化和反量化没有融合进矩阵乘。论文在性能部分明确说，把量化操作融合进矩阵乘还能进一步提速。这也是第 5 节里“单个线性层快 3.2–4.3 倍，整个块只快 2–3.3 倍”的原因之一。

4.9 第 2c 步：量化注意力与 KV 缓存

序列变长、批变大之后，注意力会受显存带宽限制，因为每一步都要把整份 KV 缓存读一遍。key 和 value 都旋转过之后，就可以把缓存量化成低比特，减少要读的数据量。QuaRot 的做法是：

  • KV 缓存用非对称量化，每 128 个数一组（正好是 LLaMA-2 的头维度，所以就是“每个 token 的每个头一组”），裁剪比例 0.95；query 保持 FP16。
  • 注意力内核基于 FlashInfer 改写（附录 A.10 分成三个例程）：Init 在 prefill 时用整段的 key/value 初始化量化缓存，而 prefill 本身的注意力直接用 FlashAttention 在未量化的 key/value 上计算；Append 在每步解码时先量化新 token 的 key/value 并追加进缓存；Decode 用当前 query 读取 INT4 缓存，分段读进来、现场反量化成 FP16、再做点积，并像 FlashAttention 一样用在线 softmax 累积结果。

4.10 走一遍：解码时一个 token 穿过 QuaRot 的一层

把上面所有步骤串起来，看一个新 token 在 decode 时经过一层要做哪些事（据论文 §4 与官方代码整理）：

  1. 残差流里的隐藏状态已经是旋转后的 \(xQ\)（FP16）。RMSNorm 在 FP32 下只做“除以长度”。
  2. 量化成 INT4（逐 token），送进三个 INT4 矩阵乘 \(Q^\top\mathrm{diag}(\alpha)W_{q/k/v}\)，结果反量化回 FP16。value 因为 \(W_v\) 里乘过逐头 Hadamard，出来就是旋转过的。
  3. query、key 加 RoPE，然后各做一次在线逐头 Hadamard（长度 128）。
  4. 新 token 的 key、value 被非对称量化成 INT4，追加进 KV 缓存（Append）。
  5. Decode 内核用 FP16 的 query 读取 INT4 缓存，分段反量化、计算注意力。
  6. 注意力输出做一次在线跨头 Hadamard，再量化成 INT4，乘 \(HW_oQ\)，反量化，加回残差流。
  7. 前馈块：RMSNorm → 量化 → 两个 INT4 矩阵乘 \(Q^\top\mathrm{diag}(\alpha)W_{\text{gate/up}}\) → 反量化 → SiLU 与逐元素相乘（FP16）。
  8. 对 11008 维的中间激活做一次在线 Hadamard，量化，乘 \(HW_{\text{down}}Q\)，反量化，加回残差流。

数一下：每层 4 次激活量化（加上 KV 缓存的量化）、7 个 INT4 矩阵乘、4 处在线 Hadamard。与原模型相比，多出来的只有这些量化/反量化和 Hadamard，它们都是读写一遍数据的轻量操作；而原来最重的 7 个矩阵乘全部换成了 INT4。

读的时候容易误解的地方：KV 缓存是 4 bit 的，但注意力本身的计算（\(QK^\top\)、softmax、乘 \(V\)）仍是 FP16。4 bit KV 缓存省的是显存和读数据的带宽，不是算力；所以它只有在“读缓存”成为瓶颈时才会变快（第 5 节会看到批很小时它反而更慢）。另外，词嵌入和输出头（lm_head）在官方代码里没有量化。

5 实验：精度掉了多少，速度快了多少，各在什么条件下

这一节要回答的问题：权重、激活、KV 缓存全部 4 bit 之后，模型的困惑度和零样本准确率掉了多少？和 SmoothQuant、OmniQuant、QUIK、Atom 比怎么样？速度和显存的收益在什么 GPU、什么批大小、什么序列长度下测得？各个设计（GPTQ、分组、Hadamard 而非任意旋转、裁剪比例）分别贡献多少？最后，这些数字能说明多少问题？

5.1 实验是怎么设计的

  • 实现：在 Hugging Face Transformers + PyTorch 上实现。根据官方仓库的说明，精度实验用 fake_quant 目录下的脚本完成，也就是在 PyTorch 里“量化后立刻反量化”来模拟 4 bit 的数值误差；速度实验则用另外写的真实 INT4 内核（CUTLASS 做 4 bit 矩阵乘，FlashInfer 改写的内核做 KV 缓存量化）。
  • 量化设置：激活逐 token 对称量化，裁剪比例 0.9；KV 缓存非对称、每组 128、裁剪比例 0.95；权重逐通道对称，用 RTN 或 GPTQ，裁剪比例线性搜索。GPTQ 的校准集是 WikiText-2 训练集里 128 条长 2048 的序列。
  • 模型与任务：LLaMA-2 7B / 13B / 70B；语言建模看 WikiText-2 困惑度（序列长度 2048）；零样本看 PIQA、WinoGrande、HellaSwag、LAMBADA（OpenAI 版）、ARC-Easy、ARC-Challenge 六项，用 LM Evaluation Harness 默认参数。附录另有 LLaMA-3 8B / 70B 和 Phi-3-mini。
  • 硬件：作者说他们面向消费级 GPU，所以所有性能实验都在 NVIDIA RTX 3090 上完成（CUDA 12.1）。量化流程本身（旋转 + GPTQ）在 A100 上跑。

先补一点背景：从耗时反推“跑到了峰值的几成”。

一个 \(m\times k\) 乘 \(k\times n\) 的矩阵乘要做 \(2mkn\) 次运算。70B 的 down-projection、2048 个 token：\(2\times2048\times28672\times8192\approx9.6\times10^{11}\)。FP16 用了 12.45 ms，相当于约 77 TFLOPS；INT4 用了 2.881 ms（不含 Hadamard），相当于约 334 TOPS（均为推算）。对照 RTX 3090 的白皮书峰值：FP16（FP32 累加）71 TFLOPS，INT4 568 TOPS。FP16 基线已经跑满了这一档峰值（实际频率高于标称加速频率，所以略超），而 INT4 只用到峰值的六成左右。这说明两件事：一是在这张卡上 INT4 的理论上限是 8 倍，实测 4.3 倍还有空间；二是 8 倍这个上限来自 GeForce 卡“FP16 配 FP32 累加只有半速”的规格，换一张卡，比例就不同了。

5.4 消融：每个设计各贡献多少

RTN 代替 GPTQ。权重不用 GPTQ、直接四舍五入（表 3，附录表 9 有完整的 4/6/8 bit 结果），校准数据和超参数都不需要了。8 bit 时完全无损：7B 困惑度 5.50（FP16 5.47），70B 3.33（FP16 3.32）；6 bit 也几乎无损（7B 5.56、13B 4.95、70B 3.36）。这就是摘要里“6 bit 和 8 bit 用 RTN 就无损”的依据。4 bit 时 RTN 明显变差：7B 困惑度 8.37、平均准确率 58.26（比 FP16 低 11.56 点），70B 困惑度 4.14、平均准确率 73.63（低 3.44 点）。RTN 和 GPTQ 的困惑度差距随模型变大而缩小：7B 差 2.27，70B 差约 0.35（论文正文写 0.34）。结论是小模型更需要 GPTQ。

分组量化（表 4，GPTQ，KV 缓存组大小固定 128）。权重和激活每 256 / 128 / 64 个数一组时，7B 困惑度从 6.10 依次降到 5.98、5.93、5.88；70B 从 3.79 降到 3.63、3.61、3.58。组越小越准，但要多存刻度，矩阵乘内核也更复杂（刻度不再沿求和维保持不变，见第 2 节）。论文的速度内核只实现了不分组的版本。

KV 缓存的位宽（附录表 6，其余部分保持高精度、只量化 KV）。K、V 都是 4 bit 时，7B 困惑度 5.51（只高 0.04），70B 3.33；降到 3 bit，最多也只高 0.21（7B 5.68），70B 只高 0.07。key 比 value 更敏感：7B 上“K 4 bit、V 3 bit”是 5.54，“K 3 bit、V 4 bit”是 5.65；“K、V 都 3 bit”（5.68）比“K 4 bit、V 2 bit”（5.75）还好。到 2 bit 就明显崩了（K2V2：7B 9.23）。

只量化权重时旋转有没有用（附录表 7，非对称逐通道，激活和 KV 保持 FP16）。旋转对 GPTQ 帮助很大：7B 的 W4 从 8.25 降到 5.60（论文说的“最多改善 2.65”）；位数越低帮助越大，2 bit 的 70B 从 25.30 降到 5.60，让 GPTQ 在 2 bit 下第一次有了“能用”的结果。对 RTN 也有帮助：W4 时 7B 从 6.99 降到 6.76，13B 从 6.32 降到 5.48，70B 从 4.45 降到 3.66。

Hadamard 还是任意随机正交矩阵（附录表 8）。由于计算不变性，残差流上的 \(Q\) 其实可以是任何正交矩阵（在线的那几处仍然用快速 Hadamard）。作者试了“随机矩阵做 QR 分解得到的正交矩阵”：7B 困惑度 7.45，比随机 Hadamard 的 6.10 差 1.35；13B 差 0.44；70B 差 0.28。随机 Hadamard 明显更好，模型越大差距越小。

在线 Hadamard 用 FP16 还是 FP32（附录表 10）。正文实验都用 FP32；换成 FP16 后，7B 困惑度 6.08（FP32 是 6.10），平均准确率 66.21（FP32 是 65.64）；13B 困惑度都是 5.40，平均准确率差 0.07。作者认为差别在噪声范围内，精度不受影响。

裁剪比例（附录表 5，LLaMA-2-7B，只量化一种东西、其余保持全精度）。只量化输入激活时，裁剪比例 1.0 / 0.95 / 0.9 / 0.85 对应困惑度 5.938 / 5.910 / 5.828 / 5.850，0.9 最好；只量化 KV 缓存时对应 5.513 / 5.510 / 5.517 / 5.532，0.95 最好。这和 Atom 论文的结论一致。

别的模型（附录表 11–13）。LLaMA-3 更难量化：8B 困惑度从 6.14 升到 8.16（分组 128 时 7.36），平均准确率从 73.22 降到 65.18；70B 困惑度从 2.86 升到 6.66（分组时 5.51），平均准确率从 79.94 降到 69.21，掉了 10.7 个点。Phi-3-mini 用 GPTQ 4 bit 时困惑度从 6.35 升到 7.85，平均准确率从 73.11 降到 66.34；8 bit 仍然无损。

5.5 结果的份量

把上面的数字放在一起看，下面几点决定了它们能说明多少问题。

精度和速度不是在同一个产物上测的。精度来自 PyTorch 里的模拟量化，速度来自另写的 INT4 内核，只测一层、而且不加载真实权重。两套实现在量化规则上一致（逐 token 对称激活、逐通道权重、每组 128 的非对称 KV），所以模拟精度大体可信；但论文没有给出“用真实 INT4 内核跑完整模型、同时测精度和速度”的结果，分组量化（QuaRot-128G）的精度也没有对应的内核。

“几乎无损”只对大模型成立。同样是 W4A4KV4，70B 平均准确率掉 1.09 点，13B 掉 2.80 点，7B 掉 4.18 点；LLaMA-3-70B 掉 10.7 点。“保留 99%”说的是 LLaMA-2-70B 这一个点。评测本身也偏轻：困惑度是在 WikiText-2 测试集上测的，而 GPTQ 的校准数据正好来自 WikiText-2 训练集，同分布，对困惑度有利；零样本是六道常识选择题，没有 MMLU、代码、数学、生成质量或长上下文检索；KV 缓存量化只在 2048 长度下验证过。

对手的条件并不统一。SmoothQuant 和 OmniQuant 的数字是从 OmniQuant 论文里抄来的，没有 70B；QUIK 保留 256 个 FP16 通道，但不量化 KV 缓存；Atom 只在分组设定下比较，QuaRot 也换成了分组设定才和它打平。所有对手里，只有 QuaRot 和 Atom 同时把 KV 缓存量化到 4 bit。速度方面，论文只和 FP16 比，没有和 QUIK、Atom 的 INT4 内核比，也没有和 W8A8（SmoothQuant）或 W4A16 的权重量化内核比；而在小批量的 decode 场景，W4A16 才是最直接的对手。

速度数字的条件很窄。只有一张 RTX 3090，只测单个 Transformer 块，FP16 基线是作者自己的 Hugging Face 层 + FlashAttention-2，而不是 vLLM、TensorRT-LLM 这类生产推理引擎。prefill 只测了序列长度 2048。decode 只报告了峰值显存和注意力内核延迟，没有报告每秒生成多少 token；而注意力内核在批大小 8 以下反而变慢。前面推算过，RTX 3090 的 INT4 与 FP16（FP32 累加）峰值相差 8 倍，这个比例是 GeForce 卡特有的；数据中心卡的比例不同，而 H100 的官方规格表里根本没有列出 INT4 Tensor Core 的算力。换句话说，这些加速数字在 Ampere/Ada 一代的消费级卡上成立，不能直接搬到 H100 上。

显存节省主要来自权重。3.63–3.89 倍是单层的峰值显存，70B 几乎全是权重；整个模型时，没有量化的词嵌入和输出头会把比例往下拉，层数多又会把比例往上拉（论文认为整体会更高）。arXiv v1 测过整个 LLaMA-2-7B：批 16、长度 4096 时从 45.20 GB 降到 12.19 GB，约 3.71 倍。

6 结论：作者自己说还差什么

这一节要回答的问题：作者怎么总结这项工作？他们认为下一步该做什么？他们对硬件有什么判断？

作者的总结是：QuaRot 用 Hadamard 矩阵消除了预训练 LLM 激活和 KV 缓存里的离群值，据他们所知第一次实现了端到端的 4 bit 量化；LLaMA-2-70B 量化到 4 bit 后保留了 FP16 基线 99% 的下游任务性能；所有 LLaMA-2 模型量化到 6 bit 和 8 bit 都无损。（结论里的加速和显存数字是 v1 的旧值，见 5.4 节末的提醒。）

作者列出的后续方向有两个：一是量化残差流，目前残差相加仍是 FP16；二是推广到混合专家（MoE）架构。在硬件方面，他们指出，用 QuaRot 做端到端 INT4 推理，可以获得和当时刚发布的 NVIDIA B200 的 FP4 格式相近的加速，而整数单元比浮点 FP4 单元便宜得多。这个判断后来只对了一半：旋转的思路确实被广泛采用，但硬件走向了 FP4 而不是 INT4（见下一节）。

后来怎么样了

QuaRot 之后，“先旋转、再量化”几乎成了低比特推理的标准前处理，而且很快从 INT4 推理扩散到 FP8 注意力、FP4 推理和 FP4 训练。后续工作大致沿三个方向走：把旋转学出来，把旋转换成更一般的变换，以及把 Hadamard 变换搬进底层内核和新的数据格式。

SpinQuant：随机旋转有好有坏，不如学一个

Meta 的 SpinQuant（Liu 等，2024-05，ICLR 2025）先做了一个 QuaRot 没做的实验：对 LLaMA-2-7B 的 W4A4 量化，换 100 个不同的随机旋转，零样本平均准确率最好和最差的相差 13 个点；即使只在随机 Hadamard 矩阵之间换，差距也有 6 个点。这说明 QuaRot 的结果有相当一部分取决于“抽到了哪个随机矩阵”。于是 SpinQuant 把旋转当成参数来学：残差流上的旋转 \(R_1\)（对应 QuaRot 的 \(Q\)）和每层注意力里 value/输出投影之间的逐头旋转 \(R_2\)，在正交矩阵构成的流形（Stiefel 流形）上用 Cayley 参数化的梯度下降优化，目标是让“激活被量化后的网络”的最终损失最小；只用 800 条 WikiText-2 样本迭代 100 步，7B 大约 25 分钟。学完以后照样乘进权重，再做 GPTQ。需要量化 KV 缓存或 4 bit 激活时，再加上和 QuaRot 一样的在线 Hadamard（\(R_3\) 用于 Q/K，\(R_4\) 用于 down-projection）。

它报告的结果是：W4A4KV4 下 LLaMA-2-7B 与全精度的零样本差距缩小到 2.9 个点（QuaRot 是 4.18 个点，但两篇论文的任务集合不同，不能直接相减）。在它自己复现的 LLaMA-3-70B 上，QuaRot + GPTQ 的 W4A4KV4 困惑度是 20.2，而 SpinQuant 是 5.5（全精度 2.8）。值得注意的是，QuaRot 自己的附录给出的 LLaMA-3-70B 结果是 6.66，两边的复现相差悬殊，这本身就说明 LLaMA-3-70B 的 W4A4 量化很脆弱，对随机矩阵和实现细节都敏感。

DuQuant 与 FlatQuant：不局限于“同一个旋转”

DuQuant（Lin 等，2024-06，NeurIPS 2024 Oral）把离群值分成两种：一种是在所有 token 上都偏大的“普通离群值”，一种是只出现在极少数 token、数值特别巨大的“超大离群值”。它认为以往的方法主要对付前者，对后者效果不好，于是利用离群值所在维度的先验，分块构造旋转矩阵，把离群值先摊到相邻通道；再用一种“之字形”置换把离群值均匀分配到各个块里，最后再旋转一次。

FlatQuant（Sun 等，2024-10，ICML 2025）则观察到：经过逐通道缩放或 Hadamard 变换之后，权重和激活的分布仍然可能又陡又散。它为每个线性层学一个可逆的仿射变换（不必是正交矩阵），用两个小矩阵的 Kronecker 积来表示，让在线计算足够便宜，并把所有操作融合进一个内核。它特别指出，QuaRot 和 SpinQuant 因为要把旋转融进 RMSNorm 两侧，所有层被残差连接绑在同一个变换上（第 3.4 节的那个约束），而 FlatQuant 保留 LayerNorm、每层各用各的变换。它报告 LLaMA-3-70B 的 W4A4 准确率下降不到 1%，比 SpinQuant 高 7.5%，相对 FP16 prefill 最高快 2.3 倍、decode 快 1.7 倍。这些速度同样是在 RTX 3090 上测的，INT4 矩阵乘用的也是 QuaRot 那一套 CUTLASS 内核，KV 缓存量化也沿用 FlashInfer。

FlashAttention-3：FP8 注意力里的“非相干处理”

FlashAttention-3（Shah 等，2024-07，见本站 FlashAttention-3 精读）在 H100 上用 FP8 做注意力时，为了降低量化误差用了两招：分块量化，以及非相干处理——在量化成 FP8 之前，把 Q 和 K 都乘上同一个“随机 ±1 对角矩阵 × Hadamard 矩阵”。因为 \((QM)(KM)^\top=QK^\top\)，注意力结果不变，离群值却被摊平了；这一步还可以和 RoPE 融合在一起，几乎不花额外时间。这和 QuaRot 第 1d 步对 query/key 做的事在数学上是同一件事；FlashAttention-3 在这里引用的是 QuIP 和 QuIP#。它用“每个元素有 0.1% 的概率加上一个标准差为 10 的噪声”来模拟离群值，测得 FP8 注意力的均方根误差从逐张量量化基线的 2.4e-2 降到 9.1e-3（约 2.6 倍）；去掉非相干处理、只保留分块量化时误差回到 2.4e-2，说明在这个测试里起作用的主要是旋转。

FP4 时代：硬件没有走向 INT4，但旋转留了下来

QuaRot 的速度依赖 Ampere/Ada 一代 GPU 的 INT4 Tensor Core（代码里 CUTLASS 的目标架构是 Sm80）。下一代数据中心卡 H100 的官方规格表只列 FP8 和 INT8 等格式，没有 INT4；再下一代的 Blackwell 加入的是 FP4（NVFP4、MXFP4 这类带细粒度缩放的 4 bit 浮点格式，见旧版 FP8 格式拆解）。QuaRot 结论里“用整数做出接近 FP4 的效果”的设想没有成为主流，但“乘一个 Hadamard 矩阵来压离群值”被原样带进了 FP4：

  • NVFP4 预训练（NVIDIA，2025-09；见旧版 FP4 训练拆解）在 12B 模型、10T token 的 FP4 训练里，对权重梯度（Wgrad）矩阵乘的两个输入做 16×16 的随机 Hadamard 变换：两个输入乘上同一个正交变换，点积里自然抵消。他们发现 16 阶比 4 阶收敛更好、与 128 阶差不多；全程共用一个随机符号向量；在较小规模的实验里，前向和激活梯度的矩阵乘上没有观察到收益，所以只用在 Wgrad 上。这篇报告把 QuaRot、FlashAttention-3、HALO、QuIP# 等列为随机 Hadamard 变换的出处。
  • MR-GPTQ（Egiazarian 等，2025-09，QuaRot 的 Ashkboos、Hoefler、Alistarh 也是作者）系统研究了 MXFP4 和 NVFP4 的训练后量化，发现 NVFP4 每 16 个数一组的小分组会让传统的离群值抑制手段失效，而 MXFP4 的“2 的幂刻度”误差又很大；它改用分块 Hadamard 变换配合针对格式改造的 GPTQ，报告在 B200 上单层最高 3.6 倍、端到端 2.2 倍的加速（相对 FP16），并得出“FP4 不是 INT4 的自动升级”的结论。
  • 同一团队的 HALO（Ashkboos 等，2025-01）把 Hadamard 旋转放进前向和反向传播，用于 8 bit 的低精度微调。

进入工具链

vLLM 项目的模型压缩工具 llm-compressor 提供了两种变换：“SpinQuant/QuaRot 风格”的 SpinQuantModifier 和 “QuIP 风格”的 QuIPModifier；文档说用 Hadamard 变换处理过的模型可以在 vLLM 里调用 hadacore 内核加速。HadaCore 是 IBM 与 Meta 在 PyTorch 博客上发布的 Hadamard 变换内核，它把快速 Walsh–Hadamard 变换拆成 16×16 的小块交给 FP16 Tensor Core 去算，报告在 A100 上比 QuaRot 所用的 Dao AI Lab 内核快 1.1–1.4 倍、H100 上快 1.0–1.3 倍；博客开头就把 QuaRot、SpinQuant 和 FlashAttention-3 列为动机。

回头看这篇论文：QuaRot 真正留下来的是两个想法，而不是 INT4 内核本身：一是“利用计算不变性把旋转写进权重，只在少数位置在线做 Hadamard”这套布置方案（SpinQuant 的 \(R_1\)–\(R_4\) 和它一一对应）；二是“随机 Hadamard 是又快又好的去离群值工具”这个经验，它后来被用到了 FP8 注意力、FP4 推理和 FP4 训练里。至于“哪个旋转最好”“要不要每层不同”“正交是否必要”，后续工作给出了不同的答案。
