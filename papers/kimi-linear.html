0 导读：这篇报告解决什么问题

大模型正在从“回答一个问题”变成“完成一件任务”：读一个代码仓库、连续调用几百次工具、在强化学习里生成几万 token 的推理过程。这类工作的共同点是上下文很长，而且输出也很长。标准的 softmax 注意力在这里要付两笔账。第一笔是计算：处理一段长度为 \(T\) 的输入，注意力要让每个 token 和它前面的所有 token 两两打分，计算量随 \(T^2\) 增长。第二笔是内存：生成阶段每个请求都要保存所有历史 token 的 key 和 value（KV 缓存），它随 \(T\) 线性增长，而且每生成一个 token 都要把它从显存里完整读一遍。上下文到了百万 token，这两笔账都会压垮推理服务。

线性注意力是另一条路：它把全部历史压缩进一个大小固定的矩阵“状态”，每生成一个 token 只更新、读取这个状态，成本与上下文长度无关。代价是固定大小的状态装不下所有细节，所以纯线性注意力模型在“从长文里精确找回某句话”这类任务上一直不如 softmax 注意力。业界的折中办法是混合：大部分层用线性注意力，少数层保留全注意力。这篇报告在这条路上做了两件事。第一，提出 KDA（Kimi Delta Attention）：在 Gated DeltaNet 的基础上，把“整个状态一起遗忘”的标量门改成“每个通道各自遗忘”的逐通道门，并为它设计了一套专门的分块并行算法，内核速度约为通用 DPLR 写法的 2 倍。第二，用 KDA 搭出 Kimi Linear：每 3 层 KDA 配 1 层 MLA 全注意力，MLA 层干脆不加位置编码，模型总参数 48B、每个 token 激活 3B。

报告最有分量的结果是一组“同配方”对照：Kimi Linear、全 MLA 模型和用 Gated DeltaNet 混合的模型（GDN-H）用同样的结构规模、同样的 1.4T token、同样的训练流程训练，Kimi Linear 在大多数短文本、长文本基准上都最好（例如 MMLU-Pro 51.0 对 MLA 的 47.2，128K 长度的 RULER 84.3 对 81.3），在数学强化学习中也涨得更快。效率方面，KV 缓存最多少 75%；1M 上下文时，批大小为 1 的单 token 解码时间是 MLA 的约 1/2.2，允许更大批量时折算到每个 token 的时间是 MLA 的 1/6.3。后面会看到，这几个速度数字的测量条件各不相同，报告也没有写明硬件。团队开源了 KDA 内核、vLLM 实现，以及训练了 5.7T token、支持 1M 上下文的 48B-A3B 模型。

1 引言：为什么又回到线性注意力

这一节要回答的问题：智能体和强化学习让推理时的上下文和输出都变得很长，softmax 注意力的计算和 KV 缓存成了瓶颈。线性注意力能省掉这两笔开销，却长期在质量上落后。近几年哪些改进缩小了差距？为什么最后还是要和全注意力混合？这篇报告声称自己和以前的混合模型有什么不同？
先补一点背景：softmax 注意力在长上下文里的两笔开销。

注意力让第 \(t\) 个 token 用自己的 query \(q_t\) 去和前面每个 token 的 key \(k_i\) 比相似度，经过 softmax 变成权重，再把对应的 value \(v_i\) 加权求和。这件事在推理的两个阶段代价不同。

  • 预填充（prefill）：一次性处理用户给的整段输入。长度为 \(T\) 时，每个 token 都要和它之前的所有 token 打分，总共约 \(T^2/2\) 对，所以计算量随 \(T^2\) 增长。输入从 128K 变成 1M（约 8 倍），这部分计算变成约 64 倍。
  • 解码（decode）：之后每一步只生成一个 token。为了不重复计算，系统把所有历史 token 的 key、value 存下来，这就是 KV 缓存（详见 vLLM 精读 §2）。每生成一个 token，都要把整份 KV 缓存从显存读一遍。KV 缓存的大小随上下文长度线性增长，所以上下文越长，每一步读得越多、越慢；同时一张卡上能同时放下的请求也越少。

线性注意力的做法是去掉 softmax，把“和历史逐个比较”改成“查一张固定大小的表”。这张表就是一个 \(d_k\times d_v\) 的矩阵状态，下一节会详细推导。它的好处是：预填充的计算量随 \(T\) 线性增长，解码每一步的读取量是常数，内存也是常数。

线性注意力早在 2020 年就被提出，但很长一段时间里，即使在短文本上，它的语言建模质量也明显不如 softmax 注意力。报告认为差距是被两类改进缩小的：一类是门控（或衰减），让状态能主动忘掉旧信息，代表作有 RetNet、Mamba2、GLA；另一类是 delta 规则，让状态在写入新信息前先擦掉同一位置的旧信息，代表作有 DeltaNet、Gated DeltaNet、RWKV-7。两者结合后，线性注意力在中等长度上已经接近 softmax 的水平。

但有一个根本限制改不掉：状态大小固定，能记住的东西就有上限。需要在很长的上下文里精确找回某个细节时（比如在 100 万 token 的仓库里找某个函数的定义），纯线性模型在理论上就处于劣势。所以近两年的大模型多采用混合架构：大部分层用线性注意力，隔几层放一层全注意力，让全注意力负责精确检索。报告批评以往的混合模型要么规模有限，要么评测不够全面，于是给自己定了一个目标：在相同训练条件下，质量追平甚至超过全注意力，同时在速度和内存上都有实质收益。

报告列出三项贡献：（1）KDA，一种改进了记忆管理和硬件效率的门控 delta 规则；（2）Kimi Linear 架构，KDA 与全注意力按 3:1 交替；（3）在 1.4T token 规模上做公平对照，覆盖短文本、长文本和强化学习三种场景，并开源内核、vLLM 集成和模型权重。报告还强调，这些组件可以直接替换现有的全注意力流水线，不需要改动缓存和调度接口。

读的时候容易误解的地方：“for the first time outperforms full attention under fair comparisons”是报告自己的说法。“公平对照”在这里有具体含义：同样的模型规模、同样的数据和 token 数、同样的训练流程，基线也由同一团队训练。它并不意味着在所有基准上都领先（第 5 节会看到 MLA 在 LongBench v2、Frames 等几项上更好），也不意味着在其他规模、其他数据配方下结论一定成立。

2 预备知识：线性注意力、delta 规则与 Gated DeltaNet

这一节要回答的问题：KDA 是在一串前人工作上做的一处修改，不先把这串工作理清，后面的公式就看不懂。线性注意力的“矩阵状态”是怎么从普通注意力里推出来的？为什么可以把它看成一个“边读边学”的存储器？delta 规则相当于在优化什么，它比原始线性注意力好在哪？Gated DeltaNet 又加了什么？报告还在这一节交代了后面分块算法要用的记号。

2.1 记号：一个头的状态、分块和累积衰减

报告里所有公式都针对一个注意力头。第 \(t\) 个 token 的 query、key 是 \(d_k\) 维列向量 \(q_t,k_t\)，value 和输出是 \(d_v\) 维的 \(v_t,o_t\)。状态 \(\mathbf{S}_t\) 是一个 \(d_k\times d_v\) 的矩阵：行对应 key 的维度，列对应 value 的维度。读出用 \(o_t=\mathbf{S}_t^{\top}q_t\)。Kimi Linear 里 \(d_k=d_v=128\)，所以每个头的状态是 \(128\times128\) 个数。

为了在 GPU 上并行，长度为 \(L\) 的序列会被切成 \(L/C\) 个块（chunk），每块 \(C\) 个 token（实现里 \(C=64\)）。报告用下标 \([t]\) 表示第 \(t\) 块：\(\mathbf{Q}_{[t]}\in\mathbb{R}^{C\times d}\) 是把块内 \(C\) 个 query 按行叠起来的矩阵，\(\square_{[t]}^{r}\) 是块内第 \(r\) 个元素，\(\mathbf{S}_{[t]}\) 是进入第 \(t\) 块时的状态（也就是上一块结束时的状态）。

衰减相关的记号有三个。\(\alpha_t\) 是第 \(t\) 步的遗忘系数（KDA 里它是一个 \(d_k\) 维向量）。块内从第 \(i\) 步到第 \(j\) 步的累积衰减是逐步相乘：\(\gamma_{[t]}^{i\to j}=\prod_{k=i}^{j}\alpha_{[t]}^{k}\)，简写 \(\gamma_{[t]}^{r}=\gamma_{[t]}^{1\to r}\)。把块内每一步的 \(\gamma^{r}\) 按行叠起来，得到 \(C\times d_k\) 的矩阵 \(\boldsymbol{\Gamma}_{[t]}^{1\to C}\)。另外 \(\mathbf{M}\)（也写作 Tril）表示含对角线的下三角掩码，\(\mathbf{M}^{-}\)（StrictTril）表示不含对角线的下三角掩码，用来保证块内只看前面的 token。

2.2 线性注意力：一张边读边写的“联想记忆表”

先补一点背景：去掉 softmax 之后发生了什么。

普通注意力的输出是 \(o_t=\sum_{i\le t}\mathrm{softmax}_i(q_t^{\top}k_i)\,v_i\)。softmax 要先看到所有分数才能归一化，所以必须把每个 \(k_i\)、\(v_i\) 都留着。线性注意力把 softmax 去掉（或者换成一个特征映射），只保留打分 \(q_t^{\top}k_i\)：

$$o_t=\sum_{i\le t}(q_t^{\top}k_i)\,v_i=\Big(\sum_{i\le t}k_i v_i^{\top}\Big)^{\!\top} q_t=\mathbf{S}_t^{\top}q_t,\qquad \mathbf{S}_t=\mathbf{S}_{t-1}+k_t v_t^{\top}$$

关键在中间那一步：标量 \(q_t^{\top}k_i\) 可以挪到括号外面，矩阵乘法满足结合律，于是“先和每个历史 token 打分再加权”变成了“先把历史累加成一个矩阵，再用 query 读一次”。这个矩阵 \(\mathbf{S}_t\) 就是状态。它的大小只取决于 \(d_k\) 和 \(d_v\)，与已经读过多少 token 无关。每来一个新 token，只需加上一个外积 \(k_tv_t^{\top}\)。这就是“线性注意力是 RNN”的含义。

为什么说状态是一张“联想记忆表”？看一个最小的例子。设 \(d_k=d_v=2\)。第 1 个 token 的 \(k_1=(1,0)\)、\(v_1=(3,5)\)，第 2 个 token 的 \(k_2=(0,1)\)、\(v_2=(-1,2)\)。累加后

$$\mathbf{S}_2=k_1v_1^{\top}+k_2v_2^{\top}=\begin{pmatrix}3&5\\-1&2\end{pmatrix}$$

状态的第 1 行存的是 \(v_1\)，第 2 行存的是 \(v_2\)。用 \(q=(1,0)\) 去读，得到 \(\mathbf{S}_2^{\top}q=(3,5)=v_1\)：key 像地址，value 像内容，query 像“按地址取数”。这个比喻在快速权重（fast weight）文献里很常见：状态是每读一个 token 就改一次的“快权重”，而生成 \(q,k,v\) 的投影矩阵是训练时才更新的“慢权重”。

问题出在写入上。假设第 3 个 token 又用地址 \(k_3=(1,0)\) 写入新内容 \(v_3=(7,0)\)。线性注意力只会累加，第 1 行变成 \((3,5)+(7,0)=(10,5)\)，再用 \((1,0)\) 去读，得到的是新旧内容的混合，既不是 3、5 也不是 7、0。地址总共只有 \(d_k=128\) 个相互正交的方向，序列一长，不同 token 的 key 必然重叠，写进去的东西互相干扰，而且越积越多。报告用优化的语言描述这个毛病：线性注意力的更新等价于对目标 \(\mathcal{L}_t(\mathbf{S})=-\langle \mathbf{S}^{\top}k_t,v_t\rangle\) 做一步梯度下降。这个目标只奖励“让读出值和 \(v_t\) 方向一致”，没有任何一项告诉状态应该擦掉什么，于是状态只增不减。

2.3 DeltaNet：写之前先擦掉旧值

DeltaNet 换了一个目标：希望用 \(k_t\) 读出来的值正好等于 \(v_t\)，也就是最小化重建误差 \(\mathcal{L}_t(\mathbf{S})=\tfrac12\|\mathbf{S}^{\top}k_t-v_t\|^2\)。对 \(\mathbf{S}\) 求梯度得 \(k_t(\mathbf{S}^{\top}k_t-v_t)^{\top}\)，以学习率 \(\beta_t\) 走一步：

$$\mathbf{S}_t=\mathbf{S}_{t-1}-\beta_t k_t\big(\mathbf{S}_{t-1}^{\top}k_t-v_t\big)^{\top}=\big(\mathbf{I}-\beta_t k_tk_t^{\top}\big)\mathbf{S}_{t-1}+\beta_t k_tv_t^{\top}$$

这就是经典的 delta 规则。它的含义可以分三步读：先用 \(k_t\) 读出当前存着的旧值 \(v^{\text{old}}=\mathbf{S}_{t-1}^{\top}k_t\)；算出旧值和新值的差 \(v^{\text{old}}-v_t\)；再沿着 \(k_t\) 这个地址把差值按比例 \(\beta_t\) 修正掉。当 \(\|k_t\|=1\) 时，修正后用 \(k_t\) 读出的值正好是 \((1-\beta_t)v^{\text{old}}+\beta_t v_t\)。\(\beta_t\in[0,1]\) 因此叫“写入强度”：\(\beta_t=1\) 时彻底覆盖，\(\beta_t=0\) 时什么都不写。

示意图：delta 规则的一步更新 = 读出旧值、算差、沿同一地址改写
旧状态 \(\mathbf{S}_{t-1}\)→① 读出\(v^{\text{old}}=\mathbf{S}_{t-1}^{\top}k_t\)→② 算差\(v^{\text{old}}-v_t\)→③ 沿 \(k_t\) 改写\(\mathbf{S}\leftarrow\mathbf{S}-\beta_t k_t(v^{\text{old}}-v_t)^{\top}\)→新状态 \(\mathbf{S}_t\)
本站示意图。原始线性注意力只有第 ③ 步里的“加 \(k_tv_t^{\top}\)”，没有第 ① ② 步，所以它不会先擦掉同一地址上的旧内容。
接着上面的例子算一遍：\(\mathbf{S}_2\) 的第 1 行是 \((3,5)\)。第 3 个 token 用 \(k_3=(1,0)\) 写入 \(v_3=(7,0)\)。取 \(\beta=1\)：读出 \(v^{\text{old}}=(3,5)\)，差值 \((-4,5)\)，改写后第 1 行变成 \((3,5)-(-4,5)=(7,0)\)，第 2 行不动。再用 \((1,0)\) 读，得到的正是 \(v_3\)。取 \(\beta=0.5\)：第 1 行变成 \((5,2.5)\)，新旧各占一半。对照线性注意力的 \((10,5)\)，delta 规则做的是“覆盖”而不是“叠加”。

矩阵 \(\mathbf{I}-\beta_tk_tk_t^{\top}\) 是一个秩 1 修正的单位阵，数值线性代数里叫广义 Householder 变换（\(\beta=2\) 且 \(\|k\|=1\) 时就是镜面反射）。很多个这种矩阵连乘起来，可以写成“单位阵减一个低秩矩阵”的紧凑形式（WY 表示），这是 DeltaNet 能在 GPU 上按块并行训练的数学基础，第 3 节会用到。

2.4 Gated DeltaNet：再加一个整体遗忘的门

delta 规则只会改写“当前地址”上的内容，没有被新 key 碰到的旧联想会一直留在状态里，哪怕它早就过时了。Gated DeltaNet（GDN）在更新前给整个状态乘一个遗忘系数 \(\alpha_t\in[0,1]\)：

$$\mathbf{S}_t=\alpha_t\big(\mathbf{I}-\beta_tk_tk_t^{\top}\big)\mathbf{S}_{t-1}+\beta_tk_tv_t^{\top}$$

\(\alpha_t\) 由当前输入算出，每个头每个 token 一个标量。\(\alpha_t\) 接近 1 时状态几乎原样保留；接近 0 时整张表被清空，相当于“换话题了，前面的不要了”。报告把它解释为对快权重做权重衰减，效果类似一个随数据变化的 L2 正则：它给每条记忆规定了寿命，减少旧内容对新内容的干扰。GDN 的完整精读见 Gated DeltaNet 精读。

报告在这里还埋了一个伏笔：如果把注意力分数写成“query 乘一串矩阵再乘 key”的形式，GDN 里那串矩阵 \(\alpha_j(\mathbf{I}-\beta_jk_jk_j^{\top})\) 就扮演了位置编码的角色。RoPE 里这串矩阵是固定的旋转矩阵，GDN 里它由数据决定、可以学习，而且不要求是正交矩阵。这个观点决定了后面 MLA 层敢不加位置编码，第 6 节会展开。

容易混淆的两点：
  • 报告的状态是 \(d_k\times d_v\)、读出用 \(\mathbf{S}^{\top}q\)；有些文献（包括 GDN 原文的部分写法）把状态写成 \(d_v\times d_k\)、读出用 \(\mathbf{S}q\)。两者只差一个转置，比较公式时要先统一方向，否则会把“按 key 维衰减”看成“按 value 维衰减”。
  • \(\alpha_t\) 是“保留比例”，不是“遗忘比例”：\(\alpha_t=0.9\) 意味着保留 90%。代码里通常存的是它的对数 \(g_t=\log\alpha_t\le 0\)。

3 KDA：把“整张表一起忘”改成“每个通道各自忘”

这一节要回答的问题：KDA 相对 Gated DeltaNet 到底改了什么？改动只有一处，为什么值得单独提出一个新模块？这一处改动让 GPU 上的高效训练变难了，作者是怎么用分块算法、WY 表示和 UT 变换把它重新变成大块矩阵乘法的？和更一般的 DPLR 写法相比，KDA 的内核为什么能快一倍？这一节对应原文 §3、§3.1、§3.2，是整篇报告的技术核心。

3.0 一个公式的改动

KDA 的递推式是：

$$\mathbf{S}_t=\big(\mathbf{I}-\beta_tk_tk_t^{\top}\big)\operatorname{Diag}(\alpha_t)\,\mathbf{S}_{t-1}+\beta_tk_tv_t^{\top},\qquad o_t=\mathbf{S}_t^{\top}q_t$$

和 GDN 相比，唯一的区别是遗忘系数：GDN 的 \(\alpha_t\) 是一个标量，KDA 的 \(\alpha_t\) 是一个 \(d_k\) 维向量，放进对角矩阵 \(\operatorname{Diag}(\alpha_t)\)。对角矩阵左乘状态，相当于把状态的第 \(i\) 行乘以 \(\alpha_{t,i}\)。前面说过，状态的行对应 key 的维度，也就是“地址”的各个分量。所以 GDN 是“整张表按同一个比例褪色”，KDA 是“表的每一行按自己的比例褪色”。

示意图：标量门（GDN）与逐通道门（KDA）对状态矩阵的作用
本站示意图，颜色深浅表示衰减后这一行的记忆还剩多少，数值是举例。原文没有对应的图；递推式见 原文式 (1) ↗。

为什么要这么细？报告给了两层理由。第一层是记忆管理：一个头的 128 个 key 通道里，有的可能用来记“这段对话的主题”，需要几千个 token 都不忘；有的可能用来记“上一个括号有没有闭合”，几个 token 之后就该清掉。标量门只能在两者之间取一个折中，逐通道门可以各取所需。第二层是位置感知（第 6 节详述）：如果把衰减看成一种位置编码，RoPE 之所以好用，是因为它给每一对维度分配了不同的旋转频率，相当于同时提供从短到长各种尺度的“距离刻度”；GDN 的标量衰减只有一种刻度，KDA 的逐通道衰减则恢复了这种“每个维度一种尺度”的多样性。

KDA 并不是第一个用逐通道衰减的模型。GLA（门控线性注意力）早就用 \(\operatorname{Diag}(\alpha_t)\)，但它没有 delta 规则，写入只能叠加。所以可以把 KDA 理解为 GLA 的细粒度遗忘 + GDN 的 delta 改写。报告附录的表 7 还给了一个统一视角：GDN 和 KDA 都相当于“先衰减得到 \(\tilde{\mathbf{S}}_{t-1}\)，再在 \(\tilde{\mathbf{S}}_{t-1}\) 上对重建误差 \(\tfrac{\beta_t}{2}\|\tilde{\mathbf{S}}_{t-1}^{\top}k_t-v_t\|^2\) 做一步随机梯度下降”，两者只差衰减是标量还是逐通道。

注意公式里衰减和 delta 改写的顺序：KDA 是先衰减、再改写（\(\operatorname{Diag}(\alpha_t)\) 写在 \(\mathbf{I}-\beta_tk_tk_t^{\top}\) 的右边，先作用于 \(\mathbf{S}_{t-1}\)）。对 GDN 来说顺序无所谓，因为标量和任何矩阵都可交换；对 KDA 来说对角矩阵和 \(k_tk_t^{\top}\) 一般不可交换，顺序不同就是两个不同的模型。这个顺序也正是下面分块算法能简化的前提。

3.1 硬件友好的分块算法

先补一点背景：同一个递推，三种算法。

线性注意力类模型在数学上是 RNN，但在 GPU 上训练时有三种算法可选，它们算出的结果相同，代价不同：

  • 逐步递推：严格按 token 顺序，一步一步更新状态。每一步只有矩阵乘向量这样的小运算，而且后一步必须等前一步，序列有多长就要串行多少步。GPU 上负责矩阵乘法的 Tensor Core 吃不饱，训练很慢。但生成阶段本来就是一次一个 token，所以解码用的就是这种形式。
  • 完全并行：像普通注意力那样，一次算出 \(T\times T\) 的“谁影响谁”矩阵。全是大矩阵乘法，但计算量随 \(T^2\) 增长，失去了线性注意力的意义。
  • 分块（chunkwise）：把序列切成长度 \(C\) 的块。块内用完全并行的方式算（\(C\times C\) 的小矩阵，适合 Tensor Core）；块与块之间只传递一个状态矩阵，按块递推。串行步数从 \(T\) 降到 \(T/C\)，总计算量仍随 \(T\) 线性增长。现代线性注意力的训练和预填充几乎都用这种形式。

对原始线性注意力，分块很容易：块内的贡献就是一个带因果掩码的 \(\mathbf{Q}\mathbf{K}^{\top}\)。对 delta 规则，难点在于每一步的转移矩阵 \(\mathbf{I}-\beta k k^{\top}\) 都不同，块内要把 64 个这样的 \(d_k\times d_k\) 矩阵乘起来。直接乘既慢又占内存，需要一个数学技巧把它变成小矩阵运算。

示意图：分块计算的三步（以 256 个 token、块长 \(C=64\) 为例）
本站示意图。蓝色三角表示块内的 \(C\times C\) 下三角矩阵运算，可以在所有块上同时进行；橙色方框是在块与块之间传递的 \(d_k\times d_v\) 状态，必须按顺序算。对应 原文 §3.1 ↗ 的式 (2)–(9)。

第一步：把块内的递推展开。设进入某一块时的状态是 \(\mathbf{S}^0\)，块内第 \(r\) 步之后的状态可以写成两部分之和（原文式 2）：

$$\mathbf{S}^{r}=\underbrace{\prod_{i=1}^{r}\big(\mathbf{I}-\beta^{i}k^{i}k^{i\top}\big)\operatorname{Diag}(\alpha^{i})}_{\mathbf{P}^{r}:\ \text{旧状态经过 }r\text{ 次转移}}\ \mathbf{S}^{0}\;+\;\underbrace{\sum_{i=1}^{r}\Big(\prod_{j=i+1}^{r}\big(\mathbf{I}-\beta^{j}k^{j}k^{j\top}\big)\operatorname{Diag}(\alpha^{j})\Big)\beta^{i}k^{i}v^{i\top}}_{\mathbf{H}^{r}:\ \text{块内 }r\text{ 次写入各自再经过后续转移}}$$

（这里省略了块编号下标 \([t]\)。）\(\mathbf{P}^r\) 是 \(r\) 个 \(d_k\times d_k\) 矩阵的连乘，直接算代价很大。

第二步：WY 表示，把连乘压缩成“对角阵减若干个秩 1 项”。原文式 (3)–(5) 证明了（附录 B 用归纳法）：

$$\mathbf{P}^{r}=\operatorname{Diag}(\gamma^{r})-\sum_{i=1}^{r}\operatorname{Diag}(\gamma^{i\to r})\,k^{i}w^{i\top},\qquad \mathbf{H}^{r}=\sum_{i=1}^{r}\operatorname{Diag}(\gamma^{i\to r})\,k^{i}u^{i\top}$$

意思是：\(r\) 次“衰减 + 秩 1 擦除”连乘起来，等于“纯衰减”减去 \(r\) 个秩 1 修正项，每个修正项由一个 key \(k^i\) 和一个辅助向量 \(w^i\) 决定。于是不需要存 \(r\) 个大矩阵，只需要 \(r\) 个 \(d_k\) 维向量 \(w^i\) 和 \(r\) 个 \(d_v\) 维向量 \(u^i\)。它们满足一个递推：\(w^r\) 等于 \(\beta^r\) 乘以“衰减过的 \(k^r\) 减去前面各个 \(w^i\) 的加权和”，权重是 \(k^{i\top}\operatorname{Diag}(\gamma^{i\to r})k^{r}\)；\(u^r\) 的形式相同，只是把 \(k^r\) 换成 \(v^r\)。这里的权重都是标量，块内总共只有 \(C\times C\) 个。报告说这里沿用了 Comba 的写法，可以省掉后续一次额外的矩阵求逆。

第三步：UT 变换，把向量递推变成一次三角矩阵求逆。上面的递推仍然是一个一个算的。UT 变换把它整体写成矩阵形式（原文式 6–7）：

$$\mathbf{M}=\Big(\mathbf{I}+\operatorname{StrictTril}\big(\operatorname{Diag}(\beta)\,(\boldsymbol{\Gamma}\odot\mathbf{K})\,(\mathbf{K}/\boldsymbol{\Gamma})^{\top}\big)\Big)^{-1}\operatorname{Diag}(\beta),\qquad \mathbf{W}=\mathbf{M}(\boldsymbol{\Gamma}\odot\mathbf{K}),\quad \mathbf{U}=\mathbf{M}\mathbf{V}$$

括号里是一个 \(C\times C\) 的单位下三角矩阵，它的逆可以用高斯消元里的前代法逐行求出，代价是 \(C^2\) 量级的小运算；求出 \(\mathbf{M}\) 之后，\(\mathbf{W}\)、\(\mathbf{U}\) 都只是一次矩阵乘法。报告强调这一步的目的是减少“非矩阵乘法”的运算，因为 GPU 上非矩阵乘法的吞吐比 Tensor Core 低一个数量级以上。

第四步：块间更新状态，块内算输出。有了 \(\mathbf{W}\)、\(\mathbf{U}\)，状态按块递推（原文式 8），输出分两部分（原文式 9）：

$$\mathbf{S}_{[t+1]}=\operatorname{Diag}(\gamma^{C})\,\mathbf{S}_{[t]}+(\boldsymbol{\Gamma}^{i\to C}\odot\mathbf{K})^{\top}\big(\mathbf{U}-\mathbf{W}\mathbf{S}_{[t]}\big)$$
$$\mathbf{O}_{[t]}=\underbrace{(\boldsymbol{\Gamma}\odot\mathbf{Q})\,\mathbf{S}_{[t]}}_{\text{块间：读上一块留下的状态}}+\underbrace{\operatorname{Tril}\big((\boldsymbol{\Gamma}\odot\mathbf{Q})(\mathbf{K}/\boldsymbol{\Gamma})^{\top}\big)}_{\text{块内：带衰减的因果注意力矩阵}}\underbrace{\big(\mathbf{U}-\mathbf{W}\mathbf{S}_{[t]}\big)}_{\text{“伪 value”}}$$

最值得理解的是“伪 value” \(\mathbf{U}-\mathbf{W}\mathbf{S}_{[t]}\)。delta 规则写入的不是 \(v\) 本身，而是“\(v\) 减去这个地址上已经存着的东西”，而“已经存着的东西”取决于进入这一块时的状态 \(\mathbf{S}_{[t]}\)。\(\mathbf{U}-\mathbf{W}\mathbf{S}_{[t]}\) 恰好把每个 token 的 value 修正成了“考虑到旧状态之后真正要写进去的量”。一旦换成伪 value，块内的计算就和普通的门控线性注意力（GLA）完全一样：一个带衰减的下三角注意力矩阵乘以 value。这就是 delta 规则能分块并行的根本原因。

剩下的麻烦：除以累积衰减。式 (9) 里的 \(\mathbf{K}/\boldsymbol{\Gamma}\) 要除以从块首到当前位置的累积衰减。累积衰减是很多个小于 1 的数相乘，块内 64 步下来可能非常小：假如某个通道每步保留 0.5，64 步后是 \(0.5^{64}\approx5.4\times10^{-20}\)（推算），它的倒数约 \(1.8\times10^{19}\)，远超 FP16 的上限 65504，BF16 虽然表示范围够，但有效数字只有 8 位左右，乘回去时误差会被放大。标量衰减（GDN）可以把这个因子留在 \(C\times C\) 的分数矩阵里统一处理；逐通道衰减的因子挂在 \(d_k\) 个通道上，躲不开。GLA 的办法是在对数域里算相对衰减，并在块内再切一层小块（二级分块）、用全精度计算。Kimi K3 的报告补充说明了 Kimi Linear 的具体做法：每个 64 token 的块再分成 16 token 的小块，非对角的小块可以直接用 Tensor Core 做矩阵乘法，对角线上的小块则需要逐个位置对显式计算，这部分是块内的主要瓶颈（K3 对此的改进见文末）。

容易误解的地方：分块算法是精确的代数变形，不是近似，它和逐步递推算出的结果在数学上相同（只有浮点误差的区别）。所以“训练用分块、解码用逐步递推”不会造成训练与推理不一致。块长 \(C\) 是一个工程折中：块越长，块内矩阵越大、越适合 Tensor Core，但块内 \(C^2\) 的开销和累积衰减的数值范围也随之变大。

3.2 效率分析：KDA 是一种受约束的 DPLR

先补一点背景：DPLR 转移矩阵。

把各种线性注意力写成 \(\mathbf{S}_t=\mathbf{A}_t\mathbf{S}_{t-1}+(\text{写入项})\) 的形式，差别都在转移矩阵 \(\mathbf{A}_t\)。一类表达力很强、又还算好算的选择是“对角加低秩”（Diagonal-Plus-Low-Rank，DPLR）：\(\mathbf{A}_t=\mathbf{D}_t-a_tb_t^{\top}\)，即一个对角矩阵（逐通道衰减）减去一个秩 1 矩阵（某种擦除）。早期的状态空间模型 S4 用的是固定的 DPLR 矩阵，RWKV-7 用的是随输入变化的一般 DPLR，其中 \(a_t\)、\(b_t\) 是两个独立生成的向量。

把 KDA 的转移矩阵展开：\((\mathbf{I}-\beta_tk_tk_t^{\top})\operatorname{Diag}(\alpha_t)=\operatorname{Diag}(\alpha_t)-\beta_tk_t\,(k_t\odot\alpha_t)^{\top}\)。它正好是 DPLR 的形式，对应关系是

$$\mathbf{D}=\operatorname{Diag}(\alpha_t),\qquad a_t=\beta_tk_t,\qquad b_t=k_t\odot\alpha_t$$

也就是说，KDA 是一个受约束的 DPLR：两个低秩向量不再独立，都由同一个 key 决定，而且 \(b_t\) 里的衰减和对角部分共用同一个 \(\alpha_t\)。这个约束有两个后果。一是表达力上它和经典 delta 规则保持一致（“擦除的方向”就是“写入的方向”）；二是计算上它省了很多事。在一般 DPLR 的分块算法里，\(a\)、\(b\) 两个向量都要和逐通道衰减交互，块内需要用二级分块精确计算四个 \(C\times C\) 矩阵；把 \(a\)、\(b\) 都绑到 \(k\) 上之后，只剩两个，而且在块间更新和输出阶段还能再省掉大约三次矩阵乘法（逐行对照见第 6 节）。报告的结论是 KDA 的算子效率比一般 DPLR 提高约 100%。

4 模型架构：KDA 层长什么样，怎么和 MLA 混在一起

这一节要回答的问题：一个完整的 KDA 层除了上一节的递推，还有哪些部件（短卷积、归一化、门）？KDA 层和全注意力层按什么比例、以什么方式混合？全注意力层为什么选 MLA，又为什么可以不要位置编码？最后用公开的模型配置算一算，1M 上下文时 KV 缓存到底能省多少。
先补一点背景：MoE 骨干和 Moonlight。

Kimi Linear 是一个混合专家（MoE）模型：每层的前馈网络被拆成很多个“专家”小网络，一个路由器为每个 token 只挑其中几个来算。这样总参数可以很大（存知识），每个 token 实际用到的参数却很少（省计算）。MoE 和 MLA 的细节见 DeepSeek-V3 精读 §2.1。报告说骨干结构沿用 Moonlight，那是 Moonshot 用 Muon 优化器训练的 16B 总参、3B 激活的 MoE 模型（见 Muon 精读）。Kimi Linear 主要的不同是把 MoE 的稀疏度提高到 32：256 个专家里每个 token 激活 8 个，总参数 48B，激活参数仍约 3B；第一层用普通的稠密前馈网络，以求训练稳定。

4.1 一个 KDA 层的完整计算

对第 \(h\) 个头，输入向量 \(x_t\) 经过下面几路投影（原文 §4 的公式）：

$$q_t^h,\;k_t^h=\operatorname{L2Norm}\big(\operatorname{Swish}(\operatorname{ShortConv}(\mathbf{W}_{q/k}^h x_t))\big),\qquad v_t^h=\operatorname{Swish}\big(\operatorname{ShortConv}(\mathbf{W}_v^h x_t)\big)$$
$$\alpha_t^h=f\big(\mathbf{W}_{\alpha}^{\uparrow}\mathbf{W}_{\alpha}^{\downarrow}x_t\big)\in[0,1]^{d_k},\qquad \beta_t^h=\operatorname{Sigmoid}(\mathbf{W}_{\beta}^h x_t)\in[0,1]$$

逐项解释，每一项都有它的理由：

  • 短卷积（ShortConv）：沿序列方向的逐通道因果卷积，核长很小（公开配置里是 4），也就是让每个通道和前面 3 个 token 的同一通道做一次加权混合。它几乎不花算力，却给 q、k、v 注入了“紧挨着的几个 token 是什么”这种局部顺序信息。第 5 节的消融显示去掉它验证困惑度变差。
  • L2 归一化 q、k：把 key 的长度固定为 1。这样 \(\mathbf{I}-\beta_tk_tk_t^{\top}\) 的特征值是 1（\(d_k-1\) 重）和 \(1-\beta_t\)，都落在 \([0,1]\) 里，状态在多次连乘后不会爆炸。如果不归一化，\(\beta_t\|k_t\|^2\gt 2\) 时会出现绝对值大于 1 的负特征值，状态会越乘越大。报告称这一步是为了“特征值稳定”。
  • 逐通道衰减 \(\alpha_t\)：先用低秩投影把 \(x_t\) 压到 128 维（等于头维度），再投影回每个头的 \(d_k\) 维，然后经过一个和 GDN、Mamba 类似的函数 \(f\) 映射到 \([0,1]\)。公开代码（以及 Kimi K3 报告的复述）给出了 \(f\) 的具体形式：先算对数衰减 \(g_t=-e^{A_h}\operatorname{Softplus}(z_t)\le0\)，再取 \(\alpha_t=e^{g_t}\)，其中 \(z_t\) 是投影结果加一个偏置，\(A_h\) 是每个头一个可学习的尺度。在对数域里参数化，保证了 \(\alpha\) 永远落在 \((0,1)\) 里。
  • 写入强度 \(\beta_t\)：每个头一个标量，Sigmoid 激活。它不需要逐通道，因为它控制的是“这一次写入多用力”，而不是“哪个通道留多久”。

KDA 递推的输出在送出之前还要经过两步（原文式 10）：

$$o_t=\mathbf{W}_o\Big(\operatorname{Sigmoid}\big(\mathbf{W}_g^{\uparrow}\mathbf{W}_g^{\downarrow}x_t\big)\odot\operatorname{RMSNorm}\big(\operatorname{KDA}(q_t,k_t,v_t,\alpha_t,\beta_t)\big)\Big)$$

先对每个头的输出单独做 RMSNorm，再乘一个由 \(x_t\) 算出的 Sigmoid 输出门，最后过输出投影 \(\mathbf{W}_o\)。输出门让模型可以按 token、按通道决定“这一层这次读出来的东西用多少”。报告说这个门借鉴了 Gated Attention 的做法（见 Gated Attention 精读），能缓解注意力汇聚点（attention sink）现象；门同样用低秩参数化，是为了和基线保持参数量相当，性能和满秩门相近。

4.2 为什么按层混合，为什么是 3:1

纯线性注意力的主要短板是长上下文检索，所以要掺一些全注意力层。混合有两种方式：层内混合（同一层里一部分头用线性注意力、一部分头用 softmax，或者对远处和近处的 token 用不同机制）和层间混合（整层整层地交替）。报告选了层间混合，理由是基础设施简单、训练稳定：同一层里只有一种计算路径，张量并行、流水并行、KV 缓存管理都不用为“半层线性、半层 softmax”做特殊处理。比例上，报告用消融实验（第 5 节表 1）比较了 0:1、1:1、3:1、7:1、15:1，认为 3:1 在质量和吞吐之间最平衡。全注意力层选 MLA，是因为 Moonshot 之前的 Moonlight、Kimi K2 都用 MLA，它本身就是一种压缩 KV 缓存的注意力。

4.3 MLA 层不要位置编码（NoPE）

先补一点背景：RoPE 为什么会妨碍 MLA 的“矩阵吸收”。

RoPE 把位置信息编码为对 query 和 key 的旋转：位置 \(i\) 的 key 被旋转角度 \(i\theta\)，位置 \(t\) 的 query 被旋转 \(t\theta\)，二者点积只依赖相对距离 \(t-i\)（详见 RoFormer 精读）。MLA 的 KV 缓存只存每个 token 的一个 512 维“潜向量”，推理时把“从潜向量还原 key 的矩阵”吸收进 query 一侧，直接拿 query 和潜向量做点积，所有头共用同一份潜向量，计算上等价于只有一个 KV 头的多查询注意力（MQA）。问题是，如果 key 先还原再旋转，旋转矩阵夹在 query 和潜向量之间，并且随位置变化，就没法预先吸收。DeepSeek 的解决办法是另开一个 64 维、所有头共用的“带 RoPE 的 key 分量”，这部分单独缓存、单独计算（详见 DeepSeek-V3 精读 §2.1）。

Kimi Linear 的所有 MLA 层都不加任何位置编码（NoPE），位置信息和“近处更重要”的倾向全部交给 KDA 层负责。报告的依据是：KDA 按顺序处理 token，逐通道衰减随距离累积，隐藏状态里已经带有相对位置信息；从这个意义上说，KDA 承担了类似短卷积或滑动窗口注意力（SWA）的“位置感知”角色，甚至更强。报告引用了几项先前工作的结论：给全局 NoPE 注意力配上一个专门感知位置的机制，长上下文表现可以很有竞争力。

NoPE 带来两个工程上的好处。第一，MLA 在推理时可以完全变成纯 MQA：没有旋转挡在中间，整个 key 都能被吸收。第二，长上下文训练变简单：RoPE 模型把上下文从 4K 扩到 128K、1M 时，通常要调大旋转频率的底数，或者用 YaRN 之类的方法插值；NoPE 模型没有这些参数可调，也就不需要调。

和代码对照时的一个细节：公开的 Hugging Face 实现里，MLA 层仍然保留了那个 64 维的“位置分量”投影（配置里 qk_rope_head_dim 仍是 64），只是不再对它做旋转（配置项 mla_use_nope 为 true，代码中没有任何旋转操作）。所以它实际上变成了 64 维额外的、所有头共用的内容分量，KV 缓存每个 token 每层仍是 512 + 64 个数。“不加位置编码”指的是不旋转，并不是把这部分维度删掉了。

5 实验（上）：合成任务、消融与缩放律

这一节要回答的问题：在真正花大价钱训练 48B 模型之前，作者先用小实验回答了三个问题：逐通道衰减在“记忆管理”类的合成任务上是否真的比标量衰减好？混合比例、输出门、短卷积这些设计选择各自有多大作用？把规模放大时，Kimi Linear 相对全注意力的优势是保持、扩大还是缩小？这一节对应原文 §5.1–5.3。

5.1 合成任务：回文、多查询联想回忆、栈

先补一点背景：为什么用这三种合成任务。

固定大小的状态有一个已知的弱点：它很难把一长串输入原封不动地记住再吐出来，也很难在大量键值对里精确找到某一个。合成任务把这些能力单独拎出来测，噪声小、结论清楚。回文（倒序复制）要求模型把一串随机 token 倒着输出一遍，考的是“完整、精确地记住全部历史”，已有研究表明这类复制任务对线性注意力很难。多查询联想回忆（MQAR）先给一串“键 值”对，再给若干个键，要求输出对应的值，考的是联想检索；已有研究发现它和语言建模质量高度相关。栈同时维护 64 个独立的栈，输入是一串“压入某栈某元素”“弹出某栈”的操作，要求在弹出时报出正确元素，考的是状态追踪。

  • 报告正文说 Mamba2 “在所有任务上都失败”，但从原图看，它在 256 长度时三个任务都接近 100%，栈任务到 512 也还是 100%，失败的是更长的设置。
  • 2048 长度的回文和 MQAR 上，KDA 也只有 42% 和 48%，并没有“解决”这些任务；它比 GDN 好，但两者都在掉。这本来就是固定状态的上限问题，也是后面仍要混入全注意力的原因。
  • 报告的是“学习率网格里最好的那条训练准确率曲线”，每个配置看来只跑了一次；2 层 2 头的小模型和 48B 混合模型之间隔着很远，这组实验说明的是机制上的倾向，不能直接推到大模型。

5.2 关键组件的消融

消融实验都在缩放律实验的第一档模型上做（16 个头、16 层，激活参数约 653M），所有变体用相同的计算量预算和超参数，比较训练困惑度和验证困惑度（越低越好）。验证集是一份高质量数据，分布和预训练语料差别很大，所以验证困惑度（5.6 左右）比训练困惑度（9.2 左右）低得多；报告选它是为了考察分布偏移下的泛化。

5.3 缩放律：放大之后优势还在吗

先补一点背景：计算最优的缩放律。

训练损失大致随训练算力 \(C\) 按幂律下降：\(L=A\cdot C^{-b}\)。Chinchilla 的做法是对每个算力预算选出最合适的模型大小和训练 token 数（计算最优），再用几组这样的点拟合出 \(A\) 和 \(b\)。两个架构的拟合曲线放在一起，就能回答“达到同样的损失，谁需要的算力更少”。“1.16 倍计算效率”的意思是：要达到 Kimi Linear 在某个算力下的损失，MLA 需要多花约 16% 的算力。算力单位 PFLOP/s-days 指“每秒 \(10^{15}\) 次浮点运算持续一天”，约 \(8.64\times10^{19}\) 次运算。

实验设置（原文表 2）。5 档 MoE 模型，激活参数（不含嵌入）从 653M 到 1.7B，头数和层数从 16 增加到 24，训练 token 从 38.8B 到 128B；都按 Moonlight 的结构，64 个专家激活 8 个，用 Muon 优化器，上下文 4096。MLA 的每一档都用网格搜索仔细调过超参数；Kimi Linear 固定 3:1 的比例，直接照搬 MLA 的训练配置，没有再调。按 \(6ND\) 粗估，这 5 档的训练算力大约在 1.8 到 15 PFLOP/s-days 之间（推算）。

拟合结果是：MLA 为 \(L=2.3092\times C^{-0.0536}\)，Kimi Linear 为 \(L=2.2879\times C^{-0.0527}\)。报告的结论是在计算最优训练下，Kimi Linear 的计算效率约为 MLA 的 1.16 倍，并认为如果给 KDA 也单独调超参数，曲线还会更好。

5.4 实验设置：怎样才算“同配方”

参与对照的模型。MLA 是全注意力基线；GDN-H 是用 Gated DeltaNet 替换 KDA 的混合基线；Kimi Linear 是本文模型。三者的结构、参数量和训练设置都相同，GDN-H 也用了 Sigmoid 输出门。为了单独检验 NoPE，报告还训练了一个 MLA 层加 RoPE 的 Kimi Linear (RoPE)。四个模型都是 48B 总参、3B 激活：报告写的是“256 个专家激活 8 个（含 1 个共享专家）”，公开配置里则是 256 个路由专家选 8 个、另加 1 个共享专家；第一层是稠密层。

预训练。四个模型都用 4,096 token 的上下文窗口、MuonClip 优化器和 WSD 学习率调度（先预热、再长时间保持、最后衰减），从 Kimi K2 的预训练语料里采样共 1.4T token，学习率 \(1.1\times10^{-3}\)，全局批大小 3,200 万 token，并沿用 K2 的退火阶段和“长上下文激活”阶段（报告没有展开这一阶段的长度和数据）。最终发布的模型用同样的流程训练了 5.7T token（与 Moonlight 对齐），支持 1M 上下文。

后训练。指令微调（SFT）数据在 K2 的 SFT 数据基础上加入了更多推理任务，分多个阶段：先在广泛的指令数据上训练通用能力，再有计划地加练推理数据。强化学习的提示集主要来自数学、代码和 STEM，先筛掉对起点模型过难或过易的题。为了防止强化学习损伤通用能力，训练中同时加了 PTX 损失（在高质量的通用数据上继续做监督学习）。算法沿用 Kimi K1.5，并加了几项稳定性措施：用截断重要性采样（TIS）修正推理引擎和训练引擎之间因数值精度不同而产生的策略偏差（这个问题的来龙去脉见 批不变性精读），动态调整 KL 惩罚和每轮更新次数，避免熵塌缩。

先补一点背景：几种评测方式。
  • 基于困惑度的评测：对于选择题，不让模型生成答案，而是比较模型给每个选项打的概率，取最高的。基座模型的 MMLU、MMLU-Redux、GPQA-Diamond、C-Eval 用的是这种方式，其他基准让模型生成答案再判分。两种方式算出的分数不能直接比较。
  • Avg@k：同一道题采样 \(k\) 次取平均正确率，用来降低温度 1.0 采样带来的方差。比如 AIME 2025 用 Avg@64，GPQA-Diamond 取 8 次独立运行的平均。
  • 长上下文基准（都在 128K 长度上测）：RULER 是可控长度的合成检索与多跳追踪；MRCR 要求在很长的多轮对话里找出某一类请求的第几次出现并复述对应回答；HELMET-ICL 是长上下文里的大量示例学习；LongBench v2 和 Frames 是贴近真实的长文档推理与多跳事实检索；RepoQA 要按描述在代码仓库里找到对应函数；Long Code Arena 的 Lib 和 Commit 两项分别是基于库的代码生成和提交信息生成。

所有模型都在内部的、基于 LM-Harness 改造的评测框架下、用同一套设置评测，温度一律 1.0。

5.6 效率：预填充和解码各快多少

先补一点背景：速度指标和批大小。

预填充耗时是处理完整段输入所需的时间，决定了首个 token 要等多久。TPOT（time per output token）是解码阶段平均每生成一个 token 的时间。批大小为 1 时，TPOT 就是单个用户感受到的生成速度；批大小为 \(B\) 时，一步同时为 \(B\) 个请求各生成一个 token，如果把一步的耗时除以 \(B\)，得到的是“摊到每个 token 上的时间”，它的倒数是吞吐量。解码阶段受显存带宽限制，批越大越划算（见 vLLM 精读 §1），而批能开多大取决于显存里放得下多少请求的缓存。

6 讨论：KDA 为什么能当位置编码，和 DPLR 差在哪，计算量有多大

这一节要回答的问题：前面几处结论都依赖一个观点：KDA 本身就带着位置信息，所以 MLA 层可以不要位置编码。这个观点从哪来？它和 RoPE 是什么关系？第 3 节说 KDA 比通用 DPLR 少算很多，具体少在哪几步？KDA 和全注意力的计算量各随长度怎样增长，推理时又是怎么切换算法的？这一节对应原文 §6。

6.1 KDA 是一种可学习的位置编码

先补一点背景：把 RoPE 写成“矩阵连乘”。

不加位置编码的注意力对输入顺序是不敏感的：把句子里的词换个顺序，每个词得到的输出不变（因果掩码只提供了“谁在前面”这一点点信息）。RoPE 的做法是把 query、key 的每两个维度看成一个平面上的向量，位置 \(j\) 的 token 在第 \(k\) 个平面上旋转 \(j\theta_k\)。报告把它写成一个统一的形式（原文式 11）：

$$s_{t,i}=q_t^{\top}\Big(\prod_{j=i+1}^{t}\mathbf{R}_j\Big)k_i$$

即 query 和 key 之间夹着一串“每走一步乘一次”的矩阵。对 RoPE，每一步都是同一个旋转，连乘的结果只取决于走了多少步 \(t-i\)，所以它编码的是相对位置；又因为旋转矩阵是正交的（\(\mathbf{R}_{t-i}=\mathbf{R}_t^{\top}\mathbf{R}_i\)），可以把旋转分别加在 query 和 key 上，不必真的去做连乘。

把 KDA 的递推展开（原文式 12，省略 \(\beta\)），第 \(t\) 个输出对第 \(i\) 个 value 的权重是：

$$o_t=\sum_{i\le t}\Big(q_t^{\top}\prod_{j=i+1}^{t}\operatorname{Diag}(\alpha_j)\big(\mathbf{I}-\beta_jk_jk_j^{\top}\big)\,k_i\Big)\,v_i$$

形式和 RoPE 一模一样：query 和 key 之间夹着一串逐步相乘的矩阵。区别有两点。第一，RoPE 每一步的矩阵是固定的，KDA 每一步的矩阵由当时的输入决定，是学出来的；第二，RoPE 的矩阵是正交的（只转不缩），KDA 的矩阵会收缩（衰减和擦除都让向量变短），距离越远，夹在中间的收缩越多，权重越小。所以 KDA 天然带有“越近越重要”的倾向，而且这种倾向的强弱可以按内容调节。报告由此把 GDN 类模型看成一种“乘法式的相对位置编码”，它放松了 RoPE 的正交约束，可能更强。

模型query 和第 \(i\) 个 key 之间夹着什么性质
softmax 注意力什么都没有（打分为 \(\exp(q_t^{\top}k_i)\)）对位置无感，需要外加位置编码
softmax + RoPE\(\prod \mathbf{R}_s\)，固定旋转正交，只依赖相对距离
线性注意力什么都没有无位置信息，也不会遗忘
Mamba2\(\prod \alpha_s\)，标量衰减所有通道同一种距离刻度
GLA\(\prod \operatorname{Diag}(\alpha_s)\)每个通道一种刻度，没有擦除
DeltaNet\(\prod(\mathbf{I}-k_sk_s^{\top})\)按内容擦除，没有衰减
Gated DeltaNet\(\prod \alpha_s(\mathbf{I}-k_sk_s^{\top})\)擦除 + 单一刻度的衰减
KDA\(\prod \operatorname{Diag}(\alpha_s)(\mathbf{I}-k_sk_s^{\top})\)擦除 + 每个通道一种刻度的衰减

为什么要逐通道？报告指出，RoPE 的一个关键优点是给每一对维度分配不同的旋转频率，相当于沿特征维度做了一次非均匀的傅里叶变换：高频的维度对相邻几个 token 的差别敏感，低频的维度能分辨很远的距离。GDN 的标量衰减只有一种“距离刻度”，缺少这种多样性；KDA 的逐通道衰减让每个通道各有一种刻度，下图画的就是这件事。

这个视角也解释了报告对 RoPE 外推问题的看法：RoPE 的频率是固定的，模型容易过拟合训练时见过的长度，超出这个长度后，高频以外的那些维度会转到训练中从未出现过的角度；业界的补救办法有部分旋转（只对一部分维度加 RoPE）、调大频率底数，甚至干脆不用位置编码。既然 KDA 层已经扮演了 RoPE 的角色，Kimi Linear 就让全局的 MLA 层用 NoPE，让位置信息由 KDA 动态地捕捉。

这是一个解释，不是证明：“KDA 可以替代位置编码”的直接证据只有表 5 的一组对照（NoPE 比 RoPE 的长上下文平均分高 2.7）和发布模型在 1M 上的 RULER 成绩。报告没有分析 KDA 学到的衰减系数实际分布成什么样，也没有测试“只用 MLA、全部 NoPE”时会怎样。

6.2 和 DPLR 的关系：少算的到底是哪几步

DPLR 结构在 S4 里就出现过，不过 S4 用的是固定的 DPLR 矩阵，计算时通常把它在复数域里对角化，表达力实际上被限制成了对角变换。随输入变化的一般 DPLR 表达力更强，但计算量大、不好并行。KDA 的转移矩阵可以改写为 \(\operatorname{Diag}(\alpha_t)-\beta_tk_tk_t^{\top}\operatorname{Diag}(\alpha_t)\)，正好是 \(a_t=\beta_tk_t\)、\(b_t=k_t\odot\alpha_t\) 的 DPLR；而因为对角部分和 \(b_t\) 共用 \(\alpha_t\)，衰减可以整体提到前面去，先像 GLA 那样做逐通道衰减，再像 DeltaNet 那样做 Householder 式的擦除。

6.3 复杂度：训练算多少，推理怎么算

训练计算量。Kimi Linear 和全 MLA 的参数量相近，各种线性投影的计算量相同，差别只在注意力核心本身。对一个头、头维 \(d_h\)、块长 \(C=64\)、长度 \(T\) 的序列，报告给出（原文式 13–14）：

$$\mathrm{FLOPs}_{\text{KDA}}=6Td_h^2+3TCd_h+TC^2,\qquad \mathrm{FLOPs}_{\text{Attn}}=2T^2d_h$$

代入 \(d_h=128\)、\(C=64\)：KDA 每个 token 约 \(6\times128^2+3\times64\times128+64^2\approx1.27\times10^5\) 次运算，是一个常数；全注意力每个 token 约 \(2Td_h=256T\) 次，随长度线性增长。两者之比在 \(T=4\)K 时约 8 倍，128K 时约 264 倍，1M 时约 2,100 倍（推算，只比较一个头的注意力核心）。但在 4K 这样的短上下文里，注意力核心只是全部计算的一小部分，大头是所有层都有的投影和 MoE 前馈，所以第 5 节图 7(a) 里 4K–16K 时三个模型的预填充时间几乎一样。

推理策略。预填充用第 3 节的分块内核（矩阵乘法密集），逐个生成时切换到逐步递推的内核（读写量小）。公开的 Hugging Face 实现正是这样切换的：一次输入的 token 数不超过 64 时走逐步递推，否则走分块。每个 KDA 头的状态固定为 \(128\times128\)，与序列长度无关。报告认为，随着序列变长，受显存带宽限制的解码时间会逼近混合比例决定的上限，并引用图 7(b) 中 1M 时“2.3 倍”的加速（图上标的是 2.2 倍）；再加上省下的显存可以支持更大的批，长上下文下的理论解码加速可达 6.3 倍。按第 4 节的推算，只有 7/27 的层读随长度增长的 KV，这个上限应在 27/7 ≈ 3.9 倍附近，而不是报告字面上写的“3:1”（推算）；实测单请求停在 2.2 倍，是因为读权重等固定开销摊不掉。

7 相关工作与结论：线性注意力、稀疏注意力与混合模型

这一节要回答的问题：KDA 在线性注意力家族里处于什么位置？同样是为长上下文省钱，稀疏注意力（NSA、MoBA、DSA）走的是另一条路，两条路各有什么长短？混合模型有哪几种做法，Kimi Linear 为什么选“按层交替 + NoPE”？

线性注意力的演化。线性注意力用核函数代替 softmax，借助矩阵乘法的结合律避免显式构造 \(T\times T\) 的注意力矩阵，从而做到线性复杂度。之后的改进主要沿两条线展开：衰减从与数据无关（RetNet）变成与数据相关（Mamba2 等），粒度从每个头一个标量变成逐通道（GLA）；更新规则从单纯叠加变成带纠错的 delta 规则。报告的表 7 用“测试时训练”（TTT）的框架把这些方法统一起来：每种方法都可以看成在每个 token 上对状态做一步梯度下降，区别只在优化的目标函数。

方法每一步在优化什么更新规则
线性注意力让读出值和 \(v_t\) 方向一致（无上限）\(\mathbf{S}_t=\mathbf{S}_{t-1}+k_tv_t^{\top}\)
RetNet / Mamba2同上，再加一个把状态拉向 0 的正则项\(\mathbf{S}_t=\alpha_t\mathbf{S}_{t-1}+\beta_tk_tv_t^{\top}\)（RetNet 的 \(\alpha\) 固定）
GLA同上，正则项逐通道\(\mathbf{S}_t=\operatorname{Diag}(\alpha_t)\mathbf{S}_{t-1}+k_tv_t^{\top}\)
Gated DeltaNet在衰减后的状态上最小化重建误差\(\mathbf{S}_t=(\mathbf{I}-\beta_tk_tk_t^{\top})\alpha_t\mathbf{S}_{t-1}+\beta_tk_tv_t^{\top}\)
KDA在逐通道衰减后的状态上最小化重建误差\(\mathbf{S}_t=(\mathbf{I}-\beta_tk_tk_t^{\top})\operatorname{Diag}(\alpha_t)\mathbf{S}_{t-1}+\beta_tk_tv_t^{\top}\)

报告也承认，即使有了这些改进，线性注意力在精确复制和极长上下文里的细粒度检索上仍然落后于全注意力，这正是要做混合、要用更有结构的更新规则（如 delta 规则的秩 1 纠错）的原因。

稀疏注意力：另一条路。稀疏注意力不压缩历史，而是每次只挑一部分历史 token 来算注意力。早期方法用固定模式（滑动窗口、空洞窗口、固定跳跃），结构僵硬、容易掉点；后来的方法按内容动态挑选（聚类、轻量路由），但挑选本身有开销，没有专门的内核就拿不到理论加速。近期的做法强调软硬件协同：NSA 和 MoBA 都从挑 token 改成挑块，NSA 用一个小网络给块打分、依赖分组查询注意力里足够多的头来凑满矩阵乘法，MoBA 用 FlashAttention 内核顺便算出的 log-sum-exp 分数选前 \(k\) 个块；DeepSeek-V3.2-Exp 的 DSA 又回到按 token 选，靠一个低精度（FP8）、小头维的“索引器”全注意力来保持效率（见 DeepSeek-V3.2 精读）。

两条路怎么比。报告的看法是：稀疏注意力更擅长取回细粒度的历史信息，但它必须保存全部 KV 缓存才能从中挑选，所以内存上不如状态固定的线性注意力；而且稀疏只是在全注意力里做选择，表达能力的上限就是全注意力。线性注意力奉行“压缩即智能”，用固定大小的状态做泛化，配上 delta 规则后理论表达力还可能更强；它的检索短板可以用扩大状态等办法缓解，真正的障碍是硬件实现和推理基础设施不成熟，这正是 Kimi Linear 开源内核、接入 vLLM 想解决的。报告最后提出，两条路并不互斥，未来可以把线性注意力的压缩能力和稀疏注意力的细粒度检索结合起来。

混合模型的两种做法。层内混合在同一层里融合不同机制，比如把 softmax 头和状态空间模型的头并排放在一层（如 Hymba），或者对较早的历史用线性注意力、对最近的 token 用滑动窗口注意力。它的缺点是系统复杂：异构的计算路径让分布式并行等优化变得麻烦。层间混合按固定比例整层交替，Jamba、MiniMax-01、混元 TurboS 等大模型都采用了这种方式，Kimi Linear 也是，只是线性部分用 KDA 而不是常见的 Mamba2，因为作者发现 KDA 整体更好，尤其是检索和复制能力。

位置编码的趋势。近期研究发现混合模型对 RoPE 频率底数的调整很敏感，给上下文扩展带来麻烦。于是不少模型向 NoPE 靠拢：Falcon-H1 用了极大的 RoPE 底数（约 \(10^{11}\)），让位置编码几乎等于没有；SWAN-GPT 让带 RoPE 的层和 NoPE 的全注意力层交替。Kimi Linear 的“KDA + NoPE 全注意力”属于同一方向，报告认为它让上下文扩展变得直接。

结论。报告的总结是：Kimi Linear 以逐通道门控的 KDA 为核心，与全注意力按 3:1 交替，内存占用最多降低 75%，解码吞吐最多提高 6.3 倍，并在相同条件下超过全注意力基线；内核和预训练权重都已开源。

后来怎么样了

Kimi Linear 发布于 2025 年 10 月底。到 2026 年 10 月，它最重要的后续是 Moonshot 自己的旗舰模型 Kimi K3 全面采用了 KDA 混合架构；同时 KDA 内核和模型实现进入了主流开源库。下面分三部分讲。

开源与采用（截至 2026-10-20）

  • 内核。KDA 的 Triton 内核在 flash-linear-attention（fla）库的 fla/ops/kda 目录下，包括训练和预填充用的分块内核、解码用的逐步递推内核和衰减门函数；该目录下的 backends 还有 flash_kda、tilelang、triton_ascend 三个后端。fla 库当时有 5,953 个 GitHub star。Moonshot 另有一个用 CUTLASS 写的开源内核仓库（2026-04 创建） FlashKDA（1,282 个 star），Kimi K3 报告说它会作为 fla 的后端被自动调用。
  • 推理引擎。vLLM 主干的模型注册表里有 KimiLinearForCausalLM，目前它和 Kimi K3 的实现放在同一个模块（vllm.models.kimi_k3）里。
  • 权重。Hugging Face 上的 Kimi-Linear-48B-A3B-Instruct 有 609 个点赞，近 30 天下载约 16.9 万次；Base 版有 84 个点赞。代码仓库 MoonshotAI/Kimi-Linear 有 1,618 个 star，MIT 许可。

Kimi K3：把 KDA 放大到 2.8T 参数

先补一点背景：Kimi K3 是什么。

Kimi K3（arXiv 2607.24653，2026-07）是 Moonshot 的旗舰模型：2.8T 总参数、104B 激活参数的 MoE，原生支持图像和视频，上下文 1M token。它的架构有四项新东西：KDA 混合注意力（沿序列方向）、Attention Residuals（沿深度方向：每一层不再把前面各层的输出等权累加，而是用一个可学习的“伪 query”对前面各层的输出做注意力，自己挑要什么）、Stable LatentMoE（沿宽度方向：896 个路由专家激活 16 个，在压缩的潜空间里计算）和逐头的 Muon 优化器。这里只讲与本文直接相关的 KDA 部分。

层的排布没有变。K3 仍是“3 层 KDA + 1 层 MLA”为一组反复堆叠，最后再加 1 层 MLA，保证最后一层一定是全局注意力，一共 93 层：69 层 KDA、24 层 MLA（Kimi K2 是 61 层全 MLA）。所有 MLA 层继续不用位置编码，并且加了一个由输入决定的、满秩的 Sigmoid 输出门（报告称为门控 MLA）。为了修正 FlashAttention 中有偏的舍入误差，K3 在训练时把注意力输出保留为 FP32。

KDA 本身改了两处。第一处是给衰减加了下界。第 3 节讲过，Kimi Linear 把 64 token 的块再切成 16 token 的小块，非对角小块用 Tensor Core 做矩阵乘法，对角线上的小块却必须逐个位置对计算，因为块内累积衰减的倒数可能大到溢出。K3 把对数衰减的映射从 \(g=-e^{A}\operatorname{Softplus}(z)\)（可以趋于负无穷）改成

$$g=g_{\min}\cdot\operatorname{Sigmoid}(e^{A}z)\in(g_{\min},0),\qquad g_{\min}=-5$$

于是每一步的保留系数都大于 \(e^{-5}\approx6.7\times10^{-3}\)，16 个 token 的累积对数衰减落在 \((-80,0)\) 之间，倒数小于 \(e^{80}\)（约 \(5.5\times10^{34}\)，推算），在 BF16 的表示范围之内。数值范围有了保证，对角小块也可以直接用 Tensor Core 的稠密矩阵乘法，块内的主要瓶颈就去掉了。代价是模型不能再在一步之内把某个通道“清零”（最多只能衰减到约 0.7%）。第二处是把 KDA 的输出门从低秩改成满秩，和门控 MLA 一致。

上下文扩展更省事。K3 预训练时上下文从 8K 扩到 64K，在最后的退火阶段再从 256K 扩到 1M。报告说，因为没有位置编码，模型“可以直接外推到 1M，不需要任何位置编码上的修改”。要注意的是 K3 实际上训练到了 1M，所以这句话说明的是“扩展时不用调 RoPE 参数”，而不是“没训练过的长度也能用”。

KDA 的系统支持是 K3 报告着墨最多的部分。

  • FlashKDA 内核。朴素实现里，块内并行计算和块间串行传递状态是交替进行的，传递状态时大部分计算单元闲着。FlashKDA 把两者重叠起来，并把工作拆成按 token 并行的阶段和按头并行的递推阶段，各自调优，报告称明显快于 Triton 参考实现（没有给出倍数）。
  • 单卡内的上下文并行。纯张量并行时，每张卡只分到几个头，超长序列预填充时递推仍然很长，大量计算单元空闲。K3 利用“每一段的状态转移可以先独立算出来、事后再精确拼接”这一性质，在一张卡内把序列切给不同的计算单元并行处理。
  • 跨卡的 KDA 上下文并行（KCP）。原始线性注意力做上下文并行很简单：各卡从零状态算出本段的状态，前面各段相加即可。delta 规则不行，因为每个 token 的转移矩阵会作用在“进入这一段时的状态”上，本段的结果依赖前面的状态。KCP 让每张卡先算两样只依赖本地 token 的东西：本段的累积转移矩阵（\(d_k\times d_k\)）和从零状态出发的本地状态；一次固定大小的 all-gather 之后，每张卡按顺序把前面各段的这两样东西套用一遍，就能还原出自己的入口状态。通信量与序列长度无关，实现在 fla 的 PR #691 中。
  • 前缀缓存。混合模型的前缀缓存比全注意力难：MLA 的 KV 按 token 存，任何前缀都能截出来复用；KDA 的状态只是某个位置上的一个快照，只有事先存了快照的位置才能复用，而快照很大，只能稀疏地存。K3 把 KDA 状态和 MLA 的 KV 放进同一个分页池（统一页大小），物理块是 6144 token，但在块内按 512 token 做前缀哈希；KDA 快照只在少数哈希边界上保存，通常是对话轮次的边界。命中时取“MLA 哈希匹配且 KDA 有快照”的最长边界，把快照复制成请求私有的状态，从那里继续预填充。见下图。
  • 投机解码。KDA 的状态在解码时原地更新，如果多 token 预测（MTP）草稿里有一部分被拒绝，状态已经走过头、没法简单回退；为每个草稿位置存快照又会成倍增加读写量。K3 的做法是只缓存草稿 token 的投影输入（远小于状态本身），验证后在片上重放被接受的那几步，再写回状态。报告说这与 Dao AI Lab 同期提出的 ReplaySSM 思路相同。

怎么评价。K3 报告说，KDA、Attention Residuals、Stable LatentMoE 加上改进的数据和训练配方，合起来让整体缩放效率比 Kimi K2 提高约 2.5 倍。这是几项改动的总效果，报告没有在 K3 的规模上单独消融 KDA，所以不能从中读出“KDA 在 2.8T 规模上贡献了多少”。能确定的是：Moonshot 在 1.4T 规模的对照之后，把 KDA + NoPE MLA 的 3:1 混合用到了自己最大的模型上，并为它补齐了训练（上下文并行）、推理（前缀缓存、投机解码）和强化学习（KDA 状态与 MLA 缓存一起换出到 CPU 内存）的整套系统支持。K3 的总体评测成绩是厂商自报：报告说它整体落后于 Claude Fable 5 和 GPT-5.6 Sol，领先于其评测范围内的其他模型。

同一时期的其他选择，以及还不知道的事

  • 同样 3:1，位置编码的选择不同。阿里的 Qwen3-Next 也是每 4 层中 3 层 Gated DeltaNet、1 层门控全注意力，但它的全注意力层保留了部分 RoPE（公开配置里 partial_rotary_factor 为 0.25，即只对 1/4 的维度旋转）。两家在“线性层选什么”“全注意力层要不要位置编码”上做了不同选择，目前没有在同一配方下直接对比的公开结果。GDN 一侧的精读见 Gated DeltaNet 精读。
  • 稀疏注意力那条路也在推进。报告第 7 节说线性和稀疏是两条互补的路；DeepSeek 选的是稀疏这条，从 V3.2 的 DSA 一路发展下来（见 DeepSeek-V3.2 精读）。两条路在同一规模上的直接比较，本站还没有查到。
  • 还不知道的。截至 2026-10，本站没有查到其他机构在同等规模上独立复现“KDA 混合在同配方下超过全注意力”的结果；KDA 相对 GDN 的优势在比 48B-A3B 大得多的规模上是否保持，K3 报告也没有给出对照。效率数字的硬件依赖同样缺少公开的第三方测量。
