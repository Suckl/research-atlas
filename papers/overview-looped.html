这一节要回答的问题：循环 Transformer 想解决的是什么问题？为什么这件事一句话就能说清，比较起来却格外麻烦？本类 19 篇精读大致分成哪几支，读完本页能回答哪些问题？

普通的 Transformer 是一摞层，每一层有自己的一套参数，每个 token 从下往上把每一层恰好走一遍。这样一来，“模型存了多少参数”和“每个 token 算了多少”就被绑在了一起：想让每个 token 多算几步，就得多放几层参数；参数一多，显存、通信和部署的成本也跟着上涨。可是有不少任务恰恰需要“连续算很多步”：把几十个数加起来，在一段上下文里沿着线索跳好几跳，一步接一步地推一道数学题。一次前向计算里能连续做多少步，上限就是层数。

循环 Transformer（looped transformer，也叫 recurrent-depth 或 recursive transformer）把这两件事拆开：只造一组层，让每个 token 的隐藏状态在这组层里反复走几圈。参数还是那一份，每多走一圈，计算就多一份。人们希望从中得到四样东西。第一，同样的参数做更深的计算，适合显存紧张而算力相对富余的场合。第二，让难的 token 多走几圈、容易的少走几圈，也就是自适应计算。第三，“同一个步骤反复做”的结构可能天然适合多步推理和长度外推。第四，2025 年以来，它被看作思维链之外另一种“推理时多花计算”的办法：模型不多写字，而是在内部多算几遍。

难处在于比较。循环模型同时记着好几本账：存了多少参数，训练花了多少算力，推理时每个 token 花了多少算力，KV 缓存占了多少显存，以及训练看了多少数据。这几本账在普通模型里大致成比例，在循环模型里却各走各的。一个 1.4B 参数、整体循环 4 圈的模型，模型文件只有 1.4B，每生成一个 token 的计算却比一个 4B 的稠密模型还多（推算，见 §1.3）。所以“循环的小模型追平了大模型”这类说法，必须先问一句：对齐的是哪本账？本页把这个问题当作主线，讲到每一篇论文都会交代它的头条数字对齐了什么、没对齐什么。

本类 19 篇精读大致分成五支（见下图）。第一支是起点和理论：Universal Transformer 第一次在深度上循环，“可编程计算机”证明循环 Transformer 能执行写在输入里的程序，“潜在思考”把循环次数和思维链步数联系起来。第二支把循环做成真正的语言模型：Huginn、Mixture-of-Recursions 和 Ouro。第三支在另一个世界里：HRM 和 TRM 用几百万到几千万参数的小网络，在数独、迷宫和 ARC 上反复修正答案（HRM 在 TRM 精读里作为背景讲）。第四支回答“怎样训得稳、到底值多少”：Parcae、Iso-Depth、SMELT 三条扩展律，Loop-μP、ELR、ARLoop 三种训练或结构配方，以及一篇纯理论投稿“循环能替代多少参数”。第五支把循环带进扩散语言模型（Loopholing、LoopMDM、R-MDM、ALoDLM、Loop-Distill），那里的“循环”有两种完全不同的意思：在一个去噪步之内把网络多算几遍，或者在去噪步之间多传一份连续状态。

1 先把问题讲清楚：循环是什么，账有几本

这一节要回答的问题：“把同一组层反复用”落到一个具体的网络上，有哪几种摆法？要让它真正能训、能用，还需要哪些零件？循环之后，参数、训练算力、推理算力和 KV 缓存这几样东西各自怎样变化？为什么本页一直要求先问“对齐了什么”？
先补一点背景：残差流，以及“每 token 计算 ≈ 2 × 参数”。

Transformer 的每一层都不直接替换自己的输入，而是算出一个增量，再加回到输入上；这条一路加下去的向量叫残差流，下一层读的就是它。一层里绝大部分计算是矩阵乘法：一个 \(d\times d\) 的矩阵作用在一个 token 上，大约要做 \(2d^2\) 次浮点运算（乘法和加法各 \(d^2\) 次），而这个矩阵恰好有 \(d^2\) 个参数。所以一个 token 前向走过 \(N\) 个参数，大约要 \(2N\) 次运算；训练时还要反向传播，合计约 \(6N\)。这条经验规则成立的前提是“每个参数对每个 token 只用一次”。循环模型打破的正是这个前提：同一组 \(N\) 个参数被用 \(r\) 遍，每个 token 的计算就变成约 \(2rN\)，而模型文件里仍然只有 \(N\) 个参数。

1.1 三种摆法：整体循环、中间循环、局部循环

最直接的摆法是整体循环：把整摞层当作一个函数，让数据连续经过它好几遍。2018 年的 Universal Transformer 就是这样做的，后来的 Ouro 把 24 层或 48 层整体循环 4 遍，ARLoop 也循环整摞层。潜在思考一文给这种模型起了一个方便的记号 \((k\otimes L)\)：\(k\) 层循环 \(L\) 遍，有效深度是 \(kL\)。

第二种是中间循环，也叫“前奏—循环块—尾声”（prelude–recur–coda），由 Huginn 系统地提出。它的理由来自对普通 Transformer 的观察：开头几层要把被切碎的子词拼成完整的概念，最后几层要把概念映射回词表，这两段的分工很特殊；中间各层的行为彼此相似，甚至可以调换顺序。于是只循环中间那段“处理概念”的层，开头和结尾各留几层只走一遍。Parcae、Iso-Depth、SMELT、ELR、ALoDLM 都用这种结构，Mixture-of-Recursions 的 Middle-Cycle 共享方式也是同一个意思（首尾各留一层独立的层）。

第三种是局部循环：只把很少几层反复算。LoopMDM 在 12 层的扩散模型里只循环靠前的第 1、2 层（从 0 开始数）；Loop-Distill 只在训练时，让 2–3 个浅层各自连续多算几遍。

1.2 让循环能训、能用的几个零件

输入注入。如果循环块只读上一圈的状态，那么转很多圈之后，结果可能只取决于起点，而和题目本身关系越来越弱。Huginn 用梯度下降打了个比方：每走一步都要重新用到数据，迭代才会停在“和这道题有关”的地方。所以中间循环的模型通常在每一圈开头，把前奏的输出 \(e\) 和当前状态合在一起再送进循环块，相当于“每想一轮之前都重新看一眼题目”。Huginn 用的是拼接后接一个线性层；后来 Parcae 发现，训练不稳定恰恰出在这个注入矩阵上（§5.1）。

循环几圈由谁决定。有四种做法。一是写死在结构里，训练和推理都转固定圈数，Iso-Depth、SMELT 是这样。二是训练时每一步随机抽圈数，让同一个模型在推理时可以自由调圈数：Huginn 抽的分布均值是 33 圈、带一条长尾；Parcae 按序列抽。三是同一次参数更新里混合多种圈数，ELR 专门研究了这件事。四是让模型按 token 自己决定：Universal Transformer 给每个位置配一个自适应计算时间（ACT），Ouro 在每一圈末尾放一个退出门，MoR 用一个小路由器在一开始就为每个 token 分配圈数，ALoDLM 在扩散模型的一步之内按位置退出。

截断反传。转 30 圈就要沿 30 圈反向传播，显存和计算都受不了。常见的折中是只对最后几圈求梯度，前面各圈只做前向：Huginn 固定只反传最后 8 圈，Parcae 只反传后一半。这样训练省了不少，但 Iso-Depth 后来量出，它会让“每一圈的价值”变低（§5.5）。

KV 缓存。生成文字时，模型要为每个已处理的 token、在每一层存下它的 key 和 value。循环模型每一圈的输入都变了，同一层在不同圈算出的 K、V 也不同，所以默认要按“执行的层数”存。Ouro 的默认实现因此是同参数稠密模型的 4 倍；它在解码阶段只留最后一圈的缓存，GSM8K 几乎不掉（78.85 对 78.92），MATH-500 掉 2 分（Ouro §5.5）。MoR 则让每一圈只缓存仍在计算的 token（MoR §4）。KV 缓存的基本概念见 vLLM 精读。

1.3 四本账：参数、训练算力、推理算力、KV 缓存

有了上面的零件，就能说清楚“循环之后什么变了”。拿 Ouro 精读 §1 算过的一组数做例子：Ouro-1.4B 整体循环 4 圈，参数 1.43B，而 Qwen3-4B 有 4.02B 参数，前者只有后者的三分之一多一点。但按每个 token 的前向计算，Ouro-1.4B 约 10.07 GFLOPs，Qwen3-4B 约 8.04 GFLOPs，循环模型反而多了约 25%；按每个 token 的 KV 缓存，Ouro 默认存 4 圈、768 KiB，Qwen3-4B 用分组查询注意力只要 144 KiB；按训练总算力，Ouro-1.4B 约 \(3.4\times10^{23}\) FLOPs，和 Qwen3-1.7B 差不多，少于 Qwen3-4B（均为推算）；训练数据则是 7.7T 对 36T，内容也完全不同。所以“1.4B 追平 4B”这句话，在参数这本账上对 Ouro 极为有利；在每 token 推理算力和 KV 缓存上对它不利；在训练算力上，它和 Qwen3-1.7B 相当、比 Qwen3-4B 省；而训练数据两边完全不同，无从比较。

为什么会这样？SMELT 精读 §3.2 给了一个很干净的解释。在稠密模型里，每个参数都会被每个 token 用到，所以“每 token 计算量”和“参数量”成比例。循环让有效深度从 \(L\) 变成 \(L_{\text{eff}}\)，计算按比例上涨；如果要把计算压回去，就只能让模型变窄或变浅，参数也就跟着变少，而且没有任何旋钮能把参数补回来，因为新加的参数又会被每个 token 用到。只有在 MoE 里，“专家总数”只影响存储、不影响每个 token 的计算，才能一边收窄付计算、一边加专家补参数。这就是本页后面反复出现的分歧的根源：在稠密模型里，“同算力”和“同参数”不可能同时成立，每篇论文只能二选一，而它选哪一个，决定了它的结论长什么样。

不同的账对应不同的部署问题。如果瓶颈是显存（比如端侧设备），同参数的比较最有参考价值；如果瓶颈是训练预算，要看同训练算力；如果要大规模提供服务，要看每 token 的推理算力和 KV 缓存。没有哪一种比较是“唯一公平”的，但每一种都只回答自己那个问题。

两种常见误读。第一，“参数少”不等于“便宜”：Universal Transformer 的翻译模型参数和 Transformer base 相同，每个 token 的计算却约是它的 4 倍（UT 精读 §2.4，推算）。第二，“相当于 500 亿参数的计算量”说的是计算，不是能力：Huginn 摘要里的这句话，按 \(1.5+32\times1.5\approx49.5\)B 算出来的是每 token 的计算规模（Iso-Depth 精读 §7 的推算），并不意味着它有 50B 模型的本事。

2.1 Universal Transformer：把“很多不同的层”换成“同一个块用很多次”

当时卡在哪。2017 年的 Transformer 在翻译上取代了 RNN，但在一些很简单的任务上反而不如 RNN：比如原样复制一串数字，只要测试的串比训练时长，它就出错。UT 的作者把原因归到结构上：RNN 每一步都用同一个变换，天然倾向于学“把同一个小步骤反复做”的解法，这种解法对任意长度都适用；Transformer 则是若干层各不相同的层叠起来，计算步数固定，也没有这种倾向。

核心想法。保留 Transformer 层内的并行计算和自注意力，但把“很多不同的层”换成“同一个块在深度上反复用”。在此之上，给每个位置配一个自适应计算时间（ACT），让每个位置自己决定被这个块处理几次（§3）。作者还论证，只要允许步数随输入增长，这样的模型是图灵完备的（§8.2）。

结果与它的份量。UT 在 bAbI 问答、LAMBADA 和算法任务上明显好于作者自己训练的 Transformer，翻译上比 Transformer base 高 0.9 BLEU。但翻译这组比较只对齐了参数：按官方代码的配置，UT base 的块和 Transformer big 的一层一样宽，每个 token 的计算约是 Transformer base 的 4 倍（推算）；计算大致对齐时，UT small 反而低 1.2 BLEU（§7.1）。2023 年一项独立复现用工具数了乘加次数，参数和 Transformer base 相同的 UT，计算量和 Transformer big 差不多，BLEU 也和它一样是 29.3。还有一个容易忽略的细节：在官方实现里，已经“停下”的位置每一步仍被照算，整批要等最慢的位置，所以 ACT 改变的是输出怎么组合，并不省计算（§3.3）。

留下了什么。UT 之后，层间共享在预训练模型上并不顺利。ALBERT 发现宽度不变时共享全部层会让下游平均分下降；直到 2024 年的 MoEUT，才第一次让层间共享的模型在语言建模上和同参数的普通 Transformer 打平甚至略胜（这两项都没有单独的精读页，见 UT 精读“后来怎么样了”）。“在深度上循环”被大规模重新拾起，要等到 2025 年人们开始寻找“不加参数也能加计算”的扩展方式。

2.2 可编程计算机：存在这样的权重，但不说明能学到

当时卡在哪。此前已有证明说 Transformer 是图灵完备的，但要么假设数字无限精确，要么要求层数随计算一起增长，也没人告诉你具体怎样设定权重，才能让一个 Transformer 执行你写好的程序。

核心想法。这篇 ICML 2023 论文不训练任何东西，而是手写每一个权重矩阵：把输入设计成一张“打孔卡”，一部分列放指令，一部分当内存，一部分当草稿区；再把 Transformer 的输出原样接回输入，每循环一轮执行一条指令。结论是：9～10 层的 Transformer 就能执行单指令计算机 SUBLEQ 的任意程序（§5.1）；不超过 13 层的循环 Transformer 能当计算器、做矩阵求逆，甚至在上下文里跑带反向传播的 SGD。

份量。这是“存在一组权重”的表达能力结论，不涉及训练能不能找到它，也不说明真实语言模型内部是这样算的。它省的是参数，不是计算：在上下文里对 100 个数据点跑 10 遍线性模型 SGD，大约要循环一万轮（§9.3 的推算）。精度要求随轮数上升，FLEQ 部分没有代码（§9.4）。后续工作真正去训练循环 Transformer 做上下文学习，发现循环 30 轮的 1 层模型能追平 12 层的标准模型；但当循环 12 轮、有效深度和对手相同时，它追不上（§11.1 介绍，本站未单独精读）。这又是一个“同参数赢、同深度输”的例子。

2.3 潜在思考：推理要的是深度，不一定是参数

当时卡在哪。已有观察说，参数相同时更深更窄的模型推理更好。如果推理真正需要的是“连续算几步”，那它也许不需要那么多参数。

核心想法与合成实验。潜在思考用 \((k\otimes L)\) 记号做了一组很干净的实验：在 \(n\) 元加法上，1 层模型只有 0.1% 的准确率，把这 1 层循环 12 次就到 99.6%–100%，和 12 层基线一样；在 p 跳归纳和合成数学题 i-GSM 上，准确率几乎只取决于有效深度，而和“深度来自新参数还是重复参数”关系不大。这里循环模型和基线的计算量相同，所以结论是“这些任务要的是串行计算”，而不是“循环省计算”。

放到语言模型上。在 1B 参数、250B token 的预训练里，循环模型和 24 层基线的训练算力、推理算力、KV 缓存都相同，只是独立参数少了 \(24/k\) 倍。结果是：困惑度全部更差（7.90–8.79 对 7.40），闭卷问答全部更差，开卷问答差得少，数学应用题有高有低，推理基元上循环模型全部更好（§3.2）。精读页核对附录发现，推理基元上的优势几乎全部来自“在上下文里找到一个值并抄出来”的单步查找，而不是多步推理。作者又把循环次数从 1 加到 12，发现除推理基元外，“循环得来的深度”带来的提升只有“新层带来的深度”的 0.5–0.6 倍（§3.5）。这个比值，是后来 Iso-Depth 用扩展律精确测量的那件事的早期版本。

理论。作者证明，\(T\) 次循环可以模拟 \(T\) 步思维链，所以循环的中间状态可以看作“潜在的思考”（§5.4）。但这是表达能力的结论：构造里每一轮只让一个位置干有用的活，模拟 \(m\) 步思维链的计算量约是思维链本身的 \(m\) 倍（精读页推算）。作者还提出一个“让相隔 \(k\) 层的权重彼此相似”的正则项，在困惑度不变（7.38 对 7.40）的情况下把 15 项平均从 26.0 提到 30.0（§4）；这个模型仍有 24 层独立参数，是训练技巧，不是省钱的办法。

这一阶段留下的问题。第一，循环能不能在推理时自由加圈，像思维链一样“想得越久越好”？潜在思考的不同循环次数是分别从头训练的模型，没有测这件事。第二，在严格匹配算力之后，循环到底值多少？潜在思考给出的是“困惑度输、推理类差得少”的定性图景。这两个问题分别由第二阶段的 Huginn 和第三阶段的 Iso-Depth 接手。

“1 层循环 12 次就能做加法”“远好于同参数模型”这类说法成立的前提，是循环模型多花了 12 倍的计算。和计算相同的 12 层基线比，它是“打平”，不是“更好”。

3 做成语言模型：Huginn、Mixture-of-Recursions、Ouro

这一节要回答的问题：2025 年，循环第一次被做到数十亿参数、数千亿到数万亿 token 的规模。三家各自怎样设计循环、怎样决定转几圈？它们的头条数字是什么，又各对齐了哪本账？做大之后暴露出哪些新问题？

3.1 Huginn：不多说，而是多算

当时卡在哪。让模型推理前“多想一会儿”，主流做法是写长长的思维链。它很有效，但要用专门的长推理示范训练，上下文越写越长，而且每一步内部的计算最后都要压成一个离散的词才能被下一步读到。Huginn 想换一条路：每个词多算几遍，而不是多写几个词。

核心想法。前奏 2 层、循环块 4 层、尾声 2 层；循环块的初始状态是随机噪声，每一圈都把前奏的输出拼进来（输入注入）。训练时每一步随机抽一个圈数，分布均值是 33、带一条长尾，让模型在任意圈数下都能工作；只对最后 8 圈反向传播，所以抽到 120 圈也不会撑爆显存（§3.3）。最终模型 Huginn-0125 有 3.5B 参数，在约 800B token 上训练，用了 4096 张 AMD MI250X。规模上去之后发生了两次失败：一次所有位置的隐藏状态变成同一个向量（表示坍塌），一次模型学会了无视传进来的状态、循环形同虚设；第三次改回三明治归一化、学习率降为十分之一才训稳（§4.3）。

头条结果。圈数从 1 加到 32，GSM8K、MATH、HumanEval 这类推理任务从接近零涨到可观的水平；同一个模型不经额外训练就能做逐 token 提前退出、跨圈共享 KV 缓存和自投机解码（§6）。权重、代码和全部训练数据都已公开，后来成了很多工作的公共试验台。

对齐了什么。和 OLMo、Pythia 的比较几乎什么都没对齐。按精读页的推算，Huginn 的训练总算力约 \(1.7\times10^{23}\) FLOPs，和训练了 4T token 的 OLMo-2-7B 同一档，而后者在通用基准和数学上全面领先，只有代码题输给 Huginn；推理时转 32 圈，每个 token 约 105 GFLOPs，是 7B 普通模型的约 7 倍（§5.5）。控制得最好的一组是“结构相同、只走一遍循环块”的双胞胎：在同样 180B token 处，循环 32 次的 Huginn 在九项上全部领先，GSM8K 约高 5 倍；但两者训练算力差了 8–10 倍（推算），所以这是同参数、同数据的结论（§5.3）。另外，训练时抽到 1 圈的概率约十万分之一，“只转 1 圈时很差”本身就是分布外条件。

独立检验。一项专门的探针研究检查 Huginn 有没有在潜空间里做“不说出来的思维链”，没有找到可以逐步读出的中间结果；在禁止写出推理过程时，GSM8K 从 4 圈的 3.11% 只涨到 32 圈的 4.93%（§7.3）。表里漂亮的 GSM8K 分数，是“循环加写出来的思维链”共同取得的。

3.2 Mixture-of-Recursions：每个 token 转几圈，由路由器定

当时卡在哪。参数共享省存储，自适应计算省计算，以前两条路各走各的；而且递归模型的 KV 缓存并没有因为共享参数而变小，提前退出的 token 在更深的圈里没有 KV，后面的 token 查不到它。

核心想法。MoR 用 Middle-Cycle 共享一叠层，最多循环 \(N_r\) 圈；一个小路由器为每个 token 决定转几圈（§3）；每一圈只缓存仍在计算的 token 的 KV（§4）；推理时用“连续深度批处理”，一个 token 停下，队列里的下一个 token 立刻补上它在共享块里的位置（§7）。

结果与对齐。MoR 的主比较是按训练 FLOPs 对齐的，这比很多循环论文公平。在 360M 档、\(16.5\times10^{18}\) FLOPs 下，循环 2 圈的 MoR 只用约一半参数，因为一部分 token 少算几层，同样预算多看了 35% 的 token，验证 NLL 从 2.7824 降到 2.7511，few-shot 平均从 42.3% 升到 43.1%；循环 3、4 圈的版本 NLL 反而更差。1.7B 档上普通模型的 few-shot 平均是 48.9%，两个 MoR 是 48.4% 和 46.7%。“最高 2.06 倍吞吐”属于质量更差的 MoR-4，质量不输普通模型的 MoR-2 是 1.23–1.60 倍，而且推理代码没有公开（结果的份量）。综合起来，MoR 稳定的收益是用一半到三分之一的参数达到相近质量、推理更快，而不是同等训练算力下更低的损失。

3.3 Ouro：7.7T token、整体循环 4 圈、学出来的退出门

核心想法。Ouro 把 24 层（1.4B）或 48 层（2.6B）整体循环 4 圈，每一圈末尾放一个退出门，用“均匀先验 + 熵正则”的目标保证训练时各个深度都被探索，再用第二阶段只训练退出门（§3.2）。训练一开始转 8 圈，出现损失尖峰，退回 4 圈（§4.3）。这是循环模型里训练量最大的公开工作之一。

头条结果。1.4B 在推理类基准上追平甚至超过 Qwen3-4B（BBH 71.02 对 70.95，MATH500 82.40 对 59.60），2.6B 在推理密集的基准上接近或超过 8B 的稠密模型，作者称为 2–3 倍参数效率（§5.1）。受控的小实验显示，循环不增加知识容量（循环与否都是每个参数约 2 bit），而是让模型更会组合已有知识（§6.1）。

对齐了什么。只对齐了参数。逐项数，1.4B 对 Qwen3-4B 是 12 项里赢 4 项、输 8 项，对参数最接近的 Qwen3-1.7B 则 12 项全赢；每个 token 的计算比 Qwen3-4B 多约 25%，默认 KV 缓存是同参数稠密模型的 4 倍；训练数据里后期混入了 SFT 风格的数据，MATH500 的巨大优势可能部分来自数据（§5.6）。把账对齐的研究给出了另一面：Ouro 自己的附录 D 在同前向计算下比较，不共享权重的标准模型在所有设置下都更好（§8）；一篇 ICLR 2027 投稿 Closing the Loop 用同样结构在 310B token 上训练了数据完全相同的双胞胎，循环 4 圈在全部 12 项上胜过同参数的稠密双胞胎（GSM8K 高 14 分），但同推理算力的 3.9B 稠密双胞胎在每一项上都领先或持平（数字转引自 Ouro 精读 §5.6，本站未单独精读）。

3.4 推理时多转几圈：收益在训练深度附近见顶

循环模型最吸引人的设想之一，是遇到难题时“多转几圈”。这一阶段的结果显示，这个旋钮多半只在训练见过的圈数以内好用。下图把 Ouro 和后来 ELR 的数字画在一起：两者训练时都最多转 4 圈。

怎么看：横轴是推理时转的圈数，灰底是训练时见过的范围（1–4 圈），纵轴是各自基准的分数。数字取自 Ouro 精读 §5.3（原文表 10–13）和 ELR 精读 §4.2（原文表 6）。所有曲线都在第 3–4 圈附近见顶；超过 4 圈后，Ouro 的选择题平均分缓慢下降，生成式竞赛题掉得很快（2.6B-Thinking 的 OlympiadBench 从 76.44 掉到 39.26）。ELR 第 2 圈涨得最多，第 3 圈已拿到 1→4 圈总涨幅的 96%。本站根据论文数字重画。

其他论文看到的是同一个形状。Parcae 在测试时从 1 圈转到 16 圈，收益在训练时的平均圈数（8 圈）附近就到头（Parcae §7.1）；ARLoop 给超出训练深度的新子层专门训练了查询向量，仍然没有改善（ARLoop §6.2）；MoR 的“测试时扩展”只是在训练过的深度以内逐步放开（MoR §9.3）。Huginn 训练时就见过很深的展开，所以在极深处是稳定的：ARC-C 一直测到 1024 圈，准确率始终在 37.0–37.9 之间，但多出来的计算也不再带来收益（Huginn §5.3）。

这一阶段留下的问题。第一，训练不稳：Huginn 两次失败，Ouro 从 8 圈退回 4 圈，每换一个圈数都要重新试学习率。第二，头条结论全是参数匹配的，“算力对齐后还值多少”没人正面量过。第三，部署的账没算清：KV 缓存翻倍、可变深度难以组批。第四，“只转 1 圈时比同成本的普通模型差一大截”，同一个检查点做不到“着急时少转、难题时多转”。第三阶段的工作逐一回应了这些问题。

三篇论文都说“测试时扩展”，意思并不一样：Huginn 是训练时随机抽圈数，推理时可以任意加；Ouro 是在训练的 4 圈以内选择，外推变差；MoR 是在固定的最大圈数以内逐步放开。不要把它们读成“推理时多算就能一直变好”。

4 另一个世界：小网络递归推理（HRM 与 TRM）

这一节要回答的问题：差不多同一时期，另一批工作在完全不同的设定里用“反复迭代”：没有预训练，只用每类任务约一千个样本，从零训练几百万到几千万参数的小网络，去解极难的数独、大迷宫和 ARC 图形谜题。它们为什么这样设计？分数主要从哪里来？和循环语言模型是什么关系？

当时卡在哪。逐个 token 往外写的大语言模型，在“答案唯一、必须一次全对”的谜题上表现很差：按 TRM 精读引用的数字，DeepSeek R1、Claude 3.7、o3-mini-high 在极难数独和大迷宫上都是 0%。2025 年 6 月的 HRM 换了一条路：一个 27M 参数的小模型，两个子网络以不同频率交替运行，在隐藏状态上反复迭代，报告了数独 55.0%、迷宫 74.5%、ARC-AGI-1 40.3%。它的设计相当复杂：用隐函数定理论证的“一步梯度”、外层的深度监督（同一道题改很多轮、每轮算一次损失）、用 Q 学习训练的停止机制，外加一层“模仿大脑”的解释（TRM 精读 §2）。

第三方复核改变了叙述。ARC Prize 团队复核 HRM 后发现：把“层级”结构换成同参数的普通 Transformer，分数只低约 5 个百分点；真正起作用的是外层的反复修正（从 1 轮加到 2 轮就高 13 个百分点）；而且大部分分数来自训练时就见过评估题的示范样例，只用 400 个评估任务训练，分数也只从 41% 降到 31%（TRM 精读插曲）。也就是说，这类模型本质上是“在每道题自己的示范上做测试时训练”。

TRM 的想法。TRM 把 HRM 剥到最简：只有一个 2 层的网络，维护两个状态，答案 \(y\) 和推理草稿 \(z\)。先用 \(z\leftarrow f(x+y+z)\) 改写草稿 6 次，再用 \(y\leftarrow f(y+z)\) 改写答案 1 次，这叫一轮完整递归；一个监督步做 3 轮，前 2 轮不求梯度，最后 1 轮完整反传；同一道题最多做 16 个监督步（§4.0）。影响最大的改动是放弃一步梯度：改回一步梯度，数独准确率从 87.4% 掉到 56.5%（§4.1）。

怎么看：左边是 HRM，右边是 TRM，每一行从内到外是一层循环。TRM 把两个网络合成一个，把“层级”换成“答案和草稿”两个状态，把一步梯度换成对一整轮递归的完整反传。两者都保留了最外层的深度监督，而 ARC Prize 的复核表明这层外循环是分数的主要来源。本站示意图，依据 TRM 精读 §4.0 与 §2。

结果。TRM 把数独从 55.0% 提到 87.4%，迷宫从 74.5% 提到 85.3%，ARC-AGI-1 从 40.3% 提到 44.6%，ARC-AGI-2 从 5.0% 提到 7.8%，参数只有 HRM 的四分之一左右。ARC Prize 按官方代码在不公开的半私有集上复核，得到 ARC-AGI-1 40%、ARC-AGI-2 6.2%，降幅比 HRM 小（HRM 复核为 32% 和 2%）。论文获得了 ARC Prize 2025 的论文奖第一名。

份量。TRM 对 HRM 的提升有同一份代码下的消融支撑，并经过了半私有集复核，是可信的。但“7M 参数打败千亿大模型”比较的是完全不同的东西（§5.4）：每个基准单独训练一个模型；“7M”没有算上题目编号嵌入表，按复核检查点推算，ARC-AGI-1 上这张表约有 4.5 亿个可学习的数，相当于“每道题的解法存储”；每个测试输入要跑 1000 个变体再投票；大模型是零样本作答，分数来自半私有集，TRM 的是公开集。参数少也不等于计算少：TRM 每个监督步调用 21 次 2 层网络，计算约是 HRM 的 1.75 倍（推算）。

和循环语言模型的关系。TRM 能迁移到语言模型上的是几个想法：对整轮递归做完整反传，而不是一步梯度或截断；把“答案”和“草稿”分成两个状态；训练时就让模型反复修正。它的数字不能迁移：TRM 一次输出一个确定的网格，靠题目编号而不是上下文学习知道该做什么，“2 层比 4 层好”是在约一千个样本、极易过拟合的条件下得出的，这些都和语言模型预训练相反（§5.5）。

“直接预测、不用思维链”说的是推理时的形式，不等于测试时没花训练算力：要解一道新的 ARC 题，这类模型必须先把这道题的示范样例放进训练集重新训练一遍。

5 训得稳、调得动、算得清：稳定性、参数化与扩展律

这一节要回答的问题：2026 年的一批工作分别回应第二阶段留下的问题。训练为什么会发散，怎样从结构上避免？换一个圈数为什么要重扫学习率？后面几圈算出来的东西，残差流能不能挑着用？最低一档（只转 1 圈）能不能不吃亏？最重要的是：在不同的对齐方式下，循环到底值多少？

5.1 为什么会发散：把循环看成动力系统（Parcae）

先补一点背景：线性迭代什么时候会爆炸。

考虑一个最简单的迭代 \(h_{t+1}=\bar a\,h_t+\bar b\,e\)，其中 \(e\) 每一步都是同一个输入。解出来是 \(h_t=\bar a^{\,t}h_0+(1+\bar a+\cdots+\bar a^{\,t-1})\bar b\,e\)。如果 \(|\bar a|<1\)，第一项随圈数衰减，第二项是收敛的几何级数，状态停在一个只由输入决定的不动点 \(\bar b\,e/(1-\bar a)\)；如果 \(\bar a=1\)，常数输入一圈圈累积；如果 \(|\bar a|>1\)，状态按指数增长。代个数（推算）：\(\bar a=1.1\) 时，转 24 圈后初始状态被放大约 9.8 倍；\(\bar a=0.9\) 时，初始状态只剩约 8%，状态收敛到 \(10\,\bar b\,e\)。对矩阵来说，决定这件事的是绝对值最大的特征值，叫谱半径。

Parcae 把循环块的更新恒等地改写成“线性部分 + 非线性部分”：\(h_{t+1}=\bar A h_t+\bar B e+\bar{\mathcal R}(h_t,e)\)，线性部分里的 \(\bar A\) 正是注入方式决定的那个矩阵。相加注入的 \(\bar A=I\)，谱半径恰好是 1，属于临界情形；Huginn 的拼接注入让 \(\bar A\) 成为一个完全自由的矩阵，谱半径可以涨到 1 以上；而作者实测发现，发散的训练确实学出了大于 1 的谱半径（§3.2）。修补办法借用了状态空间模型的离散化：令 \(\bar A=\exp(\Delta\odot A)\)，\(A\) 是对角元全为负的对角矩阵、\(\Delta\) 为正，于是 \(\bar A\) 的每个对角元都严格落在 0 和 1 之间，不稳定的区域根本到达不了（§4.1）。1.3B 模型后来又在前奏输出上加了一层归一化，因为那次爆炸来自前奏输出本身变成了天文数字。和 Huginn 式的循环模型在参数、数据都对齐时比，Parcae 在 100M、350M 上把验证困惑度降低 4.5% 和 6.2%。

5.2 为什么换个圈数就要重扫学习率（Loop-μP）

Loop-μP（ICLR 2027 匿名投稿）给出的解释很直观。若干个互不相同的层往残差流里加的增量，方向几乎互不相关，加起来像随机游走，总量按层数的平方根增长，所以已有的 Depth-μP 规则给每个残差分支乘 \(1/\sqrt L\) 就够了。而循环的每一圈用的是同一套权重，各圈加进去的增量方向相近，加起来像沿直线走，总量按圈数 \(N\) 增长。于是 \(L\) 层循环 \(N\) 圈时，残差分支应乘 \(a/(N\sqrt L)\)，学习率则不必随 \(N\) 改变（§4.1）。如果把循环当成 \(NL\) 层的普通加深，系数会大 \(\sqrt N\) 倍，\(N=8\) 时一步更新已经是应有大小的 2.83 倍（推算）。实验在 4.4 亿参数以内、每个模型 100 亿 token：Loop-μP 下，循环 1–8 次、执行深度最多 384 层的所有组合，最优基础学习率都是同一个值 \(1.25\times10^{-3}\)；不缩放时最优值漂到 \(7.5\times10^{-4}\)，较大的学习率直接发散（§6.2）。一篇公开的 arXiv 论文（2606.18524）研究了同一个问题、结论方向一致（§10 有内容对照）。证据的边界是：单种子、只看验证损失、规模不超过 4.4 亿参数，而且它本身不回答“循环值不值”。

5.3 后面几圈算的东西，能不能挑着用（ARLoop）

标准的 PreNorm 残差把所有子层的输出以系数 1 加到同一条流上。循环越多，加进去的东西越多，后面的子层没有办法说“我只要上一圈某一段的结果”。ARLoop（ICLR 2027 匿名投稿）借用 2026 年提出的注意力残差：每个子层用自己的查询向量，对前面各段的输出做一次 softmax 注意力，按需取用；并且发现循环模型只看最近 3 段输出加原始词向量就够，看全部历史反而略差（§3）。在 140M、370M、循环 1–5 次的受控实验里，它在每一列都最低，但和最强的对照（Parcae 加输入注入）只差 0.12–0.17 的困惑度，约 1%（§4.3）；在 0.6B、同配方的对比里，GSM8K 高 5.2、MATH 高 5.4，代码题的提升落在抽样误差以内（§5.2）。它的附录也给了一个对循环不利的数字：同样的有效深度下，不循环的 24 层模型要好得多（§5.4）。

5.4 最低一档不能吃亏：“单圈税”（ELR）

“同一个检查点，着急时转 1 圈、难题时转 4 圈”这个卖点，取决于最低一档的质量。ELR（ICLR 2027 匿名投稿）把“只转 1 圈时比同成本普通模型差”的差距叫作单圈税：Huginn 训练到 800B token 后只转 1 圈，ARC-Easy 是 34.89，而只训练了 180B token 的不循环双胞胎是 46.42；Parcae 140M 只转 1 圈时困惑度约 27，同尺寸 Transformer 是 21.48（读图值，见 Parcae §5.5）。ELR 的配方有两个关键选择：每一圈只沿“循环块提议的修改”走一个由门控决定的步长（初始约 0.05），而不是直接替换状态；在同一次参数更新里混合多种圈数，强制约 10% 的数据并行进程只转 1 圈（§3.2）。结果是 4B 模型（1T token）转 1 圈的十项平均 65.13，基线 65.65；转 4 圈 72.38，比基线高 6.7 分；30B-A3B 模型转 1 圈 66.08，略高于基线的 65.04（§4.2）。代价是训练算力约 1.16 倍，转 4 圈时首 token 延迟是 2.33 倍；论文没有把多圈的结果和同样推理成本的更大模型比较，这是它有意留下的空白（§4.5）。

怎么看：三列是三条扩展律，每列第一格写它固定了什么、让什么随圈数变化，第二格是它要回答的问题，第三格是答案。三者回答的是三个不同的问题，结论并不冲突：固定参数时循环是“花更多算力换更低损失”的一条路；固定算力时，循环在稠密模型里要用参数去换，换不回来；只有在 MoE 里把参数补回来，才看到一个小的净收益。本站示意图，依据 Parcae §6、Iso-Depth §2、SMELT §3.2。

Parcae 的扩展律（固定参数）。在 140M 和 370M 两个尺寸上固定参数和训练算力、扫描平均圈数，最优圈数按 \(C^{0.40}\)、最优数据量按 \(C^{0.78}\) 随算力增长：算力扩大 10 倍时，最优圈数约扩大 2.5 倍，数据约扩大 6 倍（推算）。和参数相同但不循环、把算力全用来看数据的模型比，预算较大时循环更好（Core 高 1.2–2.0 分），预算较小时不循环反而更好（§6.4）。它回答的是“权重内存固定时算力怎么花”，不回答“同样的算力，循环和更大的普通模型谁好”。

Iso-Depth 的汇率 \(\varphi\)（固定深度）。Iso-Depth 让四种模型（循环 \(r=1,2,4,8\) 圈）每个 token 都恰好执行 20 层：同宽度时，四者的训练算力、推理算力和 KV 缓存几乎相同，唯一的区别是共享越多、独立参数越少。作者在 6 个算力预算上训练了 116 个模型，拟合出一条把圈数写进去的扩展律，参数项写成 \(N_{\text{once}}+r^{\varphi}N_{\text{rec}}\)：只用一次的前奏、尾声参数照常计，循环块的参数乘上 \(r^{\varphi}\)。拟合得到 \(\varphi=0.46\)，95% 置信区间 0.41–0.53（§4.3）。

这个数该怎么读？\(\varphi=1\) 表示循环一圈和一组独立的层一样值钱；\(\varphi=0\) 表示多转几圈完全没用；0.46 表示 \(r\) 圈合起来只值 \(r^{0.46}\) 块：2 圈约 1.38 块，4 圈约 1.89 块，8 圈约 2.60 块，而它们分别花了 2、4、8 块的计算。换成模型大小（§3.3）：一个循环 4 圈、独立参数 410M 的模型，用同样多的 token 训练，损失和一个 580M 的普通模型相当，训练成本却和一个 1B 的普通模型一样；反过来说，要达到同样的损失，循环模型要多付约 1.8 倍的训练算力，换来的是权重内存只占 41%。注意 \(\varphi\) 不是“每一圈值 0.46 块”，它是一个指数，边际收益随圈数递减。

怎么看：每组四根柱子对应一个圈数 r。灰柱是这 r 圈花掉的计算，折合 r 块独立的层；三根彩柱是按不同训练配方测得的 \(\varphi\) 算出的 \(r^{\varphi}\)，也就是这 r 圈实际“值”几块；每组右侧的紫色菱形是理论投稿“循环能替代多少参数”在它的逼近论模型里得到的 \(r^{1/2}\)（只代表阶，常数未定）。\(\varphi\) 取自 Iso-Depth §4.3 和 §5.1–5.2，柱高按两位小数推算；理论对照见 该页 §7.4。本站根据定义重画。

Iso-Depth 还把 \(\varphi\) 当作诊断工具（§5）。截断反传让所有运行的验证损失都下降了，看上去是好方法，但 \(\varphi\) 从 0.46 降到 0.38：省下约 30% 的训练计算，换成了约 31.5% 更多的 token，循环本身却训得更差了，最优模型也变得更宽、推理更贵。超连接则把 \(\varphi\) 提到 0.65，最优模型变窄，是真正的结构改进。光看验证损失分不出这两种情况。它的边界也要记住：最大的对照实验约 11 亿参数、470 亿 token；只有一种配方（前奏 2 层、尾声 2 层、有效深度 20、FineWeb-Edu）；下游评测里，知识类任务跟着损失走，推理类任务在这个规模上分辨不出架构差异（§6.1）；而且没有公开代码，尚无独立复现。

SMELT：三项一起对齐（MoE）。SMELT 对 Iso-Depth 提出一个批评：固定计算量时，循环模型被迫少存了参数，所以它测到的落后，可能反映的是“参数变少”，而不是循环本身不好。SMELT 用 MoE 把三项预算同时对齐：循环多花的计算，靠把模型收窄来抵消；收窄损失的参数，靠增加专家数量补回来（专家多了，存的参数多，但每个 token 仍只用其中几个）；多出来的 KV 缓存，靠更小的注意力头和更高的分组比例压回去。对齐误差是计算 3.9% 以内、总参数 1% 以内、KV 缓存 4% 以内。三组消融定下的配方是：只循环中间一半的层，循环两遍（三遍、四遍都更差，因为预算封顶后每多一遍都要用更窄的模型换，见 §3.5）。在 100M 到 1.6B 激活参数（最大总参数约 54B）的网格上，SMELT 每一格的损失都更低；按分别拟合的扩展律，在 \(10^{20}\) FLOPs 处省 6.8–10.0% 的训练算力，在 \(10^{21}\) 处省 14.7–18.0%（§4.3）。

这个结果要配着两句话读。第一，收益是真实但很小的：按论文自己的系数推算，\(10^{21}\) FLOPs 处 14.7% 的算力节省，对应前沿上约 0.01 nats 的损失差，和拟合误差同一个量级；之所以“看起来”有 15%，是因为前沿在对数算力坐标上越来越平，同样 0.01 nats 的差距要多花很多算力才能追上。第二，它没有推翻 Iso-Depth：在稠密模型里，“计算相同”就意味着“参数更少”，这是结构的事实，不是实验设计的瑕疵；SMELT 的结论只适用于 MoE（§5.4）。SMELT 精读页还提到另一项 MoE 研究：当不循环的 MoE 对手多存了约一倍参数时，循环的 MoE 在损失上仍然不如它。参数是否对齐，会直接翻转结论。

5.6 理论能说什么：存储与调用的乘积（循环能替代多少参数）

这篇纯理论投稿（ICLR 2027 匿名）用逼近论问同一个问题：用 \(J\) 个固定大小的 ReLU 模块、总共调用 \(T\) 次，最好能把 \(d\) 维的 Lipschitz 函数逼近到什么程度？主定理说，最坏情况的误差恰好是 \((JT)^{-1/d}\) 的阶，上下界相同（§4.1）。所以在这个模型里，存储和计算以乘积的形式决定精度：模块少一半，调用多一倍，误差的阶不变。但如果固定调用次数（也就是固定计算），共享参数会让误差多出 \((T/J)^{1/d}\) 倍（§4.3），这正是“循环的好处只在参数量固定时出现”的理论版本。它还证明调用顺序有讲究：先把大部分调用花在少数几个模块上、很晚才见到后面的模块，就保不住这条前沿（§5.3）。

精读页做了一个有趣的换算（推算）：在这个理论模型里，全部模块参与循环时，循环 \(r\) 次在阶的意义上相当于 \(r^{1/2}\) 倍的独立模块，也就是 \(\varphi=1/2\)，恰好落在 Iso-Depth 的置信区间里。但这只能算一个巧合：理论衡量的是最坏函数的一致误差，Iso-Depth 是语言模型的平均损失；理论的 1/2 依赖极高精度的权重和随目标跳跃的取值；经验的 \(\varphi\) 随配方在 0.38 到 0.65 之间变动，已经超过 1/2。理论常数也很大：按附录的显式常数推算，\(d=2\) 时 \(JT\) 要超过约 \(2.7\times10^4\)，上界才开始提供信息（§7.4）。

“Parcae 说循环有用、Iso-Depth 说循环吃亏、SMELT 说循环省算力”并不是三个互相矛盾的结论，而是三个不同问题的答案：分别固定了参数、执行深度和全部三项预算。引用其中任何一个数时，都要连同它固定的东西一起引用。

6 循环 × 扩散语言模型：一步之内多算，还是步与步之间多传

这一节要回答的问题：扩散语言模型本来就要把同一个网络调用几十到上千次，它为什么还需要“循环”？本类里同时属于“扩散 LLM”分类的五篇论文，“循环”分别指什么？各自多花了哪本账，换来了什么？
先补一点背景：掩码扩散语言模型怎样生成文字。

掩码扩散模型先摆出一张长度固定、全是 [MASK] 的“画布”，然后分很多步：每一步把整张画布送进一个双向 Transformer，网络为每个被遮住的位置给出一个词表上的分布，再挑一部分位置“提交”成具体的词，其余留到下一步。步数越多，每步同时提交的位置越少，“各自独立地猜”造成的冲突越少，质量越好，但前向次数（NFE）也越多。从零训练这类模型的代表是 MDLM；另一条路线是把现成的自回归模型改造成“块扩散”，块与块之间从左往右写，块内并行去噪，见 Block Diffusion、SDAR、Fast-dLLM v2 的精读。

6.1 两种“循环”

在扩散语言模型里，“循环”有两种完全不同的意思（五篇精读的开头都专门做了区分，例如 LoopMDM §1.1、Loopholing）。第一种是深度方向的循环：在一个去噪步之内，把同一组层反复算几遍再输出这一步的预测，步与步之间仍然只传离散的 token。打个比方，这是“同一盘棋多想几遍再落子”。它的代价很直接：每一步的计算变成约 \(S\) 倍，而生成要走很多步，整段生成的计算也乘上 \(S\)。LoopMDM、R-MDM、ALoDLM 属于这一种，Loop-Distill 也是，但它的循环只发生在训练时。第二种是跨去噪步的循环：每一步网络只算一遍，但把这一步采样之前的连续状态带到下一步，相当于“把上一步的思路笔记带进下一步”，几乎不增加推理计算。Loopholing 属于这一种。

示意图：扩散语言模型里的三种“循环”，代价落在不同的账上
怎么看：三栏是三种做法。左栏在一个去噪步之内把循环块算 S 遍，步与步之间只传离散 token，所以推理的每一步都更贵。中栏每步只算一遍，实线是采样出的 token（每个位置只剩一个词），虚线是绕过采样、直接交给下一步的连续隐状态。右栏的循环只存在于训练时的教师支路里，部署的模型和原来完全一样。最下面一行写的是代价落在哪本账上。本站示意图，依据各精读页的“两种循环”小节。

为什么一步之内的循环会有用？R-MDM 给出了这一支最清楚的框架。并行解码的误差可以精确拆成两块：一块是“同时提交的几个位置彼此相关、却被独立采样”造成的依赖误差，它只由“每步提交哪些位置”决定，循环再多也动不了它，只有少提交、多走步才能降低；另一块是模型的每个位置的分布偏离真实分布造成的保真误差，循环恰好能降低它。步数少时每步提交很多位置，保真误差被放大，循环特别有用；步数多时循环的空间就小了。

6.2 Loopholing：在“采样墙”上开一条通路（跨步）

当时卡在哪。离散扩散的每一步，网络算出的是很丰富的东西：每个位置一个完整的分布，还有最后一层的隐藏向量；可一旦采样，留在画布上的只有一个词，下一步只能从这个词重新推断。Loopholing 把这个现象叫作采样墙。

核心想法。每一步照常采样，同时把网络最后一层的隐状态原样交给下一步，和下一步的词嵌入加在一起。训练时不展开整条生成链，而是借用自条件化：在同一张带噪画布上先算一遍（输入的隐状态为零、不求梯度），把得到的隐状态当作“上一步传来的”再算第二遍，只对第二遍求损失（§3.3）。训练时间因此多约 30%，推理几乎不多花。

结果与份量。在 1.69 亿参数、OWT 上训练的模型上，生成 1024 个 token、走 1024 步时，生成困惑度从 MDLM 的 108.94 降到 49.13；均匀态版本从 73.95 降到 28.76，低于自回归基线的 34.40，但熵也略低（§6.3）。和基线的比较对齐了骨干、参数、数据和训练步数，比较干净；但步数很少时优势会反转：32 步时 LDDM-M 是 248.02，反而比 MDLM 的 198.72 差。精读页的一个读法是：基线多走的步数大多是画布一个词都没变的“空转步”，Loopholing 把这些步变成了跨步累积的计算。它被 ICLR 2026 接收，代码公开，但规模只到 4.24 亿参数（§6.7）。

6.3 LoopMDM：只循环靠前的两层（一步之内）

核心想法。在 12 层、1.7 亿参数的掩码扩散模型里，只把第 1、2 层反复过 \(S\) 遍，训练时每一步随机抽 1 到 12 圈（§3.1）。作者让它和同尺寸的 MDM 总训练 FLOPs 相同，所以 LoopMDM 每步更贵、步数更少，只看了约一半的数据（§3.4）。

头条结果。评测时转 6 圈以上，LoopMDM 在三个语料上达到基线最终 NLL 所需的训练 FLOPs 少 2.34–3.34 倍（§4.2）；在 TinyGSM 上训练的 1.25 亿参数数学模型，转 16 圈时 GSM8K 比 14 层基线高 8.5 个点，比每步训练 FLOPs 相同的 21 层基线高 3.4 个点（§5）。

按推理算力重新对齐。这些比较都对齐了训练算力，却没有对齐推理算力：评测时每个去噪步要过 22 到 58 层次，是基线的 1.8 到 4.8 倍。精读页把生成困惑度换算到“生成一个样本要过多少层次”上（下图），结论变成：同样的推理计算，拿去让不循环的 MDM 多走去噪步，通常比拿去多转几圈更划算（§4.3）。在 GSM8K 上，每次前向计算最接近的一对（转 4 圈的 20 层次对 21 层基线）大致打平。

怎么看：每条线是一种模型，线上的五个点从左到右依次是 64、128、256、512、1024 个去噪步。横坐标把“步数 × 每步要过的层数”算成生成一个样本的总计算（只数 Transformer 层，推算），纵坐标是论文报告的生成困惑度（原文表 1，越低越好）。如果只比同一个步数，橙线总在灰线下方，这是论文的读法；按横坐标对齐以后，灰线在大部分范围内更低，也就是把推理计算花在“多走几步去噪”上更划算。本站根据 LoopMDM 精读 §4.3 的数字重画；转 1 圈的曲线和灰线几乎重合，未画出。

6.4 R-MDM：把循环当作扩散模型的第三条扩展轴

R-MDM 在每个去噪步里把整个共享块循环 \(L\) 遍，并系统地比了三种对齐（§4.5）。同参数时，循环越多越好、步数越少越明显：数独只走 5 步时，基线 65.2%，循环 5 遍 93.6%（§4.1）。同 FLOPs 时（循环 \(L\) 遍的 \(K\) 层块对不循环的 \(KL\) 层模型，每次前向计算、步数和训练步数都相同），数独上循环模型几乎全面占优，Countdown 上步数少时深的普通模型反而更好（Countdown-4 走 10 步：43.6% 对 58.0%），而且深层基线没有单独调参（§4.2）。同前向次数时，10 次前向下普通模型走 10 步是 85.0%，循环模型一步循环 10 遍是 94.2%，但这个循环模型用了课程训练，训练算力约是普通模型的 5.5 倍（推算，§4.3）。在 6.1 节的误差分解基础上，作者用熵同时决定“这一步再循环一遍”还是“提交哪些位置”（§7.3）。模型从 550 万到 1.61 亿参数，任务全是有明确约束的填空，没有开放式文本生成，也没有和自回归模型比较（§8.2）。

6.5 ALoDLM：一步之内按位置自适应地循环

ALoDLM 把 Qwen3 中间的一段层做成循环核心（8B 版本是第 10–25 层），每一步去噪里最多跑 4 遍：每跑一遍就读出一次预测，有把握的位置立刻提交、变成普通 token 给别人当上下文，没把握的位置保留自己的隐藏状态进入下一遍，一个退出门决定这一步什么时候停；训练时把“每个位置在第几遍提交”当作隐变量（§3.1）。只做了 5B token 的监督微调，1.7B 和 8B 两个规模在 11 项基准上的平均分都高于所评测的扩散模型和对应的 Qwen3（65.5 对 63.8，80.3 对 78.5）；单请求时，GSM8K 上比 vLLM 上的 Qwen3-8B 快约 2.67 倍（612.4 对 229.3 token/s，§5.3）。

精读页的掂量是（§5.6）：质量表用的是“一遍提交一个 token、从左到右”的解码，而 2.7 倍速度用的是并行提交，两者不是同一个设置；对 Qwen3 的 1.7–1.8 分优势落在评测流程本身的摆动范围之内（同一对模型 WeDLM-8B 和 Qwen3-8B 的先后顺序，在两套评测流程下会翻过来）；速度只在批大小为 1、只有 GSM8K 时测过，每个 token 的算术量约是自回归模型的 5–9 倍、KV 缓存是 2.33 倍（推算），高并发时谁快没有测；最关键的“同数据、不循环”对照缺失。代码和权重都已公开，这一点比同批多数工作好。

6.6 Loop-Distill：只在训练时循环，推理成本不变

Loop-Distill（ICLR 2027 匿名投稿）研究的是从自回归模型改造来的块扩散模型。作者发现，[MASK] 位置的隐藏状态在第 1 层被大幅改写（相对变化平均 69%），之后几层几乎不动（第 2 层只变 0.74%），像是“过早定型”。办法是训练时用同一套权重临时搭一个教师：把 2–3 个浅层各连续算 2–3 遍，不求梯度；只在教师的损失确实更低时，让学生在这几层、只在 [MASK] 位置上朝教师靠（§4.1）。部署的模型结构、参数、每次前向的计算和 KV 缓存都与原来相同（§4.4）。在两个 30B-A3B 模型、13 个评测上，平均分高约 2 分（GLM 2.05、Qwen 2.21），批大小为 1 时吞吐高约 11%（§7）。没对齐的是训练：每步多一次不求梯度的前向，墙钟多约 10%，论文没有给“把这 10% 拿去多训对照组”的比较；块长 32 仍比块长 4 低约 10 分，大块并行的质量损失主要还在（§10）。

这一支的共同信号。一步之内的深度循环让每一步更贵；一旦按推理算力对齐，收益要么大体消失（LoopMDM），要么需要额外的训练算力才能换来（R-MDM 的课程模型）。跨步传状态（Loopholing）和只在训练时循环（Loop-Distill）不增加推理成本，所以在推理这本账上更“干净”，但前者规模很小、在极少步数时反转，后者没有对齐训练成本。两类做法并不互斥，至今没有工作把它们叠加起来。

在扩散模型里比较“同样的去噪步数”，并不等于比较“同样的推理计算”：一步之内循环 \(S\) 遍的模型，每一步都比基线贵约 \(S\) 倍。看到“步数受限时循环特别有用”，要先问推理算力是否也对齐了。

扩散一支的五篇，正好把代价放在了不同的账上：Loopholing 和 Loop-Distill 把代价放在训练上，推理不变；LoopMDM、R-MDM、ALoDLM 把代价放在推理的每一步上。前者的头条结论更容易在部署中兑现，后者的头条结论更需要按推理算力重新对齐来读。ALoDLM 的速度优势建立在“单请求时 GPU 算力闲置”之上：此时一次前向同时定下多个 token，就能突破自回归逐 token 读参数的上限；批大小一大，“每个 token 多算几倍”就会实打实地变成更慢。

8 结果的份量（跨论文）

这一节要回答的问题：这一类论文的头条数字常常不能直接拿来比。哪些“比较方式上的问题”反复出现？每一种在本类精读里有哪些具体例子？综合起来，哪些结论站得住，哪些要打折扣？

8.1 参数匹配被读成了算力匹配

这是本类最常见的问题，几乎每一篇规模化工作都有。UT 的 +0.9 BLEU 是参数对齐、计算约 4 倍；Huginn 的“相当于 50B 的计算量”说的是计算规模；Ouro 的“2–3 倍参数效率”在每 token 计算上反而多 25%、KV 缓存 4 倍。最值得细看的是 Parcae 的“87.5%”（Parcae §5.4）。它的算法是：770M 的 Parcae 在 Core 上是 25.07，同参数的 770M Transformer 是 22.42，大一号的 1.3B Transformer 是 25.45，于是 \((25.07-22.42)/(25.45-22.42)\approx87.5\%\)，意思是“770M 的 Parcae 把从 770M 走到 1.3B 的那段路走了 87.5%”。这个数有三处要读准：它是“填补差距的比例”，不是“分数的比例”（分数之比是 98.5%）；它只在 Core 上成立，同一对模型在 Core-Extended 上只填补了 58.2%，验证困惑度上 770M Parcae（12.49）还不如 1.3B Transformer（11.95）；它也不省推理算力：770M Parcae 的训练算力约是 1.3B Transformer 的 0.75 倍（它只训练了 61.6B token，后者 104B），但推理时每个 token 的计算约 1.74 倍、KV 缓存约 2.08 倍（推算，§5.5）。所以 87.5% 说的是：花更多的推理计算，省下权重显存，换到了接近大一号模型的 Core 分数。

ARLoop 说 1.3B 模型和 Qwen3.5-2B “有竞争力”，也是同类情况：参数相近，训练算力约是后者的 1/29，推理时每个 token 的计算约是它的两倍（推算，ARLoop §5.2）。

8.2 算力对齐之后，循环还剩多少

读法可以归结为一句话：循环本质上是“用计算换内存”，汇率在稠密模型里大约是 \(r\) 份计算换 \(r^{0.46}\) 份参数。所以在参数固定时它几乎总是赢（花了更多算力），在算力固定时它多半打平或输（被迫少存了参数），只有在 MoE 里把参数补回来以后，才剩下一个约 0.01 nats 的小净收益。几处细节值得记住。其一，潜在思考在 1B 规模上测得“循环得来的深度只值新层的 0.5–0.6 倍”，和 Iso-Depth 的 \(\varphi\) 方向一致，尽管两者的量法不同。其二，\(\varphi\) 随配方变化（0.38 到 0.65），所以“循环值多少”不是一个常数，而是可以被训练方法和结构改进推高的量；超连接把它推到 0.65，已经明显高于基线。其三，扩散一支里 LoopMDM 的 GSM8K 实验在每次前向计算相同时打平，说明“一圈约值一层”在个别程序化任务上可能成立，但这只是一组目测读数，不是扩展律（LoopMDM §5）。

8.3 “推理时多转几圈”多半只在训练深度以内有效

§3.4 的图已经说明：Ouro 超过 4 圈后生成式竞赛题大幅下降，Parcae 在训练均值附近饱和，ARLoop 外推无用，MoR 只在训练深度以内放开，ELR 第 3 圈就拿到了 96% 的收益。Huginn 是一个例外，它在训练时就见过很深的展开，所以极深处稳定，但 64 圈以后也不再提高；扩散一支的 LoopMDM 转 24 圈（超过训练最大 12 圈）仍略好于 12 圈，是少数“外推还有一点用”的例子（LoopMDM §4.2）。所以“循环深度是第三条扩展轴”这句话，目前更准确的说法是：它是一条在训练时就要定下来的轴，推理时能调的只是训练范围以内的档位。

8.4 只转 1 圈的分数，常常是在分布外测的

Huginn 训练时抽到 1 圈的概率约十万分之一，所以“只转 1 圈时几乎不会做题、训练后期也不进步”既可能说明能力都在循环里，也可能只是模型从没学过 1 圈时怎样输出（Huginn §5.3）。Parcae 只转 1 圈时比同尺寸 Transformer 差得多。ELR 证明这个“单圈税”可以用训练配方去掉，但它的消融也显示，一部分功劳来自门控结构本身让 1 圈的模型变好了：同样带门、只在 1 圈下训练的小模型，损失比无门基线低 0.025，而混合圈数训练的 ELR 在 1 圈时只是和无门基线持平（ELR §4.5）。

8.5 数据与评测流程把架构效果混了进去

Ouro 的基座模型在预训练后期就读过 SFT 风格的数据，MATH500 这类“写步骤再按格式给答案”的评测对它天然有利；同样结构在 310B token 上训练的版本，MATH500 只有约 63，而 Ouro-1.4B 是 82.4，说明高分大部分来自训练量和数据，不是循环结构本身（Ouro §5.6）。Huginn 的数据约四分之一是代码，它在数学、代码上对 OLMo-2-32B 中间检查点的领先，分不清有多少来自循环（Huginn §5.5）。ARLoop 的第三阶段专门加入了数学和代码推理数据（ARLoop §5.2）。ALoDLM 的例子说明评测流程本身就能带来几分的摆动。TRM 的例子最极端：两组数字甚至不在同一个评估集上，而且一边在评估题的示范上训练过、对每个输入投票 1000 次，另一边是零样本。

8.6 规模、随机种子和自家基线

本类绝大多数实验每个配置只训练一次，没有种子方差。规模普遍不大：Iso-Depth 最大的对照约 11 亿参数、470 亿 token；Loop-μP 不超过 4.4 亿参数；Parcae 到 1.3B；SMELT 拟合用到的累计训练算力最多 \(2.2\times10^{21}\) FLOPs，而 DeepSeek-V3 粗算约 \(3\times10^{24}\) FLOPs，差了三个数量级（推算，SMELT §5.4）。基线几乎都是作者用同一套代码自己训练的，这让流程一致，但也意味着基线没有为各自的结构单独调参：R-MDM 的深层普通模型“越深越好”并不单调（R-MDM §4.2）；反过来，SMELT 的基线是一个为它自己调好的 MoE 模型族，这对基线有利。SMELT 的模型、数据和训练框架都是专有的，Iso-Depth 和 LoopMDM 没有公开代码，五篇 ICLR 2027 匿名投稿的数字都可能在修改稿中变化。开放程度最好的是 Huginn（权重、代码、全部数据）、Parcae（代码与四个尺寸的权重）、Ouro（权重）、Loopholing、TRM 和 ALoDLM（代码与权重）。

8.7 扩散里的“同步数”与“单请求速度”

扩散一支的比较有两个特有的陷阱。第一个是只比同样的去噪步数，而一步之内循环的模型每步更贵：LoopMDM 按推理算力对齐后结论反过来（§6.3），Loopholing 在 32 步时反而更差（Loopholing §6.3），R-MDM 的“同前向次数更好”背后是约 5.5 倍的训练算力。第二个是速度只在批大小为 1 时测：ALoDLM 的 2.67 倍和 Loop-Distill 的 11% 都是单请求数字，而且 ALoDLM 的工作点是在测试集上从 94 组设置里挑出来的，对手只扫了 21 组（ALoDLM §5.3）。

8.8 理论结论只说“存在”

本类三篇偏理论的工作都是表达能力或逼近论的结论：可编程计算机证明存在执行程序的权重，但精度要求随轮数上升，也不说明训练能学到（§9.4）；潜在思考证明 \(T\) 次循环能模拟 \(T\) 步思维链，但构造的计算量约是思维链的 \(m\) 倍；“循环能替代多少参数”的最优速率藏着很大的常数，而且建立在无限精度的实数参数上。它们给出的是“循环在原理上能做什么”的边界，不是“训练出来的循环模型实际在做什么”。Huginn 的探针检验也提醒我们，“潜在思考”目前还只是一种解释，没有在训练好的模型里被逐步读出来。

比较稳妥的总结：循环确实能用更少的参数换到更深的计算，在显存受限的场景里是有用的工具；在算力对齐的比较里，稠密模型上它目前吃亏，MoE 上有小的净收益；推理时加圈多半只在训练深度以内有效；“循环让模型在潜空间里推理”仍缺少直接证据。

9 还没解决的问题与走向（截至 2026-10）

这一节要回答的问题：截至 2026 年 10 月，这条路线还有哪些问题没有答案？从各精读页“后来怎么样了”一节能看出哪些方向正在推进？

严格对齐下的收益能否放大。目前唯一的三项全对齐证据是 SMELT 在 MoE 上的约 0.01 nats，最大规模的拟合算力比前沿模型小三个数量级，\(10^{22}\) FLOPs 处的数字已经是外推，置信区间下限为 0。稠密模型上，Iso-Depth 的 \(\varphi\) 只在 11 亿参数以内测过。循环在更大规模上是变得更值钱还是更不值钱，没有数据。

把 \(\varphi\) 推高。Iso-Depth 建议今后提出新配方时，在验证损失之外同时报告 \(\Delta\varphi\)，因为只有它能区分“省下算力多看了数据”和“循环本身变强了”（§6.2）。已知能推高它的是循环边界上的超连接（0.65）；ARLoop 的注意力残差、ELR 的门控更新也属于“让每一圈更有用”的改动，但它们没有报告 \(\varphi\)。截断反传会把它拉低，这让训练成本和循环质量之间有一个尚未解决的取舍。

推理系统。KV 缓存按执行深度增长是部署的主要障碍。Ouro 只留最后一圈的缓存在长生成上开始掉分；Ouro 精读提到的一项后续研究（Looped Latent Attention，arXiv 2607.15456，本站未单独精读）认为循环缓存是低秩的，但不能安全地塌缩成一圈（Ouro §5.5）。可变深度难以组批：Iso-Depth 作者的后续论文用“连续深度批处理”在 Ouro 上拿到估计最大加速的 99%，在 Huginn 上是 83%–96%，并发现全循环结构最适合这种调度（Iso-Depth“后来怎么样了”，本站未单独精读）。循环的第二遍必须等第一遍算完，是串行的；SMELT 这类对齐了算术量的论文都没有报告墙钟时间。

测试时外推。没有一篇工作做到“训练时转 4 圈、推理时转 8 圈还继续变好”的稳定外推。ARLoop 的实验说明，更好地取用前面的表示并不能带来外推；Parcae 的结论是训练深度决定了测试时扩展的天花板。这和合成算法任务上观察到的长度外推形成对比，原因还不清楚。

潜在推理是不是推理。Huginn 的探针检验没有读出潜在思维链；Ouro 关于“循环的中间状态比显式思维链更忠实”“有害性随圈数下降”的说法，证据还有限。循环到底是在做多步推理，还是在反复精炼同一个表示，需要更细的可解释性工具。

从现成模型改装。从头预训练循环模型很贵，越来越多的工作从预训练好的普通模型出发：Huginn 精读提到的“改装循环”（Retrofitted Recurrence，2025-11，本站未单独精读）把现成模型的若干层改成循环块，报告从预训练权重初始化在每单位训练算力上好得多（Huginn“后来怎么样了”）；ALoDLM 从 Qwen3 改装，Loop-Distill 在改造的 SFT 阶段加循环教师。这条路便宜，但普遍缺少“同数据、不循环”的对照，收益里有多少来自额外的微调数据，说不清。

循环 × 扩散。深度循环和跨步传状态可以叠加，但还没有工作这样做。R-MDM 的误差分解给出了一个分配原则：保真误差靠循环降，依赖误差靠多走步降，两者可以按熵动态分配。反方向的联系也在建立：Huginn 精读介绍的并行采样器工作（ICML 2026，本站未单独精读）把循环深度模型看成“连续但因果的扩散语言模型”，直接用在 Huginn 上最多带来约 5 倍的加速（Huginn“后来怎么样了”）。

小模型递归推理。TRM 在半私有集上的 ARC-AGI-2 只有 6.2%，而且依赖每题的编号嵌入和大量测试时计算；一份对复核检查点的分析发现，去掉正确的题目编号，准确率直接降到 0，最终准确率的大部分在第一次递归时就已达到。后续工作朝几个方向推进：先在公开任务上预训练、比赛时只做少量微调，把“每道题从零训练”改成“预训练加测试时微调”；在潜在状态里加噪声、并行跑多条轨迹再挑最好的一条；把“隐藏状态收敛到不动点”重新拿回来当作停止信号（TRM“后来怎么样了”，这些工作本站都未单独精读）。这类小网络的递归到底在做多深的推理，仍有争议。

10 阅读路线

这一节要回答的问题：本类 19 篇精读，按什么顺序读最省力？不同兴趣的读者可以从哪里进入？

路线一：入门，先养成算账的习惯（6 篇）。从最早的想法读到最严格的对齐，每读一篇都问“它对齐了什么”。

  1. Universal Transformer：深度循环的起点，§2.4 第一次把“参数和计算是两回事”摆上台面。
  2. 潜在思考：\((k\otimes L)\) 记号、同参数与同算力两种基线，以及“推理与记忆”的分化。
  3. Huginn：第一个从头预训练的大规模循环模型，§5.5 是很好的算账练习。
  4. Ouro：参数匹配的头条结论，以及同数据双胞胎给出的另一面。
  5. Iso-Depth：\(\varphi\) 这个“汇率”，本页大部分折算的依据。
  6. SMELT：三项全对齐怎么做，以及对齐之后还剩多少。

路线二：偏工程，训得稳、调得动、用得上（7 篇）。适合准备自己训练或部署循环模型的读者。

  1. Huginn §4.3：大规模训练的两次失败，问题从哪里暴露出来。
  2. Parcae：用动力系统解释发散，从结构上保证稳定；再读它的扩展律 §6。
  3. Loop-μP：残差分支为什么要乘 \(1/N\)，学习率怎样跨圈数迁移。
  4. ARLoop：残差流里的东西怎样按需取用。
  5. ELR：一个检查点多个档位，最低一档不吃亏。
  6. MoR：按 token 路由深度、按圈缓存 KV、连续深度批处理。
  7. Ouro §5.5：KV 缓存共享在什么时候可行。

路线三：偏前沿，循环 × 扩散语言模型（5 篇，建议先读扩散基础）。先读 MDLM 了解掩码扩散怎样训练和生成，再按下面的顺序读：

  1. Loopholing：跨步传状态，顺便把“两种循环”分清楚。
  2. LoopMDM：一步之内循环，以及按推理算力重新对齐的读法。
  3. R-MDM：依赖误差与保真误差，循环和去噪步各管哪一块。
  4. ALoDLM：从现成模型改装、按位置自适应地循环，以及单请求速度的条件。
  5. Loop-Distill：只在训练时循环、推理成本不变的另一种用法。

对理论感兴趣的读者，可以按 可编程计算机 → 潜在思考 §5 → 循环能替代多少参数 的顺序读，最后回到 Iso-Depth §3.3 对照经验的 \(\varphi\)。对小网络递归推理感兴趣的读者，TRM 一篇就包含了 HRM 的背景和 ARC Prize 的复核。
