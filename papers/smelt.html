0 导读：这篇论文解决什么问题

循环 Transformer（looped Transformer）的想法很简单：不再一层一层地往上堆新的层，而是把同一组层反复执行几遍。这样每个 token 经过的串行计算步数变多了（相当于网络变“深”了），需要存储的参数却没有增加。近两年不少工作报告说，循环之后的小模型能追上大好几倍的普通模型，本站这一类的 Huginn、Ouro、Parcae 都是例子。

问题在于这些比较大多是在“参数量相同”的条件下做的。一个模型把自己的层执行两遍，每个 token 的计算量也就差不多翻了一倍，推理时要存的 KV 缓存也翻了一倍。所以“循环模型更强”里混着一部分“它多花了算力”。反过来，如果固定计算量来比（本站 Iso-Depth 那篇就是这样做的），循环模型就得把自己缩小，存的参数变少，结果循环模型输了；可它输掉的原因，也可能只是参数少了，而不是循环本身不好。

SMELT 这篇论文想把这两种混淆一起去掉：让循环模型和不循环的对手在每个 token 的训练计算量、总参数量和 KV 缓存大小这三项上同时相等，再看循环还有没有好处。稠密模型做不到三项同时相等（第 3 节会算给你看），但混合专家（MoE）模型可以：循环多花的计算，用把模型变窄来抵消；变窄损失的参数，用增加专家数量补回来（专家多了，存的参数多，但每个 token 只用其中几个，计算量不变）；多出来的 KV 缓存，用更小的注意力头和更高的分组比例压回去。作者通过三组消融，定下一个配方，取名 SMELT（Sparse MoE Transformer, middle layers Loop Twice）：把中间一半的层循环两遍，并配上上面这些预算补偿。

主要结果是：在四个规模（以不循环基线的激活参数计为 100M、200M、600M、1.6B，最大的总非嵌入参数约 54B）和四个稀疏度组成的网格上，SMELT 在每一格都比基线的损失低。作者给两种结构分别拟合 Chinchilla 式扩展律，发现 SMELT 的损失随算力下降得更快：在“算力最优前沿”上，达到同样的损失，SMELT 在 \(10^{20}\) FLOPs 处省 6.8–10.0% 的训练算力，在 \(10^{21}\) FLOPs 处省 14.7–18.0%。在下游评测上，SMELT 的优势比“验证损失低了多少”所预测的还大，在代码数据、长样本和上下文示例多的任务上最明显。机制分析发现，循环的第二遍把原本集中在序列开头的“注意力汇”挪到了和内容相关的位置上。

读这篇论文时也要记住它的边界：所有模型、数据和训练代码都是作者内部的，没有公开；每个配置只训练了一次；14.7% 的算力节省对应的损失差大约只有 0.01 nats（本站推算）；\(10^{22}\) FLOPs 处的数字是外推。第 5 节末尾的“结果的份量”会把这些逐条摆出来。

1 引言：参数少不等于成本低

这一节要回答的问题：循环模型常被说成“用一小部分参数换来大模型的能力”，但它付出的计算量和 KV 缓存并没有变少。那么已有的比较到底对齐了什么、漏掉了什么？要干净地回答“循环本身有没有好处”，需要同时固定哪几样东西？为什么作者选择在 MoE 模型上做这件事？
先补一点背景：循环 Transformer 的“物理层数”和“有效深度”。

普通 Transformer 由 \(L\) 个不同的层串起来，每层有自己的一套权重，一个 token 从下往上依次经过每一层，每层各算一次。循环 Transformer 把其中一段连续的层（比如第 4 到第 9 层）当作一个“块”，让 token 在这个块里走两遍或更多遍，每一遍用的是同一套权重（这叫权重共享，weight tying）。

于是有两个“层数”：物理层数是真正存在、需要存储权重的层数；有效深度是一个 token 实际被执行的层数。如果把 \(L\) 层里连续的 \(m\) 层执行 \(r\) 遍，有效深度就是 \(L_{\text{eff}}=L+(r-1)\,m\)。比如 12 层模型把中间 6 层执行两遍，有效深度是 \(12+6=18\)。

训练和推理的计算量看的是有效深度：每执行一层都要做一次矩阵乘法。一个常用的估算是，每个 token 的训练计算量大约是“这次前向传播里实际用到的参数数 × 6”（前向 2 倍、反向 4 倍）。权重被用了两遍，就要按两遍算。

论文开篇举了一个例子：把一个 12 层的模型循环成 24 层来执行，它只存了一半的权重，但每个 token 花的计算量和一个 24 层模型差不多，KV 缓存也和 24 层模型一样多（每执行一层都要存一份那一层的 key 和 value）。这样的模型应该和谁比，结论会完全不同：

已有的评测大多属于上图的“对手 A”：固定存储的参数量，增加循环次数（Huginn、Parcae），或者强调循环模型比更大的不共享模型更省参数（Ouro 等）。在这种比较下，循环模型多花的计算没有被扣除，报告的收益里既有结构上的优势，也有“多算了几遍”的功劳，两者分不开。

属于“对手 B”的代表是 Schwethelm 等人的 Iso-Depth 扩展律（本站 精读页）。他们在稠密模型上固定每 token 的计算量，发现循环 \(r\) 遍只相当于 \(r^{0.46}\) 个不共享的块，循环模型在同等训练算力下输了。但本文指出，固定计算量的同时，循环模型独有的参数也被砍掉了，所以这个“输”可能来自参数变少，而不是循环这种做法本身有缺陷。

要得到干净的答案，作者认为必须同时固定三项预算，每一项管一件实际的事：

  • 每 token 的计算量（FLOPs）：决定训练成本和推理成本。
  • 总参数量：决定模型能记住多少知识。
  • KV 缓存：决定部署时能服务多长的上下文（KV 缓存是什么，见本站 vLLM 精读 §2.2）。

MoE 让这件事变得可行。MoE 的总参数和每 token 计算量是脱钩的：多加几个专家，存的参数变多，但每个 token 只用固定几个专家，计算量不变。于是循环模型可以先把自己变窄来“付”第二遍的计算，再靠增加专家数把变窄损失的参数补回来；KV 缓存则另外通过调整注意力头的大小和分组比例来补平。在这种对齐下，作者用三组消融确定了三条规则：循环中间一半而不是全部的层；让循环模型的“有效深度/宽度”比基线更大；循环两遍而不是三四遍。之后把配方扩展到最大 54B 总参数，并分别拟合扩展律。

读的时候容易误解的地方：
  • 论文里的“100M / 200M / 600M / 1.6B”是基线的激活参数，用来给每一档规模起名字。同一档的 SMELT 更窄，每走一遍物理层只用到约 2/3 的参数（比如 1.6B 那一档是 1.10B），但因为中间一半执行两遍，算下来每 token 的计算量和基线相同。
  • “54B”是总的非嵌入参数（大部分在没被激活的专家里），不是激活参数。

2 相关工作：已有研究各自对齐了什么

这一节要回答的问题：循环 Transformer、MoE 加循环、循环模型的扩展律，这几条线各自做到了哪一步？它们的比较条件分别对齐了哪些预算？SMELT 声称的新意到底是什么？另外，后面机制分析要用到的“注意力汇”，前人已经知道些什么？

循环 Transformer 这条线。Universal Transformer（本站 精读页）最早提出在深度方向共享权重，用同一个块反复计算。Huginn 把它扩展到 3.5B 参数，采用“前段—循环段—后段”（prelude–recur–coda）的布局，最大规模时是 2–4–2 层，循环的正好是中间一半；这个模板后来被大多数工作沿用。Ouro 则循环整个层栈，规模 1.4–2.6B。两者都报告循环模型在推理类评测上追平或超过大得多的普通模型。Saunshi 等人（本站 精读页）同时和“参数相同”和“计算量相同”两种对手比较：循环模型的困惑度不如计算量相同的对手，但推理任务的提升不成比例地大；只循环中间一段比循环全部层的困惑度更好。还有一些工作研究“怎么循环”：给每遍加 LoRA 放松权重共享、让每个 token 学习自己的循环次数（Mixture-of-Recursions，本站 精读页）、只在难的 token 上多算几遍等。RINS 对齐了总训练算力，但做法是让循环模型少训练一些 token；SMELT 则连训练 token 数也对齐。

MoE 加循环这条线。MoEUT 首次让基于 MoE 的 Universal Transformer 在语言建模上追平普通 Transformer。Lee 等人（arXiv 2605.09165）发现稀疏的 MoE 层对循环模型的扩展至关重要：同一个 token 在两遍里会被路由到不同的专家，部分恢复了权重共享损失的表达能力（§5 末尾会详细比较这篇）。同期还有几项在更大规模上训练 MoE 循环模型的工作：LoopMoE 在 3B 和 9B 上对齐了总参数和每 token 计算量；Gao 等人（Loopie）在 6B 和 20B 上按训练时长对齐，并独立地发现循环两遍最好；DREAMER 把单个 MoE 层循环 16–32 遍。

扩展律这条线。Kaplan 等人建立了损失与模型大小、训练 token 数之间的幂律关系；Chinchilla 进一步给出算力最优的分配：参数和 token 应该大致同比例增长。MoE 的扩展律在此基础上加入专家数、专家粒度或稀疏度等变量。在循环模型上，有两项工作从相反方向夹住了问题：Iso-Depth 固定有效深度（因而固定计算量和 KV 缓存），减少独有参数，给出“循环一遍值多少”的价格；Parcae 固定独有参数，让循环次数随算力增长，但这样深度、推理计算量和 KV 缓存都会跟着变大，拟合结果分不清“共享参数的代价”和“预算变大的好处”。

注意力汇这条线。自回归 Transformer 会把大量注意力放在序列开头的几个 token 上，不管它们内容是什么，这叫注意力汇（attention sink）。StreamingLLM 发现了它并用来做流式推理；后续工作研究了它何时出现、和残差流里的“超大激活”有什么关系、为什么随深度变强（有一种解释是它在防止信息被过度混合），以及在注意力输出后加一个依赖 query 的门控就能在所测模型上明显削弱它。这些工作都把注意力汇当作训练好的模型的一种静态性质；SMELT 后面的发现是动态的：在一次前向传播里，同一组层走第二遍时，注意力汇会变弱。

3.1 训练协议与“等算力稀疏度”

先补一点背景：混合专家（MoE）层在做什么。

Transformer 每一层由注意力和前馈网络（FFN）两部分组成。FFN 对每个 token 各自做两次矩阵乘法，参数量和计算量都很大。MoE 把一个大 FFN 换成很多个小 FFN，叫专家，再加一个小小的路由器：每个 token 进来时，路由器给所有专家打分，只挑分数最高的 \(k\) 个专家来处理这个 token，再把它们的输出按分数加权相加。没被选中的专家不参与计算。

这带来一个关键的性质：总参数量和每 token 计算量被分开了。所有专家都要存储，所以总参数随专家数 \(E\) 增长；但每个 token 只经过 \(k\) 个专家，所以计算量只随 \(k\) 增长。SMELT 里每层固定选 \(k=8\) 个专家，专家总数从 8 到 504 不等。路由的打分、选择与负载均衡的细节，可以看本站 DeepSeek-V3 精读 §2.1.2。

模型。所有模型都是只含解码器的 Transformer，前馈层全部换成 MoE，每个 token 选 8 个专家；注意力用分组查询注意力（GQA，§3.2 会解释）。作者从内部一个调好的 MoE 模型族里取出四个规模作为基线，按激活非嵌入参数称作 100M、200M、600M、1.6B，物理层数分别是 10、12、20、30。基线叫 Baseline，循环的变体统称 Looped Transformer；消融选出的最终配置就是 SMELT。两者用同一个结构模板、同一个优化器、同样的数据和评测，唯一的区别是循环方式和为对齐预算而调整的宽度、专家数、注意力头。循环段内每个子层的残差更新都乘以 \(1/r\)（\(r\) 是循环次数，SMELT 里就是 1/2），原因见 §3.2。

等算力稀疏度 \(S\)。MoE 模型存了 \(N\) 个参数，但每个 token 只激活其中一部分。通常的“稀疏度”就是“1 − 激活参数 ÷ 总参数”。作者换了一种算法：先找一个“全部激活”的对照模型，即同一规模、不循环、每个 token 用到所有专家的 Baseline，记它每 token 的训练计算量为 \(F_0\)、总非嵌入参数为 \(N_0\)。对任何一个每 token 计算量为 \(F\)、总参数为 \(N\) 的模型，定义

$$N_{\text{act}}^{\text{eq}}=\frac{F}{F_{0}}\,N_{0},\qquad S=1-\frac{N_{\text{act}}^{\text{eq}}}{N}$$

意思是：一个模型每 token 花的计算量是对照模型的几分之几，就认为它“相当于激活了”对照模型参数的几分之几，\(S\) 是剩下没被用到的比例。对照模型按定义 \(S=0\)。

算一个例子（推算）：200M 档、\(S\approx95\%\) 的 Baseline 有 192 个专家，激活参数 0.209B，总参数 3.87B。它和 \(S=0\) 的对照模型（8 个专家全部激活，0.207B）每 token 计算量几乎一样，所以 \(N_{\text{act}}^{\text{eq}}\approx0.209\)B，\(S\approx1-0.209/3.87\approx94.6\%\)，和原文表 9 的 94.6% 一致。对应的 SMELT 每 token 计算量是 Baseline 的 1.029 倍、总参数 3.89B，于是 \(N_{\text{act}}^{\text{eq}}\approx1.029\times0.209\approx0.215\)B，\(S\approx94.5\%\)；表 10 给的是 94.7%，差的 0.2 个百分点来自本站用激活参数近似计算量。

为什么要绕这一圈，而不是直接用“激活参数 ÷ 总参数”？因为循环模型的“激活参数”说不清楚：SMELT 走一遍物理层只用到 0.142B 参数，但中间一半要走两遍，真正花掉的计算相当于约 0.213B 参数（推算：0.142 × 18/12）。用计算量来定义 \(S\)，就把每一次重复执行都算了进去；另外，注意力打分的计算量随上下文长度变化，不和参数成正比，用实测的 FLOPs 也能把它包含进去。这样，同一个 \(S\) 标签下的 Baseline 和 SMELT 才真正可比。

需要注意，\(S=0\) 并不等于“稠密”。为了补回参数，\(S=0\) 那一格的 SMELT 每层有 16 个专家、选 8 个，仍然是 MoE；\(S=0\) 只表示它的“每个参数平均分到的计算量”和全激活的对照模型一样。实验报告的是 \(S\approx85\%\)、95%、97% 三档稀疏度，外加 \(S=0\) 这一档参照。

先补一点背景：WSD 学习率调度和“分叉退火”。

WSD（warmup–stable–decay）调度把训练分成三段：先短暂预热，然后用恒定学习率训练很长一段（stable），最后在一个较短的阶段里把学习率降下来（decay，也叫退火）。退火能让损失明显下降，模型只有在退火之后，损失才反映它在这个训练量下真正能达到的水平。

WSD 的好处是：可以只跑一条恒定学习率的主线，在主线的不同位置“分叉”出去各做一次短退火，于是一次训练就得到好几个不同训练量下的“完成品”。拟合扩展律需要“同一个模型在不同 token 数下的损失”，分叉退火比每个 token 数各从头训一次便宜得多。

优化器和训练量。AdamW 配 WSD 调度。恒定学习率阶段训练 196,075 步，每步 256 条序列、每条 4096 个 token，即每步约 100 万 token；在第 10,000、20,000、50,000、100,000、150,000 和 196,075 步各分叉出一次余弦退火，每次退火再训练 100 亿 token。所以每个配置有六个训练量的端点，最长的约 2150 亿 token（恒定阶段 2050 亿加退火 100 亿），而且没有重复数据。同一档规模和稀疏度下配对的 Baseline 和 SMELT，看到的是完全相同的 token 序列。

数据。预训练用的是作者内部的语料。验证集来自 39 个数据源，分成代码、数学/理工、知识、金融、网页五类。训练时把多篇文档拼进一个 4096 token 的上下文，并用分段注意力掩码让每篇文档只看到自己。

评测。论文从头到尾用三个指标。验证损失是在 39 个来源上按 token 加权的交叉熵。DCLM Core 是 DCLM 评测套件 22 个任务的“居中准确率”平均：每个任务的准确率先减去 DCLM-v2 给定的参照基线、再除以“满分减参照基线”，所以 0 代表参照水平、1 代表全对；有示例的任务用 10 个随机种子抽取示例并取平均，7 个零样本任务只跑一次。DCLM Completion 是作者定义的：在 22 个任务里有 9 个要求自由作答（而不是选择题），就在这些任务的标准答案 token 上算交叉熵，越低越好，它比准确率更连续、噪声更小。另外单独报告 MMLU 5-shot。训练前已从语料中过滤掉已知的评测题目。

读的时候容易误解的地方：论文里所有标着“±”的误差（比如 DCLM Core 的 ±0.1–0.2 个百分点）只反映 10 个评测种子之间的差别，不反映训练的随机性：每个配置只训练了一次。所以两个配置在验证损失上相差千分之几 nats 时，并不能确定这个差别在重新训练后还在。

3.2 三项预算一起对齐：稠密模型为什么做不到，MoE 怎么做到

先补一点背景：KV 缓存与分组查询注意力（GQA）。

生成文字时，模型要为已经处理过的每个 token、在每一层存下它的 key 和 value 向量，这就是 KV 缓存（详见 vLLM 精读 §2.2）。每个 token 在一层里要存的数是 \(2\times n_{\text{kv}}\times d_{\text{head}}\)：\(n_{\text{kv}}\) 是 key/value 头的个数，\(d_{\text{head}}\) 是每个头的维度。

普通的多头注意力里，每个 query 头都有自己的一对 key/value 头。GQA 让若干个 query 头共用一对 key/value 头，“GQA 比例”就是 query 头数与 key/value 头数之比。比例越高，要缓存的 key/value 头越少。头的维度变小，每个头要存的数也变少。所以“更小的头 + 更高的 GQA 比例”是压缩每层 KV 缓存的两个旋钮。

对循环模型来说，第二遍执行同一层时，输入已经变了，所以要用这一遍的输入重新算 key 和 value，不能复用第一遍的结果。于是循环模型每执行一层就要存一份 KV，KV 缓存按有效深度计，而不是按物理层数计。

先看为什么稠密模型做不到三项同时对齐。论文用了一个简单的近似：普通 Transformer 每 token 的训练计算量正比于 \(L\cdot H^{2}\)（\(H\) 是隐藏维度），因为每层的矩阵都是 \(H\times H\) 量级。循环之后，有效深度从 \(L\) 变成 \(L_{\text{eff}}\)，计算量按比例上涨，参数却没变。要把计算量压回去，只能把 \(H\) 变小，或者减少 \(L\)。可是在稠密模型里，每个参数都会被每个 token 用到，参数量和每 token 计算量是绑在一起的：

$$\text{dense:}\quad F\propto L_{\text{eff}}\,H^{2},\ \ N\propto L\,H^{2}\ \Rightarrow\ \frac{N}{F}\propto\frac{L}{L_{\text{eff}}}\qquad\qquad \text{MoE:}\quad F\propto L_{\text{eff}}\,H^{2}\,k,\ \ N\propto L\,H^{2}\,E$$

左边（dense，稠密）说明：只要循环（\(L_{\text{eff}}>L\)），稠密模型在计算量相同时，参数一定只有对手的 \(L/L_{\text{eff}}\)，没有任何旋钮能把它补回来，因为任何新加的参数都会被每个 token 用到，计算量又涨上去了。右边（MoE）说明：MoE 多了一个旋钮 \(E\)（专家总数），它只影响存储、不影响计算（计算只看每个 token 选的 \(k\) 个专家）。所以“变窄付计算、加专家补参数”在 MoE 里是可行的。这里的式子都是只看主导项的近似，用来说明道理；论文实际对齐时用的是实测的 FLOPs 和参数数。

走一遍论文的例子（原文 §3.2 与表 10 的 200M、\(S\approx95\%\) 一格）。目标是造一个 12 层、把中间 6 层循环两遍、共执行 18 层的循环模型，和对应的 Baseline 三项都对齐。Baseline 是 \(L=12\)、\(H=1280\)、每层 192 个专家，每 token 训练计算量 \(1.33\times10^{9}\) FLOPs，总非嵌入参数 \(3.87\times10^{9}\)。

  1. 只循环、其他不动。多执行了 6 层，计算量变成约 18/12 = 1.5 倍；参数不变；KV 缓存也变成约 1.5 倍（多出的 6 次执行各要存一份）。
  2. 把 \(H\) 从 1280 收窄到 1056。\((1056/1280)^{2}\approx0.68\)，所以计算量约为 1.5 × 0.68 ≈ 1.02 倍（推算），基本回到原位。但每个专家的矩阵也跟着变小了，总参数掉到约 0.68 倍。
  3. 把每层专家数从 192 增加到 288。专家多了 1.5 倍，总参数回到约 0.68 × 1.5 ≈ 1.02 倍（推算）；每个 token 仍然只选 8 个专家，计算量不受影响。专家数在所有层都一样。
  4. 把注意力头变小、GQA 比例调高。要让 18 次执行的 KV 总量等于原来 12 层的，每次执行的 KV 宽度（\(n_{\text{kv}}\times d_{\text{head}}\)）要降到原来的约 2/3。论文没有公开具体的头数和头维度，只给出了结果。

论文报告的实测结果是：每 token 计算量 \(1.37\times10^{9}\)（比 Baseline 多 2.9%），总参数 \(3.89\times10^{9}\)（多 0.4%），KV 缓存相差不到 4%（表 10 中是 1.031 倍）。计算量比本站粗算的 1.02 倍略高，是因为实测的 FLOPs 包含了随文档长度增长的注意力打分计算（按拼接后上下文里的平均文档长度计），这部分不随 \(H^{2}\) 缩小。

先补一点背景：残差流，以及为什么循环段要乘 1/2。

现代 Transformer 的每个子层（注意力、MoE）都不直接替换输入，而是算出一个“更新量”加回到输入上：\(x\leftarrow x+\Delta x\)。这条一路加下去的向量叫残差流。论文用的是“前置归一化”结构，子层先对输入做 RMSNorm 再计算。

如果一组不同的层各自写入更新，这些更新的方向大体不相关，加起来的长度大约按“层数的平方根”增长。但循环时，同一组权重在两遍里写入的更新方向很相似（§6.2 会测到它们的余弦相似度约 0.56），相似的向量相加，长度接近直接相加，残差流会被放大得更快。所以作者在循环段内把每个子层的更新都乘以 \(1/r\)：

$$\Delta x_{\text{attn}}=\tfrac{1}{r}\,\mathrm{Attn}\big(\mathrm{LN}(x)\big),\qquad \Delta x_{\text{moe}}=\tfrac{1}{r}\,\mathrm{MoE}\big(\mathrm{LN}(x+\Delta x_{\text{attn}})\big)$$

循环段外 \(r=1\)，就是普通的前置归一化层。这个缩放规则来自论文引用的 Wang 等人的另一篇论文（arXiv 2606.18524，署名作者大部分与本文相同），那篇论文论证了权重共享会让各遍的更新相关，因而需要按 \(1/r\) 而不是按 \(1/\sqrt{r}\) 缩放。

读的时候容易误解的地方：
  • 对齐的是算术上的计算量、参数数和 KV 缓存大小，不是实际运行时间。循环的第二遍必须等第一遍算完才能开始，是串行的；专家更多也意味着专家并行时的通信更多。作者在局限里承认，这些可能带来需要系统优化才能抹平的硬件效率差距。
  • 表 10 里 SMELT 的计算量比值全部 ≥ 1（1.000–1.081），也就是说残差误差的方向总是让 SMELT 多花一点计算。在逐对比较“谁赢”时，这对 SMELT 略有利；但扩展律拟合用的是每个模型实测的计算量，所以算力节省的结论已经把这点扣除了。
  • 嵌入层参数不在“总参数”里。两种结构词表相同，这部分本来就一样，不影响比较。

3.3 消融一：循环中间一半，好过循环全部

第一个问题是循环哪几层。作者固定物理层数 \(L=12\)、循环两遍，让循环段的长度从 0 层（就是 Baseline）一直变到 12 层（全部循环），循环段始终放在正中间，并在 \(S\approx85\%\) 和 \(S\approx95\%\) 两档上各做一遍，看最优位置会不会随稀疏度移动。注意每个配置都按 §3.2 重新对齐了三项预算，所以循环段越长，模型就要收得越窄。

为什么中间最好？作者的解释和已有发现一致：Transformer 的不同深度分工不同，最前面几层负责把 token 变成内部表示，最后几层负责把内部表示变回词表上的预测，这两头的层有专门的角色，适合各用一套独立的参数；中间的层做的是比较通用的“加工”，更适合反复使用。Saunshi 等人和 Kapl 等人在稠密模型上也发现循环中间一段比循环全部更好。

读这张表时要注意：\(S\approx85\%\) 那条曲线不平滑：循环 83% 的层只比 Baseline 好 0.0032，循环 100% 反而好 0.0123。这种起伏很可能来自“每个配置只训练一次”的随机性，说明单次训练之间的差别可能有千分之几 nats（这是本站的解读，论文没有给训练层面的误差）。两档稀疏度都在 50% 附近达到最低，这一点比较可信；但 33%、50%、67% 之间的差别只有零点几到一两个千分之一 nats，不能说 50% 明显好过它们。

4.2 扩展律的形式与“算力效率增益”

先补一点背景：Chinchilla 扩展律与“算力最优”。

扩展律描述“损失随模型大小和训练数据量怎么下降”。Chinchilla（Hoffmann 等，2022）用一个三项相加的形式：\(\mathcal{L}(N,D)=E+A/N^{\alpha}+B/D^{\beta}\)。第一项 \(E\) 是怎么加大模型、加多数据都去不掉的“不可约损失”；第二项随模型参数 \(N\) 变大而变小，代表“模型容量不够”造成的损失；第三项随训练 token 数 \(D\) 变大而变小，代表“数据没看够”造成的损失。

训练的总算力大约是 \(C\approx6ND\)。给定 \(C\)，模型做大了就只能少看数据，数据看多了模型就只能小一点。在这两者之间存在一个让损失最小的分配点，这叫算力最优。把每个 \(C\) 下的最优点连起来，就得到“算力最优前沿”：在每一个算力预算下，这种结构最好能做到多低的损失。Chinchilla 的结论是稠密模型大约每个参数配 20 个训练 token。

论文的形式。对 MoE 来说，总参数 \(N\) 不能说明一个 token 实际用了多少参数，所以单用 \(N\) 一个轴没法同时描述稠密和稀疏的模型。已有的 MoE 扩展律会额外加入专家数、专家粒度或稀疏度。作者沿用这条思路，把 \(N\) 换成每 token 的计算量 \(F\)，再用 §3.1 的稀疏度 \(S\) 去调节容量项：

$$\mathcal{L}(F,S,D)=E+\frac{A\,(1-S)^{b}}{F^{a}}+\frac{K}{D^{c}}$$

这里的 \(F\) 是实测的每 token 训练 FLOPs，按拼接上下文里的平均文档长度计算，包含注意力打分的部分，所以比只算参数的 \(6N\) 要大。中间的容量项随 \(F\) 变大而变小；它也随 \(S\) 变大（\(1-S\) 变小）而变小，因为更稀疏的模型在同样的每 token 计算量下存了更多参数。最后一项随训练 token 数 \(D\) 变大而变小。作者给 Baseline 和 SMELT 分别拟合这个式子，各有自己的 6 个系数 \(E,A,K,a,b,c\)，没有任何一个系数是两者共享的。

算力最优前沿。给定总算力 \(C\) 和稀疏度 \(S\)，约束是 \(C=F\cdot D\)。按 Chinchilla 的第三种方法，对上式求最小值，可以得到最优的每 token 计算量和对应的最低损失：

$$F^{*}=\left(\frac{a\,A\,(1-S)^{b}\,C^{c}}{c\,K}\right)^{1/(a+c)},\qquad D^{*}=\frac{C}{F^{*}},\qquad \mathcal{L}^{*}(C,S)=E+f(A,K,a,b,c,S)\;C^{-\gamma},\quad \gamma=\frac{ac}{a+c}$$

\(\gamma\) 是前沿上“可约损失随算力下降的速度”。\(\gamma\) 越大，算力每翻一倍，损失降得越多。

算力效率增益（CE Gain）。两种结构各有一条前沿，就可以问：在同样的损失下，目标结构比参照结构少花多少算力？做法是三步：先算目标结构（SMELT）在算力 \(C_{\text{tgt}}\) 处的前沿损失；再在参照结构（Baseline）的前沿上反查，它要花多少算力 \(C_{\text{ref}}\) 才能达到同样的损失；最后

$$\text{CE Gain}=1-\frac{C_{\text{tgt}}}{C_{\text{ref}}}$$

正值表示目标结构用更少的算力达到同样的损失。研究“算法进步”的文献常把同一个量写成倍数 \(C_{\text{ref}}/C_{\text{tgt}}\)；比如 CE Gain = 14.7% 相当于 1/(1−0.147) ≈ 1.17 倍（推算）。

5 下游表现与领域分析：优势落在哪里

这一节要回答的问题：第 4 节的算力节省全部来自验证损失，而验证损失是把所有领域、所有长度的样本平均成一个数。损失低了不一定意味着下游评测更好，平均值也可能掩盖不同领域之间的差别。所以这一节问三件事：优势能不能迁移到独立的下游评测上，而且是不是“只是损失低了带来的那一点”？优势集中在哪类数据上？它和样本长度、上下文示例数有什么关系？最后，本站把整篇论文的实验份量放在一起评估。

5.1 下游胜率，以及“超出验证损失预测”的那一部分

在 96 对配对端点上，SMELT 在 DCLM Completion 上赢了 96 对，在 DCLM Core 上赢了 83 对。MMLU 在小模型上接近随机水平（四选一，25%），配对比较不稳定，所以只统计 Baseline 至少比随机高 10 个百分点的 30 对，SMELT 赢了 29 对。原文图 5–7 把这三个指标对累计训练算力画出来，排版和图 3 相同。

作者紧接着承认：验证损失更低的模型，本来就该在跟着损失走的评测上得分更高，所以这些胜率只是把第 4 节换个说法再说一遍，并没有新信息。真正的问题是：下游的提升是和损失的下降成比例，还是超出了这个比例？

为此，作者只用 Baseline 的 96 个端点，为每个下游指标拟合一条“验证损失 → 得分”的校准曲线，形式是四参数的单调 S 形函数：

$$\hat{y}_{m}(\ell)=b_{m}+\frac{a_{m}}{1+\exp[-d_{m}\,\alpha_{m}(\ell-\tau_{m})]},\qquad \delta_{i}=s\cdot\big(y_{i}-\hat{y}(\ell_{i})\big)$$

\(\ell\) 是验证损失，\(d_m\) 控制方向（DCLM Completion 随损失上升，取 +1；Core 和 MMLU 随损失下降，取 −1）。三条曲线拟合得很紧，\(R^{2}\) 分别是 0.997、0.974、0.911。然后对每个 SMELT 端点，拿它的实际得分减去“一个验证损失和它一样的 Baseline 应该得多少分”，得到残差 \(\delta_i\)（符号 \(s\) 保证正值总是表示 SMELT 更好）。如果 SMELT 只是“损失更低”，它的点应该落在 Baseline 的曲线上，残差平均为 0。

5.3 样本越长、示例越多，优势越大

样本长度。作者把验证集里的文档按自身长度分成 8 个桶（上界依次是 32、64、…、4096 个 token），计算每个桶里每 token 损失的改进。为了只比较“改进在不同长度上的分布形状”，每一组对比都把各桶的改进除以它们的平均值。对比有三种：SMELT 对它配对的 Baseline；Baseline 内部“加专家”（相邻稀疏档之间，如 \(S=0\to85\%\)）；Baseline 内部“加参数”（相邻激活规模之间，如 200M → 600M）。结果，SMELT 在最长四个桶（512–4096 token）上的平均改进是最短四个桶（32–256 token）的 1.52 倍；“加参数”带来的改进在长短样本上差不多（0.98 倍），“加专家”甚至略偏向短样本（0.88 倍）。也就是说，在 Baseline 里把模型做大或把专家加多，都不会让收益偏向长样本，循环却会。

上下文示例数。作者另外做了一组评测：16 个需要示例的任务（15 个 DCLM 任务加 MMLU），示例数 \(k\) 取 0、1、2、4、8，其中 QA Wikidata、ARC Easy、CS Algorithms、Dyck Languages、Operators 还加测 \(k=16\) 和 32。这组评测和前面的固定示例数不同，所以准确率数字和前面的 DCLM Core 对不上。两种结构的平均准确率差距在 \(k=0\) 时是 0.9 个百分点，一旦给出示例（\(k=1\)）就扩大到 1.9 个百分点，并一直保持到 \(k=8\)。作者特别挑出 Dyck Languages（括号配对补全）：没有示例时两者都接近 0%，因为模型不知道答案的格式，唯一的提升途径是去读示例里的答案。在这个任务上差距随 \(k\) 一直扩大、没有饱和，\(k=32\) 时 SMELT 29.8%、Baseline 26.4%。16 个任务里有 14 个，SMELT 在最大示例数下的提升是显著的（配对置换检验 \(p<0.05\)，附录 C）。

5.4 结果的份量

这一部分是本站的评估，把前面的数字放回它们的实验条件里。

规模。最大的模型是 1.6B 激活、约 54B 总非嵌入参数，最长训练约 2150 亿 token，拟合用到的累计训练算力最多 \(2.2\times10^{21}\) FLOPs。作为对照，本站精读过的 DeepSeek-V3 激活 37B、训练 14.8 万亿 token，按 \(6ND\) 粗算约 \(3\times10^{24}\) FLOPs（推算），比本文最大的实验多三个数量级。所以本文覆盖的是中小规模，结论要推到前沿规模，仍然要靠扩展律外推。

对齐了什么。这是本文最扎实的地方：每 token 训练计算量（实测、含注意力）在稀疏档内最多差 3.9%，总非嵌入参数差 1% 以内，KV 缓存差 4% 以内，配对模型看的是完全相同的 token 序列，优化器、调度、评测都一样。因为每 token 计算量对齐，推理时每 token 的计算量也对齐。没有对齐的是实际运行时间和通信量：循环的第二遍是串行的，专家更多意味着专家并行的通信更多，论文没有报告任何墙钟时间。

对手是谁。Baseline 不是复现别人的模型，而是作者内部一个“调好的 MoE 模型族”，SMELT 由它按对齐规则派生出来。这对 Baseline 是有利的：它的宽度、深度、专家配置是为它自己调过的（§3.4 也显示 12 层确实是 Baseline 的最优深度）。论文没有说明学习率等优化超参数是否为 SMELT 单独调过，按“两者用同一个优化器”的描述，应该是共用的。

统计上能信多少。每个配置只训练一次，没有训练种子之间的方差；消融里相邻配置的差别常常只有千分之几 nats。算力节省的区间来自对 12 个格子的自助重抽，在 \(10^{20}\) 处可以宽到 [1, 22]，在 \(10^{22}\) 处的下限是 0。如 §4.3 所算，\(10^{21}\) 处 14.7% 的节省对应约 0.01 nats 的前沿损失差。

“超出验证损失的预测”建立在什么上面。这个结论依赖一条只用 Baseline 端点拟合的 S 形校准曲线，以及 SMELT 端点相对它的残差。残差本身很小：DCLM Core 平均 +0.9 个百分点，MMLU 平均 +1.3 个百分点，DCLM Completion 平均 8 毫奈特。论文没有给残差的置信区间，而 96 个端点并不独立：每次训练贡献六个分叉端点，实际只有 16 次 SMELT 训练。另外有一种不矛盾、但值得放在一起看的解读（本站的看法）：验证损失是 39 个内部来源的加权平均，而 §5.2–5.3 显示 SMELT 的收益集中在代码、长样本和多示例上；如果下游评测恰好更依赖这些能力，那么“下游提升超出平均损失的预测”在一定程度上反映的是“平均损失给这些能力的权重偏低”，而不一定是验证损失之外的另一种性质。

可复现性。模型族、训练框架和语料都是专有的，附录 A 明确说完整结构和训练栈无法公开；论文只给出了对齐比较需要的那些量。目前没有独立复现。

和同类结果怎么放在一起看。

  • Lee 等人的 Sparse Layers（arXiv 2605.09165）：他们在 FineWeb-Edu 的 100 亿 token 上，把 8 层×2 遍的 Looped-MoE 和 16 层的稠密模型、16 层的 MoE 模型在相同每 token 计算量下比较（等算力扩展律，最大 305M 激活 / 711M 存储参数，算力 \(5\times10^{16}\)–\(10^{18}\) FLOPs）。结论是 Looped-MoE 比稠密基线扩展得好，但在损失上仍不如不循环的 MoE。注意那里的 MoE 对手比 Looped-MoE 多存了约一倍参数。SMELT 把这一项也对齐（靠增加专家），结论变成循环的 MoE 胜过不循环的 MoE。两者并不矛盾，正好说明“参数是否对齐”会翻转结论。在机制上，Lee 等人看到同一 token 两遍的专家选择大多不同（每层 8 选 2 时，25–53% 的 token 两遍的专家完全不重合），SMELT 则发现专家池小时几乎完全重合、专家池大时重合 2–3 个（§6.1），两者的设置差别很大，不宜直接对比数字。
  • 稠密模型上的 Iso-Depth（本站 精读页）：在相同训练算力下，循环一遍只值 \(\varphi=0.46\) 个不共享的块（95% 区间 0.41–0.53）；410M 模型循环 4 遍能打平 580M 的不循环模型，但训练成本相当于 1B 的模型。SMELT 的看法是，这个亏损可能是因为循环模型被迫少存了参数。但 SMELT 没有、也无法在稠密模型上做三项对齐的实验，所以它并没有直接推翻 Iso-Depth 的结论：在稠密模型里，计算量相同就意味着参数更少，这是稠密结构的事实，而不是实验设计的瑕疵。SMELT 的结论只适用于 MoE。
  • Parcae（本站 精读页）：在参数和数据都固定的条件下，循环模型在每个规模上都优于同尺寸的 Transformer（1.3B 时 Core 高 2.99 分），770M 的 Parcae 补上了 770M 与 1.3B Transformer 之间 87.5% 的 Core 差距（训练和推理计算并不对齐）。这是“参数对齐、计算量不对齐”的比较，和 SMELT 回答的不是同一个问题。

6 第二遍在做什么：路由、残差写入与注意力

这一节要回答的问题：同一组权重，第二遍和第一遍到底算出了什么不同的东西？作者把所有配对模型放到 100 万 token 的留出验证样本上，从三个角度观察：MoE 的路由是否选同样的专家；第二遍往残差流里写入的更新比第一遍大还是小、方向是否一致；注意力看的位置和读到的内容有没有变。最后用一个括号配对任务做案例，把“上下文示例越多越有利”和注意力汇的变化联系起来。这些都是描述性的观察，不是因果证明。

6.2 第二遍往残差流里写得更多，而且方向一致

每一层都会往残差流里加一个更新 \(\Delta x\)。作者测量同一个物理层在两遍里写入的更新的长度（\(\ell_2\) 范数），报告“第二遍 ÷ 第一遍”的比值，大于 1 就表示第二遍写得更多；分别看整个层的更新、注意力的写入、MoE 的写入，以及送进下一个子层的 RMSNorm 输出。

原文图 13 画了 \(S\approx85\%\) 下四个规模循环段内逐层的残差流：在所有四个规模、每一层上，第二遍写入的更新都比第一遍大；除以残差本身的长度之后，在三个较大规模上第二遍的相对更新也一致更大。100M 的循环段只有 5 层，前几层出现了持平或反过来的情况，可能是因为残差流在两遍之间还没有拉开足够的差别。原文图 14 把这些量铺到整个 4 × 4 网格上：16 格里，四种长度比值全部大于 1，范围 1.2–3.5 倍。注意力和 MoE 两部分都有贡献。而且送进子层的 RMSNorm 输出在第二遍也更长；RMSNorm 本来会去掉输入的整体尺度，它的输出变长，只能是因为残差流的方向变了，使得归一化里逐维的增益系数放大了不同的维度。

6.4 案例：括号配对，以及注意力汇在第二遍几乎消失

先补一点背景：注意力汇（attention sink）。

注意力的权重经过 softmax，所有位置的权重加起来必须等于 1。当一个注意力头在当前位置“没什么需要看的”时，它也得把这 1 的权重放到某处。训练好的模型往往学会把这部分多余的权重倒在序列最开头的 token（通常是 BOS，即序列开始符）上，因为每个位置都能看到它，而它的内容几乎不影响输出。这种现象叫注意力汇。它很普遍，而且在普通 Transformer 里随深度增强。本文用的是拼接上下文加分段掩码，所以每段文档的开头就是这段的“汇”，论文称之为 segment-start mass（段首注意力质量）。

第 5.3 节显示 SMELT 的优势随上下文示例增多而扩大。为了弄清原因，作者选了一个答案没有歧义、必须依赖示例的任务：Dyck 括号配对。要补全一个右括号，模型必须从提示里的示例中找到与之匹配的左括号形式。作者构造了 \(k\in\{1,2,4,8\}\) 个示例的嵌套括号提示，设三个固定的目标位置，保证正确答案在前 \(k-1\) 个示例里出现过。每个示例由一串输入括号和它的补全组成，补全中位于“Output:”标记之后的 token 称为示例答案。对每个规模，作者在循环段里逐个去掉注意力头，选出去掉之后 Dyck 困惑度上升最多的那个头，称为 Dyck 头，然后看它的完整注意力分布。

在第一遍，这个头把大部分权重放在段首的 BOS 上，以及附近的位置，像是还不知道该看哪里；在第二遍，注意力汇几乎消失，权重从 BOS 转移到了提示里的示例答案上（四个示例一共 11 个示例答案 token）。三个目标位置平均，BOS 的权重从 0.60 降到 0.02，示例答案从 0.24 升到 0.85。作者推测这和 5.3 节的 ICL 优势有关：示例越多，第二遍可以看的答案片段越多，而汇的减弱腾出了权重去看它们。

这不只发生在 Dyck 上。作者在覆盖五类来源的 100 万 token 验证样本上重复测量。逐头的热图（原文图 19a，1.6B）显示，第一遍里那些段首权重很高的头，在第二遍几乎全都变弱了。更有意思的是这和普通的深度趋势相反（原文图 19b）：在 Baseline 里，段首权重随层数加深而增加，这与已有研究“注意力汇随深度增强”一致；而 SMELT 第二遍在整个循环段里都低于第一遍，虽然第二遍在执行顺序上更深。附录 D 显示四个规模都是如此。

读的时候容易误解的地方：
  • 0.60 → 0.02 这组数字来自一个规模、一个头、一个 \(k=4\) 的例子三个目标位置的平均，是用来说明现象的案例，不是统计结论。更一般的证据是图 19 和附录 D 的逐头、逐层平均。
  • 这一节的所有发现都是相关性的描述：第二遍汇变弱、和 ICL 优势同时出现，并不证明是前者导致了后者。论文自己的措辞也是“可能是性能提升背后的一种归纳偏置”，并在局限里说，到底是第二遍里的哪个机制带来了收益，仍然没有因果解释。
  • “第二遍注意力汇变弱”是相对第一遍而言。它和“加门控削弱注意力汇”的工作不是一回事：SMELT 没有改注意力的结构，汇在第一遍仍然存在。

7 结论与局限

这一节要回答的问题：作者最终主张了什么？他们自己承认了哪些没做到的地方？本站认为还需要补充哪些限定？

作者的结论是：在预算对齐的条件下，对 MoE Transformer 来说，深度方向的权重重用是净收益。按 SMELT 配方（中间一半循环两遍，更大的有效深度/宽度比）构造的模型，在四个规模、四档稀疏度上都稳定胜过 Baseline，在前沿上省 6.8–18.0% 的训练算力。优势不止体现在验证损失上：下游收益超出损失的预测，集中在结构化数据和长样本上，并随上下文示例增多而增大。内部探测给出一个一致的特征：第二遍沿用检索坐标、放大残差写入、把注意力从汇上释放出来。作者据此认为，循环更像是一个“精修”步骤，而不只是增加容量。他们把深度方向的权重共享看作和加宽、加深、加专家并列的又一条改进模型的轴。

作者列出的局限：

  • 受算力所限，设计消融只在 200M 一档（总参数最多 3.9B）做，更大规模下最优的循环段和循环次数可能不同。
  • 只研究了最简单的循环：一个连续的块、权重完全共享。每遍加低秩适配器、按 token 自适应循环深度、学习何时停止、选择性共享、跨 token 的状态复用等更丰富的变体，在预算对齐下能否保持或放大 CE Gain，留给后续工作。
  • 对齐的是算术 FLOPs、参数和 KV 缓存大小，不是墙钟成本；串行的块重复执行和稀疏路由可能带来硬件效率上的差距，需要系统层面的优化来弥补。
  • 第二遍里到底是哪个机制带来了收益，仍是开放问题；第 6 节的探测只是描述性的起点。

本站补充几点（详见 §5.4）：每个配置只训练一次；模型、数据和代码都未公开，无法独立复现；14.7% 的算力节省对应约 0.01 nats 的损失差；\(10^{22}\) 处是外推；拟合出的两条前沿在拟合范围的最左端（约 \(1\)–\(2\times10^{19}\) FLOPs）交叉，这是分别拟合带来的形式上的结果；结论只适用于 MoE，在稠密模型上三项对齐本身做不到。
