0 导读：这篇论文解决什么问题

扩散语言模型（diffusion language model，下文简称 DLM）生成文字的方式和常见的自回归模型（AR）不同：它先摆出一排被遮住的空位 [M]，然后分若干步去噪，每一步对所有空位同时给出预测，把其中有把握的几个填上。因为一次前向能定下好几个 token，它在原理上比“一次只生成一个 token”的 AR 快。可是同样大小的 DLM，生成质量通常比 AR 差一截。

这篇论文给出的解释是“计算量与难度不匹配”：在同一步里，有的空位很容易猜（比如一句话末尾的句号），有的空位很难（比如一道算术题要算出来的结果），而标准 DLM 对每个空位都用同样深度的网络算一遍。没把握的位置可以推迟到下一步再定，但这一步为它算出的中间表示会被丢掉，下一步又从 [M] 重新算起。所以，难的位置并没有因为难而得到更多的计算。

论文的做法叫 ALoDLM（Adaptively Looped DLM）。它把 Qwen3 中间的一段层做成可以反复执行的循环核心，在每一步去噪的内部再套一个内循环：核心每跑一遍，就读出一次预测；有把握的位置立刻提交，变成普通的 token 嵌入，给其他位置当上下文；没把握的位置保留自己的隐藏状态，进入下一遍继续细化；一个学出来的退出门决定这一步什么时候停。训练时，作者把“每个位置在第几遍提交”当成隐变量，推出一个条件形式的负证据下界（NELBO），用单条展开轨迹上的 score-function 梯度同时训练语言模型和退出门。

实验从 Qwen3-1.7B 和 Qwen3-8B 出发，只做了 5B token 的监督微调（没有继续预训练）。在 11 项基准上，ALoDLM-1.7B 和 ALoDLM-8B 的平均分是 65.5 和 80.3，高于论文评测的所有 DLM，也高于对应的 Qwen3 指令模型（63.8 和 78.5）。在 GSM8K 上，ALoDLM-8B 的单请求吞吐量是 612.4 token/秒，约为 vLLM 上 Qwen3-8B 的 2.7 倍，准确率相当。

这些数字的条件要先说清楚，后面各节会逐条展开：质量表用的是“每跑一遍只提交最左边一个 token”的逐个解码（据官方代码），并不是速度快的那个模式；速度只在 GSM8K、批大小为 1、一张 B200 上测过；ALoDLM 比 Qwen3 多训练了 5B token 的未公开数据（8B 共训练 8 轮），但论文没有一个“用同样数据训练、但不循环”的对照。

先分清两种“循环”

“循环”和“扩散语言模型”放在一起时，可能指两件不同的事，本站同一批的五篇精读页分别属于不同的情况，所以先把它们分开。

第一种是深度上的循环。在一次前向里，把同一组 Transformer 层反复执行几遍，参数量不变，计算量随遍数增加。Universal Transformer、Huginn、Ouro 都属于这一类。放到扩散模型里，就是“每一步去噪时，网络算得更深”。

第二种是跨去噪步的循环。每一步还是正常地把整个模型跑一遍，但除了采样出来的 token，还把上一步的某种连续状态（隐藏状态或预测分布）传给下一步。这样，采样时被丢掉的信息有机会保留下来。自条件化（self-conditioning）和 Loopholing 属于这一类。

示意图：扩散语言模型里的两种“循环”
本站示意图。ALoDLM 的隐藏状态只在一步之内延续：一步结束时，没提交的位置重新变回 [M]，下一步从头算起，这一点和右边的 Loopholing 正好相反。

ALoDLM 主要是第一种：每一步里循环核心最多跑 \(K=4\) 遍。它和普通的深度循环相比多了一个特点：一步之内，已经提交的位置会以“离散 token”的身份重新进入下一遍，所以它在一步之内也带有“边定稿边细化”的味道。同一批的其他几篇：LoopMDM 和 R-MDM 也是在深度上循环，但每个位置跑同样多遍；Loopholing 是跨去噪步传隐藏状态；Loop-Distill 只在训练时循环浅层、再把效果蒸馏回单遍模型，推理时不循环。

1 引言：扩散模型同尺寸为什么打不过 AR

这一节要回答的问题：扩散语言模型能并行生成，却在同样的参数量下质量落后。已有的补救办法要么把自回归结构加回来（块扩散一类的半自回归设计），要么只让扩散模型起草、再交给 AR 模型验证。作者想问一个更根本的问题：质量差距的根源是什么？他们的回答是一个假设：一步之内，各个空位的难度差别很大，但模型给每个空位的计算量一样多。
先补一点背景：掩码扩散语言模型一步做什么，花多少计算。

掩码扩散语言模型（如 MDLM、LLaDA）生成一段长度为 \(N\) 的回答时，先放一排 \(N\) 个 [M]。每一步，把“提示 + 当前这排 token”整个送进 Transformer 跑一遍，模型对每个 [M] 位置都输出一个词表上的概率分布；然后按某种规则挑几个位置，把预测填进去。重复若干步，直到没有 [M] 为止。

一次前向要把所有 \(L\) 层都算一遍，而且对每个位置算的层数都一样，这就是“固定深度”。如果一共走 \(T\) 步，总计算量大约是 \(T\) 乘以“一次前向的计算量”。块扩散（BD3-LM）和 WeDLM 这样的模型只对一个窗口或一块位置做这件事，但“每次前向、每个位置、同样多层”这一点不变。

再补一点背景：置信度解码。

每一步该提交哪些位置？最常用的办法是看模型有多大把握。LLaDA 的“低置信度重掩码”每步只保留最有把握的几个预测，其余重新遮住；Fast-dLLM 的阈值解码把置信度超过阈值的位置一次全部提交。ALoDLM 用的是同一类思路，只是把“置信度”换成了“熵”：预测分布的熵越低，说明模型越确定。

这种办法的效果是：难的位置被推迟，等周围更多 token 定下来、上下文更完整之后再猜。但推迟的只是时间。下一步时，这个位置的输入又是 [M] 的嵌入，网络从第一层开始重新算；上一步对它算到一半的中间表示没有被保留。

作者认为，同一步里的各个空位，难度可以相差很多，原因至少有三种：一是内在的不确定性（这个位置本来就可以填好几个词）；二是需要多步推理（比如要先算出中间结果）；三是它依赖别的、还没有定下来的空位（比如“所以答案是 __”要等前面的算式填完）。可标准 DLM 对所有空位用同一个固定深度的去噪网络，每个位置都被训练成“从带空位的上下文直接一步猜出答案”。这样一来，容易的位置用不完分到的计算，难的位置又不够用。

AR 模型基本没有这个问题，原因不在于它算得更深，而在于它一次只预测一个 token，而且前面的上下文全都已经确定。它不需要在“同一次前向里的几个空位之间”分配计算。

置信度解码只解决了一半。它让难的位置等到更好的上下文，可是这个位置最终被提交时，模型对它做的仍然只是一次固定深度的前向，之前几步为它做的计算都扔掉了。由此作者提出本文的核心原则：在每一步去噪之内，为难的位置保留并不断细化一个持续存在的隐藏状态，让计算量随难度伸缩。

读的时候容易误解的地方：“计算量与难度不匹配是质量差距的根源”是一个假设，论文没有设计实验直接检验它（比如在其他条件都相同时，只改变“是否按难度分配深度”）。后文支持它的证据有两类：ALoDLM 整体分数更高，以及数字类 token 第一遍的停止概率更低。这两条都和假设相容，但都不能单独证明因果。第 4.5 节会说明，分数的提高还混入了额外训练数据等因素。

2 相关工作：循环 Transformer、自适应停止与循环的扩散模型

这一节要回答的问题：ALoDLM 站在两条研究线的交叉点上：一条是“循环 Transformer 与自适应停止”，一条是“扩散语言模型”。前人已经有了学停止时刻的方法，也有人把循环放进了扩散模型。那么 ALoDLM 为什么不能直接照搬？它和已有的循环扩散模型区别在哪里？
先补一点背景：循环 Transformer 的账怎么算。

循环 Transformer 把一组层反复执行。它的参数量和只跑一遍时一样，但每多跑一遍，每个 token 的计算量（FLOPs）就多一份。所以“一个循环 4 遍的 1.4B 模型追上了 4B 的普通模型”说的是参数相同，不是计算相同。本站同一批的 Iso-Depth 精读页给出过一个校准数字：在训练算力相同的条件下，多循环一遍大约只抵得上 0.46 个“独立参数的块”。读后面的结果时要一直记住这笔账。相关的精读页：Universal Transformer、Huginn、Ouro、Mixture-of-Recursions、Parcae、SMELT、ELR。

再补一点背景：已有的“学会何时停”的几种做法。

ACT 与 Universal Transformer：每一遍输出一个“停止概率”，把各遍的中间状态按这些概率加权混合，作为最终结果，训练时再加一项惩罚，鼓励少算几遍（见 UT 精读页里的 ACT 算例）。

PonderNet 与 Ouro：把“在第 \(t\) 遍退出”看成一个概率分布 \(p(t)\)，训练目标是各遍损失的期望 \(\sum_t p(t)\,\mathcal{L}^{(t)}\)，再加一项正则（PonderNet 用几何先验的 KL，Ouro 用熵）。这样做能精确求和，是因为所有位置都无条件地算满 \(T_{\max}\) 遍，一次前向就拿到了每一遍的损失，某个 token 在哪一遍“退出”并不改变别的 token 的计算（见 Ouro 精读页 §3.2–3.3）。

Mixture-of-Recursions：用一个路由器给每个 token 指定循环深度，深度到了的 token 后面就不再参与计算（见 MoR 精读页）。

ALoDLM 不能照搬 PonderNet / Ouro 的精确求和，原因在于它的“退出”有副作用：一个位置在第 \(s\) 遍提交后，下一遍起它就以 token 嵌入的身份出现，其他还没提交的位置会看到它。也就是说，一个位置早一遍还是晚一遍退出，会改变其他所有位置后面的计算。要精确求和，就得对“所有位置的退出时刻组合”逐一展开一次前向，而组合的数量是 \(K^{M}\)（\(M\) 是被遮位置数）。比如一块 32 个 token 里遮住 16 个、\(K=4\) 时，就有 \(4^{16}\approx 43\) 亿种组合（推算）。第 3.2 节会讲作者怎么绕开这个问题。

在扩散模型这一边，已经有工作把循环放了进去：按 ALoDLM 的概括，LoopMDM（Lee 等，2026）用循环提高训练效率，R-MDM（Carballo-Castro 等，2026）用循环提高参数效率，Miele 等（2026）的不动点掩码生成模型按步自适应地决定计算量。它们的共同点是：一步之内，所有位置跑同样多遍。FReDA（Sun 等，2026）支持按 token 自适应地提交，但它反复修改的是一份显式的 token 草稿，而不是在遍与遍之间传递隐藏状态。ALoDLM 的定位是：按 token 自适应的潜空间深度，容易的位置在较早的一遍提交、把嵌入当上下文，难的位置保留不断演化的隐藏状态。

附录 A 还把 ALoDLM 和自条件化（self-conditioning）做了区分。自条件化把上一步的预测（通常截断梯度）作为额外输入喂给下一步，信息是跨去噪步传递的；Loopholing 跨步传递隐藏状态，训练时用两次前向的自条件化方案；DiffusionGemma 把预测概率映射成连续的条件特征。ALoDLM 相反：隐藏状态只在一步之内的各遍之间传递，而且训练时梯度会穿过这些遍反传，早先的状态被明确地训练成“为后面的预测服务”。

读的时候容易误解的地方：“最大的循环 DLM”是作者按自己所知的说法；而且这个 8B 模型是从 Qwen3-8B 转换来的，不是从零预训练的循环模型。它和 Huginn、Ouro 那种“从头按循环结构预训练”的模型不在一个起点上。

3 方法（一）：推理时，一步去噪里再套一个内循环

这一节要回答的问题：ALoDLM 生成文字时，一步去噪内部到底发生了什么？网络被切成了哪几段，每一遍循环算哪些层？谁来决定哪个位置提交，谁来决定这一步什么时候结束？这样做要多花多少计算、多占多少 KV 缓存？

3.1 结构：前奏、循环核心、尾声，加两个输出头

ALoDLM 不改 Transformer 本身，只是把一个现成的模型（Qwen3）按层切成三段：前奏（Prelude，嵌入层加上开头的若干层）、循环核心（Recurrent Core，中间的若干层）和尾声（Coda，剩下的末尾几层）。这套名字沿用了 Huginn，但 ALoDLM 没有 Huginn 那种“每一遍都把前奏的输出重新注入”的设计，遍与遍之间只传核心的输出（官方代码里中间过一次 RMSNorm）。

一步去噪开始时，前奏把带 [M] 的输入 \(\mathbf{x}_t\) 变成初始状态 \(h^{(0)}\in\mathbb{R}^{N\times d}\)。第 \(s\) 遍时，循环核心把 \(h^{(s-1)}\) 更新成 \(\widetilde{h}^{(s)}\)，尾声再从 \(\widetilde{h}^{(s)}\) 算出一个读出状态 \(r^{(s)}\)：

$$\widetilde{h}^{(s)}=\mathrm{Core}\big(h^{(s-1)}\big),\qquad r^{(s)}=\mathrm{Coda}\big(\widetilde{h}^{(s)}\big),\qquad s=1,\dots,K$$

\(K\) 是最多跑的遍数，论文取 \(K=4\)。要注意，尾声是一个读出分支：下一遍从核心的输出 \(\widetilde{h}^{(s)}\) 继续，而不是从尾声的输出继续。所以“第 \(s\) 遍读出”的网络路径是“前奏 + \(s\) 遍核心 + 一遍尾声”。

每个位置的读出状态 \(r_i^{(s)}\) 同时送进两个头。语言模型头（LMHead）给出词表上的概率分布 \(p_i^{(s)}\)；退出门（ExitGate）给出一个标量，经过 sigmoid 变成 \(\lambda_i^{(s)}\)，意思是“如果到这一遍还没停，那么在这一遍停下的概率”（这种“已经活到现在、此刻停下”的条件概率，在生存分析里叫风险率 hazard）：

$$p_i^{(s)}=\mathrm{softmax}\big(\mathrm{LMHead}(r_i^{(s)})\big),\qquad \lambda_i^{(s)}=\begin{cases}\sigma\big(\mathrm{ExitGate}(\mathrm{sg}[r_i^{(s)}])\big), & s<K\\ 1, & s=K\end{cases}$$

\(\mathrm{sg}\) 是截断梯度：退出门的训练信号不会传回主干网络，避免“为了让退出门好学，把主干的表示带偏”。最后一遍的 \(\lambda^{(K)}\) 被强制设为 1，保证每个位置最晚在第 \(K\) 遍停下，各遍的退出概率加起来等于 1。按官方代码，退出门只是一个从 \(d\) 维到 1 维的线性层，外加每一遍一个偏置，参数量可以忽略。

两个头分工不同，这是理解整个方法的关键：“哪个位置提交”由语言模型头的熵决定，“这一步还要不要再跑一遍”由退出门决定。

3.2 内循环一步步怎么走（算法 1）

算法 1 有两层循环。外层是普通的去噪步：只要序列里还有 [M]，就再走一步。内层是本文新加的：每一步之内，循环核心最多跑 \(K\) 遍。一步的流程如下。

  1. 准备。记下当前所有 [M] 的位置，组成“未解决集合” \(\mathcal{U}\)；用前奏算出初始状态 \(h\)；每个位置的累积停止概率 \(a_i\) 清零；“本步已提交集合” \(\mathcal{C}\) 置空。
  2. 跑一遍核心，读出一次。\(h\leftarrow\mathrm{Core}(h)\)，再从 \(h\) 分出一个尾声读出，得到每个未解决位置的 \(p_i\) 和 \(\lambda_i\)。
  3. 累加停止概率。对 \(\mathcal{U}\) 里每个位置，\(a_i\leftarrow a_i+(1-a_i)\lambda_i\)。这正是“到这一遍为止已经停下”的累积概率，等于 \(1-\prod_{s}(1-\lambda_i^{(s)})\)。
  4. 按熵提交。熵 \(\le\tau\) 的未解决位置组成集合 \(\mathcal{B}\)，从各自的 \(p_i\) 采样一个 token \(\hat{y}_i\)（实验里用的是贪心，取概率最大的词），把它们从 \(\mathcal{U}\) 挪进 \(\mathcal{C}\)。
  5. 把提交的位置换回 token 嵌入。下一遍的输入里，已提交位置用 \(\mathrm{Emb}(\hat{y}_i)\)，其余位置用核心的输出：
$$h_i^{(s)}=\begin{cases}\mathrm{Emb}(\hat{y}_i), & i\in\mathcal{C}^{(s)}\\ \widetilde{h}_i^{(s)}, & \text{其他位置}\end{cases}$$
  1. 判断要不要停。如果 \(\mathcal{U}\) 空了，或者 \(\mathcal{U}\) 里各位置 \(a_i\) 的平均值 \(\ge q\)，就结束内循环；否则回到第 2 条，最多跑到第 \(K\) 遍。
  2. 保证有进展。如果一整步下来一个位置都没提交，就把熵最低的那个位置强行提交。
  3. 写回序列。本步提交的 token 写进序列。下一步从更新后的序列重新开始，用前奏重新初始化状态。

这里有两个阈值。熵阈值 \(\tau\) 越大，提交得越宽松，一遍能定下的 token 越多，速度越快，但更容易出错。累积停止阈值 \(q\) 越大，内循环越倾向于多跑几遍，未提交的位置细化得越充分，但每一步更慢。这里的“累积停止概率达到阈值就停”和 Ouro 推理时的 Q-exit 规则是同一个形式，区别在于 Ouro 按每个位置各自判断，ALoDLM 把一步里所有未解决位置的 \(a_i\) 取平均，整批一起停。原因很直接：这些位置共用同一次前向，没法让一部分位置停、另一部分位置接着跑。

3.3 实际怎么解码：窗口、两种提交方式

算法 1 写的是对整条序列去噪。实验里，ALoDLM 套用的是 WeDLM 的流式块扩散框架（见 WeDLM 精读页第 4–5 节）：模型保持标准的因果注意力，靠“已知 token 挪到前面、位置编号不变”的拓扑重排，让每个空位都能看到全部已知 token；解码时维护一个长度为 16 的窗口，窗口最左边连续定下来的 token 被写进 KV 缓存、移出窗口，右边补上新的 [M]。这样，已经定稿的前缀可以像 AR 模型一样用 KV 缓存。

在这个框架下，官方代码提供两种“谁提交”的规则：

  • 熵模式（默认，论文图 1、图 3 的速度实验用它）：一个位置的熵加上一项和它到最左边那个未定位置的距离成正比的惩罚（系数 \(\gamma=0.02\)）低于 \(\tau\) 时提交。距离惩罚让靠左的位置更容易先定，这样前缀能尽快写进缓存。
  • 最左一个模式（left1，论文表 1 的质量评测用它）：每跑一遍，只提交窗口里最左边那个未提交的位置，\(\tau\) 不起作用；何时结束这一步，仍由退出门的平均累积停止概率和 \(q\) 决定。论文正文只说表 1 “每一遍提交一个 token、不用熵选择”，“最左边”这一点写在官方 README 和生成文档里。
读的时候容易误解的地方：left1 模式其实是从左到右一个一个地生成。一步跑了 \(S\) 遍，就恰好提交 \(S\) 个 token，第 \(k\) 个提交的 token 在这一步里经历了 \(k\) 遍。于是“每个 token 用几遍”主要由它在这一步里排第几决定，而不是由它自己的难度决定；退出门只决定一步跑几遍。以 8B 为例，每一步第一个提交的 token 只经过了“前奏 10 层 + 核心 16 层 + 尾声 10 层”，正好是原来 Qwen3-8B 的 36 层。这不是说 left1 下没有任何自适应，而是说表 1 的分数检验的是“这个模型在逐个解码时的质量”，并不直接检验“按难度给每个 token 分配深度”这件事（推断，依据官方代码 alodlm/inference.py）。

3.4 按深度区分的 KV 缓存（附录 B.1）

先补一点背景：KV 缓存为什么和“第几遍”有关。

生成时，模型把已定稿 token 在每一层的 key 和 value 存起来（KV 缓存），后面的位置做注意力时直接读，不必重算（细节见 vLLM 精读页 §2.2）。循环模型里，同一个物理层在第 1 遍和第 3 遍收到的输入不同，算出的 key、value 也不同。参数共享并不意味着 KV 也能共享。

所以 ALoDLM 给循环核心的每一层、每一遍都单独开一份缓存 \(\{K_{\ell}^{(d)},V_{\ell}^{(d)}\}\)。窗口里的位置在第 \(d\) 遍做注意力时，优先读前缀 token 在同一深度 \(d\) 的缓存；如果那个前缀 token 当时没跑到第 \(d\) 遍（它所在的那一步提前停了），就读它最深的一份。前奏和尾声每层只有一份缓存，尾声的缓存用最近一次读出分支的结果覆盖。论文明确说，这些“回退”和“共享尾声缓存”都是服务时的近似，和“每个前缀 token 在每个深度都重算一遍”的结果不一定相同；早退模型和循环模型（Depth-Adaptive Transformer、Huginn、Ouro）都要面对同样的问题。

代价是显存。总层数 \(L\)、循环层数 \(m\) 时，缓存的份数是 \(L+(K-1)m\)。8B 的 \(L=36\)、\(m=16\)、\(K=4\)，一共 84 份，其中 64 份属于循环核心。原来的 Qwen3-8B 只有 36 份，所以每个 token 的 KV 缓存是原来的 \(84/36\approx2.33\) 倍（推算）。这在批大小为 1 时不显眼，但在大批量服务时会直接限制能同时放下的请求数。另外，预填充（处理提示）时要为每个深度都算好缓存，这让首个 token 的延迟比 AR 模型长，论文在局限一节承认了这一点。

3.5 计算账：一遍要算多少层（附录 B.2）

设一步实际跑了 \(S\) 遍。前奏只跑一次，核心和尾声每遍都跑：

$$C_{\text{layers}}(S)=L_{\text{start}}+S\,(L_{\text{end}}-L_{\text{start}})+S\,(L-L_{\text{end}})$$

对 8B（\([10,26)\) 为核心），跑满 4 遍要算 \(10+4\times16+4\times10=114\) 层，而把整个 36 层模型跑 4 遍要 144 层。1.7B 版本没有前奏和尾声，28 层全部循环，所以是 \(28S\) 层。

4 方法（二）：训练时，把“第几遍提交”当成隐变量

这一节要回答的问题：ALoDLM 要同时学两样东西：一个去噪网络（预测被遮的 token），和一个停止策略（每个位置在第几遍提交）。停止决策是离散的，而且一个位置的决策会改变其他位置后面的计算，所以没法像普通网络那样直接反传，也没法像 Ouro 那样精确求和。作者怎样写出一个可以优化的目标？实际训练时又做了哪些放宽？
先补一点背景：掩码扩散的训练目标。

掩码扩散的训练很像“完形填空”：拿一条干净的序列 \(\mathbf{y}\)，随机抽一个比例 \(t\sim\mathrm{U}[0,1]\)，每个位置以概率 \(t\) 被遮成 [M]，得到 \(\mathbf{x}_t\)；让模型对每个被遮位置预测原词，损失是这些位置的交叉熵之和，再乘上 \(1/t\)。乘 \(1/t\) 是推导出来的权重：遮得越少的样本，每个被遮位置的权重越大。这样定义的损失是负对数似然的一个上界（推导见 MDLM、LLaDA 精读页）。ALoDLM 保留了这个框架，只是把“对每个被遮位置预测一次”换成了“沿着一条退出时刻的安排，分几遍预测”。

4.1 退出安排与它定义的似然

论文先定义退出安排（exit schedule）：对一个带遮挡的输入 \(\mathbf{x}_t\)，记被遮位置的集合为 \(\mathcal{M}_t\)，退出安排是一个向量 \(\mathbf{z}=(z_i)_{i\in\mathcal{M}_t}\)，每个分量取值于 \(\{1,\dots,K\}\)，\(z_i=s\) 表示位置 \(i\) 在第 \(s\) 遍之后提交。

\(\mathbf{x}_t\) 和 \(\mathbf{z}\) 一起完整地确定了一步去噪的过程：第 1 遍读出后，\(z_i=1\) 的位置提交；第 2 遍时它们以 token 嵌入的身份充当上下文，\(z_i=2\) 的位置在第 2 遍读出后提交；以此类推。训练时，提交进去的是正确答案的嵌入（相当于 AR 训练里的 teacher forcing），推理时则是模型自己的预测。于是在给定 \(\mathbf{z}\) 时，被遮 token 的似然可以分组写出来（附录式 12）：

$$p_{\theta}(\mathbf{y}_{\mathcal{M}_t}\mid\mathbf{x}_t,\mathbf{z})=\prod_{s=1}^{K}\ \prod_{i:\,z_i=s} p^{(s)}_{\theta,i}\big(y_i\mid \mathbf{x}_t,\ \mathbf{y}_{\text{更早退出的位置}};\mathbf{z}\big)=\exp\!\big[-\mathcal{L}_{\text{traj}}(\mathbf{z})\big]$$

可以把它理解成一种“按退出顺序分组的自回归”：同一遍退出的位置之间条件独立、并行预测；后一组以前面各组的答案为条件。\(\mathcal{L}_{\text{traj}}(\mathbf{z})\) 就是沿这条安排、每个位置在自己退出那一遍的交叉熵之和。

直接的想法是对所有安排求边际：\(p_{\theta}(\mathbf{y}_{\mathcal{M}_t}\mid\mathbf{x}_t)=\sum_{\mathbf{z}}\pi(\mathbf{z})\,p_{\theta}(\mathbf{y}_{\mathcal{M}_t}\mid\mathbf{x}_t,\mathbf{z})\)。但正如第 2 节算过的，安排的数量是指数级的，而且每种安排都要单独跑一次前向（跑到 \(\max_i z_i\) 遍为止），因为改动一个位置的退出时刻，就改变了其余位置后面看到的上下文。

4.2 条件 NELBO：用一个变分分布代替求和

先补一点背景：隐变量模型与证据下界（ELBO）。

如果一个模型写成“先抽隐变量 \(z\)，再生成数据”，即 \(p(y)=\sum_z\pi(z)\,p(y\mid z)\)，那么对数似然 \(\log p(y)\) 里是“对一个和取对数”，难算也难优化。变分推断的办法是：随便找一个关于 \(z\) 的分布 \(q(z)\)，由 Jensen 不等式可以得到

$$-\log p(y)\ \le\ \mathbb{E}_{z\sim q}\big[-\log p(y\mid z)\big]+D_{\mathrm{KL}}\big(q\,\|\,\pi\big)$$

右边就是负的证据下界（NELBO）。它只需要从 \(q\) 抽样，不需要遍历所有 \(z\)。当 \(q\) 恰好等于后验 \(p(z\mid y)\) 时，等号成立。变分自编码器（VAE）用的就是这套思路：\(q\) 是编码器，第一项是重建误差，第二项把编码分布拉向先验。

ALoDLM 把退出门当成这个变分分布 \(q_{\phi}(\mathbf{z}\mid\mathbf{x}_t,\mathbf{y}_{\mathcal{M}_t})\)：沿着一次实际的展开，每一遍对每个还没退出的位置，以概率 \(\lambda_i^{(s)}\) 抽“退出 / 不退出”。于是得到（式 5）：

$$J(\theta,\phi;\mathbf{x}_t,\mathbf{y})=\mathbb{E}_{\mathbf{z}\sim q_{\phi}}\Big[\underbrace{-\sum_{i\in\mathcal{M}_t}\log p^{(z_i)}_{\theta,i}(y_i\mid\mathbf{x}_t;\mathbf{z})}_{\mathcal{L}_{\text{traj}}(\mathbf{z})}\Big]+D_{\mathrm{KL}}\big(q_{\phi}\,\|\,\pi\big)\ \ge\ -\log p_{\theta}(\mathbf{y}_{\mathcal{M}_t}\mid\mathbf{x}_t)$$

附录的命题 2 证明了这个不等式，并指出差距正好是 \(q_{\phi}\) 与真实后验之间的 KL。先验 \(\pi(\mathbf{z})\) 仿照 PonderNet 取成各位置独立的截断几何分布：

$$\pi_{0,c}(d)=\frac{e^{-cd}}{\sum_{r=1}^{K}e^{-cr}},\qquad \pi_c(\mathbf{z})=\prod_{i\in\mathcal{M}_t}\pi_{0,c}(z_i)$$

\(c\) 越大越偏好早退。论文取 \(K=4\)、\(c=0.4\)，四个深度的先验概率约为 0.4131、0.2769、0.1856、0.1244，平均 2.02 遍。

4.3 梯度怎么算：单条轨迹 + score-function

先补一点背景：score-function 梯度估计（REINFORCE）。

当损失是“对一个离散随机变量取期望” \(\mathbb{E}_{z\sim q_{\phi}}[f(z)]\)，而 \(z\) 是抽样得到的，梯度没法沿着抽样那一步反传。score-function 估计用一个恒等式绕过去：\(\nabla_{\phi}\mathbb{E}_{q_{\phi}}[f(z)]=\mathbb{E}_{q_{\phi}}\big[f(z)\,\nabla_{\phi}\log q_{\phi}(z)\big]\)。直观地说：抽一个 \(z\)，看它的代价 \(f(z)\)；代价低就提高这个 \(z\) 的概率，代价高就降低。它无偏，但方差大；常用的补救是从 \(f(z)\) 里减去一个和 \(z\) 无关的“基线”，期望不变，方差变小。强化学习里的策略梯度就是这个方法。

训练时，每个样本只展开一次：按退出门的概率逐遍抽样，得到一条安排 \(\mathbf{z}\)，沿途算出各遍的交叉熵。去噪网络的参数 \(\theta\) 可以沿这条轨迹正常反传；退出门的参数 \(\phi\) 用 score-function。合起来，论文的代理损失是（式 7）：

$$\widehat{\mathcal{L}}_{\text{sur}}(\mathbf{z})=\frac{1}{t}\Big\{\mathcal{L}_{\text{traj}}(\mathbf{z})+\mathrm{sg}\Big[\mathcal{L}_{\text{traj}}(\mathbf{z})+\log\frac{q_{\phi}(\mathbf{z})}{\pi(\mathbf{z})}\Big]\log q_{\phi}(\mathbf{z})\Big\}$$

第一项训练去噪网络。第二项训练退出门：方括号里截断梯度的部分是这条安排的“总代价”（预测得有多差，加上偏离先验多远），它乘在这条安排的对数概率上。命题 1 证明，在“退出门的输入特征对 \(\theta\) 截断梯度”这个约定下，这个代理损失的梯度期望等于式 6 的真实梯度，是无偏的。

这里的“功劳分配”是整条序列一个分数：一条序列里所有位置、所有遍的停止决策，乘的是同一个总代价。论文认为这样能让每个停止决策对“整条序列的结果”负责（一个位置提前提交，可能帮了别的位置，也可能害了别的位置）。代价是信号很粗：一条 4,096 token 的打包序列里有成百上千个决策，只靠一个标量区分好坏，所以方差问题在这里格外突出。

论文还在脚注里提到另一条路：用 Gumbel-Softmax 一类的连续松弛让离散决策可微。作者没有采用，理由是那样就得定义“提交了一半”的 token 应该怎样喂回网络，会引入新的优化困难。

4.4 实际训练用的目标：三处放宽和一项附加损失

上面推出的 \(\widehat{\mathcal{L}}_{\text{sur}}\) 是理论目标。实际训练做了下面几处改动，论文自己也说明，命题 1 的无偏性针对的是原来那个“联合 KL”目标，不是实际实现的代理损失。

一、放宽 KL 项。原目标里的 \(\log\frac{q_{\phi}(\mathbf{z})}{\pi(\mathbf{z})}\) 会把每个位置的深度分布都拉向同一个几何先验，这和“不同 token 用不同深度”的初衷冲突。作者把它拆成两部分（附录式 24）：

$$R_{\alpha,\beta}=\frac{\alpha}{M}\sum_i D_{\mathrm{KL}}\big(r_i\,\|\,\bar{r}\big)+\beta\,D_{\mathrm{KL}}\big(\bar{r}\,\|\,\pi_{0,c}\big)$$

\(r_i\) 是位置 \(i\) 的深度分布，\(\bar{r}\) 是一个小批量里所有位置的平均深度分布。第一项惩罚“各位置之间的差异”，第二项要求“平均分布接近先验”。取 \(\alpha=\beta=1\) 时，期望上正好还原原来的联合 KL（附录定理 3）；论文用 \((\alpha,\beta)=(0.1,1)\)，也就是对平均深度管得严，对个体差异只轻轻地管，让不同 token 可以偏好不同深度。实际实现时，这两个分布还是用本次展开里的门输出近似的，论文称之为“基于展开的放宽”。

二、中间监督。式 7 只在每个位置被抽中的退出那一遍监督它。可同一次展开里，每一遍都已经读出了预测，扔掉可惜。作者把位置 \(i\) 在第 1 到第 \(z_i\) 遍的交叉熵按截断梯度后的权重加起来：\(\sum_{s\le z_i}\mathrm{sg}[\omega_i^{(s)}]\,\ell_i^{(s)}\)。权重 \(\omega_i^{(s)}\) 是退出门预测的“在第 \(s\) 遍退出”的概率，第 \(z_i\) 遍之后的概率全部并到第 \(z_i\) 遍上，保证权重加起来等于 1。这不需要多跑任何一遍。论文说明这个加权目标的梯度期望不一定和原目标相同，它的作用是降低去噪网络梯度的方差（第 5.4 节有测量）。

三、控制变量。退出门的代价里减去第 1 遍的交叉熵 \(\ell_i^{(1)}\)。第 1 遍的读出发生在任何提交之前，和抽到哪种安排无关，所以减掉它不改变梯度的期望，只减小方差（附录式 30）。

四、附加的 AR 损失。在同一批序列的干净副本上，再算一个普通的下一个 token 预测损失，权重和扩散损失相同。WeDLM、Nemotron-Labs-Diffusion 等“AR 转扩散”的工作都发现这样做有好处。按官方代码，这个 AR 损失也是在每一遍的读出上算、再对各遍取平均；最终损失是（去噪损失 + 退出门损失 + AR 损失）÷ 2。

按官方代码，一个被遮位置给退出门的代价是：

$$\text{cost}_i=\ell_i^{(z_i)}-\ell_i^{(1)}+0.1\,\big[\log q_i-\log\bar{q}(z_i)\big]+1.0\,\big[\log\bar{q}(z_i)-\log\pi(z_i)\big]$$

一条序列内所有位置的代价相加，乘以这条序列所有退出决策的对数概率之和，最后除以批里被遮位置的总数。

读的时候容易误解的地方：

一、训练和推理时，退出门扮演的角色不一样。训练时，每个位置何时退出是按退出门的概率逐个抽样的，退出后喂回去的是正确答案的嵌入。推理时，哪个位置提交由熵（或“最左边”）决定，退出门只把所有未解决位置的累积停止概率取平均，决定整步何时结束，喂回去的是模型自己的预测。两边的差异就像 AR 模型的 teacher forcing 与自由生成之间的差异，论文附录 C.1 提到了后者，但没有讨论前者。

二、论文与官方代码的一处出入。论文式 3 和算法 1 说，本步已经提交的所有位置在之后每一遍都用 token 嵌入；训练代码也是这样做的（每遍都用正确答案的嵌入覆盖已退出位置）。但官方的便携版解码器只在提交的那一遍之后换成嵌入一次，之后让它作为隐藏状态继续演化，生成文档里也是这样写的。这对结果的影响论文没有讨论。

三、“有原则的目标”与实际训练之间隔着几层放宽。KL 放宽、中间监督、AR 附加损失都不在 NELBO 推导之内，所以“我们优化的是一个似然下界”这个说法只对理论目标成立。论文也没有报告任何似然或困惑度，评测完全基于下游基准。

5.3 质量与速度的取舍

先补一点背景：为什么单请求时，多算几倍也可能更快。

一次只服务一个请求时，AR 模型每生成一个 token 都要把全部参数从显存读一遍，计算单元大部分时间在等数据（见 vLLM 精读页 §1）。以 Qwen3-8B 为例，BF16 参数约 16.4 GB（按 8.2B 参数推算）；B200 的显存带宽是 8 TB/s（NVIDIA 官方规格），读一遍约 2 毫秒，所以单请求 AR 解码的理论上限大约是每秒 490 个 token（推算，忽略 KV 读取和各种开销）。扩散模型的一次前向同时处理窗口里的十几个位置，读参数的时间几乎不变，算力又本来就闲着，所以只要一次前向平均能定下不止一个 token，它就能突破这个上限。反过来，当批大小很大、算力成为瓶颈时，“每个 token 多算几倍”就会实打实地变成更慢。

和 WeDLM 的速度—质量边界。作者对 ALoDLM-8B 试了 94 组 \((q,\tau)\)，对 WeDLM-8B 试了 21 组熵阈值，各自连出“前沿”（同样速度下准确率最高的那些点）。两条前沿在约 650 token/秒处相交：更追求准确率时 ALoDLM 更好，追求最快时 WeDLM 更好。在准确率都是 93.25% 的位置，ALoDLM-8B 每秒 612.4 个 token，WeDLM 是 564.2 个，快 8.5%。

只看计算量。吞吐量还取决于内核、显存访问和运行时开销，为了单独比较算术成本，作者用执行记录估算每生成一个 token 的浮点运算量：

$$\text{FLOPs/token}=\frac{2P_{\text{layer}}N_{\text{layer}}+2P_{\text{head}}N_{\text{head}}+4Hd_{\text{head}}\bar{L}N_{\text{layer}}}{N_{\text{gen}}}$$

\(N_{\text{layer}}\) 是“token × 层”的执行次数，\(N_{\text{head}}\) 是词表读出次数，\(N_{\text{gen}}\) 是生成的 token 数，\(P_{\text{layer}}\approx192.9\text{M}\) 是一层的稠密参数，\(P_{\text{head}}\approx622.3\text{M}\) 是输出头，\(\bar{L}\) 近似取“提示长度 + 一半生成长度”。这个估计包括预填充、窗口里被计算的所有位置、CUDA graph 的填充和实际执行的读出。在 93.25% 处，ALoDLM 每个 token 约 133.5 GFLOPs，WeDLM 约 154.6 GFLOPs，少 13.6%。

作为参照，同样的公式套在 AR 的 Qwen3-8B 上：每个生成 token 只算 36 层、1 次读出，\(2\times192.9\text{M}\times36+2\times622.3\text{M}\approx15.1\) GFLOPs，加上注意力项和摊到每个 token 上的预填充，大约在 15–25 GFLOPs 之间（推算，取决于提示长度）。也就是说，ALoDLM-8B 生成一个 token 的算术量约是 AR 的 5–9 倍，WeDLM-8B 还要更多（推算）。论文只拿 ALoDLM 和 WeDLM 比计算量，没有和 AR 比。

5.4 分析与消融

训练动态（图 4 左）。训练初期过后，越深的读出在它们“还在活跃的 token”上训练损失越低，作者认为这符合“逐遍细化”。要注意，各深度的损失是在不同的 token 子集上算的：第 4 遍还活跃的 token，是退出门在前 3 遍都没放走的那些，它们和第 1 遍的全部 token 不是同一批。所以“深的损失更低”既可能是因为多算了几遍，也可能部分来自子集不同。

测试时扩展（图 4 中）。提高推理时的阈值 \(q\)，ALoDLM-8B 的“每 token 循环数”从 1.60 升到 2.34，11 项平均分从 77.9 升到 79.1。作者据此说，循环深度是一条有效的测试时扩展轴。

6 局限：作者自己承认的，和本站补充的

这一节要回答的问题：作者认为 ALoDLM 在哪些情况下不划算？除了作者列出的两条，读者还应该注意哪些成本？

作者列了两条局限。第一，首个 token 的延迟比同尺寸的 AR 模型长，因为预填充时要为循环核心的每一个深度都建好 KV 缓存，第一批输出 token 之前还可能要先跑几遍细化。对于很短的回答或者对延迟敏感的场景，这部分开销会抵消并行解码的好处。第二，生成速度依赖输入：每一步跑几遍、一次能定下几个 token，都取决于模型的信心和退出门的判断，所以即使是贪心解码，不同提示、不同数据集、不同领域的吞吐量也会差很多；在训练数据覆盖少的领域，模型可能需要更多细化、更少并行提交，速度优势可能缩小，甚至比优化过的 AR 基线更慢。

结合前面几节，本站补充三条。一是显存：8B 每个 token 的 KV 缓存是 Qwen3-8B 的约 2.33 倍（推算），这会限制大批量服务时能同时容纳的请求数。二是训练成本：每个训练 token 要跑满 4 遍，单步训练计算量约为普通转换的 3 倍（推算）；“只做 SFT”节省的是数据，不一定是算力。三是许可：代码、文档和权重都是 CC BY-NC 4.0，只允许非商业使用；仓库里从 WeDLM 修改来的部分还保留了 WeDLM 原来的许可条款（包括地域限制）。

7 结论与案例：一段回答里，各个 token 在第几遍提交

这一节要回答的问题：作者最后怎样总结自己的贡献？附录 E 的案例图想让读者看到什么？

作者的总结是：ALoDLM 用按 token 自适应的潜空间循环缓解“计算量与难度不匹配”，一步之内有把握的 token 先提交、作为离散上下文，没把握的 token 保留并细化隐藏状态；条件 ELBO 把退出安排当隐变量，通过序列级的功劳分配来学习计算分配，再用中间监督帮助训练去噪网络；在 11 项基准上，两个规模都超过所有评测的扩散模型和对应的 Qwen3；在优化过的推理下，ALoDLM-8B 在 GSM8K 上的吞吐约为 vLLM 上 Qwen3-8B 的 2.7 倍，准确率相当。
