0 导读：这篇论文解决什么问题

扩散语言模型（diffusion LLM，下文简称 dLLM）生成文字的方式和 GPT 一类的自回归（AR）模型不同。它先在答案的位置放一整排被遮住的空位（[MASK]），然后一轮一轮地让模型同时猜所有空位，每一轮挑出其中一部分“定稿”，也就是把 [MASK] 换成真正的词，其余的留到下一轮再猜。因为一轮可以同时定稿好几个位置，人们自然期待它比一次只能写一个词的 AR 模型快。可现实是，开源的 LLaDA、Dream 要想保住准确率，几乎每一轮只能定稿一个词：写 256 个 token 就要 256 轮，每一轮还要把整段文字重新算一遍，所以它们反而比同样大小的 AR 模型慢。

此前的加速办法分两类。一类降低每一轮的成本，比如 dKV-Cache 和 Fast-dLLM 的近似 KV 缓存。另一类减少轮数，最常用的是 Fast-dLLM 的置信度阈值：每一轮把模型把握足够大的位置一起定稿。后者不需要训练，但在 LLaDA 上平均每轮也只能定稿三四个词，阈值再放低就开始掉分。dParallel 追问的是：为什么模型一次只对这么少的位置有把握？作者的观察是，模型的“把握”是从左往右一个接一个地出现的：每一轮只有紧挨着已知内容的少数位置变得确定，更远的位置要等前面的词定下来之后才变得确定。他们把这叫作确定性按顺序收敛，并认为这才是并行解码的真正瓶颈。阈值调得再低，也只是在模型还没把握时硬下决定，错误会一路传下去。

所以 dParallel 不去改采样规则，而是改模型本身。它提出确定性强制蒸馏（certainty-forcing distillation）：先让原模型对一批数学题提示生成答案，丢掉答错的；再用 LoRA 微调同一个模型，一方面用交叉熵让它在这些自己写出的答案上保持原样（“不偏离原来的生成轨迹”），另一方面对已经预测对的空位最小化预测的熵，逼它更早、更多地同时变得有把握。推理时配合熵阈值：当前块里熵低于阈值的空位在同一轮全部定稿。

论文最醒目的结果是：LLaDA-8B-Instruct 在 GSM8K 上，解码轮数从 256 降到 30，单条请求的延迟从 18.6 秒降到 2.2 秒（8.5 倍），准确率从 75.7% 变为 76.1%；在 MBPP 上轮数从 256 降到 24，加速 10.5 倍，准确率从 42.4% 变为 40.8%。训练只用 LoRA，论文说在 8 张 24 GB 的 A5000 上约 10 小时就能完成。读这些数字时要先记住几个条件：速度是在一张 RTX 6000 Ada 上一次处理一条请求测的，没有用 KV 缓存；8.5 倍是和同一个模型每轮只定稿一个词的默认解码比，不是和 AR 模型比，论文里也没有任何 AR 模型的速度对照。第 6 节末尾的“结果的份量”会把这些条件逐条拆开。

1 引言：号称能并行的模型，为什么一轮只写一个词

这一节要回答的问题：闭源的扩散语言模型已经展示过很高的生成速度，为什么开源模型做不到？已有的加速工作分成哪两类，它们各自卡在哪里？作者认为真正的瓶颈是什么，为什么普通的蒸馏训练解决不了它？
先补一点背景：“一轮”、前向次数与延迟。

dLLM 的每一轮（论文叫 decoding step，下文统一叫“一轮”或“一步”）都要把整段文字（提示加上所有生成位置，包括还是 [MASK] 的位置）送进模型完整地算一遍，这叫一次前向，算出的结果是每个 [MASK] 位置上词表的概率分布。模型再按某个规则挑出一部分位置定稿。所以轮数就是前向的次数（文献里常写 NFE，number of function evaluations）。

如果不用任何缓存，每一次前向要处理的长度都一样，耗时也几乎一样，于是总延迟 ≈ 轮数 × 每轮耗时。想加速，要么减少轮数，要么降低每轮耗时。dParallel 走的是前一条路。

与之对比，AR 模型每次前向只产出一个 token，但它可以把前面算过的 key/value 缓存起来（KV 缓存），每次只需要算新来的那一个 token，每次前向非常便宜。dLLM 的注意力是双向的，任何一个位置被定稿，所有位置的中间结果都会跟着变，所以不能直接照搬 KV 缓存（详见 dKV-Cache 精读 §1）。

论文开头先肯定了 dLLM 的潜力：双向注意力让它可以不按从左到右的顺序、一次并行地生成多个 token，闭源的 Mercury、Gemini Diffusion、Seed Diffusion 已经展示出很快的速度。但开源实现，比如 LLaDA 和 Dream，要维持生成质量，解码轮数仍然要和生成长度差不多，推理效率很有限。

已有的加速工作分两类。第一类降低每一轮的成本，主要是想办法让 dLLM 也能用上 KV 缓存（dKV-Cache、Fast-dLLM 等）。第二类改进并行采样算法，减少需要的轮数（置信度阈值等）。作者的判断是：这些工作都没能真正释放 dLLM 的并行潜力，因为只要并行度一高，性能就会下降。

作者把核心瓶颈归结为确定性的顺序收敛：虽然 dLLM 每一轮都对所有 [MASK] 位置同时给出预测，但这些预测的确定程度却是从左到右依次“收敛”的，只有紧挨着已知内容的位置先变得有把握。确定性一个位置一个位置地往右传，模型就无法可靠地在同一轮里同时决定很多个词。

先补一点背景：teacher forcing 与 diffusion forcing。

Teacher forcing 是训练序列模型最常见的做法：训练时总是把正确的前文喂给模型，让它预测下一个词，学的是“跟着给定的轨迹走”。Diffusion forcing（Chen 等，2024）原本用于视频等连续数据，它给序列里的每个位置独立地加不同强度的噪声，让模型学会在“前面干净、后面嘈杂”的各种混合状态下去噪；D2F 把它搬到了 dLLM 上。两者的目标都是让模型的输出对齐某条目标轨迹。

作者认为，单纯用 teacher forcing 或 diffusion forcing 来训练不够，因为它们只关心“预测得对不对、和轨迹是否一致”，并不关心“预测得有多确定”。一个模型完全可以在每个位置都把正确的词排在第一，却只给它 0.4 的概率；这样的模型在阈值解码下仍然不敢一次定稿很多位置。所以需要一种直接以“确定性”为目标的训练方式。

由此得到本文的方法：确定性强制蒸馏。让预训练好的 dLLM 沿着它自己原来的半自回归解码轨迹做自蒸馏，以保持轨迹一致；同时在已经预测对的 [MASK] 位置上最小化预测熵，逼出高确定性。这样，每一轮会有更多位置同时达到高确定性，并行解码的边界就被推远了。

论文在两个代表性的开源 dLLM 上验证：从零训练的 LLaDA，以及从 AR 模型（Qwen2.5-7B）初始化的 Dream。LLaDA-8B-Instruct 上，GSM8K 的解码轮数减少 88%（256 → 30），MBPP 减少 91%（256 → 24）。训练用 LoRA，引言称“在 8 张 24 GB 显存的 A5000 上约 10 小时”即可完成（附录 A 的说法不同，见 §7）。

读的时候容易误解的地方：引言里的“加速”全部是相对于同一个模型的默认 256 轮解码而言的，这是 dLLM 最慢的设置，每轮只定稿一个 token、不用任何缓存。论文没有把 dParallel 和任何 AR 模型比速度，所以“比 AR 快多少”这个问题，这篇论文本身回答不了（§6.7 引用了后续论文的第三方测量）。

2 相关工作：dParallel 在加速路线图上的位置

这一节要回答的问题：扩散语言模型从哪里来，现在有哪些分支？已有的 dLLM 加速方法各改的是哪一环，dParallel 和它们是替代关系还是可以叠加？

论文的相关工作分两段。第一段讲 dLLM 本身：扩散模型在图像生成上已经占主导，但用于文本一直很难；掩码扩散模型（MDLM、MD4、D3PM、SEDD 等）在离散空间里通过“预测被遮住的 token”来建模语言，为快速并行解码提供了可能；LLaDA 和 Dream 证明了十亿参数规模的 dLLM 能达到与 AR 模型相当的水平；此外还有推理型、多模态（如 MMaDA、LaViDa）和代码生成（如 DiffuCoder）的 dLLM。

第二段讲加速，作者把已有工作归成几类：用缓存机制和丢弃部分 token 来降低每一轮成本的；设计更好的采样策略来减少总轮数的；把 dLLM 和 AR 模型的生成方式结合起来、通过训练得到更高效推理流程的混合方法（如 D2F、块扩散 BD3-LM）；用渐进式蒸馏减少步数的 SDTT；以及用量化构造轻量 dLLM 的工作。

3 预备知识：掩码扩散怎样一轮轮写出答案

这一节要回答的问题：掩码扩散语言模型的训练目标和生成过程是什么？“半自回归分块解码”是什么意思？一轮同时定稿多个位置为什么会出错，置信度阈值和熵阈值又是怎样用“把握”来决定定稿哪些位置的？后面所有内容都建立在这几点上。

3.1 前向加噪与反向去噪

掩码扩散模型（MDLM）把生成看成两个方向相反的过程。前向过程负责“破坏”：给定一段干净的文本 \(x_{0}\)（长度 \(L\)），选一个噪声水平 \(t\in[0,1]\)，让每个 token 独立地以概率 \(t\) 被换成 [MASK]、以概率 \(1-t\) 保持原样，得到 \(x_{t}\)：

$$q(x_{t}\mid x_{0})=\prod_{i=1}^{L}\Big[(1-t)\,\delta\big(x_{t}^{i}=x_{0}^{i}\big)+t\,\delta\big(x_{t}^{i}=\texttt{[MASK]}\big)\Big]$$

\(t=0\) 时一个都不遮，\(t=1\) 时全部遮住。反向过程负责“复原”：一个网络 \(p_{\theta}\) 看着部分被遮住的 \(x_{t}\)，同时预测所有 [MASK] 位置原来是什么。关键在于，它对各个位置的预测是分开给出的：

$$p_{\theta}(x_{0}\mid x_{t})=\prod_{i:\,x_{t}^{i}=\texttt{[MASK]}}p_{\theta}\big(x_{0}^{i}\mid x_{t}\big)$$

这个乘积形式意味着：网络给每个空位一个独立的概率分布（边缘分布），但不直接告诉你“这几个空位的组合”是怎样的（联合分布）。这一点会在 §3.3 变得很重要。

训练目标是只在被遮住的位置上计算的负对数似然，并按 \(1/t\) 加权：

$$\mathcal{L}(\theta)=-\mathbb{E}_{t,\,x_{0},\,x_{t}}\left[\frac{1}{t}\sum_{i=1}^{L}\mathbf{1}\big[x_{t}^{i}=\texttt{[MASK]}\big]\log p_{\theta}\big(x_{0}^{i}\mid x_{t}\big)\right]$$

已有工作证明它是模型负对数似然的一个上界，所以最小化它就是在最大化似然的一个下界（推导见 MDLM 精读）。直观地说：随机遮掉一部分 token，让模型把它们猜回来，遮得多的样本猜起来更难，按 \(1/t\) 调整权重。这和 BERT 的完形填空很像，只是遮挡比例在 0 到 1 之间随机取。

3.2 采样：重掩码与半自回归分块

生成时从“答案区全是 [MASK]”出发，反复执行：模型对所有 [MASK] 位置同时给出分布，从中取出暂定的 token，再按某种重掩码（remasking）策略决定哪些位置真正定稿、哪些位置重新遮住留到下一轮。LLaDA 默认的策略叫 low-confidence remasking：每一轮按置信度（下面 §3.4 定义）排序，只定稿最有把握的固定个数，其余的重新遮住。

LLaDA 的指令模型通常还配合半自回归分块解码：把 256 个生成位置切成 8 块、每块 32 个，块与块之间从左到右依次处理，只有当前块（下文叫活动块）里的位置可以定稿，后面的块要等当前块全部写完才开始。块内仍然是并行、任意顺序的。之所以要分块，原因在 LLaDA 指令模型的训练数据里：微调时每条回答的末尾都补了大量结束符，模型因此对“答案区的末尾是一串结束符”非常有把握；如果不分块、全局按置信度挑位置，这些末尾位置会最先被定稿，留给正文的位置不够，回答被截短（详见 LLaDA 精读 对半自回归采样的讨论）。只许在当前块里定稿，就避开了这个问题，同时给生成加了一个“大致从左往右”的约束。论文所有实验都用这种方式，生成长度 256、块长 32。

这里顺便记住一件后面会用到的事：答案写完之后，256 个位置里剩下的部分会被结束符填满。这些位置对模型来说几乎没有悬念。

3.3 一轮定稿多个位置，为什么会出错

既然模型每一轮对所有空位都给出了预测，为什么不一轮多定稿几个？原因在于 §3.1 的乘积形式。设两个空位 \(i\)、\(j\) 的内容互相牵连，比如“从 ___ ___ 出发”里填城市名的两个词。正确的做法应该按联合分布 \(p(x_{i},x_{j}\mid\text{上下文})\) 一起选；但模型只给出两个边缘分布，同一轮定稿两个位置，相当于用乘积 \(p(x_{i}\mid\cdot)\,p(x_{j}\mid\cdot)\) 去代替联合分布。如果候选是 New York 和 San Diego，各占一半，那么两个位置各自独立地选，有一半的机会拼出 New Diego 或 San York 这种不存在的组合。如果一轮只定稿一个位置，选了 New 之后，下一轮模型看到 New，自然会把 York 的概率推到接近 1，错误就不会发生。这就是为什么保守的解码要一轮一个。

先补一点背景：置信度阈值解码（Fast-dLLM）。

Fast-dLLM 给出了一个简单的折中：每一轮，对活动块里所有 [MASK] 位置算出置信度（该位置概率最大的那个词的概率），把置信度不低于阈值 \(\tau\)（常用 0.9）的位置全部定稿；如果一个都没达到，就只定稿置信度最高的那一个，保证每轮至少前进一步。直觉是：一个位置已经有九成把握时，它和别的位置拼错的空间很小，同时定稿是安全的。Fast-dLLM 的定理把这个直觉写成了严格的条件，证明过程见 Fast-dLLM 精读 §4。

下面的小演示可以直接调阈值。画布是一句订机票的话，出发地和目的地都是两个词的城市名，同一个城市名的两半必须配对。阈值调低，每轮定稿的 token 变多、轮数变少，但同一轮揭开两半、拼出错误组合的概率也会上升。演示是按温度 1 抽样的，比论文的贪心设置更容易暴露问题，但道理相同。

阈值解码的好处是“个数不固定”：容易的地方一轮可以定稿很多个，难的地方自动退回一轮一个。它的上限也由此决定：模型自己在什么时候、对多少位置有把握。如果模型本来就只对紧挨已知内容的一两个位置有把握，阈值规则再聪明也只能一轮定稿一两个。dParallel 正是从这里切入的。

3.4 两种“把握”的量法：置信度与熵

设模型在某个位置输出的分布是 \(p(v)\)，\(v\) 取遍词表 \(\mathcal{V}\)。置信度是最大概率 \(\max_{v}p(v)\)；熵是

$$H(p)=-\sum_{v\in\mathcal{V}}p(v)\log p(v)$$

熵为 0 表示把全部概率压在一个词上（完全确定），熵越大表示越犹豫。两者大致是同一件事的两种量法，但熵还考虑了“剩下的概率是集中在一两个对手上，还是散在很多词上”。dParallel 推理时用的是熵阈值：熵低于阈值的位置定稿，LLaDA 版的阈值是 0.5（MBPP 用 0.45），Dream 版是 0.45（数学）或 0.5（代码），均见官方评测脚本。

为了把熵阈值和置信度阈值对应起来，可以算两个例子（推算，单位是 nat，即自然对数）。如果剩下的概率全给了一个对手，熵 0.5 大约对应最大概率 0.80；如果剩下的概率平分给 10 个对手，熵 0.5 大约对应最大概率 0.91。所以熵阈值 0.5 大致相当于“置信度 0.8 到 0.9 以上”，比 Fast-dLLM 常用的 0.9 略宽松或相当，具体取决于剩余概率的分布形状。

容易混淆的一点：论文实验里的“置信度阈值解码”基线用的是置信度阈值 0.90 或 0.95，而 dParallel 自己用熵阈值 0.45 或 0.5。两种阈值单位不同，不能直接说谁更激进；比较时应看最终的轮数和准确率。

4 瓶颈：模型的“把握”是一个接一个出现的（原文 §4.1）

这一节要回答的问题：dLLM 在原理上可以一次预测很多 token，实际上却做不到，差距出在哪里？作者用 LLaDA-8B-Instruct 在 GSM8K 上做了两组观察：确定性与正确率有什么关系？确定性在解码过程中是怎样分布、怎样变化的？由此能推出什么样的训练目标？

4.1 观察一：定稿时越有把握，答案越可能对

第一组实验验证一个前提：token 层面的确定性是不是预测正确与否的可靠信号。作者用 LLaDA-8B-Instruct 在 GSM8K 测试集上做阈值解码，扫一组不同的置信度阈值；每个阈值下，记录所有被定稿 token 在定稿那一刻的平均置信度，以及最终答案的正确率。

原文图 2(a) 的横轴是“定稿时的平均置信度”，纵轴是 GSM8K 正确率，每个点对应一个阈值。两者几乎单调地一起上升：最左边的点平均置信度约 0.55，正确率只有约 5%；最右边的点平均置信度约 0.95，正确率约 76%（读图约值）。作者由此得出结论：高确定性是准确生成的必要条件，在低置信度时就下决定，经常会出错。

这张图证明了什么、没证明什么：图上的每个点是一整套解码设置，而不是单个 token。阈值放低时，被定稿 token 的平均置信度降低，同时每轮定稿的个数增加、出错后能修正的余地减少，这几件事是一起变的。所以这张图说明的是“逼模型在没把握时定稿会掉分”，而不是“单个 token 的置信度能精确预测它对不对”。好在论文后面的论证只需要前一个结论。

4.2 观察二：确定性按从左到右的顺序收敛

第二组观察是全文的核心。作者发现高确定性并不是在各个位置上同时出现的，而是沿着序列一个接一个地“传”过去。在任何一轮，模型都对所有 [MASK] 位置给出预测，但只有一小部分位置的置信度很高，通常就是紧挨着已知内容的那几个；绝大多数位置一直停留在低置信度，直到新的上下文出现。一旦有一个高置信度的 token 被定稿，它就成为新的条件，使得下一批位置在下一轮变得有把握。

原文图 2(b) 画的是位置 0 到 64 上的平均置信度，每条曲线对应一个解码轮次（第 0、4、8、……、32 轮）。曲线的形状都像一道向右移动的“台阶”：台阶左边的位置置信度接近 1，台阶右边迅速掉到 0.1–0.2 左右；随着轮次增加，台阶向右推进，到第 32 轮时第一块（前 32 个位置）全部接近 1，第二块的位置仍然很低（读图）。原文图 2(c) 换了一个角度，画了第 0、4、……、28 号位置各自的置信度随轮次的变化：第 0 号位置一开始就有约 0.9，越靠后的位置起点越低（第 28 号约 0.17），而且要越晚才升到接近 1，一条接一条错开（读图）。两张图说的是同一件事：高确定性不是并行出现的，而是随着上下文一点点丰富而依次展开的。

4.3 瓶颈在哪里，出路在哪里

把两组观察合在一起，作者得出了本文的诊断。真正的并行要求在一轮里定稿很多个 token；可 dLLM 每一轮只对少数相邻位置有高确定性。如果强行在同一轮里定稿更多位置，就必然要定稿一些低置信度的预测（观察二），而低置信度的定稿常常是错的（观察一）。错的 token 一旦定稿，又会成为后续预测的条件，错误层层传递，性能随之崩溃。所以瓶颈不在采样规则，而在模型的确定性动态本身。

出路也就清楚了：如果能引导模型在多个位置上同时达到高确定性，就能打破这种顺序传递。作者再次强调，teacher forcing 和 diffusion forcing 这类传统训练只追求轨迹对齐，忽视了预测确定性的动态，不足以做到这一点；需要一种直接以确定性为训练信号的新范式，这就是下一节的确定性强制蒸馏。

4.4 本站的解读：为什么“提前确定”是可能的

读到这里，一个自然的疑问是：远处的位置没把握，难道不是理所当然的吗？一道数学题的推理写到一半，后面每一步写什么，确实取决于前面写了什么。如果模型诚实地反映了数据的不确定性，远处位置的分布本来就应该是分散的。逼它在远处“变确定”，会不会只是逼它变得盲目自信？

这里的关键在于训练目标是模型自己的贪心输出，而不是人类写的各种答案。论文推理时用的是温度 0 的贪心解码（官方代码中 temperature=0），对同一个提示，贪心解码永远给出同一个答案。也就是说，“这个提示 → 这个答案”是一个确定的函数，答案里每个位置写什么，原则上在看到提示的那一刻就已经决定了。原模型之所以对远处没把握，并不是因为答案本身不确定，而是因为它没能在一次前向里“预演”自己后面会怎样写。确定性强制蒸馏要求模型学会这种预演：在答案还只写了一部分时，就对自己将来会写的词有把握。

这个视角还能解释为什么提前确定能让并行定稿变得安全。§3.3 说过，并行定稿出错，是因为用边缘分布的乘积代替了联合分布。如果联合分布本身就集中在一个答案上，每个位置的边缘分布也都集中在这个答案的对应词上，那么边缘分布的乘积就等于联合分布，同时定稿不会拼错。下面的小例子把这一点画出来。

这个解读同时指出了方法的边界。第一，模型一次前向的计算量是固定的，要在一次前向里“预演”一长串推理，任务越难越做不到；所以可以预期，难题（如 MATH）上能压缩的轮数更少、掉分更多，§6 的结果确实如此。第二，蒸馏的代价是多样性：模型被训练成在自己的贪心答案附近非常尖锐，如果要用较高的温度采样多个不同答案（例如强化学习或自洽投票），效果可能不同；论文没有测试这种用法。第三，“已经预测对”的定义依赖于目标就是模型自己的答案，这也解释了为什么熵项只加在正确位置上（§5.4）。

5.1 教师轨迹：让原模型自己写答案

记教师模型为 \(M_{\theta_{T}}\)，就是预训练好的原版 dLLM；学生模型 \(M_{\theta_{S}}\) 初始化为它的一个完全相同的拷贝。训练集 \(\mathcal{D}=\{X^{(i)}\}_{i=1}^{K}\) 里只有指令提示，没有答案。对每个提示，教师用半自回归重掩码策略生成一个答案 \(Y=(y_{1},\dots,y_{L})\)，总长 \(L\)、块长 \(L_{b}\)，于是 \(Y\) 被切成 \(N=L/L_{b}\) 个连续的块 \(B_{1},\dots,B_{N}\)，第 \(n\) 块是 \(B_{n}=(y_{(n-1)L_{b}+1},\dots,y_{nL_{b}})\)。

先补一点背景：LoRA（低秩适配）。

学生模型是在教师的拷贝上微调出来的，但并不更新全部 80 亿个参数。全量微调的显存开销很大：光是 bf16 精度的 8B 权重就要约 16 GB，Adam 优化器还要为每个参数保存两份 fp32 状态，再加梯度，远超一张 24 GB 显卡（推算）。LoRA 的做法是冻结原来的权重矩阵 \(W\)，只学习一个低秩的增量 \(\Delta W=BA\)：若 \(W\) 是 \(d\times d\) 的矩阵，\(B\) 是 \(d\times r\)、\(A\) 是 \(r\times d\)，秩 \(r\) 远小于 \(d\)。以一个 4096×4096 的投影矩阵、\(r=32\) 为例，原矩阵有约 1,680 万个参数，LoRA 只需训练 2×4096×32≈26 万个，约 1.6%（推算）。

训练完成后，把增量按缩放系数 \(\alpha/r\) 合并回原权重，\(W'=W+\tfrac{\alpha}{r}BA\)，得到的模型结构和原模型完全一样，推理时没有任何额外开销。dParallel 官方配置列出的 LoRA 目标层是注意力的 q/k/v/o 投影和前馈层的 gate/up/down 投影，并用 DeepSpeed ZeRO-2 把优化器状态放到 CPU 内存里，这是它能在 24 GB 显卡上训练的原因。这组名字是 Qwen / LLaMA 系模型的命名，Dream 正好对得上；LLaDA 的模型代码里注意力输出和前馈层另有名字（attn_out、ff_proj、ff_out），按名字匹配的话 LLaDA 上实际只有 q/k/v 和 up_proj 会加上 LoRA（本站读代码的推断，未实际运行验证）。用 LoRA 还隐含了一个好处：改动被限制在一个低秩子空间里，学生不容易偏离教师太远，这和“保持原轨迹”的目标是一致的。

对 LLaDA，提示来自 GSM8K 训练集、PRM12K 训练集和部分 Numina-Math 数据集，教师按生成长度 256、块长 32 生成答案，再把最终答案错误的样本过滤掉，最后得到约 92k 条（官方公开的 LLaDA 蒸馏数据集有 92,428 条）。所有训练目标 token 都由模型自己生成，没有引入任何外部答案作为监督目标。

为什么要用自己生成的答案？因为目标是“不改变模型的行为，只改变它到达这个行为的速度”。如果拿人类写的答案或更强模型的答案来训练，学生会被拉向另一种写法，准确率的变化就分不清是来自更好的数据还是来自方法本身。用自己的答案，学生只需要学会“更早地知道自己会写什么”。过滤掉错误答案则带来一个小副作用：这相当于在模型自己的正确答案上做了一轮拒绝采样微调，可能顺带提高一点准确率。

“沿着轨迹”的准确含义：论文说学生“沿着原始轨迹自蒸馏”，但实际训练只用了教师生成的最终序列 \(Y\)，并没有记录教师每一轮的中间状态（哪个位置在第几轮定稿）。中间状态是下一小节用半自回归掩码“模拟”出来的。后来的 d3LLM 正是在这一点上改进：它记录教师的定稿顺序，用来构造更逼真的中间状态。

5.2 半自回归前向掩码：在训练里重现“写到一半”的状态

推理时模型看到的输入是这样的：前面几块已经写完，当前块写了一部分，后面的块全是 [MASK]。如果训练时用预训练那种“整段随机遮挡”，学生看到的输入就和推理时很不一样。所以作者设计了一个结构化的前向掩码：先均匀抽一个块号 \(n\in\{0,\dots,N-1\}\)，再把序列分成三部分。

$$\tilde{y}_{i}=\begin{cases}y_{i}, & i\le nL_{b}\quad(\text{上下文块})\\ \texttt{[MASK]}\ \text{（概率 }q\text{）或 }y_{i}\ \text{（概率 }1-q\text{）}, & nL_{b}\lt i\le(n+1)L_{b}\quad(\text{活动块})\\ \texttt{[MASK]}, & i\gt(n+1)L_{b}\quad(\text{未来块})\end{cases}$$
  • 上下文块（前 \(n\) 块）全部保持干净，扮演“已经写完的部分”。
  • 活动块（第 \(n+1\) 块）里每个 token 以概率 \(q\) 换成 [MASK]，扮演“正在写的块”。论文固定 \(q=0.5\)。
  • 未来块全部遮住，扮演“还没开始写的部分”。

这样得到的 \(\tilde{Y}\) 就是半自回归生成过程中的一个中间状态：模型在已知前 \(n\) 块的情况下，正在生成第 \(n+1\) 块。注意活动块的掩码位置是随机选的，而不是按教师的真实定稿顺序，所以它模拟的是“写到一半”的大致样子，而不是教师真实走过的那一步。

论文 vs 官方代码

官方 llada_train.py 有两处论文正文没写的细节。① 互补掩码：对同一个样本，代码还会把活动块的掩码“取反”（原来遮住的露出来、原来露出的遮住）再算一遍前向和两项损失，四项相加。这样活动块里每个 token 在一对样本中恰好被监督一次，附录 A 用一句话提到这是为了“提高 token 利用率”。② 块号的抽取范围包括“最后一块之后的剩余部分”，LLaDA 的训练序列（提示加答案）统一用结束符填充或截断到 384 个 token，所以答案后面的填充区也会被当作活动块训练。复现以代码为准。

5.3 一致性损失：别偏离原来的答案

与标准预训练“预测整段所有被遮住的 token”不同，dParallel 只在活动块里被遮住的位置上计算损失，记这些位置的集合为 \(\mathcal{M}_{a}\)。未来块虽然也全是 [MASK]，却不参与损失。第一项是普通的交叉熵，要求学生在这些位置上预测出教师答案里原来的 token：

$$\mathcal{L}_{\text{Consistency}}=-\frac{1}{|\mathcal{M}_{a}|}\sum_{i\in\mathcal{M}_{a}}\log p_{\theta}\big(y_{i}\mid\tilde{Y}\big)$$

它的作用是“锚定”：学生的生成结果要和教师一致，才能保证准确率不变。只监督活动块，是因为推理时真正要定稿的只有活动块；未来块在推理时也会被预测，但不会被定稿，不需要专门训练。

作者指出，只有交叉熵还不够。交叉熵只关心“对不对”：一旦正确的词已经排在第一，它的梯度很快变小，不会再有多大动力去继续提高置信度。下一小节的图会把这一点量化。

5.4 确定性损失：只在已经预测对的位置上压低熵

为了直接鼓励高确定性，作者加了第二项：最小化输出分布的熵，并且只作用在活动块里学生已经预测对的那些被遮住位置上。先定义这个集合：

$$\mathcal{M}_{c}=\Big\{\,i\in\mathcal{M}_{a}\ \Big|\ \arg\max_{v\in\mathcal{V}}p_{\theta}\big(v\mid\tilde{Y}\big)=y_{i}\Big\}$$

也就是 argmax 已经等于目标 token 的位置。确定性损失是这些位置上带温度 \(T\) 的分布的平均熵：

$$\mathcal{L}_{\text{Certainty}}=\frac{1}{|\mathcal{M}_{c}|}\sum_{i\in\mathcal{M}_{c}}\Big(-\sum_{v\in\mathcal{V}}p_{\theta}\big(v\mid\tilde{Y};T\big)\log p_{\theta}\big(v\mid\tilde{Y};T\big)\Big)$$

其中 \(p_{\theta}(v\mid\tilde{Y};T)\) 是把 logits 除以 \(T\) 再做 softmax 得到的分布。最小化它，会让学生在正确 token 上给出更尖锐、更确定的分布。

为什么只在预测对的位置上压熵？熵项本身不知道哪个词是对的，它只会把当前排第一的词推得更高。如果对所有位置都压熵，那些预测错的位置也会被推成“自信地错”，阈值解码就会放心地把错词定稿，正好放大了 §4.3 说的错误级联。限定在 \(\mathcal{M}_{c}\) 上，熵项只做一件事：把已经对的预测变尖。预测错的位置交给交叉熵去纠正。

温度 \(T\) 起什么作用？论文只说“\(T\) 控制确定性强制的强度”，并取 \(T=0.5\)。argmax 不受温度影响，所以 \(T\) 不改变哪些位置算“预测对”，只改变熵项梯度的形状。为了看清这一点，本站在“只有两个候选词”的玩具情形下算了一下各项损失对“正确词比对手高多少”（logit 差 \(d\)）的梯度大小：

5.5 总目标与训练算法

总的训练目标是两项之和：

$$\mathcal{L}_{\mathrm{CFD}}=\mathcal{L}_{\text{Consistency}}+\beta\,\mathcal{L}_{\text{Certainty}}$$

\(\beta\) 平衡“贴住教师轨迹”和“逼出高确定性”两个目标，附录 A 说所有训练都取 \(\beta=2\)。原文算法 1 把一次迭代写成以下几步：

  1. 从数据集中取一条教师生成的序列 \(Y\)，均匀抽一个块号 \(n\)。
  2. 用半自回归前向掩码得到画布 \(\tilde{Y}\) 和活动块的掩码位置 \(\mathcal{M}_{a}\)。
  3. 学生对 \(\tilde{Y}\) 做一次前向，得到每个位置的 logits \(z_{i}\)，分别算出普通分布 \(p_{i}=\mathrm{softmax}(z_{i})\) 和温度分布 \(p_{i}^{(T)}=\mathrm{softmax}(z_{i}/T)\)。
  4. 在 \(\mathcal{M}_{a}\) 上用 \(p_{i}\) 算交叉熵。
  5. 找出 \(\mathcal{M}_{c}\)；如果它非空，就在上面用 \(p_{i}^{(T)}\) 算平均熵，否则这一项记为 0。
  6. 两项按 \(\beta\) 加权相加，更新学生参数（实际只更新 LoRA 参数）。

作者强调这个蒸馏策略非常简单，却能显著加快 dLLM 确定性的并行收敛。值得注意的是，“教师”在训练中只出现在第一步（生成数据），之后不再参与计算：没有教师 logits 的 KL 散度，也不需要同时把两个模型放进显存。这也是它训练成本低的原因之一。

5.6 推理：熵阈值的半自回归解码

论文在 §5.1 用一句话交代推理方式：使用熵阈值的半自回归重掩码，这和训练目标天然一致。结合官方代码 LLaDA/generate.py，具体规则如下：

  1. 生成长度 256、块长 32，块从左到右依次处理。
  2. 每一轮对整张画布做一次前向（不开 KV 缓存），算出活动块里每个 [MASK] 位置的熵（温度 1）。
  3. 熵低于阈值（LLaDA 版在 GSM8K、MATH、HumanEval 上用 0.5，MBPP 上用 0.45）的位置全部定稿为各自概率最大的词；熵最低的那个位置无论是否达到阈值都定稿，保证每轮至少前进一个。
  4. 活动块全部定稿后进入下一块，直到 8 块都写完。

由此可以推出两个容易忽略的事实（推算）。第一，生成 256 个 token 至少需要 8 轮（每块至少一轮），所以“每轮定稿 token 数”的理论上限是 32。第二，代码不会在写出结束符后提前停止：答案写完之后，剩下的位置会被结束符填满，这些位置非常容易预测，往往一轮就能定稿一大片。所以 30 轮写完 256 个位置，并不等于每一轮都写出 8.5 个“有内容”的词。

训练与推理的温度不同：训练时熵项用的是 \(T=0.5\) 的分布，推理时判断阈值用的是温度 1 的分布。这并不矛盾：训练时用低温只是为了塑造梯度（§5.4），推理时看的是模型真实输出的分布。

6 实验：少了多少轮，掉了多少分（原文 §5）

这一节要回答的问题：在两种开源 dLLM、四个数学与代码基准上，dParallel 能把轮数压到多少，准确率变化多大？和免训练的阈值解码、只开缓存、直接减少轮数、一致性蒸馏相比如何？两项损失和半自回归掩码各自贡献了什么？最后，这些数字是在什么条件下测出来的，能推广到什么程度？

6.1 实验是怎么设计的

模型。两个代表性的开源 dLLM：从零训练的 LLaDA-8B-Instruct，以及从 AR 模型初始化的 Dream-7B-Instruct；附录另外测了经过强化学习后训练的 LLaDA-1.5。训练都用 LoRA。半自回归掩码的块长，LLaDA 取 \(L_{b}=32\)，Dream 取 \(L_{b}=256\)（等于整段答案，原因见 §6.3）；掩码率固定 50%；熵项温度 \(T=0.5\)。

数据。LLaDA 版见 §5.1，约 92k 条，全部是数学题。Dream 版用同样的方法生成数学数据，另外用 AceCode 数据集的约 10k 条提示生成代码数据（官方公开的 Dream 蒸馏数据集共 122,434 条，论文正文没有给出总数）。

先补一点背景：四个基准各考什么。

GSM8K 是小学数学应用题，测试集 1,319 道，答案是一个数；论文在题目后面加一句“请一步步推理”（chain-of-thought 提示），0-shot。MATH 是竞赛数学题，难得多，测试集 5,000 道（评测框架里的 minerva_math 版本）；LLaDA 用 4-shot，Dream 用 0-shot。HumanEval 是 164 道 Python 函数补全题，按单元测试是否全部通过计分（pass@1）。MBPP 是 500 道入门级 Python 编程题；LLaDA 用 3-shot，Dream 用 0-shot 的指令版。四个基准的答案都比较“确定”：一道题的正确推理或正确代码，写法虽然不唯一，但远比开放式写作集中。

知道题量很有用：GSM8K 上 1 个百分点约等于 13 道题，HumanEval 上约等于 1.6 道题，MBPP 上是 5 道题，MATH 上是 50 道题（推算）。

指标与硬件。报告准确率、平均解码轮数、延迟和加速比。所有效率测量都在 NVIDIA RTX 6000 Ada 上进行。官方评测脚本一次只处理一条请求（批大小 1），用贪心解码，不开 KV 缓存；加速比是延迟之比。

对照组。原模型用官方默认设置（256 轮）。另外四个加速基线：

  • Dual-Cache：Fast-dLLM 的双向近似 KV 缓存，前缀和后缀的 key/value 都缓存，轮数仍是 256。它降低的是每轮成本。
  • Few-step Decoding（下文称“固定 64 步”）：直接把原模型的轮数减到 64，即每轮固定定稿 4 个。
  • Conf-threshold Decoding（置信度阈值）：Fast-dLLM 式的自适应定稿，阈值按任务取 0.90 或 0.95。
  • Consistency Distillation（一致性蒸馏）：仿照图像领域的潜在一致性模型（LCM），训练模型从自身轨迹上的中间状态一次预测出全部剩余的 [MASK] token；训练数据和 LoRA 配置与 dParallel 相同，作者自己实现，评测时用 64 轮。

论文给出的两个具体数字是：LLaDA 上，在相同的 9.4 倍加速下，dParallel 在 GSM8K 上比置信度阈值高 16.5 个百分点；在相同的 9.3 倍加速下，HumanEval 上高 21.3 个百分点。从图上估读，LLaDA / HumanEval 上置信度阈值在约 5.4 倍时就掉到约 24%，在约 9 倍时只剩约 7%；dParallel 一直到约 8.2 倍都保持在约 40%（读图约值）。

这条曲线比较的是什么：两条曲线一条是“训练后的模型 + 熵阈值”，一条是“原模型 + 置信度阈值”，所以它同时包含了“训练”和“换一种阈值”两个因素。论文没有给出“原模型 + 熵阈值”或“训练后的模型 + 置信度阈值”的曲线，无法把两者的贡献完全拆开。不过消融实验（§6.6）里“只有一致性项”的模型也用熵阈值解码，却只到 4.5 倍，说明主要的提升来自训练而不是阈值的种类。原图见 原文图 4 ↗。

6.5 确定性真的提前并行收敛了吗（原文图 5、图 6）

为了直接验证机制，作者把 §4.2 的观察重做了一遍：原文图 5 画出 LLaDA-8B-Instruct 在 GSM8K 上，第 8 轮和第 16 轮时前 160 个位置的平均置信度，对比原模型、原模型加置信度阈值、dParallel 三条曲线。原模型的高置信区只覆盖最左边一小段；置信度阈值把这段推得更远一些，但形状仍是一道窄窄的波前；dParallel 的高置信区则宽得多，下降也平缓得多。估读曲线降到 0.5 的位置：第 8 轮时三者约在第 17、28、75 个位置；第 16 轮时约在第 26、44、150 个位置（读图约值）。附录图 6 用前 16 轮、前 160 个位置的完整图景重复了同样的结论。

6.7 结果的份量：这些数字是在什么条件下得到的

这一小节逐条列出读 dParallel 的数字时应该带上的条件。

① 分母是最慢的解码方式。8.5 倍、10.5 倍的分母，是同一个模型每轮只定稿 1 个 token、跑满 256 轮、不开任何缓存的默认解码。在这种设置下，每轮耗时几乎恒定，所以“延迟加速”基本就等于“轮数减少的倍数”。按表 1 推算，GSM8K 上原模型每轮约 72.7 毫秒，dParallel 每轮约 73.3 毫秒；MATH 4-shot 上分别约 198.8 和 193.5 毫秒。dParallel 没有让每一轮变快，只是让轮数变少。

② 硬件、批大小与实现。所有速度都在一张 RTX 6000 Ada（工作站显卡）上测得；评测脚本一次只处理一条请求，用 PyTorch / Hugging Face 风格的实现，不开 KV 缓存（README 明确说明论文结果没有使用缓存或稀疏注意力）。批大小 1 是 dLLM 最占便宜的场景：此时 GPU 远没有被算满，每轮多定稿几个 token 几乎不增加耗时。批变大之后，每轮前向本身更贵；而且阈值解码下每条请求需要的轮数不同，一个批要等最慢的那条，轮数减少带来的收益可能缩水。论文没有测试批大小大于 1 的情况（本站分析）。

③ 论文里没有 AR 对照，后续论文给出了一个。dParallel 本身没有和任何 AR 模型比速度。后来的 d3LLM 论文（arXiv 2601.07568）在自己的评测协议下重测了 dParallel-LLaDA：在 H100、批大小 1、Hugging Face 后端、GSM8K-CoT 上，它每秒生成 172.2 个 token，是同样条件下 Qwen-2.5-7B-Instruct（57.3）的 3.0 倍；在 A100 上是 105.9 对 50.4，约 2.1 倍；准确率 72.6% 对 74.1%（d3LLM 论文表 1、表 3）。但这里的 AR 基线也跑在没有专门优化的 Hugging Face 后端上；同一篇论文在 SGLang 推理引擎上测得 Qwen-2.5-7B-Instruct 在 H100 上为 108.6 token/秒（表 15）。如果拿这个数当分母，Hugging Face 后端的 dParallel 只剩约 1.6 倍（推算；两边引擎不同，只能说明数量级）。

④ “每轮 8.5 个 token”的口径。256 ÷ 30 ≈ 8.5 这个数里，包括了答案写完后用来填满 256 个位置的结束符（§5.6）。这些位置极易预测，会大幅拉高平均值。同一个 dParallel-LLaDA 在 d3LLM 的评测里（提示、计数方式与 EOS 处理都不同），GSM8K-CoT 上每次前向定稿 5.14 个 token、准确率 72.6%；在 MATH、MBPP、HumanEval 上分别是 3.17、2.35、4.93 个（d3LLM 论文表 1）。两套口径的数不能混用，但它提醒我们：“有内容的 token 每轮写几个”比论文的 8.5 要少。

⑤ “准确率不降”有多确定。论文每个数字只跑一次，没有报告方差。用题量换算（推算）：GSM8K 上 +0.4 个点约等于多对 5 道题，HumanEval 上 +1.8 个点约等于 3 道题，都在一次运行的随机波动范围内；MATH 上 −2.0 个点约等于少对 100 道题，MBPP 上 −1.6 个点约等于 8 道题，Dream 的 MBPP 上 −2.6 个点约等于 13 道题。所以更准确的说法是：在 GSM8K 和 HumanEval 上没有可见的损失，在 MATH 和 MBPP 上有一到两三个点的小幅下降。

⑥ 任务范围窄。四个基准都是答案相对确定的数学和代码任务，生成长度都固定在 256，LLaDA 版的训练提示也全是数学题。开放式写作、对话、长文本（几千 token）的生成都没有测试。按 §4.4 的解读，答案越不确定、推理链越长，“提前确定”越难，收益可能更小。

⑦ 对照组的取舍。表里有 Dual-Cache 和置信度阈值，却没有两者合在一起的完整 Fast-dLLM，也没有 dParallel 加缓存。作为参照，Fast-dLLM 论文在 LLaDA、MATH 4-shot、生成长度 256 上报告的“阈值 + DualCache”是 5.7 倍、33.2%（A100，Fast-dLLM 论文表 1），与 dParallel 在 MATH 上的 5.7 倍、31.5% 数字上相近。但两篇论文的硬件、提示和答案抽取都不同（例如两篇论文测出的原版 LLaDA 的 MBPP 分数就差了十几个点），这个对比只能说明：在长提示任务上，免训练的“减轮数 + 降每轮成本”组合已经能拿到相当的加速；dParallel 的价值在于把“轮数”这一个因子压得更低，而它本可以再乘上缓存的收益。另外，一致性蒸馏基线是作者自己实现的，只在固定 64 轮下评测。

dParallel 于 2025-09-30 发布在 arXiv 上（只有 v1，PDF 页眉标为 Preprint，arXiv 备注写着“Working in progress”），官方 README 记录代码、模型和数据于 2025-10-01 公开（Hugging Face 上 Dream 版权重的创建时间是 2025-10-14），2026-01 被 ICLR 2026 接收为 poster。截至 2026-10，它已经成为“训练式并行解码”这条线上被频繁拿来对比的基线。下面按与本页的关系依次介绍。

本站整理，细节见各自的精读页。

  • dKV-Cache 出自同一个实验室（新加坡国立大学 xML Lab，Xinyin Ma 等），解决的是“每一轮太贵”。它和 dParallel 一个压每轮成本、一个压轮数，dParallel 的 README 也致谢了它的代码。论文表格里的 Dual-Cache 基线来自 Fast-dLLM，不是 dKV-Cache。
  • D2F 同样用 LoRA 从双向 dLLM 蒸馏，但它把注意力改成“块内双向、块间因果”，用精确 KV 缓存和块间流水线同时压低每轮成本和轮数，并直接和 AR 模型比速度。dParallel 不改结构，所以训练后的模型可以原样替换原模型、继续用原来的推理代码。
  • d3LLM（UCSD 等）几乎是 dParallel 的直接续作：它沿用 dParallel 的确定性损失（温度 0.5，熵权重 LLaDA 2.0、Dream 1.0）、互补掩码和蒸馏数据集，换掉的是构造中间状态的方式（记录教师的定稿顺序，称为伪轨迹），并加上掩码率与窗口的课程、多块并行解码和 KV 刷新。在 d3LLM 自己提出的 AUP 指标下，dParallel 在 LLaDA 组的五个任务上都排第二，仅次于 d3LLM；GSM8K-CoT 上的每次前向 token 数是 5.14 对 9.11（d3LLM 论文表 1）。

同一团队的后续：DMax

2026-04，同一组作者发布了 DMax（官方 README 称已被 NeurIPS 2026 接收，本站未从会议官网核实）。它针对的是 dParallel 留下的问题之一：并行解码一旦定错，掩码扩散模型没有机会改正。DMax 把解码改写成从 mask 嵌入到 token 嵌入的逐步自我修正，提出“在线策略的均匀扩散训练”（On-Policy Uniform Training），让模型既能从 [MASK] 也能从自己的错误预测里恢复正确 token，并配合“软并行解码”。按其摘要，在 LLaDA-2.0-mini 上 GSM8K 的每次前向 token 数从 2.04 提到 5.47、MBPP 从 2.71 提到 5.86，准确率基本保持；在两张 H200 上批大小 1 时平均 1,338 token/秒。

还没有回答的问题

  • 和缓存叠加。dParallel 与 Fast-dLLM / dKV-Cache 的缓存原则上可以相乘地叠加，README 也这样声称，但论文没有报告叠加后的结果；d3LLM 在自己的框架里做了类似的组合。
  • 采样多样性。按 §4.4 的解读，蒸馏让模型在自己的贪心答案附近变得非常尖锐。它对温度采样、多样本投票、强化学习后训练有什么影响，目前没有看到系统研究。旧版拆解页提到的 TraceRL 观察到 RL 后训练本身也会提高动态解码的每步 token 数，两者能否结合仍是开放问题。
  • 更广的任务。所有报告都集中在数学和代码上；在开放式生成、长文本上能否保持收益，还没有独立的复现。

想看 dParallel、d3LLM、CDLM 三者的并排拆解、伪代码与简答题，见旧版结构拆解页（其中 CDLM 把图像侧的一致性蒸馏搬到 token 轨迹上，并改用块因果注意力换取精确缓存）。
