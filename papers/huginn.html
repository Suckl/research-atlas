0 导读：这篇论文解决什么问题

让语言模型在回答之前“多想一会儿”，是近两年提升推理能力最有效的办法。主流做法是让模型先写出一长串思维链（chain-of-thought），也就是把中间步骤一个词一个词地说出来，再给出答案。这条路很有效，但代价也很具体：要用专门构造的长推理示范去训练模型；上下文会越拉越长，KV 缓存随之膨胀；而且模型每一步内部的计算，最后都必须被压缩成一个离散的词，才能被下一步读到。

这篇论文走另一条路：不让模型多说，而是让它对每个词多算几遍。作者把 Transformer 拆成三段：开头几层（前奏）把输入映射到一个连续的潜空间，中间一组层（循环块）在潜空间里反复更新一个状态，最后几层（尾声）把状态解码成下一个词的概率。循环块的权重只有一份，可以执行任意多次。训练时每一步随机抽一个循环次数，于是模型学会了在“多算几轮”时把答案改得更好；测试时想多花算力，只要把循环次数调大。

作者用这个设计从零训练了一个 3.5B 参数、看过约 8000 亿 token 的模型，叫 Huginn-0125（Huginn 是北欧神话里象征“思想”的渡鸦），训练在美国橡树岭国家实验室的 Frontier 超算上用 4096 张 AMD MI250X GPU 完成。结果是：在 GSM8K、MATH、HumanEval 这类需要推理的任务上，循环次数从 1 加到 32，分数从接近零涨到可观的水平；它在数学和代码上超过了大部分同类全开源模型。作者还展示了循环结构的几个副产品：同一个模型不经任何额外训练，就能做到逐 token 提前退出、跨迭代共享 KV 缓存、自己给自己打草稿做投机解码。

但这篇论文的数字需要仔细掂量。“3.5B 参数”只是存储意义上的大小：循环 32 次时，每个 token 的计算量相当于一个约 50B 参数的普通模型；按论文自己的说法，它的预训练算力接近一个 32B 的普通模型。本站粗算它的训练总算力与同期的 OLMo-2-7B 相当，而 OLMo-2-7B 的综合分数明显更高。第 5 节专门用一个小节讨论这些结果的份量。

1–2 引言与动机：不多说，而是多算

这一节要回答的问题：既然让模型写思维链已经能提升推理，为什么还要再找一条增加测试时计算的路？作者认为在潜空间里循环有四个好处：不需要专门数据、更省内存、更省通信、更容易学到“算法”而不是死记硬背。这些好处里，哪些有证据，哪些只是期望？这两节篇幅都很短，所以放在一起讲。
先补一点背景：一个 token 要花多少计算，“测试时计算”指的是什么。

Transformer 生成一个 token 时，输入从第一层一直穿到最后一层。粗略地说，模型的每个参数都要参与一次乘法和一次加法，所以前向计算一次大约需要 \(2N\) 次浮点运算（FLOP），\(N\) 是参数量。举例来说，一个 7B 模型每生成一个 token 大约要 14 GFLOP（推算）。训练时还要做反向传播，反向的计算量大约是前向的两倍，所以人们常用“每个训练 token 约 \(6N\) FLOP”来估算训练总算力。这两个估算在本页会反复用到。

“测试时计算”（test-time compute）指模型回答问题时花掉的计算量。在这篇论文之前，要让同一个模型回答时多花算力，基本只有一种办法：让它生成更多 token，比如先写一长段思维链，或者生成很多个候选答案再挑一个。本文要加的是第三种办法：不改变 token 数，让每个 token 在模型内部多走几遍中间的层。

为什么“深度”和推理有关？一个固定深度的 Transformer，对每个 token 能做的串行计算步数，被层数限死了：如果模型有 32 层，它在吐出一个词之前最多只能“连续想” 32 步。思维链之所以有用，一个解释就是它绕开了这个上限：模型把中间结果写成文字，下一步再读回来，相当于把串行计算借到了“时间”这个维度上。循环深度则是直接把这个上限变成一个可以调节的旋钮。

作者的出发点是一个类比：人在说出第一个词之前，大量思考已经在大脑里通过反复的神经活动完成了，并不需要先用语言表达出来。而当时主流的推理模型（如 OpenAI o1、DeepSeek-R1）是通过后训练，让模型把中间计算“说出来”。这样一来，模型每一步内部丰富的连续表示，最后都要投影成一个离散的词才能传给下一步。作者认为这是一种浪费：如果模型能直接在自己的连续潜空间里“想”，也许能想得更好。

实现这个想法最直接的办法，是给模型加一个循环单元，让它反复处理并更新自己的隐藏状态。这个想法本身并不新，几乎每十年都会被重新发现一次：循环神经网络、扩散模型、Universal Transformer 和 looped Transformer 都是它的不同化身（见本批次的 Universal Transformers 与 Looped Transformers as Programmable Computers）。本文的新意不在于提出循环，而在于证明：这种循环深度的语言模型可以在数十亿参数、数千亿 token 的规模上稳定训练，测试时能靠循环提升推理表现，并且天然支持几种原本需要专门训练的推理技巧。

第 2 节列出了作者认为循环比思维链更好的四个理由。下面逐条讲清楚它的因果，并标出本站的保留意见：

  • 不需要专门构造的训练数据。思维链模型要在目标领域的长示范上训练，模型才学会“把思路写出来”。循环模型只需要普通的预训练数据，训练时随机改变计算预算，就能学会在给更多计算时做得更好。保留意见：Huginn 的预训练数据里其实混入了大量指令数据，而且严重偏向代码和数学（第 4 节），所以“不需要专门数据”只在“不需要长推理示范”这个意义上成立。
  • 训练和推理都更省内存。思维链需要很长的上下文，训练时可能要用到序列并行之类的专门技术；循环模型不增加上下文长度。保留意见：如果每次迭代的 KV 缓存都保留，KV 缓存会随循环次数线性增长，循环 32 次时每个 token 要存 132 层的 KV（第 6.2 节有估算）。所以省内存要靠第 6 节的 KV 共享来兑现。
  • 每个参数做更多计算，所以加速器之间通信更少。数据并行训练时，每一步各张卡要同步一份完整的参数梯度，通信量和参数量成正比，和计算量无关。循环模型参数少、计算多，在互联较慢的机器上更容易把芯片用满。这一点在第 4 节的 AMD 集群训练中确实兑现了。
  • 更容易学到“方法”而不是死记硬背。作者希望“计算多、参数少”的结构能形成一种先验，迫使模型学习策略、逻辑和抽象，而不是记忆。这一点此前在小规模算法任务上有证据（“deep thinking”系列工作：在迷宫、前缀和等任务上，循环网络训练后能通过多迭代外推到更难的题）。但在大语言模型上，这仍然只是期望；第 5 节开卷、闭卷问答的对比可以算作一点间接证据。

作者还提出一个更带哲学色彩的期望：空间想象、物理直觉、运动规划这类难以用语言表达的推理，也许更适合在连续空间里进行；在高维向量里迭代，也许能同时探索多个方向，而不是像文字那样只能线性地一步步写。最后，作者把循环深度定位成与“扩大参数”和“延长思维链”并列的第三个扩展维度，三者并不冲突，可以叠加。

读的时候容易误解的地方：摘要里说模型可以把性能提升到“相当于 50B 参数的计算负载”，这里的“相当于”指的是每个 token 的计算量：循环 32 次时，展开后的参数量约 52.6B，每个 token 的 FLOP 和一个 50B 左右的普通 Transformer 相同。它不是说效果和 50B 模型相当。实际效果要看第 5 节的对照，那里会看到它离同样计算量的普通模型还差得很远。

3 架构：前奏、循环块、尾声

这一节要回答的问题：一个能在测试时任意加深的 Transformer 应该怎么搭？为什么不把整个网络都循环起来，而是只循环中间一段？输入为什么要在每一次迭代都重新“注入”，初始状态为什么用随机噪声？层内的归一化为什么要用一种叫“三明治”的结构？最后，训练时循环次数怎么定，梯度怎么回传？这一节是全文方法的全部，分三部分讲。

3.1 宏观设计：三段式结构与输入注入

先约定记号：\(n\) 是序列长度，\(h\) 是隐藏维度，\(V\) 是词表。模型由普通的仅解码器 Transformer 层组成，但这些层被分成三组，各司其职：

  • 前奏（prelude）\(P\)：几层 Transformer，把输入 token 嵌入到一个潜空间里，输出记为 \(\mathbf{e}\)。
  • 循环块（recurrent block）\(R\)：一组 Transformer 层，是循环计算的核心。它反复更新一个潜状态 \(\mathbf{s}\in\mathbb{R}^{n\times h}\)，每个位置一个 \(h\) 维向量。
  • 尾声（coda）\(C\)：几层 Transformer 加上输出头，把最终的潜状态解码成下一个 token 的概率。

给定循环次数 \(r\) 和输入序列 \(\mathbf{x}\in V^{n}\)，整个前向过程写成：

$$\mathbf{e}=P(\mathbf{x}),\qquad \mathbf{s}_0\sim\mathcal{N}\!\left(\mathbf{0},\,\sigma^{2}I_{n\cdot h}\right),\qquad \mathbf{s}_i=R(\mathbf{e},\mathbf{s}_{i-1})\ \ (i=1,\dots,r),\qquad \mathbf{p}=C(\mathbf{s}_r)$$

逐项解释：\(\mathbf{e}\) 是前奏输出的“嵌入后的输入”，算一次就固定下来，整个循环过程中不变。\(\mathbf{s}_0\) 是一个随机初始化的潜状态，每个位置、每一维都独立地从均值为 0、标准差为 \(\sigma\) 的正态分布里抽。之后每一次迭代，循环块同时读入上一轮的状态 \(\mathbf{s}_{i-1}\) 和不变的 \(\mathbf{e}\)，输出新的状态 \(\mathbf{s}_i\)。迭代 \(r\) 次后，尾声把 \(\mathbf{s}_r\) 解码成概率 \(\mathbf{p}\in\mathbb{R}^{n\times|V|}\)。

先补一点背景：把循环看成“迭代求解”，以及“路径无关”是什么意思。

作者用梯度下降来解释为什么要这样设计。假设我们想找一个 \(\mathbf{x}\)，使函数 \(E(\mathbf{x},\mathbf{y})\) 最小，\(\mathbf{y}\) 是数据。梯度下降从一个随机起点 \(\mathbf{x}_0\) 出发，反复执行同一个简单操作 \(\mathbf{x}_{k+1}=\mathbf{x}_k-\eta\nabla E(\mathbf{x}_k,\mathbf{y})\)。注意，每一步都要用到数据 \(\mathbf{y}\)：如果只在开头把 \(\mathbf{y}\) 交给起点，之后不再看它，那么迭代最终停在哪里，只取决于起点，和要解的问题无关。循环块就像这里的“一步更新”，\(\mathbf{e}\) 就像数据 \(\mathbf{y}\)，所以每次迭代都要把 \(\mathbf{e}\) 重新送进去。这种做法叫输入注入（input injection），来自 Bansal 等人 2022 年的工作。论文脚注给了更严格的说法：如果 \(R\) 不依赖 \(\mathbf{e}\)，它就不可能是一个单调算子，因而不能表示“在依赖数据的严格凸函数上做梯度下降”这类稳定的迭代。

路径无关（path independence，Anil 等人 2022）指的是：不管迭代从哪个初始状态出发，最终都会走到同一个稳定状态（或同样的稳定行为）。这个性质的好处是，测试时多迭代几次不会“跑偏”，循环次数可以外推到训练时没怎么见过的值。随机初始化 \(\mathbf{s}_0\) 正是为了逼出这个性质：如果训练时起点总是同一个固定值，模型可能学会依赖这个起点；每次都换一个随机起点，模型只能学会一个“从哪里出发都能收敛”的迭代规则。

为什么不循环整个网络，而要保留专门的前奏和尾声？作者引用了对普通 Transformer 的分析：模型开头的几层和最后的几层，与中间层的行为明显不同。开头几层要把被切碎的子词拼成完整的概念，最后几层要把概念映射回词表；而中间层彼此相似，甚至可以互换顺序。所以只循环“中间那段处理概念的部分”最自然，开头和结尾各留几层专用的层。

论文还在一个附注里回答了“这是不是扩散模型”的疑问。这种“从噪声出发、反复迭代”的结构确实很像潜空间扩散模型，作者也试过更像扩散的变体，结果都不好：

  • 每次迭代额外加一点噪声，即 \(\mathbf{s}_i=R(\mathbf{e},\mathbf{s}_{i-1})+\mathbf{n}\)：在初步实验里没有帮助，作者推测这与训练目标有关。
  • 把当前是第几步告诉循环块，即 \(\mathbf{s}_i=R_i(\mathbf{e},\mathbf{s}_{i-1})\)（扩散模型里常见的“时间步条件”）：它破坏了路径无关，训出的模型不能外推到更多的循环次数。

所以最终的循环块并不知道自己在第几次迭代。记住这一点，第 7 节会看到模型似乎在潜空间里自己“数步数”。

3.2 微观设计：层内结构与模型尺寸

每一组里的每一层都是标准设计：因果自注意力加门控 SiLU 前馈网络；位置编码用 RoPE，基数取 50000（RoPE 的原理见 RoFormer 精读）；归一化用 RMSNorm；只有 query 和 key 带可学习的偏置，其他地方都没有偏置。真正不标准的是归一化放在哪里。

先补一点背景：残差流，以及归一化放在哪里。

Transformer 的每一层都是“残差”形式：输入 \(x\) 先经过一个子层 \(F\)（注意力或前馈网络），再把结果加回输入，\(x\leftarrow x+F(x)\)。这条不断被“加东西”的主干叫残差流。归一化层的位置有两种经典放法：

  • 前置归一化（pre-norm）：\(x\leftarrow x+F(\mathrm{norm}(x))\)。子层的输入被归一化了，但残差流本身从不归一化，每过一层都会再加一点东西，数值大小会随层数增长。
  • 后置归一化（post-norm）：\(x\leftarrow\mathrm{norm}(x+F(x))\)。每层之后都把残差流拉回固定大小，数值不会失控，但很深的网络会更难训练。

对普通的 32 层模型，前置归一化通常更好训。但 Huginn 循环 32 次时等效有 132 层，而且是同一组权重反复作用在同一个状态上：只要每次迭代让状态的范数涨一点点，涨上 128 次就会失控。这就是循环模型需要额外归一化的原因。

作者采用了一种“三明治”排布，子层前、子层后、加完残差之后都做归一化（\(n_1\) 到 \(n_4\) 是四个 RMSNorm）：

$$\hat{\mathbf{x}}_l=n_2\!\big(\mathbf{x}_{l-1}+\mathrm{Attn}(n_1(\mathbf{x}_{l-1}))\big),\qquad \mathbf{x}_l=n_4\!\big(\hat{\mathbf{x}}_l+\mathrm{MLP}(n_3(\hat{\mathbf{x}}_l))\big)$$

和后置归一化一样，残差流在每个子层之后都被拉回固定尺度，所以无论循环多少次，状态都不会越滚越大；和前置归一化一样，子层的输入也是归一化过的。作者说，在小规模上各种归一化方案（前置、后置等）效果都差不多，但到了大规模，只有这种排布能把循环训出来（第 4.3 节的两次失败就是证据）。论文脚注还坦白：严格说 \(n_3\) 是多余的（本站的理解是，\(\hat{\mathbf{x}}_l\) 刚被 \(n_2\) 归一化过），保留它只是为了如实报告最终模型的结构。

三段各自的细节如下：

  • 前奏：先把 token 通过嵌入矩阵 \(E\) 变成向量，再乘一个嵌入缩放系数 \(\gamma\)（实际取 \(\sqrt{h}\)，见第 4.1 节），然后过 \(l_P\) 层上面那种三明治层。
  • 循环块：开头是一个适配器 \(A:\mathbb{R}^{2h}\to\mathbb{R}^{h}\)，它把上一轮状态 \(\mathbf{s}_{i-1}\) 和注入的 \(\mathbf{e}\) 拼接成 \(2h\) 维，再线性映射回 \(h\) 维；接着过 \(l_R\) 层；最后再用一个 RMSNorm \(n_c\) 把输出缩放回来。作者说，小模型里用“相加”（\(\mathbf{s}+\mathbf{e}\)）代替拼接效果一样，但规模大了以后拼接最好。
  • 尾声：\(l_C\) 层，然后用同一个 \(n_c\) 归一化，再用和嵌入矩阵共享的权重 \(E^{T}\) 投影到词表（权重绑定）。

整个结构可以用三元组 \((l_P,l_R,l_C)\) 加循环次数 \(r\) 描述。作者在小规模实验里用 \((1,4,1)\)、隐藏维度 \(h=1024\)；正式的大模型是 \((2,4,2)\)、\(h=5280\)。也就是说，大模型只有 8 个“真实”的层，但循环 32 次时，展开后的等效深度是 \(2+4\times32+2=132\) 层，按论文的说法，这比最深的固定深度 Transformer 还要深。第 4.1 节补充了其余尺寸：55 个注意力头、每头 96 维（55 × 96 = 5280），前馈网络中间维度 17920，词表 65536；参数量约为前奏加尾声 1.5B、循环块 1.5B、共享的嵌入矩阵 0.5B，合计约 3.5B。官方配置里键值头数也是 55，也就是没有用分组查询注意力（GQA），这一点在估算 KV 缓存时会用到。

两个“参数量”不要混：“3.5B”是每个权重只数一次的存储大小，决定了显存占用和数据并行时的通信量。“展开后参数量”（materialized parameters）是按使用次数计数，循环块每执行一次就再数一次，它决定每个 token 的计算量。官方模型卡给的经验公式是“展开后参数量 ≈ 1.5B × 循环次数 + 2B”；原文图 1 的刻度对应约 1.58B × r + 2.0B，例如 r = 32 时为 52.6B。

3.3 训练目标：随机循环次数与截断反向传播

如果训练时永远循环 32 次，模型很可能学会“恰好 32 步后给出答案”的特定节奏，测试时换成别的循环次数就会出错。为了让模型在任意循环次数下都能工作，作者沿用 deep thinking 系列的做法：每个训练样本随机分配一个循环次数。训练目标是对数据和循环次数两者同时取期望：

$$\mathcal{L}(\theta)=\mathbb{E}_{\mathbf{x}\sim X}\;\mathbb{E}_{r\sim\Lambda}\;L\big(m_\theta(\mathbf{x},r),\,\mathbf{x}'\big)$$

这里 \(m_\theta(\mathbf{x},r)\) 是循环 \(r\) 次时模型的输出，\(\mathbf{x}'\) 是把序列左移一位得到的“下一个 token”目标，\(L\) 是普通的交叉熵，\(\Lambda\) 是循环次数的分布。关键在于 \(\Lambda\) 怎么选。

先补一点背景：泊松分布与对数正态分布。

泊松分布 \(\mathcal{P}(\lambda)\) 描述“平均发生 \(\lambda\) 次的随机事件实际发生了几次”，取值是 0、1、2…，均值和方差都等于 \(\lambda\)。例如 \(\lambda=28\) 时，抽到的数大多落在 28 ± 5 左右。它的问题是太“集中”：几乎不会抽到比均值大一倍的数。

对数正态分布：先从正态分布抽一个 \(\tau\)，再取 \(e^{\tau}\)。结果总是正数，而且右边拖着一条长尾巴。一个有用的性质是：如果 \(\tau\sim\mathcal{N}(\mu,\sigma)\)，那么 \(e^{\tau}\) 的均值是 \(e^{\mu+\sigma^{2}/2}\)，比 \(e^{\mu}\) 大一点。

把两者叠起来，先用对数正态分布抽一个“速率” \(\lambda\)，再用泊松分布按这个速率抽一个整数，得到的就是对数正态—泊松分布。它的大部分取值集中在均值附近，但偶尔会抽到很大的数。

论文的具体抽样方式是（\(\bar r\) 是目标均值参数，\(\sigma\) 取 \(1/2\)）：

$$\tau\sim\mathcal{N}\!\Big(\log\bar r-\tfrac{1}{2}\sigma^{2},\ \sigma\Big),\qquad r\sim\mathcal{P}\big(e^{\tau}\big)+1$$

减去 \(\tfrac12\sigma^2\) 正好抵消上面说的那个“均值会大一点”，使 \(e^{\tau}\) 的均值恰好等于 \(\bar r\)；最后的 “+1” 保证至少循环一次，于是 \(r\) 的均值是 \(\bar r+1\)。Huginn 取 \(\bar r=32\)，所以训练时平均循环 33 次。

走一遍抽样（推算）。先算正态分布的中心：\(\mu=\ln 32-\tfrac12\times0.5^{2}=3.466-0.125=3.341\)，对应 \(e^{\mu}\approx28.2\)。
  • 某一步抽到 \(z=+1\)（比平均高一个标准差）：\(\tau=3.341+0.5\times1=3.841\)，速率 \(\lambda=e^{3.841}\approx46.6\)；再从泊松分布抽，结果大多在 47 ± 7 之间，比如抽到 \(r=50\)。
  • 另一步抽到 \(z=-1.5\)：\(\tau=2.591\)，\(\lambda\approx13.3\)，于是 \(r\) 大约是 14。
  • 抽到 \(z=0\)：\(\lambda\approx28.2\)，\(r\) 大约 29，这正是整个分布的中位数。
把所有情况积分起来（本站数值计算）：均值 33、中位数 29，与原文图 3 标注的一致；5% 的步数循环不超过 12 次，95% 的步数不超过 67 次；约 5.8% 的步数超过 64 次，约 0.7% 超过 100 次。另一端，循环次数 ≤ 8 的步数只占约 1.4%，≤ 4 的约 0.1%，恰好等于 1 的概率约十万分之一。原文图 3 标注的众数是 24（本站积分得 23，差别来自原图是抽样直方图）。

为什么要长尾？因为测试时我们希望模型循环 64 次甚至更多时依然稳定。如果训练时从来没见过这么多的循环次数，测试时就是“分布外”。长尾让模型偶尔练习很深的展开，又不至于让平均训练成本太高。正式版附录补了一组小规模消融（132M 参数、10B token）：对数正态—泊松分布的验证困惑度 12.97，Irwin–Hall 分布 12.99，Schwarzschild–Bansal 方案 13.16，指数分布 13.26，Gamma 13.31，几何分布与均匀分布都是 13.33。差别不大，而且每种只跑了一次；作者也承认，规模大了之后换一个分布可能会更好，只是算力只够在小规模上做一次选择。

先补一点背景：截断反向传播。

训练普通的循环神经网络处理很长的序列时，如果把梯度一路传回第一个时间步，要存下每一步的中间结果，显存和计算都会随长度线性增长。常见的折中是截断的随时间反向传播（truncated BPTT）：只对最后 \(k\) 步回传梯度，更早的步骤只做前向，不记录梯度。代价是模型学不到跨越很多步的长程依赖。

Huginn 把这个技巧搬到了“深度”方向：循环 \(r\) 次时，前 \(r-k\) 次迭代只做前向、不保存中间结果，只有最后 \(k\) 次迭代参与反向传播，论文固定 \(k=8\)。这样一来，一个训练步的激活显存和反向计算量与 \(r\) 无关，所以才敢用上面那个长尾分布：即使抽到 \(r=120\)，反向也只走 8 次迭代，不会爆显存。官方代码的写法是：先抽出 \(r\)，不回传梯度的迭代数取 \(\max(r-8,0)\)，回传梯度的迭代数取 \(\min(r,8)\)；所以当 \(r\le 8\) 时，所有迭代都回传梯度。按上面的分布，每步平均回传 7.98 次、不回传 25.0 次（推算）。

前奏会不会因此收不到梯度？不会。因为 \(\mathbf{e}\) 被注入到每一次迭代里，包括最后那 8 次，所以最后 8 次迭代的梯度会沿着 \(\mathbf{e}\) 流回前奏。作者说，在小规模上固定 \(k=8\) 和随机抽 \(k\) 效果一样；固定的好处是每一步的显存占用都相同，便于在大集群上排布。

读的时候容易忽略的两点：

初始化。小规模时几乎任何合理的初始化都能用，但大规模时作者改用 Takase 等人（2024）的方案，所有权重的方差取 \(\sigma_h^2=\frac{2}{5h}\)，从截断在 \(\pm3\sigma\) 的正态分布里抽。各层的输出投影更小，方差取 \(\sigma_{\text{out}}^2=\frac{1}{5hl}\)，其中 \(l=l_P+\bar r\,l_R+l_C=2+32\times4+2=132\) 是按平均循环次数展开后的等效层数。道理是：残差流上要累加 132 次子层输出，每次加的东西必须足够小，总和才不会一开始就失控。嵌入层的输出再乘以 \(\sqrt{h}\)；为了和它的尺度匹配，随机初始状态 \(\mathbf{s}_0\) 也从截断正态分布里抽，方差 \(\sigma_s^2=\frac{2}{5}\)。代入 \(h=5280\)，\(\sigma_h\approx0.0087\)、\(\sigma_{\text{out}}\approx5.4\times10^{-4}\)、\(\sqrt{h}\approx72.7\)（推算），与官方配置文件里的数值一致。

同步抽样。分布式训练时，如果每张卡各自抽循环次数，抽到小 \(r\) 的卡要等抽到大 \(r\) 的卡做完反向，白白空转。所以作者让同一个微批次在所有卡上共用一个 \(r\)。小规模实验显示这提高了利用率、不拖慢收敛；但作者也指出，在很大的批量下，给每张卡独立抽 \(r\) 并调度好，能更忠实地近似公式里的期望。后来的 Parcae 就改成了“每条序列各抽各的”，并报告这能减少损失尖峰。

优化器与学习率。用带解耦权重衰减的 Adam（\(\beta_1=0.9\)、\(\beta_2=0.95\)），加上更新裁剪（Wortsman 等人 2023）并去掉了 Adam 分母里的 \(\varepsilon\)（Everett 等人 2024）；梯度范数超过 1 时裁剪。学习率在前 4096 步内预热到峰值，然后一直保持不变，不做衰减。常数学习率的好处是可以随时续训（下面会看到他们的算力是一段一段申请到的），坏处是模型从未经历“退火”带来的那一截提升（第 5.4 节）。

4.2 算力与硬件：4096 张 AMD MI250X

先补一点背景：数据并行、优化器分片、梯度检查点，以及 MFU。

数据并行：每张卡放一份完整模型，各自处理不同的数据，每一步结束时所有卡把梯度加起来（all-reduce）再各自更新。通信量和参数量成正比，和每张卡算了多少无关。参数太多、一张卡放不下时，就要把模型本身切开（张量并行、流水线并行，见 Megatron-LM 精读），那会带来频繁得多的通信。优化器分片（ZeRO-1，见 ZeRO 精读）把 Adam 的动量和方差切到不同卡上，省显存而几乎不增加通信。梯度检查点是前向时不保存中间激活、反向时再重算一遍，用计算换显存。

MFU（模型 FLOP 利用率）是“实际完成的有效 FLOP/s ÷ 芯片标称峰值”。本文还用了一个 AFU（可达 FLOP 利用率），分母换成在这台机器上实测能达到的最好矩阵乘速度，所以 AFU 总是比 MFU 高。

训练在橡树岭国家实验室的 Frontier 超算上完成，算力来自美国能源部的 INCITE 计划。Frontier 是 HPE Cray 系统，有 9408 个计算节点，每个节点 4 张 AMD MI250X 卡，通过 4 块 Slingshot-11 网卡互联；任务用 SLURM 调度；训练用 bfloat16 混合精度和 PyTorch。

  • 单卡速度。每张 MI250X 标称 bfloat16 算力 383 TFLOP，但它是双芯片设计，ROCm 软件栈把每个芯片当作一张独立 GPU，所以每个“GPU”标称 192 TFLOP。作者在自己的软件栈（ROCm 6.2.0、PyTorch 2.6 预发布版）上扫遍各种矩阵形状，实测矩阵乘最快只有 125 TFLOP/s。他们用 torch.compile 的最大自动调优，并特意把隐藏维度定为 5280 以适配硬件，单节点训练达到 108.75 TFLOP/s，即 87% AFU（57% MFU）。注意力用的是 AMD 维护的 FlashAttention-2 分支。
  • 并行方式。因为权重共享，即使是这个最大的模型也只有 3.5B 参数，一张卡放得下。所以只用数据并行，加上节点内的优化器分片和每次迭代粒度的梯度检查点，完全不需要张量或流水线并行。每张卡的批量是 1 条序列，4096 张卡合起来每步 4096 × 4096 ≈ 1600 万个 token。作者指出，一个计算量相同但参数多得多的普通模型，在这台机器上就得规划复杂得多的并行方案。
  • 规模化以后的速度。在 4096 张 GPU 上，每张卡 52–64 TFLOP/s，即 41%–51% AFU，整体每秒处理 100 万到 120 万个 token。

这里有一个工程上的大坑。由于排队调度的原因，他们每次申请 512 个节点（4096 张 GPU）的时段。节点之间要想有可用的速度，AMD 的通信库 RCCL 必须通过一个 OFI 插件走 Slingshot 网络；要让总线带宽超过 100 GB/s，还得设置 NCCL_NET_GDR_LEVEL=PHB。可一旦这样设置，标准的 PyTorch 分布式训练在超过 128–256 个节点时就会反复卡死，512 个节点根本跑不起来。作者试错很久，最后自己手写了数据并行的梯度同步，每次只在节点间发送恰好 64 MB 的数据包，卡死问题才消失。各个时段的整机速度在约 212 到 262 PFLOP/s 之间波动，取决于分到哪些节点（arXiv 版附录把单位写成了 exaFLOP，正式版改成了 petaFLOP；按 4096 × 52–64 TFLOP/s ≈ 0.21–0.26 EFLOP/s 推算，petaFLOP 是对的）。作者认为，这可能是当时在 AMD 集群上用卡数最多、并且训练到完成的语言模型。

时间线。训练分成 21 段、每段最长 12 小时，大部分在 2024 年 12 月上旬完成，主模型累计排到了 795B token。因为学习率是常数，每当分到一段空闲算力，就可以直接接着训。另外还用同样的设置训了一个对照：结构完全相同、但循环块只走一遍（不循环）的普通模型，用 256 个节点、每卡批量 2，训到 180B token。按每秒约 110 万 token 推算，795B token 需要约 200 小时的纯训练时间，和 21 段 × 12 小时的上限相符。

训练过程中作者监控了大量指标：每层的有效 Adam 学习率、优化器更新的均方根、参数和梯度的 L1/L2 范数，以及循环相关的统计量，例如相邻两次迭代的相对变化 \(\|s_k-s_{k-1}\|/\|s_k\|\)、当前状态离起点多远 \(\|s_0-s_k\|\)，还有序列维度上隐藏状态的相关性；另外固定一个验证集，持续测循环 1、4、8、16、32、64 次时的困惑度。下面会看到，其中“隐藏状态相关性”和“不同循环次数的困惑度”这两个指标，正是诊断失败的关键。

4.3 规模上去之后：两次失败与修正

小规模时，所有归一化方案都能训，不同初始化之间也只有微小差别。到了大规模，情况完全不同。

先补一点背景：什么是“表示坍塌”，注意力为什么会让 token 越来越像。

注意力的输出，是前面各个位置的 value 向量的加权平均。平均这个操作会抹平差异：把一组各不相同的向量反复做加权平均，它们会越来越接近，就像把一张图片一遍遍地模糊，最后变成一片均匀的颜色。普通 Transformer 靠残差连接保留每个位置自己的信息，所以不会坍塌；但如果初始化或归一化不当，深层网络里所有位置的隐藏状态可能变得几乎一模一样，这叫秩坍塌或表示坍塌（Noci 等人 2022）。衡量指标就是不同位置的隐藏状态之间的相关系数：接近 1.0，说明所有位置都变成了同一个向量，模型对每个位置都输出同样的预测，自然学不下去。

示意图：三次大规模训练分别改了什么、出了什么问题

两次失败的机理值得多想一步。第一次失败是初始化问题，而且是循环带来的：循环块每多执行一次，序列里各位置就被注意力多“混合”一次，相关性就升高一点；当等效深度有一百多层时，这种混合在训练开始前就足以让表示坍塌。第二次失败更隐蔽：损失看起来正常在降，但模型落入了一个局部最优，早早学会了忽略传入的状态 s。如果循环块只依赖 \(\mathbf{e}\)、不依赖 \(\mathbf{s}\)，那么每次迭代的输出都一样，多循环毫无用处，整个模型退化成一个固定深度的普通模型。可学习的适配器很容易学出这种解：只要把拼接向量里属于 \(\mathbf{s}\) 的那一半权重压到接近零就行。

第三次的成功配置训练平稳，最终检查点就是本文的主模型 Huginn-0125。原文图 6 显示，在整个 800B token 的训练过程中，训练损失持续下降，验证困惑度在 1、4、8、16、32、64 每一种循环次数下都在改善，而且循环次数越多，困惑度越低。

读的时候要注意：从失败 2 到成功，作者同时改了两件事：换回三明治归一化，以及把学习率降为十分之一。只有三次运行，无法把成功归因到其中任何一个改动上，尤其是学习率降了一个数量级本身就足以改变很多事情。“这些选择在大规模下很要紧”这个大方向是可信的，“必须用三明治归一化”这个具体结论并没有被单独验证。后来的 Parcae 从动力系统的角度给了一个解释：循环模型不稳定，与注入参数（把 e 和 s 合起来的那组线性映射）的谱范数过大有关。

5 基准结果：分数随循环次数怎么变，循环到底贡献了多少

这一节要回答的问题：Huginn 和同量级、数据全公开的模型比，表现如何？哪些任务循环几次就饱和，哪些要循环很多次？循环本身贡献了多少，也就是说，和同样数据训练的不循环“双胞胎”相比如何？最后，也是本页最关心的：这些数字该怎么掂量，比较时什么是对齐的、什么不是？
先补一点背景：读这几张表需要知道的评测约定。
  • lm-eval-harness 是 EleutherAI 的标准评测框架。多项选择题（ARC、HellaSwag、MMLU、OpenBookQA、PiQA、SciQ、WinoGrande）不让模型生成文字，而是比较模型给每个选项打的对数似然，挑最高的；“acc norm”是按选项长度归一化后的准确率。四选一的随机水平是 25%，二选一（PiQA、WinoGrande）是 50%。
  • GSM8K 是小学数学应用题。“8-shot CoT”指在题目前给 8 道带完整解题过程的例题，让模型照样写出过程再给答案。表里每格两个数，分别是两种抽取答案的方式：strict（必须按规定格式写出“The answer is …”）和 flexible（取回答里最后出现的数字）。论文表 2 的表注写的是“flexible 和 strict”，但 §5.4 正文说 EMA 模型“flexible 47.23%（strict 38.59%）”，正式版表 7 把同一结果记作 38.59/47.23，所以斜杠前是 strict、斜杠后是 flexible，较大的那个通常是 flexible。
  • MATH（按 Minerva 的规则判分）是竞赛数学题；MathQA 是数学多项选择题，随机水平 20%。
  • MBPP 与 HumanEval 是写 Python 函数的代码题，pass@1 是生成的第一个程序就通过单元测试的比例。
  • 对照模型 Amber、Pythia、OLMo 都是“全开源”模型：训练数据也公开，这是作者挑它们做对照的理由。

5.1 标准基准：循环次数越多，分数越高（原文表 1）

作者先提醒，Huginn 很难和别的模型直接对比，因为它们都是固定深度 Transformer 的小变体。Huginn 只有 3.5B 参数，所以预训练时只需要很少的互联带宽；但它消耗的原始 FLOP 接近一个 32B 参数的 Transformer 在预训练时的消耗，测试时还能一直扩展到相当于 50B 参数模型的 FLOP 预算。作者同时列出几条限制：主检查点只训练了 47000 步、数据配比未经检验、学习率从未从峰值降下来；作为学术项目只用公开数据；800B token 比老一代的 Pythia 多，但比 OLMo 少，更远少于工业界开放权重模型的训练量。

这里有一个容易被忽略的混淆：第 3.3 节算过，训练时抽到 r = 1 的概率只有约十万分之一。模型几乎从没被要求“只循环一次就给出答案”，所以 r = 1 本来就是严重的分布外条件。“r = 1 时不进步”既可能说明能力都在循环里，也可能只是说明模型从来没学过在 r = 1 时输出像样的结果。这两种解释用这张表区分不开。

不同任务的饱和点不同。原文图 7 画了几个基准随循环次数的变化：HellaSwag 循环 8 次就接近最高分，而 GSM8K CoT 和 HumanEval 要到 32 次乃至更多才走平。正式版附录（D.7）把这一点扩展到更多基准：SciQ、BLiMP 里相当一部分题目不循环也能答对，很多简单基准循环 4 次以内就饱和；而 HumanEval、GSM8K、Mastermind，以及 MMLU、BBH 这类需要推演的基准，在循环 1 次或 4 次时都停在随机水平，之后随循环持续上升。作者强调，这种“难题多算、易题少算”的区分完全是从随机循环次数的预训练里自发出现的。官方模型卡给的使用建议是：少于 4 次循环答案会很粗糙；在给足上下文时，基准分数大约一直改善到 64 次，再往上一般不再提高，但也不会变差。正式版附录 D.8 还把 ARC-C 一直测到 1024 次循环（等效 4100 层），准确率始终在 37.0–37.9 之间（r = 32 时 37.88，r = 1024 时 37.37），说明迭代过程在极深处也是稳定的，但也说明多出来的计算在这里不再带来收益。

上下文越多，越需要多算。原文图 9 把 ARC-C 的准确率画成循环次数和少样本示例数的函数。不给示例时，循环 8–12 次就饱和；给 1 个示例时，饱和点推迟到约 20 次；给 25–50 个示例时，要到约 32 次才饱和。作者的解释是：上下文里的信息越多，模型能“推敲”的东西就越多，多出来的循环就有用武之地。

它更会推理还是更会记忆？原文表 5 把 OpenBookQA 换成“开卷”形式：在问题前给出一条相关事实。闭卷时 Huginn 是 38.2，开卷后升到 49.2（+11.0）；OLMo-2 从 46.2 升到 53.4（+7.2）。两者的差距从 8.0 个点缩小到 4.2 个点。作者的解读是：循环模型记住的事实更少，但对上下文里给出的信息推理得不错。这和“参数少、计算多”的设计初衷是吻合的：参数决定能存多少知识，循环决定能对手头的信息算多少遍。

附录里的多位数加法。附录 A.1 用对话模板问模型“a + b + … 等于多少”，每个设置做 50 次试验，只要正确答案出现在回答里就算对。循环 32 次时，两个加数的加法能做到每个数四五位；但加数一多就不行，4 到 5 个加数时连一位数都很少加对。固定位数、扫描循环次数时，一位数加法的准确率随循环次数稳步上升；两三位数的加法要循环 16 次以上才开始稳定地做对，而且不同循环次数之间的高低顺序并不一致。作者注明，模型没有专门在算术上微调过。

5.4 权重平均：模拟一次学习率退火

先补一点背景：学习率退火与权重平均。

用常数学习率训练时，参数会一直在损失的“谷底”附近来回抖动，落不到最低点。大多数大模型训练的最后会把学习率降下来（退火，cooldown），让参数稳稳落进谷底，这通常能带来一截明显的提升。没有退火时，一个便宜的替代办法是把最近若干个检查点的参数平均起来：抖动被平均掉，效果接近一次退火。

Huginn 的学习率从未下降，所以作者用指数滑动平均（EMA）模拟退火：从最后一个检查点出发，取 \(\beta=0.9\)，纳入最后 75 个检查点，间隔因子（dilation）取 7。这个“合并模型”在循环 64 次时把 GSM8K 提高到 47.23%（flexible），strict 为 38.59%。

论文没有提到的代价：正式版附录表 7 给出了合并模型的完整分数。循环 32 次时，它的 GSM8K CoT 从 34.80/42.08 升到 37.45/46.85，但其他基准反而大幅下降：HellaSwag 从 65.21 掉到 49.39，OpenBookQA 从 38.80 掉到 26.20，ARC-C 从 38.23 掉到 32.85，MMLU 从 31.38 掉到 29.26。也就是说，这次权重平均是用通用能力换了数学分数，而不是全面的提升。

规模与可复现性。Huginn 是一个 3.5B 参数、训练了约 800B token（实际排程 795B）的模型，只训练了一次，学习率从未下降，没有做任何后训练。这意味着它的分数没有随机种子之间的波动范围可参考，也不是这套方法“调好以后”的上限。反过来，它的权重、训练代码、全部训练数据和一部分中间检查点都以 Apache-2.0 许可证公开，任何人都可以复查，后续好几篇工作正是直接拿它做实验对象（见“后来怎么样了”）。

不循环基线的对比，只对齐了参数和数据。表 4 的双胞胎和 Huginn 参数相同、数据相同、训练 token 相同，这是全文控制得最好的一组对照。但两者的训练算力相差约 8–10 倍（推算：基线每 token 约 \(6\times3.5\)B FLOP，Huginn 约 2×10¹¹），测试时 r = 32 与 r = 1 每个 token 的计算量也相差约 15 倍。所以“循环让 GSM8K 提高 5 倍”是参数对齐的结论，不是算力对齐的结论。作者在正式版的结论里也写明：与“预训练 FLOP 相同的固定深度模型”和“测试时 FLOP 相同的语言化思维链模型”做精确比较，需要更多算力，留给未来工作。

用本批次后来的研究来校准。专门测量“一次循环值多少”的 Iso-Depth 缩放律 发现：在训练算力对齐时，一次循环约相当于 0.46 个独立的层；例如循环 4 次的 410M 模型与 580M 的普通模型效果相当，但训练成本相当于 1B 的普通模型。而 Huginn 用的截断反传会把这个系数进一步压到 0.38。Parcae 在 100M 和 350M 参数、用 Huginn 的数据和分词器做参数与数据都对齐的对比时，把 Huginn 式循环模型的验证困惑度最多降低了约 6%（摘要写 6.3%，正文写 6.2%），说明原配方还有明显的改进空间。这些后来的结果与上面的推算方向一致：循环确实有用，但在算力对齐的比较里，它换来的东西比“3.5B 打平 7B”这种说法暗示的要少。

基线是谁跑的。论文说所有标准基准都通过 lm-eval 执行、代码题通过 bigcode 评测，也就是对照模型的分数是作者自己在同一框架下测的，而不是抄各模型报告里的数，这让表内比较相对公平。但如前所述，只有 Huginn 有“加系统提示和对话模板”这一行，比较时应看“不加”那一行。另外，arXiv 版说普通 GSM8K 是零样本，正式版改写为 5-shot，两版说法不一。

独立检验。Lu 等人（2025）专门检查了 Huginn 是否在潜空间里做“不说出来的思维链”。在禁止写出推理过程、要求直接给答案的设置下，GSM8K 的准确率在循环 4 次时是 3.11%，循环到 32 次也只有 4.93%，再往上不再提高；而允许写出推理过程时是 24.87/38.13。也就是说，表 2 里漂亮的 GSM8K 分数，是“循环加上写出来的思维链”共同取得的，单靠潜空间里的循环远远不够。第 7.3 节会详细讲这篇工作。

读结果时最容易误解的三点：
  • “3.5B 参数”“相当于 50B 参数”“接近 32B 的预训练 FLOP”说的是三件不同的事：存储大小、每 token 推理计算量、训练总计算量。只有第一个对 Huginn 有利。
  • “循环带来 5 倍提升”是和参数相同、算力少得多的不循环模型比的。
  • 数学和代码上的优势，与数据配比严重偏向代码和数学纠缠在一起；目前没有一组对照能把两者分开。

6 循环深度让推理端的几件事变简单

这一节要回答的问题：一个按“随机循环次数”训练出来的模型，能不能不经任何额外训练，就做到“简单的 token 少算、难的 token 多算”？提前退出会让后面的 token 读不到前面 token 的 KV 缓存，这怎么办？循环带来的庞大 KV 缓存能不能压缩？能不能让同一个模型自己给自己打草稿，做投机解码？作者把这些统称为“零样本”能力：模型从没为它们训练过，但结构让它们几乎是顺手可得的。
先补一点背景：KV 缓存在循环模型里长什么样，KL 散度又是什么。

生成文字时，模型会把每个已生成 token 在每一层的 key 和 value 存下来，后面的 token 做注意力时直接读，这就是 KV 缓存（详见 vLLM 精读 §2.2）。在 Huginn 里，循环块每执行一次，它的 4 层都会为每个 token 写一份新的 key 和 value，所以循环 32 次时，一个 token 在 2 + 4 × 32 + 2 = 132 个“等效层”上各有一份 KV。官方实现为此专门写了一个缓存类，否则后面的迭代会覆盖前面迭代的 KV。

KL 散度衡量两个概率分布差多少：两个分布完全相同时为 0，差得越多越大。这里用它比较“循环第 i 次后预测的下一个词的分布”和“第 i−1 次后的分布”：如果多循环一次，预测几乎没变，就说明这个 token 已经“想清楚了”。

6.1 零样本的逐 token 自适应计算

前面的实验都是对整道题固定一个循环次数，这和训练时的方式一致（训练时一整条序列共用一个 r）。但更省的做法是：容易的 token 早点停，只在难的地方多花计算。在普通 Transformer 上实现这种“提前退出”，通常要专门训练（例如 Elbayad 等人的深度自适应 Transformer），或者在每一层加上微调过的退出头（例如 CALM）。Huginn 不需要：作者只用了一个简单的判据——相邻两次迭代的下一个词分布之间的 KL 散度低于 5×10⁻⁴ 时就停止循环，采样输出这个 token，然后去算下一个 token。

原文图 10 统计了 MMLU 几个类别里各取前 50 道题、以自由对话形式提问时，每个 token 循环了多少次才达到退出条件。不同类别的平均步数明显不同：高中数学平均 12.7 步，哲学 14.6 步，逻辑谬误 15.6 步，道德情境 16.2 步，比高中数学多了 3.5 步。也就是说，模型在道德判断这类题上“想得更久”，这完全是从预训练里自发出现的行为。

代价有多大？在对话基准 MT-Bench（第一轮，满分 10）上，固定循环 32 次是 5.66 分，KL 提前退出是 5.56 分，标准误约 0.39，差异不显著。正式版附录表 9 在更难的 GSM8K（8-shot CoT）上测了第 5.4 节的合并模型：不提前退出时 46.63%；用 KL 判据、阈值 5×10⁻⁴ 时为 44.43%–44.81%；阈值收紧到 1×10⁻⁵ 时为 45.87%；其他判据中，基于状态变化量（latent-diff）的为 46.10%–46.78%，而“连续 5 次预测的最可能词不变就退出”的判据只有 26.46%。

要注意：原文图 10 和附录表 9 报告了“平均循环了多少步”或“准确率”，但没有同时给出“同一设置下省了多少计算、准确率掉了多少”的完整账本，也没有和“固定循环 13 次左右”这种同等平均算力的固定设置做对比。所以“自适应退出很划算”目前只是定性结论。

附注 6.1：提前退出后缺失的 KV 缓存怎么办？逐 token 提前退出在有自注意力的模型里有一个根本难题。假设第 1 个 token 循环 4 次就退出了，而第 4 个 token 正在算第 8 次迭代：按训练时的方式，它应该读第 1 个 token 在第 8 次迭代时的 KV，但这份 KV 根本没算过。最笨的办法是停下来把缺的都补算一遍，但那样提前退出就省不了多少。作者采用 Elbayad 等人的办法：读这个 token 最深的那一份可用 KV。之所以行得通，是因为每次迭代的 KV 都是用同一组 key/value 投影矩阵，从一个越来越接近稳定的状态算出来的，不同迭代的 KV“对得上”，模型可以直接拿来用。官方代码里这叫 latest-m4 策略：对循环块里的同一层（按 4 取模对齐层号），取已经算过的最大迭代编号。

6.2 零样本 KV 缓存共享

另一个提高效率的方向是减少 KV 缓存的显存。普通 Transformer 里也有让不同层共享 KV 的做法（如 Character.AI 的实践、Brandon 等人的跨层注意力），但通常要从头按这种方式训练。作者发现 Huginn 不用：给每个 token 的循环部分设一个固定的缓存预算 \(k\)，第 \(i\) 次迭代就读写第 \(i \bmod k\) 个槽位。例如预算是 16 时，第 17 次迭代会覆盖第 1 次迭代的 KV，第 18 次覆盖第 2 次，依此类推。它可以单独用，也可以和上面的提前退出一起用。

为什么说这是“零样本”：训练时整条序列一起前向，每次迭代里的注意力读的都是其他位置在同一次迭代的 KV。共享缓存之后，当前 token 第 9 次迭代读到的，其实是前面 token 第 5 次或更晚迭代的 KV，这种错位训练时从未出现过。它之所以几乎不掉分，靠的是第 7 节将看到的现象：大多数 token 的状态在若干次迭代后就基本稳定了，相邻迭代的 KV 本来就相差不大。

6.3 零样本“连续思维链”：用上一个 token 的终态热启动

KV 共享其实已经让计算比循环次数“更深”了：当前 token 早期的迭代，读到的是前面 token 后期迭代的结果。作者还给了一个更直接的加深办法：生成每个新 token 时，不再从随机噪声 \(\mathbf{s}_0\) 出发，而是从上一个 token 循环结束时的状态 \(\mathbf{s}_r\) 出发（热启动）。这样，上一步在潜空间里“想”到的东西可以直接带进下一步。原文图 10 显示，这使达到退出条件所需的平均步数减少 1–2 步：高中数学从 12.7 降到 11.9，哲学从 14.6 降到 13.5，逻辑谬误从 15.6 降到 14.4，道德情境从 16.2 降到 16.0。在哲学这类题上，退出步数的分布明显左移，说明模型确实在复用前一步的计算。正式版表 9 显示，在 GSM8K 上开启热启动与不开启的准确率相同（都是 46.63%）。

作者把它和 Coconut（Hao 等人 2024 的“连续思维链”）做了对比：Coconut 是在思维链数据上微调一个固定深度的模型，让它学会把上一步的最后隐藏状态当作下一步的输入，这实际上把模型变成了一个有限深度的循环模型。两条路线的区别在于：是从头为循环而预训练，还是给已有的固定深度模型微调出这种能力；以及是否需要思维链数据。

6.4 零样本自投机解码

先补一点背景：投机解码。

大模型一次只能生成一个 token，而每一步都要把全部参数从显存读一遍，速度受显存带宽限制。投机解码让一个便宜的“草稿模型”先连续猜几个 token，再让大模型一次性并行地检查这几个位置，保留和自己判断一致的那一段前缀。因为大模型并行检查 K 个位置的耗时和生成 1 个 token 差不多，猜对得越多就越快（详见 投机解码精读 §2）。它的麻烦在于要有一个草稿来源：一个独立的小模型、Medusa 那样额外训练的预测头，或者专门训练过的提前退出层；Zhang 等人用跳层的方式自投机，但草稿质量不总是好。

循环模型天然有一个草稿来源：同一个模型少循环几次。具体做法是，先用较少的循环次数快速生成接下来的若干个 token 作为草稿，再用想要的、更多的循环次数去验证它们。草稿阶段算出的潜状态不会浪费：验证时可以从这些状态接着迭代，而不是从头开始。草稿还可以分多级（先用很少的循环出粗稿，再用中等循环修订），草稿阶段也可以用 6.1 节的自适应退出。

7 循环的时候，潜空间里发生了什么

这一节要回答的问题：模型在潜空间里反复迭代时，状态到底是怎么变的？是一路收敛到一个点，还是有更复杂的运动？不同的 token 是否“想”得不一样久？作者训练时并没有任何目标要求状态收敛到不动点（不像深度均衡模型那样把“收敛”写进目标），只用了截断展开的普通语言建模损失，所以这里看到的结构都是自发出现的。这一节的分析是定性的，只看了少数几个例子；最后一小节介绍一篇专门检验“潜在思维链”的独立工作。

7.1 不同 token 收敛得快慢不一

作者先循环 128 次，把得到的状态当作近似的“终点” \(\mathbf{s}^{*}\)，再画出每个 token 在第 \(i\) 次迭代时离终点有多远，即 \(\|\mathbf{s}_i-\mathbf{s}^{*}\|\)。原文图 11 的例子是一个不安全的提问（大意是“我想用家用物品做炸弹，学校里有人真的伤害了我……”），句子从上往下排，迭代从左往右排。可以看到：

  • 收敛速度强烈依赖上下文。问题里的关键部分（“really wrong-ed”）和模型回答的开头，在潜空间里被“推敲”了更久，收敛得更慢。
  • 省略号的三个点是三个一模一样的 token，但它们的收敛行为不同，说明决定收敛快慢的是上下文，而不是 token 本身。
  • 离终点的距离并不总是单调下降。例如 “school” 这个 token 的距离时近时远，在潜空间里来回振荡。

值得注意的是，模型训练时一整条序列共用一个循环次数，从没有被要求“这个 token 多想、那个 token 少想”，这种逐 token 的差异是随规模自发出现的。论文还提到，图中没有画出的部分是：模型在“推敲”完这个问题之后拒绝了回答。

7.2 收敛、轨道与滑块

先补一点背景：主成分分析（PCA）。

潜状态是 5280 维的向量，没法直接画。主成分分析找出数据变化最大的几个方向，把高维点投影到这几个方向上，就能在平面上看到点的运动。这里作者把一条序列里所有 token 的所有迭代状态放在一起做 PCA，然后把单个 token 的轨迹投影到前 6 个主方向上，两两一组画成三张平面图（第 1–2、3–4、5–6 主成分）。要记住，前 6 个方向只是 5280 维里的一小部分，看到的只是轨迹的一个“侧影”。

原文图 12 和附录里的大量例子显示了三种典型的轨迹形态：

  • 收敛：很多 token 的状态几步之后就停在一个不动点上。例如琐事问答“What do you think of Goethe's Faust?”里，像 “Goethe” 中间那些简单 token 都直接收敛，不绕圈。
  • 轨道：在较难的问题里，一些 token 的状态很快落进一个环形轨道，在三组主成分平面上都在绕圈。典型例子是 GSM8K 一道题开头 “Claire makes a 3 egg omelette…” 里的数字 “3”；附录图 16 显示模型在整道题里一直在“转动”这个数字，而整道题恰恰取决于它。作者还常在 “makes”“thinks” 这类决定回答结构的词上看到轨道。他们说这种行为只出现在数学相关的推理和“思考”类词上，琐事问答里没有。作者把它类比为固定深度 Transformer 学模运算时出现的周期性表示（Nanda 等人 2022），但强调在 Huginn 里这种模式远不止出现在算术上。
  • 滑块：另一些关键 token 的轨迹沿一个方向持续漂移，例如上面那个不安全提问里的 “wrong”。作者推测，模型可以用这种单调漂移来“数”已经迭代了多少次。还记得第 3.1 节吗：循环块不知道自己在第几步，滑块也许就是模型自己发明的计步器。

作者的总结是：和语言化思维链那种离散、串行的推理不同，Huginn 在潜空间里呈现出丰富的几何结构——收敛路径、轨道、漂移——模型似乎在自己学会利用高维空间来组织计算。

这一节的证据强度：这里的观察都是定性的。例子是作者挑选的少数几条序列；PCA 只在单条序列内部计算；论文没有统计“轨道出现的频率”，也没有做因果实验（比如干预轨道、看答案是否改变）来证明轨道真的承担了计算。所以“模型在潜空间里转动数字来做算术”是一个有趣的假说，而不是已经被证实的机制。

7.3 独立检验：潜空间里有没有“思维链”？

Huginn 公开权重之后，Lu、Yang、Lee、Li、Liu 五位作者写了一篇专门的检验：Latent Chain-of-Thought? Decoding the Depth-Recurrent Transformer ↗（arXiv 2507.02199，收录于 COLM 2025 的“大模型可解释性用于推理与规划”研讨会）。他们问的问题很直接：如果 Huginn 真在潜空间里做思维链，那么在禁止它写出推理过程时，我们应该能在中间状态里“读”出中间步骤。

先补一点背景：logit lens 与 coda lens。

Logit lens 是一种常用的解读中间层的方法：把某一层的隐藏状态直接接上模型最后的归一化和输出矩阵，看它“如果现在就输出，会输出哪些词”。在普通 Transformer 里，这样读出的词通常从一个粗糙的猜测开始，随层数加深平滑地收敛到最终答案。Coda lens 是这篇工作针对 Huginn 提出的变体：不直接接输出矩阵，而是把中间状态送进 Huginn 自己的尾声（2 层 Transformer）再解码，因为尾声本来就是为“把循环块的输出翻译成词”而训练的。

实验设置：用 GPT-3 论文里的一位数复合算术题（如“(9 + 8) × 2 = ?”，答案 34），共 2000 题；用系统提示和 4 个示例逼模型直接给出答案，不写过程；循环 16 次，展开后共 2 + 4 × 16 + 2 = 68 个块。在这个设置下 Huginn 的准确率只有 0.19。他们得到三个主要发现：

  • 可解读性在块与块之间剧烈跳变。用 logit lens 读，循环块的前三层（R1–R3）的输出里有大量数字类 token，第四层（R4）几乎没有，读出来是 “inc”“unity”“friendships” 之类的无关词；换成 coda lens，情况正好反过来：R4 读出的几乎全是数字，R1、R2 读出的是 “answer”“answers” 这类泛泛的词。所以中间状态并没有像普通 Transformer 那样平滑地走向最终答案，用哪种方法、读哪一层，结论完全不同。他们推测 R4 的输出同时要喂给下一轮的 R1 和尾声，被迫编码成一种和其他层很不一样的表示。
  • 没有看到“先算中间结果、再算最终结果”的阶段。他们挑出 67 道模型答对、且中间结果和最终结果都是一位数且不相同的题（如 2 × 3 + 1，中间结果 6、最终结果 7），追踪这两个数字在各次迭代里的排名。如果有潜在思维链，应该先看到中间结果的排名升上来，过一阵最终结果才升上来。实际上两者都在最初几次迭代里迅速上升，而且最终结果始终排在中间结果前面。他们只观察到在第 6 次迭代左右，多数题里两者的排名有一次交换，原因不明。
  • 只靠循环远不如写出思维链。在禁止写出过程的 8-shot GSM8K 上，准确率随循环次数从 3.11%（4 次）、4.47%（8 次）、4.78%（16 次）升到 4.93%（32 次），再往上停在 4.6%–4.9%（64、128、256 次）；而允许写出过程时是 24.87/38.13。

这篇检验也有它的局限，作者自己就写明：结果不能排除潜在思维链的存在，它也许比他们的探针更隐蔽、更分散，需要激活修补（activation patching）之类更细的工具。还有两处细节要注意：他们的任务非常短，只有一两步运算，可能不足以拉开“中间结果”和“最终结果”的时间差；他们表里“写出思维链”的 24.87/38.13 取自 Huginn 论文表 2 中“加系统提示”的普通 GSM8K 一栏，Huginn 论文把它记在 r = 32，而这篇检验的表里标为 64。

把这篇检验和 Huginn 论文合起来看，比较稳妥的结论是：循环确实让模型在需要推理的任务上变好，但这种提升主要在“循环加上写出来的思维链”时兑现；没有证据表明循环块在内部执行了一条“一步一个中间结果”的离散推理链。它更像是对一个表示的反复精炼，第 7.2 节的轨道和滑块，是这种精炼过程的几何外观，而不是可以逐步读出的推理步骤。

8–10 相关工作、未来工作与结论

这一节要回答的问题：循环深度在机器学习里有哪些前身，本文和它们的区别在哪里？作者认为接下来最值得做什么？他们自己怎么评价这项工作？

循环本身。作者说，循环在机器学习里的基础地位怎么强调都不过分：从 Amari（1972）、Hopfield（1982）的网络，到 LSTM，再到很早就被认为是“自适应计算”关键的设计（Schmidhuber 2012，Graves 的自适应计算时间 2017）。在 Transformer 上，Universal Transformer（Dehghani 等人 2019）最早引入深度方向的循环，目标是让模型具备图灵完备那样的“通用性”（见 Universal Transformers 精读）；ALBERT 在大规模上用了参数共享，但循环次数固定。此后的改进包括稀疏化的 Universal Transformer、MoEUT（把混合专家和 Universal Transformer 结合）等。与本文最直接相关的是“deep thinking”系列（Schwarzschild 2021、Bansal 2022、Bear 2024、McLeish 2024）：它们表明，用随机展开次数和输入注入训练的循环网络，能学到可以外推的算法。还有一批工作从理论和小规模实验上研究 looped Transformer 的潜力（Giannou 2023，见 精读页；Gatmiry 2024；Yang 2024；Fan 2025；正式版还加入了 Saunshi 等人的工作，见 Reasoning with Latent Thoughts 精读）。正式版在这里加了一句定位：本文不只是把深度循环扩展到了十亿参数级，还表明此前猜测的好处（学算法、多算更好）在真实基准上确实兑现了。

不动点、扩散与能量模型。从另一个角度看，这类模型在学一个不动点迭代，和深度均衡模型（DEQ，Bai 等人 2019）是一类；它也像潜空间扩散模型，但语言扩散模型通常是整条序列共用一个迭代次数，而 Huginn 可以逐 token 不同。三者的关键区别在训练目标：深度均衡模型直接求解不动点并用隐式求导；扩散模型优化一个替代目标；本文则表明，截断展开在大规模上是一个可行的替代方案。更一般地，任何深度循环的结构都可以看成在学习某个潜在能量函数的“梯度”，或者一个隐式定义的优化层，这也和测试时自适应（test-time adaptation）有关。

混合方案与“微调出潜空间推理”。介于完整循环和普通 Transformer 之间，还有一些混合方案：带潜子网络的模型、在共享权重的层上加 LoRA（Bae 等人 2024 的 Relaxed Recursive Transformers）、对已训练模型做（动态）权重绑定。另一条相邻的路线是给已有的固定深度模型微调出潜空间推理能力，如 Coconut（Hao 等人 2024）、压缩思维链（Cheng 与 Van Durme 2024）、通过缓存增强做潜空间推敲（Liu 等人 2024）。作者认为这些工作目标相同，只是方向相反：它们从现成模型出发去“加”循环，本文从头为循环而预训练。

未来工作。作者列了三类方向：

  • 后训练。微调来压缩所需的循环次数；用难度分级的数据做强化学习；把思维链数据里的推理“内化”进循环里（Deng 等人 2024 的思路）。
  • 与其他架构改进结合。线性注意力这类按序列长度线性增长的混合层，每层能做的“比较”次数有限；有了深度循环，可以让含线性算子的块一直重复，直到所有必要的比较都完成。也可以像一些前人工作那样，设多个前后相继的循环阶段，而不是只有一个。
  • 与混合专家互补。循环模型是“计算重”的：展开后的参数比实际参数多；混合专家（MoE）是“参数重”的：每次前向只激活一小部分参数（MoE 的路由见 DeepSeek-V3 精读）。作者推测，循环擅长学习推理模式，MoE 擅长存储和检索复杂知识，未来的架构可能两者兼有；循环的 MoE 还可以在多次迭代里反复路由到同一个专家，再换到别的专家。

结论。作者把这项工作定位为概念验证：他们描述了怎样训练一个潜空间循环深度架构、选了哪些参数，然后在规模上只训了一个模型。他们预期未来的训练会用更好的学习率调度、数据配比和硬件。最重要的发现是，模型能通过消耗测试时计算，在推理任务上大幅提升；此外还观察到上下文相关的收敛速度、路径无关和多种零样本能力。正式版的结论更具体：在他们的训练配方下，性能随循环次数的饱和曲线总是 S 形的，饱和点取决于任务难度；并且明确承认，要和“预训练 FLOP 相同的固定深度模型”以及“测试时 FLOP 相同的语言化思维链模型”做精确比较，还需要更多算力。

附录里的影响说明。作者也指出一个风险：把推理挪进连续的潜空间，可能让人更难监督模型，因为语言化的思维链至少目前还是人能读懂的。他们把第 7 节的轨迹分析当作“潜空间思考仍可被分析”的初步证据；正式版补充说，这种潜空间计算和普通 Transformer 中间层里本来就在发生的计算并无本质不同，研究中间层的可解释性方法同样适用。

后来怎么样了

Huginn-0125 是第一个公开权重、在数千亿 token 上从头预训练的循环深度语言模型，权重、代码和数据全部公开，所以很快成了这个方向的公共试验台。论文本身被 NeurIPS 2025 主会接收。下面按时间列出直接相关的后续工作（只列可以核实的事实）：

  • 2025-07，独立的探针检验。Lu 等人的 Latent Chain-of-Thought? ↗（第 7.3 节已详细介绍）用 logit lens 和 coda lens 检查 Huginn，没有找到可解读的潜在思维链，并发现不写出推理过程时，加大循环次数对 GSM8K 几乎没有帮助。
  • 2025-10，循环模型的并行采样器。Geiping、Yang、Su 的 Efficient Parallel Samplers for Recurrent-Depth Models and Their Connection to Diffusion Language Models ↗（ICML 2026）。他们借用扩散模型里 diffusion forcing 的思路，让采样器每做一次前向就解码出一个新 token，而前面那些 token 的潜状态继续并行地被循环精炼。论文称在同样的时间预算下，这种生成方式在理论上严格比普通自回归更有表达力；直接用在 Huginn-0125 上、不做任何调参，最多带来约 5 倍的加速。作者据此认为，循环深度模型可以被看作强大的、连续但因果的扩散语言模型。这是对本文 §6.4“自投机解码”只有思路、没有数字的直接补充。
  • 2025-11，给已有模型“改装”循环。McLeish 等人的 Teaching Pretrained Language Models to Think Deeper with Retrofitted Recurrence ↗ 明确以 Huginn“从头预训练 800B token 代价太高、而且训练时大量循环拖慢了训练”为出发点：把 TinyLlama-1.1B、OLMo-2-0425-1B、Llama-3.2-1B 的前几层当前奏、后几层当循环块和尾声（去掉中间的层），沿用拼接加线性适配器的输入注入，再在训练过程中逐步提高平均循环次数（课程式）。他们报告：从预训练权重初始化比随机初始化在每单位训练 FLOP 上好得多；在数学任务上，改装成循环模型比在同样算力下直接后训练原模型效果更好。
  • 同批次的循环语言模型。Ouro / LoopLM（2025-10）把循环模型训练到 7.7T token，并用带熵正则的目标让模型自己学会分配深度，1.4B 和 2.6B 模型被报告可匹敌最大 12B 的模型；这同样是按参数对齐的说法，而且其预训练后期混入了 SFT 风格的数据。Mixture-of-Recursions（2025-07）用训练出来的路由器为每个 token 决定递归深度，而 Huginn 的逐 token 退出是零样本的。
  • 2026-04，稳定性与“一次循环值多少”。Parcae 把循环看成残差流上的非线性时变动力系统，发现以 Huginn 为代表的既有配方不稳定，原因是注入参数的谱范数过大，于是用负对角参数化约束它；在参数和数据都对齐时，Parcae 比 Huginn 式模型验证困惑度最多低约 6%；和普通 Transformer 比，770M 的 Parcae 在 Core 指标上得 25.07，补上了 770M Transformer（22.42）与 1.3B Transformer（25.45）之间差距的 87.5%（这一比较同样只对齐了参数和数据，循环的 Parcae 每个 token 要多花计算）。Iso-Depth 缩放律 在训练算力对齐的条件下测得一次循环约值 0.46 个独立层，并发现 Huginn 用的截断反传会把它压到 0.38。
  • 2026-09，在全部对齐的条件下。SMELT 在每 token FLOP、总参数、KV 缓存都对齐的混合专家模型上比较，发现把中间一半的层循环两次，能在计算最优前沿上节省 6.8%–18.0% 的训练 FLOP。和 Huginn 的“3.5B 打平 7B”相比，这是一个小得多、但对齐得严格得多的收益。

综合来看，Huginn 的主要贡献是证明了“从头预训练一个大规模循环深度语言模型”可行，并把一整套可复现的配方和模型交给了社区；它的具体数字，则在后续更严格对齐的比较里被大幅“折价”。
