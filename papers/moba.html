0 导读：这篇论文解决什么问题

大模型的上下文越来越长：一次读进几十万甚至上百万 token 的长文档、整个代码库，或者在推理时写出几万 token 的思维链。上下文变长以后，最贵的部分不再是模型的参数矩阵，而是注意力。因为每个位置都要和它之前的所有位置算一次相似度，注意力的计算量随长度按平方增长。按本站推算，一个 Llama-3.1-8B 规模的模型一次读入 100 万个 token 时，注意力约占全部计算量的 95%（§1 有算法）。所以要让长上下文便宜下来，就得让注意力少算。

这篇来自月之暗面（Moonshot AI）的论文提出 MoBA（Mixture of Block Attention，混合块注意力）。它的做法可以用三句话说清。第一，把上下文按顺序切成长度为 \(B\) 的块。第二，每个 query 用自己和每一块“平均 key”的内积给块打分，只挑出分数最高的几块，此外自己所在的块总是被选中。第三，只在被选中的这些 token 上做一次普通的 softmax 注意力。打分不需要任何新参数，所以 MoBA 和全注意力可以随时互换：同一个模型可以某些层用 MoBA、某些层用全注意力，也可以训练到一半从一种换成另一种。作者把这个思路类比成混合专家（MoE）：每个 KV 块像一个“专家”，每个 query 像一个 token，门控决定它去找哪几个专家。实现上，作者把“选了同一块的 query”收集到一起，交给 FlashAttention 现成的变长内核去算，这和 MoE 把 token 分发给各个专家的做法如出一辙。

论文的主要结果有三组。一是 5 个 5.68 亿到 21 亿参数的小模型从头训练：8K 长度上的语言模型损失和全注意力几乎重合；在 32K 序列最后 2K 个位置上，MoBA 的损失高约 4%–7%（推算），但差距随计算量增加在缩小。二是从 Llama-3.1-8B 出发续训到 100 万 token 上下文：各项基准与同样流程训练的全注意力模型接近，不过最能考验稀疏注意力的 RULER@128K 分数在 arXiv 版和 NeurIPS 版之间变了（§3.3）。三是速度：100 万 token 预填充时，注意力层快 6.5 倍，整个模型快 3.34 倍。论文还说 MoBA 已经用于支持 Kimi 的长上下文请求。

巧的是，DeepSeek 的 NSA（原生稀疏注意力）比 MoBA 早两天发布。两者都“按块挑选 KV”，但在打分方式、GQA 组内是否共享选择、内核设计、训练方式上走了不同的路。本页在实验之后专门用一节把两者放在一起对照。

1 引言：长上下文的代价，以及三条已有路线各差在哪

这一节要回答的问题：上下文变长以后，注意力究竟贵到什么程度？为了省掉这部分计算，已有的方法大致分成三类：预先规定看哪里、推理时临时挑选、干脆换掉 softmax 注意力。作者认为它们各有什么不足？由此，作者想要的注意力机制应该满足哪些条件？
先补一点背景：注意力的计算量，预填充和解码各贵在哪里。

先回忆注意力在算什么（更详细的讲解见本站 vLLM 精读 §2.1）：第 \(t\) 个位置的 query 要和前面 \(t\) 个 key 各做一次内积，得到 \(t\) 个分数（称为 logit）；softmax 把它们变成和为 1 的权重；再用这些权重对 \(t\) 个 value 加权求和。设每个头的维度为 \(d\)、query 头数为 \(h\)，内积和加权求和各要约 \(2td\) 次浮点运算，所以第 \(t\) 个位置在一层里的注意力计算量约为 \(4thd\)。把所有位置加起来，长度为 \(N\) 的序列在一层里的注意力计算量约为

$$\sum_{t=1}^{N}4\,t\,h\,d\;\approx\;2N^{2}hd$$

它和 \(N^2\) 成正比。模型里其余的矩阵乘法（QKV 投影、输出投影、前馈网络）对每个 token 的计算量是固定的，约为“2 × 参数量”，整段序列加起来只和 \(N\) 成正比。所以序列越长，注意力在总计算量里的占比就越大。以 Llama-3.1-8B 为例（32 层，32 个 query 头，每头 128 维；除词表嵌入外约 70 亿参数，每个 token 的矩阵乘法约 150 亿次浮点运算，均为本站按公开配置推算）：

推算：注意力按 \(2N^2hd\times 32\) 层计（已考虑因果掩码只算一半）；其余部分按每 token 约 150 亿次浮点运算计。1M 时注意力约 \(2.9\times10^{17}\) 次，其余约 \(1.6\times10^{16}\) 次。这只是计算量的比例，实际耗时还取决于内核效率，但趋势相同：上下文越长，越是注意力说了算。

上面说的是预填充（prefill），也就是一次性读入整段输入的阶段；训练的前向计算与它相同，反向再多算大约两倍。解码阶段则不同：每生成一个 token，只需要用这一个新 token 的 query 去读全部历史的 K、V，计算量不大，但要把整份 KV 缓存从显存里读一遍。Llama-3.1-8B 用了 GQA（32 个 query 头共用 8 组 K、V），每个 token 的 KV 缓存为 \(2\times32\ \text{层}\times8\times128\times2\ \text{字节}=128\ \text{KB}\)，100 万个 token 就是约 128 GB（推算），一张 80 GB 的卡都放不下。MoBA 这篇论文主要对付的是前者，即预填充和训练的计算量；它不减少 KV 缓存的存储量，§3.3 还会看到，论文主表在生成阶段甚至切回了全注意力。

注意力既然这么贵，一个自然的问题是：每个 query 真的需要看全部历史吗？大量观察表明并不需要。softmax 之后，绝大多数权重集中在少数位置上，其余位置的权重接近零。作者把这称为注意力分数天然的稀疏性，还引用了一项神经科学研究作类比：人脑中与记忆存储相关的海马体区域，神经元之间的连接也是稀疏的。问题在于怎么利用这种稀疏性。论文把已有的做法分成三类，并逐一指出它们的不足。

第一类：预先规定好看哪里。最常见的是滑动窗口注意力（每个 query 只看最近的 \(w\) 个 token，Longformer 等采用）和注意力汇聚点（attention sink：StreamingLLM 发现模型习惯把大量注意力权重放在序列最开头的几个 token 上，于是固定保留开头几个 token，再加上最近的一个窗口）。这些结构简单、高效，但它们替模型做了决定：窗口以外、开头以外的内容一律看不到。对“在 50 万 token 的合同里找出某一条款”这类任务，答案可能藏在任何地方，固定结构就无能为力。作者的评价是这类方法“高度依赖任务”，会损害模型的通用性。

第二类：推理时动态挑选。Quest、MInference、RetrievalAttention 等方法拿一个已经用全注意力训练好的模型，在推理时根据当前的 query 临时挑出重要的 token 或块，只算这一部分（本站精读的 SnapKV 也属于这一类，它在预填充结束时挑出要保留的 KV）。它们能省推理的计算，但模型训练时仍是全注意力，所以把模型训练到百万 token 上下文的巨大开销一点也没省。这正是作者在意的地方：长上下文模型的训练成本本身就是瓶颈。

第三类：换掉 softmax 注意力。Mamba、RWKV、RetNet 等线性注意力或状态空间模型，把注意力替换成计算量随长度线性增长的结构。它们和标准 Transformer 差别很大：要么从头训练一个全新的模型，要么花很大代价把现有 Transformer“转换”过去；而且当时它们在复杂推理任务上的效果还缺少充分的证据。

于是作者提出了一个要求很明确的问题：能不能设计一种注意力，保留原有的 Transformer 框架，遵循“少结构”（less structure）的原则，让模型自己决定看哪里，而不是由人预先规定？理想情况下，它还应该能在全注意力和稀疏注意力之间无缝切换。这样它既能直接接上现有的预训练模型，又能同时加速训练和推理，还不损失效果。

MoBA 就是作者的答案：把 MoE 的思想用到注意力上。MoE 过去主要用在前馈层，用一个门控为每个 token 挑几个专家；MoBA 则为每个 query 挑几个历史 KV 块，再用这种方式组织计算来提速。下一节先把标准注意力和 MoE 门控讲清楚，再看 MoBA 怎么把两者接起来。

读的时候容易误解的地方：
  • “少结构”是相对的。MoBA 仍然规定了不少结构：块必须是连续的一段、块长 \(B\) 固定、每个 query 选的块数 \(k\) 固定、自己所在的块必选。它去掉的只是“具体看哪几块”这一项人为规定。
  • “注意力天然稀疏”指的是训练好的模型里大多数权重很小，并不保证“按块挑”能挑对：重要的 token 可能分散在很多块里，块的平均分数也可能把单个重要 token 的信号冲淡（§2.2 有算例）。

2 方法（一）：标准注意力，与从 MoE 借来的门控（原文 §2、§2.1）

这一节要回答的问题：MoBA 改的是注意力计算中的哪一步？它借用的 MoE 门控原本是怎么工作的？把“专家”换成“KV 块”之后，哪些地方能一一对应，哪些地方其实并不一样？这些不一样会直接影响后面对 MoBA 行为的理解。

论文先写出单个 query 的标准注意力。设一个 query 向量 \(\mathbf q\in\mathbb R^{1\times d}\)，上下文里有 \(N\) 个 key 和 value，分别排成矩阵 \(\mathbf K,\mathbf V\in\mathbb R^{N\times d}\)：

$$\mathrm{Attn}(\mathbf q,\mathbf K,\mathbf V)=\mathrm{Softmax}\big(\mathbf q\mathbf K^{\top}\big)\mathbf V$$

\(\mathbf q\mathbf K^\top\) 是 \(N\) 个内积，也就是 \(N\) 个 logit；softmax 把它们变成和为 1 的权重，再对 \(N\) 个 value 加权平均。论文为了简洁省略了除以 \(\sqrt d\) 的缩放，也只写了单个头，多头注意力就是把很多个这样的单头结果拼起来。MoBA 要改的，正是“\(N\) 个 key 全部参与”这一点。

先补一点背景：MoE 的门控（路由器）是怎么工作的。

混合专家（Mixture of Experts，MoE）最早用来把前馈网络（FFN）做大、又不增加每个 token 的计算量。做法是准备 \(E\) 个结构相同、参数不同的前馈网络，称为专家；再加一个很小的路由器（router，也叫门控网络），通常是一个线性层 \(W_g\)，它给每个 token 算出对每个专家的打分。然后只保留分数最高的 \(k\) 个专家（top-k），这个 token 只送给这 \(k\) 个专家计算，输出是它们结果的加权和，权重就是门控值：

$$\mathbf y=\sum_{i\in\mathrm{TopK}}g_i\,E_i(\mathbf x),\qquad g=\mathrm{Softmax}(\mathbf x W_g)\ \text{（只保留前 }k\text{ 个）}$$

因为输出里乘了 \(g_i\)，语言模型的损失可以经过 \(g_i\) 把梯度传回路由器的参数 \(W_g\)，路由器由此学会“什么样的 token 该去哪个专家”。DeepSeekMoE 等较新的 MoE 还有两个改进，MoBA 都借用了：一是共享专家，有一两个专家每个 token 都必须经过，不参与挑选；二是细粒度专家，把专家切得更小、数量更多，同时每个 token 选更多个，总计算量不变但可能的组合更多，效果更好。这两点在本站 DeepSeek-V3 精读 §2.1.2 里有详细讲解。

怎么看：左边是 MoE 前馈层，右边是 MoBA。两边的“打分—取 top-k—计算”一一对应，但 MoBA 的门控值只决定哪些 token 能参加 softmax，不乘到输出上，打分也没有可学习的参数。本站示意图。

对照上图，MoBA 的类比是这样的：每个 KV 块相当于一个专家；每个 query 相当于一个 token；“query 与这块有多相关”相当于路由分数；query 自己所在的块（下文称当前块）相当于共享专家，总是被选中；把上下文切得更细、每个 query 多选几块，相当于细粒度专家。

但在类比之下，有三处本质的不同，后面理解 MoBA 的行为都要用到：

  1. 门控值不乘到输出上。MoE 的输出是“专家输出 × 门控值”的和；MoBA 的门控值 \(g_i\) 只取 0 或 1，作用仅仅是“这块里的 token 能不能参加 softmax”。被选中的所有 token 放在一起做一次 softmax，块与块之间谁更重要，由注意力权重本身决定。因此打分不在输出的计算路径上，损失的梯度传不到“打分”这一步。§2.2 会讲它为什么仍然能学会挑块。
  2. “专家”不是固定的参数，而是上下文的一段。每条序列、每一层的 KV 块都不一样，所以不存在“某个专家被训练得擅长什么”这回事。被挑选的是数据，不是参数。
  3. 没有负载均衡。MoE 通常要用辅助损失或偏置项让各专家分到的 token 数大致均匀；MoBA 没有这样的机制，一个块可能被很多 query 选中，也可能没人选。这不影响计算结果，但会影响 GPU 上的效率（§2.3）。

2.2 方法（二）：怎么切块、怎么打分、怎么不偷看未来（原文 §2.2）

这一节要回答的问题：MoBA 具体怎样把上下文切块、给块打分、挑出要看的块？自回归模型不能偷看未来，块级的挑选在哪些地方会破坏这一点，MoBA 又是怎么补上的？此外，作者还讨论了三个设计选择：块切多细、能不能和全注意力混用、和滑动窗口及注意力汇聚点是什么关系。

2.2.1 分块、打分、取 top-k

MoBA 让每个 query 只看上下文中的一个子集 \(I\subseteq[N]\)（\([N]\) 表示 1 到 \(N\) 的全部位置）：

$$\mathrm{MoBA}(\mathbf q,\mathbf K,\mathbf V)=\mathrm{Softmax}\big(\mathbf q\,\mathbf K[I]^{\top}\big)\,\mathbf V[I]$$

\(\mathbf K[I]\) 表示只取 \(I\) 中那些位置的 key。和标准注意力相比，公式的形式完全一样，只是参与的 key 变少了。所以对被选中的 token 来说，MoBA 算的是精确的注意力，没有任何近似；“近似”只发生在“选谁”这一步。

子集 \(I\) 按块来定。把长度为 \(N\) 的上下文切成 \(n\) 块，每块是 \(B=N/n\) 个连续的 token，第 \(i\) 块覆盖的位置是 \(I_i=[(i-1)B+1,\ iB]\)。每块有一个门控值 \(g_i\in\{0,1\}\)，所有被选中的块合起来就是 \(I=\bigcup_{g_i>0}I_i\)。门控值这样算：

$$s_i=\big\langle \mathbf q,\ \mathrm{mean\_pool}(\mathbf K[I_i])\big\rangle,\qquad g_i=\begin{cases}1, & s_i\in\mathrm{Topk}\big(\{s_j\mid j\in[n]\},\,k\big)\\[2pt] 0, & \text{否则}\end{cases}$$

逐项解释：\(\mathrm{mean\_pool}(\mathbf K[I_i])\) 是把第 \(i\) 块里 \(B\) 个 key 向量逐维取平均，得到一个和 key 同样大小的向量，下文记作 \(\bar{\mathbf k}_i\)；\(s_i\) 是 query 和它的内积，论文称为亲和度分数；\(\mathrm{Topk}\) 取所有块的分数里最大的 \(k\) 个。论文图 1(a) 的例子是 2 个 query、4 个块、\(k=2\)：路由器把第一个 query 分给第 1、2 块，把第二个 query 分给第 3、4 块，它们各自只和这两块里的 token 做注意力。

先补一点背景：块的“平均 key”打分，其实就是块内注意力 logit 的平均。

内积对加法是线性的，所以

$$s_i=\mathbf q\cdot\frac1B\sum_{j\in I_i}\mathbf k_j=\frac1B\sum_{j\in I_i}\mathbf q\cdot\mathbf k_j$$

右边的 \(\mathbf q\cdot\mathbf k_j\) 正是全注意力里第 \(j\) 个位置的 logit。换句话说，MoBA 用“这一块里所有位置的 logit 的平均值”来代表这一块，挑平均 logit 最高的几块。这个等式是本站的推导，论文没有写出，但它能解释 MoBA 的三个性质：

  • 不需要新参数。打分直接用这一层已有的 query 和 key，所以 MoBA 层和全注意力层的参数完全相同，可以随时互相切换。
  • 打分不直接受训练，却会跟着注意力一起变好。top-k 是离散的选择，\(g_i\) 又不乘到输出上，所以损失对打分没有梯度。但 query 和 key 本身会通过被选中 token 上的注意力得到训练：模型为了让该看的 token 发挥作用，会把相关的 query 和 key 学得更“对得上”，这些位置的 logit 变大，所在块的平均 logit 也随之变大，下次就更容易被选中。打分器可以说是“搭便车”学会的。这也解释了为什么从全注意力模型续训 MoBA 很自然：全注意力训练出来的 query 和 key 已经让相关位置的 logit 偏高，块平均天然带有有用的信号。
  • 平均会冲淡单个重要的 token。这是它的主要弱点，下面用一个算例说明。

2.2.2 因果性：不选未来的块；当前块必选，块内加因果掩码

自回归语言模型按“接龙”的方式生成：第 \(t\) 个位置的输出只能依赖第 1 到 \(t\) 个位置。训练时整段序列是并行计算的，靠因果掩码挡住未来的位置。块级的挑选在两个地方可能破坏这一点，MoBA 分别做了处理。

第一，不能选未来的块。如果一块整个都在 query 之后，它就完全是未来。MoBA 规定：用 \(\mathrm{pos}(\mathbf q)\) 表示 query 的位置，对所有满足 \(\mathrm{pos}(\mathbf q)<i\times B\) 的块（也就是结尾在 query 之后的块），令 \(s_i=-\infty\)、\(g_i=0\)。注意这条规则同时把 query 自己所在的块也排除在打分之外，因为它的结尾也在 query 之后。

第二，当前块要单独处理。当前块里，一部分位置是过去，一部分是未来。如果像其他块一样拿它的平均 key 去打分，平均值里就混进了未来位置的 key（见下图）。这样一来，“要不要看这一块”这个决定本身就依赖了未来的信息：训练时模型可以借这条缝隙“偷看”后面的内容来降低损失，推理时却没有这些信息，训练和推理就对不上了。MoBA 的办法是：当前块不参与打分，而是强制选中（令 \(g_i=1\)），并在当前块内部加上普通的因果掩码，每个 query 只看块内自己及之前的位置。作者指出这样做还有一个好处：保证每个 query 总能看到紧挨着自己的局部上下文。从 MoE 的角度看，当前块相当于共享专家，是路由时额外加上的一条固定规则。

2.2.3 三个设计选择：切多细、能否混用、与固定结构的关系

细粒度切块。MoE 的经验是，把专家切得更细、每个 token 多选几个，在总计算量不变时效果更好。MoBA 想验证同样的规律在“上下文方向”上是否成立：保持 \(k\times B\)（每个 query 最多看的 token 数）不变，把块切得更小、同时选更多块。§3.1 的消融给出了答案。

与全注意力混合。MoBA 不增加也不减少任何参数，所以任何一层在任何时候都可以在 MoBA 和全注意力之间切换，换过去不需要重新初始化什么。论文用了两种混合方式：按训练阶段混合（先用 MoBA 训练、最后一段换回全注意力），和按层混合（某些层固定用全注意力）。把全注意力层换成滑动窗口层的类似想法，在 SimLayerKV 中研究过。§3.2 是相关实验。

滑动窗口和注意力汇聚点都是 MoBA 的特例。如果门控总是选最近的几块，MoBA 就成了按块滑动的窗口注意力；如果门控总是选第一块再加最近的几块，就成了注意力汇聚点的按块版本。作者据此认为 MoBA 的表达能力更强：只要换上特定的门控，它就能近似很多静态的稀疏结构。

读的时候容易误解的地方：
  • “特例”是在门控可以任意指定的意义上说的。MoBA 实际用的是固定的、无参数的打分（块内平均 logit），它不能被“设定”成总选第一块；第一块会不会入选，取决于它的平均 logit 够不够高。所以这句话说的是“块选择这一族方法”比滑动窗口更一般，而不是说 MoBA 这个具体的门控一定能学出滑动窗口的行为。
  • 当前块必选，但紧挨着的上一块并不必选。位于块开头的 query，当前块里只有寥寥几个位置可看，紧邻它的上一块要靠打分入选；所以“保证能看到局部上下文”只在块内成立，跨块边界时并没有保证。后面会看到，NSA 为此专门设了一个滑动窗口分支。

2.3 方法（三）：只用现成的 FlashAttention 内核实现（原文 §2.3）

这一节要回答的问题：块稀疏注意力在 GPU 上并不好写：每个 query 选的块都不一样，如果直接用一个大掩码去算，被掩掉的部分照样要算，等于没省；自己写专门的内核又费时费力。MoBA 怎样只用 FlashAttention 现成的接口就把它跑快？官方开源代码里又有哪些论文没有写明的细节？
先补一点背景：FlashAttention 的两件工具，在线 softmax 合并与变长批处理。

FlashAttention（见本站 FlashAttention 精读 §3.2）把 key 分成小块依次处理，靠“在线 softmax”把各块的局部结果合并成精确的整体结果。它的核心是一个合并公式：对同一个 query，如果 key 被分成互不重叠的两组 A 和 B，分别算出了各自归一化后的输出 \(\mathbf o_A,\mathbf o_B\)，以及各自分数的 log-sum-exp（简称 LSE）

$$\ell_A=\log\sum_{j\in A}e^{\mathbf q\cdot\mathbf k_j},\qquad \ell_B=\log\sum_{j\in B}e^{\mathbf q\cdot\mathbf k_j}$$

那么在 A∪B 上做一次 softmax 的结果，可以直接由两部分拼出来：

$$\ell=\log\big(e^{\ell_A}+e^{\ell_B}\big),\qquad \mathbf o=e^{\ell_A-\ell}\,\mathbf o_A+e^{\ell_B-\ell}\,\mathbf o_B$$

直观地说，\(e^{\ell_A-\ell}\) 就是“A 组在全部注意力权重里占的份额”。FlashAttention 的接口会把每个 query 的 LSE 一起返回，所以分开算、再合并，结果和一次算完相同（只差浮点舍入）。

第二件工具是变长批处理（varlen）：把很多条长度不同的序列首尾相接拼成一个长张量，再传一个累计长度数组 cu_seqlens 标出每条序列的起止位置，FlashAttention 就会在一次内核调用里对每条序列各自做注意力，序列之间互不可见。它本来是为了让不同长度的样本不必补齐，MoBA 把它借来做别的事。

论文把实现概括为五步：(1) 根据门控和因果掩码，确定每个 query 被分配到哪些 KV 块；(2) 按分配到的块重新排列 query 的顺序；(3) 对每个 KV 块和分给它的 query 计算注意力，这一步可以用变长 FlashAttention；(4) 把输出按原来的顺序排回去；(5) 一个 query 可能同时去了当前块和几个历史块，用在线 softmax 把这些部分结果合并起来。这正是 MoE 的套路：MoE 先把 token 按专家分组（dispatch），每个专家对自己那组 token 做一次稠密的矩阵乘，再把结果送回原位（combine）。MoBA 把“专家”换成了 KV 块，把“专家的前馈计算”换成了“在这一块上做注意力”。

2.3.1 官方代码里论文没写的几个细节

官方仓库 MoonshotAI/MoBA 给出了两个实现：一个朴素实现（moba_naive.py），用完整的注意力掩码来算，便于理解和核对；一个高效实现（moba_efficient.py），README 称在 32K 长度、单头、块长 2048、top-3 的测试中比朴素实现快 40 倍。读高效实现（本站读的是 master 分支，最后一次提交在 2025-04），可以看到几处论文没有写明的细节：

  • 两次 FlashAttention 调用是怎么拼的。当前块那一次，cu_seqlens 直接取块的边界，于是每一块被当成一条独立的“序列”做因果注意力，块与块之间互不可见。历史块那一次，每一个“（块，头）”组合是一段：这一段的 query 是所有选了这块的 query（只取这一个头），key 和 value 是这一块的 \(B\) 个 token，不加因果掩码，因为整块都在这些 query 之前。没有任何 query 选中的（块，头）直接剔除。
  • top-k 里包含当前块。代码先把 \(k\) 减 1，再在历史块里取 top-(k−1)。每条序列的最后一块不可能成为任何 query 的历史块，也被提前剔除。
  • 打分用 FP32。平均 key 和 query 都先转成 FP32 再做内积，注释说是为了让门控分数更准。代价是代码会一次性算出一个形状为“块数 × 头数 × 序列长”的完整分数矩阵。按 100 万 token、块长 4096（约 256 块）、32 个头推算，这个 FP32 矩阵单层就约 34 GB（推算），实际运行时必须把头切到多张卡上。后来的 FlashMoBA 正是把这一步改成了分块计算、不把完整矩阵写进显存（见文末）。
  • 反向传播。两部分都直接调用 FlashAttention 的变长反向内核，传入合并后的 LSE，得到 Q、K、V 的梯度。正如 §2.2 所说，打分这一步不在梯度路径上。
  • GQA 怎么处理。在接入 Hugging Face 模型的包装函数里，K 和 V 先被复制到与 query 头数相同（repeat_interleave），再交给 MoBA。也就是说，即使模型用了 GQA（Llama-3.1-8B 是 32 个 query 头共用 8 组 K、V），每个 query 头也各自打分、各自选块，同一组里的 4 个头可能选中不同的块。复制本身也占显存：100 万 token 时，单层的 K、V 从约 4 GB 变成约 16 GB（推算，BF16）。§6 会说明这正是 MoBA 和 NSA 的一个关键区别。
  • 解码。包装函数在解码阶段（每次只来一个新 token）直接调用普通的 FlashAttention，代码注释写着分页注意力版本“待发布”。也就是说，开源版本只在预填充和训练时用 MoBA。README 还特别提醒：MoBA 需要继续训练才能发挥作用，不能直接套在现成的预训练模型上当作即插即用的稀疏注意力。

2.3.2 计算量：省了多少，打分本身又要花多少

设块长为 \(B\)、每个 query 选 \(k\) 块（含当前块）。一个处在序列后部的 query，要看 \(k-1\) 个完整的历史块，再加上当前块里平均一半的位置，所以大约看 \((k-\tfrac12)B\) 个 token，与序列长度无关。因此整条序列的注意力计算量正比于 \(N\cdot(k-\tfrac12)B\)，随 \(N\) 线性增长；全注意力则正比于 \(N^2/2\)，随 \(N\) 平方增长。

打分要让每个 query 和每块的平均 key 做一次内积，共 \(N\times n=N^2/B\) 次，仍是平方增长，只是除以了块长 \(B\)。以 8B 模型的配置推算（\(B=4096\)，\(k=12\)，\(N=2^{20}\)）：一个后部的 query 要看约 47,104 个 token，而打分只要 256 次内积，打分的计算量不到注意力本身的 1%。要到序列长约 3.9 亿 token，打分的计算量才会追上注意力本身（推算：每个 query 的注意力约 \(4d(k-\tfrac12)B\) 次运算、打分约 \(2dN/B\) 次，两者相等时 \(N\approx2(k-\tfrac12)B^2\)）。

块的大小还决定了 GPU 能不能跑得快。块大时（比如 4096），每个历史块会被很多 query 选中，④b 里的每一段都是“很多个 query × 4096 个 key”的大矩阵乘，正好是 FlashAttention 擅长的形状。块小时（比如 128），段数暴增、每段又很小，内核调度和数据搬运的开销就会盖过省下来的计算。这解释了为什么论文的配置都用很大的块（512 到 4096，§3.4 的超长实验甚至用到约 16 万），也解释了为什么后来需要专门的内核来支持小块（见文末 FlashMoBA）。

读的时候容易误解的地方：
  • 论文说实现“结合了 MoE 和 FlashAttention 的优化技术”，指的是上面这种“按块分组、再批量计算”的组织方式，不是说 MoBA 有一个像 MoE 那样可以学习的路由器。
  • 论文说 MoBA 把复杂度降到了“次二次方”。严格地说，这要求块长 \(B\) 和块数 \(k\) 都固定：此时注意力部分线性增长，打分部分以 \(1/B\) 的系数平方增长。§3.4 的千万 token 实验为了保持稀疏度不变，让块长随序列长度成比例增大，这时 MoBA 的计算量仍然按平方增长，只是常数小了约 13 倍（推算）。

3 实验：效果差多少，快多少

这一节要回答的问题：MoBA 让每个 query 少看了很多 token，效果会不会变差？作者分四步回答：先用一组从头训练的小模型画缩放律，并做切块粒度的消融（§3.1）；再看 MoBA 和全注意力怎样混用（§3.2）；然后在真实规模上，从 Llama-3.1-8B 出发续训到 100 万 token，比各项基准（§3.3）；最后测速度（§3.4）。读每一组时都要问：比较的两边是不是只差注意力？测的长度有没有长到让稀疏真正起作用？

3.1 缩放律与消融：从头训练的小模型

先补一点背景：缩放律、PFLOP/s-day 与“尾部损失”。

缩放律：在不同规模下训练一组模型，画出“验证集损失—训练计算量”的关系，通常近似一条幂律 \(L(C)=a\,C^{-b}\)。在双对数坐标里它是一条直线，指数 \(b\) 越大，增加计算量时损失降得越快。按 Chinchilla 的结论，计算量一定时，参数量和训练 token 数应同步增长（大约每个参数配 20 个 token），这样训练出的模型叫“计算最优”。计算量的单位 PFLOP/s-day 指“每秒 \(10^{15}\) 次浮点运算持续一天”，约 \(8.64\times10^{19}\) 次浮点运算。

尾部损失（trailing LM loss）：只统计序列最后一段位置（例如 32K 序列的最后 2K 个 token）上的损失，而且只统计真的长到这个长度的序列。为什么需要它？普通的验证损失是对所有位置取平均，而语料里短文档居多，每条序列前段的位置也占多数；预测这些位置几乎用不到远处的上下文，稀疏注意力在远处“漏看”的东西很难在平均损失里体现出来。最后 2K 个位置最依赖前面三万多个 token，最能暴露长上下文能力的差别。

3.2 与全注意力混合：按阶段，或按层

先补一点背景：按位置的损失，以及 SFT 的损失掩码。

按位置的损失（position-wise LM loss）：对验证集里的每个位置分别求平均损失，画成“位置—损失”曲线。越靠后的位置能利用的上下文越多，损失越低，Gemini 1.5 等报告都观察到曲线大致按幂律下降。比较两个模型时，主要看曲线的尾部有没有分开。

SFT 的损失掩码：监督微调（SFT）的数据是“提示 + 回答”，通常只在回答部分计算损失，提示部分的 token 不计损失（被“掩掉”）。在长上下文 SFT 里，提示往往有几万 token，回答只有几百 token，于是真正产生梯度信号的位置很少。

按阶段混合。作者训练了三个 1.5B 模型，都是 32K 长度、300 亿（30B）token，MoBA 的块长 2048、top-3：(1) 全程全注意力；(2) 全程 MoBA；(3) 混合：前 90% 的 token 用 MoBA，最后 10% 换回全注意力。按位置的损失（原文图 5a）显示：全程 MoBA 在尾部位置的损失明显更高，混合方案几乎和全注意力重合。本站从原图读出的最后一个位置段（约 30K–32K）：全注意力约 1.307，混合约 1.313，全程 MoBA 约 1.361；在最开头的位置，三者都约为 2.80。作者还特别指出，从 MoBA 切到全注意力时，损失没有出现明显的尖峰。

这个结果的意义在于训练成本，因为长上下文预训练里最贵的就是注意力。按本站推算，块长 2048、top-3 在 32K 长度下，MoBA 阶段的注意力计算量约为全注意力的 29%；前 90% 用 MoBA、最后 10% 用全注意力，注意力部分的总计算量约为全程全注意力的 36%，而最终的损失几乎一样。注意这只是注意力部分，模型其余部分的计算量不变，所以整个训练的节省要小一些；论文也没有报告实际的训练耗时。

按层混合。作者观察到，MoBA 在 SFT 阶段有时效果不好，损失偏高。他们猜测原因在于损失掩码：只有回答部分产生梯度，而在稀疏注意力下，回答位置的 query 只连到少数几个被选中的提示块，梯度只能沿这几条路流回提示部分，其余提示位置在这一层收不到来自回答的梯度，作者称之为“梯度稀疏”。解决办法是把最后几层换回全注意力，其余层仍用 MoBA。可以这样理解为什么换的是“最后几层”：最后几层用全注意力时，回答位置能直接看到全部提示位置，梯度也就能从回答流到每一个提示位置，再沿着残差连接一路往下传给前面的 MoBA 层。

3.3 真实规模：从 Llama-3.1-8B 续训到 100 万 token

先补一点背景：位置插值，以及几个长上下文评测。

位置插值（Position Interpolation，PI）：Llama 用 RoPE 编码位置（见本站 RoFormer 精读），模型只在训练长度以内的旋转角度上“见过世面”。要把上下文从 128K 扩得更长，PI 把新的位置编号按比例压缩回原来的范围，比如长度翻倍时，第 \(t\) 个位置按 \(t/2\) 来旋转，这样所有角度都落在模型熟悉的区间里，再配合一段续训，模型就能适应更长的上下文。

大海捞针（Needle in a Haystack）：在一篇很长的无关文本的某个深度插入一句关键信息，再问模型这句信息的内容；改变文本长度和插入深度，画成热力图。RULER 是一组更难的合成长上下文任务：多根针、多个问题、变量追踪、词频统计、长文问答等，可以指定长度（这里是 128K）。LongBench 是真实长文任务的合集，这里截断到 32K。LooGLE 是一个长文档理解评测。

为了便于别人核验，作者从公开的 Llama-3.1-8B 基座模型出发做长上下文续训（流程见下图，对应原文图 6）：先在 128K 长度上训练，再逐步扩到 256K、512K、1M，在 256K 阶段开始时使用位置插值。完成 1M 的续训后，再“打开” MoBA 训练 1000 亿（100B）token，块长 4096、top-12，最后 3 层保持全注意力，其余 29 层换成 MoBA。SFT 阶段同样从 32K 逐步增加到 1M。对照的全注意力模型 Llama-8B-1M-Full 走同样的流程，唯一的区别是全程使用全注意力。

短输入上，MoBA 层就是全注意力。§2.2 推算过，在块 4096、top-12 的设置下，长度不超过 49,152 个 token 的输入，MoBA 层的计算和全注意力完全相同。AGIEval、BBH、GSM8K、MMLU、HumanEval 这类基准的输入只有几百到几千 token，LongBench 也截断在 32K，都在这个范围以内。所以这些项目上的差异，并不来自“稀疏注意力少看了什么”，而来自两个模型最后一段训练的不同（MoBA 版在 1M 阶段用 MoBA 训练了 100B token，参数因此走到了不同的地方）。它们能说明的是“换成 MoBA 训练没有伤到短文本能力”，不能说明“稀疏注意力在这些任务上没有损失”。

真正考到稀疏的，是 RULER@128K 和长到 1M 的大海捞针。128K 时共 32 块，每个 query 最多看 12 块，论文给出的稀疏度是 \(1-\frac{4096\times12}{128\text{K}}=62.5\%\)。偏偏这里两个版本的数字不一样：arXiv 版是 MoBA 0.7818 对全注意力 0.7849，几乎打平；NeurIPS 版同一格变成了 0.7671 对 0.8031，差了 3.6 个百分点（全程 MoBA 为 0.7690）。其余 15 项的数字在两个版本里完全相同，论文没有解释 RULER 为什么变了，正文的措辞仍是“几乎追平”。

3.4 效率与可扩展性

效率实验比较的是 §3.3 两个模型的注意力层前向时间（也就是预填充时间），不包括前馈层等其他部分，理由是两个模型其余部分的计算量相同。原文图 2(a) 中，序列从 8K 增长到 1M，作者说 MoBA 在所有长度上都比全注意力（FlashAttention）快，1M 时快 6.5 倍。本站把从原图数据点读出的各长度加速倍数、按计算量推算的理想值、以及 NeurIPS 版补充的整个模型的数字画在下图。

从图中能读出三层意思。第一，长度越长，MoBA 越划算：128K 时注意力层只快约 1.2 倍，256K 约 2.1 倍，512K 约 3.9 倍，1M 时 6.5 倍。这与计算量的变化一致：块长和 top-k 固定时，MoBA 每个 query 看的 token 数不变，而全注意力随长度线性增加。

第二，实测只兑现了理想值的一半多：1M 时理想值约 11.4 倍，实测 6.5 倍。差额来自打分、按块收集 query、两次内核调用、LSE 合并这些额外步骤，以及当前块那一次因果注意力。

第三，整个模型的加速要小得多。NeurIPS 版表 6 测了两个模型完整的预填充时间：256K 时 5.67 秒对 3.55 秒（1.60 倍），512K 时 19.59 秒对 8.40 秒（2.33 倍），1M 时 73.97 秒对 22.15 秒（3.34 倍）。原因有两个：前馈层等部分不受影响；MoBA 模型的最后 3 层仍是全注意力。按本站的粗略拆分（假设每层注意力耗时相同、MoBA 层快 6.5 倍），1M 时全注意力模型约 91% 的预填充时间花在注意力上；MoBA 模型的 22 秒里，3 个全注意力层约占 6.3 秒，29 个 MoBA 层约 9.4 秒，其余部分约 6.5 秒（推算）。也就是说，到了百万 token，保留下来的那 3 层全注意力已经是最大的单项开销之一。

扩到 1000 万 token。原文图 2(b) 换了一种设置：固定 64 个块、top-3（稀疏度 \(1-3/64=95.31\%\)），块长随序列长度成比例增大，从 8K 一直测到 10M。为了在 10M 长度上放得下，作者把张量并行扩展到 query 头的层面：不同的 query 头放在不同的 GPU 上，K 和 V 广播给所有 GPU。读图约值：1M 时全注意力约 0.90 秒、MoBA 约 0.077 秒（约 12 倍）；4M 时约 14.6 秒对 1.0 秒（约 14 倍）；10M 时约 91 秒对 5.9 秒，即论文说的“16 倍”（读图约 15.5 倍）。

这组实验里块长随长度变大，所以 MoBA 的计算量和全注意力一样按平方增长，只是常数小：按因果结构推算，平均每个 query 只算全注意力的约 7.7%，理想加速约 13 倍。实测在 4M 和 10M 时还略高于这个值，论文没有解释原因。一种可能是：非因果的整块注意力比带因果掩码的全注意力内核跑得更满（按读图数字推算，10M 时 MoBA 的有效算力比全注意力高约两成），但本站无法从论文中核实。

这些时间到底是什么口径？论文没有写效率测试用的 GPU 型号和数量，也没有说明是否包含反向。从数量级可以做个推算：Llama-3.1-8B 一层注意力在 1M 长度上的前向约 \(9.0\times10^{15}\) 次浮点运算。如果图 2(a) 里全注意力的约 0.94 秒是 32 个头在同一张卡上的时间，这张卡要跑出约 9.5 PFLOP/s，远超 H800 约 0.99 PFLOP/s 的稠密 BF16 峰值；如果是单个头，则约 300 TFLOP/s，和 FlashAttention-2 在 Hopper 上的常见水平相符。官方仓库的测速脚本也是单头（head=1）。所以图 2 很可能是单个注意力头的耗时（推算）。只要两边口径一致，加速倍数仍然有意义，但不能把 0.94 秒当成真实的一层延迟。另外，基线是 FlashAttention（官方代码依赖 flash-attn 2.6.3，即 FlashAttention-2），没有和 Hopper 上更快的 FlashAttention-3 比；不过 MoBA 自己也建立在 FlashAttention-2 的内核上，两边换成更快的内核后都会变快，倍数未必有大的变化。

3.5 结果的份量

把这一节的数字放在一起，哪些可以直接信、哪些要打折扣：

  • 质量对比是同条件的，但都只跑了一次。8B 实验两边从同一个基座出发、走同一套续训和 SFT 流程，只差注意力，是一个干净的对照；小模型的缩放律实验也只改注意力，其余超参数相同。不过所有数字都是单次运行，没有误差范围（NeurIPS 检查表里作者也注明没有报告统计显著性），而 RULER 一项在两个版本之间就差了 2–4 个百分点，提醒我们这类分数本身有不小的波动。
  • 大部分基准没有考到稀疏。输入不超过约 4.9 万 token 时，MoBA 层与全注意力等价（推算）。表中 16 项里，只有 RULER@128K 和输入可能更长的 Loogle 超出这个范围（Loogle 的输入长度本站没有核实）；大海捞针单独测到了 1M。真正考到稀疏的项目上，NeurIPS 版的 RULER 差距是 3.6 个百分点。
  • “稀疏度”都是最大值，不是平均值。论文给出的稀疏度都按“序列最后一个 query”计算。考虑因果结构后的平均节省见下表（推算）。

4 相关工作：MoBA 在稀疏注意力谱系里的位置

这一节要回答的问题：高效注意力的研究已经很多，MoBA 处在哪个位置？作者认为哪些已有工作和它最接近，差别又在哪里？

论文把高效注意力分成四类：

  • 静态稀疏模式：Sparse Transformer、Star-Transformer、BlockBERT、Longformer、ETC、BigBird、LongT5、LongNet 等，事先规定好跨步、窗口、全局 token、随机连接、膨胀或块稀疏等固定模式；多模态里也有图像的轴向注意力、视频的时空注意力。其中 BlockBERT（分块自注意力，2019）的第一作者正是本文的通讯作者之一 Jiezhong Qiu。
  • 动态稀疏模式：根据内容决定看哪里。Reformer 用局部敏感哈希、Routing Transformer 用 k-means 把 token 聚类，只在同一类里做注意力；Memorizing Transformer、Unlimiformer 用 k 近邻检索要看的 token；CoLT5 用路由模块挑出重要的 query 和 key；Sparse Sinkhorn Attention 学习把块重新排列。NeurIPS 版在这里加了一句：DeepSeek 的 NSA 也是动态稀疏注意力，它的选择分支与 MoBA 的选块机制相似。
  • 无需训练的稀疏注意力：拿现成的模型在推理时加速。预填充阶段可以先把完整的提示“看一遍”再决定稀疏模式，例如 MoA、MInference、SeerAttention 研究的 A 形、竖线加斜线、动态块稀疏等模式；解码阶段主要是压缩、裁剪 KV 缓存，如 H2O、StreamingLLM、TOVA、FastGen、Quest。
  • 替换注意力结构：Hyena、Performer、Linformer、RWKV、Mamba、RetNet 等，需要从头训练，不能复用已有的 Transformer 模型。

作者点名了两项和 MoBA 最接近的工作。Quest 可以看作块更小、块的代表方式不同的 MoBA。LongHeads 可以看作 top-1 的 MoBA：每个头只挑一个最相关的块。

先补一点背景：Quest 的“上界”打分和 MoBA 的“平均”打分差在哪里。

Quest 给每个块保存两个向量：块内 key 在每一维上的最大值 \(\mathbf m^{\max}\) 和最小值 \(\mathbf m^{\min}\)。给定 query，它在每一维上取 \(q_c m^{\max}_c\) 和 \(q_c m^{\min}_c\) 中较大的那个，再把各维加起来。这个数一定不小于块内任何一个 key 与 query 的内积，所以是“块内最大 logit”的一个上界。用上界打分，块里只要有一个 token 和 query 很像，这块的分数就高，不会被其他 token 冲淡；用平均打分则正好相反（见 §2.2 的算例）。上界打分的代价是估计可能偏松，并且每块要存两倍的元数据。Quest 是推理期的方法，块也小得多，专门服务于解码阶段。

同样用块均值、但不训练的路线会怎样？本站的 XAttention 精读 讨论了这个问题：XAttention 是一种免训练的块稀疏预填充方法，它认为直接对块做池化来估计重要性太粗，改用块内反对角线上的分数之和来打分。两相对照可以看出，MoBA 的块均值打分之所以能用，很大程度上依赖续训让模型去适应它。

5 结论与局限

这一节要回答的问题：作者自己怎样总结这项工作？正式版承认了哪些局限？结合前面的分析，还有哪些局限论文没有正面讨论？

作者的总结是：MoBA 把上下文切成块，用动态门控为每个 query 挑选最相关的 KV 块，在保持与全注意力相近效果的同时显著降低了计算量，并且可以在全注意力和稀疏注意力之间无缝切换；由于不增加参数、可以接在现有模型上续训，它是提升长上下文能力的一种实用方案。作者列出的未来方向包括改进选块策略、扩展到其他模态、研究它对复杂推理泛化的作用。

NeurIPS 正式版增加了一段局限说明：第一，路由器没有参数，可能抓不住更细致的长上下文模式，未来可以研究可学习的路由器；第二，只做了文本；第三，没有研究长思维链推理这类场景。

结合前面各节，本站再补充几条论文没有正面讨论的局限：

  • 不减少 KV 缓存的存储。任何历史块都可能被选中，所以全部 K、V 都得保留；1M 长度时 Llama-3.1-8B 的 KV 缓存约 128 GB（推算）。MoBA 能减少解码时要“读”的量（如果解码也用 MoBA），但不减少要“存”的量。
  • 解码加速既没有实现，也没有测量。开源代码在解码时直接用全注意力，论文也没有报告解码速度。
  • GQA 组内不共享选择。官方实现里每个 query 头各自选块；如果解码也用 MoBA，一组 4 个头可能要从显存读 4 份不同的块，节省的访存量会打折扣（§6）。
  • 跨块边界的局部上下文没有保障。当前块必选，紧挨着的上一块却不必选，位于块开头的 query 能看到的近邻很少（§2.2.3）。

新增参数无，可以与全注意力随时互换压缩用的 MLP、门控 MLP，三个分支各有独立的 K、V 投影
GQA 组内官方实现中每个 query 头各自选块组内各头的分数相加，全组共用一套块，解码时每块只读一次
内核复用 FlashAttention-2 的变长接口：当前块一次因果调用，历史块按（块，头）分段一次非因果调用，再用 LSE 合并自写 Triton 内核：按“同一位置、同一 GQA 组的所有头”装载 query，依次读入选中的块
训练方式主实验是从 Llama-3.1-8B 续训（最后 100B token 打开 MoBA）；可与全注意力分阶段、分层混合；缩放律小模型从头训练从头预训练 27B MoE（每 token 激活 3B）、270B token，8K 预训练后用 YaRN 扩到 32K
解码主表配置在生成时用全注意力；开源代码的解码为全注意力设计目标之一；按访存量推算 64K 时约 11.6 倍（不是实测）
报告的速度1M 预填充：注意力层前向 6.5 倍（很可能是单头口径，推算），整个模型 3.34 倍64K：注意力内核前向 9.0 倍、反向 6.0 倍（A100，Triton 实现）
代码官方开源（MIT 许可）没有官方实现，有多个第三方实现

这些差别大多能从两者的出发点推出来。MoBA 想要的是一个能插进现有全注意力模型的模块：不加参数，才能在续训中途打开、在某些层关闭、在 SFT 时部分换回；用很大的块，才能直接复用 FlashAttention 的变长内核，让每个块分到足够多的 query 凑成大矩阵乘。代价是打分粗糙（平均会冲淡单个关键 token）、GQA 组内不共享、解码没有专门的支持。

NSA 则是从预训练开始的原生设计，同时追求训练和解码的效率：小块让选择更精确，但小块在 GPU 上难跑，于是它强制 GQA 组内共享选择，按组装载 query、自己写内核；压缩分支既提供全局的粗略视图，又顺带给出了经过训练的块分数；滑动窗口分支专门负责局部，避免局部模式“抢走”其他分支的学习。代价是结构更复杂、新增参数，也不能直接和现有的全注意力模型互换。

两者也有共同点：都认为稀疏应当在训练时就存在，而不只是推理时的补丁；都按连续的块来选，以便和 GPU 的分块计算对齐；都只减少计算量和读取量，不减少 KV 缓存的存储量。

不要直接横向比较两篇论文的数字：两者的实验条件差别很大。MoBA 是 8B 稠密模型续训到 1M，看 RULER、LongBench 等；NSA 是 27B MoE 从头训练到 32K，看 LongBench、64K 大海捞针和 AIME。速度的口径也不同：MoBA 是（很可能单头的）前向耗时，硬件未写明；NSA 是 A100 上 Triton 内核的前向和反向。两篇论文都没有在相同设置下与对方比较，表中的数字只能各自理解。

后来怎么样了

截至 2026-10，MoBA 的影响主要在三方面：作为“可训练的块稀疏注意力”的代表，被后续工作反复引用和比较；开源实现成为后续工作的起点；还引出了专门针对它的分析和内核。

FlashMoBA：块该多小，以及怎么让小块跑得快

MIT 与 NVIDIA 的 Guangxuan Xiao、Junxian Guo、Kasra Mazaheri、Song Han 在 2025-11 发布了《Optimizing Mixture of Block Attention》（arXiv 2511.11571）。他们为 MoBA 的路由建立了一个统计模型：把“装着关键 token 的块”和“纯噪声块”的分数之差看成随机变量，算出它的期望与标准差之比，即信噪比

$$\mathrm{SNR}=\Delta\mu_{\text{eff}}\sqrt{\frac{d}{2B}}$$

其中 \(d\) 是头维度，\(B\) 是块长，\(\Delta\mu_{\text{eff}}\) 是关键 token 相对 query 的“有效”相似度优势；选错块的概率为 \(\Phi(-\mathrm{SNR})\)（\(\Phi\) 是标准正态分布的累积分布函数），随信噪比增大而迅速下降。这和 §2.2 的算例是同一个道理：块越大，单个关键 token 被平均得越淡。由此他们给出两条改进：用更小的块；在 key 上加一个短卷积，让相关的 token 在块内聚得更紧，以提高 \(\Delta\mu_{\text{eff}}\)。在 3.4 亿参数、100B token 的实验里，块长从 512 降到 128，WikiText 困惑度降低 1.2，RULER 提高 17.2 个百分点（该论文图 2 的说明）。

问题是小块在原来的实现上很慢。他们指出，MoBA 官方实现用小块时，非注意力部分（物化完整的分数矩阵、大量零碎的分段）的开销反而让它比稠密注意力还慢，在他们的设置下长度到 128K 时显存溢出。为此他们写了 FlashMoBA 这个 CUDA 内核：分块计算 top-k，不把完整的分数矩阵写进显存；对每个选中的块，把选了它的 query 收集到片上 SRAM 里做稠密计算，再写回原位。在块长 128、top-8 的设置下，它相对 FlashAttention-2 最高快 14.7 倍。用这些改进从头训练的 3.4 亿和 10 亿参数模型，效果与稠密注意力相当。代码在 mit-han-lab/flash-moba ↗。

VMoBA：用到视频扩散模型

北京大学与快手可灵团队的 VMoBA（arXiv 2506.23858，ICLR 2026 官网的海报列表中有这篇）把 MoBA 改造成适合视频扩散模型的形式：各层轮流按一维、二维、三维的方式切块，以适应视频的时空局部性；在一个注意力头的所有 query 上做全局的块选择；按阈值动态决定选多少块，而不是固定 \(k\)。论文报告，在更长序列上训练时，计算量（FLOPs）降低 2.92 倍、延迟降低 1.48 倍，生成质量与全注意力相当或更好；不训练、直接用于高分辨率生成时，计算量降低 2.40 倍、延迟降低 1.35 倍。

月之暗面自己后来的方向

论文说 MoBA 已用于支持 Kimi 的长上下文请求，但在月之暗面之后公开的模型技术报告里，看不到 MoBA 作为主干注意力：Kimi K2（arXiv 2507.20534）的注意力是与 DeepSeek-V3 同类的 MLA，报告中没有提到 MoBA；Kimi Linear（arXiv 2510.26692）转向了线性注意力 KDA 与 MLA 的逐层混合，只在相关工作里提到 MoBA，把它和 NSA 一起归为“从 token 级转向块级选择”的方法。本站据此只能说：MoBA 在 Kimi 线上服务中怎么用、用在哪些模型上，没有公开的细节；后续公开的模型走了别的路线。Kimi Linear 的讲解见本站 Kimi Linear 精读。

稀疏注意力的另一条线：从块级回到 token 级

DeepSeek 后来在 V3.2 上用的 DSA 走了另一个方向：不再按块选，而是用一个很小的“闪电索引器”给每个历史 token 打分，再逐 token 挑选（见本站 DeepSeek-V3.2 精读 和 DSA 拆解页）。后来的 MiniMax Sparse Attention 则回到按块选择，并让 GQA 组内共享选择、单独训练一个索引分支。块级还是 token 级、打分用无参数的统计量还是训练出来的索引器，本质上都是 §2.2 讨论的“选得准”与“算得快”之间的权衡；MoBA 代表了其中最简单的一端：无参数、大块、直接复用现成内核。
