# AGENTS.md — how to work in this repo

This is a **static, no-build research site** in Chinese. Its main product is a **paper library** where each paper gets a
**reading page (论文精读)**: a section-by-section explanation of the paper in plain but technical Chinese. The older
content — method "tracks" with interactive structure pages, lineage graphs and timelines — lives under `legacy/` and is
kept and linked, but new work goes into reading pages. Everything is plain HTML + CSS + vanilla JS. Open any page
directly (`file://`) or run `python scripts/serve.py` (no-cache server on http://127.0.0.1:8765).

Audience: a researcher who wants to understand *why* each method is built the way it is.
Language of the content is **Chinese (zh-CN)**; code, identifiers and paper titles stay English.

## Layout

```
index.html                       site root = the 论文书架 (paper library, rendered by assets/js/papers.js)
papers/<slug>.html               one reading page per paper (逐节精读) — THE default deliverable
papers/<slug>/fig/               original figures, only for papers whose license allows it (CC BY / BY-SA / CC0)
papers/metrics.js                citation snapshot (generated by scripts/fetch_metrics.py)
registry.js                      single source of truth: tracks / categories, nodes (papers), edges, facts
assets/css/atlas.css             design tokens (light/dark), layout, diagram, library and reading-page styles
assets/js/atlas.js               runtime: header, TOC, KaTeX, [data-render] blocks, architecture figures, widgets
assets/js/papers.js              library (shelves, filters, citations) + reading pages (progress, status, stats)
assets/js/widgets/*.js           interactive demos; each registers window.AtlasWidgets["<name>"]
templates/reading-page.html      copy this to start a reading page
templates/model-page.html        copy this to start a legacy track node page
legacy/index.html                旧版研究路线 — lists the legacy tracks
legacy/tracks/<track>/…          legacy track overviews + node pages + SOURCES.md
scripts/check.py                 validation (registry JSON, links, ids, defs, reading pages) — run before commit
scripts/fetch_metrics.py         refresh papers/metrics.js
scripts/arxiv_blocks.py          parse an arXiv HTML paper into ordered blocks (handy for reading the paper)
scripts/serve.py                 local preview server
404.html                         forwards old /tracks/… URLs to /legacy/tracks/…
```

## 论文精读页（固定做法）— the default way to add a paper

The user approved `papers/vllm.html` as the template (2026-10-19). **Every new paper gets a reading page of this form.
No full translation**: the vLLM page keeps the translation it already has, but new pages are notes only.

1. **Registry.** The paper needs a node in `registry.js`. If it belongs to a legacy track, reuse/add the node there and
   set `"reading": "papers/<slug>.html"`. If it fits no legacy track, put it in a library-only category: a `tracks[]`
   entry with `"status": "papers-only"` and `"page": "index.html"` (hidden from the legacy track list, shown as a library
   category); its nodes set both `page` and `reading` to the reading page. Fill `full_title`, `authors`, `org`, `date`
   (first arXiv version, `YYYY-MM`), `venue`, `arxiv`, `links`, and a `tldr` of one or two plain sentences (shown on
   library cards). Citation counts come from `python scripts/fetch_metrics.py`, never by hand.
2. **Read the whole paper** (arXiv HTML `https://arxiv.org/html/<id>`, else the PDF; official code / project page for
   details). Verify every number you will use.
3. **Copy `templates/reading-page.html`** to `papers/<slug>.html`; set `<title>`, description, `data-track`,
   `data-node`; fill the header (a Chinese title that reads naturally + the English title, authors with affiliation
   superscripts exactly as printed, pills). `[data-stats]` fills citations / first version / venue automatically.
4. **Write 逐节精读** (`<h2 id="notes">` → `<div id="notes-body">` → one `<section class="note">` per section of the
   paper, in the paper order, plus `0 导读` first and `后来怎么样了` last). Style rules — the user's requirements:
   - Open every section with a `.note-ask` box: in full sentences, the question this section answers and where the
     question comes from. **Never a telegraphic one-line gist** ("A 靠 B；B 被 C 卡住" is unreadable).
   - Explain every prerequisite in a `.note-pre` box before first use, starting from what a reader already knows
     (e.g. why batching raises throughput, what attention reads, OS paging). The notes may carry more information
     than the paper itself.
   - Every claim as cause → effect with explicit connectives; one idea per sentence; define a term before using it.
   - Say what each number means; work small examples; mark our own calculations “推算”.
   - Use analogies and step-by-step walk-throughs of the paper's own examples.
   - End sections with `.note-warn` boxes for common misreadings (baselines that are re-implementations, conditions
     under which the gain shrinks, overloaded terms).
   - The notes must cover everything a separate summary would; there is no separate TL;DR section.
5. **Figures are required.** Put each figure next to the text that discusses it with a “怎么看” caption (axes, colours,
   what to read off it, the conclusion). Original figures only when the arXiv abstract page shows CC BY / CC BY-SA /
   CC0 (download into `papers/<slug>/fig/` and credit the license in `.license-note`). Otherwise draw our own diagrams
   (`.dia` HTML boxes — `.dia-row/.dia-track/.dia-seg`, `.dia-flow/.dia-box`, `.cells/.cell`, `.gantt` — or inline
   `svg.dg`) that explain the same idea in our own way, and link to the original figure (`…/html/<id>#S3.F2`).
   Plot data may be restated as numbers or as a simplified chart of the reported values. Never trace or copy a figure.
6. **Authors / impact / more.** Authors: affiliation as printed + only publicly verifiable background (homepages, lab
   pages) — no rankings, no Semantic Scholar h-index (its author profiles are unreliable). Impact: venue, adoption,
   code stars with a date. More: links to related reading pages / legacy pages and back to `../index.html`.
7. **Check.** `python scripts/check.py` (0 errors), then look at the page in a browser at desktop and phone width:
   formulas render, every figure loads, no horizontal overflow, the notes read naturally.

Reading notes are commentary in our own words, not a translation: do not reproduce paragraphs of the paper. Short
technical terms, formulas and individual numbers are fine.

## Legacy tracks: adding a node (paper / concept) to an existing track

1. **Register it** in `registry.js` → `nodes[]`. Required: `id`, `track`, `kind`
   (`model` | `paper` | `concept` | `bridge`), `lane`, `title`, `date` (`YYYY-MM`), `page`, `tldr`.
   Add `facts{}` (keys = that track's `compare_fields[].key`) for model nodes so the
   compare table picks it up. Put the node into the track's `reading_order` and add
   `milestones[]` / `edges[]` entries as appropriate.
2. **Create the page** by copying `templates/model-page.html` to
   `legacy/tracks/<track>/NN-<slug>.html`. Set `<body data-node="<id>">` and keep the section
   skeleton (see "Page anatomy"). The header, hero, TOC and prev/next are rendered from the
   registry — do not hand-write them.
3. **Draw the architecture** as inline SVG inside `<figure class="arch">` (see "Diagrams").
4. **Record sources** in `legacy/tracks/<track>/SOURCES.md` (one row per fact: value → paper
   section / table / code file).
5. Run `python scripts/check.py`. Fix everything it reports.

## Legacy tracks: adding a track

1. Append to `registry.js` → `tracks[]` (`id`, `title`, `short`, `page`, `summary`,
   `reading_order`, `lanes`, `milestones`, `compare_fields`).
2. Copy `legacy/tracks/jepa/index.html` → `legacy/tracks/<track>/index.html`, change `data-track` and
   the hand-written prose; the `[data-render]` blocks are generic.
3. Add nodes as above. Create `legacy/tracks/<track>/SOURCES.md`.

## registry.js schema

The file assigns a **strict-JSON** object to `window.ATLAS_REGISTRY` (double quotes, no
trailing commas, no comments inside the object). `scripts/check.py` parses it with a JSON
parser, so keep it that way.

```
site:   { title, subtitle, lang }
tracks: [{ id, title, short, status, page, summary,
           reading_order: [node ids in reading order],
           lanes: [{ id, label }],            // columns of the lineage diagram (keep labels short)
           milestones: [{ date, label, node?, anchor?, url?, venue? }],  // chronological; node OR url
           compare_fields: [{ key, label }],   // rows of the compare table
           questions?: [{ id, text, nodes: [{ node, anchor }] }] }]  // review-question index
nodes:  [{ id, track, kind, lane, title, full_title?, authors?, org?, date, venue?, arxiv?,
           modality?: "image" | "video",   // optional; if any node of a track has it, the lineage colours by modality
           links?: [{ label, url }], page, tldr, tags?, facts?: { <compare key>: text } }]
edges:  [{ from, to, label, kind? }]          // lineage arrows (node ids); kind "baseline" = only a main
                                               // baseline comparison (dotted), default = inheritance
```

`kind` is one of `model` (a model/architecture), `paper` (a systems/method paper), `concept`, `bridge`.

### Lineage diagram

`[data-render="lineage"]` draws one **column per lane** and stacks time **downwards in year bands** (a node takes
the next free row of its lane inside its year, always below same-year parents). The svg is drawn at the host's real
width, so text never scales; it re-lays out on resize. Same-lane edges that skip nodes become brackets in the column
margin; cross-lane edges choose a curve or elbow that does not pass through other boxes. Edge labels appear on hover
(the node's ancestors and descendants are highlighted) or via the "显示全部关系标签" toggle. Keep `title` short
(≤ 2 lines of ~10 CJK chars in a 5-lane track) and edge `label` ≤ 16 chars. With `modality` set, image→video
edges are drawn dashed green ("图像 → 视频"). A track may set `lineage_band: "half" | "quarter"` when its nodes
cluster in a short period (rows become "2025 Q3" bands); a long compare table can use `data-orient="rows"`.
`page` paths are relative to the repo root. A page may include a `#fragment` (several nodes may share one page,
e.g. `lejepa` → `04-le-world-model.html#lejepa`, `h-jepa` → `10-hierarchical-wm.html#h-jepa`).

### Timeline milestones

`milestones[]` must be in chronological order (the checker warns otherwise). Each entry links either to a node
(`node`, optionally `anchor` = an id on that node's page, e.g. `{ "node": "eagle", "anchor": "c-eagle3" }`) or,
for notable papers that have no page of their own, to an external `url` (rendered with ↗ and a dashed dot).
Prefer adding a milestone with `url` over leaving a gap in the timeline; promote it to a node page later.
`check.py` verifies node/url presence, https, date format, ordering and that every `anchor` / `#fragment` exists.

### Question index (tracks that answer a fixed list of questions)

A track may carry `questions[]`. Each entry maps a question id (`"Q7"`) and its text to one or more
`{ node, anchor }` pairs. The track page renders the index with `<div data-render="questions">`; a node
page's hero automatically shows "本页回答 Q7 Q16 …" badges linking to `#<anchor>` (for any node on that page file). Put the answers in a
`<h2 id="questions">简答题</h2>` section using this markup (CSS in `atlas.css` §9):

```html
<div class="qa">
  <h3 id="q7"><span class="qid">Q7</span>Question text</h3>
  <div class="ans"><p class="short">One-paragraph answer.</p><ul>…</ul><p class="cite">依据：…</p></div>
</div>
```

`check.py` verifies every `{node, anchor}` points at an existing page id.

## Page anatomy (what templates/model-page.html gives you)

```
<body data-root="../../" data-page-kind="model" data-track="<track>" data-node="<id>">
<header id="site-header">            ← filled by atlas.js
<svg class="atlas-defs">…</svg>      ← arrow markers + hatch pattern used by every diagram; keep verbatim
<div class="layout"><nav class="toc"> <main class="content">
  <div data-hero>                    ← title/authors/links/TL;DR from registry
  <h2 id="motivation">   1. 动机
  <h2 id="architecture"> 2. 全局架构  → <figure class="arch" id="fig-arch">
  <h2 id="components">   3. 组件拆解  (h3 per component; widgets go here)
  <h2 id="shapes">       4. 张量形状追踪 (table.shapes)
  <h2 id="objective">    5. 训练目标与防坍塌 (KaTeX)
  <h2 id="pseudocode">   6. 伪代码 (<pre><code class="lang-py">)
  <h2 id="hyperparams">  7. 关键超参
  <h2 id="results">      8. 关键结果
  <h2 id="evolution">    9. 承上启下 (.diff was/now)
  <h2 id="references">   参考
  <div data-pager>                   ← prev/next from reading_order
```

Keep the section ids: the TOC is generated from `h2[id]`/`h3[id]`, and cross-page links
rely on them (`01-i-jepa.html#c-masking`, etc.).

### Conventions for prose

- Every quantitative claim must be traceable: cite inline with `<span class="src">论文 Tab. 6</span>`
  and add a row to `SOURCES.md`. When paper and official code disagree, say so in a
  `<div class="callout code-note">` ("论文 vs 官方代码") and prefer the code for reproduction.
- Mark anything you could not verify with `<span class="unverified">…</span>`; never present
  an estimate as a paper number.
- Use the same symbols across pages of a track. JEPA: `x` context/history, `y` target, `z` conditioning
  variable, `s_x/s_y` representations, `Enc_θ`, `Pred_φ`, `D` distance/energy, `λ` reg weight.
  Few-step: data `x_0`, noise `ε`, `x_t` (state the time convention), velocity `v`, student `G_θ`, teacher
  score `s_real`, fake score `s_fake`, consistency function `f_θ`, average velocity `u`, discriminator `D_ψ`,
  frozen feature encoder `φ`, condition `c`, guidance scale `w`, NFE.
- Math: `\( … \)` inline, `$$ … $$` display (KaTeX auto-render). Inside `<pre>`/`<code>` math
  is not rendered.

### Diagrams (`svg.dg`)

- Inline SVG, `viewBox` ~960 wide, `class="dg"`. Only CSS variables for colour — never raw hex
  for semantic parts (light/dark themes). Scene-illustration colours (a sky, a ball) may be hex.
- Semantic roles → CSS classes on the group or box:
  `enc` online/trainable encoder · `tgt` EMA/frozen encoder · `pred` predictor ·
  `loss` loss/energy · `act` actions/proprioception · `reg` regulariser · `data` inputs/indices.
  Token squares: `<rect class="tk enc|tgt|pred|act|mask|off">`. Edges: `<path class="edge [enc|tgt|pred|act|loss|reg|sg|ema|grad|idx]">`
  (`sg` dashed = stop-gradient, `ema` dotted purple, `grad` = gradient path, `idx` = index/mask routing).
  Few-step track reuses the same classes with these roles: `data` noise / data / latents · `enc` student generator
  (trainable) · `tgt` teacher or any frozen network · `pred` auxiliary trainable net (fake score, critic,
  discriminator head) · `loss` · `reg` regulariser · `act` condition (text, past frames, actions, KV cache).
- Interactive architecture figure: `<figure class="arch">` containing
  `.arch-canvas > svg.dg` + `.arch-foot > .arch-panel + .controls` + hidden `.arch-notes`.
  - Clickable component: `<g data-part="<id>">` ↔ `<div data-note="<id>">` in `.arch-notes`.
  - Walkthrough: put `data-step="k"` (space-separated list allowed) on any SVG element and a
    `<div data-step-note="k">` per step. Steps number the forward/backward computation order.
  - Do **not** put inline `opacity` on stepped elements (the walkthrough controls opacity).
- Each page carries the `<svg class="atlas-defs">` block (markers `ah`, `ah-enc`, … and
  `#hatch`). Copy it verbatim from the template; `check.py` verifies it exists on pages that
  use `.dg`.

### Widgets

`<div data-widget="<name>" data-…></div>` + `<script defer src="../../assets/js/widgets/<file>.js">`.
Available: `mask-2d` (I-JEPA block masking), `mask-3d` (V-JEPA tubelet masking),
`attn-mask` (block-causal vs causal+AdaLN), `cem` (CEM + MPC toy planner; caption via `data-caption`),
`sigreg` (SIGReg / Epps–Pulley in 2-D with gradient descent),
`roofline` (prefill/decode roofline + KV-cache calculator; `data-panel="both|roofline|kv"`),
`paged-kv` (PagedAttention blocks, block tables, copy-on-write), `specdec` (speculative-decoding
speedup curves + rejection-sampling demo), `collectives` (all-reduce / all-gather / reduce-scatter /
all-to-all step-through; `data-ranks`), `fewstep-2d` (2-D toy for few-step generation with an exact GMM
teacher: `data-focus="sampling|regress|dmd|drift"` — Euler NFE, regression coupling, DMD particles, drifting field),
`memory-toy` (top-down toy world: four memory policies — window, frame retrieval, 3D map, recurrent state — recalling a
demolished wall on revisit, change seen vs. unseen),
`dllm-decode` (parallel unmasking on a toy canvas with a correlated city pair; exact P(invalid) and E[NFE] for
fixed steps / threshold τ / block size B vs. left-to-right; `data-focus="steps|threshold|block"`). Widget attributes must not be named `data-note` — that name is
reserved for architecture-figure notes and the checker will flag it.
New widget = new file registering `window.AtlasWidgets["<name>"] = (el, Atlas) => {…}`;
helpers on `Atlas`: `h` (DOM), `s` (SVG), `rng(seed)`, `gauss(rand)`, `esc`, `typeset`.
Widgets must be deterministic for a given seed and must not fetch anything.

## Paper library internals

- The library (`index.html`) lists every non-concept node as a card; a node with `reading` links to its reading page,
  otherwise to its legacy page. Shelves (未读 / 在读 / 已读 / 收藏) and progress are per viewer in localStorage
  (`atlas-paper:<node id>`); categories are the registry tracks (including `papers-only` ones). A cross-field paper
  can also appear under other categories: list their track ids in the node's optional `also` array (e.g.
  `"also": ["dllm"]`); the card then shows both labels.
- `papers/metrics.js` is a Semantic Scholar snapshot (citations, highly influential citations) keyed by arXiv id;
  `scripts/fetch_metrics.py` refreshes it (rate-limited without a key; it backs off). When a full refresh keeps
  getting rate-limited, `python scripts/fetch_metrics.py --missing` fetches only the papers absent from the snapshot
  and merges them in. Papers older than ~6 months that come back with 0 citations are re-matched by exact title.
- Reading-page markup: `.note`, `.note-ask`, `.note-pre`, `.note-warn`, `.paper-fig` (+ `.imgs`, `figcaption`), `.dia*`,
  `.gantt`, `.author-cards`, `.license-note`; progress runs from `#notes` to the end of `#notes-body`
  (or `#fulltext-body` on the vLLM page, which also has a bilingual full translation in `.bi` blocks).

## Checks

```
python scripts/check.py          # registry is strict JSON; every node.page exists; ids unique;
                                 # every data-part has a data-note; local links resolve;
                                 # pages that use .dg contain atlas-defs; widgets referenced are loaded
```

There is no test suite beyond this and a manual look in a browser (`python scripts/serve.py`).
When you change `atlas.js` or `atlas.css`, open at least one model page and one track index.

## Things not to do

- Don't add a build step, bundler, framework or package.json. Pages must work from `file://`.
- Don't load third-party scripts other than KaTeX from jsDelivr (already pinned to 0.16.11).
- Don't hand-write the header/hero/TOC/pager; they come from the registry.
- Don't duplicate facts between `registry.js` `facts{}` and page prose in a way that can drift —
  the compare table is the registry; the page is the explanation. If a number changes, change
  both and the SOURCES row.
